# 桌面运行日志：两个文件、轮转与旧大日志处理

适用范围：`desktop/`（Electron 桌面宿主）。变更来源：`harden-windows-desktop-reliability` 任务 1.1–1.3。

## 1. 两个文件，各自一个写入者

| 文件 | 写入者 | 内容 |
|---|---|---|
| `run.log` | 后端（Python，`common/log.py` 的 `RotatingFileHandler`） | 后端启动、请求、技能与工具执行 |
| `desktop-main.log` | 桌面宿主（Electron 主进程，`desktop/src/main/host-log.ts`） | 宿主 `console.*`、崩溃、渲染/GPU 进程退出、后端启动前的 stdout/stderr、后端退出码 |

**为什么必须分开**：同一文件由两个进程轮转在 Windows 上不安全（句柄与备份竞争）。宿主曾经把自己的诊断写进后端的 `run.log`，这既是 1.1 GB 事故的载体，也让「打开日志目录」只能看到一半。

目录由 `desktop/src/main/data-dir.ts` 统一定义，两个文件始终同目录：

| 运行形态 | 目录 |
|---|---|
| 源码/开发运行 | 仓库根（`app.py` 所在目录） |
| 打包安装 | `~/.cow`（Windows：`%USERPROFILE%\.cow`） |
| 显式指定 | 环境变量 `COW_DATA_DIR`（任意构建下优先，后端读同一个变量） |

入口：菜单「日志」页显示后端实时日志（`/api/logs`，即 `run.log`）；启动失败页的「打开日志目录」打开上表目录，两个文件都在其中。

## 2. 轮转策略

- `desktop-main.log`：单文件上限 **10 MiB**，保留 **2** 个历史文件（`desktop-main.log.1`、`.2`），最旧的一份先删除。每个文件由一个写入者负责轮转（`host-log.ts`）。
- `run.log`：沿用后端既有 Python 轮转，本次未改动。
- 写入是**同步**的：每条记录在被接受时就已落盘，宿主不维护日志队列、不缓冲、不丢记录；磁盘持续失败时按上限（3 次）停止重试并降级为「无文件日志」，不会反复重试或把异常抛回调用方。

## 3. 旧超大日志的人工处理

升级前可能存在一个由宿主无限刷屏写大的 `run.log`（开发模式下位于仓库根，打包模式位于 `~/.cow`）。处理原则：**先停写入者，再动文件**。

1. **停止写入者**：退出桌面应用（退出托盘实例）；若在开发模式，确认没有遗留的 `python app.py` 进程。只有一个写入者时文件才是安全的。
2. **保留现场**：把旧文件改名或压缩保留（如 `run.log.2026-10-13.bak`），不要直接删除——排查仍可能需要它。文件很大时用移动而不是复制，避免瞬时双倍占用。
3. **不要原地截断活动文件**：进程仍持有句柄时截断会写入空洞或触发未定义行为；也不要对正在写入的文件做「另存为」覆盖。
4. **不要删除业务数据**：`identity.db`、`config.json`、记忆目录、上传文件都不属于日志清理范围。日志目录里只有 `run.log*`、`desktop-main.log*` 是本次可以处理的文件。
5. 重启应用后，两个日志文件都会按各自策略重新开始，大小有界。

本次**不提供**自动迁移、日志面板、导出流程或「日志大小/轮转状态」界面：旧文件的识别与处理按上面的人工步骤完成，客户端不尝试自动判断混合历史日志的归属。

## 4. 相关代码与验证

| 位置 | 作用 |
|---|---|
| `desktop/src/main/host-log.ts` | 宿主日志：同步写入、10 MiB×2 轮转、终端断管保护、崩溃直写（无 console） |
| `desktop/src/main/data-dir.ts` | 数据目录唯一来源（与后端 `COW_DATA_DIR` 一致） |
| `desktop/src/main/index.ts` | 启动时安装日志与崩溃捕获；退出时关闭 |
| `desktop/src/main/python-manager.ts` | 后端启动输出在其就绪前写入宿主日志；失败原因经 `[SHELL]` 记录 |
| `tests/test_desktop_host_log.cjs` | 15 项：格式化不抛错、断管/同步抛错只静音一次、崩溃不递归、轮转有界、突发不丢记录、不触碰 `run.log` |

Windows 上「重命名仍被本进程打开的文件」已实测可行（libuv 使用 `FILE_SHARE_DELETE`）；实现同时先关闭描述符再重命名，使顺序不依赖平台细节。
