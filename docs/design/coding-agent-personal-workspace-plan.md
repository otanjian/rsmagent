# Code 类智能体个人文件夹完整设计方案

日期：2026-10-10。状态：设计提案，尚未实施。

Code 类智能体统一使用 OpenCode 服务端的 `<项目目录>/user/<登录账号>/` 保存个人业务文件。点击对话页右上角文件按钮，打开当前账号在当前项目下的个人文件夹；不存在时自动创建。文件面板、对话附件、智能体工具和结果下载共同使用这一目录绑定。

本方案适用于共享和私有的 Code 类智能体，内部类型为 `coding`。普通智能体继续使用现有规则。本方案中的“输入输出文件”指用户上传的附件、智能体下载或生成的业务文件、脚本及中间文件；聊天正文、会话数据库、服务日志和模型配置仍由现有系统管理。用户主动导出的聊天记录属于输出文件，也保存到个人文件夹。

## 1 用户可见行为

以登录账号 `tanjian`、智能体配置项目目录 `/data/projects/sap-assistant` 为例：

```text
/data/projects/sap-assistant/
├── rsmcode/                           项目提供的可信工具与配置（`.opencode/` 为上游别名）
├── …                                  项目公共资源
└── user/
    ├── tanjian/                       本人文件面板的根目录
    │   ├── uploads/                   输入附件
    │   │   └── <会话ID>/<附件ID>/原文件名.xlsx
    │   ├── outputs/                   生成结果
    │   │   └── <会话ID>/<任务ID>/分析报告.xlsx
    │   └── work/                      脚本与中间文件
    │       └── <会话ID>/<任务ID>/...
    └── other-account/                 另一账号的目录
```

个人文件夹按登录账号 `username` 命名，例如 `tanjian`，不使用昵称，也不以 UUID 作为可见文件夹名。鉴权和所有权绑定继续使用不可变的 `user_id`。

同一账号在同一项目中的多个会话共用个人根目录，附件和结果通过会话、任务子目录避免重名。不同项目有各自的个人目录。同一租户内两个智能体若配置了同一个项目，按这一物理布局也会共用同一账号的文件夹；配置界面需明确显示这一关系。

文件按钮保留当前位置。打开后标题显示“我的文件 · tanjian”，面包屑从 `tanjian` 开始，不能返回项目根或 `user` 父目录。支持浏览、搜索、预览、上传、下载、新建目录、重命名及移入回收站；编辑沿用现有文件类型与权限限制。文件操作能力由服务端返回，前端不假设远端具备某项能力。

切换账号、租户、智能体或历史会话后，重新解析文件来源并清空旧目录、预览和上传状态。迟到的请求结果不得展示在新会话中。目录创建失败时显示原因和重试入口，不切换到项目根或其他智能体目录。

## 2 现状及需要衔接的位置

| 现有位置 | 当前行为 | 本方案的调整 |
| --- | --- | --- |
| `channel/web/static/js/workspace.js` | 顶部按钮走 `toggleWorkspacePanel`；文件接口使用平台工作区路径，并存在目录缺失时的父目录候选回退 | 为 coding 增加独立文件来源，根目录由服务端返回，取消 coding 的父目录回退 |
| `channel/web/fork/handlers/workspace.py` | 普通智能体的写入范围按个人目录收紧，coding 保留整智能体目录语义 | 保留普通路径，coding 接入专用远端文件接口 |
| `channel/web/fork/handlers/coding.py` | 从档案读取 `coding_project_dir` 后创建会话 | 将配置项目根解析为本人工作目录，再创建或打开会话 |
| `agent/coding/sessions.py` | 关联行保存会话创建时的 `project_dir`，iframe 和上游调用复用这个快照 | 区分配置项目根和实际运行目录，并保存个人工作区绑定 |
| `channel/web/fork/handlers/coding_browser.py` | 校验会话、项目参数，代理文件读取和消息请求 | 细化到个人工作区；统一附件准入和文件访问边界 |
| 配套 RSMCode 的 `packages/app/src/components/prompt-input/` | 本地图片等附件可作为 `data:` 内容随消息提交 | 在发送前上传到个人目录，并用已持久化附件的可信引用构造消息 |
| 配套 RSMCode 的 Location 和工具层 | 工具默认基于 Location；项目识别及配置发现可能向父目录查找 | 运行目录与可信配置来源分别传递，文件访问范围不随 Git 根扩大 |
| `Scene/sap_workbench/backend/` | 工具安装和部分绑定校验使用项目路径 | 工具安装继续使用配置项目根，运行绑定增加个人工作区信息 |

平台工作区和 `coding_project_dir` 当前是两套存储语义。后者是 OpenCode 主机上的路径，因此不能在平台机器上直接 `mkdir` 同名路径来代替远端创建；即使两台机器恰好存在相同路径字符串，也不能视为同一份文件。

配套源码检查基于本地 `rsmcode/opencode`；上线前需核对实际部署版本及其能力。新增远端接口和运行目录约束属于本方案的实现工作，不假定当前 OpenCode 已支持。

## 3 统一目录解析与账户绑定

定义两个明确的路径：

```text
P = Code 智能体配置的项目根目录
U = P/user/<服务端查询到的 username>

文件面板根目录 = U
上传根目录     = U
会话运行目录   = U
业务文件写入范围 = U 的子树
可信项目配置来源 = P 中明确允许的配置和资源
```

目录解析服务暂命名为 `CodingWorkspaceService`。它接收已经鉴权的用户、租户、智能体和可选会话标识，不接收客户端指定的 owner、username 或绝对存储路径。账号名称由身份数据库按 `user_id` 查询。

新会话使用智能体当前配置的 P；已有个人目录模式会话使用会话保存的 P、U 和工作区绑定。管理员修改智能体项目目录后，只影响新会话，历史会话仍能访问自己的原文件。档案列表等只读查询不创建目录；点击文件按钮、启动会话和实际上传之前才执行目录准备。

账号路径段必须通过独立的安全校验。当前新账号规则已限制为字母、数字、点、下划线和连字符；存量账号仍需复查。保留数据库中账号的规范拼写，不因登录时输入了不同大小写而新建目录，不用字符替换产生可能重名的目录。不合规存量账号返回可识别错误。

目录与 `user_id` 的映射持久化。账号停用、重新启用不会改变目录归属。重新注册的同名账号不能继承旧目录；遇到已有路径却缺少可信归属记录时报告冲突，由迁移流程处理，不自动认领。现阶段按首次绑定的登录账号固定路径；若以后增加账号改名，需通过停写、冲突检查、原子改名和会话绑定更新完成，不能在登录时自动搬目录。

项目由远端服务返回规范路径和不透明的 `project_ref`。同一服务内，同一物理项目不能同时绑定到不同租户；还要检查路径别名及项目根互相包含导致的跨租户重叠。这样保留用户要求的 `P/user/username` 结构，无须在个人路径中额外加入租户名。

## 4 目录创建和失败恢复

目录准备按下列顺序执行：

1. 平台校验登录、租户成员资格、`chat.use`、`agent.use`、智能体可用性、私有所有权和已有会话归属。
2. 根据账号、项目和用户 ID 取得或预留工作区绑定；数据库唯一约束处理同时打开多个窗口的情况。
3. 通过经过服务认证的内部接口，要求 OpenCode 主机确认 P 已存在且属于已登记项目。
4. 远端安全创建 `user`、账号目录和 `uploads/outputs/work`。这些目录不得是普通文件、链接或跳出已登记项目的路径。项目根必须已正确配置，不因拼写错误创建一个新项目。
5. 返回规范 U 和工作区版本，将绑定置为 ready，再允许创建会话、上传或展示文件。

状态为 `preparing → ready`；失败保存错误原因和重试状态。创建成功但平台回包丢失时，用原绑定重试；目录创建、归属确认和回包都必须幂等。已准备好但尚未产生会话的空个人目录可以保留。

首次创建与后续操作都在远端执行路径检查。检查和打开文件应使用基于目录句柄的安全操作，防止校验后被替换为链接；不能只用字符串 `startsWith` 或一次 `realpath` 检查。工具执行端也使用同一范围，禁止通过链接、目录跳转或硬链接操作访问范围外的业务文件。

目录缺失、磁盘满、权限不足、归属冲突、远端不可用分别返回稳定错误码。任何失败都不得回退到公共项目根写文件。

## 5 文件面板与远端文件服务

复用现有文件面板的展示和交互，增加 `coding_remote` 文件来源。现有平台工作区和桌面本地来源保持各自适配器。coding 来源负责把面板的树、预览、上传、编辑、删除和回收站操作映射到远端文件 API。

建议的浏览器接口如下，名称可在实施时按仓库路由规范收敛：

| 接口 | 用途 |
| --- | --- |
| `POST /api/coding/workspace/open` | 根据 `agent_id` 和可选 `session_id` 准备本人目录，返回绑定与能力 |
| `GET /api/coding/workspaces/{id}/tree` | 列出个人根下的相对目录 |
| `GET /api/coding/workspaces/{id}/search` | 在个人根下查找文件 |
| `POST /api/coding/workspaces/{id}/uploads` | 流式上传，返回附件 ID、相对路径与版本 |
| `GET /api/coding/workspaces/{id}/files/{file_id}` | 鉴权预览或下载文件 |
| `PATCH /api/coding/workspaces/{id}/files/{file_id}` | 使用版本条件编辑或重命名 |
| `POST /api/coding/workspaces/{id}/directories` | 新建个人目录内的子目录 |
| `POST /api/coding/workspaces/{id}/trash` | 移入个人回收站；恢复和清理采用配套接口 |

`workspace/open` 返回 `workspace_id`、`source=coding_remote`、`root_label=username`、`root_path=""`、`capabilities` 和 `binding_version`。前端只用根相对路径操作文件，不拼接服务器绝对路径。接口中的 ID 是定位符，每次请求仍需验证用户、租户、智能体使用资格和绑定范围。

浏览器访问平台同源接口，平台在重新鉴权后调用 RSMCode 内部文件服务。远端调用使用短期、限定工作区和操作的服务签名凭据；上传按方法、目标、大小上限校验，不能演变为持有任意路径的通用远程读写接口。上游服务密码不下发到浏览器。

内部文件服务部署在 OpenCode 能访问 P 的主机上。同机和异机部署均走同一协议，避免两套文件落点逻辑。预览、下载和上传采用流式传输，文件面板应按服务端能力获取大小及并发限制，不能把消息代理现有的请求体限制当作文件上传能力。

下载用受鉴权的 `file_id` 链接，支持断点和大文件流式返回。HTML 等主动内容不能在平台同源下无约束执行，沿用安全预览机制。文件被重命名后更新定位记录；移入回收站和删除后链接分别返回已删除状态和不存在，不能用同名新文件冒充旧文件。

## 6 对话输入与结果输出

所有文件入口都使用同一个工作区绑定：面板上传、输入框选择文件、拖拽、粘贴图片、`@文件`、外部场景传入附件及服务端消息接口。只改面板上传无法覆盖 iframe 内的附件。

| 文件来源 | 保存规则 |
| --- | --- |
| 输入框上传、粘贴图片、场景附件 | 发送前保存到 `U/uploads/<会话ID>/<附件ID>/原文件名` |
| 尚未建会话时从面板上传 | 保存到 `U/uploads/manual/<附件ID>/原文件名`，之后可通过引用用于任意本人会话 |
| 面板在指定子目录上传 | 按用户选择保存到 U 内的子目录，检查冲突后发布 |
| `@` 引用本人已有文件 | 使用经鉴权的文件记录，无须重复复制 |
| 工具下载、浏览器下载、MCP 返回的文件 | 经绑定的输出目录或导入接口保存到 U，再生成下载引用 |
| 报告、代码、导出结果 | 默认保存到 `U/outputs/<会话ID>/<任务ID>/` |
| 中间脚本、数据处理临时文件 | 保存到 `U/work/<会话ID>/<任务ID>/` |

附件先落盘成功，再允许消息进入模型执行。图片、PDF 等需要以二进制或 `data:` 形式发给模型时，由已保存的文件读取内容生成模型请求，仍保留个人目录中的原件。不能仅把浏览器上传数据放进消息数据库后就视为“已存入个人文件夹”。

服务端的消息准入层执行同一规则，直接调用消息接口也不能绕过。客户端提交任意 `file://` 路径、伪造的附件归属或范围外路径时拒绝；后端只把已授权的附件记录转换成上游需要的路径或内容。

上传采用临时文件、完整性校验和原子发布，上传标识用于重试去重。同名文件默认产生独立附件 ID 或提示冲突，明确覆盖时要求当前文件版本。上传后未发送消息的文件仍保留在上传目录，临时未完成载荷才按保留策略清理。

运行时传递实际目录，如 `RSM_WORKSPACE_DIR=U`、会话专属 `RSM_INPUT_DIR`、任务专属 `RSM_OUTPUT_DIR` 和 `RSM_WORK_DIR`。系统提示说明输出位置，工具执行层负责真正的目录约束。用户可以明确选择 U 内其他位置；目录外输出返回错误，不静默改投，也不依靠任务完成后到处扫描搬文件。

新建或修改文件的工具事件携带工作区、会话、任务、文件 ID 和相对路径。面板据此刷新，消息中的结果卡片使用平台鉴权下载链接。事件中断后通过重新列目录补齐；未登记的本人目录文件在用户浏览时可以登记，不能因缺少索引而永远不可见。

纯文本回复正常保存在会话系统，不强制为每条消息生成文件；“代码块”只有被实际保存为文件后才作为文件交付。删除聊天不自动删除个人文件，删除个人文件也不删除聊天记录。

## 7 会话目录与工具执行

新会话创建时，将 OpenCode 的实际 Location 设为 U，并让 iframe 地址、文件查询和消息请求使用同一目录。不能让文件面板使用 U、模型继续在 P 工作。

项目配置与运行目录分别提供：可信配置来源仍为 P 下已登记的 `rsmcode`、技能和公共资料，业务读写基准为 U。配置加载须设置明确的上界和优先级，个人目录内上传的同名配置不能覆盖平台的目录限制或注册任意服务端插件。普通代码或文档仍作为业务内容处理。

OpenCode 的项目识别可能把 U 识别为上层 Git 仓库的一部分；项目 ID 相同只能证明代码项目关系，不能证明个人文件权限相同。文件树、搜索、差异、Git 状态、工具路径、LSP 和格式化入口均需采用 U 的范围；发现不能安全限定的能力时，返回不支持，不能展示整个项目或其他用户目录。

文件工具校验规范路径，且外部目录权限不能由浏览器权限确认绕过。Shell 或任意脚本仅设置 `cwd=U` 不能保证文件写入 U：配套源码的 bash 工具当前仍使用宿主用户权限。因此，若保留这些能力并要求所有业务文件归位，需要为命令及有文件副作用的本地插件启用执行沙箱。

生产执行约束为：U 可写，指定项目配置和运行依赖只读，其他用户目录不可见；沙箱临时区、工作 HOME 和缓存落在 U 下受管理的隐藏目录或任务临时区。不能把包含所有用户目录的完整 P 作为可读挂载暴露进去。宿主模型凭据、控制服务端口和状态数据库不进入命令沙箱。远端 MCP 的业务数据仍由远端系统管理，其交付给用户的文件通过受限导入接口保存到 U。

这一沙箱能力是“包括任意脚本在内都只能在个人范围产生业务文件”的交付条件。阶段联调若尚未具备沙箱，应禁用有任意文件副作用的执行能力；不能只上线提示词和 cwd 后宣称实现了完整约束。

## 8 会话元数据与鉴权

在身份侧增加项目与用户工作区登记，在会话库增加绑定字段。以下为逻辑字段，具体 schema 按现有迁移机制落地：

| 数据对象 | 关键字段与约束 |
| --- | --- |
| 项目登记 | `project_ref, service_id, tenant_id, canonical_project_root`；远端规范物理项目只能归属一个租户 |
| 个人工作区绑定 | `workspace_id, project_ref, user_id, username_at_creation, relative_root, canonical_user_root, version, state`；`project_ref + user_id` 唯一，个人路径不能绑定两个用户 |
| `opencode_session_links` 扩展 | `workspace_id, base_project_dir, workspace_mode, binding_version`；现有 `project_dir` 继续表示实际发送给上游的会话目录，新模式为 U |
| 文件定位记录 | `file_id, workspace_id, relative_path, version, source_session_id, message_id, task_id, status`；用于附件引用、结果链接和来源追踪 |

会话 owner 和租户继续从现有 `sessions` 行读取，不再增加另一套会话所有权来源。工作区表持有的是文件夹归属，并在关联时与会话 owner 校验一致。

新会话、重试、打开历史、分叉、attach、内部子任务和场景触发均继承同一绑定。当前 attach 有以 OpenCode 项目 ID 判断同项目的逻辑；新模式必须另外验证工作区绑定、真实目录和创建来源，不能仅凭同一 Git 项目 ID 接管其他账号的远端会话。

平台浏览器代理按工作区和会话 ID 双重过滤消息、文件、列表、差异和事件。无会话 ID 的文件变化事件必须包含可信 `workspace_id`，才可投递给对应账号。目录级或项目级 SSE 不能直接转发。

文件来源解析必须确定当前 agent 与 session；多个标签页的授权 cookie 不能通过“取第一个匹配范围”决定读写目录。页面通信继续验证 origin、iframe source 和随机 channel，页面消息只发意图和文件 ID，不能授予路径权限。

个人模式要求浏览器走统一的平台身份代理。现有独立 OpenCode 认证部署须先接入等效的本人范围约束，且共享服务不对普通浏览器直接开放；否则不能启用并宣称个人目录隔离。权限撤销或账号停用后，对文件和会话的新访问立即拒绝，活动事件订阅在重新校验时关闭。

## 9 SAP 等场景的兼容

SAP 场景的工具包仍安装在 P 的可信配置位置，所有个人会话都加载同一版本；不要把每个用户目录变成一份需要独立升级的工具安装目录。

场景快照拆分 `base_project_dir` 与 `workspace_id/runtime_dir`。目前 `store.py` 中比较项目快照与 `link.project_dir` 的逻辑需相应调整，否则把运行目录改为 U 后会错误报告项目不匹配。

SAP 会话绑定、MCP 权限档案、模型转发和浏览器会话仍按现有用户及租户鉴权。浏览器导出、截图、下载附件必须使用本次任务的 U 内目录，不能继续写入进程全局下载目录。启用个人模式前，将“在个人目录运行时工具可发现、可调用、导出文件可下载”作为场景验收的一部分。

## 10 旧会话与旧文件过渡

旧会话的 `project_dir=P` 已与远端会话绑定，不能只更新平台数据库就假装远端也切换到 U。默认采用以下过渡规则：

1. 存量关联标记为 `workspace_mode=legacy_project`，新增会话使用 `personal_v1`。升级只补元数据，不移动文件。
2. 旧会话继续提供本人历史消息查看；启用个人模式的智能体不再允许在旧公共根继续产生新一轮文件写入。代理必须限制 prompt、command、shell 等所有执行入口，不能只隐藏发送按钮。
3. 提供“在个人文件夹中继续”操作：准备 U 并创建新的个人会话。仅导入本人可访问的对话上下文及有明确归属的附件，不复制旧项目的整个目录。需要摘要时明确标记摘要来源，不伪装为原始完整历史。
4. 工作区文件按钮始终打开本人的 U。旧消息内的附件仅在原授权及归属可证明时提供兼容下载；无法确认归属的旧路径不得借机开放公共根。
5. 旧文件整理单独执行只读预检，按可信附件记录、会话 owner 和工具记录生成迁移清单。身份不明、多用户共用和目标冲突的文件进入管理员处理清单，不按文件名推断所有者。

迁移在停止相关写入并备份后进行。远端保存原路径、目标路径、摘要和迁移状态，支持幂等恢复。已确认迁移的旧附件引用通过受保护的单跳映射找到新文件，然后按新目标重新鉴权；不存在的文件明确显示缺失，不读取同名替代物。

如果后续需要保留同一个远端会话 ID 完成切换，必须另行验证 RSMCode 对 Location、配置缓存、分叉及历史文件引用的完整迁移能力，不能在本次方案中假定修改 directory 就足够。

## 11 发布与回退

先升级远端文件服务、绑定能力和执行约束，再升级平台身份及会话 schema，随后接入面板和 iframe 附件入口。增加按项目的模式状态：`legacy → preparing → personal`，以便同一物理项目关联的智能体统一切换，避免一部分仍可向公共根写入。

切换前运行能力检查：项目存在、目录可准备、文件 API 版本匹配、身份代理生效、执行范围可约束、项目工具加载成功。切换期间阻止启动新的旧模式任务，并排空或停止在途写入；全部满足后启用 personal。未具备能力时保留明确的准备失败状态，不把新会话降级到公共根运行。

兼容性回退先停止该项目的新任务，保留个人目录和绑定记录，恢复支持该元数据的上一兼容版本。若回退至完全不理解个人目录的旧版本，应停用受影响的 Code 执行入口，不能把已有 U 改回 P 或让旧版本恢复公共写入。已迁移的历史文件按迁移清单单独回退，冲突时不覆盖新增文件。

## 12 实施顺序和代码范围

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| 1 目录与契约 | 定义 P/U、项目登记、用户绑定、错误码；补充适用的行为规范 | 账户、项目、会话三个维度的路径规则固定 |
| 2 远端基础能力 | 安全建目录、个人文件服务、文件引用、执行沙箱及受限配置加载 | 能在 OpenCode 主机上创建并限制本人文件范围 |
| 3 平台会话接入 | `agent/coding`、`coding.py`、`coding_browser.py`、会话 schema 与鉴权路由 | 创建、打开、重试、分叉和代理使用同一 U |
| 4 文件交互接入 | `workspace.js` 来源适配、`coding.js` 生命周期、RSMCode 附件准入及结果事件 | 点击按钮、上传附件、生成文件和下载形成完整闭环 |
| 5 场景和历史 | SAP 路径拆分、导出目录、旧会话继续入口、旧文件预检及兼容下载 | 场景工具正常，历史衔接可解释且可恢复 |
| 6 联调发布 | 两用户真实交互、异机存储、失败注入、灰度及回退演练 | 全部验收条件通过后切换项目 |

平台预计新增 `agent/coding/workspace.py`、远端文件客户端和专用文件 handler；修改现有 coding 会话和浏览器代理。普通智能体的 `common.state_dir.agent_user_root` 不直接改成 username，也不用于解释远端路径。

配套 RSMCode 需要同时修改服务端目录与文件能力、Location/工具执行边界以及 `packages/app` 附件流程。实施时遵守对应仓库的模块边界和协议生成流程，不能只提交平台前端改动就作为完成。

## 13 验收条件

| 场景 | 预期结果 |
| --- | --- |
| 首次点击文件按钮 | 自动生成 `P/user/tanjian` 及基础子目录，面板根显示 `tanjian` |
| 重复点击与双窗口并发 | 只有一个个人绑定和一份目录，不产生重名副本 |
| 两个账号访问同一智能体 | 每人只看到自己的目录；不能通过 API、搜索、差异、事件或工具访问另一账号文件 |
| 同账号创建多个会话 | 共用个人根，附件和结果按会话及任务区分 |
| 切换项目及历史会话 | 新会话跟随新 P，历史个人会话保持原 U，不混入迟到响应 |
| 输入框选择文件、拖拽、粘贴图片 | 发送前在 U 内存在完整文件；上传失败不发送该附件 |
| 直接调用消息接口 | 仍执行附件落盘和归属校验，伪造路径被拒绝 |
| 生成 Excel、PDF、代码与浏览器下载 | 文件全部位于 U，面板可见，结果卡片可下载 |
| 文件面板上传后使用 @ 引用 | 智能体读取同一份文件，刷新后仍能重新引用 |
| 普通文件与 Shell 越界 | 路径跳转、链接及脚本访问他人目录均被拒绝；cwd 设置不能代替此验证 |
| 上层目录是 Git 仓库 | 项目发现不扩大个人读写、搜索、差异和会话 attach 范围 |
| SAP 场景 | 个人会话仍能调用授权工具，导出文件进入本人的 U |
| 平台与 OpenCode 分别部署 | 文件实际出现在 OpenCode 主机的 P 下，平台没有生成同名假目录 |
| 项目不存在或磁盘故障 | 返回明确错误，不创建错误项目，不向公共目录回退 |
| 上传中断、回包丢失、同名修改 | 重试去重，临时文件不误报成功，编辑版本冲突可识别 |
| 停用账号、撤销权限、切换登录 | 旧文件引用与事件访问失效，不显示上一账号的缓存内容 |
| 旧会话继续与旧文件迁移 | 新执行进入个人会话，仅导入已确认归属的文件，旧公共写入入口关闭 |
| 删除会话与回退 | 个人文件保留；回退不恢复公共根写入，也不覆盖新文件 |

自动化验证覆盖目录解析、真实文件操作、鉴权 HTTP、会话创建与分叉、前端来源切换及上传异常；最后用两个真实账号完成“上传附件 → 智能体处理 → 生成结果 → 文件按钮查看 → 下载”的端到端验收。设计文档完成不代表上述功能或验证已实施。
