# 租户共享智能体的用户运行数据隔离方案

日期：2026-09-24。状态：历史完整方案，尚未实施。

> 当前范围已收敛为：租户共享 Agent 下建立 user/<user_id>，仅限制 RongAI 平台文件页面与文件接口访问其他账号目录。Python/Shell/技能/coding 保持现有开放方式；不保证租户共享智能体内部脚本直接读盘时的用户隔离，既有跨租户、私有 Agent 及敏感路径规则不变。以下完整隔离方案仅为历史背景，不作为实施要求；以 [当前 change](../../openspec/changes/isolate-shared-agent-user-data/proposal.md) 及其 design/specs/tasks 为准。

目标：同一租户的多个用户使用同一个共享智能体时，每个人上传、生成和处理的数据默认只属于本人。智能体配置、技能和明确发布的公共知识继续共享。

## 1. 推荐架构与权限语义

采用“共享智能体定义 + 用户运行空间 + 会话工作目录 + 文件对象授权”。无需为每个用户复制一个智能体。

- 智能体是能力配置；用户是运行数据的所有者；会话与运行记录提供来源和生命周期。
- 使用权限 `agent.use` 不授予其他用户的数据读取权限。管理智能体配置也不自动授予用户内容读取权限。
- 同一用户在不同租户的数据相互隔离。同一用户在同一智能体的多个会话中可在“我的文件”看到自己的文件，但每次运行只自动载入当前会话资料；跨会话使用需本人选择。
- 本期不引入成员间分享。后续需要分享时，增加明确的资源授权记录，不通过移动到共享目录或转发预览链接隐式分享。
- 租户管理员和平台管理员在产品接口内均不自动获得私人文件正文、文件名、会话标题或检索片段。治理页面仅提供必要的数量、空间占用、状态等元数据。
- 这里的私有是应用用户之间的隔离。拥有服务器、数据库或备份管理权限的运维人员属于另一个信任边界；本方案不声称对宿主机管理员实现密码学不可见。

| 数据类别 | 默认归属 | 运行时权限 |
| --- | --- | --- |
| 智能体配置、技能、已发布知识 | 租户/智能体 | 按资源授权使用；运行时只读 |
| 用户上传的文件、目录、录音、图片 | 当前租户 + 当前用户 | 本人读取、删除和引用 |
| 生成的报告、表格、图片、音频、HTML | 发起任务的用户 | 本人读取、下载和预览 |
| 解压文件、转换结果、截图、缩略图、临时文件 | 继承源文件或运行的所有者 | 与源数据一致 |
| 会话、工具输出、任务进度、检索索引 | 会话/任务所有者 | 本人可访问；共享索引查询必须先限定归属 |
| 系统或租户级定时任务的数据 | 明确的服务主体 | 单独授权，不冒充某个用户，不因缺少用户而自动共享 |

## 3. 存储与运行目录

新增统一路径解析服务，分别返回配置根、公共素材根、私人运行根。不要直接改变 `profile.workspace` 的全局含义，以免把技能、模型配置、记忆和会话数据库一起改错。

建议结构：

```text
<tenant_shared_root>/agents/<agent_id>/       # 保留配置和管理用途

<private_data_root>/tenants/<tenant_id>/
  users/<user_id>/
    files/<file_id>/...                      # 私人文件对象及派生物
    agents/<agent_id>/
      sessions/<session_id>/
        work/                               # 当前会话工作目录
        runs/<run_id>/tmp/                   # 本次运行临时数据
    memory/                                 # 迁移后的私人记忆源文件
```

- 可基于 `tenant_app_data_root()` 定义 `user_private_data_root()`、`session_work_root()`、`run_tmp_root()`；所有 ID 来自可信对象，统一校验路径段。
- 新私人数据不置于通用共享文件浏览根之下。即便其父级在平台文件浏览范围内，也必须优先排除私人子树，不能由管理员大目录权限绕过 owner 检查。
- 现有 `user_root()` 下的个人记忆可分批迁移，但上线前必须先保护其原始文件、索引数据库及目录元数据。不能只保护新的 uploads/outputs。
- 给工具暴露的共享内容应是明确发布的文件集合或只读快照。不能把整个智能体工作区、租户根、`.env`、会话数据库和记忆索引挂载给用户执行环境。
- 当前会话运行目录在请求开始时固定；使用显式 `cwd`，不修改进程级工作目录，不临时修改共享的 AgentProfile。

## 4. 文件对象与统一授权

新增文件元数据仓储，例如 `file_assets`：

```text
id, tenant_id, owner_user_id, agent_id,
session_id(nullable), run_id(nullable), source_file_id(nullable),
kind, original_name, storage_key, mime_type, size_bytes, checksum,
visibility, status, created_at, deleted_at
```

- 用户上传及运行产物的 `visibility` 固定为 `private`；owner 从登录身份或任务发起者的持久化身份读取。客户端、模型和工具参数不能指定或覆盖 owner。
- `agent_id`、`session_id`、`run_id` 记录来源，不代替所有权。关联会话之前必须验证 tenant、owner、会话所属智能体。
- 对衍生文件继承来源数据的 owner；转码、解压、OCR、索引化等不能重新落入共享域。
- 使用不可枚举的 `file_id` 标识文件，但随机 ID 只是降低猜测风险，授权检查仍然必需。
- 所有读、写、删除、预览、列表、搜索、引用、附件发送统一调用文件授权服务。至少验证：有效身份、有效租户成员关系、文件 tenant 一致、owner 一致、文件状态和操作权限。
- 文件所有权不依赖智能体配置的读取权限。建议智能体使用资格撤销后，本人仍能通过“我的文件”访问其历史文件；继续运行智能体则仍需 `agent.use`。
- 目录项、名称、大小、搜索命中和缩略图同样属于私人内容。搜索在候选检索时就限定归属，再计算排序、总数和分页，不能先跨用户搜索再过滤返回值。

建议接口为 `POST /api/files`、`GET /api/files`、`GET /api/files/{id}/content`、`DELETE /api/files/{id}`，并提供私有预览入口。上传响应和 artifact 事件返回 `file_id` 等公开字段，不返回宿主机绝对路径。

尚未建立会话的上传，先以 tenant/user 归属建立待关联文件；绑定新会话时再次校验并原子更新。后台清理本人未关联且超期的上传，不能靠客户端传来的 session_id 决定归属。

写入采用“暂存 → 注册/校验 → 就绪”状态；只有 `ready` 文件可被读取。失败的文件或元数据需补偿清理。程序生成文件通过受控工作目录收集、登记和发布，未登记产物也只能留在本人的隔离运行空间。

授权采用默认拒绝，并在每个请求和静态资源读取上校验对象权限；可参考 [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

## 5. 执行层必须同时隔离

文件接口鉴权不能阻止模型调用工具读取同租户其他用户的文件。

**文件工具**：`read`、`write`、`edit`、`ls`、`search_files`、`send`、artifact 发布及项目目录切换统一使用当前运行的访问策略。允许读当前用户明确提供的输入与已授权公共素材，允许写当前会话工作目录。校验规范化路径和真实路径，处理 `..`、软链接、硬链接、解压路径及检查与打开之间的竞态；不采用字符串前缀判断目录包含关系。

**任意代码工具**：Bash、Python、技能脚本、本地 MCP 子进程必须进入 OS 级隔离执行环境。参数解析不能证明任意脚本不会读取他人的数据。

建议运行沙箱按 tenant/user/session 分配，可复用同一用户同一会话的实例：

```text
/workspace        当前会话目录，可写
/inputs           本次选择的本人文件，只读
/shared           已授权、已发布的公共素材，只读
/tmp              本次运行独立临时目录
```

- 不挂载其他用户目录、宿主机租户根、服务端数据库、Docker socket 或服务端凭据。
- 非特权运行，关闭宿主机 PID/网络等共享命名空间，限制资源；外部访问经受控工具或代理。不能让执行代码通过宿主机服务绕回读取全量文件。
- 为运行设置独立的临时目录、HOME、缓存和浏览器 profile；浏览器 Cookie、下载目录不能在用户间复用。
- 沙箱无法启动或身份不完整时，拒绝代码执行，不能回退到宿主机执行。
- 在沙箱交付前，只能开放完成用户边界校验的受控工具。仍开放宿主机任意代码执行的版本，不能作为“用户数据私有”的完成版本验收。
- 容器配置仍需验证实际挂载和权限；只读挂载的机制可参考 [Docker Bind mounts](https://docs.docker.com/engine/storage/bind-mounts/)。

模型进程可以共享，但含用户状态的运行实例、MCP 会话、浏览器状态和可变缓存必须按可信身份隔离。建议运行缓存键为 `(tenant_id, owner_user_id, agent_id, session_id)`，命中后继续验证归属；纯模型连接池和不可变配置仍可复用。

## 6. 下载与预览

- 私人文件统一经带身份的文件接口输出，设置 `Cache-Control: private, no-store`，避免当前 `public` 缓存策略复用私人内容。
- 旧的 `/uploads/...`、`/api/file?path=...`、目录预览 token 都必须收紧或迁移。只新增安全接口、保留旧接口可读同一文件，会留下旁路。
- 第一版建议由已登录页面获取文件或预览资源清单，再用 Blob/隔离 iframe 展示。HTML 所引用的图片、脚本和样式只能来自授权后的产物集合，并将相对引用解析到该集合；不能授权任意父目录。
- 生成 HTML 在隔离 iframe 中运行，默认限制外部网络，避免与主站认证环境共享权限。需要额外外部资源时按产品规则显式开放。
- 若后续保留 token 预览，token 必须有短有效期、限定文件或产物集合，并绑定有效登录会话、tenant 和 owner；消费时重新校验。token 中写了 owner 字段并不证明访问者就是 owner。
- 当 iframe 无法携带身份时，应调整为父页面鉴权取数或其他会话绑定方案，不能为兼容展示降级为“持有链接即可读取私人文件”。
- 对非本人使用统一的无权访问/不存在响应，避免返回文件详情。撤销、删除及成员停用后新请求立即失效。

将文件存于 Web 公开根之外、通过应用层标识映射访问，也符合 [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 的存储建议。

## 7. 记忆、检索与后台任务

- 自动摘要、记忆固化和用户上传资料建立的知识索引默认私人。共享智能体的公共记忆只由明确授权的管理/发布操作维护。
- 保留现有会话 owner 和记忆 scope 的设计，统一覆盖向量检索、全文检索、重排输入、片段缓存、提示词缓存以及历史文件原文读取。
- 私人资料不得通过自动提炼写进公共 MEMORY.md、公共知识库、共享提示词或可供他人读取的运行日志。
- 子智能体、委派、队列、定时任务、重试和取消后清理都携带可信的原始 owner；切换执行智能体不改变产物所有者。
- 任务持久化身份只记录内部身份标识，不保存可外传的登录密钥。任务执行时按任务类型重新检查成员有效性和权限，不接受模型指定新的执行用户。
- 无法识别用户的外部渠道消息不能回落到共享私人空间；需要可信渠道身份绑定。多人群聊中的公开回复与附件会被群成员看到，因此个人私有模式应使用私聊/个人入口，或只返回需本人登录才能读取的结果入口，不把私人正文发送到群中。
- 操作日志尽量记录 ID、状态和错误类别；需要保留正文的调试记录同样按 owner 隔离，并设置保留周期。

## 8. 迁移和交付顺序

> **交付状态（2026-09-24）**：本 change（`isolate-shared-agent-user-data`）交付的是**平台文件面**的本人目录规则，即「阶段一 · 第 5 条」的收敛部分：
>
> - 已交付：共享 Agent 下的 `user/<user_id>/uploads|outputs|work` 落点（`common/state_dir.py`）、`ObjectScope` 与共用文件路径策略的 owner 前置校验（`auth/object_scope.py`、`channel/web/fork/handlers/files.py`）、上传与回传落点（`channel/web/fork/runtime.py`）、面板 tree/search 的进入前剪枝与目标目录拒绝（`channel/web/fork/handlers/workspace.py`）、私人文件不自动公开复制（`agent/tools/send/send.py`）、前端迟到响应丢弃（`channel/web/static/js/workspace.js`）。
> - 已交付：可重跑的旧文件迁移脚本 `scripts/migrate_agent_user_files.py`（按可信记录归属，无法唯一归属的进入 `user/_legacy/<原 legacy 根>/...` 隔离区，保留相对路径以免同名相撞，且对文件接口不可读）。已在真实租户 `test15` 上 dry-run（75 个文件、0 碰撞），`--apply` 尚未执行。
> - **未交付（仍为方案）**：下文阶段二的执行层隔离（`profile.workspace` 配置根与运行根分离、沙箱、文件对象仓储与配额），阶段三的索引/记忆/后台任务全链路 owner 贯彻。共享智能体内的 Python/Shell/技能/coding 保持现状，脚本直接读盘的用户隔离**不在**本次验收保证内。
> - 验收证据见 `openspec/changes/isolate-shared-agent-user-data/evidence.md`；需求基线以该 change 的 spec delta 为准，不以本文档为准。

### 阶段一：确定归属、封堵现有读取入口

1. 建立文件仓储、统一授权服务和私人目录解析。
2. 盘点旧 uploads、生成文件、个人记忆、索引、临时目录及旧链接。
3. 从可信会话消息、上传记录和运行记录恢复唯一 owner；仅凭文件名、时间或路径猜测不算可靠归属。
4. 无法确认或存在多个候选 owner 的旧运行文件进入隔离待认领区，由有凭据的流程处理，不继续默认共享。明确发布的公共资料另建白名单。
5. 一并收紧旧下载、预览、文件浏览、平台浏览和原始数据库访问路径；处置旧 token 和缓存。已被其他人下载的副本无法通过迁移收回。

### 阶段二：完成端到端私人运行

1. 上传、生成、转换、目录搜索、预览全部接入文件对象授权。
2. 初始化器分离配置根和运行根；文件工具、沙箱、缓存及子任务贯彻用户身份。
3. 记忆及索引禁止私人数据进入共享域，迁移旧用户目录。
4. 前端默认显示“本次会话文件”，提供“我的文件”；公共资料单独只读展示。
5. 文件存储限额、会话保留策略、孤儿上传和运行临时目录清理按 owner 统计处理。停用、删除和备份恢复不得改变归属。

### 阶段三：验证与切换

以租户为单位灰度，新旧映射可追踪、迁移可重跑，并核对文件数量、校验和及引用一致性。回滚时保留已建立的私人归属；可暂停新运行，不能恢复“旧共享目录全部可读”。

阶段一是风险收敛，阶段二和验收通过后才可对外承诺完整的用户私有运行数据。需要任意代码的共享智能体，必须在沙箱就绪后开放该能力。

## 9. 验收条件

准备同租户用户 A、B，另一租户用户 C，租户管理员与平台管理员：

1. A/B 同时使用同一共享智能体，上传同名文件、生成同名报告，各自内容和工作目录互不覆盖。
2. B 即使拿到 A 的 file_id、旧 URL、绝对路径、预览链接或 session_id，也无法列出、读取、搜索、预览、下载、修改或删除 A 的资料；文件名和搜索统计也不泄漏。
3. A 让智能体读取 B 的资料，通过文件工具、Shell/Python、技能、MCP、浏览器下载和附件发送都无法完成；父目录、软链接和临时目录不能绕过。
4. 管理员仅能管理配置与查看允许的统计数据；通用平台文件浏览不能绕过私人 owner。
5. A 的上传资料、会话摘要、记忆和向量检索片段不进入 B 的回复；公共知识仍可被获准用户使用。
6. 跨智能体委派、异步任务、定时任务、服务重启和重试后，数据仍归原始用户；身份缺失、停用或授权服务故障时拒绝相关操作。
7. 旧预览链接、缓存、HTML 相对资源、缩略图和原始文件端点执行同一规则。
8. 无 owner 的历史运行文件保持隔离；迁移中断、回滚、删除和备份恢复均不重新公开。
9. 验证“未建会话先上传”、跨会话引用、智能体停用后本人历史文件访问，以及群聊入口的私人结果投递行为。
