# 企业岗位调研问题库

更新日期：2026年10月21日

本题库配合[企业调研与智能体场景规划方案](enterprise-agent-planning-advisor.md)，先根据公司名称、实际业务和受访岗位确定访谈内容，再从工作日程、作业方法和资料使用中识别高频、高耗时、高业务价值且容易试点的具体任务。

下列岗位与工作内容是访谈线索，不代表受访企业必然存在这些职责或频次。先结合企业业务调整，再按实际职责和已知信息选择问题，每轮只问 1～3 个相关问题；无需逐项遍历。规模小、兼岗多的企业按职责组合使用。

## 开场和背景问题

第一轮优先问：“您所在公司的名称是什么？您在哪个部门、担任什么岗位？”随后根据已有回答选择补充问题：

1. 公司名称有歧义时：方便补充所在城市、官网或所属业务单元，帮助确认是哪家公司吗？
2. 企业主要提供什么产品或服务，面向什么客户？您负责其中哪一块业务？
3. 这块业务按什么方式开展：标准产品、客户定制、项目交付或持续服务？请用一个近期订单或项目说明。
4. 您亲自负责哪些工作，哪些由团队成员承担？还兼任其他职责吗？
5. 最常与哪些部门协作？主要使用什么系统、表格或资料？
6. 这次最想改善什么？有没有最近发生的具体例子？

能够查到公司资料时，用核实式提问：“公司公开介绍提到……，这与您所在业务单元的实际情况一致吗？”没有检索或无法确认时直接请用户补充，不假装已了解公司。用户不便提供公司名时可匿名继续。面对一线人员，不要求其猜测公司预算、经营战略或接口权限。

## 从公司背景选择访谈主题

先由用户开放描述实际职责，再根据已确认的业务模式补漏。以下是条件式提问示例；只有相应职责存在时才继续深入。

| 岗位与业务情境 | 先确认的问题 | 确认后深入的方向 |
| --- | --- | --- |
| 定制制造业务的销售 | 您是否要根据客户规格或图纸准备报价？ | 规格澄清、历史资料检索、技术协同、价格及交期依据、版本变化 |
| 贸易业务的销售 | 报价是否要同时核对货源、库存和供应商条件？ | 多来源资料、报价有效期、规格与单位、承诺确认、发运跟进 |
| 软件服务业务的销售 | 您是否负责需求沟通、演示、试用或续约？ | 需求记录、产品能力核对、方案准备、试用反馈、技术问题交接 |
| 制造业务的成本会计 | 成本工作是否需要归集材料、工时和费用？ | 数据取得、订单或产品关联、口径、归集规则及差异追查 |
| 电商业务的财务 | 是否需要核对平台结算、退款和手续费？ | 多平台账单、订单关联、周期差异、异常追查与确认 |
| 工程业务的财务 | 是否按项目跟踪成本、结算资料和收款节点？ | 项目台账、进度依据、资料完整性、跨部门确认及汇总 |
| 制造业务的采购 | 是否根据物料需求采购并协调到货？ | 规格与编码、供应商报价、缺料、在途、催交和质量反馈 |
| 项目业务的采购 | 是否需要按项目范围采购材料、设备或服务？ | 清单版本、技术要求、报价范围、节点、变更和验收材料 |
| 连锁业务的人力人员 | 是否要处理多个门店的排班、考勤或人员调配资料？ | 门店汇总、例外核对、资料催收、规则差异和重复录入 |

管理层关注改善目标、团队总投入及验收，执行人员关注实际操作，系统或数据人员关注资料取得和连接条件。同一任务可由多个岗位补充信息，但不能把同一份工时重复汇总。

建议向用户概括：“结合您刚才介绍的业务和职责，我想先了解 A、B、C 三类工作，再补充周月固定事项。哪些需要调整？”记录用户修正；题库里没有的新工作也要纳入。

## 按周期盘点工作

| 周期 | 调研问题 |
| --- | --- |
| 每天 | 昨天从上班到下班先后做了什么？哪些是每天固定的，哪些是临时的？上午下午是否不同？昨天是否有代表性？哪些任务一天重复多次？ |
| 每周 | 哪些报表、会议、检查、计划和对账每周固定发生？集中在哪一天？准备和跟进分别要多久？ |
| 每月 | 月初、月中、月末有什么不同工作？最忙的几天在做什么？哪些结算、盘点、分析和考核集中发生？ |
| 每季度与每年 | 有哪些预算、规划、审计、评估或集中业务？要准备多久？哪些资料因为平时未积累而需要集中补做？ |
| 临时事件 | 遇到客户询问、插单、缺料、投诉、故障或人员变动时做什么？最近一个月发生几次？ |
| 旺季与特殊时期 | 工作量何时上升？次数、复杂度还是异常更多？哪些任务导致加班或临时增员？ |

用户已谈过的周期直接小结，不重问；确认“不适用”“暂时跳过”和“尚不清楚”，不能把沉默记成没有任务。

## 每项任务的深入问题

| 主题 | 追问方式 |
| --- | --- |
| 真实实例 | 最近一次从什么消息或材料开始？最后交付给谁什么结果？能按实际顺序讲一遍吗？ |
| 具体操作 | 您先打开哪个系统或文件？接着查、复制、计算或编写什么？哪些步骤在多个工具之间反复切换？ |
| 发生次数 | 昨天、上周或上个月做了多少次？这是个人的还是全团队的次数？ |
| 每次业务量 | 一次是一张单、一个客户，还是一批文件？一批有多少明细？ |
| 正常和复杂耗时 | 正常一次多久？复杂情况多久？复杂情况大约占多少？估计依据是什么？ |
| 准备资料 | 需要哪些资料？分别在哪里、找谁拿、如何确认最新且齐全？找资料、催收、下载和整理格式各多久？ |
| 处理与判断 | 阅读、录入、计算、比对、判断和编写分别花多久？ |
| 检查与返工 | 谁检查、检查多久？多久退回一次？返工时间是否已经包含在刚才的总时间里？ |
| 沟通与等待 | 实际沟通花多久？等他人回复多久？等待时能否做别的工作？ |
| 人员投入 | 谁执行、谁协助、谁复核？各自投入多久？同一工作是否被不同人重复处理？ |
| 截止时间 | 最迟何时完成？逾期影响什么？是否有集中加班期？ |
| 资料与输出 | 输入来自哪些系统或文件？已有一个合格输出样例吗？哪些资料当前能获权使用？ |
| 规则和例外 | 新人按说明能完成哪些步骤？哪些判断依赖经验？最常见例外有哪些？ |
| 实际作业方法 | 书面说明与实际做法一致吗？您为什么用现在的方法？能举一个必须靠经验改变处理方式的例子吗？ |
| 输出及归档 | 什么样的结果算合格？完成后存在哪里、交给谁、录入到哪里？下次哪些内容能直接复用？ |
| 现有办法 | 目前工具能解决多少？哪些功能已有但未使用，为什么？ |
| 最小帮助 | 如果只替您完成一个步骤，哪一步最有帮助？产物怎样检查才放心？ |

先了解整项工作，再定位最耗时步骤。需要时把“做报表”“做采购”拆成资料准备、处理、核对、解释、交付和后续行动，避免直接用一个宽泛名称推荐智能体。

## 资料收集和样本核对问题

先了解资料目录，再围绕重点任务请求材料；无需用户先上传整套公司资料。每次说明想核实的问题，使用当前实际可读取的材料。

| 主题 | 问题示例 |
| --- | --- |
| 公司与职责背景 | 有现成公司介绍或职责说明可参考吗？其中哪些内容与您的实际业务不同？ |
| 任务输入 | 上次处理这项工作用到了哪些文件、消息和系统记录？能按先后列一下吗？ |
| 作业依据 | 用什么制度、公式、标准、模板或历史案例做判断？当前有效版本由谁确认？ |
| 资料取得 | 您怎样找、向谁要、多久能拿到？哪些步骤最费时？是否反复催收？ |
| 数据关联 | 两份资料怎样认定属于同一订单、项目或客户？关键编号、单位和期间一致吗？ |
| 完整性和更新 | 怎样知道资料齐了、没过期？缺项、重复或版本冲突时怎么处理？ |
| 正常样例 | 为核实处理步骤，能否提供一组获权可用的实际输入和已确认结果？需要时可先脱敏。 |
| 异常及返工样例 | 有没有一例普通办法处理不了或被退回修改的情况？当时缺什么依据，后来如何解决？ |
| 可读性与格式 | 是可导出的表格、正文文档、截图、扫描件还是纸件？哪些内容还要手工转录？ |
| 持续获取 | 本次拿到样例后，日常每次使用还能这样取得吗？谁更新、多久更新、每次准备多久？ |
| 使用范围 | 哪些资料可用于本次调研和后续试点？哪些字段需删除或遮盖？ |
| 样本核对 | 您刚才说按订单号匹配，这份样例中部分订单号为空，这类情况平时如何处理？ |

若用户只提供模板，记录为模板；若只有口述，记录为口述。不能据此判断真实数据已经可用。材料暂时无法提供时，先记录关键字段、样例结构、责任岗位及待验证问题，继续访谈。

## 根据回答调整下一问

| 已得到的回答 | 下一步 |
| --- | --- |
| 公司介绍说做制造，用户实际负责贸易业务 | 以其业务单元为范围，核实货源、报价和交付方式，调整访谈主题 |
| 岗位叫销售，实际还做售后和订单跟进 | 分别盘点三类职责，合并共用资料，避免遗漏兼岗劳动 |
| 只说每天很忙，列不出具体任务 | 从昨天收到的第一条业务消息或第一个文件开始回顾 |
| 只说制作报告，不清楚具体步骤 | 询问最近一次从哪里取数，怎样整理、计算、解释并交付 |
| 任务要两天，但多数时间等资料 | 分开记录人工查找、催办、处理时间与被动等待，分别判断可改善部分 |
| 日常重复不多 | 继续了解每周、月末、项目交付和旺季集中工作 |
| 公司已有软件，却仍在手工处理 | 了解软件已解决哪些步骤，人工处理是因资料、规则、功能还是使用习惯 |
| 样例和描述不一致 | 请用户解释样例的时期、版本及是否属于例外，保留不同来源 |
| 价值很高，但数据散落、难以取得 | 先量化收集成本和确认责任岗位，判断能否从一类资料小范围试点 |
| 已有足够背景、任务和样本 | 汇总已知内容，补问影响价值或可行性判断的缺口，不继续遍历题库 |

## 管理与经营岗位

| 岗位 | 周期盘点线索 | 岗位追问 |
| --- | --- | --- |
| 企业负责人或总经理 | 日常异常决策；周经营沟通；月经营复盘；季度年度目标 | 最重要的经营改善是什么？哪些信息总拿不到或拿得晚？先解决哪个部门的问题最有价值？谁能牵头试点？ |
| 运营负责人或 COO | 日常跨部门协调；周交付与资源检查；月运营分析 | 哪条流程最容易积压？哪些异常靠人催才被发现？汇总状态和协调分别多久？哪些规则已明确？ |
| 战略或经营分析人员 | 临时研究取数；周专题分析；月经营报告；年度规划 | 哪些分析反复重做？拼数据、解释和做材料各多久？管理层最常追加什么问题？分析结果怎样转成行动？ |
| 部门负责人 | 日任务分配与成果检查；周进度和例会；月指标与资源安排 | 团队累计最耗时的三项工作是什么？哪项最依赖熟练员工？准备汇报和您复核追问各多久？什么结果算试点成功？ |
| 项目经理或 PMO | 日进度和问题协调；周报与会议；月预算及里程碑 | 每周几场会议，纪要和行动项整理多久？进度从哪里收集？哪些风险发现晚？变更影响如何评估和确认？ |

## 销售与客户岗位

| 岗位 | 周期盘点线索 | 岗位追问 |
| --- | --- | --- |
| 销售负责人 | 日重点商机协调；周销售进展；月预测和业绩复盘 | 汇总进展要追问多少人？哪些商机长期停滞？预测为什么不准？哪些经验可以重复使用，哪项改善能被观察到？ |
| 销售人员或客户经理 | 日客户回复、报价、跟进；周商机整理；月业绩汇总 | 每天几次报价或回复？每次查哪些资料、问哪些人？CRM 有哪些重复录入？价格和交期承诺由谁确认？ |
| 售前或方案工程师 | 日需求澄清；周方案和评审；月案例及资料整理 | 一份方案中多少内容重复？查参数和案例多久？客户要求最常遗漏什么？哪些技术判断必须验证？ |
| 报价或投标专员 | 日询价和文件处理；周比价或项目跟踪；月报价复盘 | 每月多少份资料，格式如何？核对规格、费用、交期和资格分别多久？哪些条款易漏？谁审核最终内容？ |
| 市场或品牌运营 | 日内容和信息整理；周活动执行；月效果复盘 | 找素材、核实事实和写初稿各多久？产品资料在哪里？活动线索怎样交给销售？什么内容需要审核才能发布？ |
| 电商或渠道运营 | 日商品维护、订单和投放观察；周活动；月渠道分析 | 哪些平台重复维护同一信息？每天拼哪些数据？如何发现退货或销售异常？哪些调整只能提出建议？ |
| 客服人员 | 日咨询和工单；周未结项与重复问题；月服务统计 | 每天多少咨询属于重复问题？查一个答案多久？资料如何保证有效？什么问题必须转交，怎样确认解决？ |
| 售后或客户成功人员 | 日客诉与服务跟进；周交付检查；月客户和问题复盘 | 排查要查多少历史记录？交接常缺什么？哪些问题反复出现？报告和解释花多久，哪些情况必须升级？ |

| --- | --- | --- |

## 生产工程与质量岗位

| 生产负责人 | 日产量和异常；周产能交付协调；月效率与损耗 | 掌握现场状态需要多少汇总沟通？哪些异常发现晚？主要瓶颈是什么？哪些建议仍须现场确认？ |

## 业务价值追问

| 受访者表达 | 下一步追问 |
| --- | --- |
| 能提高效率 | 节省谁的什么操作？每月多少时间？省下后用于什么工作？ |
| 能减少错误 | 常见错误是什么？多久出现一次？修复多久，影响什么后续业务？ |
| 能提升客户体验 | 当前多久回复？哪些问题导致重复咨询或投诉？改善如何观察？ |
| 能帮助销售 | 是更快报价、减少遗漏、改善跟进还是准备资料？哪个结果可测量？ |
| 能辅助管理 | 谁看结果并采取什么行动？目前缺什么信息，造成什么延误？ |
| 能降低风险 | 具体提前发现什么异常？谁核实处理？有什么历史实例能验证？ |

对没有使用者和后续行动的报告需求，继续澄清用途；不能仅凭“分析很全面”认定高价值。请用户分别选出最耗时、最重复、业务帮助最大的几项任务，再比较其依据。

## 容易落地的核对问题

1. 当前就能取得几份真实输入样本吗？资料是否获准使用？
2. 是否有清楚的合格输出或现成模板？规则由谁确认？
3. 能否先限定一个岗位、一类资料或一个步骤？
4. 结果能否快速复核？复核是否会变成重新做一遍？
5. 发现错误后怎样处理？能否回到原有流程？
6. 谁愿意提供样本、试用并反馈？实际使用入口在哪里？
7. 项目现有能力是否经核实适用？还缺哪些资料或配置？
8. 如果先只生成草稿或异常清单，由人确认，是否已经产生价值？

可讨论的候选方向包括知识查询、重复答复准备、多表核对、材料提取、异常整理、会议行动项和报告初稿；这些方向都要由真实频次、耗时、样本及复核条件证明，不能直接当作推荐结论。

## 定制设备企业销售访谈示例

以下为虚构对话，用于展示每轮围绕一个主题推进的方法。

**顾问**：您所在公司的名称是什么？您在哪个部门、担任什么岗位？

**受访者**：示例设备公司，我在销售部做销售工程师。

**顾问**：公司主要提供什么设备？您负责的业务是销售标准产品，还是根据客户要求定制？

**受访者**：我们做定制检测设备。我负责前期需求沟通、报价，也要跟进交付。

**顾问**：我先围绕需求、报价和交付跟进了解，再补充周月固定事项。请回顾昨天从上班到下班，主要处理了哪些事情？

**受访者**：上午整理了一个客户的规格要求，找工程师确认；下午做两份报价，还催了一个订单进度。

**顾问**：其中哪项最费时间？以最近一次为例，您收到什么资料后开始，实际按什么步骤处理？

**受访者**：整理规格要求。客户发来文件和聊天说明，我先合并内容，再查以前类似项目，列出疑问问工程师。

**顾问**：上周您个人处理了多少次？每次找资料、整理和核对大约各多久？

**受访者**：上周三次，大概每次两小时，找历史项目就要一小时。具体没记过。

**顾问**：先记为上周个人三次、每次约两小时的估算。历史项目存在哪里，您按什么条件判断能参考？

**受访者**：文件夹里，主要看检测对象、参数和配置，但版本有时找不准。

**顾问**：为了核实资料是否能支持整理，可以先提供一组获权可用、必要时脱敏的客户要求、参考项目和最终需求清单吗？我想对照您实际怎样提取和判断。

**受访者**：可以整理一个已经做完的例子。

**顾问**：如果更快形成带出处的需求清单和待确认问题，会怎样影响后续报价？由您检查还是工程师检查，通常需要多久？

此时可将“客户需求整理与历史项目依据检索”列为待验证候选，继续核实样本版本、可比较条件、遗漏或误配的后果、复核时间及日常资料取得成本。最终价格、技术可行性和交期由对应岗位确认。随后回到尚未了解的报价、交付跟进及周月固定任务，不能凭这一个实例直接断定它是全岗位最优场景。
