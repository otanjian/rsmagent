# IM 访客账号（IM guest access）

面向租户管理员与实施人员的管理说明。对应变更 `add-im-guest-accounts`（规范：`im-guest-access`，以及 `external-identity-binding`、`user-membership`、`identity-session`、`tenant-channel-configuration`、`role-resource-authorization` 的增量）。

## 它解决什么问题

未在平台注册的飞书 / 企业微信用户，向租户共享机器人发消息时默认会被拒绝并提示“请联系管理员绑定”。开启访客访问后，租户管理员可以让这些用户**直接使用该机器人**，由系统在首条消息时自动创建一个持久访客账号；访客可以对话、保留历史，但**不能登录平台**。

“访客”指未关联正式账号的身份，不是临时会话：账号、成员关系、历史都稳定保存，改名不影响身份。

## 在哪里配置

管理控制台 → 模型与接入 → 消息渠道 → **租户共享机器人**卡片 → 编辑 → **访客访问**。

只有 `scope=tenant`（租户共享）的实例可以开启；个人实例只服务其所有者，不能开放给陌生人。

三个配置项：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 未绑定用户 | 要求先绑定账号 | 保持现状；改为“自动创建 IM 访客”才开放 |
| 访客角色 | 空 | 开启时必选本租户的普通角色；不能是租户管理员，也不能含身份/配置管理类权限，且必须包含“使用对话” |
| 访客群 ID | 空（仅私聊） | 每行一个提供方群 ID，精确匹配；不支持通配或群名；全局 `ALL_GROUP` 不能绕过它 |

保存沿用渠道实例的版本校验：页面版本过期会提示冲突并保留草稿；旧客户端不传这三个字段表示保留原值。

## 访客能做什么

- 只能通过**已验证来源**的消息渠道交互；身份由 `(provider, issuer, subject)` 唯一确定，昵称仅作显示名。
- 每次实际调用（模型、工具、子运行）的权限 = **成员角色授权 ∩ 当前渠道的访客角色授权**，再叠加既有租户/资源/Agent/配额限制。同一访客在别的渠道获得的角色不会扩大本渠道权限。
- 私聊、附件、历史按既有租户/用户归属隔离；群聊保留真实发送者，不注入个人私聊记忆。
- 不能登录 Web/桌面，不能取得个人 API 凭据，不能改密或通过重置密码“转正”，不能创建定时任务或执行本机代码。

## 停用与恢复

- **停用某个访客**：成员页（现有页面）把该成员设为停用。作用范围是该访客在**本租户的全部机器人**，其他租户不受影响；历史保留。
- **关闭某渠道的访客**：把该渠道的“未绑定用户”改回“要求先绑定账号”。该渠道的访客全部被拒绝，已有正式账号不受影响。
- **解绑某个访客**：在成员的外部身份弹窗里解绑。访客映射会被**标记停用**而不是删除，防止下一条消息重新开户；列表里显示“已停用”，可点“恢复”重新启用**原映射**（不会连带恢复账号、成员或角色）。
- 重新开启渠道或恢复映射都不会自动恢复已停用的账号/成员/角色。

## 不包含（本期边界）

- 访客与正式账号的自动关联、转正、历史迁移。
- 自动到期清理、按人按实例封禁、独立访客管理页。
- 新的开户配额体系；运行成本仍由既有硬配额与入口限流控制。

## 实施与验收顺序

1. 部署具备账号类型与访客授权守卫的版本（迁移只为既有数据补默认值：普通账号、要求绑定、映射有效）。
2. 用测试实例分别验收飞书、企业微信（每个提供方独立验收，未验收的提供方不要开启）。
3. 逐个实例开启；回退时先关闭访客接入，只使用理解访客限制的兼容版本，或停机一致恢复，不把访客改成普通账号。
