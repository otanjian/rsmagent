# macOS SAP 工作台常用入口与布局记忆

本次只实现四项：新会话快捷引导、页面采集反馈、账号与连接菜单、布局记忆。返回首页保留业务现场、整体连接状态区和平台免重复授权不在本次范围。

界面调整：按后续要求隐藏“账号与连接”（含登录记忆状态）、页面读取按钮与采集反馈、空会话快捷引导。聊天区直接接在助手标题下方；已有登录记忆、对话工具读取及布局记忆逻辑保持有效。下面记录的是原有能力与验证过程。

空会话欢迎语：在 OpenCode 会话正文中显示用户指定的两段欢迎语，包含页面解读、报错分析、业务查询、事务代码、需求梳理和 ABAP 编写能力。仅当嵌入来源标记为 `rsm_scene=sap_workbench` 且消息列表已加载为空时展示；有消息后自动隐藏。欢迎语属于界面文案，不触发模型、页面读取或消息保存，之前隐藏的快捷卡片保持隐藏。

- 空会话展示“总结当前页面”“解释当前报错”“打开事务”。前两项调用当前 OpenCode 会话的输入框发送请求；打开事务只填入草稿，用户补充事务码后发送。已有草稿不会被覆盖，助手忙碌时暂停快捷操作。默认会话标题使用现有中文翻译。
- “读取当前页面”复用 `sap_page_read`，采集结果经原有服务端请求通道确认后，显示页面标题和采集时间。页面导航后将上次采集标记为过期；界面只保留采集元信息，不另存页面内容或聊天。
- 登录记忆状态常驻显示；记住/清除登录入口放入“账号与连接”。菜单说明清除本机记忆与退出当前 SAP 会话是不同操作。
- 分栏比例和助手展开状态写入既有 `desktop-remote.json` 的 `preferences.sapWorkbenchLayout`。窗口大小继续使用既有 `window-state.json`。缩小窗口时给 SAP 保留约 560 CSS px，临时压缩助手不会覆盖用户偏好的比例。

## 边界

原生桥增加 `sapWorkbenchLayout({action:'load'})` 和 `sapWorkbenchLayout({action:'save',ratio,open})`。沿用主文档、来源和文档代次校验，保存只接受有限比例（0.1–0.8）及布尔展开状态，不接受额外字段或路径。

OpenCode 的两套输入框共用 `createEmbedComposer`。消息必须来自本次嵌入的父窗口、精确来源和通道，并匹配当前会话。仅传递提示词及空会话/忙碌/草稿状态；模型、消息、草稿和发送逻辑仍由 OpenCode 自己维护。

## 验证（2026-10-06）

- 桌面构建、OpenCode app 类型检查通过。
- 工作台、原生桥和桌面配置共 153 项测试通过；OpenCode 嵌入协议及标题显示 19 项测试通过。
- 两种 OpenCode 输入框的浏览器测试通过：填入事务草稿、拒绝覆盖草稿、通过原有发送接口发送页面读取请求。
- macOS 实机验证：中文快捷入口、事务草稿填入、草稿保护、账号菜单说明，以及重启后恢复展开状态和窗口大小。当前 test15 未登录 SAP；再次验收时 SAP 测试地址还出现 ERR_CONNECTION_CLOSED，独立 HTTPS 连通性检查也失败。本次未完成登录后业务页面采集的实机验收；成功结果的标题/时间及导航失效反馈由自动测试覆盖。
- 生产构建的会话切换基准已记录变更前后结果，场景均通过。后续测量受本机高负载影响，延迟波动明显，不能据此确认性能持平；本次不宣称性能提升。

远程平台和 OpenCode Web 源码已更新并保留部署备份；这次没有修改 OpenCode 项目插件，也没有引入独立模型或聊天存储。
