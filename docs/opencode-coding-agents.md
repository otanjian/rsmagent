# 编码智能体（OpenCode）部署与运维

本文件对应 OpenSpec change `add-opencode-coding-agents`。它面向**部署与运维**：平台侧要配什么、OpenCode 那边要提供什么、浏览器怎么认证、共享服务的信任边界在哪、以及升级与回滚怎么做。

功能行为与验收口径以 `openspec/specs/` 下的规范为准（`opencode-coding-agents`、`opencode-embedded-chat`、`opencode-session-sync`、`session-history-workbench`、`agent-chat-launch`、`execution-isolation`）；本文件只是把这些能力对应的**环境要求**写清楚。

## 1. 全局配置

编码能力只有一个开关块，位于平台配置文件（`config.json`）顶层，缺省关闭：

```json
{
  "opencode": {
    "enabled": false,
    "service_id": "default",
    "api_url": "http://127.0.0.1:4096",
    "web_url": "",
    "username": "opencode",
    "password_env": "RSM_OPENCODE_PASSWORD"
  }
}
```

| 键 | 含义 | 说明 |
| --- | --- | --- |
| `enabled` | 能力总开关 | `false` 时：不创建远端会话、不调用任何模型，但**不删除**任何档案、关联或缓存（见 §6） |
| `service_id` | 服务实例标识 | 关联表按它区分实例。**换值等于换服务**：旧关联的会话标识属于另一个实例，平台按「服务已变化」拒绝继续使用，不会把旧 ID 当成新实例的会话 |
| `api_url` | 服务端连接地址 | 平台后端用它调用 OpenCode API（`/api/*` 与兼容路由）。用户浏览器不直接访问它 |
| `web_url` | 浏览器可访问的 Web 根 | 嵌入 iframe 的地址来源（见 §3）。**必须**是用户浏览器能打开的地址，不是 `127.0.0.1`，除非部署确实同机 |
| `username` | 服务端连接的 HTTP Basic 用户名 | 缺省 `opencode`，与上游默认一致 |
| `password_env` | 存放口令的**环境变量名** | 只写变量名，不写口令本身 |

口令相关约定：

- 口令只从 `password_env` 指定的环境变量读取，**每次请求实时读取**，因此轮换口令无需重启即可对下一次调用生效；变量未设置即视为「无凭据」，而不是空口令。
- 口令只用于**平台后端**到 OpenCode 的连接，绝不进入任何 API 响应、控制台投影、iframe URL 或页面消息。`/api/coding/settings` 只返回开关、服务标识、浏览器地址与是否可用。
- 关闭能力不需要删除该块；把 `enabled` 置 `false` 即可，其余字段留作重新启用时的现场。

部署检查清单：

1. `web_url` 从**用户机器**能打开（`curl` 一下），且与 `api_url` 指向同一台服务的同一份数据。
2. `password_env` 指向的环境变量在平台进程里可见（`enabled=true` 且口令缺失时，调用会以上游不可达失败，而不是静默降级）。
3. 反向代理放行 SSE 与 WebSocket（§3）。

## 2. 「远端项目目录」的含义

创建 coding 智能体时要填的 `coding_project_dir`（控制台显示为「项目目录」），指的是**OpenCode 主机上的一个已有绝对路径**，不是平台的 `agent_workspace`，两者互不相关：

- **平台不创建、不校验、不修改它**。目录不存在时上游同样接受创建请求（已实测），所以「目录写错」不会在创建表单报错，而会在嵌入页里表现为一个空项目——这是需要运维在交付前确认的字段。
- 目录可以非空，且通常就是已有的代码仓库；平台**不会**在其中写入状态、索引或凭据，删除 coding 会话也**不触碰**该项目目录里的任何文件（仅删除远端会话记录）。
- 目录是**会话的项目快照**：会话创建时记录在关联行里，之后编辑智能体的默认项目**不会**移动已有会话。
- 每个会话在平台上按「智能体 + 会话」区分，在 OpenCode 侧按项目目录定位。因此**同一目录被多个智能体使用时，它们看到的是同一个代码工作区**，只是会话各自独立。

复制 coding 智能体只复制档案与项目配置，不带入原会话、凭据或任何代码文件。

## 3. 配套 Web 根路径部署

嵌入地址由平台拼装，不来自用户输入：

```
{web_url}/{base64url(项目目录, 无填充)}/session/{外部会话 ID}?rsm_embed=1
```

控制台挂载 iframe 时再追加两个**每次挂载都不同**的参数：

```
&rsm_parent_origin=<父页 origin>&rsm_channel=<本次挂载的随机通道>
```

要求：

- `web_url` 必须是**同一版本**的 OpenCode Web 构建的根路径。上游前端与后端 API 有版本耦合，混用不同版本的 UI 与后端会出现难以定位的失败；升级时两边一起升。
- `web_url` 必须是**带嵌入适配的 Web 构建**（即配套仓库那次定制构建），不能填 `api_url` 指向的 OpenCode 服务自身默认界面。服务自身附带的界面是**未适配**的上游构建：它不认识 `rsm_embed`，也不会回发 `rsm.opencode.ready`。此时平台侧表现是「面板能挂载、子页也渲染，但一直停在『正在打开编码会话…』直到重试提示」，容易误判成平台缺陷。核对方法：该构建的入口脚本里应包含嵌入上下文（仓库内即 `packages/app/src/context/rsm-embed.ts` 被打进产物）。
- 路径形态是 OpenCode 自己的路由（目录用 base64url 编码），反向代理**不得重写或剥离**路径前缀与查询串；`rsm_embed`、`rsm_parent_origin`、`rsm_channel` 必须原样到达前端。
- 反向代理需允许 SSE 长连接（不要缓冲）与终端的 WebSocket 升级；否则表现为「消息不刷新」「终端打不开」。
- 不要额外加 `X-Frame-Options` 或限制性的 `frame-ancestors`：嵌入正是设计的一部分，其作用域由 §5 的通道校验约束，而不是由禁止嵌入约束。
- 平台页面自身（`/chat`）与 `web_url` 可以是同域，也可以跨域；跨域时前端会带上父页 origin，子页只向该 origin 回发消息。

`rsm_embed=1` 是嵌入模式的唯一标记。它让 OpenCode 只留出「这一个会话」：重复的导航与全局服务设置（侧栏、项目切换、设置入口）被隐藏，**标题栏整条**也不渲染——其中的会话标签是第二套导航，会在平台不知情的情况下改变 iframe 指向——连同只有该标题栏渠道徽标才能开关的开发诊断条。输入、工具权限确认、代码差异、文件、终端与分叉等全部工作区能力**保留**；不带该参数的正常访问行为完全不变。

上表参数在**子页首次加载时**被读取并保存，随后子页可能按自身路由重写地址栏（例如收敛为 `…/server/<base64(api_url)>/session/<id>`），届时查询串不再出现在 `location.search` 里。这是 OpenCode 的正常行为，嵌入状态已在其内存中；平台侧**不得**依赖挂载后回读 frame 的 URL 来判断嵌入标记。

## 4. 浏览器认证

本 change **不引入新的认证流程**：嵌入的仍是普通浏览器会话，沿用 OpenCode 既有的两种方式。

1. **同源 + 既有会话（推荐）**：把平台与 `web_url` 放在同一个反向代理/单点登录之下，浏览器对 OpenCode 主机已有的 Cookie/会话直接生效，嵌入页打开即用，平台不接触任何用户凭据。
2. **OpenCode 自带的连接界面或令牌**：OpenCode 支持 Basic 凭据与 `?auth_token=<base64(user:pass)>`；用户在 OpenCode 自己的界面里完成一次连接即可。

平台侧的边界（与规范一致）：

- 平台**不会**把服务口令放进 iframe URL 或页面消息，也不会把服务端凭据下发给浏览器。用户在页面上能拿到的只有会话地址。
- 若某个部署确实需要一次性令牌，应由 **OpenCode 侧或反向代理**在浏览器会话层解决，而不是让平台去转发服务口令。
- 用户在嵌入页内的可见范围由 OpenCode 的目录权限决定；平台侧只保证「谁能打开这条会话」。

## 5. 共享服务边界（本 change 的验收范围）

首版是**一个管理员配置的共享服务**，不是一个用户一个实例：

- 会话隔离依据是**项目目录 + 由已验证身份派生的会话 ID**（派生自服务标识、租户、用户、智能体与请求 ID），而不是容器或操作系统账号隔离。
- 因此**同一目录的可见性等于 OpenCode 主机上的目录权限**：能通过平台打开该项目会话的用户，也就拥有该项目在 OpenCode 主机上的可见范围。不要把互不信任的租户指向同一个目录。
- 「无需用户输入服务密码、无需独立服务地址」是刻意的：租户不应各自搭建服务。
- **容器隔离、网络隔离、按租户的项目沙箱不在本 change 范围内**，本 change 只负责把共享边界写清楚并让入口授权生效。需要更强隔离时应作为后续 change 立项。

## 6. 升级、重新启用与回滚

### 升级

1. 先升级 OpenCode 服务与其配套 Web 构建，确认 `api_url` 与 `web_url` 指向新实例。
2. 再升级平台。平台首次打开数据库时会按既有 seam 创建 `opencode_session_links` 表（`CREATE TABLE IF NOT EXISTS` 与增量列同一路径，**不需要第二个迁移工具**，重复打开是幂等的）。
3. 旧的普通智能体不需要任何迁移：缺少类型字段的档案按 `normal` 处理，且保存时**不会被写回**类型字段。
4. 已有会话（关联行 + 缓存标题时间）继续可用；升级期间远端不可达只会标记为暂时不可用，不会删除任何记录。

### 重新启用（`enabled: false` → `true`）

关闭期间**保留**档案、关联与缓存。重新打开后：

- 已有 coding 智能体与历史会话照常出现，远端仍然存在的会话可直接打开；
- 关闭期间未能完成的创建会以 `creating` 状态留在列表里，可继续重试，沿用**同一个**外部会话 ID（不会产生第二条会话）；
- 关闭期间被远端删除的会话，在下一次刷新时收敛（明确 404 才判定为「已删除」）；
- 关闭期间不写任何新行（已实测：拒绝发生在触库之前）。

### 回滚

1. 把 `opencode.enabled` 置 `false`：coding 入口立即停止创建与会话调用，普通智能体路径不受影响；历史仍可查看，但不再刷新远端状态。
2. 若要完全移除功能面，回滚平台代码即可：`opencode` 配置块是新增键，旧版本忽略它；`opencode_session_links` 表是新增表，旧版本不读它；`sessions` 表的既有列与旧消息**不被本功能修改**，coding 会话不写 `messages` 行。
3. **不要**用回滚去删除远端项目目录或远端会话；平台从不触碰项目目录，远端会话由 OpenCode 侧自行清理。

### 交付前自检（可复现）

任一部署都可以用同一个脚本复现本节四项结论（临时目录、不接触生产数据）：

```bash
.venv/bin/python scripts/verify_coding_upgrade.py
```

它检查：无类型的旧档案按 `normal` 读取且保存不写回类型/项目字段、关联表被反复初始化后行数与数据不变、`enabled=false` 时拒绝且不落行不调用上游、重新启用后旧关联仍在且新会话可创建、项目目录与 `messages` 行不被改动。
