## 自动更新

桌面客户端内置自动更新能力。有新版本时会自动检测并提示，你也可以在应用左下角菜单中手动「检查更新」，一键下载并重启完成升级。

## 与命令行部署的区别

- **桌面客户端**：适合个人用户开箱即用，无需安装任何依赖，图形界面操作，支持自动更新。
- **命令行部署**：源码运行方式，适合开发者在本地或服务器部署，方便扩展功能，可定制性更强，详见 [一键安装](/zh/guide/quick-start)。

## 通过浏览器访问

桌面客户端启动后会在本机监听 `9876` 端口，其后端与 Web 控制台完全一致。因此在打开客户端的同时，也可以直接用浏览器访问 `http://localhost:9876`，获得与客户端界面一致的完整体验。

如果该端口不可用（例如 Windows 上被 Hyper-V/WSL2 保留），客户端会自动改用其它端口并正常启动。此时实际端口可在 `run.log` 中的 `Local access` 一行查到，也可以在 `config.json` 中设置 `web_port` 来指定固定端口。

## 账号与重新登录

桌面客户端使用与本机后端相同的账号体系：登录在系统浏览器中完成，客户端本身不接收密码。

- 在「账号菜单」中退出后，客户端会先确认当前会话退出，再结束本机原生会话、回收本地授权并关闭容器，然后回到客户端的登录界面。退出后**不需要重启应用**，重新登录即可继续使用。
- 容器页面提示需要重新登录时，请使用页面上的「重新登录」入口。它走的是同一套原生登录流程，不会在容器内单独创建一个只有 Web 的会话。
- 选择本地目录前需要处于已登录状态。如果目录绑定提示 `not signed in`，说明本机原生会话已经失效：退出后重新登录一次即可，无需清理数据或重装。

客户端与随包分发的 Web 控制台属于同一次构建，升级时整体替换即可，不需要单独升级其中一方；本改动不涉及数据库迁移，也不改变账号、角色或权限配置。本地目录不可用时仍会给出具体原因（权限、租户、网络或设备错误），不会退化为通用的失败提示。需要回退时，按 [升级指南](/zh/guide/upgrade) 替换回上一版本。

## 本地数据存储

桌面客户端的所有数据都保存在本机：

- **配置文件**：位于用户目录下的 `~/.cow`，包含 `config.json`（模型密钥、通道等配置）以及日志、缓存等运行数据。
- **系统工作空间**：默认位于 `~/cow`，用于存放对话记录、知识库、记忆、技能、定时任务等 Agent 产生的文件。

卸载客户端不会自动删除这两个目录，重装后数据依然保留。如需彻底清理或迁移到其他设备，手动备份或删除对应目录即可。
