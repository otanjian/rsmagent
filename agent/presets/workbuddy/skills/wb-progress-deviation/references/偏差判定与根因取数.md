# 偏差判定与根因取数 · 完整版

本文件是 SKILL.md STEP 1~3 的展开，可直接作为企业内部《生产执行偏差日跟规范》使用。

---

## 一、数据时点校验（这一步在所有分析之前）

### 为什么必须先做这一步

一个必须承认的现实：**工人赶工时不会停下来报工**。多数厂的报工是"等一批干完了才对着工单一次性补录"，所以：

- 系统里的"滞后 4 天"，可能有 3 天是没录、只有 1 天是真慢
- 反过来也有工单实际已经卡住两天，但因为还没到报工节点，系统里看起来一切正常

**在数据补齐之前，任何归因都是在替车间编故事。**

### 阈值表

```
距今小时数 = 当前时间 − 该工单最后一次报工时间
```

| 距今 | 判定 | 处理方式 |
|---|---|---|
| ≤ 24h | 可信 | 正常参与分析 |
| 24~48h | 可疑 | 滞后天数标注"可能含录入延迟"，根因结论加保留字样 |
| **> 48h** | **不可信** | **滞后天数标为不可信**；今日第一动作改为"补齐报工"；**不得输出根因结论** |
| 未开工 | 不适用 | 但要检查是否在等某个被占用的工位 |

### 一个容易忽略的连带检查

未开工的工单也要看：**它是不是在等某个工位，而那个工位被一张滞后的工单占着**。这类连带影响在单看工单表时是看不出来的，要靠班组备注（如"还没排上，等 0804 让出焊接工位"）或工序资源占用关系推出来。

### 为什么错误问责的代价特别大

一次基于错误数据的问责，会让车间**下次更不愿意报工**——报了就被追问，不报反而清静。这是个会自我强化的恶性循环，一旦形成，这个场景的数据基础就彻底毁了。

所以 Skill 的态度是：**宁可今天什么结论都不给，也不能拿不可信的数据去指认。**

## 二、三类偏差判定

### ① 欠数

```
欠数 = 计划数 − 累计完工数
```

判为偏差的条件：`当前工序 ∉ {已完工, 未开工}` 且 `欠数 > 0`

**注意区分"欠数"和"正常在制"**：粗加工阶段完工 120/500 是正常进度，不是偏差。判断依据是**计划完工日 vs 预计完工日**，而不是完成率高低。

### ② 滞后

```
滞后天数 = 预计完工日 − 计划完工日
```

必须结合第一节的可信度标记。**不可信的滞后天数不参与排序，也不作为根因分析的输入。**

### ③ 返工未补回（最容易被漏掉，必须独立成一类）

**这是唯一一类会伪装成"接近完工"的偏差。**

判定算法：

```
1. 筛出完成率 ≥ 95% 且 欠数 > 0 的工单        # 进度条看起来接近满格的
2. 按工单号到返工单里匹配
3. IF 匹配到返工记录 AND 返工数量 ≈ 欠数:
       → 该欠数实为返工件，非"尚未生产"
4. 检查返工单的「是否已补回」字段:
       IF 为空or "未记录":
           → 这批件的实际状态未知（可能已返工完成未入账，也可能尚未返工）
5. 计算 剩余天数 = 交货日 − 今日
       IF 剩余天数 ≤ 2:
           → 判为最高优先级，标注"不能等到明天早会再看"
```

**为什么两种常规排序都会漏掉它**：

| 排序方式 | 这类工单的位置 | 结果 |
|---|---|---|
| 按完成率排序 | **排最前面**（98%，看起来最好） | 被当成"最健康的"跳过 |
| 按滞后天数排序 | **排很后面**（滞后不多） | 被当成"不严重的"跳过 |

所以必须**独立识别 + 按剩余时间判优先级**。

### 排序原则：按紧急度，不按滞后天数

```
紧急度 ≈ f(剩余天数, 偏差性质, 是否有连带影响)
```

- 剩余天数 ≤ 2 天且状态未知 → 最高
- 数据不可信但下游有工单在等 → 次高（因为要先解锁数据）
- 即将断料（有明确等料窗口）→ 中
- 欠数但交期充裕 → **明确标"不需列入早会"**

**最红的不一定最急。** 滞后 4 天的工单如果交货日还有 5 天，未必比进度 98% 但明天交货的更急。

## 三、四类根因 · 取数口径与可得性

### 总原则

**逐类标明数据可得性，可定量的给算式，查不到的只给候选项。**

输出格式固定：

```
①缺料 [可定量]
   证据：…（含具体数字与算式）
   结论：…（或"可明确排除"）

③ 品质 [数据不足]
   证据：…（照录原始描述）
   为什么算不了：…
   待确认：向谁确认什么
```

---

### ① 缺料 · 可定量

**取数**：ERP 齐套报表

```
缺口 = 需求量 − 已领用 − 库存可用
是否影响当前工序 = (在途到货日 > 该工序需料日)
等料窗口天数 = 在途到货日 − 前道工序预计完成日
```

**这是四类里唯一能完整定量的**，所以：
- 能明确判定影响 → 给出缺口数量、到货日、等料窗口
- **能明确排除的必须明确排除**（如"本工单焊丝缺口为 0，可排除缺料因素"）

排除性结论和肯定性结论一样有价值——它把嫌疑范围缩小了。

---

### ② 设备 · 可定量（但资料在设备科）

**取数**：设备科维修工单

```
影响工作日 ≈ 停机时长(h) ÷ 每日有效工时(默认 7.5h)
```

**必须同时说明的话**：`停机 3.0 小时 ≈ 0.4 个工作日，这解释不了 4 天滞后`。

不要因为找到了一个可定量的因素就把它当成主因。**能算出来的那部分，往往只占滞后的一小部分。**

另注意"未停机但降容运行"的情形（如温控仪表偏差、需校准），停机时长为 0 但实际影响产能，要单独说明。

---

### ③ 品质 ·常不可定量

**取数**：品保部返工/报废单（多为纸质台账转录）

两个典型缺陷：

**缺陷 A：数量栏是文字描述**
实际单据上常写"少量""几件""一批"。这时：
- **照录原始描述**，不要自己换算成数字
- 明确写"数量栏为文字描述，无法计算返工工时占用"
- 待确认：向品保确认实际件数

**缺陷 B：不追踪"返工是否已补回"**
返工完成后有没有补回产量、补回多少，多数厂不记录。这时：
- 标注该批件"实际状态未知"
- 给出两条分支（若已完成 / 若未完成）分别对应什么动作

**报废可定量**：报废单通常有明确数量（因为要走财务），可直接算出需补投数量。

### 顺带发现必须报出来

如果**同一缺陷在短期内多次出现**（如两天内两次焊缝气孔），即使数量不明，也要提示：

> 同类缺陷两天内出现两次，可能是工艺或设备的连带表现，建议同步品保。

**这类发现的价值在于**：那两张返工单是品保部两张独立的纸质单据，**没有人把它们放在一起看过**。而"同一个缺陷两天内两次"这个事实，比任何一次的数量都更有信息量。

---

### ④ 人手 · 基本不可定量

**取数**：人事出勤表

能拿到的：应到人数、实到人数、缺勤人数、缺勤原因、加班工时。

**拿不到的（也是关键的）**：**当天这个人被安排在哪个工位/哪张工单上**。

人员在工位之间的临时调动只在班长口头掌握，不进任何系统。所以：

- 可以说"焊接组连续三天减员（缺 2 / 缺 2 / 缺 1）"
- **不能说"因此本工单滞后是人手问题"** —— 因为这几个缺勤的人本来是不是安排在这张工单上，数据里根本没有
- 待确认：向班长确认这三天的实际工位安排

**硬规则：标为"数据不足"的根因，不得给出百分比或天数贡献。** 宁可写"无法计算"，不可写"约占 30%"。

## 四、"投入 − 完工"差额的处理

工序报工明细里常见 `投入 400、完工 396`，差额 4 件，备注写"差额未说明"。

这4 件可能是：
- 报废了（应有报废单，可核）
- 在返工（应有返工单，可核）
- 数错了 / 漏报了

**处理方式**：
1. 先到返工单和报废单里按工单号 + 工序匹配
2. 匹配到 → 明确归类
3. 匹配不到 → **标注"差额去向不明，建议向该工序报工人确认"**，不要猜

**不要把差额一律当成在制。** 这是很多进度看板失真的根源。

## 五、"数据不足"不是缺陷，是这个场景的前提

最后一条，也是这个 Skill 设计理念的核心：

**返工单写"少量"、出勤表没有工位维度——这不是企业数据没准备好，是这两类数据在中小企业本来就不以可计算的形式存在。**

任何要求"先把数据规范起来再用"的方案，在这个场景都会失败。所以正确的做法是：

1. 接受数据的真实形态
2. **把四类根因的嫌疑证据全部摆出来**，标明哪条是算出来的、哪条只是同期发生
3. 让 PMC 勾选

**PMC 心里其实知道答案。他缺的不是分析能力，是把散在四个部门的证据摆到一起的那个动作。**
