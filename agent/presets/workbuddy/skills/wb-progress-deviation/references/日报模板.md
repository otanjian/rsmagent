# 日报模板 · 列结构与排版

交付物形态：**Excel 3 sheet（工作用）+ PDF 1 页（早会打印签字用）**。

关键认知：按调研结论，中小企业这类日报是要**打印成纸质件留档**的，不是电子看板。所以 PDF 排版必须按 A4 考虑，且要有签收栏。

---

## 一、Excel sheet 1 · 偏差清单

### 列结构

`工单号 | 产品 | 客户 | 订单交货日 | 剩余天数 | 计划数 | 累计完工 | 欠数 | 完成率 | 当前工序 | 计划完工日 | 预计完工日 | 滞后天数 | 报工数据时点 | 数据可信度 | 偏差类型 | 紧急度 | 备注`

### 两列是这张表的关键

**「报工数据时点」**：直接照录系统里最后一次报工的时间戳。**不要格式化成"1天前"这种相对时间**——早会上要能直接读出具体日期时间，才有说服力。

**「数据可信度」**：三档`可信 / 可疑 / 不可信`，并用填充色区分。不可信的行整行标红。

### 排序

**按紧急度降序，不按滞后天数。**紧急度的判定见 `偏差判定与根因取数.md` 第二节。

### 样式要点

```python
ws.freeze_panes = 'A2'
ws.auto_filter.ref = f'A1:R{last_row}'
ws.sheet_view.showGridLines = False
# 行填充：不可信 FDF2F2 / 高紧急 FDF2F2 / 中FBF1DD / 低或正常 F4FBF6
# 完成率 ≥95% 且欠数>0 的行，完成率单元格用琥珀色字提醒（防"进度条陷阱"）
```

## 二、Excel sheet 2 · 根因待确认（这一页是给人填的）

### 列结构

`工单号 | 根因类别 | 数据可得性 | 证据（照录） | 可算出的影响 | 为什么算不了 | 待确认对象 | 待确认内容 | ☐ 确认 | 确认人 | 确认结果`

### 设计要点

**「☐ 确认」「确认人」「确认结果」三列必须留空。** 这一页不是给人看的报告，是**给 PMC 在早会上边问边填的工作表**。

**「数据可得性」只有两个值**：`可定量` / `数据不足`。用不同填充色区分，让PMC 一眼看出哪几行需要去问人。

**「证据」列要照录原始描述**。返工单上写的是"少量"就写"少量"，不要换算成数字。这一列的可信度全靠原样照录。

**能明确排除的也要单独列一行**，标 `可定量` + 结论"可明确排除"。排除性结论和肯定性结论一样有价值。

## 三、Excel sheet 3 · 补产建议

### 列结构

`工单号 | 是否需补产 | 补产数量 | 建议动作 | 分支条件 | 责任人 | 完成时点 | 是否需转5.4排产 | 备注`

### 设计要点

**「分支条件」列**：用于"若已完成 / 若未完成"这类需要先确认状态才能定动作的情形。这是返工未补回类工单的标准处理方式。

**必须包含"不需补产"的行**，且在备注里明确写"不需列入早会"。早会时间有限，**把不用讨论的摘出去和把该讨论的排上来同等重要**。

**「是否需转 5.3 排产与插单调整 排产」列**：本Skill 不改工单，需要重排产能的在这一列标 `是`，由 PMC 决定是否调用排产场景。

## 四、PDF · 执行偏差日报（A4 一页，早会打印用）

### 版面结构（从上到下）

```
┌────────────────────────────────────────┐
│ 执行偏差日报                            │
│ 企业名 · PMC · 数据截止 YYYY-MM-DD HH:MM │
├────────────────────────────────────────┤
│ ⚠ 数据时点异常提示（若有，放最前面）      │
├────────────────────────────────────────┤
│ 今日必须处置（2-4 张，表格）             │
│  工单/偏差类型/关键数字/建议动作/责任人/时点│
├────────────────────────────────────────┤
│ 待确认事项（问谁 · 确认什么）            │
├────────────────────────────────────────┤
│ 签收：PMC / 生产经理 / 车间主管│
└────────────────────────────────────────┘
```

### 硬要求

1. **只放今日必须处置的工单**（通常 2-4 张）。全量清单在 Excel 里，日报不是清单的打印版。
2. **数据时点异常提示放最前面**。如果有工单数据不可信，这件事比任何偏差都重要——因为它决定了今天的会该怎么开。
3. **签收栏三个签字位**：PMC（编制）/ 生产经理 / 车间主管。行高至少 16mm 留出手写空间。
4. **A4竖版**，字号正文 8~9pt，标题 15pt。

### reportlab 要点

```python
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.cidfonts import UnicodeCIDFont
pdfmetrics.registerFont(UnicodeCIDFont('STSong-Light'))
F = 'STSong-Light'
# 必须给 Table 显式 rowHeights，否则内容只占上半页
# 签收栏行高 ≥ 16mm
```

## 五、自检断言（跑不过就不出文件）

```python
# 1. 欠数守恒
for wo in workorders:
    assert wo['欠数'] == wo['计划数'] - wo['完工数'], f"{wo['号']} 欠数不守恒"

# 2. 完成率与欠数一致
for wo in workorders:
    rate = wo['完工数'] / wo['计划数'] * 100
    assert abs(rate - wo['完成率']) < 0.1, '完成率算错'

# 3. 数据不可信的工单不得有根因结论
for wo in workorders:
    if wo['可信度'] == '不可信':
        assert wo.get('根因结论') is None, '不可信工单不得输出根因结论'

# 4. 标为"数据不足"的根因不得含百分比或天数贡献
import re
for c in causes:
    if c['可得性'] == '数据不足':
        assert not re.search(r'\d+%|\d+\s*天', c.get('影响', '')), \
            '数据不足的根因不得给量化贡献'

# 5. 日报里的工单数必须 ≤ 4
assert len(today_must) <= 4, '日报工单过多，早会读不完'

# 6. 必须存在至少一条"不需补产"的记录（否则说明没做减法）
assert any(x['是否需补产'] == '否' for x in suggestions), '未做减法，检查是否漏判'
```

第 3、4 条是这个场景特有的断言，直接对应 SKILL 的硬规则——**从代码层面阻止"硬凑归因"**。
