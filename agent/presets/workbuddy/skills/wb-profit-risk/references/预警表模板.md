# 预警表模板 · 列结构与版面

交付物：**Excel 2 sheet（工作用）+ PDF 1 页（给老板）**。

---

## 一、Excel sheet 1 · 在制订单毛利预警

### 列结构

`销售订单号 | 客户 | 客户等级 | 产品 | 数量 | 合同额 | 报价·材料 | 报价·工费 | 报价·外协 | 报价·其他 | 报价成本合计 | 报价毛利率 | ①超领 | ②外协增量 | ③加急运费 | ④返工工时(估) | 增量合计 | 估算金额 | 估算占比 | 实际成本 | 预计毛利率 | 偏差pt | 阈值 | 判定 | 归口方向`

### 关键设计

**「估算金额」与「估算占比」两列必须有。** 它们告诉看表的人这个结论有多稳。估算占比 > 20% 时该单元格标红。

**「报价·工费」列标黄底**，并在表尾注明"该项为经验估算，不做逐项比对，仅并入合计"。

**判定列三档填色**：🔴 已跌破 FDF2F2 / 🟡 关注 FBF1DD / 🟢 正常 F4FBF6。

**必须至少有一行是"正常"**，且不要把它藏在最后 —— 按偏差排序自然会在最后，但要确保它存在。

### 样式要点

```python
ws.freeze_panes = 'B2'          # 冻结首列订单号 + 首行
ws.auto_filter.ref = f'A1:Y{last_row}'
ws.sheet_view.showGridLines = False
# 金额列 number_format = '#,##0.00'
# 毛利率与占比列 number_format = '0.0%'
# 偏差 pt 列用 '+0.0;-0.0' 显示正负
```

## 二、Excel sheet 2 · 增量成本明细

### 列结构

`销售订单号 | 增量项 | 单据号 | 日期 | 数据可信度 | 算式 | 金额 | 反查依据 | 原记账科目 | 备注`

### 关键设计

**「数据可信度」三个值**：`准` / `反查` / `估算`。用不同底色区分。

**「反查依据」列**：只有反查项才填，要写清用了哪几个线索（如"收货客户 + 发货日 + 备注语义（返工件补发，可与 RW-20260804-23 交叉验证）"）。

**「原记账科目」列**：反查项必填（如"管理费用-运输费"）。这一列是暴露流程缺口的证据。

**每笔必须有单据号。** 无单据号的金额不得写入 —— 这是这张表可信的前提。

## 三、PDF · 利润风险提示（A4 一页，给老板）

### 版面结构

```
┌──────────────────────────────────────────┐
│ 利润风险提示                              │
│ 企业名 · 财务 ｜ 扫描日期 ｜ 在制 N 张，跌破 M 张│
├──────────────────────────────────────────┤
│ 数据可比性声明（一段小字，放最前）          │
├──────────────────────────────────────────┤
│ 【跌破阈值】订单卡                         │
│  · 报价 GM → 预计 GM，偏差                 │
│  · 四项增量瀑布拆解                        │
│  · 责任面三方拆解                          │
│  · 建议动作（含明确的"不建议"）             │
├──────────────────────────────────────────┤
│ 【跨单提前提醒】（若有）                    │
├──────────────────────────────────────────┤
│ 流程层面建议 3 条                          │
├──────────────────────────────────────────┤
│ 页脚：估算占比 X% ｜本报告不做商业取舍建议  │
└──────────────────────────────────────────┘
```

### 硬要求

1. **只放跌破阈值的订单**（通常 1-2 张）+ 跨单提醒。全量表在 Excel 里。
2. **数据可比性声明放最前面**，一段小字：哪部分准、哪部分反查、哪部分估算、工费为何不逐项比。
3. **瀑布拆解要能看出主次** —— 哪一项吃掉的最多。
4. **页脚必须印明**："本报告为成本偏差信号，非精确成本核算；估算部分占增量 X%；商业取舍建议由管理层判断。"

### 瀑布拆解画法（reportlab）

用横向条形表示，宽度按金额占报价毛利的比例：

```python
bar_w = amount / quoted_gross_profit * max_width
# 报价毛利：绿色底
# 各项增量：红色系（反查项用琥珀色，估算项用灰色）
# 剩余毛利：蓝色
```

**反查项和估算项用不同颜色**，一眼能看出"这部分是找回来的""这部分是估的"。

## 四、自检断言（跑不过就不出文件）

```python
# 1. 报价成本分项== 合计
for o in orders:
    assert abs(o['mat'] + o['lab'] + o['os'] + o['oth'] - o['cost']) < 0.01, '报价成本分项不等于合计'

# 2. 报价毛利率公式一致
for o in orders:
    assert abs((o['amt'] - o['cost']) / o['amt'] - o['gm']) < 0.0001, '报价毛利率不符'

# 3. 预计毛利率公式一致
for o in orders:
    act = o['cost'] + o['inc_total']
    assert abs((o['amt'] - act) / o['amt'] - o['gm2']) < 0.0001, '预计毛利率算错'

# 4. 增量分项 == 增量合计
for o in orders:
    assert abs(o['over'] + o['os_inc'] + o['frt'] + o['rw'] - o['inc_total']) < 0.01, '增量分项不等于合计'

# 5. 估算占比正确
for o in orders:
    if o['inc_total'] > 0:
        assert abs(o['rw'] / o['inc_total'] - o['est_ratio']) < 0.001, '估算占比算错'

# 6. 必须有"正常"行
assert any(o['verdict'].startswith('🟢') or '正常' in o['verdict'] for o in orders), \
    '未出现判定为正常的订单，检查是否在凑异常'

# 7. 每笔增量必须有单据号
for d in details:
    assert d['doc_no'], f"{d['order']} {d['item']} 缺单据号"

# 8. 反查项必须有反查依据
for d in details:
    if d['trust'] == '反查':
        assert d['basis'] and d['orig_account'], '反查项必须写明依据与原记账科目'
```

第 6、8 条是这个场景特有的断言：**从代码层面阻止"凑异常"和"无依据反查"**。
