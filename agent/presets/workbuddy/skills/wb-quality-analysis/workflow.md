# 品质异常分析 · 根因追溯与 8D 生成

## 这个 Skill 解决什么

客户投诉进来，或产线出批量不良，品质工程师要在很短时间内凑齐证据、做归因、写报告、推整改。难的不是写报告，是三件事：

1. **凑齐证据** —— 客户只给一个批号，报工在生产系统、检验记录在纸质表、来料台账在仓库、历史处理记录在某个人的电脑里
2. **把根因追到能改的那一层** —— 而不是停在"操作员未按规程执行"
3. **答上客户一定会追问的那一条** —— "就算问题发生了，你们的检验为什么没拦住？"

**定位边界（重要）**：不要替用户"定"根因。质量结论要担责。本Skill 的产出是**带证据的候选根因与可疑变异点**，拿不准的必须明确说拿不准。最终判断权在人。

---

## 六步流程

```
Step 1 汇聚      读全部资料 → 统一到「批号/工单/工序/设备/班组/人/原料/参数/检验」九元组
Step 2 履历      从批号反查，还原全工序时间轴
Step 3 硬比对实际参数 vs 工艺卡要求；检验记录 vs 检验标准 → 标出偏离项与实测偏差值
Step 4 重复性五维交叉比对历史异常台账 → 判定是否同源复发
Step 5 双路径归因 发生原因链 + 流出原因链，各自追到流程/标准层
Step 6 出交付物8D 报告 + 支撑分析 + 整改跟踪表，措施必标性质
```

**Step 4 必须放在 Step 5 之前。** 一旦判定是同源复发，Step 5 的追问方向就要从"这一批为什么出问题"转为"**这个条件为什么反复出现、前几次整改为什么没防住**"，根因层级更深一层，措施也完全不同。顺序错了就会又写出一份"加强培训"。

---

## Step 2· 批次履历还原

反查链路：

```
批号 → 工单（在报工记录按「生产批号」列匹配）
     → 工序清单（同工单号全部报工行按开工时间排序）
     → 每道工序的设备 / 班组 / 操作员
     → 每道工序的 投入原料批号 → 去来料台账查供应商 / 检验结论 / 实测值
     → 检验放行记录（在检验记录按「工序 + 时间窗」匹配）
     → 标记异常点：参数偏离、换型标记=是、检验项缺失、无签字留痕
```

若客户只给客户端序列号：先在出货明细里按序列号找出货批号，再进上面链路。

输出必须含9 列：序 / 工序 / 设备 / 班组 / 操作员 / 检验员 / 起止时间 / 原料批号 / **关键事实**。
最后一列是价值所在 —— 把参数偏离、换型标记、检验缺项直接写在这里，用 ★ 标出可疑工序。

匹配失败的处理：

| 情况 | 处理 |
|---|---|
| 批号在报工记录查不到 | 提示"批号 XXX 无匹配，请确认批号或补该批工单导出"，不要猜 |
| 一个批号对应多个工单（拆单生产） | 全部列出，逐工单分别还原，提示"该批跨 N 个工单需分别评估" |
| 检验记录按时间窗匹配不上 | 标注"该工序无检验记录"——这本身就是一条重要发现 |
| 原料批号为空（非首序工序） | 正常，只有投料工序才有 |

## Step 3 · 参数硬比对

每条偏离必须给出：**参数项 / 工艺卡要求（含上下限） / 实际记录值 / 偏差量 / 导致的后果机理**。

**硬规则**：直接原因必须有实测数值支撑。只有定性描述（"焊接质量不良""参数不合适"）的不算直接原因，须回去取数或标注"缺实测数据，待补"。

---

## Step 4 · 重复性问题识别（五维交叉）

| # | 维度 | 命中判定 |
|---|---|---|
| 1 | 设备 | 设备编号完全相同即命中 |
| 2 | 班组 / 人 | 班组相同即命中；操作员也相同则加权 |
| 3 | 工序 | 工序名完全相同即命中 |
| 4 | 批次背景 | 背景类型相同即命中（如都是"换型后首批"、都是"月末冲量"、都是同一班次） |
| 5 | 来料批次 | 批号相同即命中 |

**判定阈值**：命中 ≥ 2 个维度 → 判定为疑似重复性问题，须在报告中明示"本问题为近 N 个月内第 M 次同源发作"并列出历史单号。

**关键原则—— 不要靠现象比，要靠条件比。** 同一个根因在不同条件下会表现成完全不同的现象（热输入不足 → 气孔；分布不均 → 变形；熔深不够 → 开裂）。所以比对必须基于设备/班组/工序/背景这些客观条件，而不是"不良现象像不像"。

**判定为重复时，必须额外做两件事**：

1. **逐条列出前几次的整改措施，并判断它属于哪一类** —— 如果前几次全是"培训/加严检验"这类，就要明确写出"前 N 次均为治现象未治根因，故复发"
2. **把追问方向改为"这个条件为什么反复出现"** —— 根因往往是某个流程环节压根不存在

**未命中的维度也要写出来。** 未命中是排除性结论，同样有价值：若三次异常对应三个不同来料批次且检验实测值接近，即可排除来料方向 —— 这通常是排查里第一个方向也是最耗时的方向，主动排除能省一整轮供应商追溯。**排除必须给依据，不能含糊地不提。**

历史台账缺失时：跳过本步并明确提示"无历史台账，无法判断是否复发，建议补齐"，不要假装做过。

---

## Step 5 · 双路径归因（本Skill 的硬性要求）

**必须产出两条独立的追问链，缺一条视为报告不完整。**

### 路径一· 发生原因（Occurrence）
问题为什么产生。逐层追问到**流程 / 标准 / 作业文件的空白**。

### 路径二 · 流出原因（Escape）
问题为什么没被拦住、流到了客户手上。这条追首件、巡检、终检、抽样方案、检验标准。

**为什么必须两条**：只写发生原因是客户退件的第一原因。客户逻辑很直接——"就算问题发生了，你的检验为什么没拦住？"

### 追问深度要求

| 层级 | 应落在哪一层 | 反例（不合格） |
|---|---|---|
| Why 1 | 失效的物理表现 | "产品不合格"（太笼统） |
| Why 2 | 物理机理 / 参数偏离 | "质量意识不强" |
| Why 3 | 参数为何偏离（人机料法环的具体触发） | 停在"操作员失误" |
| Why 4 | **流程 / 标准 / 作业文件的空白** | 停在"培训不到位" |
| Why 5 | **管理机制为何没发现这个空白** | 空着不填 |

**每一层必须挂证据来源**（哪份表、哪一行、哪个字段）。无证据的 Why 标注"待验证"。

### 反甩锅硬规则

出现"操作员未按规程执行""员工操作不当""质量意识不足"这类结论时，**禁止停下，必须继续追**：

- 规程里到底有没有写这一步？→ 没写 = 标准缺失（流程空白）
- 写了为什么没执行？→ 有没有防错？有没有确认签字？节拍是否逼人跳步？
- 首件/巡检为什么没拦住？→ 检验表里有没有这一项？

### 直接原因 vs 系统原因判定

| 判定问题 | 答"是"→ 直接原因 | 答"是"→ 系统原因 |
|---|---|---|
| 改掉它，这一批的问题会立刻消失吗？ | ✅ | ❌ |
| 改掉它，未来同类批次都不会再犯吗？ | ❌ | ✅ |
| 它描述的是一个具体偏离值？ | ✅ | ❌ |
| 它描述的是"没有规定/没有环节/没有检项"？ | ❌ | ✅ |

**系统原因至少写 2 条。** 只写 1 条通常说明归因不够深。

## Step 6 · 措施分类与交付物

### 措施必须按性质分三类

| 性质 | 含义 | 典型动作 |
|---|---|---|
| **围堵（先灭火）** | 把客户端和在制的火压住 | 退换货、现场全检、在制批复检、隔离标识 |
| **纠正（改这一批）** | 把当前偏离改对 | 参数复位、返工、重新放行 |
| **预防（防再发）** | 堵住流程空白 | 改作业文件、改表单加检项、改检验标准、加防错、改关闭规则 |

**硬规则**：若清单里没有任何一条"预防"类，必须明确警示"本次整改无预防措施，问题极可能复发"。前几次整改失败通常就是因为清单里全是前两类。

### 三件必须点出的容易漏项

1. **横向展开** —— 其他机台/ 其他产线 / 同类产品 / 其他供应商是否存在同一隐患？**逐项给结论，不能只改出问题的这一台**
2. **待改文件清单** —— 作业指导书 / 检验标准 / 点检表 / 控制计划 / 培训教材，列出文件名与需改内容。措施不落到文件上，下次审核照样被开不符合项
3. **效果验证要求** —— 不能只写"已整改"。必须写明**要看几批数据**（建议连续 3 批或1 个月）。审核最常问的就是"凭什么认为这个问题解决了"

### 交付物形态（详见 references/deliverable_templates.md）

产出必须是可直接流转的正式文件，不是对话式总结：

1. **8D 报告** —— D0~D8 分区，含 5W2H 与 Is/Is-Not、双路径追问链、措施带责任人与验收、**客户签核栏 + 版本号 + 单据编号**
2. **支撑分析** —— 履历时间轴、参数偏差表、五维交叉矩阵、**被排除的方向与依据**、我方检验 vs 客户检验对比
3. **整改跟踪表** —— 按性质分类，含责任人/时限/验收标准/实际完成日/证据编号、待改文件清单、横向展开待办

命名规范：`8D报告_客户名_不良现象_YYYYMMDD_Rev01.xlsx`

## 输入容错

**不强制格式。** 现实是"检验记录在纸质表、报工在系统里、台账在某个人的 Excel 里"。

| 输入 | 必需性 | 缺失时的降级 |
|---|---|---|
| 客户投诉单 | 强烈建议 | 按内部异常单走，问题描述由用户口述补全 |
| **报工记录** | **必需** | 无法做履历还原，明确提示"请提供报工导出" |
| 检验记录 | 建议 | **无法追流出原因**，须提示这会导致报告不完整 |
| 来料批次台账 | 建议 | 无法做来料维度排除，五维降为四维并说明 |
| 历史异常台账 | 重复性识别必需 | 跳过该步并提示"无法判断是否复发，建议补齐台账" |

**列名容错**：设备编号 / 设备号 / 机台 / 机台号 / Machine / Equipment No 都识别为"设备编号"。"批次背景"可从"换型标记 / 首批标记 / 备注"推断。

**格式支持**：xlsx / xls / csv / pdf（含扫描件）/ docx / 图片（纸质表拍照）/ 邮件正文粘贴。

**缺陷描述归一化**：同一种不良在不同人手里会写成不同名字（"无划痕/OK/√"、"电阻偏大/阻值超上限"）。做统计前先归一化，但**必须保留原始描述列**，让清洗动作可追溯。

## 拿不到的数据要明说

常见拿不到的东西：设备实时参数曲线（在控制器里未导出）、模具号/模穴号、精确的报废成本、客户端使用工况。

**处理方式**：在报告里明确写出"该项数据当前无法获取，本次分析以 XX 为依据，建议后续接入"。**敢说"这个我拿不到"，比声称什么都能分析更可信** —— 硬编一个根因会被现场工程师一眼看穿。

---

## 覆盖范围

品质工程师异常分析、客诉响应、内部批量不良分析。履历还原与重复性识别可复用到设备、工艺、供应商质量相关场景。
