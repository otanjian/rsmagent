**填写要求**

- 必须写到具体人名，不得只写部门

## D2 · 问题描述（5W2H）

| 要素 | 内容 |
|---|---|
| What（是什么问题） | <失效模式 + 具体部位 + 量化程度，如"立柱与底板角焊缝开裂，长度 8~15mm"> |
| Where（在哪发现） | <客户来料检验 / 客户装配线 / 我方终检 / 我方巡检> |
| When（何时） | 投诉/发现日期 <日期>；对应出货日期 <日期>；对应生产日期 <日期> |
| Who（哪个批次 / 谁做的） | 批号 <批号> / 工单 <工单号> / 涉及工序与班组 <…> |
| Why（为何构成问题） | <违反哪条标准 / 客户要求，如"焊缝熔深要求 ≥1.6mm"> |
| How found（怎么发现的） | <检验方法 + 是否受力后显现> |
| How many（多少） | 检验数 <N> 台 / 不良数 <n> 台 / **不良率 = n ÷ N = <x>%** |

**填写要求**
- 不良率必须写算式，口径统一为 **不良数 ÷ 检验数**
- 若我方抽检与客户全检口径不同，必须两个口径分别列出，并说明为何不冲突
- 禁止写"产品质量不良""客户不满意"这类无法据以分析的描述

## D3 · 临时围堵措施（Containment）

**五个流向必须逐一交代，数量为 0 也要写明。**

| # | 流向 | 数量 | 围堵动作 | 责任人 | 完成时限 | 状态 |
|---|---|---|---|---|---|---|
| 1 | 客户端已收货 | <n> | <退换/ 现场100% 复检 / 挑选> | | | |
| 2 | 在途 | <n> | <拦截/ 到货后先检后入> | | | |
| 3 | 成品库 | <n> | <隔离挂红牌 / 全检> | | | |
| 4 | 在制（含在制工单号） | <n> | <全数复检 / 返工 / 暂停流转> | | | |
| 5 | 原料 / 半成品 | <n> |<隔离 / 复验 / 退供应商> | | | |
| 6 | 过程冻结 | — | <特定设备 / 工序暂停承接某类生产> | | | |

**填写要求**
- 围堵措施允许低效但必须快（100% 复检、暂停生产都可接受）
- 每条必须有责任人和时限，不得写"尽快"
- 围堵不是整改，不得把围堵措施写进 D5
- 若判定为重复性问题，还需检查**历史同源批次是否已出货给其他客户**，并说明是否需扩大围堵

|---|---|---|---|---|

## D5 · 永久纠正措施（Corrective Action）

| # | 对应原因 | 措施 | 措施性质 | 责任人 | 时限 | 验收标准 |
|---|---|---|---|---|---|---|
| 1 | 直接原因 | | 纠正 | | | |
| 2 | 系统原因① | | 治根因 | | | |
| 3 | 系统原因② | | 治根因 | | | |

**措施性质只能填**：临时围堵 / 治现象 / 治根因 / 有效性验证 / 闭环

**填写要求**
- 每条系统原因至少对应 1 条措施，不得漏挂
- **治根因措施数量必须 > 0**
- 禁止只写"加强培训""加强检验"就收尾。措施必须能指出改哪份文件、加哪个检项、锁哪个参数、装哪个防错
- 判定为重复性问题时，必须有一条针对"为什么反复发生"的措施

|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |

**填写要求**
- 验证方式必须可核实（连续 N 批跟踪 / 签字留痕率 / 关键参数实测 / 破坏性抽检）
- 判定标准必须量化（"≥1.6mm""100% 留痕""连续 3 批客诉为 0"）
- 禁止写"效果良好""已改善"
- 验证未达成的措施不得判定为有效，需回到 D5 重新设计措施

## 附：常见退回原因（客户端与内审最常打回的 8 条）

1. D2 只有定性描述，没有批号、检验数、不良数、不良率
2. D3 只处理客户端，在制与在途没交代
3. D4 根因写成"操作员未按 SOP 执行"，没有追到标准层
4. D4 系统原因只有1 条或干脆没有
5. D5 措施全是"加强培训/ 加强检验"，无治根因措施
6. D6 写"效果良好"，无样本量与量化标准
7. D7 没更新 PFMEA / 控制计划，问题关闭后标准原样不动
8. 历史同类问题已发生过，本次仍作为新问题处理，未做重复性说明
