# 交付物模板与栏位规范

产出必须是**可直接流转的正式文件**，不是对话式总结。质量文件要发给客户、要被审核员抽查，所以栏位缺一项就不像真的。

---

## 交付物①8D 报告

**文件命名**：`8D报告_客户名_不良现象_YYYYMMDD_Rev01.xlsx`

###抬头栏位（缺一项都会被客户打回）

| 栏位 | 说明 |
|---|---|
| 8D 编号 | 内部单据号，如 QA-2607-041 |
| 客诉单号 | 客户给的投诉单号 |
| 客户名称 | |
| 产品型号 / 图号 | 含客户零件号 |
| 涉及批次 / 数量 | 出货批号、工单号、出货数、不良数、不良率 |
| 发行日期 / Rev 版本 | Rev01、Rev02…每次修订都要留痕 |
| 组长 / 小组成员 | 姓名 + 岗位 + 负责模块 |
| 当前状态 | Open / Closed + 关闭日期 |
| **客户签核栏** | 留空给客户签，这一栏没有等于报告没提交完 |

### D0~D8 分区必填内容

**D0 应急反应**
风险分级（是否涉安全/是否可能停线/是否需召回）、受影响批次与数量、是否已出货、已采取的立即动作。

**D1 小组成立**
跨职能名册。至少含：质量（组长）、工艺、生产、当事操作岗、客户沟通窗口。每人写清负责模块，不要只写名字。

**D2 问题描述**
必须量化，且必须带两张表：

- **5W2H 表**：What（什么产品什么缺陷）/ When（哪天生产、哪天发现）/ Where（哪个工序哪个工位、缺陷在产品什么位置）/ Who（哪个班组哪个操作员、谁检验放行）/ Why（客户为什么判不合格）/ How（怎么发现的）/ How many（检验数、不良数、不良率）
- **Is / Is-Not 对比表**：哪些批次有、哪些没有；哪台设备有、哪台没有；哪个班次有、哪个没有。这张表本身就在缩小根因范围。

反例："产品外观不良" —— 太笼统，客户会退回。
正例："7月15日 WO-26-0715 批次生产 P-CAB-02 共120 台，客户全检检出 9 台（7.5%）立柱与底板角焊缝开裂，开裂长度 8~15mm，部分件装配受力后显现；其余检验项客户判定合格。"

**D3 围堵措施**
三件事必须齐：

1. **隔离** —— 在制 / 库存 / 在途 / 客户端各自怎么处置，分区标识
2. **回溯** —— 前后批次是否要全检，全检后的真实不良数是多少
3. **加严** —— 临时全检 / 巡检频次加倍 / 参数锁定

每条带责任人、完成时间、**有效性证据**（检测报告编号等）、**失效期**（"本临时措施保持至预防措施验证通过"）。

**D4 根本原因**
**必须双路径，缺一条视为不完整：**

- 发生原因链（问题为什么产生）—— 逐层追到流程/标准空白
- 流出原因链（为什么没被拦住）—— 追首件、巡检、终检、抽样方案、检验标准
- 每层挂证据来源（哪份表哪一行）
- 若判定为重复性问题，此处必须写明"本问题为近 N 个月内第 M 次同源发作"并列历史单号，同时说明前几次整改为何无效

根因确认标准：**因存在则缺陷在，因去除则缺陷消失。** 无法验证的写"待现场验证"。

**D5 永久对策**
分别对应发生原因与流出原因，**一一对应，不要混在一起**。防错优先于依靠人的自律。

**D6 实施与验证**
每条措施：做什么 / 谁做 / 何时完成 / 怎么验证 / 成果证据编号。
**量化效果要求**：整改后连续 3 批（或 1 个月）的合格数据，不能只写"已整改"。
撤除D3 临时措施的条件与日期。

**D7 预防再发**
两张清单，最容易漏也最容易被审核抓：

- **横向展开清单**：其他机台 / 其他产线 / 同类产品 / 其他供应商 × 是否存在同一隐患 × 结论。**逐项给结论**，"不适用"也要写明为什么。
- **文件更新清单**：文件名 / 编号 / 旧版本 → 新版本 / 生效日 / 责任人。作业指导书、检验标准、点检表、控制计划、培训教材都要过一遍。

示例写法（这种才叫可核查）："已同步修订《换型作业指导书》WI-CHG-012，A 版 → B 版，2026-08-20 生效，新增焊机参数复位与双人确认签字栏。"

**D8 团队认可与关闭**
管理层签核、客户确认、关闭日期、经验分享（Lesson Learned 入库编号）。

### 附件索引
不良品照片、隔离标识照片、全检明细、参数记录、检验记录扫描件 —— 逐项编号列出。

## 交付物 ② 支撑分析

多 sheet，给内部用，也用于客户追问时逐条摆证据。

| Sheet | 内容 |
|---|---|
| 1 履历时间轴 | 9 列：序/工序/设备/班组/操作员/检验员/起止时间/原料批号/关键事实（★标可疑工序） |
| 2 参数偏差表 | 参数项 / 工艺卡要求（含上下限）/ 实际值 / 偏差量 / 后果机理 / 数据出处 |
| 3 五维交叉矩阵 | 五个维度 × 各次异常取值 × 是否命中 × 判定说明 |
| 4 **排除结论** | 被排除的方向 / 排除依据 / 数据支撑。**这一 sheet 常被忽略但很值钱** —— 它证明分析是穷尽的，也省掉别人重复排查 |
| 5 检验对比 | 我方检验（数量/方法/检出）vs 客户检验（数量/方法/检出）+ 差异原因逐条 |
| 6 归一化明细 | 清洗后的结构化不良明细，**保留原始描述列**让清洗动作可追溯 |

若做了帕累托或趋势分析，另加：不良类型 TOP3 及累计占比、按班次/设备/来料批次的层别对比、月度趋势。

## 交付物 ③ 整改跟踪表

单 sheet 可筛选，是后续跟催和审核抽查的依据。

| 列 | 说明 |
|---|---|
| # | 序号 |
| 动作 | 具体做什么。**禁止以"加强培训""加强巡检"结尾** |
| 性质 | 围堵 / 纠正 / 预防 —— 必填|
| 责任人 | 姓名，不写部门 |
| 计划完成日 | |
| 实际完成日 | 留空待填 |
| 验收标准 | 可核查的，如"新版表单启用，首件必填参数实测值" |
| 证据编号 | 培训签到表号 / 检测报告号 / 新版文件号 |
| 状态 | 待整改 / 进行中 / 已完成 / 已验证 |

**表尾附两块**：

- 待改文件清单（文件名 / 编号 / 旧版 → 新版 / 生效日 / 责任人）
- 横向展开待办（对象 / 是否同隐患 / 结论 / 责任人 / 期限）

## 三个"像真的"的判断标准

做完自检这三条，缺任何一条都会被客户或审核看出是凑数的：

1. **文件名带Rev 版本号和单据编号**，不是"报告.xlsx"
2. **每条措施都有责任人姓名 + 日期 + 证据编号**，没有一条以"加强培训"结尾
3. **D7 里有可核查的文件更新记录**，写到"XX 文件 A 版→B 版，某日生效"这个程度
