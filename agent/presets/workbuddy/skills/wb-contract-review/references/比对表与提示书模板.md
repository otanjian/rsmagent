# 比对表与提示书模板

交付物：**Excel 1 sheet（工作用）+ PDF 2 页（第1 页给老板，第 2 页给客户）**。

---

## 一、Excel · 条款差异比对表

### 列结构

`条款号 | 条款标题 | 条款原文摘录 | 销售初步意见 | 风险类别 | 命中红线编号 | 与历史基线对比 | 风险等级 | 不利后果（一句话） | 建议修改文本 | 是否可让 | 需合并审查 | 结论`

### 关键设计

**「销售初步意见」列必须保留。** 它是最好的对照——让人看到"销售觉得没问题"和"实际是高风险"之间的差距。

**「需合并审查」列**：需要和其他条款组合看的，标注为同一组（如"与第 4.3 条合并审查"）。**这一列防止逐条看漏掉组合风险。**

**「是否可让」列**：三个值 `必须改` / `建议改，可谈判` / `提示即可`。**这一列防止一刀切标高危。**

**「建议修改文本」列必须是可直接替换的条款原文**，不是"建议关注 XX"。销售应该能直接复制进反馈邮件。

**排序**：按风险等级降序，同级按条款号升序。

### 样式

```python
ws.freeze_panes = 'B2'
ws.auto_filter.ref = f'A1:M{last_row}'
ws.sheet_view.showGridLines = False
# 风险等级填色：高 FCECEC / 中 FBF1DD / 低 F4FBF6
# 需合并审查的行加左侧粗边框标记为一组
```

## 二、PDF 第 1 页 · 三条致命项摘要（给老板）

### 版面

```
┌──────────────────────────────────────────┐
│ 合同条款风险提示                │
│ 企业名 ｜ 合同编号 ｜ 客户 ｜ 标的与金额        │
├──────────────────────────────────────────┤
│ 基线说明（一段小字）│
├──────────────────────────────────────────┤
│ 【必须改的三条】                │
│  逐条：条款号 / 问题 / 算成钱的后果 / 建议     │
├──────────────────────────────────────────┤
│ 【同一客户旧账】（若有）                      │
├──────────────────────────────────────────┤
│ 【相对我方历史合同】五项松紧对比表│
├──────────────────────────────────────────┤
│ 谈判优先级建议                               │
└──────────────────────────────────────────┘
```

### 硬要求

1. **只放三条**。老板没时间看 11 条，要的是"哪几条不改不能签"。
2. **每条必须算成钱**。"违约金偏高"没有意义，"逾期 10 天赔 4.24 万元，占合同总价 10%"才有意义。
3. **基线说明放最前**，一段小字说明企业无标准模板、用了哪两个基线。
4. **同一客户旧账单独成块** —— 这是最有力的谈判抓手。

## 三、PDF 第 2 页 · 完整清单 + 建议文本（可直接用于对客反馈）

### 版面

逐条列出：`条款号 | 风险等级 | 问题 | 建议修改文本 | 是否可让`

**建议修改文本要完整可复制** —— 销售把这一页发给客户或转成邮件即可。

### 页脚（必须印明）

> 本表为条款风险提示，不构成法律意见；重大合同建议由专业律师审阅。本表未涵盖合同外文件（图纸、技术协议、会议纪要）之间的一致性核对。

**这句话不是免责套话，是这个场景的能力边界的诚实表达。**

## 四、自检断言（跑不过就不出文件）

```python
# 1. 每条必须有风险等级
for c in clauses:
    assert c['level'] in ('高', '中', '低'), f"{c['no']} 缺风险等级"

# 2. 高风险项必须有建议修改文本
for c in clauses:
    if c['level'] == '高':
        assert c['suggest'] and len(c['suggest']) > 20, f"{c['no']} 高风险项缺建议文本"

# 3. 建议文本不得是"建议关注"这类无法执行的表述
import re
for c in clauses:
    if c['suggest']:
        assert not re.match(r'^(建议关注|需注意|应重视)', c['suggest']), \
            f"{c['no']} 建议文本不可执行"

# 4. 不得所有条款都是高风险（防一刀切）
high = sum(1 for c in clauses if c['level'] == '高')
assert high < len(clauses), '全部条款均为高风险，检查是否一刀切'
assert high / len(clauses) <= 0.7, f'高风险占比 {high/len(clauses):.0%} 过高，可能一刀切'

# 5. 必须有"是否可让"
for c in clauses:
    assert c['negotiable'], f"{c['no']} 缺是否可让"

# 6. 不得出现具体法条号（防 AI 编造法条）
LAW_PAT = re.compile(r'第\s*\d+\s*条.{0,6}(规定|之规定)|《[^》]*法》第\s*\d+')
for c in clauses:
    txt = (c.get('issue') or '') + (c.get('suggest') or '')
    assert not LAW_PAT.search(txt), f"{c['no']} 出现法条引用，本Skill 不得引法条"

# 7. 致命项必须恰好 3 条且都算成钱
assert len(fatal) == 3, '致命项应为 3 条'
for f in fatal:
    assert re.search(r'\d+(\.\d+)?\s*万|\d+%', f['impact']), f"致命项 {f['no']} 未算成钱"

# 8. 页脚免责必须存在
assert '不构成法律意见' in footer_text, '缺免责表述'
```

第 4、6 条是这个场景特有的断言：**从代码层面阻止"一刀切标高危"和"编造法条"** —— 这两个正是 AI 审合同最常见的两种翻车方式。
