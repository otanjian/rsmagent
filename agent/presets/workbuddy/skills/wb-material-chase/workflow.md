# 来料跟催·风险分级与话术生成 Skill

> 采购岗位场景 6.2 专用 Skill · 从在途单台账 → 供应商履约画像 → 到货预测 → 逾期程度 × 下游影响面四象限分级 → 带数据筹码的跟催话术 + 升级路径

---

## 1. 用途

采购每天盯几十张在途采购单，真正的难点从来不是"哪张晚了"，而是"**哪张晚了会出事**"。这个 Skill 一次做完 6 件事：

1. **多源台账对齐**：在途采购单 + 供应商履约台账 + 工单需求计划 + 库存快照，四份表按「物料」和「供应商」两个键拼成一张全景
2. **供应商履约画像**：近6 个月准时率 / 平均延误天数 / 延误波动度 σ / 最大延误，把"这家到底靠不靠谱"变成三个可核实的数字
3. **到货预测**：预测到货日 = 有效承诺日 + 该供应商平均延误天数。供应商说"明天到"不再只能信，可以拿历史数据算一遍
4. **下游影响面测算**：每张在途单挂到关联工单 → 计划上线日 / 客户 / 优先级；再算可撑天数与断料日，得出缺口天数
5. **四象限风险分级**（核心差异化）：按「逾期程度 × 下游影响面」两轴分四色。**关键是能识别出"逾期 5 天但根本不急"和"还没到交期就该催"这两类反直觉的单**
6. **跟催话术+ 待办+ 升级路径**：话术强制带四要素数据筹码（禁止空催），并明确什么情况升级、什么情况启动替代料、什么情况通知 PMC 调排产

**这个 Skill 解决的真实痛点**：传统做法是在 Excel 里筛"交期已过还没到"的单，然后按逾期天数从大到小打电话。结果是——催的顺序全凭感觉，先催了嗓门大的供应商，真正卡住交付的那张反而没催；而"还没到交期"的单一张都进不了筛选结果，等到交期过了才发现来不及。

## 2. 触发方式

### 2.1 用户一句话触发（推荐）

```
我是采购，手上18张在途采购单，帮我排一下今天该催谁。
在途采购单、供应商履约台账、工单需求计划、库存快照我都放在
D:\workbuddy_data\采购\场景②_来料跟催\ 了。

别按逾期天数排。每张单都要算清楚晚到会卡哪张工单、哪个客户，库存还能撑几天。
给我四色分级、到货预测、分供应商的跟催话术（要带履约数据）、待办清单。
```

Skill 会自动读取目录下全部文件，按表头识别哪份是在途单、哪份是履约台账。

### 2.2 只问优先级

```
今天该催哪几张单？
```

→ Skill 只输出 🔴 紧急催清单 + 每张的判定依据，不出话术。

### 2.3 只要话术

```
帮我写一段催S-021 的话，要带上他家的准时率。
```

→ Skill 只跑「履约画像 + 话术生成」，输出可直接发送的话术（含四要素自检）。

### 2.4 单张单的可信度判断

```
S-021 说 PO-20260728-031 08-06 一定到，信得过吗？
```

→ Skill 只跑「到货预测」，输出：该供应商准时率 / 平均延误 / σ → 预测到货日 → 与下游断料日的缺口 → 可信度结论。

### 2.5 直接拖文件

用户把 4 份表一起拖到对话框。**只给在途采购单一份也能跑**，但会降级（见第 3 章）。

## 3. 输入格式规范

**不强制格式** — 采购现场的现实是"在途单在 ERP、履约台账在自己的 Excel、工单计划在 PMC 手里、库存在仓库系统"。

| 输入 | 必需 | 关键字段（有别名容错） | 缺失时的降级行为 |
|---|---|---|---|
| **在途采购单** | **必需** | 采购单号 / 物料编码 / 订单数量 / 供应商 / 下单日期 / 承诺到货日 / 当前状态 | 缺失则无法运行，Skill 明确提示"请提供 ERP 采购模块在途单导出" |
| **供应商履约台账** | 强烈建议 | 供应商编码 / 总单数 / 准时单数 / 延误天数（或逐单的承诺日 + 实际到货日） | 缺失则**无法做到货预测**，分级退化为"只看承诺日 vs 断料日"，并提示"当前预测未计入供应商历史延误，实际风险可能被低估" |
| **工单需求计划** | 强烈建议 | 工单号 / 产品 / 数量 / 计划上线日 / 客户 / 所需物料 / 需求数量 | 缺失则**无法测算下游影响面**，四色分级退化为两色（逾期 / 未逾期），价值大幅下降，Skill 会明确提示 |
| **库存快照** | 建议 | 物料编码 / 现有库存 / 安全库存 / 日均耗用量 | 缺失则可撑天数按 0 计（最保守），断料日 = 计划上线日，会导致偏保守的分级，需提示用户 |
| **替代料关系表** | 可选 | 主料 / 替代料 / 认证状态 / 客户批准要求 | 缺失则升级建议里不出替代料路径 |

**列名容错**：以下都能识别为"承诺到货日"：承诺到货日 / 承诺交期/ 交期 / 计划到货日 / 约定到货日 / Promised Date / ETA。
以下都能识别为"日均耗用量"：日均耗用量 / 日耗 / 日均用量 / 平均日耗 / Daily Usage。
若同时存在「原承诺到货日」与「最新承诺到货日」，**取最新承诺日为有效承诺日用于预测**，但**逾期天数仍按原承诺日算**（否则供应商每改一次日期就能把逾期记录洗白）。

**格式支持**：xlsx / xls / csv / ERP 导出的 txt / pdf（对账单）/邮件正文粘贴 / 微信截图（多模态识别供应商口头承诺）。

**必须向用户确认的一个参数**：分析基准日（默认取今天）。逾期天数、可撑天数全部依赖这个日期。

## 5. 核心处理逻辑

### 5.1 跟催五步法

```
Step 1 对齐   在途单逐张挂上：物料 / 供应商 / 有效承诺日 / 逾期天数 / 已到数量 / 剩余数量
Step 2 画像   算供应商准时率 / 平均延误 / 波动度 σ（见 5.2）
Step 3 预测   预测到货日 = 有效承诺日 + 平均延误（取整），含承诺失效兜底（见 5.3）
Step 4 影响   在途单 → 工单 → 客户；算可撑天数、断料日、缺口天数（见 5.4）
Step 5 分级   四象限定色 → 生成话术（见 5.6）→ 定升级路径（见 5.7）→ 出待办
```

**关键顺序说明**：Step 4（下游影响面）必须放在 Step 5（分级）之前，且**不能被 Step 3 的结果左右**。常见错误是"看到预测会晚就直接判红"——晚不晚是供应商的事，急不急是我们自己库存和排产的事，**两者必须分别算完再交叉**。这就是四象限的意义。

### 5.2 供应商履约画像计算方法

#### 三个指标的定义与算式

| 指标 | 算式 | 口径要点 |
|---|---|---|
| **准时率** | 准时单数 ÷ 总单数 | 实际到货日 **≤** 承诺到货日记准时（**当天到货算准时**）。只统计**已关闭单**（已全部到货入库），在途单结果未知，计入会虚高 |
| **平均延误天数** | 延误天数合计 ÷ **延误单数** | **分母是延误单数，不是总单数**。这是最容易搞错的一条 |
| **延误波动度 σ** | 各单延误天数（准时单记 0 天）的**样本标准差** | σ 越大 = "什么时候到"越不可预测，需要更早介入、留更多冗余 |

#### 为什么平均延误的分母是延误单数

这是本 Skill 最重要的口径决策，直接影响预测准确度。

```
S-021：13 张单，8 张准时，5 张延误（2/3/4/5/7 天，合计 21 天）

❌ 除以总单数：21 ÷ 13 = 1.6 天 → 预测 08-06 + 2 天 = 08-08→ 判定"不急"→漏判
✅ 除以延误单数：21 ÷ 5 = 4.2 天 → 预测 08-06 + 4 天 = 08-10 → 判定 🔴 → 抓住
```

**理由**：跟催场景要回答的是"**如果它晚，会晚多少**"，这是一个条件期望。把准时单的 0 天摊进去，会系统性低估延误幅度，让所有单看起来都还来得及 —— 而这恰恰是最危险的误判方向。准时率这个指标已经单独承担了"会不会晚"的判断，两个指标各管一件事，不要混。

#### 履约等级判定

| 等级 | 条件 | 跟催策略 |
|---|---|---|
| **A 稳定** | 准时率 ≥ 90% 且 σ ≤ 1.0 | 例行邮件留痕即可，不占用电话资源。**逾期也先看库存再决定要不要催** |
| **B 一般** | 准时率 70% ~ 90% | 承诺日前 1 天确认发运节点 |
| **C 高风险** | 准时率 < 70%，或 σ > 3.0 | 承诺日**前 3~5 天**就介入；只认书面承诺；关键料必须要求分批发货 |

**样本量下限**：单个供应商近 6 个月单数 < 5 张时，准时率不稳定，**必须标注"样本量不足（N=x），仅供参考"**，且不得单凭该指标判 C 级。

#### 口头承诺兑现率（可选加分项）

若台账里有跟催记录，额外算一个指标：**近 3 次口头承诺（电话 / 微信）中兑现几次**。这个数字在话术里比准时率更有杀伤力 —— 准时率是系统数据，供应商可以辩解"你们下单太急"；口头承诺兑现率是他自己说过的话。

### 5.3 到货预测方法

#### 基础公式

```
预测到货日 = 有效承诺到货日 + 该供应商平均延误天数（四舍五入取整天，0.5 进位）
```

- **有效承诺日**：有「最新承诺到货日」取最新，否则取原承诺日
- **逾期天数**：始终按**原承诺日**算 = 基准日 − 原承诺日（仅计正数）。供应商改期不能洗白逾期记录

#### 三种特殊情况的处理

| 情况 | 处理规则 | 理由 |
|---|---|---|
| **已逾期，且按公式算出的预测日已过基准日** | 预测日取 **基准日 + 1 天**兜底，并标注"**承诺失效**" | 这类单的预测值只能当**下限**用；真正的动作是"重新取得书面承诺日"，而不是相信一个算出来的日期 |
| **供应商未给出新承诺日（最新承诺 = 空）** | 按原承诺日 + 平均延误推算，并**强制标注"信息缺口"** | 无承诺日本身就是最高级别的风险信号，比"承诺了但会晚"更严重 |
| **已发货在途且有物流单号** | 按物流时效算，**不叠加历史平均延误** | 货已在路上，历史履约数据不再适用。这类单不要重复电话催 |

#### 预测的边界（必须对用户说明）

预测是**概率判断，不是确定结论**。所以由预测触发的动作只能是：
- ✅ 提前跟催、要求分批发货、通知 PMC 预留调整余量
- ❌ 直接改排产、直接下替代料订单、直接向客户报延期

σ 大的供应商（如 σ = 3.5 天）要按**预测日 ±σ 区间**看，而不是一个确定的日子。Skill 输出时会把 σ 一并列出，就是为了让采购知道这个预测有多"虚"。

### 5.4 下游影响面测算（可撑天数与断料日）

```
可用库存   = 现有库存 − 安全库存
可撑天数   = 可用库存 ÷ 日均耗用量        （保留 1 位小数）
断料日     = 关联工单计划上线日 + ⌊可撑天数⌋   （向下取整，不给自己留虚假余量）
缺口天数   = 预测到货日 − 断料日
缓冲天数   = − 缺口天数
```

**四条口径要点**：

1. **安全库存不算进可用库存**。安全库存是给客户需求波动留的，动用需PMC 批准。把它算进来 = 提前花掉救命钱，会系统性低估风险
2. **可撑天数向下取整进断料日**。可撑 1.8 天不能算 2 天，宁可保守
3. **在途单 → 工单的配对用 FIFO**：同一物料被多张工单需求、同时有多张在途单时，按「工单计划上线日先后」与「在途单承诺到货日先后」一一配对。第 2 批及以后的在途单，**前批库存已被首个工单占用，可撑天数按 0 计**
4. **部分到货的单只看剩余数量**。已到 1500kg 的那部分已进库存快照，不能重复计算

**配对失败的处理**：

| 情况 | 处理 |
|---|---|
| 在途单的物料在工单需求里找不到 | 标注"无下游需求（备库/ 售后备件）"，直接判 🟢 或 ⚪，不占跟催资源 |
| 一张在途单对应多张工单 | 取**最早上线**的那张工单为主判定对象，其余在备注里列出（影响面更大，话术里要提） |
| 工单需求量 > 在途单数量 + 可用库存 | 标注"**数量缺口**"，这是另一类问题（漏下单 / 下单量不足），要单独提示补下单，不是跟催能解决的 |
| 库存快照里没有该物料 | 可撑天数按 0 计，并提示"该物料无库存记录，请确认是否为新料号" |

### 5.5 风险分级四象限规则（逾期程度 × 下游影响面）

**这是本 Skill 的核心。** 两个轴各自独立：

```
        下游影响面（缺口天数 /缓冲天数）
              紧 ←─────────────────→ 松
          ┌─────────────────┬─────────────────┐
     已│   🔴 紧急催      │  ⚪ 逾期但不急│
     逾   │  逾期 + 会停线    │ 逾期但库存能撑    │
     期   │  最高优先级       │  只需邮件留痕     │
          ├─────────────────┼─────────────────┤
     未   │   🔴 紧急催      │   🟢 正常        │
     逾   │ 没逾期但按历史推│  没逾期且缓冲足│
     期   │ 算会晚 + 会停线   │  周例会常规跟踪   │
          │ ★传统方法筛不出│                │
          └─────────────────┴─────────────────┘
                🟡 关注 = 缓冲 ≤ 2 天的临界带，或已逾期但尚有缓冲
```

**判定顺序（严格按此顺序，命中即停）**：

```
① 缺口天数 > 0                                        → 🔴 紧急催
② 已逾期 且 缓冲 ≥ 7 天 且 最早上线日 ≥ 基准日 + 14 天  → ⚪ 逾期但不急
③ 缓冲 ≤ 2 天                                → 🟡 关注
④ 已逾期（但不满足 ②）                                 → 🟡 关注
⑤ 其余                                                → 🟢 正常
```

**⚪ 三个条件必须同时满足**，缺一不可：
- 缓冲 ≥ 7 天 —— 供应商再晚一周也不影响
- 最早上线日 ≥ 14 天后 —— 下游根本还没排到
- 已逾期 —— 未逾期的正常单归🟢，不需要单独标一个"不急"

只满足前两条但未逾期 = 🟢 正常；只满足逾期 = 🟡 关注。**把这三条同时收紧，是为了防止"逾期但不急"被滥用成"逾期都不急"的偷懒借口。**

**四色对应的动作强度（跟催资源分配）**：

| 色 | 动作 |渠道 | 时限 | 是否占用电话资源 |
|---|---|---|---|---|
| 🔴 紧急催 | 电话跟催（带履约数据）+ 索取书面承诺 + 同步 PMC | 电话 + 邮件留痕 | 当日 | ✅ 优先占用 |
| 🟡 关注 | 邮件确认发运节点并留痕 | 邮件 | 当日，48h 未回复升🔴 | ❌ |
| 🟢 正常 | 周例会常规跟踪 | 无 | 周 | ❌ |
| ⚪ 逾期但不急 | 本周内邮件要一次书面到货日，**明确告知"无需加急"**；纳入月度履约扣分 | 邮件 | 本周内 | ❌ |

**⚪ 单为什么还要发邮件**：两个目的——① 留痕，逾期事实要进履约台账，否则月度绩效算不出来；② **明确告知不用加急**，保护供应商关系。A 级供应商被无差别催货，会把有限的加急产能浪费在不需要的单上，真正急的时候反而没得用。

**分级结果的自校验**：四色张数加总必须等于在途单总数。不等就是有单被漏判或重复判，Skill 拒绝输出并报错。

### 5.6 跟催话术生成规则（必须带数据筹码，禁止空催）

#### 四要素（缺一不可）

| # | 要素 | 内容 | 反例 |
|---|---|---|---|
| 1 | **履约数据** | 近 6 个月准时率 + 平均延误天数（带算式：13 张单准时 8 张） | "你们经常延误" |
| 2 | **预测结果** | 按历史推算实际约几号到 | "怕你们又晚" |
| 3 | **后果** | 卡哪张工单 / 哪个客户 / 库存撑几天 / 几号断料 | "会影响我们生产" |
| 4 | **具体请求** | 几号前发多少件，可执行、可回复是或否 | "请尽快""请务必" |

#### 禁止清单

```
❌ "请尽快安排"           —— 无时点，供应商无法回复
❌ "请务必按期交货"       —— 无信息量
❌ "麻烦催一下"           —— 把压力踢回给对方，没有筹码
❌ "领导很生气"           —— 情绪代替事实，一次性消耗关系
❌ "你们上次也晚了"       —— 有指责无数据，容易被辩解
✅ "近 6 个月 13 张单准时 8 张，准时率 62%，平均延误 4.2 天"  —— 事实，无法辩解
```

#### 三条生成规则

1. **按供应商聚合，不按单聚合**。一家供应商有3 张单要催，合并成一次沟通、一封邮件，按单内优先级排序。一张单打一个电话是在消耗自己的时间和对方的耐心
2. **请求必须给对方留可执行的余地**。"08-05 前分批先发 60 件保上线（60 件可支撑 3 天），余 60 件 08-10 前补齐"——比"120 件必须 08-05 全到"成功率高得多。**分批发货是跟催最有效的杠杆**，因为它把"你做不到"变成"你能做到一部分"
3. **对 A 级供应商，话术要反着写**。明确写"这批 08-08 到完全可以接受，不需要你方调整排产"，并顺带表扬（"准时率 92%，是我们履约最稳的板材供应商，这一点在年度框架续签时会体现"）。**跟催的目标是保交付，不是显示自己在干活。**

#### 话术发出前的六条自检

```
① 有没有引用准时率和平均延误的体数字？
② 有没有说清预测到货日与算法？
③ 有没有点明卡哪张工单、哪个客户、停几天？
④ 请求是不是具体到"几号发多少件"？
⑤ 有没有约定书面回复时限？
⑥ 对履约好的供应商，有没有把"不需要你加急"也说清楚？
```

### 5.7 升级规则（三条路径互不替代）

**核心判断**：三条路径的成本完全不同，**必须从成本最低的先试**。

```
成本从低到高：
① 通知 PMC 调排产   —— 内部动作，不涉外，最快见效
② 要求供应商分批发货 —— 涉外但不升级，不消耗关系
③ 找供应商老板      —— 消耗商务关系，用一次少一次
④ 启动替代料        —— 涉及品质/工艺/客户批准，周期最长、风险最高
```

#### 三条路径的触发条件

| 路径 | 触发条件 | 前置要求 | 不适用的情况 |
|---|---|---|---|
| **通知 PMC 调排产** | 缺口 > 0，且**存在同产品、上线日更晚、客户要求更松的工单可对调** | 两张工单产品相同或工艺路线相近；后者无PPAP / 无指定料号 | 全部工单都是 KA 客户 / 都有PPAP 要求 → 无可调空间 |
| **找供应商老板 / 升级采购经理** | ① **当日 18:00 未取得书面承诺**（信息缺口）② 连续两月准时率 < 70% ③ 断供风险（对应手册 L3 橙色） | 已先走过销售层且留痕；有履约数据支撑 | 只是"态度不好""回复慢"——不构成升级理由 |
| **启动替代料** | 缺口 > 0 且**调排产无空间 + 分批发货被拒** | ① 替代料已过认证（EVT / DVT）② **KA 客户 PPAP 锁定料号必须客户书面批准 + 走 ECN** ③ 品质 SQE + 工艺出可行性意见 | 认证未通过的二供不能直接切；采购**不得自行拍板**（对应手册明确禁止事项） |

#### 硬规则

1. **升级是有成本的，用早了下次就不好用**。能靠调排产解决的，不要动替代料；能靠分批发货解决的，不要升级到老板层
2. **替代料路径必须同时启动"关闭条件"**。客户不批准就明确关闭这条路径并记录，不能挂在那里当心理安慰
3. **升级的触发条件要写成客观事实**（"18:00 未取得书面承诺"），不能写成主观感受（"供应商不配合"）。客观条件才能自动触发，主观感受只会拖到来不及
4. **每次升级都要带上履约数据**。向采购经理上报时，说"S-021 准时率 62%、连续两月低于 70%、本次 PO缺口 +1 天影响某主机厂"，比说"S-021 又拖了"有用得多

### 5.8 常见坑

| 坑 | 表现 | 本 Skill 的应对 |
|---|---|---|
| **按逾期天数排序跟催** | 逾期 5 天的排第一，实际它库存能撑 18.7 天；没逾期但库存只够1 天的排不进来 | 四象限强制两轴独立判定，逾期只是其中一轴 |
| **"没逾期"当成"不用催"** | 传统 Excel 筛"交期已过"，未逾期单一张都筛不出来 | 到货预测把未逾期单也纳入判定，缺口 > 0 一律判 🔴 |
| **平均延误分母搞错** | 用总单数当分母，4.2 天算成 1.6 天，风险被系统性低估 | 硬性规定分母 = 延误单数，并在输出里附算式 |
| **准时率把在途单算进去** | 在途单结果未知，计入会虚高准时率 | 只统计已关闭单，并在口径说明里写清 |
| **安全库存算进可用库存** | 提前花掉救命钱，可撑天数虚高 | 可用库存 = 现有 − 安全，安全库存不参与计算 |
| **多张在途单对同一物料重复用库存** | 第 2 批也按完整库存算缓冲，两张单都判"不急" | FIFO 配对；第 2 批及以后可撑天数按 0 计 |
| **部分到货重复计算** | 已到的 1500kg 既在库存里、又在在途单里算了一遍 | 部分到货单只算剩余数量 |
| **相信口头承诺** | 供应商说"明天到"就改判绿色 | 口头承诺不改变分级，只有书面承诺 + 物流单号才降级 |
| **供应商改期洗白逾期** | 每次改期就重算逾期天数，台账永远干净 | 逾期天数按**原承诺日**算，改期只影响预测不影响逾期记录 |
| **无差别催所有单** | A 级供应商被反复催，加急产能浪费在不需要的单上 | ⚪ 单明确告知"无需加急"；🟢 单不占用电话资源 |
| **空催** | "请尽快安排"，供应商无法回复，也没有压力 | 话术四要素强制 + 禁止清单 + 六条自检 |
| **一单一电话** | 一家供应商 3 张单打 3 个电话 | 按供应商聚合成一次沟通 |
| **只催不留痕** | 微信口头催，月底算履约拿不出证据（对应手册"催料必须可追踪"） | 每条待办都有"验收标准 = 书面回复"，微信也要求截图归档 |
| **替代料越界** | 采购自己决定切料，KA 客户 PPAP 料号未经批准 | 替代料强制前置条件：认证状态 + 客户批准 + ECN |
| **无承诺日的单被漏掉** | 供应商没给日期，表里是空的，筛选时被跳过 | 空承诺日强制标注"信息缺口"，按最高风险信号处理 |
| **数量缺口当成交期问题催** | 需求 500 但只下了 300，怎么催都不够 | 配对时校验需求量 vs 在途量 + 可用库存，数量不足单独提示补下单 |

### 用户常见问法

| 用户说 | Skill 动作 |
|---|---|
| "今天该催哪几张单" | 五步法全流程，输出四色分级 + 话术 + 待办 |
| "逾期最久的是哪张" | 输出逾期排序，并**同时给出各张的缺口天数**说明逾期 ≠ 紧急 |
| "S-021 说明天到，信得过吗" | 只跑履约画像 + 到货预测，输出可信度结论 |
| "帮我写段催 S-021 的话" | 生成含四要素的话术 + 六条自检 |
| "这批料晚到会影响谁" | 在途单 → 工单 → 客户，输出影响链条 + 停线天数 |

### 追问剧本

**Q1**：逾期 5 天的单为什么排在最后？
→ 因为逾期和紧急是两件事。PO-20260710-008逾期 5 天，但那颗料（M-SPCC-20 冷轧板）可用库存 2800kg、日均耗用 150kg，可撑 18.7 天；且它在 8 月**没有任何工单需求**，最早是 WO-2026-0824 于 09-08 上线，算上库存断料日是 09-26。供应商新承诺 08-08，缓冲 47 天。这张单今天占用一个电话，就等于真正卡交付的那张少了一个电话。

**Q2**：还没到交期的单，凭什么现在就催？
→ 凭历史数据。PO-20260728-031 承诺 08-06，看着还有 2 天。但 S-021 近 6 个月 13 张单准时 8 张（准时率 62%），延误时平均晚 4.2 天 → 预测 08-10 到。而下游 WO-2026-0812 于 08-08 上线，M-PCB-001 可用库存只够 1.0 天 → 08-09 断料。缺口 +1 天，某主机厂订单直接受影响，且是 PPAP 锁定料号不能替代。**等到 08-06 发现没到再催，已经来不及了。**

**Q3**：预测到货日会不会算错？错了怎么办？
→ 会。这是概率判断不是确定结论，所以 Skill 只用它触发"提前催 + 要分批"这类**低成本、可撤销**的动作，不用它直接改排产或向客户报延期。σ 值一并输出就是为了让采购知道这个预测有多虚：S-012 的 σ 是 0.5 天，预测基本准；S-052 的 σ 是 3.5 天，预测只能当区间看。**预测的作用是决定跟催顺序，不是替代判断。**

**Q4**：为什么平均延误要除以延误单数，不除以总单数？
→ 因为要回答的问题是"如果它晚，会晚多少"。S-021 除以总单数是 21 ÷ 13 = 1.6 天，预测 08-08，判定"不急"→ 漏判；除以延误单数是 21 ÷ 5 = 4.2 天，预测 08-10，判定 🔴 → 抓住。把准时单的 0 天摊进去，所有单看起来都还来得及，而这正是最危险的误判方向。"会不会晚"由准时率单独负责，两个指标各管一件事。

**Q5**：供应商说"明天一定到"，能不能就把它降级？
→ 不能。口头承诺不改变分级。S-021 近 3 次微信承诺有 2 次没兑现，这个数字本身就该写进话术。只有两种情况可以降级：①拿到**书面**承诺（邮件 /盖章回单）② 已发货且有**可查的物流单号**。第② 种情况下预测改按物流时效算，不再叠加历史平均延误—— 货已在路上，历史数据不适用了。

**Q6**：为什么不急的单还要发邮件？不是浪费时间吗？
→ 两个目的。① **留痕**：逾期事实要进履约台账，否则月度绩效算不出来，年度框架谈判也没有依据；② **明确告知不用加急**：A 级供应商被无差别催货，会把有限的加急产能浪费在不需要的单上，真正急的时候反而没得用。一封邮件同时处理 5 张 ⚪ 单，成本很低。

**Q7**：这套方法要求的四份表，客户不一定都有怎么办？
→ 在途采购单是唯一硬性必需的。缺工单需求计划 → 四色退化成两色（逾期 / 未逾期），价值大幅下降，Skill 会明确提示；缺库存快照 → 可撑天数按 0 计，分级偏保守；缺履约台账 → 无法做到货预测，Skill 会提示"当前预测未计入供应商历史延误，实际风险可能被低估"。**降级路径都会明说，不会静悄悄给一个看起来完整的错答案。**

## 7. Skill 组合

| 组合 Skill | 何时组合 | 效果 |
|---|---|---|
| **齐套与缺料预警** |跟催前先要知道哪些工单缺料 | 先出缺料清单定"要催什么"，再由本 Skill 定"先催谁、怎么催" |
| **生产排产 / PMC 排程** | 缺口 > 0 且需要对调工单排期时 | 把"通知 PMC 调排产"从建议变成可执行的排产方案 |
| **ECN 工程变更管理** | 启动替代料需要客户批准与文件改版时 | 替代料切换走 6 步法审批，避免采购越界拍板 |
| **交付可行性分析** | 缺料确定影响客户交期时 | 评估在手订单交付影响，决定是否要向客户提前报延期 |
| **钉钉分部门通知 / 待办推送** | 待办清单要推到 PMC / 品质 / 仓库时 | 按责任人拆分待办，@到人，带时限 |
| **供应商绩效评审** | 月度输出高风险供应商清单时 | 把本次跟催结果沉淀成绩效数据与订单策略调整依据 |

**推荐组合链路**（采购处理一天跟催的完整闭环）：

```
早上 08:30 拿到四份表
  → [齐套与缺料预警] 明确哪些工单缺料、缺多少
  → [来料跟催·风险分级与话术生成] 四色分级 + 到货预测 + 话术 + 待办
  → 缺口 > 0 且可调排产 → [生产排产] 出对调方案，PMC 老周确认
  → 调排产无空间 → [ECN 工程变更管理] 替代料走审批（含客户批准）
  → 确定影响客户交期 → [交付可行性分析] 评估在手订单，决定是否报延期
  → 待办分派 → [钉钉分部门通知] 推 PMC / 品质 / 仓库责任人
  → 月末 → [供应商绩效评审] 本次逾期记录进台账，调整订单策略
```
