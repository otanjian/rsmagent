# 试产开工条件核查 Skill

> 研发 PE 场景 3.2 专用 Skill · 一句话跑完 5 项核查 · 半天问一圈变一分钟

---

## 1. 用途

试产 / 量产前，PE 要跨5 个部门问一圈：BOM 齐了吗？料齐了吗？SOP 有了吗？产能腾出来了吗？工装到位了吗？传统做法是发企微、打电话、开碰头会，几个小时才凑齐答案；等答案凑齐，其中某项状态又变了。

这个 Skill 一次做完 4 件事：

1. **并行读 5 份跨部门报表**（BOM 基线 / 齐套报表 / SOP 发放台账 / 产能负荷表 / 工装状态表）
2. **按产品 ID 交叉过滤**，每份文件里跟本产品相关的部分自动匹配
3. **五项打红黄绿 + 综合判定**（不再是"能开/不能开"二元，而是"可开 / 需补 / 不可开"三档）
4. **卡点补齐建议 + 责任岗位**（不只打颜色，还给具体动作）

---

## 2. 触发方式

### 2.1 用户一句话触发（推荐）

```
下周一要试产 P-IPC-01300 台，
现在具备开工条件吗？不具备的话卡在哪里？

数据在 D:\workbuddy_data\研发PE\开工条件\ 目录下：
BOM 基线、齐套报表、SOP 发放台账、产能负荷表、工装状态表。

请五项分别打红黄绿，并给出卡点补齐建议 + 责任岗位。
```

### 2.2 极简版（数据放约定目录时）

```
下周一要试产 P-IPC-01 300 台，现在具备开工条件吗？
```

Skill 会自动去约定目录读5 份最新报表，并做五项核查。

---

## 3. 五项核查规范

| # | 检查项 | 数据源 | 判定规则 |
|---|---|---|---|
| ① | **BOM 版本** | BOM 基线.xlsx | 当前版本已受控 + ECN已闭环 → 🟢；有未闭环 ECN → ⚠；未受控 → 🔴 |
| ② | **物料齐套** | 齐套报表.xlsx | 需求 ≤ 可用 → 🟢；需求 > 可用但替代料可补 → ⚠；缺口无替代 → 🔴 |
| ③ | **工艺 SOP** | SOP 发放台账.xlsx | 完整工序链的 SOP 都已受控 + 发放 → 🟢；关键工序 SOP 未发放 → 🔴 |
| ④ | **产能位** | 产能负荷表.xlsx | 所有工序有余量 → 🟢；某工序 ≥ 90% → ⚠；某工序 100% 满载 → 🔴 |
| ⑤ | **工装治具** | 工装状态表.xlsx | 所需工装全部就绪 → 🟢；有工装未点检/未到位 → ⚠；关键工装缺失 → 🔴 |

---

## 4. 综合判定规则

- 5 项全绿 → **🟢 绿灯 · 可开工**
- 有红灯但**都能通过补齐动作解决** → **⚠ 黄灯 · 可开工，X项需补**
- 有红灯**无法在合理时间内解决**（如工装报废需重制） → **🔴 红灯 · 不可开工**
- 关键原则：**黄灯必须给"补齐动作 + 责任岗位 + 预计完成时间"**，不能只打颜色

---

## 5. 输出格式规范

```markdown
## P-IPC-01 试产 300 台 · 开工核查结果

**综合结论**：⚠ 黄灯 · 可开工，2 项需补

### 五项红黄绿

| # | 检查项 | 状态 | 关键结论 |
|---|---|---|---|
| ① | BOM 版本 | 🟢 | v1.3 已受控，ECN-2026-0728-01 已闭环 |
| ② | 物料齐套 | ⚠ | 主控板 M-PCB-001 缺 60（替代料 M-PCB-002 可补） |
| ③ | 工艺 SOP | 🟢 | SOP-A-06 V1.3 已发放，工序链完整 |
| ④ | 产能位 | 🔴 |喷涂 WC-PAINT 100% 满载 |
| ⑤ | 工装治具 | 🟢 | 6 项齐备，含新增 Type-C焊接治具 |

### 卡点补齐建议

**② 主控板缺口 60 件**
- 用替代料 M-PCB-002 × 60 补齐（沙箱查询：avail = 60，恰好补平）
- 需走替代评审+ 首件校验，预计 1 个工作日
- 责任：PMC + 采购

**④ 喷涂产能满载**
- 300 台喷涂需求 20 小时，喷涂本周已排 80 小时
- 建议：300 台分 3 批过喷涂，每批 100 台 × 6.7 小时，穿插到装配完工节奏
- 责任：PMC + 生产主管

**达成上述条件后 → 可开工 🟢**
```

## 6. 快速参考卡

### 用户常见问法

| 用户说 | Skill 动作 |
|---|---|
| "下周一试产 XX 能开工吗" | 读 5 份报表 · 打五项红黄绿 · 综合结论 |
| "红灯项能不能豁免" | 结合数据给"豁免代价" vs "补齐代价"两方案对比 |
| "直接开了会怎样" | 列具体后果（停线在哪、堵在哪、交期能不能守） |
| "还有没有其他隐性风险" | 主动补盲：人员到位、来料检验、客户是否知情 |

## 7. Skill 组合

| 下游 Skill | 何时组合 | 效果 |
|---|---|---|
| **交付可行性分析** | 出黄灯或红灯 · 需要评估对客户交期的影响 | 结合 5.1/5.4 场景 · 判断是否需重排|
| **企微等IM分部门通知** | 卡点补齐建议出来后需推IM | 按责任岗位分段推送 |
| **BOM 导入·工程基线核对** | 若 BOM 项打红 · 需要重新核对新版基线 | 场景 3.1 联动 |
