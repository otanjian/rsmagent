# 分级与归口规则 · 完整版

本文件是 SKILL.md STEP 3、STEP 4 的展开，可直接作为企业内部《异常分级与升级管理规范》使用。

---

## 一、为什么只设三级

一个真实的教训：某企业导入分级初期，一线把 **80% 的问题都判成最高级**，资源被彻底摊平，真正紧急的反而没人跟；后来把最高级压到 **15% 左右**，客户满意度反而上升了。

原因不复杂：**级别设计得越复杂，一线越倾向于全部往高的填。** 因为对上报人来说，"说重了"的代价远小于"说轻了没人管"的代价。

所以设计原则是：

- **三级（P1/P2/P3）+ 三层（班组/ 部门 / 老板）** —— 这是中小企业真正维持得住的粒度
- 不做四象限矩阵，不做 5 级细分
- **P1 占比是这套机制的健康指标**。如果每周 P1 超过 3 件，说明阈值需要上调，或者企业确实处在需要专项整治的状态

## 二、三级判定条件（默认版，企业可改）

### P1 紧急 · 响应 2 小时 · 24h 内出临时方案 · 升 L3 总经理

满足**任一**即为 P1：

1. **已导致或将导致客户停线** —— 判据是客户产线上线日 vs 我方可交付日
2. **A级客户明确要求升级** —— 客户主动说"要找你们老板""要投诉到高层"
3. **停线影响 3 张以上在制工单** —— 数工单号，不数感觉
4. **同一问题第 3 次以上重复发生** —— 来自历史检索

通知范围：总经理 + 相关部门负责人 + 销售

### P2 重要 · 响应当日 · 3 个工作日出方案 · 升 L2 部门经理

满足**任一**即为 P2：

1. 影响单张工单交期
2. B/C 级客户投诉但未停线
3. 同一问题第 2 次发生
4. 跨 2 个部门需协调

通知范围：相关部门负责人

### P3 一般 · 响应 3 个工作日 · 1 周内闭环 · L1 班组/主管

满足**任一**即为 P3：

1. 客户提醒改进但已验收（未要求退货、未索赔）
2. 现场可自行消化（且现场已做出妥善处置）
3. 首次发生且影响面单一

通知范围：班组内 + 记录归档

## 三、四维判据的取数口径

| 判据 | 取数来源 | 可算/需判 | 注意 |
|---|---|---|---|
| **影响面** | 涉及工单号数量、订单金额合计、是否已停线 | 客观可算 | 工单要逐个数出来，不能写"多张" |
| **紧迫度** | 客户产线上线日、约定交货日、已拖天数 | 客观可算 | 跨部门久拖类要算"从首次提出至今多少天" |
| **复杂度** | 原文中出现的部门数 | 客观可数 | ≥3 个部门且各方说法都成立 → 触发"需管理层指定" |
| **是否重复发生** | 历史处置记录检索 | **需检索，无字段** | 见下节 |

### 商业权重的取数（决定同一事实的不同分级）

同样一条"客户投诉外观问题"，A 级客户和 C 级客户的分级完全不同。必须取到：

- 客户等级（A/B/C）
- 近 12 个月采购额与**占营收比**
- 近 12 个月投诉次数
- 是否有质量协议
- 历史特殊情况（如"去年曾因交期问题暂停下单 2 个月"——这类备注价值极高）

**若客户背景数据缺失**：一律按 B 级处理，并在输出中标注"客户等级未知，按 B 级处理，请人工校准"。

## 四、重复性检索方法（最有价值的一步）

### 检索键优先级

1. **设备编号** —— 如"2 号折弯机"。同一台设备的同类故障是最硬的重复信号
2. **产品 + 部位** —— 如"P-CAB-11 门锁"。同一部位反复出问题指向设计或工艺缺陷
3. **客户 + 问题类型** —— 同一客户反复投诉同类问题，关系风险远大于技术风险
4. **工序 + 现象** —— 如"喷涂 + 返工率"

### 每条命中必须提取四项

```
发生日期 ｜ 当时归口部门 ｜ 当时处置措施 ｜ 是否闭环
```

### 三个高价值信号（看到就要显式指出）

**信号① 当时归口为"未明确"**
说明这个问题当时就没人认领。如果历史上出现两次"未明确"，本次基本可以断定是**归口机制本身有缺口**，而不是某次疏忽。

**信号② 当时处置含"临时""现场修配""口头提醒""未做原因分析"字样**
这是最有价值的发现：**前几次的临时处置往往就是本次发生的直接原因。**

示例因果链（必须显式写出来）：
> 2026-04-09 液压站漏油 → 处置为"临时补漏，未换密封件" → 2026-08-08 同一处再次漏油
> **今天这次不是新的意外，是四个月前那个"先凑合一下"的决定结出的果。**

**信号③ 历史记录不完整 / 经手人已离职**
如"2026-05-21 记录不完整，当时经手销售已离职"。这类情形要在输出中提示：
- 本次判定的重复次数可能**被低估**
- 建议按可获得的凭证（财务费用单、邮件、聊天记录）回溯补录

### 输出形态

```
本次为第 N 次发生
├─ 第1次：YYYY-MM-DD ｜归口 X ｜处置：… ｜是否闭环
├─ 第 2 次：YYYY-MM-DD ｜归口 未明确 ｜处置：无 ｜未闭环
└─ 本次：YYYY-MM-DD
```

## 五、降级判定（这套机制的核心价值）

**必须对每一条上报明确标出：与上报预期一致 / 降级 / 升级。**

降级是最容易被质疑的输出，所以理由要给足——把所有判据逐条摆出来。

### 典型该降级的三种情形

**情形① 按"客户投诉"上报，实为 P3**
判据组合：C 级客户（占营收 < 3%）+ 货已交付且客户已验收 + 未要求退货或索赔 + 客户表述为"下次注意""提醒改进"

> 降级不等于不处理。仓库出一份包装作业要求即可闭环，**只是不需要占用管理层的处置时间**。

**情形② 按"现场停线"上报，实为排班/人员问题**
判据组合：未实际停线 + 未产生不良 + 现场已自行做出妥善处置 + 首次发生

> 关键是识别出**"这不是异常，是日常管理"**。班长让新人练手而不是硬上产量，这是正确处置，不是需要升级的问题。

**情形③ 按"批量不良"上报，但数量与影响面均单一且首次**
按 P2 或 P3 处理，视是否影响交期。

### 降级的表述方式

不要写"此项不重要"。要写：

> 判为 P3，留在现场处理。理由：①…②…③…。**建议动作**：X 部门出 Y，Z 日前闭环。**不占用今日管理层会议。**

最后那句"不占用今日会议"是降级判定的落地——**它明确告诉老板：这条你今天可以不看。**

## 六、归口判定与排除逻辑

### 输出格式（固定）

```
建议归口：X 部门
为什么是 X：（判据）
为什么不是 Y：（排除理由）
为什么不是 Z：（排除理由）
协办部门：…
本次特别要解决的：（若为重复发生，必须写这一项）
```

### 常见问题的归口参考

| 问题特征 | 建议归口 | 排除逻辑要点 |
|---|---|---|
| 尺寸/孔位类不良，**工艺文件有明确要求** | 生产部 | 属执行偏差。**若工艺文件本身无要求或存在内部矛盾，则改归工艺部** —— 这一步必须先核对工艺文件 |
| 设备故障，首次 | 设备科 | 属维修范畴 |
| 设备故障，**同类重复发生** | 设备科 | 仍归设备科，但**性质从"修好"变成"改机制"**：预防性维护计划 + 关键备件安全库存。协办采购部 |
| **来料与标准争议并存，多部门互相归因** | **需管理层指定** | 见下节 |
| 包装/运输类客户提醒 | 仓库 | 属出货作业范畴。**若为包装设计问题（如护角结构）则归工艺部** |
| 人员技能/排班导致产能不足 | 车间自行消化 | 属现场管理。若影响交期则同步 PMC 调计划 |
| 客户投诉需对外答复 | 责任部门 + **销售协办** | 对外口径必须由销售统一，不允许技术部门直接对客 |

### "需管理层指定"的判定标准（不得硬派）

同时满足以下条件时，**必须**判为"需管理层指定"，禁止硬派某个部门：

1. 涉及 **3 个以上部门**
2. **各方说法各自成立**（不是有人明显在推责）
3. 历史上**已多次讨论无结论**

这类问题的本质是**标准空白**，不是某部门失职。

**正确的输出不是指派责任，而是把它转化为具体的待拍板问题：**

❌ 错误：`归口品质部，负责降低喷涂返工率`
✅ 正确：
> 无法按常规归口。症结是「板材来料清洁度」和「喷房温湿度控制范围」**两项标准本身是空白的**。
> 需总经理本周内拍板：**这两项标准分别归谁定、什么时候定完**。
> 不定归属，下次周会仍会重复第四次。

**判断标准一句话**：如果这个问题的答案是"某部门该更努力"，那是假归口；如果答案是"某项标准该由谁定"，那才是真症结。
