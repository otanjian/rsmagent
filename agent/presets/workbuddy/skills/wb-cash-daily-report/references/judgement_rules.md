# 判断口径与看点

## 这个场景最值得讲的四处

### 从历史里想起了公司踩过的坑

上个月老板问「账上钱够不够付供应商那笔 18 万的货款」，出纳只报了银行余额，没算在途的微信收款和待付的审批单，结果差点让老板以为钱不够临时去调头寸。这次日报把「可用资金」这个口径固定了下来。

### 该拦的地方拦住了

结论是「这份日报今天还不能直接发」——因为微信里有两张收款截图金额模糊看不清，需要业务员补发原图。替代方案：先用「已确认」口径出表，两张模糊的标「待确认」，不影响老板看大头。

### 排除性结论

「那笔 3 万的微信收款可以排除重复，依据是：截图时间是昨天 18:20，跟另一笔 3 万是同一客户分两笔转的，备注里写了『尾款』——不是同一笔重复记。」

### 把技术动作翻译成钱

「三家账户余额合计 86.4 万，但真正的可用资金是 91.2 万，差出来的 4.8 万是两笔在途收款。老板如果只看银行余额，会以为还差 4.8 万去凑头寸。」

## 四类看点的威力排序（通用）

1. **从历史记录里「想起」了公司踩过的坑** —— 最有威力。
   不靠那位当年经手的老员工还在不在职。
2. **该拦的地方拦住了** —— 结论写成「这份东西现在还不能发出去」，
   然后给出不用干等的替代方案。
   一个会在该停的地方停下来的助手，比一个永远给得出答案的助手可信得多。
3. **排除性结论** —— 「这个方向可以排除，依据是……」省掉一整轮最耗时的排查。
4. **把技术动作翻译成钱** —— 这一层是给老板看的，工程师看的那层拿不到预算。

## 输入区要点出那份「平时压根不在核对范围里」的资料

它躺在另一个部门、是另一个人管的、平时不在核对范围里 —— 这是价值的来源。

## 结论的写法

- 每条结论标注证据出处（哪份文件第几条、哪张单号）
- 事实、推断、建议分栏
- 来源冲突必须并列展示，不替客户选
- 拿不到的数据明确写出来
