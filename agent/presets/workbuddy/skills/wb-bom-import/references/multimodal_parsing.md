# 多模态输入解析规范

> 定义 5 种输入格式的解析规则和容错策略

---

## 一、支持格式一览

| 格式 | 扩展名 | 一等公民 | 说明 |
|---|---|---|---|
| Excel | .xlsx / .xls | ✅ | 直接读取表格结构 |
| CSV | .csv | ✅ | 自动识别 UTF-8 / GBK / GB2312 编码 |
| PDF | .pdf | ✅ | 表格 PDF 用 pdfplumber，扫描件用 OCR |
| 邮件正文 | .eml / html / txt | ✅ | 抓取表格 + 正文段落 |
| 图片 | .png / .jpg / .jpeg | ✅ | 多模态视觉理解 |
| Word | .docx | ✅ | 表格 + 段落抽取 |

---

## 二、列名智能识别

**不要求列名规范** — 以下都识别为"料号"：

| 标准字段 | 识别的别名 |
|---|---|
| **料号** | 料号 / 物料号 / 物料编码 / 物料编号 / 件号 / 材料编号 / Part No / P/N / PartNumber |
| **物料名称** | 物料名称 / 品名 / 名称 / 描述 / 描述性名称 / Description / Name |
| **用量** | 用量 / 数量 / 用量数 / QTY / Quantity / Qty |
| **单位** | 单位 / 计量单位 / Unit / UOM |
| **版本** | 版本 / 版次 / 版本号 / Rev / Revision / Version |
| **替代料号** | 替代料 / 替代料号 / 替代品 / 替代物料 / Alternative / Alt PN |
| **供应商** | 供应商 /厂家 / 生产厂家 / 品牌 / Vendor / Supplier / Manufacturer |
| **备注** | 备注 / 说明 / 注释 / 附注 / Note / Remark / Comment |

**匹配策略**：完全匹配 → 别名匹配 → 关键词匹配 → 语义匹配（VLM 兜底）。

## 三、各格式解析细节

### 3.1 Excel / CSV

**解析器**：openpyxl（Excel）/ pandas（CSV）

**多 Sheet 处理**：
- 优先读名为"BOM 明细""明细""物料清单""Details"的 Sheet
- 若无匹配，读第一个 Sheet
- 若发现多个 BOM Sheet，主动提示用户选择

**表头识别**：
- 自动扫描前 10 行，找到第一个"料号"列所在行作为表头
- 允许表头前有"公司抬头""产品编号""版本"等元数据行

### 3.2 PDF

**表格 PDF**（可复制文字）：
- 用 pdfplumber `.extract_tables()` 提取
- 若一份 PDF 有多个表格，按顺序合并（并附各表格所在页码）

**扫描件 PDF**（不可复制）：
- 转成图片，用多模态 VLM 处理
- 提示用户："扫描件精度较低，建议提供原始 Excel"

**PDF 中的段落**：
- 表格外的段落**保留**，作为"研发备注"输入到关联步骤

### 3.3 邮件正文

**支持三种形态**：

| 形态 | 解析方式 |
|---|---|
| 用户直接粘贴到对话框 | 从对话上下文中抓取 HTML/markdown 表格 |
| 用户上传 .eml 文件 | 解析 MIME 结构，抓取 text/html 部分 |
| 用户复制邮件正文成txt | 用 markdown/纯文本表格识别 |

**表格识别**：
- 优先识别 HTML `<table>` 标签
- 其次识别 markdown 竖线表格（`| 料号 | ... |`）
- 最后识别缩进对齐的纯文本"伪表格"

**正文抽取**：
- 表格外所有 `<p>` / `<div>` 段落全部保留
- 作为"邮件备注"输入到关联步骤

### 3.4 图片 / 截图

**处理**：多模态 VLM 直接理解，输出结构化表格

**质量检查**：
- 若图片分辨率 < 800px宽 或 表格识别置信度 < 60%，主动提示用户提供更清晰版本
- 若图片是屏幕截图（含 Windows 边框等干扰），先做图像裁剪

### 3.5 Word

**处理**：python-docx 抽取 `<table>` + 正文 `<p>`

**混合内容**：
- 表格作为 BOM 明细
- 正文作为研发备注

## 四、混合输入场景

用户可以同时上传多种格式，Skill 会自动识别每份文件的角色。

### 场景 A · 一份 Excel + 一份 PDF
- 通常 Excel = 客户 ERP 导出（基线），PDF = 研发发的正式变更单（新版）
- Skill 按元数据里的版本号+ 时间戳自动区分

### 场景 B · 两份 Excel
- 按元数据里的"BOM 版本"字段区分（v1.2 vs v1.3）
- 若元数据缺失，按导出/修改时间戳区分

### 场景 C · 一份 Excel + 一段邮件正文
- Excel = 基线（客户 ERP 导出）
- 邮件正文里贴的表格 = 新版
- 邮件正文里的段落 = 研发备注（关联到差异行）

---

## 五、置信度分级

Skill 在完成解析后，会给每份文件打一个**置信度分数**：

| 分数 | 含义 | 建议 |
|---|---|---|
| ≥ 90% | 高置信度，字段完全对齐 | 直接使用 |
| 70-90% | 中等置信度，个别字段不确定 | 输出中显式标记不确定项 |
| < 70% | 低置信度，可能有笔误 | 主动提示用户"是否使用原始文件重跑" |

---

## 六、容错策略

**遇到问题时的原则**：
- **不假装懂** — 识别不了的字段用 `?` 标记，让PE 决定
- **给建议、不下判断** — 待澄清项只输出疑点 + 建议动作
- **保持可追溯** — 每一行差异都要能追溯到源文件哪一行/哪一段
