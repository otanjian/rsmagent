# BOM 差异分类与判定规则

> 可作为客户内部规范建设的直接参考

---

## 一、差异五类总览

用行业通行的五类分组，而不是笼统的"标出不同之处"。

| 类型 | 含义 | 触发条件 | 后续处置 |
|---|---|---|---|
| **新增** | 只在新版存在 | 料号在基线中查不到 | 新料建档→ 询价 → 定供应商 → 走变更审批 |
| **删除** | 只在基线存在 | 料号在新版中查不到 | 核对是否已装旧料、在途能否退改 |
| **替换** | 一增一减且功能对应 | 一条新增 + 一条删除，描述相近或备注/正文说明了替代关系 | 成对处理，确认切换时点 |
| **用量变化** | 料号一致，用量或单位变化 | 用量数值变化，或单位变化 | 核算物料需求差额，检查在途 |
| **信息修订** | 料号与用量一致，其他字段变化 | 版本 / 供应商 / 替代料 / 备注等变化 | 按变化字段的性质定审批层级 |

**归类优先级**：先识别"替换"（成对），再判新增/删除，最后判用量变化与信息修订。
一条差异同时命中多类时，按上表顺序取先者，并在详情里注明其他命中项。

## 二、置信度分层（重要）

料号匹配不是非黑即白，**必须分档，并且如实告知**。

| 档位 | 判定 | 处理 |
|---|---|---|
| **高** | 料号完全一致；或一增一减且正文明确说明替代关系 | 直接归类，注明依据 |
| **中** | 描述相似度高但料号不同；或替代关系靠推断 | 归类同时标注"待确认" |
| **低** | 无法可靠对应 | **列入待澄清，不猜** |

原则：**主动展示"我不确定的那部分"，比声称高准确率更可信。**
比对场景本来就容许AI 不完美 —— 差异摆在眼前，人一看就知道对不对。

---

## 三、来源交叉核对规则

当同一个版本同时提供了多个来源（Excel + PDF、Excel + 截图等），**必须先把这些来源互相对一遍**，再与基线比对。

|冲突字段 | 严重度 | 处理 |
|---|---|---|
| **单位** | **阻塞** | 不得自行选值。单位错误不会报错，会安静地一路生效到采购与发料 |
| **用量** | **阻塞** | 两份来源数量不同，只能由出具方确认 |
| 版本号 | 阻塞 | 影响追溯基准 |
| 替代料 | 阻塞 | 涉及采购可选范围 |
| 供应商 | 警示 | 标出并请确认 |
| 备注 | 提示 | 取信息更全的一份，注明来源 |

**核心原则：出具方自己发的两份文件都对不上，就必须由出具方说清楚。**
AI 在这里选一个"看起来更合理"的值，等于把问题埋得更深。

## 四、脏数据体检项

在比对之前先扫一遍。**这一步对准确率要求很低，只要把可疑项捞出来给人看即可** —— 但命中一条就能省一次实际损失。

| 检查项 | 判定线索 | 典型后果 |
|---|---|---|
| **疑似重复料** | 描述高度相似但料号不同（相差一个 0、多一个后缀、全半角差异）；同供应商同规格 | 多个编码多个库存账；系统显示无货去紧急采购，实际仓库还压着一批 |
| 单位可疑 | 同料号在不同来源或基线中单位不一致；同类物料单位不统一 | 采购数量错一个量级 |
| 用量异常 | 空值、0、非数值、数量级明显偏离同类件 | 缺料或超采 |
| 层级孤儿件 | 有父项引用但自身不存在，或反之 | 齐套计算漏项 |
| 替代料未标 | 关键件无替代料，且基线中原本有 | 断供时无备选 |
| 版本号缺失 | 新增件未写版本号 | 后续无法追溯 |
| 料号格式异常 | 不符合企业命名规范，疑似笔误 | 建档错误 |
| 供应商码名不符| 代码变了名称没变，或反之 | 认证与质量口径混乱 |

## 五、待澄清触发规则

以下情形**不得自行决定**，必须列为待澄清项。

### R1 · 替代料字段原有值被清空
- **触发**：基线中替代料非空，新版变为空
- **为什么不能自己填回去**：可能是漏填，也可能是**有意留空在等对方接话** —— 两种性质完全相反
- **判断方法**：**必须结合正文文字**。若邮件或备注里有"供货紧张""请评估""断供风险"等表述，
  则大概率是有意留空，含义是"原来那颗替代料也不保险了，请重新定义"
- **按漏填处理的后果**：把一个已经不成立的替代关系带过审批，等采购下单才发现走不通

### R2 · 关键件标记或提前期信息消失
- **触发**：基线备注含"关键件""提前期 N 天"，新版变空
- **可能性**：漏填 / 有意解除关键件属性—— 后者影响采购策略

### R3 · 供应商变化但无任何说明
- **触发**：供应商字段变化，备注未说明原因
- **需确认**：是否需要追加首件确认或认证流程

### R4 · 同版本多来源冲突
- 见第三节，一律阻塞

### R5 · 版本号跳跃
- **触发**：中间版本缺失（v1.2 直接到 v1.4），或主版本大跳（v1 → v3）且无说明
- **需确认**：中间版本是否有未同步的变更

### R6 · 用量变化幅度大
- **触发**：同料号用量变化显著（如超过 20%）
- **需确认**：是否伴随工艺或作业指导变更

### R7 · 替代关系单向
- **触发**：A 的替代料是 B，但 B 的替代料不是 A
- **需确认**：是双向替代还是单向替代（影响采购可选范围）

## 六、输出时的分组要求

把结果分成三类，**便于用户分头行动**：

| 分组 | 内容 |
|---|---|
| **可先送审** | 依据清楚、置信度高的差异 —— 不必等阻塞项解决 |
| **必须先澄清** | 阻塞项 + 待澄清项，**汇总成一张问题清单一次问完**，不要发现一个问一次 |
| **顺手要处理** | 体检发现的存量问题（如重复料），与本次变更无关但既然发现了就一并清掉 |

---

## 七、不适用的情况

以下情况**不输出差异清单，而是先向用户说明**：

- 两份 BOM 属于不同产品（产品编号不一致）
- 时间戳倒置（新版比基线还旧）
- 文件损坏或字段严重缺失（可解析字段少于 3 个）
- 图像识别置信度过低 —— 请用户提供更清晰的源文件或原始 Excel，**不要用猜测填补模糊字段**
