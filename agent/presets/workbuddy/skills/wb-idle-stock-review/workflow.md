# 库存结构与呆滞料复盘 Skill

> PMC 岗位场景 5.6 专用 · **存量驱动**（与 6.1 齐套缺料预警的缺料驱动方向相反）· 从五份数据 → 剔除伪呆滞 → 图纸公差反查 → 四档处置 → 安全库存修正建议 + BOM 溯源

---

## 1. 用途

呆滞料年年清、年年清不掉。真正的原因不是没人管，是**"能不能用"这个判断没人做得了**。这个 Skill 一次做完五件事：

1. **剔除伪呆滞**（必须最先做）：用未关闭采购单 + 在制工单预留 + 销售合同预留三方交叉，把"账面呆滞但实际已配套"的摘出去
2. **图纸公差反查**：判断能否转用，依据是**实测值是否落在某个在产产品的图纸公差区间内**，而不是"规格是否相同"
3. **四档处置**：转用 / 代用 / 暂缓 / 报废，**报废排最后一档**，每条带图号+版本号作为技术判据
4. **安全库存修正建议**：按月均耗用、波动σ、实际采购提前期算，**只输出建议表，不直连系统写回**
5. **BOM 版本溯源**：找出停产但BOM 未作废的产品及其独占物料 —— 这是呆滞的源头

**与 6.1 齐套缺料预警的区别（关键）**：

| | 6.1 齐套与缺料预警 | 5.6 呆滞料复盘（本 Skill） |
|---|---|---|
| 驱动方向 | **缺料驱动** —— 我缺 532 kg，去库里找什么能顶 | **存量驱动** —— 库里躺着 4.47 万，逐条问能用到哪 |
| 触发时点 | 开工前、事件触发 | 季度复盘、周期性 |
| 输出 | 缺口化解路径 + 三色开工结论 | 四档处置 + 安全库存修正 |

两者会用到同一份图纸公差信息，但**问题方向相反**。

## 2. 触发方式

### 2.1 用户一句话触发（推荐）

```
季度呆滞料复盘，库龄表我拉出来了。另外把采购单、工单预留、销售合同预留，
还有技术部的在产产品图纸公差摘录也一起放进来了。
先帮我把不是真呆滞的挑出去 —— 有的是在等在途的料，有的已经被订单预留了，
这种报上去会被采购和销售笑。
剩下的按图纸公差看看能不能转到在产的产品上用，能转的优先转，别一上来就报废。
要客户确认的单独标出来。
安全库存那块给个建议就行，别直接改 —— 改错了下个月缺料我担不起。
```

### 2.2 输入材料清单

| # | 材料 | 必需 | 说明 | 缺失时的降级策略 |
|---|---|---|---|---|
| 1 | 库龄分析表 | **必需** | 库龄须由 ERP「最后移动日期」自动采集，**禁止人工维护** | 无此项无法运行 |
| 2 | 交叉校验数据（采购单/工单预留/销售合同） | **必需** | 剔除伪呆滞的唯一依据 | **缺失时不得直接判呆滞**，须提示"未做交叉校验，本清单可能含已配套物料" |
| 3 | **在产产品图纸公差摘录** |强烈建议 | 判能否转用的唯一依据，**在技术部** | **缺失时不得输出"转用/代用"结论**，全部转为"待技术确认" |
| 4 | 历史处置记录 | 可选 | 多数企业没有或不完整 | 缺失时提示"建议自本次起建立，含技术判据栏" |
| 5 | 安全库存与耗用历史（含 BOM 版本状态） | 建议 | 修正建议与溯源的依据 | 缺失时跳过第4、5 步 |

## 3. 五步法工作流程

### STEP 1 · 剔除伪呆滞（必须最先，误伤比漏判更伤信任）

**库龄长不等于真呆滞。** 三方交叉逐条校验：

| 校验项 | 判据 | 命中即剔除 |
|---|---|---|
| **未关闭采购单** | 该物料存在状态为"未关闭"的采购单，有在途未到量 | 是—— 在等在途余量到齐 |
| **在制工单预留** | 已被某张已下达/进行中的工单预留 | 是 —— 已配套 |
| **销售合同预留** | 已被执行中的销售合同预留（尤其客户指定件） | 是 —— 已锁定 |

**输出要求**：剔除项要**单独列出并说明剔除依据**（采购单号 / 工单号 / 销售订单号），不能悄悄删掉。

**为什么这一步排第一**：如果按库龄一刀切，这些"已配套"的料会被当成问题资产报到复盘会上，采购和销售会觉得 PMC 连这个都分不清。**一次误报，下次这张清单发出去就更没人回了。**

### STEP 2 · 图纸公差反查（这个场景最有价值的一步）

**判据不是"规格是否相同"，是"实测值是否落在某个在产产品的图纸公差区间内"。**

对每一项真呆滞，遍历在产产品图纸摘录，做**三重判断**：

```
① 材料/规格类型是否匹配（材质、类型）
② 实测值/规格值是否落在该在产产品的图纸公差区间内
③ 该产品「是否允许代用」= 允许？「客户是否需确认」= 需要/不需要？
```

三项都过→ 可转用（不需客户确认）或可代用（需客户确认）
任一不过 → 不可用于该产品，继续试下一个在产产品
全部试完无匹配 → 无转用去处，进入暂缓或报废判定

**必须逐个在产产品比，不能只看规格像不像。** 同一批料对不同在产产品的结论可能完全不同（如某电机对 A 产品因系统电压不符不可用，对 B 产品因功率落在区间内可代用）。

**结论必须带技术判据出处**：图号 + 版本号 + 公差区间原文。

**克制原则**：技术上"能改"不等于"该改"。如需重新烧录固件、重新做首件验证、重新提交 PPAP 的，成本与风险不可控时应判"不建议转用"。

### STEP 3 · 四档处置（报废排最后）

| 档 | 前置条件 | 必须写明 |
|---|---|---|
| **① 转用** | 落在在产件公差内+ 允许代用 + 不需客户确认 | 转用去向产品、数量、技术判据（图号+版本）、待技术部确认 |
| **② 代用** | 技术等效，但**客户指定过品牌/料号** | 同上 + **需客户书面确认**，未获确认前不得执行 |
| **③ 暂缓** | 无转用去处，但**物料本身不会失效**（如标准件） | **不报废的理由** + 真正的问题（通常是安全库存设错）+ 对应的参数修正建议 |
| **④ 报废** | 技术上无法转用（如版本淘汰、超保质期、实测衰减） | **需财务按可变现净值重估** —— 账面金额不等于实际损失额 |

**为什么"转用"必须排第一**：实际执行中处置方式往往只剩"报废"和"打折退供应商"两条——因为转用要技术判、代用要客户认，这两件事都跨部门都要有人拍板，**而报废只需要财务走个流程**。于是能用的料被当成不能用的处理掉了。

**"暂缓"这一档不可省**：标准件不会失效，报废它是纯浪费。库存量异常通常是安全库存设错导致的持续超采，**正确动作是改参数让它自然消化，而不是处理掉它**。

### STEP 4 · 安全库存修正建议（只建议，不写回）

```
建议安全库存 ≈ 月均耗用 ÷ 30 × 实际采购提前期(天) + 2σ
```

- 近 12 月**零耗用**且原产品已停产 → 建议设为 0（转用完成后停用该物料）
- **必须给完整算式**，让 PMC 可以自己复核，而不是接受一个黑盒数字
- **必须包含建议上调的项**（如果有）—— 这证明这套东西不是一味削减库存。一份全是"降低库存"的建议会被怀疑只是在配合财务压库存

**硬规则：只输出建议表，不直连系统写回。** 改安全库存会直接影响 MRP 采购建议，改错了下个月就缺料，**这个决定必须是人做的**。

### STEP 5 · BOM 版本溯源（找源头）

检查 BOM 版本状态表：**是否存在已停产/已设变但BOM 未作废标记的产品**，及其独占的物料。

若这些物料正是本次的呆滞料，则要明确指出：

> 这批呆滞不是偶然，是一个结构性缺口每年都在生产新的呆滞料。ERP 无BOM 版本失效预警机制，停产产品的 BOM 仍可被 MRP 引用。**建议建立 BOM 作废机制——产品停产或设变后，旧版 BOM 应同步作废标记，并检查其独占物料是否需转用或停采。清库存是治标，这个才是治本。**

**这条建议往往比本次清出来的金额更值钱。**

## 4. 输出结构（固定，不可缺项）

```
一、剔除的伪呆滞（逐项 + 剔除依据的单号）
二、真呆滞清单（金额守恒：剔除 + 真呆滞 = 库龄偏长总额）
三、图纸公差反查逐条（含明确的不可用判定与理由）
四、四档处置汇总（含可消化占比与报废占比）
五、安全库存修正建议（含算式，含上调项）
六、BOM 版本溯源与治本建议
七、交付物：呆滞清单与处置 xlsx（4 sheet）+ 处置意见书 pdf（可五方会签）
```

---

## 5. 硬规则（不可违反）

1. **剔除伪呆滞必须在最前**。无交叉校验数据时不得直接判呆滞。
2. **无图纸公差摘录时不得输出"转用/代用"结论**，全部转为"待技术确认"。
3. **报废排最后一档**。不得跳过转用与代用直接判报废。
4. **每条处置必须带技术判据出处**（图号 + 版本号 + 公差原文）。无出处的转用建议不得写入。
5. **报废项必须注明"需财务按可变现净值重估"**，账面金额不等于实际损失额。
6. **安全库存只出建议不写回**，且必须给完整算式。
7. **金额必须守恒**：剔除项 + 真呆滞 = 库龄偏长总额；四档处置分项= 真呆滞总额。
8. **"能改"不等于"该改"**。需重新验证/重新 PPAP 且成本风险不可控的，判"不建议转用"。
9. **不做采购责任追究**。呆滞成因（超采/设变/订单取消）只做归类，不判责。

## 6. 常见坑

| 坑 | 规避 |
|---|---|
| 按库龄一刀切判呆滞 | 先做三方交叉剔除伪呆滞 |
| 按"规格是否相同"判能否转用 | 按"实测值是否落在在产件图纸公差内"判 |
| 只试一个在产产品就下结论 | 遍历所有在产产品，同一批料对不同产品结论可能相反 |
| 忘了查"是否需客户确认" | 客户指定过品牌/料号的，技术等效也只能判代用 |
| 把标准件判报废 | 标准件不会失效，判暂缓 + 调安全库存 |
| 报废金额当成实际损失 | 注明需财务按可变现净值重估 |
| 安全库存建议全是下调 | 必须包含上调项（如果有），否则可信度受损 |
| 直连系统改安全库存 | 只出建议表 |
| 只清库存不找源头 | 查 BOM 版本是否未作废 —— 治本比治标值钱 |
