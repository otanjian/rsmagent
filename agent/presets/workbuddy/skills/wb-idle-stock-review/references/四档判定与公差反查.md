## 一、为什么"剔除伪呆滞"必须排第一

**库龄长不等于真呆滞。** 三种常见的"账面呆滞但实际已配套"：

| 情形 | 表现 | 为什么不是呆滞 |
|---|---|---|
| **在等在途余量** | 采购单分批到货，已到部分入库后未再移动 | 采购单状态未关闭，余量在途，到齐后即开工 |
| **已被工单预留** | 已下达待开工的工单占用了这批料 | 计划开工日一到就会领用 |
| **已被销售合同预留** | 客户指定型号，按合同提前备料 | 合同执行中，不可动用 |

### 校验方法

对每一项"疑似呆滞"，逐条查三张表：

```
IF 存在状态为"未关闭"的采购单 且有未到量:
    剔除（依据：采购单号）
IF 存在已下达/进行中工单的物料预留:
    剔除（依据：工单号）
IF 存在执行中销售合同的预留:
    剔除（依据：销售订单号）
```

### 输出要求

剔除项要**单独列出并写明剔除依据的单号**，不能悄悄删掉。因为：
- 复盘会上有人会问"上次那批铝板呢"
- 下季度再跑时要能对上

**核心理由：误伤比漏判更伤信任。** 一次误报，下次这张清单发出去就更没人回了。

## 二、图纸公差反查（这个场景最有价值的一步）

### 判据的本质

**不是"规格是否相同"，是"实测值是否落在某个在产产品的图纸公差区间内"。**

举例：
- ERP 里看：呆滞料是1.8mm 冷轧板，在产产品用的是 2.0mm → **规格不同，判不能用**
- 图纸里看：在产件图纸要求"板厚 1.8~2.2mm" → **1.8落在公差下限内，可以用**

**这层信息只在技术部的图纸里，ERP 的物料主数据里没有。** 所以从来没人往这个方向想过。

### 三重判断（缺一不可）

```
① 材料/规格类型是否匹配（材质、类型是否同类）
② 实测值/规格值是否落在该在产产品的图纸公差区间内
③ 该产品「是否允许代用」= 允许？「客户是否需确认」= 需要 / 不需要？
```

| 判断结果 | 结论 |
|---|---|
| ①②③ 全过，且不需客户确认 | **可转用** |
| ①②③ 全过，但需客户确认 | **可代用**（须客户书面确认后执行） |
| ② 不过（超出公差） | 不可用于该产品，试下一个 |
| ③ 不允许代用 | 不可用于该产品，试下一个 |
| 遍历完所有在产产品无匹配 | 无转用去处 → 进入暂缓或报废判定 |

### 必须遍历所有在产产品

**同一批料对不同在产产品的结论可能完全相反。** 典型例子：

某 24V 60W 电机：
- 对 A 产品：材料要求栏写"24V ±10% / 功率 ≥55W"，但**该产品实际设计为 36V 系统**（当前用料为 36V）→ **不可代用**
- 对 B 产品：要求"24V ±10% / 功率 50~70W"，本料 60W 落在区间内 → **技术可代用**，但该产品客户指定过品牌 → **需客户确认**

只试一个就下结论，会漏掉真正可用的去处。

### 结论必须带技术判据出处

格式：`图号 + 版本号 + 公差区间原文`

例：`DWG-BRK-07 Rev.D（板厚 1.8~2.2mm）`

**这一条是这个Skill 最核心的沉淀价值。** 因为呆滞料处置的判据在多数企业是失传的——原工艺工程师一离职，"某型号旧料当年为什么判了不能用"就没人说得清了。把判据固化成图号+版本，下次同类料进来不用再从零判。

### 克制原则：能改不等于该改

技术上可以重新烧录固件、可以重新做首件验证、可以重新提交 PPAP —— 但如果：
- 需重新验证且验证周期不可控
- 需重新提交客户认可（如 PPAP Level 3，周期 4~6 周）
- 改制成本接近或超过物料本身价值

则应判**"不建议转用"**，而不是"可转用"。

## 三、四档处置的前置条件与必写内容

### ① 转用（不花钱，优先级最高）

**前置**：落在在产件公差内 + 允许代用 + 不需客户确认

**必写**：转用去向产品、数量、**技术判据（图号+版本+公差原文）**、待技术部确认

### ② 代用（需客户认）

**前置**：技术等效，但客户指定过品牌/料号

**必写**：同转用 + **需客户书面确认**、确认周期、**未获确认前不得执行**

### ③ 暂缓（保留但改参数）

**前置**：无转用去处，但**物料本身不会失效**（标准件、通用件、无保质期限制）

**必写**：
- **不报废的理由**（如"标准件不会失效，报废是纯浪费"）
- **真正的问题**（通常是安全库存设错导致持续超采）
- 对应的参数修正建议

**这一档最容易被忽略。** 库存量异常不代表这批料该处理掉——320 只轴承对应 40 个月用量，问题在安全库存设了 150 而月均只用 8只。**改参数让它自然消化，比报废它正确。**

### ④ 报废（最后一档）

**前置**：技术上无法转用（版本淘汰、超保质期、实测值衰减超标）

**必写**：**需财务按可变现净值重估** —— 账面金额不等于实际损失额（如控制板可能还有残值）

## 四、安全库存修正建议

### 公式

```
建议安全库存 ≈ 月均耗用 ÷ 30 × 实际采购提前期(天) + 2σ
```

其中 σ 为近 12 个月耗用的标准差。实际采购提前期用**实际值**而非合同承诺值。

### 特殊情形

| 情形 | 建议 |
|---|---|
| 近 12 月零耗用 + 原产品已停产 | 设为 0（转用完成后停用该物料） |
| 月均耗用远小于现行安全库存 | 按公式下调，但留适当余量（如算出 12 取 30） |
| **现行值低于公式算出值** | **建议上调** —— 这是真正的缺料风险 |

### 两条硬要求

**① 必须给完整算式。** 让 PMC 可以自己复核，而不是接受一个黑盒数字。

**② 必须包含建议上调的项（如果有）。** 一份全是"降低库存"的建议会被怀疑只是在配合财务压库存。**敢提"这一项你们设低了"，这份建议才可信。**

### 为什么只建议不写回

改安全库存会直接影响 MRP 采购建议，改错了下个月就缺料。**PMC 通常不敢单独改**——这个决定涉及采购、财务、生产多方，必须是人做的。

## 五、BOM 版本溯源（找源头）

### 检查什么

BOM 版本状态表里，是否存在**已停产 / 已设变但BOM 未作废标记**的产品，及其独占的物料。

### 为什么这是源头

ERP 通常**没有 BOM 版本失效预警机制**，停产产品的 BOM 仍留在系统里可被 MRP 引用。于是：

1. 产品停产 → BOM 未作废
2. MRP 仍可能按旧 BOM 生成采购建议
3. 或者：物料因无产品消耗而长期不动 → 变成呆滞

**若本次的呆滞料正好是这些停产产品的独占物料，则要明确指出这是结构性缺口，不是偶然。**

### 治本建议的写法

> 建议建立 BOM 作废机制——产品停产或设变后，旧版 BOM 应同步作废标记，并检查其独占物料是否需转用或停采。**清库存是治标，这个才是治本。**

**这条建议往往比本次清出来的金额更值钱**，因为它决定明年会不会再有这批料。

## 六、金额守恒（自检的核心）

```
库龄偏长总额 = 剔除的伪呆滞 + 真呆滞总额
真呆滞总额   = 转用 + 代用 + 暂缓 + 报废
可消化占比   = (转用 + 代用) / 真呆滞总额
报废占比     = 报废 / 真呆滞总额
```

**这两条守恒关系必须在输出中体现，并用断言校验。** 金额对不上是这类报告最容易被一眼看穿的错。
