# 处置意见书模板 · 列结构与会签

交付物：**Excel 4 sheet（工作用）+ PDF 1 页（要会签的正式件）**。

按调研结论：呆滞料处置在规范企业里是**要跨部门会签的**，且单笔金额超过一定门槛须多方签署方可执行。所以 PDF 必须做成可签字的正式件形态。

---

## 一、Excel sheet 1 · 呆滞清单与处置

### 列结构

`物料编码 | 物料名称 | 规格 | 单位 | 库存数量 | 单价 | 占用金额 | 最后动用日 | 库龄(天) | 成因 | 建议处置 | 转用去向 | 技术判据（图号+版本） | 可变现净值 | 执行责任人 | 限期 | 备注`

### 关键设计

**剔除的伪呆滞项要单独标注**（可用一个"是否呆滞"列或单独分组），并在备注里写明剔除依据的单号。**不能悄悄删掉。**

**「技术判据（图号+版本）」是这张表最重要的一列。** 它是下次同类料进来时不用从零判的依据。转用与代用项必填。

**「可变现净值」列**：只有报废项填，且注明"需财务重估"。**账面金额不等于实际损失额。**

**必须有金额守恒的合计行**：剔除 + 真呆滞 = 库龄偏长总额。

### 样式

```python
ws.freeze_panes = 'A2'

# 处置档位填色：转用 E7F6EE / 代用 EAF1FD / 暂缓 FBF1DD / 报废 FCECEC / 剔除 F1EFE8
# 金额列 number_format = '#,##0.00'
```

## 二、Excel sheet 2 · 待技术确认

### 列结构

`物料编码 | 建议处置 | 转用去向产品 | 技术判据 | 公差区间原文 | 需确认事项 | ☐ 技术确认 | 技术确认人 | ☐ 客户确认 | 客户确认结果 | 备注`

### 关键设计

**「☐ 技术确认」「☐ 客户确认」两列必须留空。** 这一页不是报告，是**给技术部和销售填的工作表**。

代用项的「☐ 客户确认」必填，转用项标"不适用"。

**「公差区间原文」列照录图纸原文**（如"板厚 1.8~2.2mm"），技术部一眼能核。

## 三、Excel sheet 3 · 安全库存修正建议

### 列结构

`物料编码 | 物料名称 | 现行安全库存 | 设定日期 | 近12月总耗用 | 月均耗用 | 波动σ | 实际采购提前期 | 建议安全库存 | 调整方向 | 完整算式 | 依据说明`

### 关键设计

**「完整算式」必须是一列**，写出 `月均÷30×提前期 + 2σ≈ X` 的完整计算过程。让 PMC 可以自己复核。

**「调整方向」用 ↓ / ↑ / = 标注**，且**上调项要用醒目颜色**——它证明这不是一味削减库存。

**表头或表尾必须注明**："本表仅为建议，不直连系统写回。修改安全库存会影响 MRP 采购建议，须经采购与生产确认后执行。"

## 五、PDF · 呆滞料处置意见书（A4 一页，要会签）

### 版面结构

```
┌────────────────────────────────────────────┐
│ 呆滞料处置意见书                              │
│ 企业名 · PMC ｜ 单据编号 ｜ 复盘期间            │
├────────────────────────────────────────────┤
│ 一、复盘范围与剔除说明                │
│  库龄偏长 N 项 X 元 → 剔除伪呆滞 M 项 Y 元      │
│  → 真呆滞 K 项 Z 元（含剔除依据单号）           │
├────────────────────────────────────────────┤
│ 二、处置意见（逐项表格）                       │
│  物料/数量/占用金额/成因/建议处置/技术判据/责任人/限期│
├────────────────────────────────────────────┤
│ 三、四档汇总 + 可消化占比                │
├────────────────────────────────────────────┤
│ 四、治本建议（BOM 作废机制）                   │
├────────────────────────────────────────────┤
│ 五方会签+ 总经理批准                          │
├────────────────────────────────────────────┤
│ 页脚：金额门槛与执行约束                        │
└────────────────────────────────────────────┘
```

### 会签栏（顺序不可乱）

```
编制（PMC）→ 会签（采购）→ 会签（销售）→ 会签（技术）→ 会签（财务）→ 批准（总经理）
```

规则：
- **转用/代用项须技术会签**方可执行
- **代用项须销售确认客户认可**
- **报废项须财务会签**（可变现净值重估）
- **页脚印明**："单笔占用金额 5 万元以上须采购、销售、技术三方签署方可执行；未签署前系统锁定该物料出库。"

## 六、自检断言（跑不过就不出文件）

```python
# 1. 金额守恒：剔除 + 真呆滞 = 库龄偏长总额
assert abs(excluded_amt + real_idle_amt - total_aged_amt) < 0.01, '剔除+真呆滞 != 库龄偏长总额'

# 2. 四档分项 = 真呆滞总额
assert abs(reuse + substitute + hold + scrap - real_idle_amt) < 0.01, '四档分项 != 真呆滞总额'

# 3. 每项金额 = 数量 × 单价
for it in items:
    assert abs(it['qty'] * it['price'] - it['amt']) < 0.01, f"{it['code']} 金额算错"

# 4. 转用/代用项必须有技术判据
for it in items:
    if it['disposal'] in ('转用', '代用'):
        assert it['basis'] and 'Rev' in it['basis'] or 'DWG' in it['basis'], \
            f"{it['code']} 转用/代用缺技术判据（图号+版本）"

# 5. 报废项必须注明需财务重估
for it in items:
    if it['disposal'] == '报废':
        assert '可变现净值' in it.get('note', '') or it.get('nrv_flag'), \
            f"{it['code']} 报废项未注明需财务按可变现净值重估"

# 6. 剔除项必须有依据单号
for it in excluded:
    assert it['evidence_no'], f"{it['code']} 剔除项缺依据单号"

# 7. 安全库存建议必须含至少一项上调（若存在现行值低于公式值的物料）
if any(x['suggest'] > x['current'] for x inss):
    assert any(x['direction'] == '↑' for x in ss), '存在应上调项但未标注'

# 8. 可消化占比 +暂缓占比 + 报废占比 = 100%
pcts = [reuse_pct, sub_pct, hold_pct, scrap_pct]
assert abs(sum(pcts) - 100) < 0.1, f'占比合计 {sum(pcts)} != 100%'
```

第 4、5、6 条是这个场景特有的断言：**从代码层面阻止"无判据的转用建议""报废项当成实际损失""悄悄删掉剔除项"**。
