# 经营复盘·一页式简报 Skill

> 管理层场景 2.1 专用 Skill · 五条线数据一次读完 ·恶化项必须归因到具体订单/客户/物料/工序 · 输出一页式经营简报

---

## 1. 用途

管理层每周/每月要回答一个问题：**订单、交付、库存、质量、成本这五条线，到底健康不健康？**

传统做法是各部门各交一份报表，管理层自己在脑子里拼。销售说订单饱满、生产说产能吃紧、财务说毛利下滑——三张表拼不到一起，会开两小时最后变成互相解释。而且报表只回答「是什么」，不回答「为什么」和「谁该做什么」。

本 Skill 一次做完 5 件事：

1. **五线合读**：订单 / 交付 / 库存 / 质量 / 成本五份数据一次读进来，统一到同一期间口径
2. **逐项健康度判定**：每条线同时对比上期 + 对比目标，给出 改善 / 持平 / 恶化 三态判定
3. **恶化项归因下钻**：指标 → 产品线 → 订单/客户 → 根因（物料涨价 / 工序不良 / 插单挤占），逐层带金额
4. **指标间矛盾检测**：找出「好看的数字是怎么来的」——OTD高但加班多、库存降但缺料增等
5. **一页式简报输出**：三个必须关注的问题 + 责任部门 + 建议动作 + 完成时限 + 衡量口径

**与 BI 看板的分界线**：BI 只能显示「毛利率这条线在往下走」；本 Skill 要能说出「主要由 P-BRK-03拖累（该线毛利仅 8.4%），原因是 M-SPCC-20 板材 6 月涨价 11.0% 但对客报价未同步调整，涉及某主机厂 3 张在执行订单共 20.3 万元敞口，建议销售部 8 月 15 日前完成调价谈判」。

## 2. 触发方式

### 2.1 用户一句话触发（推荐）

```
把 6 月的经营数据复盘一下。
数据在 D:\workbuddy_data\管理层\场景①_经营复盘\
订单、交付、库存、质量、成本五份表都在里面。
哪些指标在恶化？为什么？谁该做什么？
```

Skill 会自动识别目录下的五类数据表（按表名关键词 + 表头字段特征双重匹配），无需指定哪份是哪份。

### 2.2 直接拖拽多份文件

用户可以把 5 份表一次拖到对话框（格式可以混：xlsx / csv / pdf 导出的月报都行）。Skill 按表头字段特征自动归类到五条线。

### 2.3 只看某条线

```
这个月毛利率为什么掉了2.6 个点？给我拆到具体产品和订单。
```

此时 Skill 跳过五线合读，直接进入第 3 步归因下钻（详见 `references/归因下钻规则.md`）。

### 2.4 追问式复盘

```
OTD 96.8% 是真的好还是假的好？
```

触发矛盾检测（第 4 步），Skill 会拉出同期的插单次数、加班工时、外协费用做交叉验证。

## 3. 输入格式规范

**不强制格式** — 客户环境现实是「各部门报表各有一套模板」。

| 条线 | 典型表名 | 必需字段（任一别名即可识别） | 可选字段 |
|---|---|---|---|
| **订单** | 订单月度汇总 / 销售月报 / 订单台账 | 产品编码、订单金额、期间 | 客户、订单张数、单价、月度目标、上期金额 |
| **交付** | 交付履约明细 / OTD 报表 / 交货台账 | 承诺交期、实际交付日（或直接给 OTD） | 加急插单次数、加班工时、标准工时、平均交付周期 |
| **库存** | 库存与呆滞 / 库存周转表 / 存货明细 | 库存金额、期间 | 库龄、呆滞金额、缺料条目、分类（原材料/在制/成品） |
| **质量** | 质量异常汇总 / 不良月报 / NCR 台账 | 不良率或不良件数、质量损失金额 | 客诉件数、NCR 开立/关闭数、工序、产品编码 |
| **成本** | 成本与毛利 / 损益表 / 产品线毛利表 | 收入、成本（或直接给毛利率） | 成本项拆解、物料采购价、上期毛利率 |

**字段别名容错**：
- 订单金额 = 订单额 / 合同金额 / 销售额 / Order Amount
- 准时交付率 = OTD / On-Time Delivery / 及时交付率 / 按期交付率
- 毛利率 = GM% / Gross Margin / 毛利比率
- 呆滞库存 = 滞料 / 长库龄 / Slow Moving / E&O

**期间对齐规则**：以本期为基准，自动找出各表中的对比期。若某表缺对比期数据，Skill 明确标注「该线仅有本期数据，无法判定趋势」，**不猜、不补**。

## 4. 输出格式规范

```markdown
##恒信精密机械 · 2026年 6 月经营简报（一页式）

**一句话结论**：订单在涨、交付表面达标，但毛利率跌破目标 2.4pp、质量五项全恶化、
库存结构在恶化；交付达标是靠加班堆出来的，不可持续。

### 一、五条线健康度判定

| 条线 | 核心指标 | 本期 | 上期 / 目标 | 判定 | 判定依据 |
|---|---|---|---|---|---|
| 订单 | 新增订单金额 | 2,440.0 万元 | 上期 2,280.0 / 目标 2,400.0 | 🟢 改善 | 环比+7.0%，达成率 101.7% |
| 交付 | 准时交付率 OTD | 96.8% | 上期 93.1% / 目标 ≥95.0% | 🟡 改善但存疑 | 60/62 达标，但加班占比 15.0% 超上限 |
| 库存 | 库存总额 / 呆滞占比 | 1,860.0 万元 / 16.8% | 上期 1,940.0 / 14.7% | 🟡 持平 | 总额 -4.1%，但呆滞 +2.1pp、缺料 8→14 项 |
| 质量 | 不良率 / 质量损失 | 3,850 PPM / 38.6 万元 | 上期 3,120 / 26.4 | 🔴 恶化 | 五项质量指标全部环比恶化 |
| 成本 | 整体毛利率 | 15.6% | 上期 18.2% / 目标 18.0% | 🔴 恶化 | 跌破目标 2.4pp；P-BRK-03 仅 8.4% |

### 二、恶化项归因下钻（毛利率 -2.6pp）

L1 指标：整体毛利额 397.0 → 361.6 万元
  └ L2 产品线：按上期各线毛利率重算应得 422.84万元，缺口 61.24 万元
      ├ P-BRK-03  缺口 41.90 万元（68.4%）  ← 主因
      ├ P-IPC-01  缺口 16.38 万元（26.8%）
      └ P-CAB-02  缺口  2.96 万元（4.8%）
  └ L3 成本项（P-BRK-03缺口 41.90 万元拆解）
      ├ M-SPCC-20 板材涨价      21.4 万元（51.1%）= 400 吨 × 535 元/吨
      ├ 质量返工与报废          12.4 万元（29.6%）= 返工 5.6 + 报废 6.8
      └ 外协赶工加工费           8.1 万元（19.3%）
  └ L4 订单/客户
      └ 某主机厂在执行 3 张（SO-2604-009 / SO-2605-022 / SO-2606-018）
        共 9,500 件 · 未调价敞口 9,500 × 21.4 = 20.3 万元

**根因结论**：M-SPCC-20 单价 4,850 → 5,385 元/吨（+11.0%），但对客报价 460 元/件
自 2026-01-01 生效后未调整。建议调价至 481.4 元/件（+21.4 元 / +4.7%）。

### 三、指标间矛盾（2 处）

**① OTD 是加班堆出来的**
- 好看的指标：OTD 96.8%（上期 93.1%，超目标 1.8pp）
- 同期反向指标：加急插单 23 次（上期 12）· 加班工时 3,180 h（+40.1%）· 占比 15.0%（上限 12.0%）
- 结论：交付达标依赖加班与插单，不可持续；已外溢为质量损失与外协成本

**② 库存降了但结构在恶化**
- 好看的指标：库存总额 1,860.0 万元（-4.1%）· 周转 1.03 次/月（达标）
- 同期反向指标：呆滞 312.0 万元 / 16.8%（上期 14.7%）· 缺料预警 14 项（上期 8）
- 结论：被消耗掉的是好料，留下的是呆料

### 四、必须关注的三个问题

| # | 问题 | 责任部门 | 建议动作 | 完成时限 | 衡量口径 |
|---|---|---|---|---|---|
| Q1 | P-BRK-03 毛利率 8.4%，占毛利缺口 68.4% | 销售部（主）· 采购部（协） | 完成调价谈判 460→481.4 元/件 | 2026-08-15 | 毛利率回到 ≥15.0% |
| Q2 | OTD 靠加班堆出来 | PMC（主）· 生产部（协） | 出插单准入规则 + 加班占比 12% 硬上限 | 2026-07-20 | 加班占比 ≤12.0% |
| Q3 |呆滞升至 312.0 万元且缺料翻倍 | 采购部（主）· 研发 PE（协） | Top 4 呆滞逐项出处置方案 | 2026-07-31 | 呆滞占比 ≤13.0% |
```

**输出硬规则**：
1. 每个判定必须带「本期 + 上期 + 目标」三个数，缺一不可
2. 每个归因层级必须带金额，且下层金额之和 = 上层缺口（可验算）
3. 每个建议动作必须带责任部门 + 完成时限 + 衡量口径，三缺一不算合格产出
4. 问题数量控制在 **3 个**（管理层一次能推动的极限），其余进「观察项」附录

## 5. 核心处理逻辑

### 5.1 五步法总览

```
Step 1  五线合读     5 份表 → 统一期间口径 → 抽取指标 →缺数据的明确标注
Step 2  健康度判定   每指标 × (对比上期 + 对比目标) → 改善/持平/恶化 三态
Step 3  归因下钻     对每个「恶化」项做 L1→L2→L3→L4 四层下钻，逐层带金额
Step 4  矛盾检测     跑矛盾规则库，找出「好看的数字是怎么来的」
Step 5  简报输出     三个问题 + 责任部门 + 建议动作 + 时限 + 衡量口径
```

### 5.2 Step 1 · 五线合读

**期间口径统一**（最容易出错的一步）：
- 订单看**下单日**，交付看**实际交付日**，成本看**收入确认期**——三者天然不同期
- 规则：以「财务收入确认期」为基准期。订单表的金额是「本期新增订单」，成本表的收入是「本期确认收入」，**两者不应相等**，若客户表里相等要提示「疑似口径混用」
- 本案例：6 月新增订单 2,440.0 万元 ≠ 6 月确认收入 2,320.0 万元，属正常（有在执行未交付部分）

**缺数据处理**：某条线缺对比期 → 标注「仅有本期数据，无法判定趋势」；缺目标值 → 用`references/指标定义与阈值.md` 的行业默认健康区间，并注明「使用默认阈值，建议客户确认」。

### 5.3 Step 2 · 健康度三态判定

判定必须**同时看两个维度**，不能只看环比：

| 对比上期 | 对比目标 | 判定 | 说明 |
|---|---|---|---|
| 改善 | 达标 | 🟢 **改善** | 真健康 |
| 改善 | 达标，但支撑指标反向 | 🟡 **改善但存疑** | 主指标好看，代价藏在别处 → 必须进 Step 4 |
| 改善 | 未达标 | 🟡 **持平** | 方向对但没到位 |
| 恶化 | 达标 | 🟡 **持平** | 有缓冲但趋势要盯 |
| 恶化 | 未达标 | 🔴 **恶化** | 必须进 Step 3 归因 |

**「改善但存疑」是本Skill 的关键设计**：普通报表只会打绿灯，这一态专门抓「靠不可持续手段换来的达标」。

### 5.4 Step 3 · 归因下钻（详见 `references/归因下钻规则.md`）

四层结构，**每层都必须带金额，下层之和等于上层缺口**：

```
L1 指标层哪个指标恶化了？恶化多少？（毛利额 397.0 → 361.6，缺口用 L2 结构剔除法算）
L2 结构层   拆到产品线 / 客户 / 事业部，找出贡献最大的那一个
L3 动因层   拆到成本项 / 工序 / 物料，找出可操作的那一个
L4 对象层   落到具体订单号 / 客户 / 料号，算出敞口金额
```

**结构剔除法**（L1→L2 的标准算法）：
```
某产品线缺口 = 该线本期收入 × 上期该线毛利率 - 该线本期实际毛利额
总缺口 = Σ 各线缺口
该线占比 = 该线缺口 / 总缺口
```
本案例：P-BRK-03 缺口 = 460.0 × 17.5% - 38.6 = 80.50 - 38.6 = 41.90 万元

**下钻停止条件**（避免无限下钻）：
- 落到具体订单号 / 料号 / 工序，且能给出可执行动作 → 停
- 某层某项占比 < 10% → 归入「其他」不再下钻
- 下钻 4 层仍未落到可操作对象 → 输出「需补充 XX 明细数据才能定位」，**不编根因**

### 5.5 Step 4 · 矛盾检测（这是管理层最需要的）

管理层最需要的不是「指标是多少」，而是「**这个好看的数字是怎么来的**」。

矛盾检测规则库（完整版见 `references/归因下钻规则.md` 第 4 节）：

| # | 好看的指标 | 需检查的反向指标 | 判定条件 | 结论模板 |
|---|---|---|---|---|
| C1 | OTD 上升且达标 | 加急插单次数、加班工时占比、外协加工费 | 任一项环比 +20% 或超上限 | 「OTD 是靠加班/插单堆出来的，不可持续」 |
| C2 | 库存总额下降 | 呆滞金额/占比、缺料预警条目 | 呆滞占比上升 或缺料条目上升 | 「消耗掉的是好料，留下的是呆料」 |
| C3 | 收入/订单上升 | 毛利率、单一客户集中度 | 毛利率下降 ≥1.0pp 或集中度 >45% | 「增长质量在下降 / 客户结构在集中」 |
| C4 | 平均交付周期缩短 | 内部不良率、返工工时 | 不良率环比 +10% 以上 | 「交付周期靠压缩检验/工序换来」 |
| C5 | 质量损失下降 | NCR 开立数、按期关闭率 | 关闭率下降 或 开立数上升 | 「损失下降可能是问题未结案，不是真改善」 |
| C6 | 采购降本达成 | 来料不良率、缺料条目、供应商集中度 | 来料不良或缺料上升 | 「降本是拿供应保障和质量换的」 |
| C7 | 产能利用率上升 | 在制品金额、设备故障停机时长 | 在制品环比 +5% 以上 | 「利用率高是因为在制堆积，不是效率提升」 |

**本案例命中**：C1（OTD vs 加班/插单）、C2（库存降 vs 呆滞升+ 缺料翻倍）。

**矛盾输出必须给「量化证据 + 外溢代价」**：不能只说「OTD 靠加班」，要说「加班工时 3,180 h（+40.1%）、加班成本 14.31 万元、并已外溢为 4 份 P-BRK-03 的 NCR 和 8.1 万元外协赶工费」。

### 5.6 Step 5 · 简报输出

**为什么只给 3 个问题**：管理层一次经营会能真正推动的事项就是 3 件。给 8 条等于没给。

**3 个问题的挑选规则**（按优先级）：
1. 命中「红线」的指标（见 `references/指标定义与阈值.md`）优先
2. 归因链已落到具体订单/客户/料号、动作可立即执行的优先
3. 矛盾检测命中项优先（因为这类问题不做复盘不会被发现）
4. 同一条线最多进 1 个（避免三个问题全是财务的）

**责任部门指派规则**：动作落在哪个部门的权限范围内，就指派给谁；跨部门的写「A（主）· B（协）」，**必须有唯一主责**。

## 6. 快速参考卡

### 用户常见问法

| 用户说 | Skill 动作 |
|---|---|
| 「把这个月的经营数据复盘一下」 | 走完整五步法，输出一页式简报 |
| 「哪些指标在恶化？」 | 只输出 Step 2 判定表，恶化项高亮 |
| 「毛利率为什么掉了？」 | 跳到 Step 3，直接输出四层归因链 |
| 「OTD 96.8% 是真的好吗？」 | 触发 Step 4 矛盾检测规则 C1 |
| 「库存降了是好事吧？」 | 触发 C2，拉呆滞占比 + 缺料条目做交叉验证 |
| 「这三个问题谁负责？」 | 输出 Step 5 责任部门 + 时限 + 衡量口径表 |
| 「上个月说的三件事做到了吗？」 | 拉上期简报的衡量口径，与本期实测值逐项比对（需上期简报作为输入） |
| 「给我下钻到具体订单」 | L4 层输出：订单号 + 客户 + 数量 + 敞口金额 |

### 追问剧本

**Q1**：这不就是 BI 看板吗？
→ BI 显示「毛利率在往下走」，到这里就停了。本 Skill 继续往下走三层：拆到 P-BRK-03（占缺口 68.4%）→ 拆到 M-SPCC-20 涨价 21.4 万元 → 落到某主机厂 3 张在执行订单 20.3 万元敞口 → 给出「8月 15 日前完成调价谈判」的动作。**BI 回答「是什么」，这里回答「为什么」和「谁该做什么」。**

**Q2**：五条线数据口径不一样怎么办？
→ 以财务收入确认期为基准期做对齐。订单表的「本期新增订单」与成本表的「本期确认收入」天然不等（本案例 2,440.0 vs 2,320.0），Skill 不会强行拉平；若两者相等反而会提示「疑似口径混用」。

**Q3**：归因会不会编？
→ 不会。下钻 4 层仍未落到可操作对象时，Skill 输出「需补充 XX 明细数据才能定位」而不是给猜测。所有金额都必须能从输入表反算（如 21.4 万元 = 400 吨 × 535 元/吨）。

**Q4**：矛盾检测会不会漏？
→ 规则库目前 7 条（C1-C7），覆盖制造业最常见的「假达标」。规则库是可扩展的，客户有自己的经验规则可以补进 `references/归因下钻规则.md`。

**Q5**：为什么只给 3 个问题，其他问题呢？
→ 其余进「观察项」附录，不占管理层注意力。3 个是一次经营会能真正推动的极限。

**Q6**：可以做周度复盘吗？
→ 可以。周度时质量/成本数据通常不全，Skill 会自动降级为「订单+交付+库存三线周报」，并标注哪两条线因数据不全未判定。

## 7. Skill 组合

| 组合 Skill | 何时组合 | 效果 |
|---|---|---|
| **交付风险预警** | Q2（OTD 靠加班）需要看下月还会不会再犯时 | 把在执行订单按风险排序，识别下一批要靠加班的订单 |
| **库存与呆滞复盘** | Q3（呆滞 312.0 万元）需要逐项出处置方案时 | Top 4 呆滞逐项给让利清库/改制/供应商回购方案 |
| **质量异常分析** | 质量线五项全恶化需要根因分析时 | 从 19 份 NCR 做帕累托 + 5Why，定位到折弯工序换型确认 |
| **BOM 导入·工程基线核对** | Q3 提到「版本变更前先跑库存影响评估」时 | 版本切换前反查Where-Used 与在库数量 |
| **企微等IM分部门通知** | 三个问题需要一键派发到责任部门时 | 按责任部门拆成分部门待办卡片，带时限 @负责人 |

**推荐组合链路**（管理层一次月度经营复盘的完整闭环）：

```
五份月度数据
  → [经营复盘·一页式简报] 出五线判定 + 归因链 + 三个问题
  → Q1 毛利 → 销售部调价谈判（本 Skill 给出建议单价与敞口）
  → Q2 交付 → [交付风险预警] 看下月哪些订单还会靠加班
  → Q3 库存 → [库存与呆滞复盘] Top 4逐项处置方案
  → 三个问题 → [企微等IM分部门通知] 按责任部门派发带时限的待办
  → 下月复盘 → 拉本期简报的「衡量口径」列逐项验收
```
