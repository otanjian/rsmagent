# 判断口径与看点

## 这个场景最值得讲的四处

### 从历史里想起了公司踩过的坑

去年另一个部门辞退试用期员工，仲裁庭上公司拿出了一份「事后补的考核表」，员工当场指出日期在辞退之后 —— 程序倒置坐实，赔了 8,100。这次 Agent 第一件事就是核对所有证据的日期链，把「哪份材料是补不了只能承认没有」摆在最前面。这条经验写进了检查步骤，不靠当年经办人还在不在。

### 该拦的地方拦住了

结论写的是「现在还不能启动辞退流程」—— 三个法定条件一个都不满足，此时辞退按判例口径是必输的 2N。给出的不是干等：方案 A 先与员工协商（N+1 约 1.1 万，员工入职 5 个月）；方案 B 立即开始周度书面考核（剩余两周可形成 2 份记录，但坦承「仅两周记录在仲裁中证明力弱」），两个方案的金额与风险都列了，选择权在老板。

### 排除性结论

「挖出的周报数据可以直接排除『工作量不达标』这条理由 —— 周报显示其装配不良率 0.72%，低于车间平均。拿这个理由去辞退等于递刀。」—— 砍掉一条必输的辩解路径。

### 把技术动作翻译成钱

「没有录用条件确认书」翻译成「按法定口径：入职 5 个半月（不满六个月经济补偿按半个月计），违法解除 2N = 7,200 元、协商解除 N+1 = 10,800 元；而入职当天签一份录用条件确认书成本是零」—— 这张纸的钱就这么算。

## 四类看点的威力排序（通用）

1. **从历史记录里「想起」了公司踩过的坑** —— 最有威力。
   不靠那位当年经手的老员工还在不在职。
2. **该拦的地方拦住了** —— 结论写成「这份东西现在还不能发出去」，
   然后给出不用干等的替代方案。
   一个会在该停的地方停下来的助手，比一个永远给得出答案的助手可信得多。
3. **排除性结论** —— 「这个方向可以排除，依据是……」省掉一整轮最耗时的排查。
4. **把技术动作翻译成钱** —— 这一层是给老板看的，工程师看的那层拿不到预算。

## 输入区要点出那份「平时压根不在核对范围里」的资料

它躺在另一个部门、是另一个人管的、平时不在核对范围里 —— 这是价值的来源。

## 结论的写法

- 每条结论标注证据出处（哪份文件第几条、哪张单号）
- 事实、推断、建议分栏
- 来源冲突必须并列展示，不替客户选
- 拿不到的数据明确写出来
