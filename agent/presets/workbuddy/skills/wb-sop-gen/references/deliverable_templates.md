# 交付物栏位模板

> 四份交付物的完整栏位清单。★ = 体系审核必查项，不可省。

---

## 一、作业指导书（主产出）

**形态**：A3 横版单页 PDF（打印塑封挂工位）+ 可编辑源文件（.docx / .xlsx）。
一页一工序，工序复杂时拆页并标注页码 x/y。左图右文，关键参数红色粗体。

### 文件头

| 栏位 | 说明 |
|---|---|
| ★文件编号 | 建议规则：`SOP-工序码-产品码`，如 SOP-WLD-CAB02 |
| ★版本号 | V3.0 形式；大版本=重大升版，小数位=小修订 |
| ★生效日期 | 与文控发放日一致 |
| 页码 | 第 x 页 / 共 y 页 |
| 产品型号 | — |
| 工序号 + 工序名 | 如 OP60箱体骨架焊接 |
| 适用工位 / 产线 | — |
| ★依据文件清单 | **必须含版本号**：工艺路线卡 V__、图纸 Rev.__、控制计划 CP-__ V__ |

### 作业前准备

| 栏位 | 说明 |
|---|---|
| ★人员资质 | 特殊工序须写持证要求（焊接、无损检测等） |
| ★防护用品 | 具体到件（面罩/手套/护脚），不写"按规定佩戴" |
| ★设备与工装 | 名称 + **编号** |
| ★量具 | 名称 + 编号 + **校准有效期** |
| 来料确认 | 上工序交接项、物料型号批次核对 |

### 作业主体

| 栏位 | 说明 |
|---|---|
| ★作业步骤 | 编号连续，一步一动作；单步描述过长应图示化 |
| ★关键控制参数 | **必须带公差范围**，禁止只写单值；禁止"适当/合适/少许" |
| 节拍 / 标准工时 | 可选 |
| 图示 | 现场实拍或三维图，箭头标注关键对位点 |

### 质量与风险

| 栏位 | 说明 |
|---|---|
| ★质量检查要点 | 检查什么 |
| ★判定标准 | 合格判据，可量化 |
| ★检验频次 | **多久一次、查几件**（如"每批首件 + 每 2 小时抽 1 件"）——写了"检查"没写频次等于无法执行 |
| ★关键/特殊特性标注 | 醒目标识（加粗/变色/符号）；符号须按客户要求，不可自创 |
| ★异常处理 | 超范围时：**停机 → 隔离范围 → 通知到人 → 复产条件**，四要素齐 |
| ★操作安全要求 | 明文要求项，高频不符合项 |
| 环保要求 | 如涉及 |

### 受控要素

| 栏位 | 说明 |
|---|---|
| ★签字栏 | **编制 / 审核 / 会签 / 批准** 四栏 + 各自日期 |
| ★变更履历表 | 版本｜日期｜变更内容｜**变更依据**｜修订人｜审核人 |
| 受控印章位 | 留白 |
| 发放范围 | 部门 + 份数 |

**加分做法**：在关键参数旁写明历史教训，例如"本参数曾因取值偏低导致虚焊返修，不得擅自下调"。让下一个接手的人不必重新踩坑。

## 二、校验报告（Excel）

### Sheet1 · 总览

- 参与校验的文件清单（文件名 + 版本 + 日期 + 来源部门）
- 完整性判定：缺哪份关键输入
- 问题统计：按类型（依据过期/参数偏差/无量化值/要求过严/栏位缺失）× 按严重度
- 升版判定结论 + 触发了哪几条判定条件
- 本次未覆盖的范围（如"无控制计划，未做该项比对"）

### Sheet2 · 问题清单

| 列 | 说明 |
|---|---|
| 问题编号 | 便于跟踪引用 |
| 类型 | 依据过期 / 参数偏差 / 无量化值 / 要求过严 / 栏位缺失 |
| 严重度 | 高 / 中 / 建议 |
| 问题描述 | 一句话说清 |
| **证据定位** | 文件名 + 条目号/ Sheet + 单元格 —— 没有定位的问题会被认为是误报 |
| 指导书现值 | — |
| 工艺卡值 | — |
| 图纸值 | — |
| **判定依据** | 按哪份文件哪一条判的 |
| 建议修正值 | — |
| **关联历史异常** | 异常单号 + 数量 + 损失 |
| 责任人 / 期限 / 状态 | 供跟踪 |

### Sheet3 · 参数对照矩阵

| 参数 | 图纸 | 工艺卡 | 指导书 | 控制计划 | 检验标准 | 链路是否一致 |
|---|---|---|---|---|---|---|

> 这张表是最有力的链路证据 —— 一眼看出同一个参数在几份文件里有几个状态。

## 四、变更说明（发布用文本）

结构固定，可直接复制进文控流程与车间培训通知：

```
[文件编号] 自 [旧版本] 升级为 [新版本]，对齐 [工艺卡版本] 及 [图纸版本]。

主要变更：
① [变更内容] —— 解决 [实际问题，附异常单号]
② [变更内容] —— 解决 [实际问题]
③ [变更内容] —— 依据 [文件条目]

所有变更均有上游文件或历史异常记录依据支撑。
发布后要求：车间培训并留考核记录、首件确认、旧版回收作废。
```

**要点**：每条变更后面都要跟"解决了什么实际问题"。只写"电流改为 200A"是技术描述；写"电流 180→200A，解决四月与五月两次虚焊返修"才是能说服人签字的理由。

## 五、审核前预演清单（Excel）

| 列 | 说明 |
|---|---|
| 预计提问 | 模拟审核员会问什么 |
| 对应条款 | 体系条款或企业程序文件条款号 |
| 现有证据 | 能拿出什么文件/记录 |
| 是否能答 | 能 / 勉强 / 答不上 |
| 待补充 | 缺什么、谁去补、什么时候补 |

**典型提问示例**：
- 这份指导书依据的图纸是哪一版？现行图纸是哪一版？
- 这个参数的公差范围从哪里来？
- 这个检查项多久做一次？记录在哪？
- 参数超出范围时操作工怎么处置？培训过吗？
- 这道工序有安全风险，指导书里的防护要求在哪一条？
- 这个关键特性在控制计划里对应哪条控制措施？
