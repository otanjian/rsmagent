# 作业指导书一致性校验与升版

## 用途

把现行作业指导书与其上游文件摆在一起逐条核对，产出**可以直接进文控流程的正式件**。

## 定位（重要）

**目标不是"从图纸自动生成一份能发布的指导书"。** 参数取值牵涉安全与责任，没有人会让机器直接定；行业里的实践也都是人机各干一半。

**目标是"把该核的地方全核一遍、把拿不准的标出来、把改动理由和证据备齐，让工程师签字签得下去"。**

因此有三条硬原则：

1. **校验优先于生成** —— 找出不一致比写出新文件更刚需、也更容易证明价值
2. **每条结论必须可追溯** —— 定位到哪份文件哪一条、并排列出各文件的值、写明判定依据
3. **不替用户定参数** —— 权威值取自工艺卡/图纸；两者冲突或都没有时，列为待确认，不自行取值

## 输入

| 文件 | 作用 | 缺失时 |
|---|---|---|
| 现行作业指导书 | 被校验对象 | 必需 |
| 工艺路线卡 | **参数权威值来源** | 无则参数偏差无法判定，只能做完整性扫描 |
| 图纸技术要求 | 技术要求与公差来源 | 同上|
| 历史异常记录 |返工/客诉台账，用于闭环 | 无则跳过闭环步骤，但要说明"本次未做异常闭环" |
| 控制计划 / 检验标准 | 可选，有则一并纳入比对 | — |

格式不限：Word / Excel / PDF / 扫描件 / 图片均可。

## 执行流程

### Step 1 · 确认权威关系

先明确谁说了算，再开始比：

- 工艺参数 → 以**工艺路线卡**为权威值
- 技术要求与公差 → 以**图纸最新版**为准
- 作业指导书 → 被校验对象，不作为权威源
- 工艺卡与图纸冲突时 → **列为待确认，不自行取舍**

### Step 2 · 依据版本追溯（必须最先做）

检查指导书首页"依据文件"栏引用的版本号，与各文件实际最新版本比对。

**这是审核员翻开一份文件的第一个动作。**依据版本对不上，后面参数写得再漂亮也没有意义 —— 整份文件的基准就错了。

且此项直接影响升版等级判定（见 Step 6）。

### Step 3 · 参数逐条并排比对

**输出形态必须是并排表**，不是"哪些不一样"的列表：

| 工序/参数 | 指导书现值 | 工艺卡（权威） | 图纸 | 判定 |
|---|---|---|---|---|

判定分三种性质，**不要混为一类**：

| 性质 | 表现 | 说明 |
|---|---|---|
| **参数值偏差** | 两边都有值但不同 | 通常是上游改了、指导书没跟 |
| **无量化值** | 指导书写"适当""合适""少许""按经验" | 不是值错，是压根没有值——把判断权丢给了工人 |
| **要求过严** | 指导书比图纸/工艺卡更严 | 看着保险，实际白花工时，也可能引发客诉 |

人工核对最容易只盯住第一种，**把后两种漏掉**。

### Step 4 · 完整性扫描（与参数对不对无关，但审核必查）

| 检查项 | 判定线索 |
|---|---|
| **模糊表述** | "适当/合适/少许/大约/按经验/用力"等主观词 |
| **参数缺公差** | 只有单值没有允许范围 |
| **检查项缺频次** | 写了"检查"但未写多久一次、查几件 |
| **异常处理空白** | 参数超范围时该停机、隔离、通知谁，未写明 |
| **缺操作安全要求** | 作业指导书须包含操作人员安全规则——明文要求，且是高频不符合项 |
| **关键特性未标注** | 关键/特殊特性未在文件中醒目标识，传递链断在这里 |
| 缺使用工装量具及校准状态 | 量具无编号或未注校准有效期 |
| 缺人员资质要求 | 特殊工序（焊接等）未写持证要求 |

> 栏位缺失的成因与参数偏差不同：多半是**这份文件当年照着老模板写的，从没对着体系要求逐项过一遍**。所以要作为独立一类列出。

### Step 5 · 历史异常闭环（最能体现价值的一步）

**拿每条参数偏差反过来去异常台账里查**，而不是只做文档比对。

对每条偏差检索：相同工序、相同参数、相近判因的历史返工/客诉记录。

命中时输出：异常单号 + 时间 + 数量 + 台账上写的判因 + 累计损失。

>异常台账上记的判因往往是**现象**（"焊接强度不足""铆压力度不足"），不是根因。把参数偏差与之对上，才知道根因是"上游改了、指导书没跟"。
>
> 这一步决定了改动的性质：从"工艺卡写200 那就改成 200"，变成"**这个参数已经让我们返修过8 件、赔过一次客诉**"。前者经理会问"急不急"，后者经理会问"怎么到现在才发现"。

### Step 6 · 升版等级判定（按规则，不凭感觉）

**任一条件触发即判为重大升版**：

- 引用的依据文件跨大版本
- 关键参数偏差 ≥ 3 处
- 存在已致客诉或批量不良的偏差
- 涉及安全要求变更

重大升版意味着：文控审批 → 车间培训并留考核记录 → 首件确认 → 旧版回收作废，四步不可省。

否则为小版本修订。

**避免"每次都升小版本"** —— 越攒越乱，最后没人知道现场那份该不该信。

### Step 7 · 连带影响提示

参数变更往往不止牵动指导书。必须主动列出**还有哪些文件要同步改**：控制计划的监控参数与频次、检验标准的判定值、失效模式分析的相关条目、点检表。

>只改指导书，下次审核照样被开不符合项。

## 交付物（四份 + 一份附件）

**不要只给一段对话或一份诊断报告。**在这一行，没有签字的文件不算文件 —— AI 产出的东西必须能被人签字担责。

### ① 新版作业指导书（主产出）

形态：**A3 横版单页 PDF（可打印塑封挂工位）+ 可编辑源文件**。一页一工序，左图右文，关键参数醒目。

**必备栏位，一项不可省**：

- 文件头：文件编号、版本号、生效日期、页码 x/y、产品型号、工序号与工序名、适用工位
- **依据文件清单**（含版本号：工艺卡 / 图纸 / 控制计划编号）
- 作业前准备：人员资质、防护用品、设备工装量具（**带编号与校准有效期**）、来料确认
- 逐步作业步骤（编号连续，一步一动作）
- **关键控制参数及公差范围**（不能只有单值）
- **质量检查要点 + 判定标准 + 检验频次**
- 关键/特殊特性醒目标注
- **异常处理**：超范围时停机 → 隔离 → 通知到人 → 复产条件
- **操作安全要求**
- **编制/ 审核 / 会签 / 批准 四个签字栏 + 日期**
- **变更履历表**（版本、日期、变更内容、依据、修订人）
- 受控印章位

**一个有价值的做法**：在关键参数旁写明它的历史教训（如"本参数曾因取值偏低导致虚焊返修，不得擅自下调"）。下一个接手的人不用重新踩一遍。

### ② 校验报告

形态：**Excel**（工程师要能筛选、排序、加批注、发给责任人），附一页摘要给管理者。

- Sheet1 总览：参与校验的文件清单及各自版本、问题数与分类统计、升版判定结论
- Sheet2 问题清单：问题编号｜类型｜严重度｜问题描述｜**证据定位（文件+条目/单元格）**｜各文件的值并排｜**判定依据**｜建议修正值｜关联历史异常单号｜责任人｜期限｜状态
- Sheet3 参数对照矩阵：参数｜图纸值｜工艺卡值｜指导书值｜控制计划值｜检验标准值｜链路是否一致

### ③ 变更影响清单

形态：**Excel**。栏位：变更来源（ECN号/图纸版本/异常单号）｜变更内容｜受影响文件清单（编号+当前版本+需改为）｜是否已更新｜需重新培训的岗位与人员｜旧版回收状态｜新版生效日期｜发放部门与份数｜回收人签字。

### ④ 变更说明（发布用）

一段可直接复制进文控流程与车间培训通知的文本：本次从哪版升到哪版、对齐了哪些上游文件、主要变更三到五条（**每条附解决的实际问题**）、发布后要求（培训 + 首件确认）。

### 附 · 审核前预演清单

模拟审核员会问的问题，以及现在哪几条答不上来。形态 Excel：预计提问｜对应条款｜现有证据｜是否能答｜待补充。

## 常见问题

**工艺卡和图纸对不上怎么办** —— 不自行取舍，列为待确认并同时列出两个值及各自出处，交工艺与设计确认。

**没有历史异常记录** —— 跳过闭环步骤，但必须在报告里写明"本次未做异常闭环"，不要让人误以为已经查过。

**指导书是扫描件/照片** —— 能读的部分照读，读不清的字段标注"图像不清晰，需人工确认"，**不要用猜测填补参数**。参数是安全相关字段，猜错代价极高。

**用户说"直接把新版发布了吧"** —— 提醒必走流程：审批、培训、首件确认、旧版回收。重大升版尤其不能跳。AI 生成的文件可作草案，正式发布须人工签字。

**几百份指导书要批量核** —— 支持批量，但建议先按风险排序：涉及关键特性的、四个月以上未修订的、上游刚升版的、有异常记录关联的优先。
