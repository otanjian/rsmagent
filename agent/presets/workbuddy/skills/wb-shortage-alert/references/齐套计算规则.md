# 齐套计算规则

> 本文件是「齐套与缺料预警」Skill 的核心规则文档。
> 解决一件事：**齐套报表说有货，投产当天领不出料。**

---

## 一、为什么齐套算不准

齐套这件事看起来是纯算术：需求减库存。但真到现场，同一批工单三个人算能算出三个结果。原因不在算术，在口径。

| 口径分歧 | 具体表现 |
|---|---|
| **拿总库存当可用量** | 报表显示 320 片，扣掉安全库存、已分配、待检只剩 120 片。差200 片不是账错了，是这200 片本来就不该被算进来 |
| **在途算不算得上** | 承诺 08-10 到货，工单 08-06 开工，这笔在途算不算？答案取决于这个物料挂在第几道工序 |
| **需料日等于开工日吗** | MRP 默认等于。但装配用的电子件，需料日比开工日晚 5 个生产日 |
| **损耗率算不算** | ERP 下单量含损耗放大，齐套判定用净用量。两个口径混用就会差几个百分点 |
| **BOM 版本对不对** | 07-20 生效的新版和旧版单位用量不同，取错版本整张表都错 |

结果就是：**每个人手上的数字都对，但对不上；对不上就没人敢拍板开工。**

## 二、可用库存：四项扣减

### 2.1 公式

```
可用库存 = 总库存 − 安全库存 − 已分配 − 待检
```

### 2.2 四项为什么必须扣

| 项目 | 是什么 | 为什么不能算进可用 | 能不能动 | 动了要做什么 |
|---|---|---|---|---|
| **安全库存** | 应对供应波动的缓冲量，按 N 天用量设定 | 它存在的意义就是"不被日常需求消耗"。算进齐套等于把保险丝当电线用 | 可以 | **采购经理审批** + 同步补库计划 |
| **已分配** | 其他在制工单已锁定的量 | 挪用只是把缺料问题搬到另一张工单头上 | 可以 | **先评估被挪工单的影响**，本质是优先级重排 |
| **待检** | 已到货未经IQC 放行 | 未放行投产是品质违规，判不合格整批返工 | **不可以** | 只能催 IQC 加急检验（另开一条动作） |

### 2.3 输出必须逐项列出

不能只给"缺 60 片"这个结果。因为缺口成因不同，应对完全不同：

```
真没货（总库存本身就不够）      → 采购动作
被安全库存占住                  → 审批动作（要不要动缓冲）
被其他工单分配占住               → 排产动作（优先级重排）
被待检占住                      → 品质动作（催 IQC 加急）
```

把四项摊开，采购一眼能看出该找谁。只给一个总数，等于把判断成本又推回给人。

### 2.4 特殊情况

| 情况 | 处理 |
|---|---|
| 库存表只有总库存一列 | 明确警告"只能按总库存粗算，结果偏乐观"，输出全程标注口径，并建议补齐三列 |
| 安全库存为 0 | 正常。替代料、呆滞料通常不设安全库存，整批可动用 |
| 待检量 > 30% 可用量 | 单独提示"催 IQC 加急后可用量将变为 XXX"，作为独立动作条目 |
| 可用库存算出负数 | 说明已分配超发，提示核查库存数据一致性，**不要直接把负数当缺口** |
| 多仓库存 | 按物料汇总后扣减；有调拨限制时按可调拨范围分别核定 |
| 有"冻结/呆滞"标记的库存 | 不计入可用，但要单独列出 —— 它可能通过公差反查变成可用（见《替代料判定规则》） |

### 2.5 案例：320 片为什么只能用 120 片

```
M-PCB-001 控制主板 V2.0（STM32F103）

  总库存      320 pcs
  − 安全库存   80 pcs   3 天用量，断供缓冲
  − 已分配    100 pcs   WO-2026-0798 在制占用
  − 待检       20 pcs   S-010 立讯 07-28 到货批，IQC 未放行
  ─────────────────────
  可用库存    120 pcs

  总需求      180 pcs   WO-2026-0801 100 台 + WO-2026-0802 80 台
  净缺口60 pcs
```

报表上"320 > 180"，看着富余140 片；真实情况是缺 60 片。**这个反差是齐套算不准最常见的单一原因。**

## 三、净缺口与在途可及量

### 3.1 公式

```
净缺口 = 总需求 − 可用库存 − 在途可及量

（负数表示富余，输出保留负号并标注"富余"，不要归零）
```

### 3.2 在途可及量的判定

```
在途可及量 = Σ（承诺到货日 ≤ 需料日 的在途单数量）
```

**关键在需料日怎么定。** 两个口径：

| 口径 | 需料日 |谁在用 | 特点 |
|---|---|---|---|
| **A** | 一律 = 工单计划开工日 | ERP MRP 默认 | 保守，会产生伪缺口 |
| **B** | 按工艺路线的工序需料日 | 现场实际 | 准确，需工艺路线数据 |

### 3.3 工序需料日推算

```
工序 n 的需料日 = 工单计划开工日 + (n − 1) 个生产日
```

- 按生产日历跳过休息日（如周日不生产）
- 流转批制下，前序完成首个流转批即可开下序，所以按"生产日"递进而非"整单完成"
- 单班/多班、工序标准工时会影响精度，但对齐套判定（天级颗粒度）通常够用

**推算示例**（WO-2026-0801，P-IPC-01，计划开工 2026-08-06 周四，周日休息）：

| 工序 | 序号 | 所需物料 | 需料日 |
|---|---|---|---|
| OP10 下料 | 1 | M-SPCC-20 | 08-06（周四） |
| OP20 折弯 | 2 | — | 08-07|
| OP30 焊接 | 3 | 焊丝（常备辅料） | 08-08（周六） |
| OP40 表面处理 | 4 | M-PWD-01 | 08-10（周一，跳过 08-09 周日） |
| OP50 装配 | 5 | M-PCB-001 / M-CAB-001 / M-USBC-01 | 08-11 |
| OP60 测试包装 | 6 | 包材（常备辅料） | 08-12 |

### 3.4 双口径必须并列输出

不能只给一个口径。理由：

1. **口径 A 是客户现有报表的口径**。只给口径 B，客户会觉得"你的数字和我系统里的不一样，谁对？"
2. **两个口径的差额就是伪缺口**，这个差额本身是有价值的输出
3. 摊开来才能说清"MRP 没算错，只是口径不含工序维度"

### 3.5 伪缺口案例

```
M-USBC-01  USB-C 面板接口
  总需求 180 pcs / 可用 160 pcs
  在途 PO-2026-0720300 pcs，承诺 2026-08-10

  口径 A（按开工日 08-06 判）：在途不可及 → 净缺口 20 pcs
  口径 B（按 OP50 需料日 08-11/08-12 判）：在途可及 → 净缺口 0

  → 20 pcs 是伪缺口
```

如果按口径 A 去做紧急采购，就是为一个不存在的缺口付溢价。

### 3.6 在途承诺日的可信度处理

| 情况 | 处理 |
|---|---|
| 有"原承诺 / 最新承诺"两列 | 取**最新承诺日**，同时在备注标出变更（如"原 08-11 改 08-14"）—— 这是供应商履约信号，要进供应商绩效台账 |
| 承诺日已过但未入库 | 视为不可及，生成紧急跟催动作 |
| 承诺日 = 需料日（同日） | 视为可及但标注"零缓冲"，要供应商书面二次确认 |
| 有明确不可提前理由（如"轧制排产在 08-13"） | 记入判定依据，**直接排除"跟催提前"这条路** —— 避免做无用跟催 |
| 分批到货的在途单 | 按批次拆行判定，不要整单算 |

## 四、需求展开的三个坑

### 4.1 BOM 版本

必须确认用的是**工单对应的 BOM 版本**。有多版本时按工单下达日期匹配生效版本。取错版本，整张表的需求量都错。

### 4.2 损耗率

| 用途 | 是否含损耗 |
|---|---|
| 采购下单量 | **含** —— 要放大以覆盖损耗 |
| 齐套判定 | **不含** —— 用净用量，与 MRP 齐套口径一致 |

两个口径混用会导致缺口虚增几个百分点。**输出里必须明写用的是哪个口径。**

### 4.3 哪些物料纳入齐套

| 类型 | 纳入 | 理由 |
|---|---|---|
| 主料、关键件、外购件 | ✅ |缺了就停线 |
| 常备辅料（焊丝、包材、螺钉等） | ❌ | 库存充裕、不做工单级分配，纳入只会制造噪音 |
| 客户供料 | ⚠ 单独列 | 缺料责任在客户侧，处置路径完全不同 |
| 工装夹具、刀具 | ❌ | 不是物料齐套问题，属设备准备 |

**判定标准**：这个物料会不会做工单级分配？会→ 纳入；不会 → 不纳入。

## 五、缺口的时点分布

只给"缺 532 kg"不够用，因为缺口不是一次性发生的。要按需料日排出时点分布：

| 需料日 | 工单 | 工序 | 本次需求 | 累计需求 | 累计供给 | 当日缺口 | 累计缺口 | 判定 |
|---|---|---|---|---|---|---|---|---|
| 08-06 | WO-2026-0801 | OP10 | 450 | 450 | 2350 | 0 | 0 | ✅ 可投 |
| 08-06 | WO-2026-0803 | OP10 | 960 | 1410 | 2350 | 0 | 0 | ✅ 可投 |
| 08-07 | WO-2026-0802 | OP10 | 360 | 1770 | 2350 | 0 | 0 | ✅ 可投 |
| 08-10 | WO-2026-0805 | OP10 | 600 | 2370 | 2350 | 20 | 20 | ⚠ 差 20 |
| 08-11 | WO-2026-0806 | OP10 | 192 | 2562 | 2350 | 192 | 212 | ⛔ 全缺 |

**时点分布的价值**：

1. 看出**哪几张工单能开、哪几张不能**，而不是笼统的"这个物料缺"
2. 看出**缺口发生在哪一天**，决定紧急采购的到货时限
3. 看出**前面的工单不受影响** —— 不要因为最后一张单缺料就把整批都停掉

**累计供给的计算**：可用库存 + 该日期前已到货的在途量。在途按承诺到货日累加。

## 六、齐套判定的输出检查清单

出结论前逐条自查：

1. ☐ 可用库存是否按四项扣减，且逐项列出了算式
2. ☐ 需求展开用的 BOM 版本是否与工单匹配
3. ☐ 需求量是否用净用量（不含损耗）
4. ☐ 常备辅料是否已排除
5. ☐ 在途可及量是否双口径并列
6. ☐ 工序需料日是否按生产日历跳过了休息日
7. ☐ 在途承诺日是否取了最新值，变更是否已标注
8. ☐ 净缺口为负时是否保留负号标注"富余"
9. ☐ 缺口是否排出了时点分布
10. ☐ 富余物料是否也列出（避免只看缺料，漏掉可以支援其他工单的余量）
11. ☐ 与 MRP 结果是否一致；不一致时是否输出了口径差异说明
12. ☐ 是否明确写了"不替代 MRP 做确定性计算"

## 七、与 MRP 的分工

| 事项 | 归谁 |
|---|---|
| 需求展开（BOM × 数量） | MRP |
| 库存扣减、净缺口 | MRP |
| 建议采购量、下单时点、提前期| MRP |
| 工序级需料日口径 | **本Skill 补充** |
| 缺口的时点分布 | **本 Skill 补充** |
| 缺口化解路径评估 | **本 Skill 判定** |
| 最终拍板 | **人** |

**口径不一致时的处理顺序**：

```
1. 先假设 MRP 对，检查自己：漏扣待检？BOM 版本不同？含了损耗率？辅料没排除？
2. 口径核完仍不一致 → 输出「口径差异说明」，列双方数字和各自算法
3. 不得直接以本 Skill 的数字覆盖 MRP 结果
```

这一条不是客气，是实用主义：ERP 的算术模块经过多年生产验证，出错概率远低于口径理解偏差。把"我算得更准"当默认假设，多半会翻车。
