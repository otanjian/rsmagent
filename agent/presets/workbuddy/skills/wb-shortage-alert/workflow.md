#齐套与缺料预警 Skill

> 采购场景 6.1 专用 Skill · 需求展开 → 可用量核定 → 净缺口计算 → 缺口化解六条路径 → 三色开工结论 + 动作清单
>
> **核心定位**：MRP 算「缺多少」，这个 Skill 判「缺口怎么化解」。

---

## 1. 用途

明天要投产的工单能不能开工，这件事 ERP 给不出答案。MRP 能算出"M-SPCC-20 缺 532 kg"，但接下来全靠人判断：

- 这个缺口能不能用替代料顶？替得了技术，客户认不认？
- 库里那批呆滞 8 个月的料规格接近，能不能用？
- 能不能先跳过这道工序，让后面几道先做？
- 要不要花溢价买现货？要不要动客户交期？要不要拆单？

这些判断在 MRP 里没有答案，只在老采购脑子里。这个 Skill 一次做完 6 件事：

1. **需求展开**：BOM 单位用量 × 工单数量，逐物料汇总总需求
2. **可用量核定**（核心口径）：可用库存 = 总库存 − 安全库存 − 已分配 − 待检。**安全库存不参与齐套计算**
3. **净缺口计算**：净缺口 = 需求 − 可用库存 − 在途可及量。在途可及量按「承诺到货日 ≤ 需料日」判定，**需料日按工艺路线的工序区分，不一律用计划开工日**
4. **缺口化解六条路径**（核心差异化）：替代料 → 呆滞料反查 → 分批投产 → 紧急采购 → 调整交期 → 拆单，按顺序逐条判可行性 / 代价 / 风险 / 前置条件
5. **替代料四道校验**：客户是否认可 / 技术是否等效 / 是否需重新首件 / 成本差异，四道缺一即淘汰
6. **三色开工结论 + 动作清单**：每张工单红黄绿，每条动作带责任人、时限、验收标准、是否需升级

**边界先说清**：本 Skill **不替代 MRP 做确定性计算**。详见 5.8。

## 2. 触发方式

### 2.1 用户一句话触发（推荐）

```
明天开始有一批工单要投产，帮我判断能不能开工。
资料我都放在 D:\workbuddy_data\采购\齐套预警\ 了。

先算清楚每个物料到底缺多少——可用库存要扣掉安全库存、已分配和待检。
缺口算出来之后逐条看有没有化解办法：能不能用替代料顶？库里的呆滞料有没有规格能凑上的？
哪些工序其实可以先投产、不用等料齐？
最后给我每张工单一个开工结论，红黄绿标清楚，再出动作清单，每条带责任人和时限。
```

Skill 自动读取目录下全部文件（BOM / 库存 / 在途 / 工单 / 替代料 / 呆滞料 / 工艺路线），按表头识别用途。

### 2.2 只算缺口

```
帮我算一下这批工单的净缺口，可用库存记得扣安全库存和已分配。
```

→ 只跑 Step 1~3，输出缺口计算表（含可用库存与净缺口的逐项算式）。

### 2.3 只判替代料

```
M-PCB-001 缺 60 片，能不能用 M-PCB-002 替？
```

→ 只跑替代料四道校验，**必须按「物料 × 客户」逐组合给结论**，不给一个笼统的"能替/ 不能替"。

### 2.4 只做呆滞料反查

```
我这批呆滞料还能不能用在现在的单上？
```

→ 只跑呆滞料公差反查（见 5.5），输出「呆滞批号 × 在产产品 × 客户」的三维可用性矩阵。

### 2.5 只问能不能开工

```
WO-2026-0806 明天能不能开工？
```

→ 单工单模式，输出该工单的三色结论 + 缺口 + 化解路径 + 前置动作。

### 2.6 直接拖文件

用户把 7 份表一起拖进对话框，Skill 按表头自动识别哪份是库存快照、哪份是替代料关系表。

## 3. 输入格式规范

**不强制格式** —— 采购现场的现实是"BOM 在 ERP、呆滞料在库龄表、替代料关系在某个人的 Excel 里、图纸公差只在图纸上"。

| 输入 | 必需 | 关键字段（有别名容错） | 缺失时的降级行为 |
|---|---|---|---|
| **工单需求** | **必需** | 工单号 / 产品编号 / 数量 / 计划开工日 / 客户 | 缺失则无法确定需求，Skill 明确提示"请提供待开工工单清单" |
| **BOM 明细** | **必需** | 产品编号 / 物料编码 / 单位用量 / **备注（图纸公差）** | 缺失则无法展开需求。**备注列缺失时呆滞料反查降级**，只能按"规格完全相同"判，会漏掉公差内可用的呆滞料 |
| **库存快照** | **必需** | 物料编码 / 总库存 / 安全库存 / 已分配 / 待检 | 只有总库存时，Skill 会明确警告"当前只能按总库存粗算，结果偏乐观，请补齐安全库存/已分配/待检三列"，并在输出里标注口径 |
| **在途采购单** | 强烈建议 | 采购单号 / 物料编码 / 订单数量 / **承诺到货日** | 缺失则在途可及量按 0 计，缺口偏大；有"原承诺 / 最新承诺"两列时**取最新承诺日** |
| **工艺路线** | **分批投产必需** | 产品编号 / 工序号 / 工序名称 / **本工序所需物料** | 缺失则无法算工序需料日，需料日一律取计划开工日（等同 MRP 口径），**分批投产路径不可用**，Skill 会提示"补齐工艺路线可识别伪缺口" |
| **替代料关系表** | **替代料判定必需** | 原物料 / 替代物料 / 技术等效性 / **客户是否认可** / 是否需重新首件 / 成本差异 | 缺失则跳过替代料路径。**只有"技术等效"没有"客户认可"列时，Skill 拒绝直接给"可替"结论**，改为输出"技术可行，客户认可待确认"并列为待办|
| **呆滞料清单** | 呆滞料反查必需 | 物料编码 / 批号 / 数量 / 单价 / 呆滞月数 / **备注（实测值）** | 缺失则跳过该路径。**备注无实测值时不得下"可用"结论**，只能输出"疑似可用，需实测复核" |

**列名容错**：以下都能识别为"可用库存"：可用库存 / 可用量 / 可用数 / 非受限库存 / ATP / Available。
"已分配"= 已分配 / 已占用 / 已锁定 / 预留 / Reserved / Allocated。
"待检"= 待检 / 检验中 / 未放行 / QC Hold / Quality Inspection。
"承诺到货日"= 承诺到货 / 最新承诺 / 确认交期 / ETA / Promise Date（有多列时取最新）。

**格式支持**：xlsx / xls / csv / pdf（含扫描件走 OCR）/ docx / 图片（纸质呆滞料盘点表拍照）/ 邮件正文粘贴（供应商到货确认）。

## 4. 输出格式规范

```markdown
##齐套与缺料预警 · 恒信精密机械 · 2026-08-04 · 6 张工单 / 630 台

### ① 缺口计算
| 物料编码 | 单位 | 总需求 | 总库存 | 可用库存 | 在途可及(A) | 净缺口(A) | 在途可及(B) | 净缺口(B) | 缺口成因 |
|---|---|---|---|---|---|---|---|---|---|
| M-PCB-001 | pcs | 180 | **320** | **120** | 0 | 60 | 0 | 60 | 320 − 80安全 − 100已分配 − 20待检 = 120 |
| M-USBC-01 | pcs | 180 | 260 | 160 | 0 | 20 | 300 | **0** | 口径差异→ 伪缺口 |

口径 A = 按计划开工日判在途可及（MRP 默认）
口径 B = 按工艺路线的工序需料日判在途可及
每行必须附可用库存算式与净缺口算式

### ② 缺口化解六条路径逐项判定
| 路径序 | 路径名称 | 适用缺口 | 具体方案 | 可行性 | 代价 | 风险 | 前置条件 | 判定依据 | 吃掉缺口 |
|---|---|---|---|---|---|---|---|---|---|
（按 5.4 的固定顺序排列，可行性只能填：可行 / 部分可行 / 不可行 / 不推荐(备选)）
（末尾必须有缺口收敛验算：原始缺口 − 各路径吃掉量 = 剩余缺口，必须归零或明确说明未归零部分）

### ③ 替代料四道校验结果
| 原物料 | 替代候选 | 目标工单 | 客户 | ②技术等效性 | ①客户是否认可 | ③是否需重新首件 | ④成本差异 | 四道结论 | 淘汰/采纳理由 |
|---|---|---|---|---|---|---|---|---|---|
（必须按「物料 × 客户」逐组合建行，同一替代关系不同客户结论可以相反）
（淘汰的必须写明卡在第几道）

### ④ 三色开工结论
| 工单号 | 产品 | 数量 | 计划开工日 | 客户 | 结论 | 缺口与化解路径 | 开工前置动作 | 客户交付影响 |
|---|---|---|---|---|---|---|---|---|
（必须附验算：三色工单数加总 = 总工单数；三色台数加总 = 总台数）

### ⑤ 动作清单
| # | 关联工单 | 动作内容 | 所属路径 | 责任人 | 协同 | 时限 | 验收标准 | 是否需升级 | 升级对象 | 未完成后果 |
|---|---|---|---|---|---|---|---|---|---|---|
（每条必须有验收标准；需升级的必须写升级对象）
```

**输出硬规则**：

1. 所有涉及可用库存和净缺口的数字**必须附算式**，不能只给结果
2. 缺口收敛链条**必须闭合**：原始净缺口 − Σ各路径吃掉量 = 剩余缺口，剩余不为 0 时必须明确说明
3. 三色结论的**工单数与台数都要加总验算**
4. 替代料四道校验表**按「物料 × 客户」建行**，不按物料建行
5. **不输出耗时数字与效率百分比**。价值体现在能力差异（见 5.9），不在速度对比

## 5. 核心处理逻辑

### 5.1 齐套与缺料预警五步法

```
Step 1 需求展开   BOM 单位用量 × 工单数量 → 逐物料汇总总需求
                  区分「纳入齐套的物料」与「常备辅料」（焊丝/包材等不做工单级分配的不纳入）
Step 2 可用量核定 可用库存 = 总库存 − 安全库存 − 已分配 − 待检（见 5.2）
Step 3 净缺口     净缺口 = 需求 − 可用 − 在途可及量；在途可及量双口径并列（见 5.3）
Step 4 缺口化解   六条路径按固定顺序逐条判（见 5.4~5.7）
Step 5 结论输出   三色开工结论（见 5.6）+ 动作清单
```

**关键顺序说明**：Step 3 必须**双口径并列输出**，不能只给一个口径。因为口径 A（按开工日）是 ERP MRP 的默认口径，客户的现有报表就是这么算的；口径 B（按工序需料日）才是现场实际。两个口径的差额就是伪缺口，把差额摊开来，客户才能看懂"为什么你说的和我系统里的不一样"。

### 5.2 可用库存计算规则（本Skill 的口径基石）

**公式**：

```
可用库存 = 总库存 − 安全库存 − 已分配 − 待检
```

**四项的含义与为什么要扣**：

| 项目 | 含义 | 为什么不能算进可用 | 能不能动|
|---|---|---|---|
| **安全库存** | 应对供应波动的缓冲量，通常按 N 天用量设定 | 它的存在意义就是"不被日常需求消耗"。算进齐套等于把保险丝当电线用 | 可以动，但**必须采购经理审批**，且要同步补库计划 |
| **已分配** | 其他在制工单已锁定的量，物理在库但归属已定 | 挪用会造成另一张工单缺料，只是把问题搬了个位置 | 可以动，但**必须先确认被挪工单的影响**，本质是优先级重排 |
| **待检** | 已到货未经 IQC 放行 | 未放行物料投产是品质违规，一旦不合格整批返工 | **不能动**。但可以催IQC 加急检验，这是一条独立的动作 |
| **总库存** | 账面结存| —— | —— |

**典型反差案例**（本 Skill 的经典演示点）：

```
M-PCB-001 控制主板
  总库存    320 pcs   ← 报表上看着够（需求 180）
  安全库存  −80 pcs   （3 天用量）
  已分配   −100 pcs   （WO-2026-0798 在制占用）
  待检      −20 pcs   （S-010 立讯 07-28 到货批，IQC 未放行）
  ────────────────
  可用库存   120 pcs   ← 实际能用的
  需求       180 pcs
  净缺口      60 pcs   ← 报表说够，其实缺 60
```

**这一条是最常见的口径错误**。很多企业的齐套报表直接拿总库存比需求，结论必然偏乐观，到投产当天才发现领不出料。

**扣减顺序不影响结果，但输出时必须逐项列出**，让采购能看出缺口是"真没货"还是"被占住了"—— 这两种情况的应对完全不同：真没货要采购，被占住要重排优先级。

**特殊情况处理**：

| 情况 | 处理 |
|---|---|
| 库存表只有总库存一列 | 明确警告"当前只能按总库存粗算，结果偏乐观"，输出里全程标注口径 |
| 安全库存为 0（如替代料、呆滞料） | 正常，不设安全库存的物料整批可动用 |
| 待检量占比很高（>30% 可用量） | 单独提示"建议催 IQC 加急，放行后可用量将变为XXX"，并作为一条独立动作 |
| 可用库存算出负数 | 说明已分配超发，提示"已分配 + 安全 + 待检 > 总库存，请核查库存数据一致性" |
| 多仓库存 | 按物料汇总后再扣减；若有仓库间调拨限制，按可调拨范围分别核定 |

### 5.3 净缺口计算与在途可及量双口径

**公式**：

```
净缺口 = 总需求 − 可用库存 − 在途可及量
（负数表示富余，输出时保留负号并标注"富余"）
```

**在途可及量的判定**：

```
在途可及量 = Σ（承诺到货日 ≤ 需料日 的在途单数量）
```

关键在「需料日」怎么定：

| 口径 | 需料日取值 | 谁在用 | 特点 |
|---|---|---|---|
| **口径 A** | 一律 = 工单计划开工日 | ERP MRP 默认 | 保守。把后序工序的缺料也算成阻碍开工，会产生伪缺口 |
| **口径 B** | 按工艺路线的工序需料日 | 现场实际 | 准确。需要工艺路线数据支撑 |

**工序需料日推算**：

```
工序n 的需料日 = 工单计划开工日 + (n − 1) 个生产日
（按生产日历跳过休息日；流转批制下前序完成首个流转批即可开下序）
```

**双口径的价值**：两个口径的差额= 伪缺口。识别出伪缺口能避免两件事——① 为不存在的缺口付紧急采购溢价；② 现场自行推迟开工，白丢生产日。

**必须说清的一句话**：口径 A 并不是MRP 算错了。MRP 只负责确定性计算，工序级需料时点要结合工艺路线补上。这是补充，不是纠错。

**在途承诺日的可信度处理**：

| 情况 | 处理 |
|---|---|
| 有"原承诺 / 最新承诺"两列 | 取最新承诺日；同时在备注标出变更（如"原 08-11 改 08-14"），这是供应商履约信号 |
| 承诺日已过但未入库 | 视为不可及，并生成一条紧急跟催动作 |
| 承诺日 = 需料日（同日） | 视为可及，但标注"零缓冲"，建议要供应商书面二次确认 |
| 有明确不可提前理由（如轧制排产在某日） | 记入判定依据，直接排除"跟催提前"这条路，避免做无用跟催 |

### 5.4 缺口化解六条路径的判定顺序

**固定顺序，不可打乱**：

```
① 替代料      → ② 呆滞料反查 → ③ 分批投产
→ ④ 紧急采购 → ⑤ 调整交期   → ⑥ 拆单
```

**排序依据**：

| 段位 | 路径 | 逻辑 |
|---|---|---|
| 先用已有资源 | ①替代料 ② 呆滞料反查 | 不花钱、不延期、不动客户。库里已经有的东西，先想办法用上|
| 再用时间腾挪 | ③ 分批投产 | 不消耗物料，只是换需料日口径。**放在紧急采购之前**，可以避免为伪缺口付溢价 |
| 然后才花钱 | ④ 紧急采购 | 花钱但不影响客户，代价可控 |
| 最后动客户 | ⑤ 调整交期 | 影响客户产线、计入供应商绩效，代价最高 |
| 兜底 | ⑥ 拆单 | 前五条都用完仍有零头时，把大单拆成"能做的先做+ 剩下的等料" |

**漏斗式执行**：六条路径不是并列选项。每条先判「可行 / 部分可行 / 不可行 / 不推荐(备选)」，可行的先吃掉一部分缺口，**剩余缺口才往下一条走**。

**收敛链条示例**（必须在输出里闭合）：

```
M-SPCC-20 原始净缺口 532 kg
  ② 呆滞料 M-SPCC-18顶 WO-2026-0804 的 320 kg  →剩 212 kg
  ④ 紧急采购代理商现货 200 kg→ 剩 12 kg
  ⑥ WO-2026-0806 拆单（112 台先做 + 8 台等料）    → 剩 0 kg  ✅闭合
```

**每条路径必须给全五项**：

| 项目 | 要求 |
|---|---|
| **可行性判定** | 四选一：可行 / 部分可行 / 不可行 / 不推荐(备选)。"部分可行"必须写明吃掉多少、剩多少 |
| **代价** | 量化到金额或具体工作量（如"+144.00 元"、"增加 5 件尺寸 + 载荷测试"），不写"成本略增" |
| **风险** | 写具体失效场景，不写"有一定风险"。如"1.78mm 低于公差下限，须逐张复测挑选" |
| **前置条件** | 谁在什么时点前做完什么，能直接转成动作清单的条目 |
| **判定依据** | 标明数据出处：哪份表、哪一行、哪个字段。**无依据的判定视为推测，必须标注"待确认"** |

**六条路径各自的判定要点**：

| 路径 | 判定要点 | 常见误判 |
|---|---|---|
| ① 替代料 | 必须过四道校验（见 5.5）；**按「物料 × 客户」逐组合判** | 只看技术等效就下"能替"结论 |
| ② 呆滞料反查 | 按「实测值 → 图纸公差区间 → 客户认可」三层判（见 5.5） | 按"规格是否相同"判，规格不同就直接放弃 |
| ③ 分批投产 | 按工艺路线找断点（见 5.6） | 一律按开工日判缺料，后序缺料也认为整单开不了 |
| ④ 紧急采购 | 要核MOQ、溢价幅度、是否超采购授权、材质证明书 | 忽略 MOQ 导致"只需12 kg 却必须买 200 kg"没被发现 |
| ⑤ 调整交期 | 要区分"改客户交货日"与"改我方完工日"；前者影响客户绩效 | 把完工日有缓冲当成交货日可以改 |
| ⑥ 拆单 | 要核拆出的子单产能能否排进、客户是否接受分批到货 | 只在纸面拆单，没出排产、没向客户报备 |

### 5.5 替代料四道校验 + 呆滞料公差反查

#### 5.5.1 替代料四道校验

**四道，缺一即不可用**：

| 道 | 校验项 | 判据来源 | 不过的后果 |
|---|---|---|---|
| ② | **技术是否等效** | 图纸公差 / 技术规格书 / 老化与EMC 报告 / 材质证明 | 淘汰，且**不必再问客户**，省一轮沟通 |
| ① | **客户是否认可** | PPAP PSW / 客户技术规格书 / 图纸会签记录 / 客户书面批复 | 淘汰。这是**硬门槛** |
| ③ | **是否需重新首件** | 变更点性质（料号变更 / 材料变更 / 同图号版本内变更） | 不淘汰，但决定前置工作量与时限 |
| ④ | **成本差异** | 替代物料单价 − 原物料单价 | 不淘汰，但决定要不要报批 |

**执行顺序：先过②技术等效，再问 ① 客户认可。**
技术上已经否决的（如 1.8mm 板材用于公差 1.95~2.05mm 的产品），不必去问客户；技术过了但客户不认的，才是真正需要摆到桌面上的取舍。

**第① 道是最容易被跳过的一道。** ERP 的替代料主数据通常只维护"技术上可替"，客户认可状态散落在 PPAP 文件、客户技术规格书、图纸会签记录里，不在任何一张表的字段里。

**硬规则**：

1. 替代料关系**必须按「物料 × 客户」建行**。按「物料」建行一定会出错 —— 同一个替代关系，有 PPAP 约束的客户和通用工业客户结论可以完全相反
2. 「技术等效」不代表「客户认可」。这两件事必须分两列，不能合成一列"是否可替"
3. 有 PPAP / PSW 的客户，**料号、材料规格、供应商都在批准范围内锁定**，任一项变更都是变更点，须客户书面认可（PPAP 重提交或材料偏差申请）
4. 判定为"可替"后，**可用库存的分配顺序要重排**：优先分配给无替代路径的工单。这一条见 5.5.3

#### 5.5.2 呆滞料按公差区间反查

**核心原则**：呆滞料能不能用，判据是**实测值是否落在图纸公差区间内**，不是"规格是否相同"。

**三层判定**：

```
第 1 层 实测值    读呆滞料清单的备注列，取实测值（如厚度实测 1.78/ 1.81 / 1.83 mm）
                  无实测值 → 不得下"可用"结论，只能输出"疑似可用，需实测复核"
   ↓
第 2 层 公差区间  读 BOM 明细备注列/ 图纸的公差要求（如 P-BRK-03 板材公差 1.8~2.2mm）
                  逐产品比：实测值落在该产品公差区间内 → 技术通过
                  超出区间 → 技术否决，不必再问客户
   ↓
第 3 层 客户认可  技术通过的组合，再过替代料四道校验的第 ① 道
                  无 PPAP 约束 → 按图纸公差自动认可
                  有 PPAP 约束且涉及材料规格变更 → 须客户书面认可
```

**典型案例**（本 Skill 的核心演示点）：

```
需要：M-SPCC-20冷轧板 2.0mm
库里：M-SPCC-18 冷轧板 1.8mm，呆滞 8 个月，460 kg，2829元
      备注实测厚度 1.78 / 1.81 / 1.83 mm

按「规格是否相同」判→ 1.8 ≠ 2.0，放弃  ❌ 这是大多数系统和人的做法
按「公差区间」判：
  P-BRK-03  图纸公差 1.8~2.2mm  → 1.8mm 落在区间内✅ 技术通过
  P-IPC-01  图纸公差 1.90~2.10mm → 超下限 0.10mm      ⛔ 技术否决
  P-CAB-02  图纸公差 1.95~2.05mm → 超下限 0.15mm      ⛔ 技术否决

P-BRK-03 再过客户认可：
  华东电气（无 PPAP）→ 按图纸公差自动认可      ✅ 可用
  某主机厂 HX-3155（有 PPAP）→ 材料规格已随 PSW 批准，须书面偏差申请  ⛔ 不可用
```

**为什么这条路径 MRP 永远给不出来**：图纸公差在图纸里，实测值在盘点记录里，客户认可状态在 PPAP 文件里。物料主数据只有"M-SPCC-18"和"M-SPCC-20"是两个不同的物料编码，没有任何字段能表达"其中一个在某个产品上可以顶另一个"。

**呆滞料反查的附加价值**：一次动作解两个问题 —— 解缺口 + 消化呆滞库存。输出时**必须算出消化金额**（数量 × 单价），这是采购月度考核的呆滞项，比省下的材料成本更有意义。

**下限侧无余量的坑**：实测值刚好压在公差边界（如实测最小 1.78mm、公差下限 1.80mm）时，**不能整批放行**，必须逐张复测挑选，并把这条写进动作清单。忽略这一点会导致"用了呆滞料反而出批量不良"。

#### 5.5.3 可用库存的分配顺序（容易漏的一条）

替代料判定完成后，可用库存的分配顺序要重排：

```
优先级：无替代路径的工单 > 有替代路径的工单
```

**为什么**：若把可用库存先给了有替代路径的工单，缺口就落在无替代路径的工单上，那是个死结。

**案例**：M-PCB-001 可用 120 pcs，需求 180 pcs（WO-2026-0801 某主机厂 100 台 + WO-2026-0802 华东电气 80 台）

```
✅ 正确：120 优先给 WO-2026-0801（PPAP 锁定料号，无替代路径）
        → 剩 20 给 WO-2026-0802 → 缺 60 → 用M-PCB-002 替代补齐 → 两张单都能做

❌ 错误：按工单号顺序或开工日先后自动分配
        → 若WO-2026-0802 先拿到货，缺口落在 WO-2026-0801 上 → 无替代路径 → 死结
```

**MRP 按工单号或开工日自动分配，不看有无替代路径。** 分配顺序本身就是一个判断。

### 5.6 分批投产按工艺路线断点判定

**核心原则**：物料挂在第几道工序，决定它的需料日是不是等于开工日。

**断点判定规则**：

| 物料挂在 | 缺料影响 | 是否构成分批投产断点 |
|---|---|---|
| **首序（如OP10 下料）投料** | 整单开不了工 | ❌ 否 —— 缺料即无法开工，只能走其他路径 |
| **中后序（如 OP40 表处 / OP50 装配）投料** | 前面工序可以先做 | ✅ **是** —— 前序可先投，该物料到货后接后序 |
| **无新增投料的工序（如折弯）** | 无影响 | ❌ 否 —— 无投料不构成断点 |
| **常备辅料（焊丝 / 包材）** | 无影响 | ❌ 否 —— 不做工单级分配，不纳入齐套计算 |

**判定步骤**：

```
Step 1  读工艺路线，建立「产品 → 工序序列 → 各工序所需物料」映射
Step 2  对每个缺料物料，找出它挂在哪道工序（可能挂多道）
Step 3  算该工序的需料日 = 计划开工日 + (工序序号 − 1) 个生产日（按生产日历跳休息日）
Step 4  比对该物料的在途承诺到货日 ≤ 工序需料日？
          是 → 该缺口是伪缺口，标记为"可分批投产化解"
          否 → 真缺口，进入下一条路径
Step 5  输出分批投产方案：「OP10~OPn 可先投，物料到货后接 OPn+1」
```

**输出必须写清三件事**：

1. 哪几道工序可以先投（工序号 + 工序名）
2. 断点在哪一道（哪个物料、哪天到）
3. **谁要做什么才能落地** —— 通常是 PMC 把到料节点挂到工序看板。**没有这一步，现场仍会按"开工日缺料"理解，自行推迟开工，白丢生产日**

**分批投产的代价与风险**（不能只讲好处）：

| 项目 | 内容 |
|---|---|
| 代价 | PMC 需按工序建立到料节点跟踪，而非只跟开工日；管理颗粒度变细 |
| 风险 | 若在途再次短交，会卡在后序而非开工，**在制品占用增加**（比卡在开工更糟，因为料已经投下去了） |
| 前置 | 必须拿到供应商的**书面二次到货确认**，不能只凭系统里的承诺日 |

### 5.7 三色结论标准

|颜色 | 标准 | 输出必须包含 |
|---|---|---|
| 🟢 **绿** | 现有可用库存 + 在途可及量（**按工序需料日口径**）已满足全部工序需求 | 无缺口的依据；若依赖后序到料，要写明需PMC 挂工序看板 |
| 🟡 **黄** | 缺口有明确化解路径，但**需前置动作**才能开工（替代料首件 / 呆滞料公差确认 / 紧急采购到货） | 缺什么、走哪条路径、**谁在什么时点前做完什么** |
| 🔴 **红** | 原计划无法完整执行，**需升级决策**（拆单 / 溢价审批 / 客户报备） | 为什么前几条路径都不通（逐条写明）、升级给谁、升级后的方案 |

**硬规则**：

1. **黄色必须写清"谁 / 何时 / 做什么"**。写不清的黄色会烂成红色。"有风险"、"需关注"这种模糊说法不算黄色结论
2. **三色工单数加总 = 总工单数**，台数加总 = 总台数，必须在输出里验算
3. **红色不等于"做不出来"**。红色的含义是"原计划无法完整执行、需升级决策"。拆单后 112 台按期 + 8 台顺延，和120 台全部失守是完全不同的结论，输出时要说清
4. 绿色工单如果依赖后序到料（分批投产），**必须写明这个依赖**，不能只写"无缺口"
5. 三色判定的**基准是工序需料日口径（口径 B）**，不是开工日口径。同时输出口径 A 的结果供客户与现有报表对照

**按客户维度复核**：输出后按客户拆一遍。若某客户的红黄工单明显偏多，要说明成因（通常是 PPAP 约束让化解路径天然更少），这不是数据巧合，是机制的必然结果。

### 5.8 Agent 不替代 MRP 做确定性计算（边界）

**这一条必须在演示和交付时主动讲清，不能等客户问。**

| 事项 | 归谁 | 说明 |
|---|---|---|
| 需求展开（BOM × 数量） | **MRP** | 确定性计算，ERP 算得又快又准 |
| 库存扣减、净缺口 | **MRP** | 同上。Agent 复算只是为了验证口径一致，**不推翻 MRP 的结果** |
| 建议采购量、下单时点 | **MRP** | 提前期、批量规则都在 ERP 里 |
| 工序级需料日口径 | **Agent 补充** | MRP 默认按开工日，Agent 结合工艺路线补上工序口径，识别伪缺口 |
| 替代料能不能用 | **Agent 判定** | 需要 PPAP、客户技术规格书、图纸公差，不在 ERP 确定性计算范围内 |
| 呆滞料能不能顶 | **Agent 判定** | 需要图纸公差 + 实测值，物料主数据没有这个字段 |
| 分批投产可不可行 | **Agent 判定** | 需要工艺路线断点 + 在途承诺日的交叉判断 |
| 化解路径的代价与风险 | **Agent 判定** | 需要 MOQ、溢价授权、客户绩效影响等散落信息 |
| **最终拍板** | **人** | Agent 摆判据，采购和采购经理做决定 |

**说法建议**：

```
✅ "MRP 算出缺 532 公斤，这个数字我们不重算也不推翻。
    我们做的是 MRP 做不到的两件事：
    一是补上工序级需料日口径，识别出哪些是伪缺口；
    二是对真缺口逐条评估化解路径，把散在图纸、PPAP、库龄表里的判据摆到一起。
    判定权仍在采购手上。"

❌ "AI 全自动算齐套，比 ERP 更准"
    —— 技术型客户听到这句会立刻降低信任
```

**如果 Agent 复算结果与 MRP 不一致怎么办**：

1. **先假设 MRP 对**，检查自己的口径（是否漏扣待检、是否用了不同的 BOM 版本、是否含损耗率）
2. 口径核对后仍不一致 → 输出"口径差异说明"，列出双方数字和各自算法，交给采购判断
3. **不得直接以Agent 的数字覆盖 MRP 结果**

### 5.9 价值表述规范

**不要写**：耗时数字（"2 小时 → 3 分钟"）、效率百分比（"-95%"）、"效率提升"这类无法核实的表述。

**要写可核实的能力差异**：

| MRP 输出 | 本 Skill 输出 |
|---|---|
| "M-SPCC-20 缺 532 kg" |532 kg 的时点分布（哪天缺多少）+ 六条化解路径的逐项判定 + 收敛到 0 的链条 |
| "M-PCB-001 缺 60 pcs" | 缺口分配到哪张工单、为什么按这个顺序分配、哪张能替哪张不能替及依据 |
| 无 | 11 个替代候选的四道校验结果，淘汰的写明卡在第几道 |
| 无 | 呆滞料按公差区间反查的三维可用性矩阵（批号 × 产品 × 客户） |
| 无 | 6 张工单各自的三色开工结论 + 前置动作 |
| 无 | 16 条带责任人、时限、验收标准的动作清单，3 条标出需升级 |

**每条判断都标数据出处**（哪份表、哪一行、哪个字段），可逐条回溯核对—— **可回溯性本身就是价值**，比任何百分比都实在。

### 5.10 常见坑

| 坑 | 表现 | 本 Skill 的应对 |
|---|---|---|
| **拿总库存当可用量** | 齐套报表直接用总库存比需求，结论偏乐观，投产当天领不出料 | 强制四项扣减，且输出逐项算式，让缺口成因可见 |
| **安全库存被吃掉** | 齐套计算把安全库存算进可用，缓冲消失，下次波动直接断供 | 安全库存明确不参与齐套；要动必须走采购经理审批并同步补库 |
| **待检当成能用** | 未放行物料被算进可用，投产后 IQC 判不合格，整批返工 | 待检强制扣除，不可挪用；可另开"催IQC 加急"动作 |
| **只看技术等效就替** | 替代料主数据只维护技术等效，PPAP 指定料号的客户照样被替，客户审核开不合格项 | 四道校验第 ① 道客户认可为硬门槛；替代关系按「物料 × 客户」建行 |
| **替代料按物料建行** | 一个替代关系一行，不分客户，导致有PPAP 的客户被误判可替 | 强制按「物料 × 客户」建行，同一关系不同客户结论可相反 |
| **呆滞料按规格判** | 规格不同就放弃，公差内可用的呆滞料一直躺在库里 | 按「实测值 → 图纸公差区间 → 客户认可」三层反查 |
| **呆滞料整批放行** | 实测值压在公差边界仍整批用，出批量不良 | 下限侧无余量时强制逐张复测挑选，并写进动作清单 |
| **无实测值就下结论** | 呆滞料清单只有规格没有实测值，直接判"可用" | 无实测值只能输出"疑似可用，需实测复核" |
| **一律按开工日判缺料** | 后序工序的缺料也算成阻碍开工，产生伪缺口，为伪缺口付紧急采购溢价 | 双口径并列，按工艺路线算工序需料日，识别伪缺口 |
| **分批投产没落地** | 方案给了但PMC 没把到料节点挂到工序看板，现场仍自行推迟开工 | 分批投产方案必须带"PMC 挂工序看板"这条动作，否则不算可行 |
| **分批投产只讲好处** | 不提在制品占用增加的风险 | 强制输出代价与风险；且要求供应商书面二次确认 |
| **忽略 MOQ** | 只需 12 kg 却必须买 200 kg，溢价与余料没被算进代价 | 紧急采购路径强制核 MOQ、溢价幅度、是否超采购授权 |
| **可用库存分配顺序错** | 按工单号自动分配，缺口落在无替代路径的工单上，变成死结 | 分配顺序重排：无替代路径的工单优先 |
| **黄色写得模糊** | "有风险""需关注"，没人知道该做什么，黄色烂成红色 | 黄色必须写清"谁 / 何时 / 做什么 / 做完算什么标准" |
| **红色等于放弃** | 一张红色工单被理解成整单交付失守 | 红色必须给出升级后的方案与实际交付影响（如 112 台按期 + 8 台顺延） |
| **拆单只在纸面** | 拆单决议有了，排产没出、客户没报备 | 拆单路径的前置条件强制含"PMC 出排产"+"销售向客户报备" |
| **做无用跟催** | 在途单有明确不可提前理由（轧制排产已定），仍反复催 | 判定依据里记录不可提前理由，直接排除"跟催提前"这条路 |
| **口径不一致就吵架** | Agent 数字和 ERP 不一样，双方互相不信 | 先假设 MRP 对，核完口径仍不一致则输出口径差异说明，不覆盖 MRP 结果 |
| **缺口收敛不闭合** | 各路径吃掉的量加起来对不上原始缺口 | 强制输出收敛链条并验算，剩余不为 0 必须说明 |
| **忘了算呆滞消化金额** | 只讲解了缺口，没讲同时消化了多少呆滞库存 | 呆滞料路径强制输出消化金额（数量 × 单价） |

### 追问剧本

**Q1**：M-PCB-001 库里不是有 320 片吗，怎么还缺 60 片？
→ 320 是总库存。扣掉安全库存 80（3 天用量，断供缓冲不参与齐套）、已分配 100（WO-2026-0798 在制已锁定）、待检 20（S-010 立讯 07-28 到货批，IQC 未放行），可用只有 120 片。需求 180，净缺口 60。这三项里待检不能动，安全库存动要采购经理审批，已分配动要先确认被挪工单的影响 —— 三种情况的应对完全不同，所以输出里必须逐项列出，不能只给一个"缺 60"。

**Q2**：M-PCB-002 库里有 75 片，直接替不就行了？
→ 要分客户看，同一个替代关系两个相反结论。华东电气那张单（WO-2026-0802）四道全过，可以替 60 片，成本 +2.40 元/片。某主机厂那张单（WO-2026-0801，零件号 HX-2041）技术等效性通过 —— Pin-to-Pin 兼容，1000h 高温老化和 EMC 复测都做过 —— 但客户认可这道过不了：PPAP 的 PSW 已经锁定料号 M-PCB-001，切换要重走 PPAP Level 3 含 PSW 重签，周期 4~6 周。所以可用的 120 片要优先给某主机厂那张单，剩下的缺口才让华东电气走替代。如果分配顺序颠倒，缺口落在没有替代路径的工单上，就是死结。

**Q3**：库里有没有什么料能顶一下 M-SPCC-20 这532 公斤缺口？
→ 有一批 M-SPCC-18（1.8mm 冷轧板，批号 RM-SPCC-2512-08，460 kg，呆滞 8 个月，账面 2829 元）。规格和需要的 2.0mm 不一样，但备注里实测厚度 1.78 / 1.81 / 1.83mm，而 P-BRK-03 的图纸 DWG-BRK-03 RevB 板材厚度公差是 1.8~2.2mm —— 1.8mm 落在公差区间内。所以 WO-2026-0804（华东电气 P-BRK-03 200 台，需 320 kg）可以用这批料，既解 320 kg 缺口又消化呆滞库存 1968 元。但同一批料在 P-CAB-02（公差 1.95~2.05）和 P-IPC-01（公差 1.90~2.10）上技术就否决了；在 P-BRK-03 上给某主机厂（WO-2026-0806）也不行—— 原材料 2.0mm 已随 PPAP 提交获PSW 批准，厚度变更属材料变更点，须客户书面偏差申请。另外实测最小值 1.78mm 低于公差下限 1.80mm，必须逐张复测挑选，不能整批放行。

**Q4**：喷粉粉末和 USB-C 接口要 8/10 才到，是不是这几张单都得等？
→ 不用等。M-SPCC-20 挂在 OP10 下料，是首序投料，缺了整单开不了工；但 M-PWD-01 挂在 OP40 表面处理、M-PCB-001 / M-CAB-001 / M-USBC-01 挂在 OP50 装配。WO-2026-0801 从 08-06 开工算，OP40 需料日是 08-10、OP50 是 08-11，在途的 08-10 到货是赶得上的。所以 08-06 可以按原计划开工，先做 OP10 下料 → OP20 折弯 → OP30 焊接，粉末到货接OP40，电子件到货接 OP50。这两项在 MRP 里报的缺（20 pcs / 88.4 kg）是伪缺口 —— MRP 按开工日判在途可及，口径偏保守。**但 MRP 不是算错了**，它只做确定性计算，工序级需料时点要结合工艺路线补上。落地还差一步：PMC 要把两笔到料节点挂到工序看板，否则现场仍按"开工日缺料"理解，自行推迟开工。

**Q5**：明天到底哪几张能开、哪几张不能开？
→ 绿 2 张 180 台（WO-2026-0801 / 0803，无缺口按计划开工）；黄 3 张 330 台（0802 走替代料需08-06 前签首件、0804 走呆滞料需 08-07 前出公差确认、0805 走紧急采购需 08-06 前批 320 元溢价）；红 1 张 120 台（0806，呆滞料被 PPAP 否决、在途 08-17 才到且轧制排产 08-13 无法提前、现货扣掉 0805 用量后仍差 12 kg，走拆单：112 台 08-11 正常投产，8 台等 08-17 到料后投、08-18 完工、08-19 交货仍在客户交货日内）。验算：2+3+1 = 6 张，180+330+120 = 630 台。红色不等于做不出来 —— 它的含义是"原计划无法完整执行、需升级决策"，实际是 112 台按期 + 8 台顺延。

**Q6**：为什么你算的缺口和我 ERP 里的不一样？
→ 大概率是在途可及量的口径不同。ERP MRP 按工单计划开工日判在途是否可及，我们同时给出按工艺路线工序需料日判的结果，两个口径都摊在表里。差额就是伪缺口 —— 后序工序才需要的物料，在途到货早于该工序需料日，MRP 按开工日判会把它算成缺料。这不是 MRP 算错，是它的口径不含工序维度。如果口径核对完数字仍然不一致，我们会输出口径差异说明列出双方算法，不会直接用我们的数字覆盖 ERP 的结果。

**Q7**：这套东西是要替掉我们的 MRP 吗？
→ 不是。需求展开、库存扣减、净缺口、建议采购量这些确定性计算 MRP 做得又快又准，我们不重算也不推翻。我们补的是 MRP 做不到的两层：一是工序级需料日口径，二是对真缺口逐条评估化解路径 —— 替代料能不能用要看 PPAP，呆滞料能不能顶要看图纸公差和实测值，分批投产要看工艺路线断点，这些信息都不在 ERP 的确定性计算范围内。最终拍板仍然是采购和采购经理。

**Q8**：动作清单里哪几条是必须升级的？
→ 3 条。序9 紧急采购溢价 320 元需采购经理审批（超采购授权）；序 12 WO-2026-0806 拆单方案需采购经理拍板（涉及排产与交付方式变更）；序 14 向某主机厂报备分批交货需管理层（客户交付方式变更，未报备会被计入交付异常影响供应商绩效）。其余 13 条在采购、工艺、IQC、PMC、仓库的常规授权范围内。

## 7. Skill 组合

| 组合 Skill | 何时组合 | 效果 |
|---|---|---|
| **来料跟催** | 缺口靠跟催在途单化解，或供应商承诺日反复变更时 | 把"跟催 PO-2026-0726拿发运凭证"这类动作转成带升级规则的跟催台账，承诺日变更自动回流重跑齐套 |
| **交付可行性分析 / 排产** | 三色结论出来后要落到排产，或需要拆单排产时 | 把"0806-A 112 台 08-11 投产 + 0806-B 8 台 08-17 投产"排进产能，验证工时能否排下 |
| **ECN 工程变更管理** | 替代料要长期化，或呆滞料使用需要固化为正式替代关系时 | 把临时替代转成正式变更单走 6 步法审批，避免"临时替代用成常态却没走流程" |
| **品质异常分析·根因追溯** | 替代料或呆滞料投产后出现不良时 | 从批号追回是否用了替代料/ 呆滞料批次，判断是否为材料变更导致 |
| **对账差异核对** | 紧急采购溢价、替代料价差需要与财务对账时 | 核对溢价、价差是否与审批单一致 |
| **企微等IM分部门通知** | 动作清单要推到各责任人时 | 按责任人拆分待办（采购小林 6 条 / 工艺王工 3 条 / IQC 2 条 / PMC 老周 2 条 / 仓库 1 条 / 采购经理 1 条 / 销售 1 条），@到人带时限 |
