# 本地文件工具

技能内 `scripts/scenario_io.py` 的路径相对技能目录，不是当前工作目录。使用 RULE.md 记录的 Python 解释器和脚本绝对路径。所有新文件放进当前会话或智能体工作区内独立运行目录。

`prepare --output <新目录>` 仅复制内置演示资料并写出场景任务。
`inspect <输入文件> --output <证据.json>` 保留 Excel 坐标、合并区域、公式与缓存，以及 Word 表格、PDF 页码、文本行号。大文件提取结果落盘后按 Sheet/范围读取；不要仅凭截断的控制台输出分析整张表。

`render <report.json> --output <输出目录>` 把已完成的业务分析写成真正的报告。不要把下面的结构示例当成场景数据。调用前根据原始输入用 Python 完成计算，再组装 JSON；没有来源的行不生成结论。

```json
{
  "title": "本次分析标题",
  "basis": "演示或真实业务；分析期间；原始输入清单与口径",
  "files": [{
    "filename": "分析结果.xlsx",
    "sheets": [{
      "name": "明细",
      "columns": ["单据", "数量", "单价", "金额", "来源"],
      "rows": [["示例编号", 2, 3, {"formula": "=B4*C4", "value": 6}, "输入.xlsx/明细!A2:C2"]]
    }]
  }]
}
```

每份文件可覆盖 `title`、`basis`。工作表第 1 行标题，第 2 行依据，第 3 行列名，第 4 行起明细，所以公式要从正确坐标引用。公式字典必须提供独立计算的数值缓存，普通以 `=` 开头的输入文本不会被执行成公式。默认冻结表头、自动筛选、换行、横向打印。复杂列宽、图表、签批布局、分页及指定页数要求由自定义脚本精调。

Word/PDF 文件条目使用 `filename` 和非空 `paragraphs` 字符串数组；文本/Markdown 文件使用 `filename` 和 `text`。PDF 支持中文，复杂表格和严格页数的交付请直接使用 ReportLab。Word 可直接使用 python-docx。Excel 可直接使用 XlsxWriter/openpyxl。脚本不会替你填写判断、计算或签字。

`check <报告文件...>` 检查可读取、空表及常见公式错误，返回 SHA-256。`business_validated: false` 表示文件结构检查无法证明业务正确。公式无缓存、扫描 PDF 等提示必须继续处理。交付前另外检查业务合计、来源覆盖、缺口、法律口径有效期和版面，不能把此命令成功当作业务验收通过。
