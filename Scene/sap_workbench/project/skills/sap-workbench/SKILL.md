# SAP 智能工作台

本技能描述工作台会话能做什么、不能做什么，以及必须遵守的操作纪律。能力边界是硬约束，不是建议。

## 能力边界（不可协商）

| 需求 | 状态 | 正确做法 |
|---|---|---|
| 在左侧画面打开事务码 | **有限可用** | 调用 `sap_transaction_open` |
| 读取 SAP 业务数据 | **可用** | 调用 `sap_data_call`（`read_table` / `run_query`） |
| 写入 SAP 业务数据（经 BAPI） | **可用，且会改变数据** | 调用 `sap_data_call`（`call_rfc`） |
| 读取左侧页面内容（字段、表格、标签、消息） | **不可用** | 不要尝试，也不要根据臆测回答 |
| 在左侧页面填写字段 / 执行 / 保存单据 | **不可用** | 不要尝试，也不要用其他浏览器代替 |

左侧 SAP 画面是从 SAP 源站载入的**跨域 iframe**。没有任何可用工具能读到它的 DOM，因此：

- **绝不允许**根据"看过左侧页面"来回答字段值、表内容、标签页、系统消息或单据状态；
- **绝不允许**把截图或页面观察当作业务依据；
- `sap_transaction_open` **只确认导航指令已送达**左侧画面，**不代表** SAP 已登录、用户有权限、事务标题正确或单据状态如何。回报时必须如实说明"已把导航发送到左侧页面"，不得声称检查过它。

## 凭据纪律

SAP 连接、账号与口令**保存在服务端场景配置里，由工作台在服务端使用**。

- **绝不得**在对话中向用户索要 SAP 密码、主机名或客户端号；
- **绝不得**把它们写入文件、命令或工具参数；
- `sap_data_call` 的参数面**只接受业务参数**：不接受 `connection_id`、`user`、`password`、`client`、`host`、`url` 等任何连接或身份字段——连接由服务端按会话归属解析，模型既拿不到凭据也拿不到连接标识。

## 打开事务码

用户明确要求打开事务码时（例如"打开 me21n"、"打开 ME23N"、"打开 SPRO"）：

1. 只传事务码本身，不要附加 URL、主机或客户端；
2. 使用 `sap_transaction_open`——它是**当前工作台**的导航工具；
3. 通用 playwright / 浏览器工具操作的是**另一个浏览器**，在那里打开页面**不会**改变用户左侧的 SAP 画面。即使用户在前面的对话里用过这类工具，也**不得**用它替代 `sap_transaction_open`；
4. 工具失败时如实报告失败，**不要**改用其他浏览器"绕过"。

事务码写法与常见清单见 `references/transactions.md`。

## 读写 SAP 业务数据

要用数据回答问题时，调用 `sap_data_call`，不要去读页面。可达工具只有三个：

| tool | arguments | 用途 |
|---|---|---|
| `read_table` | `{table_name, fields?, where?, row_count, row_skip?}` | 按条件读一张表的若干列 |
| `run_query` | `{sql_query, row_count}` | 单条只读 `SELECT` |
| `call_rfc` | `{function_name, parameters_json?}` | 调用 RFC / BAPI，**可能改变业务数据** |

- 先读后写：能用 `read_table` / `run_query` 回答的，不要用 `call_rfc`；
- `call_rfc` 会真实改变 SAP 数据。只在用户明确要求该业务动作时调用，并且**先**用读取确认对象与影响范围；
- 参数里不要出现表名以外的连接信息；`where` 与 `sql_query` 里不要写多条语句或注释。

**返回值的性质**：`sap_data_call` 返回的是 MCP 传输结果，**不是**业务结论。

- 读到记录 ≠ 单据已成立、已审批、已过账、未关闭；
- `call_rfc` 的传输成功 ≠ SAP 已完成该业务动作。RFC 返回里通常需要检查 `RETURN`/`BAPIRET2` 之类的消息结构才能判断成功，**在检查之前不得声称"已创建""已过账""已审批"**；
- 无法判断时就说无法判断，并说明缺的是哪一步的验证。

工具缺失或失败时，明确说明缺失或失败，**不要**改用读页面、截图或换浏览器来凑答案。

## 禁止动作

- 不伪造业务结论（"已创建成功"、"已过账"、"已审批"）——除非返回值里有可核对的成功凭据，否则这类结论没有依据；
- 不做用户没有要求的写入：`call_rfc` 的参数不得由你凭空补全（如自动生成单据号、供应商或数量）；
- 不索取、不推断、不转述 SAP 凭据，也不在参数里补连接或身份字段；
- 不把页面观察当作事实来源；
- 不在失败后改用其他浏览器或工具链重复同一个意图并宣称成功；
- 不在一次调用里连带执行多个业务动作（例如"顺便再建一张"）。

## 其他工具

同一会话中的其他 OpenCode 工具、模型、智能体、MCP 连接与项目配置**照常可用**，用于它们原本的用途（写代码、查资料、处理文件等）。本技能只约束 SAP 工作台相关的操作。能力边界的详细依据见 `references/boundaries.md`。
