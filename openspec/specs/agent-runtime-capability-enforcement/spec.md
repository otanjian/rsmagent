# agent-runtime-capability-enforcement Specification

## Purpose
定义会话构建与工具调用路径上对智能体能力绑定的运行时真裁剪，确保白名单/黑名单与知识、技能、SOP 绑定在执行层生效，而非仅停留在配置存储。
## Requirements
### Requirement: 工具白名单与黑名单硬过滤
当智能体配置了非空工具白名单时，系统 MUST 仅向该次运行暴露白名单内且未被黑名单排除的已注册工具。当白名单为空或缺省时，系统 SHALL 暴露默认可用工具集，但仍 MUST 排除该智能体（及继承场景后合并）黑名单中的工具。过滤 MUST 在工具注册/枚举与调用入口同时生效，客户端伪造工具名不得绕过。

#### Scenario: 白名单裁剪
- **WHEN** 智能体工具白名单为 `web_search,read`，黑名单为空，用户发起对话
- **THEN** 模型可见与可调用的工具集合不包含白名单外的工具（如 `bash` 若未列入）

#### Scenario: 黑名单排除
- **WHEN** 智能体未设白名单但黑名单含 `bash`
- **THEN** `bash` 不出现在工具列表，且直接调用被拒绝

#### Scenario: 伪造调用被拒
- **WHEN** 客户端或模型输出请求调用不在有效集合内的工具
- **THEN** 系统拒绝执行并返回错误，不产生副作用

### Requirement: 员工上下文注入
系统 SHALL 在归属该智能体的会话构建系统提示时注入有效员工上下文，至少包括：核心人设文件内容（既有）、非空的人设摘要与问候策略说明，以及场景继承后的有效场景提示（若绑定场景）。注入 MUST NOT 破坏既有系统提示构建顺序的兼容约定（场景/员工附加段可置于既有 `extra_system_suffix` 或等价扩展点）。

#### Scenario: 带人设摘要的对话
- **WHEN** 智能体配置了 `persona_summary` 且用户在该智能体会话发消息
- **THEN** 构建的系统提示包含该人设摘要语义

#### Scenario: 场景与员工同时生效
- **WHEN** 智能体绑定场景且场景有 `system_prompt`，员工另有非空人设摘要
- **THEN** 两者均按继承/覆盖规则进入有效提示，员工非空字段不被场景覆盖

### Requirement: 技能与知识绑定在运行时生效
系统 SHALL 按智能体技能绑定限制技能提示词装配与技能相关能力发现；SHALL 按知识条目绑定限制知识检索范围（在 shared/own 与授权之后）。SOP 标识 Phase 1 SHALL 至少进入可观察的员工上下文或能力清单，完整 SOP 状态机执行不作为本 requirement 的强制范围。

#### Scenario: 技能子集
- **WHEN** 智能体仅绑定技能 `xlsx`
- **THEN** 技能提示装配不包含未绑定且非隐含必需的其他已安装技能

#### Scenario: 知识条目限制
- **WHEN** 智能体绑定了特定知识条目 ID 集合
- **THEN** 该会话知识检索结果不包含集合外条目（授权内）

### Requirement: 缺省兼容

未配置任何新裁剪字段的智能体 SHALL 在工具、技能与知识行为上与改造前兼容，以便平滑迁移。存量受管连接尚未配置分配时 SHALL 沿用原授权，页面明确显示该状态；首次保存分配后仅该连接增加分配限制，工具白名单为空不能豁免。新建连接或平台模板首次新增租户消费关系 SHALL 默认已配置且空分配。个人邮箱、内置工具、本地知识与未迁移旧 MCP 路径的原有规则保持，不因本 change 增加新的分配限制。

#### Scenario: 旧智能体无新字段
- **WHEN** 仅有改造前配置的智能体处理消息，使用尚未配置分配的存量连接
- **THEN** 原工具与技能可用性保持，已有授权与隔离要求仍生效

#### Scenario: 一个连接首次配置
- **WHEN** 用户为一个存量连接首次保存分配
- **THEN** 仅该连接开始按分配限制，不要求其他连接或整个租户同时切换

#### Scenario: 个人邮箱继续按原资格使用
- **WHEN** 用户在满足原有 owner、智能体范围及执行条件时使用本人邮箱
- **THEN** 本 change 不新增必须绑定私有智能体等条件，也不增加邮箱分配入口

### Requirement: 已配置连接的分配在展示与派发生效

对本期受管租户 MCP/ERP/OA 和租户继承平台 MCP，系统 SHALL 先确认当前消费租户的连接分配状态。已配置连接仅向已分配智能体展示可调用工具，实际派发前 MUST 重验分配；未配置存量连接沿用原授权。有效集合 SHALL 与原用户权限、租户开放范围、连接状态及智能体/场景工具范围取交集，保留风险、隔离、审批和配额。已配置空分配、状态缺失或查询失败 MUST 拒绝，不能回落旧文件或其他连接。

#### Scenario: 白名单允许但未分配
- **WHEN** 已配置连接未分配给当前智能体，即使工具白名单和当前用户权限允许
- **THEN** 不向该智能体展示可调用工具，伪造直接调用也被拒绝

#### Scenario: 已分配但原条件不满足
- **WHEN** 连接已分配，但目标工具被黑名单排除、调用者缺少 `tool.execute` 功能权限或执行切片未开放
- **THEN** 保持原拒绝，不因分配成功而开放工具或 MCP 业务调用

#### Scenario: 分配是该连接的授权
- **WHEN** 连接已配置分配且当前智能体在关系内，而调用者没有该动作的逐资源授权
- **THEN** 该连接的读动作照常可见与可派发，分配替代逐资源授权而不叠加要求

#### Scenario: 移除后继续旧会话
- **WHEN** 分配已成功移除，而旧会话、重连或排队任务仍持有工具描述
- **THEN** 后续装配和派发按当前分配拒绝，不延续旧缓存资格

#### Scenario: 状态丢失或查询失败
- **WHEN** 调用前应有分配状态缺失或查询异常
- **THEN** 拒绝且可诊断，不把异常当成合法未配置状态

### Requirement: 分配使用受信运行上下文

智能体外部调用 SHALL 使用受信上下文中的租户、调用主体及当前 Agent，模型参数或客户端字段 MUST NOT 替换该身份，缺失上下文时拒绝。现有 Web、通道、委派与调度共同派发路径 SHALL 遵守同一规则；独立连接配置/测试及真实非 Agent 消费者保持原边界，不伪造 Agent 分配。

#### Scenario: 冒用另一个智能体或丢失身份
- **WHEN** 未获分配的智能体在参数中指定另一个已分配 Agent，或后台调用丢失当前身份
- **THEN** 不能借用参数或降级为独立连接调用获得使用权

#### Scenario: 独立测试连接
- **WHEN** 合法操作者通过管理入口进行获准的受限连接测试
- **THEN** 按现有测试规则处理，不要求虚构分配，不执行业务工具
