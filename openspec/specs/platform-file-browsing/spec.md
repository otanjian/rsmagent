# platform-file-browsing Specification

## Purpose
定义文件服务在唯一 database 身份模式下的作用域：平台级只读文件根仅平台管理员可浏览、租户成员限本租户共享根与授权 Agent workspace，且不再以操作员主目录或全盘作为默认根。
## Requirements
### Requirement: 平台级只读文件根仅平台管理员可浏览

系统 SHALL 提供平台级文件根用于平台管理员只读浏览，默认 MUST 为部署数据目录，MUST NOT 默认使用操作员主目录或文件系统根。平台级文件根入口 SHALL 仅允许平台管理员，MUST NOT 允许写入、上传、删除或重命名，并 SHALL 记录可归属审计。配置指定文件系统根时必须显式声明，系统不得以未声明的高风险根作为默认。

平台入口资格 SHALL 只允许读取其中本来就获准的平台文件，MUST NOT 绕过子路径实际归属。根内成员私有配置、记忆、会话、知识、租户共享 Agent 的 user/<user_id> 文件和凭证仍按本人边界及凭据规则保护；非 owner 的平台管理员不得经目录枚举、搜索、绝对路径、下载或预览取得这些内容。

#### Scenario: 平台管理员只读浏览
- **WHEN** 平台管理员请求浏览平台级文件根
- **THEN** 系统返回该根内允许的文件内容且拒绝任何写入操作

#### Scenario: 普通成员访问平台级文件根
- **WHEN** 非平台管理员请求平台级文件根
- **THEN** 系统返回 403，不返回平台级路径或目录结构

#### Scenario: 平台根包含成员私有工作区

- **WHEN** 非 owner 的平台管理员从平台文件根请求成员私有目录或正文
- **THEN** 目录与读取结果按实际归属过滤或拒绝，不因父目录可浏览返回成员私有内容

#### Scenario: 平台父目录包含共享 Agent 的用户文件
- **WHEN** 非 owner 平台管理员经平台文件根访问共享 Agent 的 user/A
- **THEN** 在目录和内容返回前执行 owner 校验，不因平台入口资格放行

### Requirement: 租户与 Agent 工作区文件服务按作用域隔离

租户成员的文件服务访问 SHALL 限于当前有效租户的共享根与获授权 Agent workspace，并对其中 user/<user_id> 子树追加本人归属校验；缺少有效租户上下文返回 403，其他租户对象按不可见拒绝。系统 MUST NOT 因客户端自报路径、租户头、Agent 标识或目录包含关系扩大范围，MUST NOT 沿用单租户 instance-root 的全局可见语义。

浏览器原生发起、无法携带租户头但仍具有有效认证会话的文件读取（下载导航与子资源）SHALL 在被显式登记为「租户由被寻址资源派生」后，由服务端从被寻址资源解析租户，并仍校验调用者对该租户的有效成员资格；调用方自报的路径、租户头或 Agent 标识 MUST NOT 成为授权来源，只可用于冲突检测。

公共文件的能力令牌预览（`GET /preview/<token>/<name>`）SHALL 以不可伪造的签名令牌限定可寻址范围；其纵深根校验的允许根 SHALL 覆盖全部租户共享根与全部绑定 Agent 的 workspace（来源为服务端静态登记，不依赖请求身份），以便解析不到请求身份的公开预览仍能读取合法工作区文件；这些工作区之外的路径（含操作员主目录）MUST 仍被拒绝。该根校验 MUST NOT 通过构造「身份缺失」错误来实现，以免残留的状态或响应头污染成功响应。私有资源（包括共享 Agent 的 user/<user_id>）的预览、下载与关联子资源 SHALL 在**消费时**验证当前有效身份、租户和 owner；旧链接不能充当绕过新本人边界的持有者授权，不满足新条件的旧私有令牌必须失效。

控制台工作区面板的文件接口（`GET /api/workspace/tree|search|resolve|meta|read` 与 `POST /api/workspace/write`）SHALL 以调用者的有效租户为作用域并保持可用，MUST NOT 因身份模式本身返回整体不可用。其相对路径读取与写入 SHALL 限定于调用者的租户共享根、已绑定且获授权 Agent 的 workspace，或调用者私有项目目录。绝对路径的解析、读取与写入 SHALL 按**调用者租户作用域**授权（仅平台管理员可越出至平台根），MUST NOT 复用「覆盖全部租户与全部 Agent 工作区」的静态根列表作为授权依据。系统资产（`MEMORY.md`、`knowledge/` 等）的回落解析 SHALL 同样限定在调用者租户内，MUST NOT 回落到全局默认 Agent 的工作区。工作区写入 SHALL 在工作区边界校验之外经过统一管理写来源校验。

租户包含关系 MUST NOT 单独构成绝对路径或被寻址资源的授权依据：系统 SHALL 解析该资源**所属 Agent**，并对其执行与请求显式声明的 Agent 参数**相同**的私有/共享归属校验（仅该资源所属 Agent 的属主本人放行；管理员资格不形成私有读取旁路）；共享根与共享 Agent 的非私人资源按原共享语义处理；命中 user/<user_id> 时，SHALL 在任何共享或平台根放行之前验证当前用户与目录 owner 一致，MUST NOT 以 Agent 共享属性忽略该子目录。该归属校验 SHALL 覆盖以绝对路径、相对路径（含租户共享根之下的目录嵌套）与服务端签发 URL 寻址的文件读写，MUST NOT 因「路径落在调用者租户共享根内」而跳过。目录列举（`tree`）与文本搜索（`search`）SHALL 同样按归属过滤，MUST NOT 返回无权读取的私有 Agent 或其他用户子目录的名称及路径存在性；从 Agent/租户/平台父目录进行递归搜索、计数或既有打包操作时 SHALL 在遍历前排除无权子树。归属 MUST 取**最具体**（最长）的命中根；当路径同时落在两个不同 Agent 的 workspace 之下、或归属无法解析时，系统 MUST 失败关闭并按不可见拒绝，MUST NOT 任选其一放行。请求自报的 `agent_id` MUST NOT 作为授权来源，只可用于与解析归属的冲突检测。

#### Scenario: 同租户成员访问本租户文件
- **WHEN** 有效租户成员请求本租户共享根或获授权 Agent workspace 内的文件
- **THEN** 系统在租户及原权限范围内返回文件内容；命中 user/<user_id> 时还需本人归属一致

#### Scenario: 跨租户或缺少租户上下文
- **WHEN** 请求指向其他租户的文件路径，或调用方没有有效租户上下文
- **THEN** 系统按不可见拒绝（404 或 403），MUST NOT 返回该文件内容或路径存在性

#### Scenario: 自报共享 Agent 实际请求他人私有文件

- **WHEN** 用户提交共享 Agent 标识，但相对或绝对路径实际定位到他人私有工作区
- **THEN** 按实际资源 owner 拒绝，不返回正文或路径存在性

#### Scenario: 非 owner 持有旧私有预览链接

- **WHEN** 非 owner 使用曾签发的私有预览或下载链接
- **THEN** 消费时拒绝，不以旧令牌、管理员身份或 URL 缺少 Agent 参数绕过本人边界

#### Scenario: 浏览器原生下载本租户工件

- **WHEN** 已登录且获权的成员以无法携带租户头的下载导航请求本租户 Agent 生成的文件
- **THEN** 系统由文件所属工作区派生租户并校验成员资格及用户子目录归属后返回内容，不因「未选择租户」拒绝

#### Scenario: 能力令牌预览合法工作区文件

- **WHEN** 持有服务端签发的合法预览令牌、但无法提供会话凭据的请求读取租户或 Agent 工作区内原本允许公开预览的非私人文件
- **THEN** 系统返回该公开范围内文件，仍拒绝工作区之外及 user/<user_id> 等私人路径

#### Scenario: 成员浏览本租户工作区面板

- **WHEN** 已登录且获权的租户成员打开控制台工作区面板，请求本租户工作区目录树、文件元数据或正文
- **THEN** 请求返回成功且根为本租户共享根、绑定 Agent workspace 或调用者私有项目目录，不因身份模式返回整体不可用；展开 user 时只返回本人子目录

#### Scenario: 以绝对路径解析他租户文件

- **WHEN** A 租户成员以绝对路径请求解析、读取或写入属于 B 租户工作区（或平台根，且调用者非平台管理员）的文件
- **THEN** 系统按不可见拒绝，响应不含文件元数据、`preview_url` 或文件内容

#### Scenario: 系统资产回落不越出租户

- **WHEN** 非默认租户成员以相对路径请求 `MEMORY.md` 或 `knowledge/...` 等系统资产
- **THEN** 系统在调用者租户作用域内解析该资产，MUST NOT 读取全局默认 Agent 的工作区

#### Scenario: 同租户成员以绝对路径请求他人私有 Agent 文件

- **WHEN** 普通成员（非该 Agent 属主）以绝对路径（或携带不带 `agent_id` 的服务端签发 URL）请求解析、读取或下载同租户内他人**私有** Agent workspace 中的文件，即使请求同时声明了一个共享 Agent
- **THEN** 系统按不可见拒绝（403 或 404），响应 MUST NOT 含文件内容、文件元数据、`preview_url` 或 `raw_url`

#### Scenario: 同租户成员以相对路径或目录嵌套请求他人私有 Agent 文件

- **WHEN** 普通成员（非该 Agent 属主）以相对路径请求同租户内他人私有 Agent workspace 中的文件，包括该 workspace 恰位于调用者租户共享根之下（`agents/<private-agent>/…`）的情形
- **THEN** 系统按不可见拒绝，MUST NOT 返回文件内容或路径存在性

#### Scenario: 目录列举与搜索不暴露他人私有 Agent

- **WHEN** 普通成员（非该 Agent 属主）列举本租户共享根下的目录，或执行文本搜索
- **THEN** 结果 MUST NOT 含他人私有 Agent 的目录名或路径

#### Scenario: 私有 Agent 的属主与租户管理员

- **WHEN** 私有 Agent 的属主本人，或同租户的 `tenant_admin`，请求该私有 Agent workspace 中的文件
- **THEN** 属主本人返回文件内容；`tenant_admin` 不因管理资格取得文件内容，仅在治理接口获得归属与用量等脱敏元数据

#### Scenario: 共享资源不受属主判定影响

- **WHEN** 本租户成员请求租户共享根内文件，或请求本租户共享 Agent workspace 内原本获权且不属于 user/<user_id> 等私人范围的文件
- **THEN** 系统返回文件内容，不引入额外属主门槛

#### Scenario: 归属无法唯一确定

- **WHEN** 被请求的路径同时落在同租户两个不同 Agent 的 workspace 之下（互相同构或嵌套的配置退化）
- **THEN** 系统失败关闭并按不可见拒绝，MUST NOT 任选其一放行

#### Scenario: 共享 Agent 用户目录接口与缓存
- **WHEN** A 通过 tree/search/resolve/meta/read、下载或预览请求本人文件，B 用相同链接请求该文件
- **THEN** A 在满足原有权限时成功，B 被拒绝；私人响应 private/no-store，不向 B 返回元数据或链接

#### Scenario: 现有写入操作校验目标归属
- **WHEN** A 调用既有写入、删除或移动接口操作 user/B 或改名 owner 根
- **THEN** 后端拒绝且无文件副作用，不能仅在前端隐藏该操作

#### Scenario: 静态路径与关联资源不能绕行
- **WHEN** B 或匿名访问者绕过主页面请求用户子目录的静态 URL 或预览图片等子资源
- **THEN** 静态访问被关闭或执行相同本人校验，主文件授权不替代每个子资源授权

### Requirement: 工作区面板默认锚定当前 Agent 自己的目录并在无权时回落到本人私有 Agent

控制台对话页右侧工作区面板的顶栏入口 SHALL 在打开时锚定当前会话的实际业务目录：已选有效项目时使用项目目录；无项目的共享普通 Agent 或私有普通 Agent 使用 `<agent workspace>/user/<本人不可变用户ID>/`。新建与存量对象使用同一规则，落点 SHALL 与既有服务端默认目录及文件来源一致，前端路径计算不构成授权，不要求新增布局协议。入口打开后 SHALL 位于「文件」页签并重新列举该目录，MUST NOT 因上次预览过文件而停在预览页签，MUST NOT 沿用上次浏览的子目录或上一次的回落作用域，MUST NOT 以残留条目冒充当前 Agent 的目录。

有效项目或不适用统一目录的既有入口按其实际工作区落点显示，MUST NOT 因不存在 `agents/<id>` 而报「不是目录」。普通 Agent 的本人目录尚未创建时 SHALL 经授权准备后列举，准备失败 MUST 明确报告，不得回落 Agent 根或租户根。用户自己浏览进入的路径不存在时 SHALL 照常报错。回到获权父目录的面包屑仍可用，导航不改变执行 cwd。

当该目录的列举以一个**权限判定拒绝**作答（服务端对该 Agent 的租户绑定、私有归属或会话归属拒绝，返回 403/404）时，前端 SHALL 回落到**调用者本人的私有 Agent 实际业务目录**（普通 Agent 为该 Agent 的 user/<本人ID>）：以调用者本人的私有 Agent 作为该面板的作用域，并以该业务目录继续列举，保持该作用域用于面板后续的预览、读取与写入，同时 SHALL 以既有提示机制告知已切换到本人智能体目录。回落后的重试 SHALL 按回落后的 Agent 重新取路径，MUST NOT 复用被拒 Agent 的目录；面板回落不改变聊天目标和执行 cwd。

回落 MUST NOT 放宽任何授权：作用域仍由服务端按实际资源归属判定，客户端自报的 Agent 标识 MUST NOT 成为授权依据。回落 SHALL 至多发生一次（一次落点最多探询一次本人的私有 Agent），MUST NOT 形成重试循环。调用者没有本人的私有 Agent，或本人私有 Agent 的目录同样被拒时，面板 SHALL 给出本地化的「没有权限打开该智能体的目录」提示，MUST NOT 把服务端的原始拒绝串（如 `agent not found`）当作结果呈现，MUST NOT 回落到他人目录，MUST NOT 以成功状态伪装。

面板锚定的 Agent 因切换 Agent、切换会话或重新打开入口而改变时，SHALL 丢弃上一次的回落作用域，按当前 Agent 重新判定并重新落到其实际业务目录。

#### Scenario: 打开入口即看到当前 Agent 自己的目录

- **WHEN** 用户在与某 Agent 的对话中点开顶栏工作区入口，且此前预览过另一个文件、浏览过某个子目录
- **THEN** 面板显示服务端投影的该会话业务目录，普通 Agent无项目时为本人子目录；位于「文件」页签，必要的目录准备后只对该落点发起一次列举请求

#### Scenario: 工作区根之下没有该 Agent 的目录

- **WHEN** 当前会话已打开项目目录，或不适用统一目录的单 Agent 入口下工作区根即 Agent 目录，因此根之下不存在 `agents/<agent id>`
- **THEN** 面板显示工作区根的条目，不显示「不是目录」之类的错误

#### Scenario: 用户浏览进入的路径不存在

- **WHEN** 用户点进一个已被删除的目录
- **THEN** 面板照常报告该路径不存在，MUST NOT 悄悄退回工作区根

#### Scenario: 无权浏览该 Agent 目录时回落到本人私有 Agent

- **WHEN** 当前会话对应 Agent 自己的目录被服务端以 403/404 拒绝（他人私有 Agent、跨租户、未绑定当前租户或非本人会话），且调用者拥有本人的私有 Agent
- **THEN** 面板改为列举调用者本人私有 Agent 的实际业务目录并保持该作用域，且提示已切换到本人智能体目录；聊天目标和执行 cwd 不改变

#### Scenario: 没有可供回落的目录时给出本地化提示

- **WHEN** 当前会话对应 Agent 自己的目录被拒绝，而调用者没有任何私有 Agent，或本人私有 Agent 的目录同样被拒
- **THEN** 面板显示本地化的「没有权限打开该智能体的目录」，不回落、不重复重试、不呈现服务端原始拒绝串

#### Scenario: 回落作用域不跨 Agent 与会话存活

- **WHEN** 用户在回落状态下切换到另一个 Agent 或另一个会话，随后再次打开面板
- **THEN** 面板按新的当前 Agent 重新判定并列举其实际业务目录，不沿用上一次的回落 Agent

#### Scenario: 本人目录首次打开与不安全容器
- **WHEN** 私有 Agent 的本人目录不存在，或 user 容器被替换为链接/文件
- **THEN** 前者经受控准备后显示本人目录；后者明确失败，不以打开根目录伪装成功

#### Scenario: 单 Agent 工作区就是实例根
- **WHEN** 普通 Agent 工作区就是实例根
- **THEN** 面板使用该根下 user/<本人ID>，不因为没有 agents/<id> 而落到实例根

### Requirement: 工作区面板支持把文件与文件夹拖拽上传到本人目录

控制台对话页右侧工作区面板的「文件」页签 SHALL 接受从操作系统拖入文件或文件夹作为上传入口。落点 SHALL 是面板**当前浏览目录**，且该目录 SHALL 位于**调用者本人的可写范围**之内：

- **租户共享**普通 Agent 与**私有**普通 Agent 的工作文件可写范围 SHALL 均为其工作区下的 `user/<调用者 user_id>` 子树；私有对象同时要求当前调用者为真实 owner；
- 项目和外部 coding 使用各自既有契约，不通过本规则扩大权限。文本编辑与配置维护保持既有鉴权，不因上传范围统一而重构。

`user_id` MUST 取自**已验证的请求身份**，MUST NOT 取自请求体。落点不属于本人可写范围时（例如共享或私有 Agent 的根、他人的 `user/<user_id>`、他 Agent 的目录），上传 SHALL 被服务端拒绝并给出可读原因，MUST NOT 落盘到任何其它目录，MUST NOT 静默丢弃或改为回落到某个「就近可写」目录。面板在落点不可写时 SHALL 在拖入前就以可见方式表明该目录不可写入，MUST NOT 让用户只有在拖完才知道会被拒。

拖入文件夹时，所含文件 SHALL 落在落点之下与其源相对路径一致的位置；不含文件的空目录不要求保留。

拖入面板 MUST NOT 触发聊天附件上传：一次拖拽 SHALL 只产生一次上传意图，聊天输入区的待发送附件列表 MUST NOT 因此新增条目。面板自身的拖拽产物（`application/x-cow-workspace-file`）与从操作系统拖入的文件 SHALL 按拖拽负载类型区分，互不触发对方路径。

目录遍历 SHALL 完整：目录读取接口按批返回时，客户端 SHALL 持续读取到返回空为止，MUST NOT 只上传首批条目而对外表现为成功。运行环境不支持目录拖入时，客户端 SHALL 给出本地化提示并指出可用的替代入口，MUST NOT 静默只上传顶层文件或以成功状态伪装。

搜索态下拖入时，落点 SHALL 仍为当前浏览目录本身，MUST NOT 取某条搜索结果的父目录或搜索结果集合作为落点。

#### Scenario: 拖入一个含多级子目录的文件夹

- **WHEN** 用户把 `支持性文档/`（含 `2024/合同/a.xlsx`）拖入面板，且面板停在本人可写范围内的某目录
- **THEN** `a.xlsx` 落在该目录下的 `支持性文档/2024/合同/`，层级与源一致

#### Scenario: 拖入多个文件夹与散落文件

- **THEN** 三者都落在当前浏览目录之下，散落文件直接在落点根，两个文件夹各自保持自己的层级，互不混淆

#### Scenario: 共享 Agent 的共享根不是可写落点

- **WHEN** 租户共享 Agent 的面板停在共享根（`agents/<agent id>`），用户把文件拖入
- **THEN** 上传被拒绝并给出可读原因，共享根与其下任何目录都不新增文件，面板不把落点改到 `user/<本人 user_id>` 而假装成功

#### Scenario: 他人用户的子树不是可写落点

- **WHEN** 用户把文件拖入 `user/<他人 user_id>` 或指向该子树的任意层级
- **THEN** 上传被拒绝，该子树内不新增任何文件，响应不透露该目录的存在性

#### Scenario: 拖入面板不产生聊天附件

- **WHEN** 用户把文件拖入面板的文件页签并松手
- **THEN** 文件写入落点目录，聊天输入区的待发送附件列表不新增条目，上传只走面板这一条路径

#### Scenario: 搜索态下拖入

- **WHEN** 面板处于搜索结果显示状态，用户拖入一个文件且当前浏览目录在可写范围内
- **THEN** 文件落在当前浏览目录（面包屑所示目录）而非任何搜索结果的目录

#### Scenario: 大目录的遍历不丢条目

- **WHEN** 拖入的文件夹含超过单次读取上限的条目（例如 5000 个文件）
- **THEN** 客户端持续读取至返回空，最终上传的文件数与源目录一致，MUST NOT 只上传首批条目

#### Scenario: 运行环境不支持目录拖入

- **WHEN** 运行环境不提供目录拖入能力，用户拖入一个文件夹
- **THEN** 客户端给出本地化提示并指出可用的替代入口，不静默只上传顶层文件，也不以成功状态伪装

#### Scenario: 私有 Agent 的根不接受工作文件上传
- **WHEN** owner 在私有 Agent 根拖入文件，或旧客户端直接提交该落点
- **THEN** 服务端明确拒绝且无文件副作用，客户端不把它静默改投本人目录；既有配置维护入口仍按独立权限提供

### Requirement: 工作区上传的落盘边界、归属与冲突处置

上传 SHALL 是经服务端授权的写操作，其作用域与归属规则 SHALL 与既有的文件读写**完全一致**（见「租户与 Agent 工作区文件服务按作用域隔离」）并**额外收窄到本人可写范围**（上一条要求）：本次 MUST NOT 新增或放宽任何一条既有规则。双重判定 SHALL 同时成立——既有的归属规则（不可见即不可写）与本人可写范围的判定缺一不可，MUST NOT 以「既有规则已放行」替代范围判定，也 MUST NOT 以范围判定替代归属判定。

每条相对路径 SHALL 在落盘前完成两道校验：拒绝 `..`、绝对路径、盘符与 NTFS 数据流等逃逸形态；再按**最终真实路径**校验仍位于目标目录之内。逐级解析 MUST NOT 跟随符号链接——中间目录被替换为符号链接、或校验与打开之间发生替换时 SHALL 拒绝而不是跟随，MUST NOT 以路径字符串前缀作为充分依据。写入 SHALL 为原子操作：单条失败 MUST NOT 留下半截文件，也 MUST NOT 让该条以成功计入结果。

同名冲突 SHALL 由服务端裁决并自动重命名（`name (1).ext` 递增），MUST NOT 覆盖既有文件，MUST NOT 静默跳过；被重命名的条目 SHALL 在响应中如实报告实际落盘名，使界面能显示真实结果。

重试 SHALL 只重传未成功项：客户端 SHALL 依据逐项结果重传失败项，MUST NOT 重传已报告成功的条目。系统 MUST NOT 承诺重复提交的去重——同一文件被再次提交时 SHALL 按同名冲突处理；服务端 MUST NOT 为跨请求的去重保留状态。无论是否重复提交，系统 MUST NOT 留下半截文件或半截目录。

#### Scenario: 目标目录在本人范围之外

- **WHEN** 调用者把上传目标指向共享 Agent 的共享根、他人 `user/<user_id>`、他人私有 Agent 的工作区或另一租户的目录
- **THEN** 请求被拒绝，目标目录内不新增任何文件或目录，响应不透露该目录的存在性

#### Scenario: 相对路径试图逃出目标目录

- **WHEN** 某条相对路径含 `..`、绝对路径、盘符或以冒号表示的 NTFS 数据流
- **THEN** 该项上传失败并被逐项报告，逃逸目标处不产生文件，同批其它合规条目按各自结果处理

#### Scenario: 目标目录下的中间目录是符号链接

- **WHEN** 目标目录中某个将被写入的中间目录实际是指向目录之外的符号链接
- **THEN** 写入被拒绝，链接指向的位置不产生文件，校验不以字符串前缀放行

#### Scenario: 落点已存在同名文件

- **WHEN** 落点已存在 `报告.xlsx`，调用者上传一个同名文件且未表达覆盖意图
- **THEN** 既有文件内容不变，新文件以不同的可用名（如 `报告 (1).xlsx`）落盘，响应报告实际落盘名

#### Scenario: 重试只重传失败项

- **WHEN** 某批次因网络中断失败，调用者重试
- **THEN** 客户端只重传该批未成功的条目，已报告成功的条目不重传；重试不产生半截文件，也不需要服务端记忆历史请求

#### Scenario: 单条写入失败不污染结果

- **WHEN** 批次中某一条因目标不可写或空间问题失败
- **THEN** 该条以失败项报告，其余条目按各自结果处理，失败条目不在目标目录留下部分内容

### Requirement: 工作区上传的容量上限、超限提示与实时进度

系统 SHALL 对上传施加可判定的上限：**单个文件大小**（服务端权威）、**单次拖拽的条目数与总字节**（客户端体验护栏）。超出任一上限的条目 SHALL 被跳过并以**逐项**提示报告（路径、大小与原因），其余未超限的条目 SHALL 继续上传，MUST NOT 因个别超限项而全部中止，也 MUST NOT 只给一句整体失败。

服务端 SHALL 以**无状态**方式独立复核**单请求内即可判定**的上限（单文件大小、单请求条目数），MUST NOT 以前端限制替代服务端校验，也 MUST NOT 为跨请求的累计判定引入服务端状态。单次拖拽级的条目数与总字节上限 SHALL 由客户端在清单确定后判定并在超出时于发送前提示；该上限是体验护栏而非授权或配额边界，MUST NOT 被表述为安全保证——磁盘容量与资源配额的权威约束属于资源配额的责任域，本次不重复实现。

上传的实现 SHALL 使「一个 200MB 文件」与「5000 个小文件」走同一条判定与重试路径：单条失败 SHALL 可被单独重传，MUST NOT 要求客户端为失败项重建一个更大的发送单元。分块与并发数属实现细节，不在规范内约束。

上传过程 SHALL 展示准确的实时进度，同时反映已传字节与总字节、已完成项数与总项数、以及完成百分比。总字节 SHALL 在文件清单确定之后才作为分母，MUST NOT 在清单尚未确定时给出百分比（该阶段 SHALL 只报告已发现的项数）。存在失败或跳过项时，界面 MUST NOT 展示「已完成 100%」，SHALL 表达为部分完成并给出可展开的逐项结果；失败与跳过项 SHALL 支持单独重试。

界面所显示的已传字节数 SHALL 与落盘总字节处于同一量级（偏差不超过 1%），MUST NOT 以请求体总长度（含 multipart 与协议开销）直接充当文件字节。

#### Scenario: 单个大文件成功

- **WHEN** 用户拖入一个接近单文件上限的文件，且部署的传输链允许该体积
- **THEN** 上传成功且进度逐段推进到完成，落盘文件字节数与源文件一致

#### Scenario: 单个文件超过上限

- **WHEN** 用户拖入一个超过单文件上限的文件，同时拖入若干合规文件
- **THEN** 超限文件被跳过并逐项提示（路径与原因），其余文件照常上传成功，整体结果不呈现为全部失败

#### Scenario: 一次拖入约 5000 个文件

- **WHEN** 用户一次拖入约 5000 个文件、多个文件夹
- **THEN** 文件数与目录结构与源一致，进度单调推进至完成，且单个文件的失败不影响其余文件上报成功

#### Scenario: 进度的分母与完成语义

- **WHEN** 一次拖拽尚未遍历完文件清单，或过程中有文件失败
- **THEN** 清单未确定前只报告已发现的项数、不显示百分比；存在失败时不显示 100%，而是部分完成并给出逐项结果

#### Scenario: 单次拖拽上限在发送前被拦

- **WHEN** 用户一次拖入的条目数或总字节超过单次拖拽上限
- **THEN** 客户端在清单确定后、发送前给出提示（说明上限与超出量），不进入上传；服务端仍独立复核每个请求的单文件上限

### Requirement: 工作区面板支持在本人可写范围内删除条目，且可经回收站恢复

面板的「文件」页签 SHALL 支持删除**单个文件、目录（含其全部内容）**，一次请求 SHALL 可包含多个待删条目。可删除范围 SHALL 与上传的本人可写范围**同源但更严**：除下列四项外，本人可写范围内的条目 SHALL 可删除——

1. **Agent 运行内部**：Agent 工作区根下的 `AGENT.md`、`USER.md`、`RULE.md`、`BOOTSTRAP.md`、`MEMORY.md` 及 `memory/`、`scheduler/`、`tmp/`、`knowledge/`、`skills/`、`websites/`、`subagents/`、`system/`、`plans/` 目录本身 MUST NOT 可删（判定 SHALL 以**工作区根的第一层条目**为单位，MUST NOT 递归到本人目录内的同名条目——本人自己目录里的 `memory/` 是本人内容，可删）；
2. **本人目录容器与其本身**：工作区根的 `user/` 容器，以及调用者本人的 `user/<本人 user_id>` 目录本身 MUST NOT 可删——后者既是共享及私有 Agent 的可写范围根，也是回收站的父目录，删掉它会把回收站一并带走，使同一次删除无法再恢复；
3. 回收站目录本身；
4. 可写范围根自身（不允许把范围根整体删掉）。

删除 SHALL 是**软删除**：服务端 SHALL 把条目**移动到回收站**而不是直接抹除，MUST NOT 在原地直接销毁数据。移动 SHALL 为同文件系统内的原子重命名；跨设备等无法原子移动的情形 SHALL 以该项失败报告，MUST NOT 退化为「先复制再删除」而留下不确定的中间态。

删除 SHALL 需**二次确认**，确认文案 SHALL 包含本次待删的**条目数与总体积**（MUST NOT 只是笼统的「确定删除吗」）；删除目录时 SHALL 显式说明会连同其全部内容一并移入回收站。确认文案 SHALL 说明该操作可经回收站恢复，MUST NOT 把软删除表述为不可逆。彻底删除的确认文案则 SHALL 说明不可恢复。

回收站 SHALL 位于调用者本人的 `user/<本人 user_id>/.trash/` 之下，SHALL 不出现在文件列举与搜索结果中——该排除 SHALL 由显式准入规则保证，MUST NOT 仅依赖名字的点前缀（列举接口的隐藏文件开关是客户端可达的，点前缀只在默认调用下生效）。回收站 MUST NOT 可作为上传落点或删除目标。回收站中的条目 SHALL 保留其**原始相对路径**，使恢复能回到原位置。若该业务位置在离线升级中迁移，原路径 SHALL 留在备份清单中，当前恢复目标更新为迁移后的对应位置，不扩大本人可写范围。

面板 SHALL 提供回收站浏览，并支持**恢复到原位置**与**彻底删除**。浏览、恢复与彻底删除 SHALL 均只作用于**调用者本人**的回收站，MUST NOT 因批次标识来自请求体而触及他人的回收站或回收站之外的任何路径。恢复时 SHALL 重新校验目的地仍在调用者当时的可写范围内且未变为不可删集合中的条目（Agent 可见性可能在删除之后改变）；不再合规时 SHALL 拒绝该项并说明原因，MUST NOT 恢复到范围之外。恢复遇到原位置已被占用时 SHALL 以可用的新名落盘并在结果中如实报告实际路径，MUST NOT 覆盖占用者、MUST NOT 静默失败。彻底删除 SHALL 仅销毁本人回收站内被选中的条目，MUST NOT 触及回收站之外的任何路径。

删除与恢复 SHALL 逐项报告结果；越权、属于不可删集合或不存在等失败项 MUST NOT 中止其余条目，也 MUST NOT 以成功计入结果。回收站 SHALL 有清理点（保留期限与触发时机为实现常量），MUST NOT 无限积累。

#### Scenario: 删除前的二次确认

- **WHEN** 用户对已选中的文件或目录发起删除
- **THEN** 界面先给出确认，文案含本次待删的条目数与总体积，目录删除时说明会连同全部内容一并移入回收站，并说明可经回收站恢复

#### Scenario: 删除本人目录内的文件

- **WHEN** 用户在本人可写范围内删除一个文件
- **THEN** 该文件从原位置消失并进入回收站，目录列举中不再出现，回收站中可见且带有原相对路径与删除时间

#### Scenario: 删除目录及其全部内容

- **WHEN** 用户删除一个含多级子目录与文件的目录
- **THEN** 该目录整棵进入回收站，原位置不再存在该目录，回收站中的条目可被恢复为原来的目录结构

#### Scenario: 删除范围之外的条目

- **WHEN** 用户尝试删除共享 Agent 的共享根条目、他人 `user/<user_id>` 下的条目或他人私有 Agent 的条目
- **THEN** 请求被拒绝，该条目与其内容原样保留，响应不透露该目录的存在性

#### Scenario: 删除 Agent 运行内部被拒绝

- **WHEN** 用户在私有 Agent 的工作区根尝试删除 `AGENT.md`、`knowledge/` 或 `memory/`
- **THEN** 该项被拒绝并说明原因，该条目原样保留，同批其它可删条目按各自结果处理

- **THEN** 该项被拒绝，该目录与其内容（含回收站）原样保留——回收站不因一次删除而被一起移走

#### Scenario: 本人目录内的同名条目不适用不可删集合

- **WHEN** 用户在本人 `user/<本人 user_id>/` 下删除一个名为 `memory` 或 `knowledge` 的目录
- **THEN** 删除成功进入回收站——保护规则只作用于工作区根的第一层条目

#### Scenario: 恢复回到原位置

- **WHEN** 用户对回收站中一个条目选择恢复，且原位置空闲
- **THEN** 该条目回到原相对路径，内容与删除前一致，回收站中不再保留该项

#### Scenario: 原位置已被占用时恢复

- **THEN** 占用者内容不变，条目以可用的新名落在原父目录并在结果中报告实际路径，MUST NOT 静默失败

#### Scenario: 彻底删除只作用于回收站

- **WHEN** 用户对回收站中条目选择彻底删除，或清空回收站
- **THEN** 只有本人回收站内被选中的条目被销毁，回收站之外的任何文件不受影响，他人的回收站也不受影响

#### Scenario: 回收站不出现在文件列举中

- **WHEN** 面板列举本人目录或执行搜索
- **THEN** 回收站目录及其内容不出现，也不能被选为上传落点或删除目标

#### Scenario: 升级前根业务文件的回收站恢复
- **WHEN** 私有 Agent 的 owner 恢复旧布局下删除的根业务文件
- **THEN** 按离线迁移中已更新的恢复目标回到本人目录，沿用同名不覆盖规则；归属或目标不明则拒绝并保留条目，不新增运行时恢复映射协议
