# agent-user-file-directories Specification

## Purpose
为租户共享智能体增加按真实用户组织的文件子目录，使多人共用智能体时，经 RongAI 平台文件页面、下载预览和文件接口只能访问本人子目录。保持现有代码执行能力，并明确该目录规则不等于共享智能体内部脚本直接读盘的用户隔离。
## Requirements
### Requirement: 共享智能体按真实用户保存平台文件

租户共享 Agent 的平台上传和回传结果 SHALL 保存于其工作区的 `user/<不可变用户ID>/`，该用户来自已认证的当前租户身份。账号名称仅用于展示，客户端或模型自报 owner MUST NOT 决定落点；无可信用户、租户/Agent 冲突或会话属于他人时 MUST 拒绝平台文件写入及私人链接生成，不回落共用上传目录。用户目录 SHALL 与 Agent 配置分开，MUST NOT 修改进程级 cwd 或共享 Profile 来临时切换用户。已有私有 Agent 的目录和权限规则不因本变更扩大。

#### Scenario: 两用户上传及回传同名结果
- **WHEN** A、B 在同一个租户共享 Agent 中上传同名文件，平台分别回传生成结果
- **THEN** 文件分别进入 user/A 和 user/B 的相应子目录，不覆盖他人文件，返回链接对应真实发起用户

#### Scenario: 改名或伪造用户
- **WHEN** A 修改账号显示名，或请求携带 B 的 owner 字段
- **THEN** 改名仍使用 A 的原用户目录，伪造 B 的落点被拒绝，不转移文件归属

#### Scenario: 无会话上传与后台身份缺失
- **WHEN** 已登录 A 尚无业务会话就上传，或后台结果没有可验证的原始用户
- **THEN** 前者归 A；后者不发布私人文件或共用下载链接，不能靠服务进程身份猜测 owner

### Requirement: 平台文件访问对用户子目录执行统一归属判断

平台文件页面及 HTTP 文件入口 SHALL 在原有身份、租户、Agent 和动作权限之外检查实际命中的 `user/<user_id>/`。仅当前用户与该目录 owner 一致时可继续原有授权；租户/平台管理员、共享 Agent 和父目录权限 MUST NOT 绕过。未命中用户子树的配置及公共资料仍遵从原有权限，不因本变更自动公开。拒绝 SHALL 不包含他人名称、路径存在性、正文或预览 URL。

该规则 SHALL 覆盖列表、搜索、计数、元数据、下载、预览和现有写入、删除、改名、复制、移动、打包入口；本能力不要求新建尚不存在的文件操作。跨 owner 的 API 移动/复制及对 user 容器或 owner 根的改名 MUST 拒绝，防止通过文件操作转移归属。

#### Scenario: 获权用户读取本人文件
- **WHEN** A 具备原入口所需权限并读取共享 Agent 的 user/A 文件
- **THEN** 返回文件；缺少原权限时不能仅凭 owner 放行

#### Scenario: 管理员与另一用户直连文件接口
- **WHEN** B 或非 owner 管理员请求 user/A 的绝对路径、相对路径或旧链接
- **THEN** 各入口均按不可见拒绝，不能通过更换 Agent 参数或平台父目录放行

#### Scenario: 文件接口转移归属
- **WHEN** A 通过已有文件接口改名 user/A 为 user/B，或将文件移动到他人子目录
- **THEN** 操作被拒绝，原文件及归属不变

### Requirement: 父目录遍历和别名不绕过本人范围

从 Agent 根、租户根、平台根或 user 父目录发起的递归列表、搜索、计数和打包 SHALL 在进入其他用户目录前过滤；user 下只展示本人子目录。API 路径的原始定位和实际打开目标 SHALL 同时验证，拒绝父级/编码逃逸、软硬链接别名及检查后替换所造成的跨 owner 访问。保护根本身不得由不可信路径替换，无法确定唯一真实归属时 MUST 拒绝，不能把路径字符串前缀作为充分依据。

#### Scenario: 展开与搜索父目录
- **WHEN** A 展开共享 Agent 的 user 或递归搜索整个 Agent/租户根
- **THEN** 只进入 A 的用户子目录，不返回 B 的目录名、文件片段或数量，公共资料继续按原权限返回

#### Scenario: 路径别名与编码逃逸
- **WHEN** A 经父目录、双重编码、软硬链接或并发替换请求 B 的文件
- **THEN** 平台文件接口拒绝实际访问，即使请求的外观路径位于 user/A

### Requirement: 平台私人文件交付不自动变为公开链接

用户子目录的预览、下载及关联子资源 SHALL 在消费时验证当前身份和 owner，目录 token 或链接持有者身份 MUST NOT 单独授权。平台对该目录的静态映射 SHALL 禁用或经过同一校验；响应使用 private/no-store。既有安全预览可以复用，不支持可靠鉴权的类型 SHALL 提供本人鉴权下载，不降级匿名访问。平台 send/回传私人文件 MUST NOT 自动复制到公开网站目录。

#### Scenario: 转发私人预览及其图片链接
- **WHEN** B 或匿名请求者使用 A 的预览 token、下载链接或预览子资源 URL
- **THEN** 请求被拒绝，A 登录并满足原权限时仍可读取

#### Scenario: 已配置网站地址的 send
- **WHEN** 平台向 A 回传共享 Agent 的本人文件，部署已配置网站基础 URL
- **THEN** 返回本人鉴权链接，不自动复制到公开网站目录

### Requirement: 旧文件兼容不猜测用户归属

启用前 SHALL 检查预留 user 目录及旧上传/平台结果。存在名称冲突时停止该 Agent 的文件布局切换，不覆盖原目录。已知 owner 的旧文件 SHALL 依据可信会话/上传记录迁入本人目录并更新或映射原引用；未知/冲突归属保留在不可经普通文件接口读取的位置，不能分给当前访问者或全部用户。迁移 SHALL 保留内容及业务标识，支持从清单重复执行；旧私有 token/公开副本不得继续经平台链接开放。

#### Scenario: 已知归属与迁移中断
- **WHEN** 旧文件可唯一关联 A，迁移中断后按原清单重跑
- **THEN** 内容验证后只生成一个目标，原会话可通过本人鉴权引用访问，B 不能用旧路径读取

#### Scenario: user 名称冲突或未知 owner
- **WHEN** 预留 user 路径已有不兼容内容，或旧上传无法证明归属
- **THEN** 冲突不自动覆盖，未知旧文件不经普通文件接口开放，源数据保持可恢复

### Requirement: 文件页面隔离不新增执行能力门槛

本能力 SHALL 只声明租户共享智能体中 RongAI 平台文件页面和文件 HTTP 接口的用户目录隔离。Python、Shell、技能脚本和 coding SHALL 保持现有开放方式与执行授权，MUST NOT 因本 change 新增沙箱依赖、关闭开关或执行隔离验收门槛。租户共享智能体内部脚本直接读盘、终端执行及 OpenCode 原生文件服务不属于本能力的用户隔离保证；不检测程序自行复制内容的行为。产品及验收记录 MUST NOT 将页面/API 校验表述为执行层用户隔离，且 MUST NOT 据此放宽已有跨租户、私有 Agent 或系统敏感路径规则。

#### Scenario: 文件隔离上线后继续执行
- **WHEN** 原已获权用户在租户共享 Agent 中运行 Python、Shell、技能脚本或进入 coding
- **THEN** 原有执行入口继续可用，不要求本 change 交付沙箱；平台回传的文件链接仍按用户目录校验

#### Scenario: 执行边界保持原规则
- **WHEN** 脚本触及同一租户共享 Agent 内其他用户目录，或请求跨租户/私有 Agent/系统敏感路径
- **THEN** 前者不由本 change 承诺阻断，后者仍执行既有权限与执行边界；测试报告明确区分两类保证
