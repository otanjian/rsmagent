# agent-digital-employee-profile Specification

## Purpose
定义智能体作为数字员工的岗位化档案：职位、分类、标签、问候与人设摘要、场景绑定及空字段从场景继承的规则，并扩展智能体管理「概况」配置面。
## Requirements
### Requirement: 岗位化档案字段可配置
系统 SHALL 允许在智能体配置中持久化并读写以下可选字段：`position`（职位）、`category`（业务分类）、`tags`（标签列表）、`greeting`（问候语）、`persona_summary`（人设摘要）。缺省时系统 SHALL 保持与改造前等价的行为（仅名称与职责描述即可运行）。系统 SHALL NOT 引入与智能体 ID 平行的第二套员工 ID。

#### Scenario: 保存岗位化字段
- **WHEN** 管理用户为某智能体填写职位、分类、标签、问候语与人设摘要并保存成功
- **THEN** 后续读取该智能体配置返回相同字段值，且 `revision` 按既有冲突规则前进

#### Scenario: 旧配置缺省字段
- **WHEN** 配置中仅有改造前的智能体字段（无岗位化键）
- **THEN** 系统按缺省空值加载，列表与对话仍可使用，不因缺字段失败

### Requirement: 场景绑定与字段继承
系统 SHALL 允许智能体可选绑定 `scene_id`。当智能体某可继承字段为空且已绑定场景时，系统 MUST 从该场景解析有效值（至少覆盖场景系统提示相关上下文、场景关联技能选择、场景工具列表与场景模型覆盖若场景侧存在）。智能体非空字段 SHALL 覆盖场景对应项。工具黑名单 SHALL 为智能体与场景黑名单的并集；若智能体工具白名单非空，则 SHALL 以该白名单为准覆盖场景工具集。

#### Scenario: 空字段继承场景
- **WHEN** 智能体绑定有效 `scene_id`，且未配置工具白名单
- **THEN** 有效工具集取自场景工具配置（若场景提供），对话构建使用场景提示相关上下文

#### Scenario: 员工覆盖场景
- **WHEN** 智能体同时绑定场景且配置了非空工具白名单与人设摘要
- **THEN** 运行时使用员工工具白名单与人设摘要，不以场景工具集或场景同名字段覆盖员工非空值

#### Scenario: 场景不存在或未绑定
- **WHEN** `scene_id` 为空，或指向的场景在场景配置中不存在
- **THEN** 不继承场景字段；不存在的 `scene_id` 在保存或激活路径上返回可理解错误或明确忽略策略（管理保存 MUST 拒绝无效 `scene_id`）

### Requirement: 管理概况页签扩展
智能体管理「概况」界面 SHALL 提供岗位化字段的编辑控件，并保留既有名称、职责、头像、模型覆盖与知识库 shared/own 能力。Desktop 与 Web 管理面 SHALL 暴露同一组字段语义。

该界面 MUST NOT 提供「分类」(`category`) 与「关联场景」(`scene_id`) 的编辑控件，MUST NOT 为二者渲染标签文案或占位下拉。

`category` 与 `scene_id` 仍 SHALL 作为可持久化字段存在，并继续可经智能体管理 API 读写、继续参与 `revision` 乐观并发。本要求只约束控制台界面不提供编辑入口，MUST NOT 被解释为字段被删除、被清空或被停止维护。

#### Scenario: 概况可编辑新字段
- **WHEN** 用户打开某智能体概况页签
- **THEN** 可编辑职位、标签、问候、人设摘要，并与名称、职责一并保存

#### Scenario: 概况不提供分类与场景入口
- **WHEN** 用户打开任一智能体（含默认智能体与非默认智能体）的概况页签
- **THEN** 界面不渲染「分类」与「关联场景」两个控件，也不渲染二者的标签文案；同页的职位、标签、问候语与人设摘要仍照常渲染并可编辑

#### Scenario: 已绑定分类或场景的智能体保存后不回退
- **WHEN** 某智能体的 `category` 或 `scene_id` 已有非空值，用户在概况页修改并保存其他字段
- **THEN** 保存请求携带这两个字段的现值，保存后读取该智能体仍返回原值，字段不被清空

#### Scenario: 默认智能体兼容
- **WHEN** 用户编辑默认智能体概况
- **THEN** 岗位化字段可保存；既有「默认智能体模型跟随全局」规则保持不变
