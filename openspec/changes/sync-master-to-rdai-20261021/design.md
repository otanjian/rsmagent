## Goals / Non-Goals

**Goals:**

- 以前端 master 优先、必要 rdai 适配为准则；完整文件清单用于防遗漏，按能力组织实现与验收证据。
- 复用上游业务算法/数据结构和 rdai 既有身份、执行、文件与传输边界；新增数据仅有一个权威归属。
- 把代码整合、业务适配、平台验收、远端交付拆成可核验阶段；同候选的证据决定开放状态。
- 本轮以 Web 的真实业务闭环作为准入条件，桌面验证保留后补任务，不要求先安装/构建 Electron 才能进行 Web 验收。

**Non-Goals:**

- 本规划阶段不合并、提交、推送或发布产品代码，不改写本地或远端 master。
- 不把同步扩大为重新实现桌面执行框架、访客体系、共享 Agent 治理或全站重构；其已交付行为保留，Web/共享后端受影响切片本轮回归，桌面运行回归后补，未交付切片仍由原 change 负责。
- 不宣称源全部能力或所有平台已通过；必要适配未完成时不能以永久关闭来结案，范围变化须有明确产品裁定。

## Decisions

### D0. 前端以 master 为交付基准，rdai 定制保持必要范围

固定 `ee2dc052` 的前端是共享功能的默认实现和验收参照。页面布局、组件样式、菜单编辑、弹窗、空态/错误反馈、加载/滚动和主要操作顺序采用上游；在已有前端挂载点和授权投影中补 rdai 差异。不得为保留旧 `console.js` 外观而丢失上游拆分模块和交互，也不将全部 rdai 页面重写或另建路由、状态、设计系统。后台继续由 rdai 实际授权入口承接，UI 对齐不恢复上游共享密码或全局资源访问。

| 页面/交互 | 采用基准 | 必要 rdai 差异 |
| --- | --- | --- |
| 对话、会话/历史、上下文、文件/产物、技能/MCP、模型/配置及上游已有知识/任务等共享页面 | 上游页面、组件及操作流程；修复和新增入口完整接入 | 可信身份和资源 ID、授权过滤、文件来源、既有品牌及服务账号凭据 |
| 默认导航及菜单编辑器 | 保留「业务工作台／控制台」两个区域；区域内采用上游菜单、编辑和恢复交互 | 按既有路由归属及授权投影过滤，同一份本人布局保留全部区域条目；保留合法恢复入口 |
| rdai 自有工作台 | 保留原业务内容，名称改为「业务工作台」 | 稳定业务路由/权限不变；调用共享功能时复用同一实现 |
| 登录、租户切换、组织/成员/角色等 rdai 专有管理页 | 现有 rdai 业务合同 | 使用现有挂载点和公共样式，不在本次同步重做业务流程 |

只记录相对上游的例外及其身份、权限、品牌或独有业务依据；共同功能默认不逐页重新裁定。按真实 view/路由映射，不按标题判断同功能。验收结合 WB-02、03、06–09 对照上游源页面与候选实际浏览器的关键布局及操作步骤，记录必要差异；不新增全站像素级截图系统。

主要菜单默认命名以合并前 rdai（`c9bd4942`）为准，覆盖简体、繁体和英文；管理页使用「智能体管理、模型服务、能力中心、记忆管理、消息渠道、运行日志」，业务页使用「知识库、定时任务」等原名。仅 rdai 自有工作台按既定裁定改称「业务工作台」，用户自定义标题优先。master 优先指页面、组件和交互，不覆盖这些产品菜单名称。主要菜单的默认位置、分组和顺序同样以合并前 rdai 为准：业务区依次为对话、智能体、定时任务、知识库、场景应用、历史会话；控制台概览置顶，随后为智能体开发、模型与接入、组织与权限、平台管理。区域切换入口固定在侧栏底部、账号区上方，按当前区域显示控制台或业务工作台返回入口。用户已保存的自定义分组和排序继续优先，不进行布局迁移。

### D1. 从最新交付基线建立隔离候选

选择独立克隆，从固定 `c9bd4942` 建立 `codex/sync-master-to-rdai-20261021-*` 分支，源固定 `ee2dc052`。克隆须拥有源/目标对象和本 change 文件；未提交文件不会自动进入克隆，应在实施前以可追溯文档提交或明确复制并核对内容携带，不能忽略。

运行 `scripts/sync-from-master.sh` 排练，确认其自动撤销后 HEAD、工作树和 MERGE_HEAD 状态，再用 `git merge --no-ff --no-commit <source-sha>` 生成正式候选。脚本会 fetch，源若移动则记录并重新决定固定版本，不能把新旧证据混用。保留 merge 的第一父目标、第二父源；适配和后续修复可形成普通提交。选择 merge 而不批量 cherry-pick，确保 770 个源提交的祖先关系和后续同步基线完整。

交付前再次 fetch：目标前移则整合并更新候选与受影响证据；源前移时明确本轮仍固定此源或重新规划增量。正式工作区不做 reset/clean，已有 master 不改写。交付仓库/分支是 `gitea/rdai`，不沿用旧文档的 `gitea/main` 示例。

真实模型凭据等外部依赖阻塞时，允许先将经过本地检查的候选 merge 保存到独立同步分支并发布草稿 PR。草稿须列明失败、未验证和延期范围，并确认 Gitea 将其识别为 draft；不得标为可合入、自动合并或据此关闭正式验收/交付任务。该顺序调整只提前保存和评审候选，阶段 D 的真实 Web 验收仍是正式合入 rdai 的前置。

### D2. 全量文件普查、能力裁定与实际接线同时推进

`evidence/upstream-files.tsv` 保存全部 876 个变更路径，`file-workstreams.tsv` 为待审查的规划分组。所有路径均需完成分类；行为、实际消费者、依赖和测试证据按能力记录，一条记录可覆盖多个关联文件。实际冲突、授权/数据变化和接线差异逐项说明；纯文档、翻译及同一行为的配套文件可合并记录，不要求为每个文件新建能力 ID 或重复测试。仍须检查无冲突增量，不能只按提交标题或扩展名判断已完成。

共同修改路径见 `both-sides-touched.txt`，每个实际冲突按 `scripts/conflict-baseline.txt` 裁定，保留删除理由和上游新增语义；不整文件 ours/theirs。`keep-fork` 与 rerere 结果都要检查同文件增量。纯通用算法和协议留上游层，身份/资源决策留 fork 层；必要完整 fork 要登记来源与不能复用的理由，不再新建平行会话/路由框架。

本轮证据补入现有 `docs/design/upstream-sync/{capabilities,source-census,runtime-contract,required-tests}.json`，稳定 GAP ID 保留；新增行为使用新 ID 并映射本 change，不能只替换 source_sha。额外工具、CLI、渠道和 Desktop 覆盖不能被仅统计 Web 的 source-census 遗漏。

### D3. 产物索引复用会话存储，安全范围由会话和文件共同决定

上游在 `agent/memory/conversation_store.py` 的 artifacts 索引以 `(agent_id, path)` 识别条目，`api/artifacts.py` 通过全局 registry 聚合并可返回绝对路径。rdai 复用索引结构、渲染协议、提取逻辑和既有会话 schema/查询接缝，先从可信会话关系取得 tenant、owner 和来源。查询、更新和登记去重都必须限定相同归属及文件来源，不能先按全局 Agent/路径合并再过滤。仅在既有键无法可靠表达该边界时追加最小索引字段/约束，不预设整套身份字段复制、全库重建或通用产物服务；必要迁移在事务中验证。

新增 fork handler 并在 route_registry 登记 GET/POST 及动作授权；获取本人会话与来源对象后才读写索引。文件正文不复制到新库，预览/下载沿用既有文件授权和设备传输；远程设备产物使用现有带来源的引用，禁止从客户端绝对路径读取服务器同名文件。移除只删索引，改名只改展示标题。列表先过滤再分页，操作逐次重验；后台索引失败不能重新提交整个聊天消息。

选择在现有存储扩展索引而不另造产物数据库，是为保持消息/文件来源一致，便于幂等恢复和私有历史隔离。历史无可信归属的行保留并隔离，不能按 Agent 当前租户回填。

### D4. 自定义菜单是个人布局，权威授权继续由投影决定

自定义菜单属于本人当前租户的偏好，统一从侧栏账号菜单的「自定义菜单」进入，与个人偏好相邻；移除侧栏底部和分组旁的重复编辑入口。复用同一菜单编辑器及保存/恢复默认接口，打开时关闭账号弹层并将焦点移入编辑器，关闭后返回账号按钮；移动账号面板和折叠侧栏保持可用。

上游 `api/menu.py` 已提供 JSON 清洗、原子写入和重置，`version: 1` 是格式版本，不是并发控制版本。直接使用全实例 `menu_file()` 会让成员互相覆盖布局，因此只替换存储作用域：复用目标已有 `common/state_dir.py:tenant_app_data_root()`，在该私有目录下按可信用户 ID 保存一份 `menu.json`。路径解析集中于现有 state_dir 接缝，校验用户段和路径包含关系，不使用可浏览的共享工作区，不接受客户端传入 tenant/user/路径。沿用上游 JSON 及原子保存，不新增身份数据库表或通用偏好框架。

读取由 `auth/console_projection.py` 的现行能力与菜单授权过滤，保留写请求来源保护；公共管理页不因上游 REQUIRED_VIEWS 中的 config 被强制展示给普通成员。复用上游编辑器、保存反馈和恢复入口；无偏好或损坏时使用经授权过滤的上游默认导航及 rdai 扩展入口。同身份并发按最后成功原子写入生效，写失败保留已落盘内容，不增加 expected_version、冲突草稿或协同编辑协议。客户端未识别但服务端格式合法的条目在编辑其他项时保留；身份切换后丢弃旧请求结果。

产物项复用现有可校验来源引用，外链限制合法协议并复用受限 iframe/外部打开边界，不在外部页面暴露 Cookie、鉴权头或 Electron preload。旧实例全局菜单文件保留但不自动赋给成员；无本人配置时采用上述默认导航。本次不新增全局菜单导入界面或迁移向导。

rdai 自有工作台区域的默认展示名使用「业务工作台」（繁体「業務工作台」、英文 `Business Workspace`），覆盖菜单/区域标题、面包屑和返回入口。仅修改指向该区域的默认文案，保留用户自定义品牌文案，以及 SAP 工作台等独立业务名称；现有路由、权限 ID 和业务内容按原归属维护。固定源没有内置 `view=workbench`；用户所称上游「工作台」按实际入口核对，不据名称新造页面。2026-10-21 用户验收后明确要求恢复「业务工作台／控制台」两个清晰入口。侧栏底部账号区上方显示获准的控制台入口或返回业务工作台入口，区域标题和菜单反映当前位置；内置项按既有路由登记的 area 分区，自定义产物/外链属于业务工作台。不新增路由表、数据库字段或菜单迁移；仅过滤侧栏显示，编辑器继续读写同一份完整布局，保留混合分组、隐藏项和未知项。控制台入口使用同一服务端 available_views 投影，无可达管理页时隐藏；旧深链接、刷新、前进后退、未保存编辑保护继续走上游共享路由。不能因保留两个区域而回退共享前端。Web 要验证改名后旧链接、刷新/前进后退及权限仍正确；Desktop 文案整合可随代码同步，运行显示验证后补。

账号底部布局：侧栏折叠按钮移至账号行右侧，替换省略号，与头像/账号菜单按钮独立；移除最底部独立按钮栏。收起后头像与展开按钮上下排列，保留账号菜单、键盘操作、提示和刷新后的状态恢复；移动视口继续使用抽屉。复用现有折叠偏好键，统一共享导航与 rdai 样式的状态。两个按钮为同级元素，避免嵌套按钮或点击冒泡误开账号菜单；收起时允许账号弹层在窄栏旁显示，导航滚动仍由原导航容器负责。

顶部栏外链：按用户验收意见，在共享 `layout/header.html` 中为文档、官网和 GitHub 三个入口使用既有 `hidden` 样式，所有 Web 导航区域和视口统一隐藏。保留文档节点及标识，使既有语言和品牌链接更新逻辑继续兼容；语言、主题、租户选择不受影响，不新增开关或偏好存储。

### D5. 兼容 API 复用上游语义，服务账号凭据和会话归属保持唯一

把 `channel/web/api/openai_compat.py` 的请求解析、事件格式、用量和资源释放修复接入实际 `channel/web/openai_api.py`；能抽为纯值变换的部分复用，不继承上游共享 token 认证。新增模型目录路由须明确注册并使用相同服务账号认证和当前允许集合；配置 UI 消费既有服务账号凭据管理能力，不复制上游 ChatApiCard 的共享明文密钥模式。

持久会话键及锁包含真实用户、租户、规范化 Agent 和 conversation_id。Agent 别名在锁定前解析。没有 conversation_id 时使用请求历史独立执行，不把 user 字段作为会话或身份来源；这是上游行为带来的兼容变化，升级说明必须给出显式 conversation_id 的迁移示例。旧会话保留其真实归属，不通过统一匿名键批量迁移。

在服务端/客户端两侧验证流结束、idle timeout、取消和提供方错误均释放锁/队列/连接，已产生副作用如实记录。全局配置开关至多控制部署开放，不能覆盖身份/资源权限，也不能破坏当前已验收的服务账号 API。

### D6. 配置、技能、模型和上下文适配保持既有数据归属

技能目录安装优先复用 `agent/skills/` 新 archive/替换逻辑，接入 `fork/handlers/skills.py` 的资源 ID 和动作授权。目录地址与凭据由既有合法配置域管理，回退公共目录不携带私有令牌；公共维护与本人使用参数分开。原子安装、元数据确认、启停失败回滚分别验证，不因展示名相同定位错资源。

模型发现接入 `fork/handlers/models.py` 的管理动作及原提供方凭据，结果只是候选；不改变 `role-model-assignment` 的允许集合和 fallback 重验。搜索提供方、headers、API base/key 等新增配置先分类平台/租户/个人归属，复用现有加密与脱敏，不由上游全局配置覆盖租户选择。产品默认 Agent 名称通过上游新增配置接缝接入既有 RongAI 品牌源，不改写 Agent ID 或用户命名。

上下文用量复用上游 `sessions.context_usage`、读写方法及 `restored` 标记，沿用上游用量卡片与「上次运行」反馈，不增加独立快照表、接口或面板。查询仍验证本人会话；为兼容 rdai 现行合同，无实时实例保持 `available=false`，用量字段仍返回最后一次数据并置 `restored=true`。UI 仅对显示条件作必要适配，使有快照时仍展示原卡片，而压缩资格只取实时状态；不为读取创建 Agent。压缩仍只改变实时窗口，历史正文和并发到达消息保持。

### D7. 通用修复与桌面/访客合同按实际边界组合

文件原子写、Word/Excel/PPT 解析、MCP 生命周期、搜索抓取、模型流、调度、记忆、渠道等修复优先复用上游算法，并把引用变更接入运行实现。任务未知字段、运行身份、通知及迁移提交保持；MCP/调度失败不能被 fork 包装成成功。

上游 Windows Bash、多行 Python、chcp 修复应用于已支持的执行路径，不据此开放尚未验收的 Windows 本机执行。完整保留 `harden-windows-desktop-reliability` 和 `add-windows-local-project-access` 的合同版本、文件/脚本两面开关、原生 helper、expected_version、journal 和 OS 隔离。共享后端在 Web 可达的拒绝/授权路径本轮仍验证；旧 v2、新 v3 和平台原生运行验证列入后补桌面任务，不以源码存在自动设置 accepted。

远端新增的 IM guest 账号不可登录、渠道来源、角色交集和停用重验与 `chat_channel.py`、agent_stream 及渠道增量一并保留；本轮不替原 change 勾选真实飞书/企业微信未验收任务。

TLS 复用 `core/tls.py` 的显式配置并接入实际启动路径；保留交付目标中的 loopback HTTP 修复和现有远程 TLS/certificate pin 规则。品牌覆盖目录 `rsmCode/branding/` 保持独立，源产品名、链接和模型身份改动须经过既有品牌门禁；检查 Web 产物前先构建，不能因 dist 缺失静默跳过。

| 阶段 | 进入条件 | 输出及结束条件 |

| F 桌面补验 | 后续安排，需重新固定受测版本和平台 | 完成延期清单后才报告桌面通过或发布桌面包；Web 本轮通过不能替代此阶段 |

本轮必须使用真实 Web 应用、同候选后端和前端资源，从正常浏览器完成 [Web 验收清单](evidence/web-acceptance.md) 的 WB-01–WB-12。准备至少两个租户、多个普通成员/管理员、两个服务账号及目标已有 IM guest 夹具。覆盖登录/退出/重登、租户和身份切换、业务工作台与管理区、对话流和取消、历史/上下文、服务器工作区文件、产物/菜单、技能/MCP、模型、知识、任务/通知、兼容 API、TLS 及故障恢复。Web 文件面板与聊天实际读取分别验证，至少保留真实模型请求的完整证据；mock 或页面能打开不能替代业务闭环。

桌面 D1–D6、Electron 原生容器、main/preload/IPC、设备本机文件、原生 helper/OS 隔离、双端菜单同步及 Windows/macOS 安装包测试本轮统一记为 `deferred / not verified`，不要求执行桌面构建或测试。范围、承接任务和恢复测试条件见 [桌面延期清单](evidence/desktop-validation-deferred.md)。共享后端/协议的 Web 可达行为不得因文件名含 desktop 而排除；纯服务端测试仍按 Web 风险保留。代码审查和冲突处理仍覆盖 desktop 路径。

核心检查采用合并规范第 4 节中适用于 Web/后端的部分，包含路由/接缝检查、`check-upstream-sync.py --source <固定源> --baseline <实际目标>` 的完整行为运行、相关核心 pytest/Node、`tests/test_rdai_simplification.py` 和本轮新增 Web 必要用例。当前 `required-tests.json` 包含 pytest、Node 和普通浏览器批次，可以独立运行；不能改用 `--structure-only` 宣称 Web 通过。

当前 `scripts/check-production.sh --local` 会要求 Desktop 依赖、构建并运行原生容器，本轮不把该混合入口整组通过作为前置。实施时逐项执行其中适用 Web/共享后端子检查并汇总准确范围，保留 Web 审计、导航等检查；不虚构现有 `--web-only` 参数，不修改全局门禁来掩盖失败，不把未执行的整套 production 检查标绿。CI 报告应独立显示 Web 结果与桌面延期；确需增加范围化汇总时保留原全量默认行为和完整用例清单。范围内必要用例的 skip/xfail/缺依赖/零收集仍阻止 Web 交付。

同一候选、环境和用例的结果可被实现任务、必要清单及最终验收共同引用，不为每个阶段重复执行；树、依赖或相关配置变化后再重跑受影响检查及最终核心检查。只在本轮修改门禁逻辑时补相应失败验证，沿用现有测试/报告格式。远端阻断证明复用原同步 change 的有效证据或由其原任务补齐，不重复建设 CI 或另加整套治理前置；只读菜单等动作不凭空增加模型配额、执行审批依赖。

对源新增的 `test_artifact_index.py`、`test_web_menu.py`、`test_openai_chat_api.py`、`test_openai_default_session_lock.py`、`test_external_api_switch.py`、`test_session_context_usage.py`、`test_model_discovery.py`、技能替换/配置保存、`test_web_tls.py`、`test_bash_multiline_python.py` 的适用后端行为及 Web scroll 登记本轮用例；Desktop 专属部分归入延期清单，不按整个文件粗略跳过混合用例。源独立测试通过仅证明上游行为，rdai 要补真实装配的授权组合。

## Risks / Trade-offs

- 876 个路径中有 284 个双侧修改，文本冲突和无冲突遗漏都可能发生 → 全量分类、按能力记录处置和证据，冲突及行为差异逐项复核，禁止以旧 keep-fork 直接舍弃增量。
- 上游全局菜单/产物索引在多租户中可能泄露 → 可信 tenant/owner 分区、来源校验和先过滤后分页；旧无归属记录隔离，迁移失败可恢复。
- API 无 conversation_id 行为变化影响旧调用方 → 在发布前完成迁移示例、旧调用回归及明确版本说明，不静默续接或合并历史。
- 当前源新增 Windows 修复可能误扩大本机执行能力 → 保留原合同/开关和平台资格；本轮完成相关 Web/后端保护验证，原生平台补验后再判断桌面可用性，原 change 未验收任务继续保留。
- 桌面测试延期意味着无法证明当前同步候选的桌面运行质量 → 本轮报告限定为 Web 已验收，Desktop 明确未验证；补验单列任务，不发布桌面包、不将延期结果计为通过。
- 同步期间交付目标或共享规范前移 → 用新目标重建差异和证据，保留他人提交；本 change 的 MODIFIED 块再对基线校验，不覆盖活动 change 需求。
- 远端 CI 配置存在但未实际阻断 → 核实 runner/必需检查及失败 PR；未验证时标记未验证并提供同等人工证据，相关自动化任务不能关闭。

## Migration Plan

1. 在隔离数据副本上核对会话库、身份库与迁移编号；合入上游 artifacts、context_usage 迁移，仅为归属隔离补实际缺失字段/约束。菜单使用私有范围的 JSON，不新增菜单表；保留旧全局文件且不自动导入。保留远端 guest 等既有迁移，解决编号冲突，不修改已执行内容。
2. 验证旧库升级、重复执行、失败/中断恢复、同名/同路径跨作用域及无法确定归属的行。索引重建只处理已授权来源，不删除业务文件或原始历史。
3. 完成 Web 客户端与服务端配套测试、配置说明和 API 迁移说明。新 capability 的 Web 路径先经必要依赖切片和正向验收，再使用已有投影/部署开关开放；不能靠关闭原已支持 Web 能力来通过同步。Desktop 配套运行、打包与平台测试后补，不将 Web 通过传播为桌面 accepted。
4. 人工复核候选树和实际构建后提交 merge 并推送同步分支，PR base 为 rdai。交付源/目标移动时按 D1 重新处理；PR 必须引用持久化证据、未验收范围及回滚方案。
5. 回滚共享代码使用经核实父提交的 revert 和 PR，不强推。数据库/外部状态按已演练备份恢复，避免旧进程忽略新身份字段；先停止写入并保全升级后的原始数据。revert 同一 merge 不会让再次 merge 自动重放，恢复需单独评估。
