# 真实提供方 Web 验收

2026-10-21，使用独立克隆的实际 `build_web_app()`、真实 Chrome、全新 IAM/会话库与合成用户。提供方为现有配置的 DeepSeek，模型 `deepseek-v4-flash`。凭据仅在运行时读取，不进入 Git、截图或结果记录。模型响应和工具执行没有替身；隔离夹具只限定配置、数据目录及初始化器的旧环境文件路径。

## 实际结果

1. Web 对话要求模型 write 创建合成 Markdown，再 read 读取。实际 SSE 中按顺序收到 write/read 成功、done 和 stream_end；助手正文及磁盘文件一致。
2. 产物页自动列出该文件；预览、回溯源对话、工作区搜索/预览和下载均成功，下载字节与工具写入内容一致，页面脚本错误为 0。
3. 两个普通服务账号分别拥有租户分配范围内的一个模型、同一 Agent 与 read/write 权限。各自目录只返回获准模型。一个非流式、一个流式执行真实 write/read，并核对 token 用量与完成状态。
4. 两账号使用相同 `conversation_id` 和相同旧 `user`，后续各自只能接续本人标记；会话库的 owner/tenant 独立。再以同一旧 `user` 发起无 `conversation_id` 请求，不继承既有上下文、不新增持久会话。

脱敏机器证据见 `results/real-provider-status.json`、`real-chat-result.json`、`real-file-browser-result.json`、`real-api-result.json`。三张 `real-*.png` 截图仅含合成文件。最终核心/受影响检查见 `results/affected-final/`，共 376 项，无失败或跳过。故障、超时/断开释放、身份撤销和并发边界仍由原必要回归覆盖，不把真实提供方成功请求当作所有故障分支的证明。

## 验收发现及修复

- 工具默认写入用户私有工作区，产物相对路径却使用共享工作区。修复复用既有 `personal_default_dir()`，保留显式项目优先级；增加两用户同名文件及共享同名干扰文件回归。
- SAK 聊天路由先经过浏览器租户会话入口，导致合法服务密钥无法进入处理器。改由现有兼容 API 处理器统一完成 SAK/database、租户、Agent 和模型授权；真实完整应用回归继续验证匿名、跨租户、未授权模型及撤销密钥拒绝。
- 处理器缺少 403/409 HTTP 状态映射，正确的授权/模型冲突会被误报 500。补齐状态，不改变授权结论。

最初目录为空来自夹具漏配租户模型上限；修正测试授权，没有放宽生产权限。一次连续请求失败来自初始化器加载操作者环境文件覆盖了夹具加密密钥；后续夹具将该环境文件限定在临时目录后，五次真实请求及身份隔离全部通过。

本文件证明 Web/后端声明范围，不证明 Desktop、生产部署、其他浏览器或其他模型提供方通过。
