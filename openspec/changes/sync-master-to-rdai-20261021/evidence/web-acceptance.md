# 本轮 Web 验收清单

范围依据：用户于 2026-10-21 要求「测试时，可以先不用测试桌面端，但要保证 web 端 ok」。本文件保留原验收要求；2026-10-21 的实际执行结果见下方。**WB-01–WB-12 的本轮 Web 范围已通过；Desktop 延期及远端 CI 自动阻断缺口分别保留。**

## 环境与证据

- 使用最终候选的实际 `build_web_app()`、后端和浏览器加载资源；需要构建的 Web bundle 使用同一候选构建，记录代码树/提交、资源摘要、依赖、配置和浏览器版本。
- 至少使用 Chromium 完成全清单，并在实际交付使用的另一受支持浏览器存在时补充登录、导航、对话、文件/产物核心冒烟；声明范围只包含实际验收的浏览器/部署形态。
- 准备两个租户、多个普通成员/管理员、两个服务账号及既有 guest 夹具，使用隔离身份库和合成业务数据。Web 不依赖操作者已有登录态、Desktop 安装或 Electron。
- 每项同时记录用户操作、期望结果、实际结果、对应自动化用例/人工证据、网络请求与可归因的浏览器/服务端错误。必要用例必须实际收集和执行，不能以页面返回 200、截图、mock 或代码存在替代。
- 至少完成一次真实模型的 Web 对话和受控工具调用，核对真实文件/结果；其余失败、并发和隔离边界可用可控提供方故障注入，但不能由固定模型响应代替全部正向链路。
- 前端参照固定 `master@ee2dc052` 的实际源页面/组件，在候选浏览器对照导航、对话、产物、菜单编辑和技能/模型的关键布局、操作顺序及反馈；记录上游依据、候选结果和必要 rdai 差异。共用流程按上游交付，不仅检查功能可达；品牌、权限和独有业务按 design D0 保留。不要求新增全站截图或像素对比系统。
- 同候选、同环境已有的有效自动化/人工证据可由多个任务和 WB 项引用；仅在相关代码、依赖或配置变化后重跑，不重复生成逐文件验收材料。

## 执行入口与放行标准

1. 执行路由覆盖、模块接缝和完整 `check-upstream-sync.py --source <固定源SHA> --baseline <目标SHA>` 行为检查；`--structure-only` 不构成验收。
2. 补齐合并规范中适用的 Python/Node 核心、`tests/test_rdai_simplification.py`、变更模块双侧断言及上述清单所需真实浏览器用例。相关后端测试即使文件名含 desktop，只要保护 Web 可达入口或共享授权，也仍在范围内。
3. 现有 `scripts/check-production.sh --local` 混合了 Desktop 依赖、构建和原生容器。本轮独立执行其 Web/共享后端子检查并汇总，不声称该全量入口通过，不用清空全局 required-tests 或吞掉失败来获得绿灯。
4. Web 范围必要用例 skip、xfail、零收集、缺依赖、实际资源缺失、未解释的业务/权限回归均阻止 Web 交付。正常流程、权限边界、并发及故障恢复必须有对应证据。
5. 全部适用 WB 项与相关后端回归通过后，报告「本轮同步 Web 验收通过，Desktop 未验证」，可进入本轮人工评审、PR 和合入。桌面延期本身不阻塞此阶段；远端门禁是否真实生效单独记录。

桌面代码同步和后续验证的边界见 [desktop-validation-deferred.md](desktop-validation-deferred.md)。本清单不是将普通浏览器测试当成桌面测试的替代证明。
