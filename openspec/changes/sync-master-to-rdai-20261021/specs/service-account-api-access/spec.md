## ADDED Requirements

### Requirement: 兼容 API 模型目录和选择使用服务账号当前授权

兼容 API SHALL 支持模型目录读取及聊天请求中的可选 Agent/模型选择，身份继续来自现有服务账号凭据。目录 SHALL 仅显示调用账号在目标租户实际可使用的模型；显式 Agent/模型必须在当前授权范围内，省略时仅使用合法默认链。请求中的 `user`、Agent 别名或模型名称 MUST NOT 代替真实主体、租户或资源授权；目录和错误不得暴露凭据。

#### Scenario: 查询目录并选择获准模型
- **WHEN** 服务账号读取模型目录并为获准 Agent 选择目录中的可用模型
- **THEN** 请求沿既有执行链成功，返回实际模型与用量，目录中不包含未获准模型

#### Scenario: 猜测模型或 Agent 标识
- **WHEN** 调用方提交未获准、禁用或其他租户的 Agent/模型标识
- **THEN** 请求在执行前被拒绝，不自动使用全局默认或泄露未获准资源详情

### Requirement: 兼容 API 区分请求历史与持久会话并隔离并发

不带 `conversation_id` 的请求 SHALL 使用所传消息作为本次上下文，不因相同 `user` 字段续接另一请求的历史；带 `conversation_id` 时 SHALL 以真实服务账号、当前租户、规范化 Agent 和会话标识确定持久会话。不同主体的同名会话 MUST NOT 共享消息或结果；同一真实会话的并发请求 SHALL 串行处理或明确冲突，默认 Agent 的等价别名使用同一并发边界。部署升级 SHALL 明确告知旧客户端将依赖 `user` 的续聊迁移为显式 `conversation_id`，不猜测合并旧会话归属。

#### Scenario: 无会话标识的多消息请求
- **WHEN** 调用方提交多条历史消息和最后一条用户消息但没有 `conversation_id`
- **THEN** 本次响应使用这些历史，相同 `user` 的后续独立请求不继承本次上下文

#### Scenario: 同名会话跨服务账号
- **WHEN** 两个服务账号或不同租户使用相同 `conversation_id`
- **THEN** 各自只能接续自己的会话，既有历史和输出不会跨主体出现

#### Scenario: 默认 Agent 别名并发请求
- **WHEN** 同一主体通过两个等价默认 Agent 标识同时写同一会话
- **THEN** 两请求共用并发边界，不重复或交错保存消息；失败请求不伪报执行成功

### Requirement: 兼容 API 输出和故障释放保持完整语义

流式与非流式响应 SHALL 保留源版本支持的文本、思考、工具过程与用量语义，并遵守同一授权。提供方失败、无效请求、取消、流空闲超时和消费者断开 SHALL 明确结束并释放资源及会话锁，MUST NOT 把错误或不完整结果包装为完整成功。执行中撤权 SHALL 在后续受控动作前生效，API 开关不替代服务账号资格，未验收的配置入口不得生成或回传实例共享明文密钥。

#### Scenario: 流式工具调用正常结束
- **WHEN** 获准请求产生文本、工具事件和用量并正常完成
- **THEN** 流事件和结束状态可由客户端正确消费，非流式路径具有对应完整结果

#### Scenario: 流中断后再次请求
- **WHEN** 提供方失败、长时间无事件或客户端断开，随后同一主体再次请求该会话
- **THEN** 原请求释放占用并准确记录已发生效果，新请求不因遗留锁永久等待，未完成输出不作为完整回答返回
