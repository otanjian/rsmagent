## Why

2026-10-21 已获取 `origin/master`，固定源为 `ee2dc0521714fc144e0c9923f363147fe865ad2f`；相对共同祖先 `48c0d79c36146950667f8d1884ab823deae62305` 有 770 个待接入提交（其中 452 个非合并提交）、876 个变更文件，包含 v2.2.1 及其后续修复。需要将这些行为接入 rdai 的真实运行入口，同时保留 database 身份、租户/owner 隔离、产品品牌及桌面执行约束，不能仅完成文本合并。

交付目标固定为本次 fetch 后的 `gitea/rdai`：`c9bd4942261156f56c02ffd65e4d81c6153e1594`。它比本地 `rdai` 的 `92d468157d79c2fb1869f9123ac812f0c353af10` 前进 12 个提交，本轮须完整保留这些 IM 访客、飞书注册、日志脱敏及桌面修复。以上为提案时的固定依据；当前实施与验收状态以 tasks.md 和 evidence 中的交付记录为准。

**本轮验收范围（2026-10-21 用户调整）**：先保证 Web 端及其实际后端链路通过，Desktop 测试暂缓，不作为本轮同步 PR/合入的前置。桌面代码仍按同步范围审查和整合，桌面构建、Electron/原生测试、D1–D6、双端互通及安装包验收登记为待补，不计为通过，也不据此发布桌面包。Web 必测范围见 [Web 验收清单](evidence/web-acceptance.md)。

## What Changes

- 按用户验收意见隐藏顶部栏的文档、官网和 GitHub 三个外链入口；共享头部在业务工作台、控制台及移动视口一致生效，保留语言、主题和租户切换。
- **前端交付以固定 master 为基准**：共享页面的布局、组件、操作流程、反馈及流式交互优先采用上游实现；顶层保留「业务工作台／控制台」两个明确入口，区域内复用上游菜单组件与编辑交互；rdai 通过既有扩展点保留身份/租户/权限、品牌和独有业务入口。不能仅把上游后端接到旧 rdai 界面便视为完成，也不重做一套等价界面。
- 按仓库合并规范，在独立克隆中从最新交付基线建立同步分支，固定源 SHA 排练并以 merge commit 接入，保留双方历史、逐功能冲突决策和无冲突语义审查。
- 接入上游产物中心及 Web/Desktop 自定义菜单：复用上游索引、协议和展示组件，补齐个人会话归属、实际文件授权、菜单权限投影及客户端生命周期。
- 将 rdai 自有工作台的默认展示名调整为「业务工作台」，同步菜单、标题、面包屑和多语言文案；按实际功能和稳定标识分别映射上游页面，不因同名覆盖 rdai 内容。
- 菜单直接复用上游编辑器、JSON 格式与原子保存，在现有私有应用数据目录按租户/用户隔离；同身份并发保存采用最后成功写入生效。取消额外菜单数据库表、乐观锁/冲突草稿协议及旧全局菜单导入功能；产物与上下文沿用已有存储接缝和上游字段，仅添加隔离确有需要的适配。
- 完善现有 OpenAI 兼容接口的模型目录、Agent/模型选择、多轮历史、流式/非流式输出和错误处理；继续使用 rdai 服务账号凭据，不引入实例共享明文 API Key。
- **BREAKING（兼容 API 会话语义）**：与固定源对齐，没有 `conversation_id` 的请求按传入历史独立执行；旧客户端若依赖相同 `user` 自动续聊，升级前需改为显式 `conversation_id`。该字段始终不作为身份来源，迁移不把不同服务账号的历史合并。
- 接入技能目录安装/创建、展示元数据、替换失败恢复，模型发现、上下文用量恢复与压缩并发修复，以及直接 HTTPS 的启动配置；所有配置保持明确的数据归属和授权。
- 全量审查其余增量：模型/Responses、工具/MCP、记忆/知识、调度、渠道、CLI/备份、文件原子操作、流式渲染与 Windows Bash 等，复用上游测试并补测实际 rdai 消费方。新增缺口不可因文件无冲突而省略。
- 更新持续能力清单、来源树、运行时装配和必要用例；继承 GAP-001–008 的历史状态、GAP-007 待验收项及已有 partial 项，不以换源或本 change 关闭其他 change 的任务。
- 使用同一候选完成 Web 构建/资源装配、真实浏览器端到端、相关后端双侧回归和数据库隔离验收，人工复核后向 `gitea/rdai` 提交英文 PR；桌面测试列入延期清单，不阻塞本轮 Web 验收交付，未经验证的平台和远端阻断仍明确标注。

- 主要菜单默认命名以合并前 rdai（`c9bd4942`）为准，覆盖简体、繁体和英文；管理页使用「智能体管理、模型服务、能力中心、记忆管理、消息渠道、运行日志」，业务页使用「知识库、定时任务」等原名。仅 rdai 自有工作台按既定裁定改称「业务工作台」，用户自定义标题优先。master 优先指页面、组件和交互，不覆盖这些产品菜单名称。主要菜单的默认位置、分组和顺序同样以合并前 rdai 为准：业务区依次为对话、智能体、定时任务、知识库、场景应用、历史会话；控制台概览置顶，随后为智能体开发、模型与接入、组织与权限、平台管理。区域切换入口固定在侧栏底部、账号区上方，按当前区域显示控制台或业务工作台返回入口。用户已保存的自定义分组和排序继续优先，不进行布局迁移。

- 自定义菜单属于本人当前租户的偏好，统一从侧栏账号菜单的「自定义菜单」进入，与个人偏好相邻；移除侧栏底部和分组旁的重复编辑入口。复用同一菜单编辑器及保存/恢复默认接口，打开时关闭账号弹层并将焦点移入编辑器，关闭后返回账号按钮；移动账号面板和折叠侧栏保持可用。

- 侧栏折叠按钮移至账号行右侧，替换省略号，与头像/账号菜单按钮独立；移除最底部独立按钮栏。收起后头像与展开按钮上下排列，保留账号菜单、键盘操作、提示和刷新后的状态恢复；移动视口继续使用抽屉。复用现有折叠偏好键，统一共享导航与 rdai 样式的状态。

## Capabilities

### New Capabilities

- `conversation-artifact-catalog`: 在当前租户和本人会话范围中索引、查阅、预览、置顶、改标题、移除及回溯产物；规范既有文件与新索引的归属、迁移和失败边界。
- `web-transport-configuration`: 支持显式配置的 Web 直接 HTTPS，配置无效时启动失败，保持已有反向代理及本机连接边界。

### Modified Capabilities

- `console-navigation-availability`: 明确共享前端以 master 为基准，增加「业务工作台」命名及入口区分、本人菜单布局的 Web/Desktop 共用、权限过滤、外链/产物展示和原子保存；本轮先验收 Web，桌面互通后补。
- `service-account-api-access`: 扩展兼容聊天 API 的模型目录、会话模式及流式输出，保持现有服务账号身份和逐请求授权。
- `tenant-skills-tools-console`: 增加受控目录安装、新建技能、展示字段及失败原子性，沿用现有资源与动作权限。
- `role-model-assignment`: 增加获权管理者的提供方模型发现，区分发现、目录登记和用户授权。
- `session-context-controls`: 增加重启后持久用量快照的诚实呈现，继续区分实时上下文和手动压缩资格。

其余错误处理、安全修复和接线保持性沿用 `fork-upstream-decoupling`、`database-runtime-consumers`、`tenant-resource-isolation`、`execution-isolation` 等既有规范；不为每个上游修复另造能力。

## Impact

- **代码与协议**：主要影响 `agent/`、`channel/web/`、`desktop/`、`models/`、`channel/`、`common/`、`cli/`、`voice/`、测试及构建资源。`channel/web/route_registry.py` 仍是授权路由唯一登记源；兼容 API 实际实现为 `channel/web/openai_api.py`，不能只修改上游参考模块 `api/openai_compat.py`。
- **数据唯一归属**：身份/成员/权限/凭据继续由身份域负责；会话及产物索引由既有会话存储接缝承载，文件正文仍留原工作区/设备；菜单为当前租户、当前用户的偏好；公共技能和模型由既有资源域维护。新增迁移仅追加，不复制身份库或另建会话执行系统。
- **兼容风险**：上游全局菜单、跨 Agent 产物和共享 API Key 的假设不直接适用于多租户。会话别名、同名资源、Web 客户端和数据库迁移本轮必须验证；桌面旧客户端及 Windows 文件/脚本合同的运行验收后补，不能声称桌面兼容已通过。
- **跨 change 依赖**：继承 `restore-upstream-web-parity-and-sync-gates` 的 GAP-007/远端门禁任务；与 `harden-windows-desktop-reliability`、`add-windows-local-project-access` 协调共享文件和未验收平台开关；以远端目标中的 `add-im-guest-accounts` 实施状态为准，保留访客资格/权限交集和未完成渠道验收。`add-shared-agent-release-governance` 与本轮重叠的授权规范按切片核对，不等待整份 change，也不擅自修改其完成状态。
- **证据**：固定版本、完整提交/文件清单及历史缺口见 [evidence/refs.json](evidence/refs.json)、[evidence/upstream-files.tsv](evidence/upstream-files.tsv) 和 [evidence/inherited-gaps.json](evidence/inherited-gaps.json)。这些是规划依据，不是测试通过记录。
