## Context

场景卡片经 `Scene/_shared/frontend/adapter.js` 分发到 `SapWorkbench.open({view:'new-session'})`。工作台前端已有两条会话路径：`POST /sessions {binding_id}` 复用一条仍可续的绑定，`POST /sessions {request_id}` 新建（服务端在新建时回收该账号其它绑定并标为 `closed`）。后端 `GET /sessions` 已经按 `tenant_id + user_id` 返回该登录用户的绑定，最新在前。

真正的缺口只有一个：卡片入口此前调用 `startSession(false)`，即永远新建，把本来还能续的旧会话顶掉；只有显式的「恢复已有会话」按钮才走复用。因此本 change 是把这个默认反过来：自动入口以复用优先，新建降级为「没有可续会话时」。

## Goals / Non-Goals

**Goals:**

- 进入 SAP 工作台时默认继续该登录用户最近的工作台对话，不再无脑新建。
- 没有可续会话时才新建；用户仍能显式新建一个全新对话。
- 复用严格限定在当前租户与当前登录用户，沿用既有归属校验，不新增信任面。

**Non-Goals:**

- 不改动普通智能体卡片与其他场景的会话入口。
- 不复用被替换的终态（`state='closed'`）绑定，不改变其终态语义。
- 不新增接口、数据库字段、迁移或功能开关；不重构工作台的 opening/代次机制。
- 不引入 SAP 账号维度的复用选择（见 D2）。

## Decisions

### D1. 复用作为自动入口的默认，新建降级为「无可续会话时」

自动入口（卡片、选择器、直达）在配置与能力就绪后先 `GET /sessions`，取最新的 `state != 'closed'` 绑定：命中则以 `{binding_id}` 复用，未命中才以新的 `{request_id}` 预留。显式「新建工作台会话」保持永远新建。

「恢复」不因此变成隐式：复用只发生在自动入口，显式新建入口仍然独立可达。复用路径不产生新的 `request_id`，因此并发进入/重试不会额外分配绑定——这条幂等由既有服务端契约与前端 opening/代次逻辑共同保证，本 change 不新增状态机。

### D2. 身份范围沿用租户 + 登录用户，不做 SAP 账号维度

复用范围是 `store.sessions(ctx.tenant_id, ctx.user_id)`，即服务端按受信身份解析的当前租户与当前登录用户（与用户确认的口径一致）。MUST NOT 采信请求体声明的用户，MUST NOT 跨用户或跨租户取用绑定。

场景配置里的 SAP 账号不是复用的选择键，而是绑定快照的一部分：配置改变会体现在 `config_version` 上，由 D3 处理。

### D3. 配置变化或复用被拒时回退新建，不静默续旧目标

复用请求可能被服务端拒绝：`config_conflict`（配置版本已变）、`session_not_running`（运行实例已回收）、`session_closed`（绑定已被替换）。这些都不构成「打开失败」：前端 SHALL 以新的 `{request_id}` 回退新建，而不是把用户停在错误上，也不是隐式续到已失效的 SAP 目标。

### D4. 只复用可续绑定，不动终态记录

`state='closed'` 是被新会话替换后的终态。复用的候选集是 `state != 'closed'`；被替换的记录不复用，此时按「没有可续会话」走新建，符合既有「终态绑定不可恢复」的服务端契约（`session_closed` 410）。要「连对话一起接上」需要重新绑定平台历史里的编码会话，属更大的改动，明确不在本次范围。

## Risks / Trade-offs

- [复用把用户带进旧对话，而用户想要新对话] → 显式「新建工作台会话」入口始终可达且始终新建；不取消该入口。
- [复用选中一条与当前配置不符的绑定] → 服务端 `config_conflict` 拒绝，前端回退新建；不静默续旧目标。
- [把「恢复」隐式化后失去可控性] → 复用只作用于自动入口，显式新建与显式恢复语义保持独立。
- [并发进入重复分配] → 复用路径不产生新的 `request_id`；并发/重试的幂等契约由既有服务端幂等与前端代次逻辑保证。
- [规范与实现再次漂移] → 本 change 同时修订三条 capability 的规范，归档时同步主规范。

## Migration Plan

1. 前端接入点改动 + 回归：卡片入口续会话、无可续会话才新建、并发进入不重复分配。
2. 规范增量随本 change 归档；`scene-application-console`、`sap-workbench-session-binding`、`agent-chat-launch` 的主规范在归档时同步。
3. 无数据迁移、无开关。升级保留既有绑定、历史与 `closed` 终态；代码回退不改写数据，最坏情况是回到「每次新建」的旧行为。
4. 本机未用真实账号端到端验证「关闭后再次进入复用同一对话」，如实记为待确认，不以替身测试等同真实链路通过。

## Open Questions

- 无。复用范围与回退行为已按用户确认的口径确定：按平台登录用户（`tenant_id` + 登录用户）。
