## MODIFIED Requirements

### Requirement: 功能和资源允许集合共同生效

普通有效成员操作五类资源 SHALL 同时具备对应功能及资源动作grant；多个当前租户角色的功能、资源集合各取并集，再与租户上限、归属、Agent限制及消费者状态相交。未授予或空集合 SHALL 拒绝，不使用deny/角色继承，管理不隐含执行。本人历史、待办等其他数据保持原功能和owner规则，不增加逐对象 grant。明确跨用户历史读取额外使用 Agent 的 `history_read_all` 动作和 `history.read_all` 功能权限，仅扩大获准目标的历史只读范围。

#### Scenario: 多角色重复授予同一资源
- **WHEN** 两个角色均授予工具执行且其中一个被移除
- **THEN** 另一来源仍生效，最后来源移除后下一请求及实际调用拒绝

#### Scenario: 只有功能权限或只有资源选择
- **WHEN** 普通成员仅有tool.execute却没有目标grant，或只有grant却无tool.execute
- **THEN** 两种情况都不能执行，空资源列表不表示全部

### Requirement: 租户管理员对自己租户绑定的资源行使管理权

对绑定到其租户的智能体，租户管理员 SHALL 无需逐资源 grant 即可读取、使用（对话）、编辑、归档与删除；该放行 MUST 以 `agent_bindings` 的租户归属为唯一判据，命中即放行、未命中即回落到既有「功能权限 + 资源 grant」检查。平台管理员对上述原有动作按既有全权限语义处理。新增 `history_read_all` 不属于上述放行：tenant_admin 或平台 all 均不能代替当前租户角色对目标 Agent 的显式 `history_read_all` grant，私有 owner 也不隐含此跨用户动作。

放行 MUST NOT 解释为放宽普通成员：成员仍须同时具备功能权限与资源动作 grant，空集合仍表示拒绝。放行也 MUST NOT 扩大跨租户访问：对绑定到其他租户的智能体，租户管理员在读取、使用与编辑上均被拒绝并返回 403。

系统 SHALL 保持读取、展示（可用性）与实际执行三处使用同一判据，避免出现「列表可见但发送被拒」或「卡片不可用但接口放行」的不一致。

#### Scenario: 租户管理员使用本租户智能体
- **WHEN** 租户管理员对其租户绑定的智能体发起读取或对话，且其角色不带任何 `agent:*` grant
- **THEN** 读取返回该项、可用性标记为可用，对话动作被放行，三处判定一致

#### Scenario: 租户管理员跨租户访问被拒
- **WHEN** 租户管理员对绑定到另一租户的智能体发起编辑或其他动作
- **THEN** 返回 403，且不改变该智能体、不影响其他租户的可见性

#### Scenario: 普通成员不受放行影响
- **WHEN** 普通成员只具备 `agent.read` 而没有目标智能体的 `use` 授权
- **THEN** 仍按空集合拒绝执行，目录中不出现未授权对象

#### Scenario: 绑定变更后立即生效
- **WHEN** 某智能体的租户绑定发生变更（例如改绑或解绑）
- **THEN** 后续请求按新的绑定判定，不以缓存延长原管理权限

#### Scenario: 管理员未获全部会话 grant
- **WHEN** 管理员可管理或使用本租户 Agent，但其当前租户角色没有目标 `history_read_all` grant
- **THEN** 不能据此读取其他成员的会话，原有智能体管理和本人会话能力不变


## ADDED Requirements

### Requirement: 按角色和明确智能体授予全部会话读取

Agent 合法动作 SHALL 增加 `history_read_all`，对应功能 `history.read_all`；角色配置 SHALL 支持在明确选择的智能体上勾选“查看全部会话”。已获权查看者的历史目标选择器 SHALL 按该授权返回必要的 Agent 标识/名称，不要求其具有聊天使用权，也不由此开放 Agent 核心配置。授权 SHALL 复用现有角色权限/grants 保存、expected_version、资源上限与审计事务，不新增角色或授权数据库。资源标识为稳定 `agent:<id>`，目标必须为当前租户绑定的共享普通 Agent；不允许通配全部智能体、按显示名称匹配、私有 Agent 或未验收的编码/远端来源。

多个当前租户角色的合法功能和 grants 可按既有规则取并集；读取时还必须验证当前成员、租户、目标 Agent 归属及可信会话 owner。权限撤销、解绑、转私有或来源失效 SHALL 在下一次读取生效；仅停用执行且读取条件仍有效时可读取已保存历史，但不允许新运行。

#### Scenario: 授权规划顾问并保留其他范围
- **WHEN** 管理员为“调研管理者”角色显式授予 `history.read`、`history.read_all` 及 `agent:enterprise-planning-advisor` 的 `history_read_all`
- **THEN** 该角色成员可读取本租户此共享普通智能体全部可信会话，不能因该 grant 读取其他智能体、私有 Agent 或其他租户的会话

#### Scenario: 多角色来源及撤销
- **WHEN** 两个角色都授予目标动作，随后分别撤销
- **THEN** 撤销一个时剩余来源仍有效，撤销最后来源后下一次列表/原文读取或报告生成被拒绝或回到本人范围，旧会话链接和缓存不延长授权

#### Scenario: 角色配置冲突或非法目标
- **WHEN** 提交过期版本、跨租户/私有目标或未知动作
- **THEN** 原角色事务整体拒绝并保留现有权限，不部分保存或按名称改用另一对象
