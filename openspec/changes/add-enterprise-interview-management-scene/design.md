## Context

动机与产品范围见 [proposal.md](proposal.md)。现有角色资源授权已支持 `agent:<id>`，会话和消息已有持久化；需求只需扩大指定 Agent 的历史读取范围，并从原问答生成一次报告。

| 接入点 | 本次职责 |
| --- | --- |
| `auth/policy.py`、现有角色/grant 服务 | 登记功能和 Agent 动作，复用保存/版本事务，保留显式目标范围 |
| `channel/web/fork/handlers/sessions.py`、`authorization.py` | 扩展读取授权及报告入口，写操作继续使用原 owner 守卫 |
| `agent/memory/conversation_store.py` | 在原存储按可信 tenant/agent/owner 查询，不复制访谈 |
| 现有角色编辑页、历史页及详情组件 | 配置授权、选择查询范围、只读问答、临时报告预览 |
| 现有模型客户端、身份、审计和配额服务 | 按真实请求者执行一次有时限的报告生成 |

已核对的代码约束：`_require_session_owner` 的名称不能代表已验证真实消息 owner；default Agent 有存储键映射；既有标题/提示优化能单次调用模型，但其 handler 不能直接当作本功能的完整授权和计量实现。报告也不能复用发送到原会话的接口，否则会违反 owner 和只读边界。上述为设计依据，不代表本功能已实现。

## Goals / Non-Goals

**Goals:** 复用角色及历史页完成指定智能体的跨用户只读管理；报告由单次请求生成，成功返回后可预览、下载。

**Non-Goals:** 新场景应用、企业档案、报告持久化、后台任务及版本管理、附件解析、长会话分段汇总、跨会话报告、代聊或修改访谈规则。

## Decisions

### 1. 保留现有两层授权，不新建权限体系

登记功能 `history.read_all` 和 Agent 动作 `history_read_all`，保存到既有 `role_resource_grants`，目标仍为 `agent:<id>`。本人历史沿用 `history.read`；跨 owner 读取增加新功能与明确目标 grant。角色编辑页复用已有功能权限和资源动作布局，不增加访谈专用角色、逐会话授权或权限配置页。

两层授权分别表达“能做什么”和“允许哪个智能体”，是现有机制的正常扩展，不能简化为看到 Agent 即可看到全部用户会话。管理员和平台 all 的原有 Agent 管理快捷分支不代替新动作的显式 grant；不扩大私有 owner 动作，不自动给内置角色或已有 grant 补权。目标仅限本租户共享普通 Agent，原多角色合并、事务和即时撤权规则复用。

### 2. 历史页只增加必要范围和只读详情

现有 `scope=all` 仍表示跨 Agent 的本人会话；新增 `read_scope=agent_all` 要求明确 `agent_id`。服务端先验证授权，再按可信 tenant、存储 Agent 键查询该 Agent 各 owner 的会话；不能用 `user_id=None` 充当全量标记。列表、原文、标题搜索和计数使用同一读取判定。

目标选项由当前目标 grant 提供最少标识/名称，不要求聊天使用权。沿用现有标题搜索、归档筛选及分页，增加创建人展示即可；本次不再新增创建人候选接口、时间筛选器或企业索引。覆盖原存储可识别的历史/进行中/已归档及可信已落盘渠道，不建设新的渠道同步或适配器，无归属数据不猜测放行。

他人记录在历史页内打开只读问答，不恢复到聊天输入框，不注入查看者身份，不返回内部 active_request/tool/run 控制数据。本人继续走原访谈入口。所有写动作保持真实 owner 守卫，读写共用存储定位但不共用允许集合。附件显示复用现有组件及文件权限，新历史授权不开放私人目录。

### 3. 报告按需返回，取消持久化任务和报告表

首版报告只服务稳定 ID `enterprise-planning-advisor` 且仍绑定当前租户的共享普通 Agent，不设计可配置报告目标列表或业务绑定表。增加一个鉴权 POST，在请求生命周期内读取问答、调用模型、返回完整 Markdown 和来源元数据。用独立临时上下文承载真实请求者，复用现有模型客户端与执行授权/凭据/计量，不向原 session 发送消息，不运行访谈工具循环。

完整结果在当前页面安全预览；浏览器将已获权响应生成本地 `.md` 下载，无需服务端保存、报告 ID、下载接口或持久链接。页面明示“报告不自动保存，请下载留存”，刷新/关闭后需要重新生成；切换身份、租户或会话时销毁临时结果及对象 URL，丢弃迟到响应。禁用本功能响应缓存和浏览器长期缓存，预览不执行 HTML/脚本或自动加载外部资源。

原方案的任务状态表、排队/领取、轮询、重启恢复、报告版本、新内容监听和删除清理，都是为了管理服务端留存的任务及报告。本需求尚不需要该能力，因此整组取消。代价是页面关闭不能继续取回结果，用户需下载留存；以后确有报告归档需求再单独设计。

### 4. 仅分析完整问答，一次模型调用

从服务端按已授权来源读取完整已保存问答，固定消息截止；输入及校验摘要只在请求内存中存在。首版不解析附件、不抓取 URL、不调用技能、Shell 或 MCP。正文里的资料摘要属于访谈陈述，报告明确未核验原件；已有访谈模板可作为整理固定报告提示的依据，不引入运行时知识检索或资料同步。

生成内容遵循报告规范，保留逐项工作输入/方法/输出、日周月频率与耗时、错误后果、资料缺口及场景价值/可行性。将问答视为待分析资料而非执行指令，用消息 ID 或序号说明依据，区分确认、未确认及建议。输入超出本次模型预算时直接给出限制，不静默截断，不引入分段任务或多次模型汇总。

受控调用前检查当前身份、CSRF、源读取、chat/Agent/model 使用、凭据及硬配额。返回前再次检查身份/读取权和来源；重读固定截止范围或复用已有版本标识来验证输入仍有效，若被删改则拒绝返回，仅追加问答则保留原截止。无需持久来源指纹或后台失效监听。已返回并下载的报告是当时的副本，不承诺远程撤回或自动更新。

### 5. 失败处理沿用一次请求的边界

页面生成中禁用重复点击；服务端复用现有并发限制、限流和配额，不新建幂等键存储、执行锁表或任务队列。输入、输出和模型调用均设上限，单次超时须小于部署实际请求/代理超时，防止连接先失效而模型长期运行。

超时、断开、重启和模型错误不自动重试，不承诺恢复结果。能取消时取消底层调用，不能取消的已发生用量按现有机制据实计量；只在完整成功且重新鉴权后返回报告。错误可解释且不泄漏敏感输入。多标签页的独立请求可能分别消耗模型额度，这是一次请求方案的明确取舍，不为“恰好一次”新增调度系统。

## Risks / Trade-offs

- [Agent 可管理被误当作历史可读] → 显式目标 grant；真实 tenant/owner 校验；原写接口单独回归。
- [只分析正文的信息不完整] → 报告标注未分析附件、未确认及资料缺口；原智能体继续收集材料和访谈。
- [长会话或模型响应超出上限] → 调用前预算检查和有界超时，明确失败；首版不承诺后台完成。
- [报告未下载即关闭] → 生成入口及结果区说明下载留存；原问答仍在原会话，可重新生成。

## Migration Plan

1. 先验收现有身份/租户、角色事务、审计和历史存储切片，核对并行历史 change；缺失依赖不以 mock 通过上线门槛。
2. 权限动作复用现有表结构；本次不新增数据库表或迁移访谈。验证升级不重写现有角色/grants、默认集合或空集合，只有管理员明确配置后才取得新权。
3. 使用现有配置机制增加一个默认关闭的新功能开关，统一控制新增跨用户读取和报告入口/API，原本人历史与访谈不依赖它。先完成跨用户读取和原写操作回归，再进入报告阶段检查真实模型/凭据/配额/审计切片。
4. 在验收租户明确授权一个 Agent，完成真实访谈查看、生成/下载及撤权测试后开启新功能。报告实际运行仍受现有权限、配额和可用性限制，不另建一套执行开关。
5. 回退关闭该开关并拒绝在途请求返回新功能结果；原会话无迁移可回滚。保留显式 grant 供兼容版本使用，旧版本必须能安全拒绝未知权限/动作，否则使用兼容修复版回退，不以扩权方式恢复服务。

## Open Questions
