## Why

用户反馈 code 类智能体历史会话无法归档和删除。当前实现已有对应接口，已确认的前端缺陷是删除最后一条当前编码会话后又自动创建远端会话；归档失败的具体原因仍需通过实际请求定位。本 change 聚焦修复这条操作链路。

## What Changes

- 修复删除最后一条当前编码会话后的跳转：关闭目标编码视图并进入空态，用户显式新建时才创建会话；普通会话保持原行为。
- 检查历史行菜单、所属 Agent、请求响应和刷新链路，按实际证据修复归档问题；复用本地归档和既有恢复入口。
- 在现有归档／恢复／删除处理函数中补齐必要的等待、防重复、错误提示和上下文检查；删除在途切换会话或身份后，旧回调不能错误跳转。
- 对删除路径的编码关联读取保留明确失败，避免异常被当作普通会话而只清理本地。沿用既有远端删除、失败保留、重复删除及文件保留语义。
- 增加针对上述缺陷的回归测试和实际页面验证，不扩建归档页，不重构远端会话生命周期。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `session-history-workbench`: 补充编码会话删除后的空态、操作等待与错误反馈，以及完成回调的目标一致性。
- `opencode-session-sync`: 明确删除时编码关联读取异常不得降级为普通会话清理。

## Impact

- 主要接入点为 `channel/web/static/js/console.js`，复用 `coding.js` 已有离开／挂载代次处理；必要时小幅调整 `channel/web/fork/handlers/sessions.py` 的删除分流及现有三语文案。其他文件仅在实际根因需要时修改。
- 继续使用现有 `GET /api/sessions`、`PUT /api/sessions/{id}`、`DELETE /api/sessions/{id}`，不新增 API、数据库字段或功能开关。
- 平台 `sessions` 持有归属、归档和置顶，`opencode_session_links` 持有远端关联及项目快照，OpenCode 持有正文和工具记录；数据归属不变，删除聊天保留项目和个人文件。
- 依赖既有历史权限、会话归属校验和 OpenCode 客户端，无新增跨 change 前置。与个人工作区、登录优化 change 的重叠代码按现有接缝合并，保留其他工作。
- 归档页搜索／分页／直接删除、当前会话归档状态栏、通用操作状态框架、创建／删除并发协议及停止确认轮询不纳入本次修复。现有权限、文件边界、服务开关与上游接缝保持不变。
