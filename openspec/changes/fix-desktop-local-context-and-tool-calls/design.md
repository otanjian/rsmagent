## Goals / Non-Goals

**Goals:**

- 选择本机目录后，当前会话能列出该目录的真实文件并读取文本。
- 绑定或设备失效明确报错，不把服务器默认目录内容当成本地结果。
- 修复实际模型工具协议问题；持续异常明确失败，正常工具调用保持兼容。

**Non-Goals:**

- 不增加本地 Shell、同步、写回或完整物化流水线。
- 不引入新存储、跨窗口 CAS 协议、全局当前目录或另一套执行状态机。
- 不实现通用 DSML 解析执行、语义引用分类器、自动纠错重试或旧历史改写。
- 不将全平台发行、更新、迁移演练重新纳入这个故障修复。

## Decisions

### 1. 连接现有接口，补齐缺失映射

沿用父 change 的配对 Web 创建业务绑定、原生解析并注册/关联 workspace 的顺序。主进程使用真实登记设备与可信身份，替换 IPC 占位，不把网页合成的 device ID 当作已登记设备。新会话先通过现有流程建立归属。

明确区分本机 `grant.id` 与服务端 `workspace_id`：它们分别生成，不保证相同。主进程保存“服务端 workspace → 本机活动 grant”的会话内映射，命令执行时重验；不能把页面的 `desktop:<grantId>` 原样当成服务端 workspace。

绑定确认后更新标签。取消保留原状态；失败显示原因。现有 capability/feature flag 控制入口，必要时补齐已有能力响应，不新建版本协商体系。

### 2. 每次发送明确引用，服务端重验

选中本机目录时，聊天发送和重新生成请求携带可选 `desktop_context`，包含 `binding_id`、`workspace_id`、`grant_version`；不含绝对路径。普通浏览器和服务器项目请求不携带此字段。

这是目标引用而非授权。消息入口用当前认证身份、配对关系、Agent 和业务 session 解析并校验，转换为可信运行上下文；`client_files` 消费该上下文，拒绝模型用其他 ID 替换。无效引用返回明确错误，不能当作“没选目录”继续执行。只有通过确认的来源才注入本地目录提示，服务器 cwd 独立沿用现有解析。

页面通过当前原生会话状态恢复引用；恢复失败显示断开。切换会话/Agent/身份先丢弃旧引用，迟到回调通过现有上下文代次或简单请求序号丢弃。对多窗口替换，复用已有 binding 撤销和版本检查：旧窗口收到失效后重新连接即可，不要求实时同步所有窗口。切回服务器项目清除本地引用并断开当前本地绑定。

### 3. 返回实际结果，不返回排队成功

核对并补齐主进程从已登记设备连接到文件命令消费的装配，沿用父 change 的 origin、lease、epoch、路径防护与操作白名单。本机后端仅使用主进程登记的 loopback 例外，远程连接遵守既有 HTTPS 规则，不增加直接读服务器路径的捷径。

`client_files` 对本次修复的 list/stat/search/read_text 在已有命令服务上有界等待终态，使用现有 run 取消信号；轮询即可，不引入消息总线或新的多 worker 协调框架。服务层补充必要的 runtime 结果查询/取消接缝时，仍校验当前身份、会话、绑定及版本。沿用父契约读取 60 秒、离线等待至多 30 秒上限。

仅 succeeded 且匹配的结果返回数据；失败/撤销/超时/取消返回错误，分页/截断如实标识。重复命令沿用现有去重。二进制传输和 materialize 由原桌面 change 负责，本次不重做；不得把不可用的读取操作宣传成已支持。

### 4. 先修模型出口，再增加小范围错误检查

先用无敏感内容的请求核对实际 provider、tools/schema、tool_choice、thinking 参数及 SSE 的 content/tool_calls。修正有证据的请求或适配错误；不能只清洗正文而跳过正常工具调用验证。若接口确实不支持所需协议，明确报告，不偷偷切换模型。

兜底检查放在相关适配/流结束接缝、写入成功历史和判定任务完成之前：仅针对本次已知的“无有效结构化调用、正文含明确 DSML calls/invoke 执行封装”返回 `tool_protocol_error`。实现使用小范围格式匹配并排除围栏代码/明确引用示例，不建设通用协议解析或语义分类服务；仅出现 DSML 字样不报错。

复用现有错误/最终内容事件，最终气泡、复制内容和新持久化结果显示失败原因，而非原始调用封装；已有流式临时内容可以在结束时被替换。本次不承诺任何片段均不会短暂显示，因此不需要预先缓存整个回答或新建流式撤回协议。验证完成状态与通知同样为失败，避免现有 done 传输事件被误计为成功。

不新增协议自动纠错重试，且该错误不能进入现有网络重试循环。结构化 tool_calls 始终是执行依据；正常调用沿用原处理，正文里的同名标记不能变成第二次调用，也不因出现一个标记就废弃合法调用批次。旧历史保持原样，不扫描改写或追溯执行。

### 5. 验证范围与依赖边界

实现顺序为：复现与契约核对 → 本地读取接通；模型修复可独立进行 → 合并验收。每条线路先确认实际消费的身份/路径/工具切片可用，已有测试与证据直接复用，不重新建立全套门禁文档。

最低完成证据：

1. 当前桌面实际选取临时目录，列出中文名文件和子目录，并读出已知文本；服务器默认目录放置不同文件，确认没有回落。
2. 绑定失败、断开/超时、取消、会话切换和旧响应各有针对性回归；普通 Web 和服务器项目行为不变。
3. 标准模型工具调用成功；已知 DSML 异常得到明确错误且执行次数为零；引用示例与正常结构化调用不受影响。
4. 当前模型出口真实冒烟与模拟响应测试分别报告，不能把模拟当成真实兼容证明。

当前环境验证不等于其他平台已通过。新增平台认证继续归原桌面 change；本修复沿用已验收平台及既有开关，不降低授权和路径约束，也不要求无关平台全部通过才修复当前环境。

## Risks / Trade-offs

- [实际设备消费可能只有辅助函数] → 必须补齐当前读取所需的最小装配；仅禁用按钮或通过 mock 测试不能算完成。
- [DSML 来源尚未确定] → 先检查实际请求；无法验证模型出口时明确保留未完成任务，不以“已经有报错”替代正常调用验收。
- [结束时才检测异常] → 最终内容可以更正，但不保证流中零瞬时泄露；接受这一边界，避免本次引入复杂流式处理。
- [旧窗口持有被替换的绑定] → 复用既有失效响应要求重连，无需新增并发版本和全窗口同步。

## Migration Plan

本方案不要求数据库迁移。旧目录候选及仅保存在前端的 `desktop:` 值需重新选择，不能迁成活动授权；旧历史、服务器项目和已提交副本保持不变。按已有开关部署，在实际链路验收后沿用原启用规则。

回退复用现有断开/撤销和文件能力关闭流程，取消本次等待，不修改本地源文件。相关调用指引与已知限制更新到既有用户文档，不新建一套运维体系。
