## MODIFIED Requirements

### Requirement: 入站消息只在渠道实例所属租户内执行

经某渠道实例进入的消息 SHALL 只在该实例所属租户内解析与执行，租户归属 MUST 以实例自身的登记归属为准，不由所绑定 Agent 或消息参数推断。符合显式访客策略的未知发送者或有效访客 SHALL 在执行前按 `im-guest-access` 建立必要映射及本租户成员；其余未绑定、非成员、停用或受限（含强制改密）账号 SHALL 拒绝且不调用模型或产生工具副作用。已有正式账号缺少成员或权限 MUST NOT 降级为访客。系统 MUST NOT 回退到全局默认或其他租户资源，访客目标沿用现有公共渠道的 Agent 绑定/本租户默认解析及授权规则。

#### Scenario: 其他租户成员向该渠道发消息
- **WHEN** 已绑定正式账号的用户并非该渠道实例所属租户的有效成员，却向该实例发送消息
- **THEN** 消息被拒绝并返回固定提示，不执行对话

#### Scenario: 未绑定的发送者
- **WHEN** 发送者尚未完成外部身份绑定且不满足已启用的访客接入条件
- **THEN** 消息被拒绝且不调用模型

#### Scenario: 实例绑定与实例归属不一致
- **WHEN** 某实例所绑定 Agent 的租户与该实例自身登记的租户不一致
- **THEN** 入站解析以实例自身归属为准，且 MUST NOT 因该 Agent 的绑定而放行到另一租户

#### Scenario: 访客不能自报其他租户
- **WHEN** IM 正文或模型参数声明另一租户
- **THEN** 开户和执行仍固定实例登记租户，跨租户请求拒绝

## ADDED Requirements

### Requirement: 访客访问复用现有渠道和成员配置

系统 SHALL 在「管理控制台 → 模型与接入 → 消息渠道 → 租户共享机器人卡片 → 编辑」增加“访客访问”，仅新增未绑定用户处理、访客角色及访客群 ID 白名单配置。存量及新建实例 SHALL 默认 require_binding，只有当前租户有效 tenant_admin 可为本租户 scope=tenant 实例启用 auto_guest。个人实例、无租户实例及越权请求 MUST 拒绝。角色 SHALL 属于本租户且仅具备合格普通使用权限，目标机器人和模型须满足当前授权；不新增访客 Agent 名单或复制能力授权目录。

配置 SHALL 复用实例 expected_version 和同库审计事务，省略新增字段表示保留，校验或审计失败整体回滚。访客群 ID 白名单 SHALL 默认空（仅私聊），通过可信消息群 ID 精确匹配并满足现有 @ 规则，不支持名称或通配。全局群白名单及 ALL_GROUP MUST NOT 绕过该实例名单；普通已绑定用户沿用原群规则。模型、工具、附件和运行额度 SHALL 继续使用既有能力与授权/配额规则。

成员页 SHALL 标识 IM 访客并复用已有停用/恢复，外部绑定弹窗展示映射停用状态并复用原账号绑定操作恢复；单人停用作用于当前租户全部机器人，其他租户不受影响。渠道改为 require_binding SHALL 阻止该渠道全部访客，但不改变正式账号资格；重开 MUST NOT 恢复账号、成员、映射或角色的独立停用/撤销。不新增独立访客列表或按人按实例状态。

#### Scenario: 在既有卡片开启访客
- **WHEN** 租户管理员提交当前版本、auto_guest 及合法访客角色且依赖切片已通过
- **THEN** 原子保存策略并提示不能登录平台，机器人目标及能力继续来自现有配置

#### Scenario: 非法配置或冲突
- **WHEN** 操作者无权、实例为个人/无租户、角色越界或含管理权限、必要资源不可用、版本过期或审计写入失败
- **THEN** 服务端拒绝整次修改，保留原配置；版本冲突不覆盖页面草稿

#### Scenario: 群聊没有明确准入
- **WHEN** 访客从未列入当前实例访客群 ID 名单的群发消息，即使发送者已有访客账号或全局设置 ALL_GROUP
- **THEN** 消息拒绝，不因私聊开户或渠道全群开关获得该群访问

#### Scenario: 停用成员及重开渠道
- **WHEN** 管理员停用本租户某访客成员，之后关闭并重新开启渠道访客模式
- **THEN** 该成员在本租户所有机器人仍不可用，其他租户不受影响，历史保留
