## Why

未关联平台账号的飞书、企业微信等 IM 用户需要先绑定账号才能使用共享机器人。租户管理员应能选择自动创建 IM 访客，让这些用户直接使用对应机器人，同时明确禁止其登录平台。这里的“临时”表示未关联正式账号，身份和历史仍需稳定保存。

## What Changes

- 在既有 User 上增加 `account_type = normal | im_guest`；复用 Membership、外部身份映射和角色授权，不增加成员访问类型。昵称作显示名，可信 `(provider, issuer, subject)` 决定唯一身份，系统生成内部账号名。
- 在「管理控制台 → 模型与接入 → 消息渠道 → 租户共享机器人卡片 → 编辑」增加未绑定用户处理（默认要求绑定／自动创建 IM 访客）、访客角色，以及默认空的访客群 ID 白名单（空表示仅私聊）。机器人目标及 @ 触发沿用现有规则；模型、知识、工具和额度沿用现有授权与配额。
- 首条获准消息原子创建必要账号、成员、所选普通角色关联、外部映射及审计，随后以访客身份执行；重投复用身份。已有正式账号继续使用原资格，停用成员和已撤销权限不会被重新开户恢复。
- 访客没有可用密码，也不能取得或使用 Web/Desktop 登录会话和个人 API 凭据；普通密码重置不能改变账号类型。访客模式跳过首个私聊发送者认领创建者的路径。
- 实际执行继续检查成员权限，并以当前渠道的访客角色收窄范围，避免不同渠道的角色并集扩大权限；当前限制随模型、工具和子运行传递。只允许已验证的租户共享 IM 来源。
- 单人停用复用租户成员 active，作用于该访客在本租户的全部机器人；关闭某渠道的访客模式只阻止该渠道访客。访客解绑在现有映射行保留停用标记，防止下一条消息重复开户；不新增实例访客关系表或独立撤销表。
- 本期不做正式账号关联、转正、历史迁移、自动到期清理、按人按实例封禁、独立访客管理页或新开户配额体系。这些扩展不作为本需求交付前置。

## Capabilities

### New Capabilities

- `im-guest-access`: 稳定访客身份、受控原子开户、停用不复活、可信 IM 运行和数据隔离。

### Modified Capabilities

- `external-identity-binding`: 未绑定消息的显式访客例外、停用映射识别和访客解绑后禁止重新开户。
- `user-membership`: 管理员策略预授权开户例外，复用成员与角色管理，禁止访客凭据及管理员升级。
- `identity-session`: 在既有认证和会话边界拒绝访客，普通账号规则保持。
- `tenant-channel-configuration`: 现有渠道编辑增加访客模式、角色和必要群范围，默认关闭并按实例所属租户执行。
- `role-resource-authorization`: 现有成员授权与当前渠道访客角色取交集，并用于实际调用。

## Impact

- **数据**：`identity.db` 仍是唯一身份真值。追加 User 类型、渠道策略字段和外部映射 active；复用现有账号、成员、角色、映射、版本及审计，不新建访客身份或访问关系表。
- **后端**：修改 `auth/store.py`、`auth/service.py`、认证/会话边界、`channel/external_identity.py` 与可信运行上下文；在统一渠道入口实现，提供方适配器只提供可信消息身份。
- **界面**：扩展现有 fork 渠道 handler、渠道卡片及翻译；成员页显示 IM 访客类型并沿用已有停用/恢复，不新增一级菜单。
- **依赖**：复用审计、凭据、资源授权、配额及实际开放工具所需审批/隔离切片；`add-shared-agent-release-governance` 涉及相同渠道和资源域，实施时保留有效公共发布版本规则，不等待整份 change。
- **交付**：先完成身份与登录拒绝，再验收 IM 运行与界面，最后逐实例启用。迁移默认普通账号、有效旧映射和要求绑定；关闭策略可停止访客，旧构建不能忽略新账号类型。此次仅调整规划产物。
