## Context

本需求是“未绑定 IM 用户可使用对应共享机器人，但不能登录平台”。审查发现原稿把后续身份转正、多级访问状态和专用管理功能纳入首期，增加了不必要的存储、界面与授权分支。本次收敛范围，保留必要的身份和权限边界。

| 现有接缝 | 可复用行为／必要调整 |
| --- | --- |
| `auth/store.py` | 已有 User、Membership、角色关联、唯一 external_identities；只追加必要字段 |
| `auth/service.py::find_user_for_external_identity` | 目前未绑定与账号停用都返回空；必须查询原映射和状态，只有确实不存在时才能开户 |
| `channel/external_identity.py` | 统一决定身份；auto_guest 跳过 `claim_instance_for_sender`，保留挑战与个人路由优先、失败不回落访客 |
| `auth/runtime.py`、`common/runtime_identity.py` | 已传递真实用户和租户；增加可信实例与外部映射引用，以当前渠道角色收窄现有授权 |
| `auth/service.py::login`、`auth/session.py`、桌面授权 | 复用统一账号资格检查，覆盖会话签发与消费 |
| 飞书、wecom_bot 的群规则 | 当前适配器会设置全局 ALL_GROUP，无法据此限制单个租户实例，需最小的访客群 ID 白名单 |
| 现有渠道编辑、成员管理、资源角色、配额 | 增加模式/角色/访客群 ID 白名单和访客类型提示，其余沿用现有入口与规则 |

## Goals / Non-Goals

**Goals:**

- 获准的首条 IM 消息自动建立稳定访客，后续复用，不要求平台登录或改密。
- 每次运行使用真实访客、当前租户及机器人授权，停用和撤权可生效。
- 管理员在现有渠道和成员页面完成配置、查看及停用。

**Non-Goals:**

- 关联已有正式账号、访客转正、历史迁移和自动过期清理；本期 account_type 不提供变更操作。
- 新增 Membership 访问类型、实例访客关系表、独立撤销表、访客管理页面或开户配额系统。
- 重复配置 Agent 名单和附件/记忆开关，或建设新的群管理模块；访客发起独立后台任务或取得本机任意代码执行资格。

## Decisions

### D1. 最小数据变化，复用已有状态

User 增加 `account_type = normal | im_guest`，旧账号默认 normal。访客 `active=true` 才能使用 IM，禁止登录由 account_type 决定，不能用 active=false 代替。保留 password_hash 非空约束，保存明确不可验证标记（拟用 `!im_guest`），不生成初始密码，must_change_password=false；解析器必须拒绝该标记，账号类型检查仍为强制门槛。

Membership 不增加字段。只有缺少本租户成员关系时，自动创建成员并分配渠道选定的普通角色；已有成员不自动追加角色、不恢复停用或移除过的授权。不同渠道使用不同角色或更换角色后，若已有成员授权不足，管理员通过现有成员页调整。这样避免为每次访问建立另一套角色同步及访问关系。

external_identities 增加 `active`（存量 true）。访客解绑将原行置为 false，保留唯一三元组和 user_id；再次发消息拒绝。恢复复用有权管理员对原账号的显式绑定操作，只能恢复原映射，不恢复账号/成员状态或角色。普通账号解绑继续沿用原删除语义。访客映射本期不能转给另一账号，普通冲突规则保持；未来正式账号关联需另行设计。

内部 username 使用唯一系统标识，IM 昵称仅作为经长度与显示处理的 display_name。不能用昵称匹配已有账号或因改名重复开户。

### D2. 配置保留模式、角色和必要群范围

入口为「管理控制台 → 模型与接入 → 消息渠道 → 租户共享机器人卡片 → 编辑 → 访客访问」。增加：

1. `unbound_user_policy = require_binding | auto_guest`，默认 require_binding。
2. `guest_role_id`，开启时必选本租户普通角色，复用现有角色的功能、资源 grants 和默认模型；不得包含管理员或身份/配置管理能力。
3. `guest_group_ids`，默认空，仅允许私聊；需要群聊时填写明确的提供方群 ID，不支持通配或按群名称匹配。

所用机器人仍由实例 agent_id 或本租户公共默认 Agent 解析。访客角色必须有该目标及模型的使用权；默认目标变更后重新检查，不新增第二份 Agent 允许列表。子智能体也按既有委派规则及当前访客授权检查。

私聊沿用现有入口；群聊必须命中当前实例 guest_group_ids 并满足现有 @ 触发规则。代码中通用白名单是全局配置，且飞书、wecom_bot 初始化会设置 ALL_GROUP，不能视为租户管理员授权。因此保留这一必要字段，以可信消息中的群 ID 校验，不增加群目录、群管理页或其他群配置；全局允许全部群也不能放行未列出的访客群。附件、知识和工具复用 Agent 开放能力与角色权限。调用沿用现有租户/用户 messages、tokens、tool_calls 等配额及入口限流，本期不增加开户计量、时效或独立配额管理。

仅有明确 tenant_id 的 scope=tenant 实例可启用，个人实例及无租户平台渠道拒绝。三个字段直接随现有渠道 expected_version 和审计事务保存，旧客户端省略字段表示保留。启用前检查角色、公共目标、模型和必要安全切片；无法检查时拒绝启用。角色后来失效或混入管理权限时，访客调用拒绝，不借管理员旁路执行。

### D3. 开户是原子操作，不重建已知身份

顺序为：验证提供方消息与三元组 → 校验实例归属/状态、凭据及消息范围 → 既有验证挑战/个人路由 → 查询映射和账号状态 → 必要时访客开户 → 授权与配额 → 执行。

auto_guest 的未知发送者不调用“首个私聊发送者认领创建者”。已有正式用户完全按原成员与角色规则处理，缺少成员或权限不能降级成访客。有效访客可在另一个开放租户建立缺失成员关系，但既有停用关系不恢复。查询故障不能当作不存在。

写事务重验当前实例策略、租户、映射、成员和角色；必要时创建 User、Membership、角色关联、外部映射，与成功审计一起提交。审计记录真实发送者、预授权渠道/版本及其管理员来源，不伪造管理员在发送这条消息。唯一约束处理并发，冲突后读取最新合法结果，不能覆盖绑定。提交后首条消息继续派发；消息重投继续复用既有去重机制，不另建通用幂等平台。

开户和计费仍各在现有职责边界内处理；若开户成功后调用配额拒绝，允许保留已创建访客记录，下次复用，不承诺跨存储回滚。既有配额未配置/故障的行为须符合 resource-quota 主规范，不能因访客另加无限额回退。

### D4. 在既有授权上收窄，不产生新的登录身份路径

有效权限 = 当前成员角色授权 ∩ 当前渠道访客角色授权 ∩ 既有租户/资源归属/Agent/消费者限制。选定角色的当前内容在实际调用时检查，不能只在首次开户复制一次。空集合拒绝，同一访客在其他渠道取得的角色不能扩大本渠道权限。

运行上下文补充可信 IM 来源、instance_id 和 external_identity_id（连同现有 user/tenant/agent/session），由服务端解析，消息正文和工具参数不可覆盖。实际模型、知识、工具、子运行及结果投递沿用现有授权边界重读当前状态，映射必须仍有效且指向同一 user，群来源仍须在当前名单中，不新增访客访问版本或权限快照。缺少可信实例来源的 im_guest 拒绝执行。

共享群会话保留真实发送者，不能注入个人私聊记忆；私聊、文件和历史继续按现有租户/用户/来源隔离。IM 文件回复走已有投递路径，不发平台登录令牌。访客模式关闭、映射/账号/成员停用或角色撤权后，阻止新调用和后续动作，回复前重验；已发生副作用如实记录，不新增全局运行扫描或假称全部回滚。

所有现有 Web/Desktop 登录、AuthSession 创建/消费、桌面 token 兑换及个人 API 凭据入口使用账号类型门槛。im_guest 和未知类型不得取得或使用平台凭据；普通改密、重置、角色调整、绑定操作不能修改 account_type。普通账号的认证及租户选择语义保持原样，无需新增 im_only/standard 租户过滤。

### D5. 停用复用现有管理入口

成员页标识“IM 访客”，继续使用已有列表、角色调整及 active 停用/恢复；现有外部绑定弹窗显示映射停用状态并支持有权管理员恢复原映射；不新增渠道访客列表。单人停用作用于本租户全部机器人，其他租户不受影响。平台账号停用影响该账号所有租户。某渠道改为 require_binding 后，该渠道的全部访客都拒绝，已有正式用户资格不受影响。

重新开启渠道不恢复停用账号、成员、映射或已撤销角色。按人按实例封禁、独立到期时间和正式身份转正均留待实际需求，不为这些未来功能预建状态机。管理员操作仍沿用现有权限、版本和同库审计。

### D6. 两个实施阶段，按实际切片验收

1. **身份与认证基础**：追加迁移、访客不可用密码、认证入口拒绝、带状态映射解析通过；策略仍关闭。审计和身份唯一性是后续开户的前置。
2. **IM 接入与配置**：原子开户、当前渠道授权、数据隔离、停用、界面及实际开放能力的配额/审批/隔离切片通过后，分别验收飞书和 wecom_bot，再逐实例启用。其他提供方必须独立验收。

不建设“验收状态管理系统”；通过既有发布证据和渠道就绪检查控制开放。与 `add-shared-agent-release-governance` 在渠道和资源域协作，保留有效公共发布版本、私有 owner 和委派边界；不等待整份 change。`optimize-console-login-startup` 不改变账号资格，继续保留普通登录回归。

## Risks / Trade-offs

- **转正延期**：自动开户后的同一外部身份本期不能自动关联正式账号，页面说明限制；未来另立 change，不通过重置密码绕过。
- **停用粒度**：本期单人停用影响本租户全部机器人；按人按实例封禁需要额外访问记录，暂不引入。
- **角色切换**：不自动同步既有成员授权，切换角色后权限不足可能需要管理员调整；这是复用现有撤权语义的取舍。
- **开户增长**：身份持久保存，没有本期专用开户额度和自动清理。管理员可收紧访客群范围、入口限流或关闭访客；运行成本仍由既有硬配额控制。
- **解绑复活**：只增加现有映射的停用标记，不能删除访客唯一身份依据后又允许自动开户。
- **来源或授权丢失**：实际执行拒绝，不能以创建者、默认 member 或进程身份代跑。

## Migration Plan

1. 在备份上追加迁移：User.account_type、渠道模式/角色引用/群 ID 名单、external_identities.active；存量 normal、require_binding、映射 active。不修改历史迁移，不回填访客或新增成员访问类型。
2. 先部署具备账号类型和访客授权守卫的 Web/渠道/worker，完成阶段一检查后再启用阶段二功能；不让不理解访客的旧进程处理访客。
3. 在合成飞书、wecom_bot 实例分别验收，保留构建 SHA、配置版本与结果。仅更新文档不代表完成真实渠道验证。
4. 回退先关闭访客接入并处理在途，保留身份、历史和映射停用标记。只使用理解访客限制的兼容构建，或停机一致恢复代码、身份库及关联业务数据，不把访客改成普通账号适配旧代码。
