## MODIFIED Requirements

### Requirement: 多租户代码执行必须隔离

database 模式下，Agent 发起的任意代码执行（技能脚本、bash 及任何派生子进程的工具）SHALL 在操作系统强制的隔离边界内运行，MUST NOT 直接读取其他租户的 workspace、identity 数据、凭据或系统敏感路径。隔离边界 SHALL 以当前主体实际获准的租户、个人、Agent、项目根和必要运行时只读根为限，路径穿越、软链接逃逸与用户提供的未授权目录 MUST 被拒绝。隔离策略 SHALL 在服务端强制，不能仅依赖提示词、前端隐藏或命令字符串参数检查；解释器运行时拼接路径和派生进程的访问同样受约束。

客户端执行的边界 SHALL 以当前有效的原生项目授权根、获权只读技能资源、隔离临时目录及必要解释器/系统库的只读路径为限。原生选择本机目录 SHALL 只为对应设备、用户、租户、Agent 和会话登记所需项目根，不能使其成为全租户通用根；该客户端路径 MUST NOT 被登记为远程服务器可访问根。本机脚本与派生进程 SHALL 由实际有效的执行边界约束；仅切换 cwd、参数字符串检查、设置环境变量或启动子进程 MUST NOT 被作为本机脚本隔离已验收的证明。

屏蔽区（用户 home、全局数据根、其他租户共享根）SHALL NOT 遮蔽本租户任一合法读/写根：路径仅在「落在屏蔽区**且**不属于本次执行实际获准的合法根」时才拒绝。部署实例根（`agent_workspace`，缺省 `~/cow`）与 operator 配置的租户基目录（`tenant_shared_base` / `COW_TENANT_BASE`）位于 home 之下时，本租户对其自身获准根的访问 MUST 被放行，而同一 home 中未被登记为合法根的路径（如凭据目录）MUST 继续被拒绝。屏蔽区的加入 MUST NOT 再依赖「默认智能体工作区」这一单一来源。

租户共享根包含其他用户私有子目录时，父目录授权 SHALL NOT 扩大这些子目录的既有 owner 边界；隔离视图 MUST 排除未授权私有子树。执行进程 MUST NOT 通过全局临时目录、父进程环境、继承文件描述符、宿主进程视图或管理 socket 取得其他任务的数据与控制面能力。

#### Scenario: 跨租户路径读取被拒绝
- **WHEN** 某租户的 Agent 尝试让技能或 bash 读取另一租户目录或 identity 数据
- **THEN** 执行前可判定的引用被拒绝，运行时产生的越界访问由 OS 拒绝，不返回其他租户内容，也不因同进程或共享凭据放行

#### Scenario: 路径穿越或软链接逃逸
- **WHEN** 请求路径经 `..`、符号链接、绝对路径或校验后的链接替换指向隔离根之外
- **THEN** 越界引用或实际访问被拒绝，不把已登记根当作所有子路径安全

#### Scenario: 本租户根位于 home 之下
- **WHEN** 默认智能体拥有位于实例根之下的私有工作区，且租户共享根为实例根或 operator 配置的租户基目录，二者均位于 home 之下
- **THEN** 当前主体仍可在其原有授权范围内通过文件工具和 bash 访问自身共享资源、Agent 工作区与用户根，不因父级 home 屏蔽而失败

#### Scenario: home 内非本租户路径仍被拒绝
- **WHEN** 某租户的 Agent 尝试读取同一 home 下未被登记为合法根的路径或全局数据根
- **THEN** 访问被拒绝，不因本租户根位于 home 之下而放宽

#### Scenario: 解释器构造路径并派生进程
- **WHEN** 任务用解释器拼接受保护路径，或启动子进程访问该路径
- **THEN** 即使命令参数中没有明文路径也不能读取或改写目标，前台和后台执行结果一致

#### Scenario: 共享根包含另一成员私有数据
- **WHEN** 成员 A 的执行任务访问共享根下属于成员 B 的私有目录或其他任务临时文件
- **THEN** 访问被拒绝，A 对其既有获准共享文件和本人目录的访问继续成功

#### Scenario: 真实脚本绕过参数检查
- **WHEN** 本机脚本通过动态构造路径、派生进程或链接替换访问未授权路径
- **THEN** 实际执行边界阻止访问；无法证明阻止的平台不开放本机脚本执行能力

#### Scenario: 本机授权不扩散
- **WHEN** 另一个会话或远程服务器尝试使用已登记的本机绝对路径
- **THEN** 未取得同一设备作用域授权的调用被拒绝，不因本机项目已打开而获得权限

### Requirement: 权限模式在租户语境下收紧

现有会话权限模式（read-only / workspace-write / full-access）在 database 多租户下 SHALL 按执行目标的获权隔离根收紧解释。服务器 `workspace-write` 只允许在该租户工作根与获权 Agent 状态目录内写入；本机项目 `workspace-write` 只允许在当前原生授权项目根及运行临时目录内写入，本机技能缓存保持只读。`full-access` MUST NOT 突破对应隔离边界或访问其他租户/全局敏感凭据。只读 grant、只读会话或未开放脚本能力的设备 MUST NOT 因选择项目而升级权限。

#### Scenario: full-access 不突破租户边界
- **WHEN** 某租户会话以 `full-access` 运行
- **THEN** 仍受执行目标的隔离根约束，不能读取其他租户目录或全局明文凭据

#### Scenario: 只读项目请求写入
- **WHEN** 会话或原生项目授权为只读而技能请求修改文件或执行可写脚本
- **THEN** 写入和相应执行被拒绝，不以技能已获权替代项目写权限

#### Scenario: 项目内写入而技能缓存只读
- **WHEN** 获准技能生成项目报告并尝试修改其缓存脚本
- **THEN** 项目报告可按权限写入，缓存修改被执行边界拒绝
