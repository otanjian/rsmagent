# 6.5 服务端侧场景：只重启网关 / 只重启 Web（2026-10-14，本机测试实例）

环境：仓库 `app.py`（`127.0.0.1:9899`）+ `integrations.desktop.gateway`（`127.0.0.1:9877`）+ TLS 分流终止器（`https://127.0.0.1:8443`：`/api/desktop/connect`→网关，其余→Web）。客户端信任本地 CA。测试数据根与测试配置见 `local-test-server-3-5-remote.md` §1。

## 1. 基线

| 端点 | 结果 |
|---|---|
| `/api/desktop/meta` | **200** |
| `/api/desktop/connect` | **401 `auth_required`**（路由已发布） |
| `/auth/check` | **200** |

## 2. 场景 A：只重启**网关**（Web 不动）

| 阶段 | `/api/desktop/meta` | `/api/desktop/connect` | `/auth/check` |
|---|---|---|---|
| 网关停止中 | **200** ✓（Web 正常） | **502** ✓（设备通道断开） | 200 ✓ |
| 网关恢复后 | 200 | **401** ✓（回到鉴权门） | 200 |

→ 即任务 6.2/6.5 要求的"**网关失败而业务/聊天正常**"：两个面**分别**呈现，互不冒充。

## 3. 场景 B：只重启**Web**（网关不动）

| 阶段 | `/api/desktop/meta` | `/api/desktop/connect` | `/auth/check` |
|---|---|---|---|
| Web 停止中 | **502**（业务面断开） | **401** ✓（**网关独立存活**） | **502** |
| Web 恢复后 | 200 | 401 | 200 |

## 4. 这两组结果说明了什么

1. **Web 与网关是两个独立进程**：任一停止时，另一面仍按自己的契约回答（不是一起 502、也不是把失败转嫁给对方）；
2. **设备通道的"不可用"与业务的"不可用"用不同状态表达**（502 vs 401），符合规范"缺口能力不得隐式降级"与"分别检查探测/页面/WSS"；
3. 与生产对照：生产上 `/api/desktop/connect` 是 **404**（路由未发布）→ 表现为客户端每 ~30s `1006:handshake_failed`；本机测试实例发布该路由后为 **401**（鉴权门）→ 说明**生产只需补反代与网关**，客户端的重连行为本身符合预期。
