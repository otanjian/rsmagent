## ADDED Requirements

### Requirement: 远程桌面部署提供兼容的同源安全入口

远程桌面部署 SHALL 提供明确 HTTPS origin、可验证的证书链和兼容的桌面 metadata、原生授权及工作台入口。metadata SHALL 直接返回 JSON 且不被代理登录重定向或缓存。部署说明 SHALL 区分服务器执行、本机模式和未开放本机能力，不把普通聊天连接成功视为本机执行验收；远程 origin 不支持的子路径形态 SHALL 明确拒绝。

#### Scenario: Windows 客户端连接正式域名
- **WHEN** 真实 Windows 客户端连接经 HTTPS 代理的服务器
- **THEN** metadata、协议协商、浏览器授权、配对、聊天与流式响应成功，实际运行版本可追溯且无需本机 Python

#### Scenario: 企业证书或内网部署
- **WHEN** 部署使用企业 CA 或经 VPN 访问的内网域名
- **THEN** 分别验证客户端探测、容器页面及适用 WSS 的信任与可达性，不以浏览器单独可访问作为全部通过证据，不关闭证书校验

### Requirement: 远程设备网关显式代理并保持身份一致

使用桌面设备通道的部署 SHALL 将同源 `/api/desktop/connect` 正确转发至实际网关，支持 WebSocket Upgrade、心跳及重连，并提供网关进程管理与就绪诊断。Web 应用和网关 SHALL 使用同一权威身份及命令存储配置；网关内部端口 SHALL 限于受控网络，不要求客户端公网入站。代理 MUST 保留来源校验、认证及既有流式与压缩边界。

#### Scenario: 独立网关握手及重启
- **WHEN** 代理转发设备连接到独立网关，随后网关重启
- **THEN** 当前身份被正确验证，连接可恢复且旧连接不扩大目录或工具授权，Web 服务状态不被假定等同网关就绪

#### Scenario: 网关路由误配或身份存储不一致
- **WHEN** WSS 转发到错误端口或网关与 Web 使用不一致的身份配置
- **THEN** 部署验收失败并指明设备通道原因，不以重新登录作为修复代理的替代，不错误宣传本机能力可用

### Requirement: 远程桌面运维记录可重现的连接与恢复条件

部署说明 SHALL 列出客户端版本、应用与网关启动方式、实际代理端口、HTTPS/出站网络条件、模型及工具依赖、持久化范围和升级回退步骤。验收 SHALL 使用合成数据覆盖真实 Windows 安装包、账号/租户隔离、上传回读、断网恢复、会话撤销与服务重启。文档及日志 SHALL 明确服务器数据与本机授权根的唯一归属，不上传本机绝对目录。

#### Scenario: 重建远程服务
- **WHEN** 按部署说明重建 Web 或网关服务并重新连接客户端
- **THEN** 配置、账号、已提交业务数据与上传文件保留，客户端按当前会话重验，不以旧缓存伪造就绪

#### Scenario: 升级和回退候选部署
- **WHEN** 操作者按指定版本升级或回退
- **THEN** 保存应用、客户端和代理配置版本记录，验证协议兼容和恢复行为，不混用未验收的产物
