## Context

需求动机见 `proposal.md`。当前菜单翻译由 `channel/web/static/js/i18n/navigation.js` 的 `menu_skills` 提供，页面主标题来自 `channel/web/static/js/i18n/core.js` 的 `skills_title`。`console.js` 的 `VIEW_META.skills` 已让导航标题消费同一菜单翻译，无需修改导航逻辑。

`channel/web/chat.html` 的静态默认文案仍有「工具与技能」「技能管理」，对应 `templates/layout/sidebar.html` 与 `templates/views/skills.html` 则使用「能力」。实际 Web 页面加载 `static/js/i18n/*.js` 命名空间；`static/js/core/i18n.js` 是旧字典，现有 i18n 覆盖测试明确检查它未被页面加载。原生 Desktop 另有独立字典，不属于此次 Web 菜单更名的接入点。

## Goals / Non-Goals

**Goals:**
- 通过现有翻译键完成新名称切换，保持导航元数据与运行行为稳定。
- 统一实际页面和对应模板的默认文字，避免翻译应用前出现旧名称。

**Non-Goals:**
- 不重命名翻译键、视图、路由或服务端接口，不调整技能与工具配置。
- 不做全仓库「能力」字符串替换，不重写旧字典，不调整原生 Desktop 或智能体详情页签。

## Decisions

1. **只更新两个展示键。** `menu_skills` 与 `skills_title` 的 `zh`、`zh-Hant` 均改为「能力中心」，`en` 改为「Capability Center」。现有导航标题继续引用 `menu_skills`。单改侧栏会违反正式规范的名称一致性要求；新建翻译键则会增加不必要的引用迁移。
2. **同步 HTML 默认文案和翻译快照。** 定向修改 `chat.html` 与两个对应模板的 `data-i18n="menu_skills"`、`data-i18n="skills_title"` 默认文字，快照只更新对应语言下这两个键。保留「探索工具与技能」等独立描述，不将其当作正式页面标题。
3. **在既有导航规范中更新映射。** 完整保留「全部旧入口有明确迁移结果」要求的原有场景，更新技能入口名称并补充多语言、旧地址、默认文案和范围边界的验收场景；不新建能力域，也不复制技能工具服务端授权规范。
4. **沿用已有验证。** 运行现有 i18n 覆盖与快照对齐测试，并检查真实页面的侧栏、顶部及主标题。此次可逆文案修改无需新建仅断言固定字符串的测试套件。

## Risks / Trade-offs

- 修改旧字典而页面不生效 → 以 `chat.html` 实际脚本引用和已存在的 i18n 覆盖测试为依据，修改命名空间字典。
- 默认 HTML 与翻译结果不一致 → 同步主页面与对应模板的目标文案，检查首次加载和刷新。
- 全局替换误改智能体页签 → 仅按两个目标翻译键定位，审查差异中其他「能力」文案未被修改。
- 较长名称在收起侧栏或窄屏显示不全 → 使用已有布局进行目视检查，确认名称提示、当前项与点击区域可用；只有实际发现问题才调整样式。

## Migration Plan

1. 实施前核对当前页面仍加载上述翻译命名空间及目标 HTML，确认既有导航、权限和 i18n 测试可作为本次基线；无新增跨 change 前置。
2. 完成文案及快照同步后，运行已有 i18n 定向检查，再检查页面语言切换、刷新、旧地址与 classic/split 名称一致性；保留实际验证记录后才标记实施完成。
3. 随正常 Web 静态资源发布，无数据库或业务数据迁移；使用既有资源版本机制，无需新 feature flag。现有 classic/split 开关两侧均应显示新名称，不改变任何消费者启用门槛。
4. 恢复时回退本次字典、HTML 与快照改动即可，原地址和资源数据继续有效。

无未决实施参数。当前文档仅定义后续实施与验收方式，不表示产品代码已修改或页面验收已通过。
