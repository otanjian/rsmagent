## Purpose

定义 Windows 桌面端在用户明确授权的本机项目内执行有限文件操作的可靠行为，涵盖句柄锚定、可观察写入、协议兼容及真实平台门槛，使本地与远程工作台使用同一文件来源而不自动获得脚本或系统访问能力。

## ADDED Requirements

### Requirement: Windows 文件工具独立于任意脚本执行开放

系统 SHALL 在已验收的 Windows x64 与本地 NTFS 目录上提供 ls、search_files、read、write、edit，并分别声明读取/写入可用性。本机与远程模式 SHALL 使用相同文件操作授权，不要求系统 Python、Rust 或管理员权限。文件工具 MUST NOT 执行脚本、Shell、项目插件或调用普通无隔离 worker；未支持环境返回明确原因。

#### Scenario: 本机和远程处理相同项目
- **WHEN** 获权用户分别在本机模式与远程 HTTPS 模式打开同样内容的 Windows 本机项目
- **THEN** 五种操作作用于所选本机目录，服务器同名哨兵不变，缺本机 Python 不影响文件操作

#### Scenario: 请求 Shell 或不支持的存储
- **WHEN** 经文件工具请求 bash/PowerShell/cmd，或选择未验收的网络盘、UNC、非 NTFS 目录
- **THEN** 对应操作明确拒绝，不替换为服务器执行、路径检查后直接 spawn 或虚假成功

### Requirement: 本机文件访问锚定原生目录对象

本机文件工具 SHALL 将授权绑定到原生选择的实际目录对象，按句柄及对象身份限制每次枚举、读取和写入。根或中间组件被替换、reparse point、路径别名、ADS、设备路径、越界和不安全硬链接写入 SHALL 在产生越界效果前拒绝。字符串规范化、最终路径前缀或事后比对 MUST NOT 单独作为防替换边界。

#### Scenario: 校验后替换中间目录
- **WHEN** 外部进程在请求解析与文件打开间将中间目录替换为 junction 或其他对象
- **THEN** 操作只作用于仍受原句柄约束的对象或失败，根外哨兵内容与元数据不被读取/修改

#### Scenario: 特殊路径和硬链接
- **WHEN** 请求含盘符相对路径、ADS、设备名称、大小写/短名别名逃逸或指向根外对象的硬链接写入
- **THEN** 安全拒绝或规范化为同一已授权对象后按原权限处理，不经别名扩大权限

### Requirement: 有限文件写入具有版本和明确发布状态

读取 SHALL 返回绑定项目/路径、对象及内容版本的不透明版本值；覆盖与编辑 SHALL 携带expected_version并在写前验证，新建要求不存在。缺失或过期 SHALL 无写入地返回错误，不能套用旧执行后的告警语义。替换 SHALL 避免半文件，保持目标访问权限及声明支持的属性；不能安全保持时发布前拒绝。并发串行且检查冲突，不承诺任意外部编辑器的跨进程事务；失败/取消报告真实效果，不清理用户原文件。

#### Scenario: 外部编辑器更新源文件
- **WHEN** AI 基于旧版本提交编辑，而磁盘上文件已更新
- **THEN** 返回冲突并保留待提交内容，不静默覆盖；新建目标已存在时同样不冒充首次创建

#### Scenario: 缺版本或冲突后的重试
- **WHEN** 覆盖/edit缺预期版本或版本已过期
- **THEN** 拒绝写入，调用方重新读取并重建修改后重新提交，不自动覆盖或换命令ID重放旧意图；面板与模型使用同一规则

#### Scenario: 目标权限比目录更窄
- **WHEN** 替换具有独立收紧DACL或受支持属性的文件
- **THEN** 发布后保持目标访问权限、owner及适用完整性标签和声明支持的属性，不继承更宽目录权限；无法保持或安全描述符并发改变则发布前拒绝，结果不明时标未知，不承诺File ID或全部元数据不变

#### Scenario: 暂存写入失败
- **WHEN** 文件写入在发布前磁盘满、取消或 helper 中断
- **THEN** 原文件完整，未发布暂存可安全清理；发布结果无法确认时报告待确认而非保证已回滚

### Requirement: 统一执行合同按能力协商且兼容旧端

双方 SHALL 通过新版project_execution合同协商Windows文件/脚本工具及运行时，旧v2的win32.supported=false、只读及Bash拒绝语义保持。版本/工具/schema/运行时协商 SHALL 以合同为唯一来源，平台验收不得代替授权或维护另一套工具名单。未知版本/缺能力 SHALL 拒绝相关操作，不升级旧grant、不把文件面当成通用执行。两阶段共用执行骨架，helper各自有限白名单保持；部署控制只能收紧能力交集。

#### Scenario: 新客户端连接旧服务器
- **WHEN** 任一端没有兼容执行合同及Windows文件能力协商
- **THEN** 不提供新读写入口，原已获准能力按原规则运行，不尝试v2无约束替代路径

#### Scenario: 文件面已验收但脚本未验收
- **WHEN** Windows 仅通过文件能力验收
- **THEN** 文件五工具可按权限使用，scripts_verified 仍为 false，v2 全量 Windows 支持不因文件面通过而自动开启

### Requirement: 文件命令复用业务授权与副作用记录

文件命令 SHALL 关联原运行/调用及用户、租户、设备、项目、grant、连接代次、合同版本和工具/参数摘要，并在入队、开始及结果交付时重验适用资格。写入 SHALL 在副作用前持久记录意图，同一命令重投不重复修改；合同升级不能绕过去重，改工具/参数冲突拒绝。无法确认已发布结果的命令 MUST NOT 自动重跑，不能新建第二套 Agent 循环或身份真值。

#### Scenario: 写完但回执丢失
- **WHEN** write 已发布后连接中断，服务端重投同一命令
- **THEN** 返回已记录结果或待确认状态，不再次覆盖文件；同ID改工具或参数被拒绝，版本升级不重复执行

#### Scenario: 开始前撤权或切换身份
- **WHEN** 命令排队后成员资格/目录授权被撤销，或账号/租户/服务器切换
- **THEN** 不启动旧写入，已发生效果按原作用域登记，迟到结果不能更新新会话

### Requirement: 项目操作集合绑定授权且旧记录不升级

系统 SHALL 将明确确认的operations绑定到既有binding/grant中的服务器、用户、租户、设备、项目和grant版本，并持久化；缺省无新权限，旧grant不得回填升级。操作集合摘要、grant版本及脚本运行时约束 SHALL 纳入开始许可与参数摘要，服务端及桌面在入队/开始时核对。文件集合不授予脚本，脚本需额外确认；设备能力自报、部署开关和持久记录均不得替代活动授权。

#### Scenario: 旧授权读取或版本回退
- **WHEN** 读取缺少operations的旧记录，或旧端接收新版权限字段
- **THEN** 不产生新增Windows写入/脚本权限，旧v2按原合同解释；回退保留记录且不扩大授权，重新确认后才可获新权限

#### Scenario: 开始许可后篡改操作或运行时
- **WHEN** 请求扩大operations、改变运行时约束，或grant版本已变化
- **THEN** 摘要/许可验证失败，副作用前拒绝；文件grant不能借工具名替换变为脚本许可

### Requirement: 文件授权和 helper 生命周期不自动复活

根句柄、活动文件授权和 helper 通道 SHALL 由受信宿主管理，仅原生选择及明确用途确认可创建。退出、撤权、helper 失效和来源切换 SHALL 停止新操作；取消及清理仅作用于本次资源。重启候选路径、journal 或已保存标签 MUST NOT 恢复授权，恢复须重新选择并验证对象。

#### Scenario: helper 崩溃或客户端重启
- **WHEN** helper 或桌面进程退出后恢复
- **THEN** 旧文件grant/句柄失效，历史路径仅为候选；未确认写入不重跑，用户重新授权后才恢复文件操作；在途脚本按独立运行许可与真实隔离依赖处理，不能因文件通道失效假称脚本授权也已撤销

#### Scenario: 清理暂存文件
- **WHEN** 任务取消或临时资源到期
- **THEN** 仅清理记录在本任务注册表的暂存对象，不通过向上拼路径删除项目、盘根或其他会话文件

### Requirement: 本机文件结果和产物来源准确

文件面板、模型输入、编辑结果及产物引用 SHALL 使用同一已确认设备/项目来源；只有本机真实写入成功后才显示成功。绝对授权根留在本机，文件默认不上传；返回内容/摘要可进入服务器及模型，产品说明 SHALL 如实告知。显式上传、下载和预览继续遵守原授权，不将本机路径当作服务器路径。

#### Scenario: 切换项目后打开旧文件引用
- **WHEN** 文件在项目 A 写入，用户切到项目 B 后打开历史引用
- **THEN** 仍按 A 的设备、项目、版本重验，失效则说明原因，不打开 B 或服务器的同名文件

#### Scenario: 模型仅声称生成文件
- **WHEN** 回答声称创建成功而没有对应真实 helper 结果和文件验证
- **THEN** 不显示可用产物或保存成功，不自动上传整目录来弥补缺失

### Requirement: Windows 文件能力按真实平台证据启用

正式开放 SHALL 同时满足兼容合同、可信helper、当前用户资格及真实边界证据。部署策略与平台验收分别校验，新增控制不得绕过能力交集；Windows新能力默认不可用，POSIX验收或已有开关不替代Windows证据。Windows 10 22H2/11 x64、普通用户、NTFS、真实安装包及两模式 SHALL 分层有证据；历史skip逐项映射为Windows等价验证或保留平台专属测试，不以移除skip冒充通过，未验收平台不得扩大声明。

#### Scenario: helper 缺失或版本不匹配
- **WHEN** 安装后 helper 被隔离、缺失或私有协议不匹配
- **THEN** 文件能力关闭并提示修复安装，聊天仍可用，不通过 PATH 下载/运行未知 helper 或普通 Python 回退

#### Scenario: 只打开服务器开关
- **WHEN** 部署允许文件能力但本机未通过探针或当前目录不受支持
- **THEN** 仍拒绝相应操作，metadata 和界面给出实际原因，不能宣称 Windows 全量执行可用
