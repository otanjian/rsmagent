## ADDED Requirements

### Requirement: Windows 脚本隔离身份授权最小且可恢复

Windows脚本 SHALL 隔离当前授权作用域，不累积其他项目或不同资源资格；会话身份复用仅限资源一致且能停止全部关联进程。实际需要ACL变更时 SHALL 明示确认、持久记录恢复依据，并先验证对象移动、链接及继承变化的恢复；保护继承不自动视为不支持，无法安全配置/恢复的组合改动前拒绝。系统 MUST NOT 放宽其他主体、降低完整性标签或默默提权；不强制逐命令改ACL。

#### Scenario: 文件grant升级到脚本确认
- **WHEN** 用户已有项目文件读写权限并明确确认脚本及其必要权限配置
- **THEN** 仅当前授权作用域取得约定隔离访问，另一个项目及其他用户数据保持拒绝，原普通用户权限不被扩大

#### Scenario: 同一项目会话复用隔离身份
- **WHEN** 同一授权会话连续运行资源资格相同的脚本
- **THEN** 可复用隔离身份但每次保留独立Job/临时资源，SHALL 按同根副作用串行执行；下一运行前确认上一Job及后代退出、本运行临时资源及仅本运行有效的授权已清理，保留的会话资源资格仍一致，额外Skill资源资格不一致或项目/身份切换时不得合并权限

#### Scenario: 上一运行残留阻止会话身份继续执行
- **WHEN** 上一运行取消后仍有派生进程，或临时资源/本运行授权清理失败或无法确认
- **THEN** 系统 SHALL 阻止该身份/项目下一运行，即使新命令、重连或新Job也不能绕过；明示待清理状态，其他独立作用域不被连带阻断，独立Job不被当作资源访问隔离证明

#### Scenario: ACL不允许配置或并发改动
- **WHEN** 当前主体不能安全配置隔离身份，或用户在运行中修改ACL
- **THEN** 配置失败不启动；恢复核对对象与当前安全状态，移除本次权限且验证未意外改变原访问语义，不盲目覆盖旧DACL或用户并发改动，不用管理员或普通进程回退

#### Scenario: 继承权限传播及特殊DACL
- **WHEN** 目标使用显式/继承/受保护、NULL或空DACL，或存在硬链接
- **THEN** 配置前验证作用对象及传播/恢复语义，无法保证安全的组合不修改；删除新增ACE不能单独作为恢复证明，不为某个硬链接放宽同一文件其他入口的权限

### Requirement: Windows 隔离资源回收先于成功恢复声明

运行结束/取消 SHALL 回收本运行进程树与临时资源，按运行身份随之回收，会话身份在撤权/退出/结束先停关联Job再回收。崩溃恢复 SHALL 核对进程和对象状态，不复活授权、不删用户项目或覆盖并发ACL变动。找不到对象、状态冲突或覆盖不明 SHALL 明示残留/恢复未完成并保留记录，阻止受影响身份/项目新脚本及残留SID复用，不换身份绕过。删除容器profile或ACE不等于恢复；不承诺所有异常自动恢复，文件面按自身资格工作。

#### Scenario: 配置权限后启动失败或宿主崩溃
- **WHEN** 脚本尚未运行或运行中宿主异常退出
- **THEN** 核对进程状态，并在有权限变更时依持久记录恢复相应授权，未知副作用不重跑，不删除用户项目或覆盖其他ACL

#### Scenario: 清理失败
- **WHEN** 某运行的进程或授权清理无法确认
- **THEN** 显示未完成状态并阻止受影响身份/项目的新脚本，原文件工具保持自身授权，不能报告完全撤销或误杀其他会话

#### Scenario: 对象移出根或新增对象无法完整定位
- **WHEN** 原对象被用户移出项目，或新增对象的权限传播/位置记录不能完整核对
- **THEN** 依据可靠对象身份定位和当前状态恢复；仅扫描原目录不能证明完成，不能定位则报告残留、停止相关进程、禁止SID复用并阻断受影响作用域，不删除移动后的用户文件或伪报自动恢复
