## ADDED Requirements

### Requirement: Windows 原地项目选择明确文件操作用途

Windows Desktop SHALL 通过原生选择提供可区分的只读输入与本机项目读写确认，说明生效目录、权限和文件结果的数据流。界面 SHALL 只有在身份、工具资格、用途、目录对象及 helper 均就绪后标记可用；普通网页、模型绝对路径、历史候选和旧只读 grant 不得代替新读写确认。读写确认 MUST NOT 授予脚本或服务器目录权限。

#### Scenario: 用户打开本机项目读写
- **WHEN** 用户明确选择允许的目录并确认读写，当前身份及五文件工具资格有效
- **THEN** 工作台展示 Windows 本机项目和实际可用操作，后续文件请求使用已绑定对象，不复制目录到服务器

#### Scenario: 授权说明涉及项目内敏感业务文件
- **WHEN** 用户确认整个项目可读写
- **THEN** 界面 SHALL 说明获准项目内的配置和业务秘密可能被工具读取并进入模型，不承诺自动隐藏所有秘密；宿主身份库/控制面重叠根仍拒绝授权

#### Scenario: 只读用户或取消选择
- **WHEN** 用户仅确认只读，或在读写选择/绑定完成前取消
- **THEN** 只读请求不能写，取消不创建 grant 或错误替换原绑定，不能借重登/刷新升级权限

### Requirement: Windows 文件面板与模型派发使用同一可信来源

Windows 文件树、搜索、读取、保存、模型文件工具及历史引用 SHALL 使用同一已确认设备项目与各自当前授权；来源切换只影响后续请求，不重定向在途写入。平台/目录不支持、helper 缺失、冲突、离线与身份失效 SHALL 提供对应恢复动作，不回落服务器同名目录，也不将不可访问描述为空目录。

#### Scenario: 快速切换目录或账号
- **WHEN** 用户从 A 切到 B 或切换账号后旧目录 Promise 返回
- **THEN** 旧结果不更新新面板/绑定，在途效果仍属于 A，不能写入 B

#### Scenario: 本机与服务器目录同名
- **WHEN** 服务器有与 Windows 项目同名但内容不同的路径
- **THEN** 面板读取和 AI 编辑均使用 Windows 文件结果；无法访问时明确失败，服务器哨兵不变
