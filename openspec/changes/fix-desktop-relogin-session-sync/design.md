## Context

本文件描述待实现方案，产物完成不代表客户端问题已修复。

2026-10-01 18:55:48，现场原生会话和配对 Web 会话因 `web_logout` 一起撤销；18:56:06，同一账号仅创建普通 Web 会话。页面看似已登录，目录绑定调用 broker 时却没有原生会话。此前的 `client_files` 工具权限拒绝是另一问题。

## Goals / Non-Goals

**Goals:** 在同一应用进程内退出、重新登录或换账号后能重新选择目录；现有分裂状态有恢复入口；退出失败可重试，旧账号目录不能进入新账号。

**Non-Goals:** 重做认证体系、持续巡检全部 Cookie/配对、重构租户切换、修改工具授权、支持所有新旧版本组合的透明修复。既有 PKCE、强制改密/租户 gate 和服务端授权继续适用。

## Decisions

### 1. 用一个宿主动作接通现有退出链路

新增受信容器 `signOut()`，不接受账号、密码、Cookie、令牌或任意目标参数。通过已有能力声明、允许列表、sender / 主 frame / origin / document generation 校验暴露。它只触发既有 `detachRemoteContainer()` → broker `logout()`，不承担登录、租户选择或状态查询。

网页退出按以下顺序执行：

1. 沿用现有离开检查、单次提交和身份失效处理，等待 `suspendLocalContext('logout')` 停止旧目录访问。
2. 沿用同源 `/auth/logout`，确认当前 Cookie 会话退出；来自该接口的明确会话失效也视为该会话已结束，网络错误不能视为成功。
3. 调用 `signOut()` 让主进程完成原生退出、旧资源清理和壳界面恢复；不再执行 `location.reload()`。

保留第 2 步是为了处理已存在的普通 Web 会话：仅清空 partition 会丢弃 Cookie，却未撤销服务端普通会话。正常配对状态下，Web logout 已撤销父子会话，随后 broker logout 收到原生会话失效可按现有语义幂等完成。两步串行，不由网页和宿主并发启动相互竞争的退出。

Web logout 失败时留在现有退出错误界面重试；宿主阶段失败则由本地壳呈现 `logout_incomplete` 并重试。只结束当前容器会话及其原生会话，保留独立浏览器/其他设备会话。

### 2. 刷新已有本地壳，不增加会话状态机

主进程在退出开始和结束时通知受信本地 renderer。开始时使用现有等待 gate；结束后重新读取 broker 状态，成功呈现原登录/连接入口，失败呈现现有阻断及重试。通知只表达操作阶段，不复制用户、租户或凭据快照；完成显示不能依赖已被销毁的 Web 文档收到 IPC 回调。

本地模式复用 `desktop-auth-begin` → `tryAutoBindLocalWeb`，远程模式复用 `RemoteConnectPage` → `desktopRemoteConnect` → `attachRemoteContainer`。远程壳同时清除旧 `attached` 展示。容器已启用时，配对/挂载失败须可见，不能被后台 Promise 吞掉后显示连接成功；用户可从原入口重试，不另建配对恢复状态机。

为现有退出操作增加一个在途 Promise，合并重复调用；退出期间及 `logout_incomplete` 时拒绝新的授权/attach。继续使用 broker 的取消机制、epoch、容器和目录 generation；仅补该退出链路遗漏的失效点。旧回调不得重挂已销毁的容器或清理后来建立的会话。

### 3. 桌面重新登录回到原生入口

在 `showLoginScreen` 和登录提交接缝区分受信 Desktop 与普通浏览器。Desktop 显示“桌面登录连接已失效，请重新登录”，用户点击后走第 1 节的串行退出，再在本地壳使用原有原生授权入口。普通浏览器继续原 Cookie 密码登录。

同一恢复入口用于历史分裂状态及当前身份接口确认的会话失效。页面身份字段和普通 Cookie 不用于恢复原生令牌。授权成功以服务端返回账号为准，重新建立配对和容器；沿用改密/租户 gate。取消授权或配对失败停留在可重试界面，不自动弹出授权、不自动重放目录/工具调用。

Web 逻辑放在 fork 模块，通过最小装配接缝接入，沿用三语文案机制。新增桥接只包含 `signOut`；不增加 `sessionState`、`signIn` 或 `selectTenant`。

### 4. 目录入口只补本次需要的检查

主进程在 `chooseWorkspace` 打开对话框前读取已有 broker 状态：原生会话为空或退出未完成时拒绝，并返回稳定原因码供页面呈现恢复入口。内存状态检查不能证明服务端会话仍有效，后续绑定继续以现有服务端验证为准；不在每次目录选择前增加完整身份/配对查询。

已知的原生缺失、绑定响应确认的会话失效映射到重新登录提示。工具 403、租户资格问题、设备离线、网络故障保留各自错误，不统一改成登录失效。目录对话框或绑定进行中退出时，复用现有 generation 丢弃旧结果并释放临时 grant，不显示选择成功；重登后重新选目录，不继承旧授权。

原 `containerBindingTransport` 捕获租户的问题属于租户切换路径；本次重新挂载会创建新的 transport，故不顺带改造为全局动态上下文服务。

### 5. 本轮选中目录同时进入模型上下文

21:00 的复测已成功绑定 `模拟财务报表_2024`，相关成员已有 `client_files` 工具授权，但该会话没有设备读取命令，模型连续用 `bash` 扫描服务器工作区。现有 bridge 只把已验证引用写到工具实例，模型提示词并不知道本轮已经选择本地输入。

复用该引用在每轮设置/清除 Agent 的 `desktop_context`，构建提示词时说明当前数据来源、`client_files` 列举/文本读取以及二进制文件 `materialize` 路径；提示词不插入绑定标识或客户端绝对路径，不改变 cwd、执行目标或工具授权。工具不可用时明确说明暂时不能读取，不回落成“目录无数据”。提示词重建失败也附加本轮来源说明；已有本地执行项目继续使用原有工具路由，不重复添加只读输入指引。

这是本轮上下文传递的补漏，不新增目录服务或认证机制。根目录列举示例固定为 `client_files({"op":"list"})`；协议要求省略 `relative_path`，空字符串和 `.` 都无效。

### 6. 本地后台实际启动既有设备网关

实机跟进发现，模型正确调用工具后，命令仍停在 queued。桌面日志从原始复现开始就持续记录 `handshake_failed`，身份库没有连接 lease：客户端向本地 WSGI Web 端口请求 WebSocket Upgrade，而该端口没有设备网关。此前直接文件读取验收仅证明宿主文件访问，没有覆盖服务端排队、WebSocket 下发、设备回传的完整链路。

仅在 `COW_DESKTOP=1` 的后台启动现有 aiohttp gateway，同一身份服务、同一命令队列，绑定 `127.0.0.1` 动态端口，并随 WebChannel 停止。现有 `/api/desktop/meta` 可选返回正在运行的 `local_gateway_port`；不新增身份、命令 API 或轮询通道。受信宿主仅对已登记的本地后台读取该字段，拒绝重定向和非法端口，连接目标固定为回环地址；远程来源继续使用同源 `/api/desktop/connect`。本地后台重启后重连会重新发现端口。Bearer、租户、binding、grant 和工具权限校验保持原有实现。

文件面板 watcher 的授权键仅由 workspace、binding、selection generation、grant version 构成。连接 epoch 属于传输状态，初次握手和重连不能因此清除有效目录选择；设备执行命令继续检查自身 epoch，真正撤销或更换 grant 仍结束 watch。

### 7. 文件传输沿用原生请求的租户上下文

目录列举成功后的 Word 读取暴露 `missing_tenant`：现有 materialize HTTP 传输只带 Bearer，遗漏租户头。为 reserve/chunk/commit 补充从 broker 每次读取的 `X-Tenant-ID`，与现有原生业务请求一致；无租户时不发送。服务端仍检查命令、传输与租户归属，不允许模型提供租户、不增加默认租户或扩大授权。

设备传输成功后，`client_files` 在同一次调用内复用已有 `_materialize_committed` 返回实际服务器分析路径，避免只返回 transfer 编号让模型猜路径。该落盘步骤检查当前用户、租户、智能体及本次命令归属，并约束 run 目录标识；已有显式 transfer_id 的离线读取继续可用。

## Risks / Trade-offs

- Web 退出已成功但宿主调用尚未完成：页面只显示正在退出/恢复，重试不能回到普通登录表单；宿主销毁容器后的结果由本地壳承接。
- 壳仍持有旧登录状态：通知必须在覆盖期间也能接收，退出进行中及失败时都阻止重连，避免短暂恢复旧业务。
- 系统浏览器仍登录另一账号：沿用原授权页的账号确认/切换，以授权结果为准，真实验收包含 A 换 B。
- 简化只减少新增机制，不能省略旧资源清理、服务端撤销或 sender 校验；这些复用点必须通过行为回归确认。

## Migration Plan

1. 先补失败回归并确认原生授权、配对、容器清理切片在受测构建可用，再接线；不以历史归档代替本次证据。
2. 客户端与 Web 页面配套发布。新页面在识别 Desktop 后若缺少 `signOut` 能力，明确提示升级并停止本次桌面恢复流程；不能误判为普通浏览器。旧页面不列为透明修复目标，要求更新工作台。不另建版本兼容协调层。
3. 无数据库迁移，不恢复已撤销会话、不修改角色权限。现存分裂状态由用户从恢复入口退出并重新授权。沿用既有 feature flag；关闭本地文件能力时账号退出/登录仍可用，不新增开关、不改切片验收声明。
4. 自动化通过后，用真实客户端验证原复现路径、换账号、历史分裂恢复和失败重试。以已授权账号真实读取新选文件为成功依据，另验证无工具权限仍明确拒绝；保存脱敏证据。
5. 更新使用与排障文档。回滚使用配套客户端/页面版本，旧凭据及目录授权不回填；必要时沿用现有开关关闭受影响文件入口。文档及 mock 通过不等于客户端已交付。
