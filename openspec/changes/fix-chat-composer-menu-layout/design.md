## Context

参见 [proposal.md](proposal.md)。本 change 追溯记录已部署到 `27fe5b6b` 的会话交付，不新增一轮业务实现。

当前 Web 入口加载 `console.css`、`appearance.css` 和 `console.js`。`appearance.css` 的高优先级首页规则曾覆盖公共菜单方向及高度；工作空间和模型菜单位于输入框层，桌面智能体菜单则嵌套在头像容器内，因此不能给所有菜单套用同一个 `bottom: 100%`。拆分目录中的 `workspace.css`、`chat/workspace-selector.js` 同步保存本次涉及的规则，避免已有两种源码组织发生差异。

参照 master 提交 `48c0d79c36146950667f8d1884ab823deae62305` 的模型、智能体、指令和引用菜单；工作空间菜单按用户要求借鉴模型菜单的定位。

## Goals / Non-Goals

**Goals:**
- 菜单位置由实际触发入口决定，长列表保持足够高度和内部滚动。
- 在现有显示函数内生成紧凑目录提示，完整路径仍由原选择状态持有。
- 对齐本会话代码、验证、部署和规范记录。

**Non-Goals:**
- 不引入浮层库、传送到 body 的新菜单系统、自动上下翻转或光标定位算法。
- 不调整指令处理、引用查询、智能体授权、项目绑定、主题或欢迎页其他布局。
- 不扩展发布治理、Windows 执行隔离或容器部署能力；不据本次菜单验收关闭其他 change。

## Decisions

### 按菜单类型保留公共定位

| 菜单 | 接入点和最终规则 |
| --- | --- |
| 工作空间 | `console.css` 与 `workspace.css` 的底部偏移统一为 `calc(2rem + 14px)`，与模型菜单同在工具栏上方；最大高度 380px |
| 模型 | 保留公共工具栏定位和 380px 上限，移除首页方向/高度覆盖 |
| 智能体 | 桌面继承 `.composer-menu` 的头像上方定位和 380px 上限；手机保留卡片宽度约束，底部偏移改为工具栏位置 |
| `/`、`@` | 删除首页强制向下及高度压缩规则，恢复公共的 `bottom: calc(100% + 6px)`，上限分别为 320px、300px |
| 附件 | 本会话保留其已有独立首页规则，不把其他菜单的修复扩大为附件重构 |

采用已有 CSS 规则可保持当前 DOM、焦点及选择事件。统一放在整张输入框上方会让工具栏菜单远离按钮；统一放到下方则重现截图中的底部截断。没有新增自动位置翻转，因此本次验证不代表所有任意高度、缩放或虚拟键盘状态均已覆盖。

### 只格式化按钮悬停文本

两处 `_wsSelUpdateLabel()` 从当前项目路径或默认工作空间路径读取值，以两种分隔符切分、过滤空段、取最后两段并用 `/` 拼接；空结果按原路径或本地化标题回退。原状态及 `current.name` 不被写回，选择请求仍使用完整路径。项目菜单各条目的原有路径提示不在此次用户指定的按钮调整范围内；桌面宿主的不透明目录引用也不被解释成新的文件系统授权。

### 补记 delta，保留既有范围

修改 `Responsive task-oriented homepage` 的菜单段落，并完整保留该 requirement 的其他内容和场景。历史场景名 `Composer menus stay reachable below the centered input` 保留用于基线追溯，其 WHEN/THEN 改为旧问题入口及新的向上展开验收；具体新行为由新增菜单锚点和路径提示 requirements 承载。

新 change 不直接改写已归档的外观历史，也不在本次补记中归档或覆盖主 spec。发布治理的方案与历史共享切片已有对应文档；[会话覆盖清单](evidence/session-coverage.md) 记录其归属及合并边界。

## Risks / Trade-offs

- 首页高优先级覆盖再次出现 → 保留实际浏览器几何检查和菜单布局回归，升级时核对两层样式。
- Windows 分隔符及末尾斜杠影响提示 → 两种源码入口均检查路径案例，只改变展示值。
- 测试夹具漂移造成完整页面无法初始化 → 浏览器验证使用本地服务渲染后的 HTML，并按当前工作台投影契约提供隔离数据；不把夹具后端当作真实授权验收。
- 静态资源已更新而页面仍缓存 → 核对页面带版本参数的资源引用及文件摘要，用户刷新后加载新资源。
- HTTP 健康与整体运行就绪混淆 → 部署证据分别记录健康探针与既有 Windows 执行隔离限制。

## Migration Plan

1. 核对菜单源码、主规范及 master 基线，保留已有选择和授权语义。
2. 菜单布局与路径格式检查通过后才进入部署；发布记录见 [verification-2026-10-10.md](evidence/verification-2026-10-10.md)。
3. 推送前 fetch 并合并 `gitea/rdai`，服务器工作树干净且远端提交符合预期时才 fast-forward 到固定提交。
4. 本次 UI 修复仅涉及静态 CSS/JS，无数据迁移和新开关；更新后核对本地及公网实际返回资源。最早包含 Python 变更的整合部署另行重启目标应用及重载代理，不能仅以源码 HEAD 断言运行进程已更新。
5. 如需撤回某项 UI 修复，对对应提交创建反向提交并按相同流程发布，不强制覆盖工作树或清除用户数据。补记文档本身不要求服务重启。

当前无待决实施参数。验证范围和仍未验收的事项见证据，既有主规范的其他首页条款不在本次重新验收范围内。
