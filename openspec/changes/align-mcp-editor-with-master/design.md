## Context

当前实际入口为 `channel/web/chat.html` → `static/js/external-connections.js`；MCP 使用该页面的通用抽屉。仓库保留的 `templates/modals/mcp-editor.html`、`static/js/views/skills.js` 与固定 master 的相关实现一致，但未装入当前 MCP 页面。

核查基线：`rdai=414bc6b3e2eabdd8d3406efae32b79cb9944bece`，`origin/master=48c0d79c36146950667f8d1884ab823deae62305`。现有代码已具备单条 CRUD、版本检查、秘密槽的保留/替换/清除、草稿探测和页面离开保护；主要缺口是编辑器接线与字段映射。

实现边界是当前 MCP 编辑入口及其必需的配置映射，已有服务与页面机制优先复用。布局和输入方式按 master 对齐，数据库写入仍遵循本项目既有连接契约。

## Goals / Non-Goals

**Goals:**

- 使用 master 的弹窗、表单/JSON、高级设置和测试保存交互，支持字段能保存、回读和实际使用。
- 在当前系统接入页面复用上游代码及已有服务，以少量映射连接两者。
- 保持连接 ID、权限、继承、分配和秘密管理语义。

**Non-Goals:**

- 重新模块化能力中心、接线未使用的完整上游页面或恢复 Desktop 原生 MCP 编辑器。
- 新建整批事务 API、逐键秘密合并协议、版本协商机制、配置迁移平台或授权流程。
- 改变其他连接类型、MCP 执行授权和部署开关。

## Decisions

### 1. 定向复用编辑器，只有当前入口需要接线

直接装入 master 的 `mcp-editor.html`，沿用样式、翻译及元素标识。从 `skills.js` 提取当前入口需要的 MCP 函数，保持上游解析、序列化、切换和结果渲染逻辑；放入一个小的 MCP 编辑器模块，接收测试/保存回调。该模块只服务当前入口，不为未启用的上游页面再建持久化适配器。

当前页面继续管理列表、作用域、权限、身份和离页保护。不能整体加载 `skills.js`，因为它与 `console.js` 有同名全局符号；也不重写一套 JSON 解析器。原上游文件作为来源保留，不改它的装配。记录来源 SHA 和必要差异，验证实际页面只装载一个编辑器。

新增、编辑、租户覆盖共用弹窗；已有只读详情可保留，不为形式一致再重构查看模式。编辑名称锁定，存量中文名称等仍按稳定 ID 编辑。能力中心与 Desktop 的跳转路径保持。

两处已记录的关闭动作差异（与 §3 的整组凭据、§4 的逐项批量是另外两件事）：保存成功即关闭，与 master 一致——已提交的保存不是被丢弃的草稿，不再弹“是否放弃”的问题；而 Escape 走页面自己的未保存提问，草稿脏时先问、空草稿时与 master 一样直接关闭。后者是并入本项目离页保护后的必然结果：会丢弃输入的地方不止编辑器一处，关闭入口必须共用同一套提问。

### 2. 只补齐 master 字段落到现有模型所需的能力

| master 输入 | 现有服务适配 |
| --- | --- |
| `type`、`serverUrl` | 映射为 `transport`、`url`，复用传输别名和缺省推断 |
| `command`、`args` | 现有字段，保持独立参数列表 |
| `env` | 使用现有 `env_keys` 和 `env` 加密槽 |
| `headers` | 增加请求头名称列表及一个加密映射槽，兼容旧单请求头 |
| `tool_name_prefix` | 沿用已有字段，补齐编辑器回读和提交 |
| `timeout` | 增加正整数配置并传入现有客户端，仍受既有运行时期限上限约束 |
| `scope` | 增加独立 `oauth_scope`，与连接归属及旧 `oauth_provider` 区分 |
| `disabled` | 映射 `enabled`，创建服务增加可选初始值，默认保持原行为 |

前端映射只服务这个编辑器，服务端继续由 registry 做权威校验，不新增通用配置转换框架。未知字段在模式转换/提交前明确报错，服务端再次校验，避免上游宽松解析使配置被静默丢弃。JSON 中不得覆盖连接归属。

多请求头使用现有字符串秘密槽保存 JSON 映射即可，不新增秘密表。新槽有值时使用新表示，否则读取旧 `header_name/header`；替换或清除新表示时同步停用旧表示，避免清除后回退到旧秘密。普通字段编辑不强制搬迁旧槽。

OAuth scope 只接入已有授权/令牌绑定机制。对缺少独立 scope 的旧记录保留原有效行为，显式保存后写入新字段；不批量改写旧配置或新建授权向导。普通附加头可保留，手填 Authorization 与 OAuth 冲突时明确拒绝。默认 stdio 及不支持的传输/认证组合显示现有能力原因，不改变部署开关。

### 3. 秘密整组操作沿用现有契约

现有 `ecBuildSecrets` 和 `_write_secrets` 已约定：省略或空白保留、非空替换、null 清除。环境变量和请求头分别作为一组，沿用这个契约；不再设计逐键保留/清除、独立秘密版本请求字段或服务端合并算法。

编辑时显示“已配置；留空保留，输入后整体替换”。新输入通过 master 的键值文本或 JSON 提供完整组；显式清除移除整组。JSON 缺少字段或空对象表示保留，不能自动解释成清除；如果仅想删其中一键，需要输入删减后的完整组并替换。已保存值不回显，允许展示已配置的键名；模式切换保留本次输入和整组操作状态。

保留组时配置中的键名也保留；替换时键名和值同时更新；清除时同时清理，避免元数据与秘密脱节。连接更新仍只使用已有 `expected_version` 协议。创建租户覆盖使用自己的凭据。关闭或身份变化继续按现有机制清理内存秘密。

取舍：整组替换需要用户掌握该组完整配置，但与现有凭据契约及 master 文本输入一致，避免把此次表单接入变成逐键凭据管理功能。

### 4. JSON 批量输入复用单条创建接口

本次对齐的是批量输入能力，不要求数据库整批提交语义。解析后先检查批内重名、当前获准目录中的同名及基本字段，再对待提交项依次调用现有平台/租户创建接口。每项继续享有现有连接、秘密、审计和分配的单条原子事务。无需新增 batch-create 路由、抽取通用批量服务或迁移名称唯一索引。

弹窗用简短结果列表显示成功、失败、未提交。首个保存失败或结果未知时停止后续请求，已成功项保留，并从待提交 JSON 中移出；未完成项仍可处理。成功项不能因重试再创建，也不能为模拟整批回滚自动删除。全部完成后关闭弹窗；部分成功时刷新已确认目录变化并保留弹窗。目录刷新会推进列表读取代次，因此弹窗的异步守卫按身份（租户/账号）判断失效，而不是按列表代次：同一身份下的刷新不得作废仍在进行的保存与重试；身份失效仍由既有机制强制清理草稿。实际批量事务行为与 master 有此差异，需要在提示中明确。

每项使用现有 Idempotency-Key，结果未知时保留该项原键和原请求，在确认结果前不允许换负载盲目重发；先以原键核对未知结果，不能被目录中该项自己产生的同名记录挡住重放。已明确失败且修改输入时可创建新键。状态仅在当前弹窗内，关闭清除秘密，不设计持久化导入任务或队列。

核查发现 `create_connection` 先提交连接，随后另一个事务记录幂等结果，存在中断后重试重复创建的窗口。为可靠复用单条接口，在现有创建方法内补齐创建与其幂等记录同事务、事务内同键复查及重放前当前权限检查；不复制 MCP 专属创建服务，共用代码受到影响的其他类型保留原契约并做回归。既有单条幂等规范已要求此行为。新增初始停用也在该单条事务完成，不能创建后再发一次停用请求。

### 5. 测试扩展落在已有入口和运行时

复用现有新建草稿测试接口；平台增加对应作用域入口，身份判断按路由范围执行。现有平台已保存测试 handler 仍使用 `require_tenant=True`，应一起修正这处接线，保证零租户平台管理员可测试。

编辑草稿在草稿测试接口增加可选连接 ID 和预期版本。服务端授权后复用已有 snapshot、秘密解析器和受控探测，配置用本次草稿，秘密按整组保留/替换/清除解析；测试前后利用现有配置/秘密标记识别失效结果，不增加前端秘密版本协议。现有 `probe(draft=True)` 仍从数据库读配置，不能直接调用它来假装测试了修改后的输入。租户覆盖草稿不借用平台秘密。

草稿测试的作用域在请求体里，路由级策略无法在鉴权阶段得知，因此该路由使用新增的 `scoped` 策略：网关照常解析身份并校验声明的权限，租户强制留给 handler 按作用域判断。若沿用 `tenant` 策略，零租户平台管理员会在 handler 之前被 `missing_tenant` 拒绝，平台模板草稿实际不可测。

`scoped` 的解析仍以请求自身的选择为准：带租户头的请求按租户域解析并校验成员关系，不带头部的按个人/平台域解析（因此只有平台管理员能满足声明的权限）。忽略租户头会让租户管理员在网关上就变成"无租户"，把该路由本来要服务的租户草稿一并拒掉。handler 对 `scope=platform` 另按独立平台权限判断，因此租户管理员不能靠请求体声明作用域取得平台草稿测试资格。

沿用 master 的测试、保存前检查和失败后“仍然保存”。探测失败可保存合法配置，字段错误、无权限和版本冲突继续拒绝。将已有结果映射为上游展示结构，保留脱敏原因；需要授权如实提示，不把所有认证失败变成成功。逐项探测即可，不增加专用并发调度器。草稿测试不写健康记录，保存成功不表示测试成功或获得执行权限。

### 6. 验证与发布按受影响范围执行

前后端作为同一候选发布，沿用现有资源版本机制；不增加编辑器就绪标记、新旧协议握手或多版本编辑兼容层。已有测试/执行开关照常工作，仅验证本次实际消费路径；不把整个上游同步、权限和隔离工程的再次验收设为前置。

验证聚焦：master 弹窗及表单/JSON 行为、支持字段进入客户端、整组凭据保留、批量部分成功和重试、真实注册路由的租户/平台权限、原页面生命周期。使用已有测试和受控 MCP 协议测试服务；至少一个远程协议从实际页面完成新增、测试、保存、回读闭环。其他受影响传输和 OAuth 映射用针对性集成测试覆盖；未启用 stdio 验证拒绝即可，不能声称已验收启动能力。

## Risks / Trade-offs

- 批量可能部分成功 → 逐项结果、停止后续提交、仅重试未完成项，不自动删除成功项。
- 整组凭据替换会移除未提供的键 → 输入前明确提示，空白保留，替换时校验完整组。
- 新字段保存后未生效 → 验证到现有 MCP 客户端及回读，不能只验表单。
- 上游符号与单体冲突 → 只提取所需函数，检查实际装载和重复监听。
- 旧单请求头/OAuth 数据误变 → 兼容读取并用存量样例验证，不做强制回填。

## Migration Plan

配置仍使用原 JSON 和加密存储，不需要新业务表或全量迁移。旧单请求头和 OAuth 字段兼容读取，显式编辑时才采用新表示，ID、继承和分配保持。

按项目现有方式备份并同版本发布前后端；文档注明旧版本不能完整表达多请求头和独立 scope。恢复沿用项目既有备份/发布流程，先核对受影响数据，不实现自动降级或旧 UI 写新配置的兼容系统。
