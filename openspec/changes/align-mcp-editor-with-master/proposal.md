## Why

当前系统接入的 MCP 配置使用独立抽屉，缺少 master 的表单/JSON 切换及批量输入。用户要求界面形式、配置方式对齐 master，并尽可能沿用其代码；本次以接入上游编辑器和补齐必要字段映射为范围。

## What Changes

- 固定来源为 `origin/master=48c0d79c36146950667f8d1884ab823deae62305`，直接复用 MCP 弹窗模板、样式和翻译，定向提取其表单/JSON、字段联动和结果展示代码，接入当前系统接入页面。
- MCP 新增、编辑及创建租户覆盖使用居中弹窗，保留三种传输、表单/JSON、高级设置、测试及保存前检查。ERP/OA/邮箱继续使用已有界面，能力中心和 Desktop 保留进入系统接入的现有路径。
- JSON 支持 master 的单条及多条输入形式。批量输入由前端依次调用现有单条创建接口，明确显示成功、失败和未提交项；部分成功时保留结果并只重试未完成项，不新增整批事务接口。
- 对接现有连接 CRUD、版本检查、凭据保留/替换/清除和测试接口。补齐多请求头、环境变量映射、超时、OAuth scope、工具名前缀及新增即停用的必要字段链路。
- 凭据按请求头组或环境变量组整体保留、替换、清除；不引入逐键修改协议。已有秘密不回显，未修改时保留，输入新内容时明确提示整组替换。
- 小幅扩展现有草稿测试以支持平台范围和编辑时保留的凭据；复用受控运行时，不新增探测框架。补齐单条 MCP 创建中幂等记录与连接提交的原子性，保证逐项重试不重复创建。
- 使用当前页面已有的身份、离页保护和资源版本机制；同版本交付前后端，不新增编辑器就绪开关或跨版本兼容层。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `external-system-access-console`: MCP 居中弹窗、表单/JSON 交互、逐项批量结果、整组凭据编辑及原页面生命周期。
- `mcp-connection-integration`: master 字段映射、必要运行时生效和存量配置兼容。
- `external-connection-management`: MCP 初始停用、平台/编辑草稿测试；继续遵循既有单条事务、幂等和秘密更新规范。

## Impact

- 前端主要涉及 `channel/web/templates/modals/mcp-editor.html`、`static/js/views/skills.js` 的所需代码、`static/js/external-connections.js` 及 `chat.html`。只检查实际装载的一套编辑器，不重接未使用的完整上游页面。
- 后端仅扩展现有 handler、registry、连接服务和 MCP adapter 的必要字段及测试入口。连接、秘密、继承和智能体分配仍使用原数据库记录，不写全局 `mcp.json`。
- 草稿测试的作用域在请求体里，因此该路由的策略由 `tenant` 改为新的 `scoped`（`channel/web/route_registry.py` + `auth/http_policy.py`）：网关照常解析身份与声明的权限，租户强制交给 handler 按作用域判断。路由、方法、权限声明不变，其他路由的策略不变。
- 复用现有权限、凭据、OAuth 绑定、审计和测试/执行开关；按本次受影响路径验证，不重新验收整个权限、执行隔离或上游同步体系。stdio 是否允许启动仍由已有部署条件决定。
- 不增加新配置表、通用批量框架、逐键凭据协议、编辑器版本协商或自动降级机制；不恢复 Desktop 原生 MCP 表单。
- 实施已完成；本次实际运行的用例、未验收项和既有缺陷记录见 `tasks.md` 的「验证记录」。真实页面端到端（含远程 MCP 协议闭环）与窄屏/主题/键盘的人工检查尚未执行。
