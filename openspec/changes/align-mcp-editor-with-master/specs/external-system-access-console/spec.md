## MODIFIED Requirements

### Requirement: 新增连接按类型进入差异化配置

「新增连接」SHALL 先显示 MCP、ERP、OA、邮箱类型选择；MCP SHALL 打开与固定 master 基线一致的居中编辑弹窗，ERP、OA、邮箱 SHALL 打开对应配置抽屉。各类型 SHALL 使用对应类型规范的字段、默认值、校验和测试方式。类型选择 SHALL 显示当前可创建范围和不可用原因；已存在的 OA 或本人邮箱 SHALL 引导编辑现有连接，不生成第二条。已有连接的类型与归属 SHALL 不通过编辑表单改变。MCP 的编辑和创建租户覆盖 SHALL 复用同一弹窗，覆盖关系由获准操作绑定，不能通过 JSON 指定其他连接的归属。

#### Scenario: 新建邮箱与新建 MCP
- **WHEN** 用户分别选择邮箱和 MCP
- **THEN** 邮箱抽屉呈现独立 IMAP/SMTP 配置，MCP 居中弹窗按传输协议切换 URL 或命令参数表单，不要求填写其他类型无关字段

#### Scenario: 当前租户已有 OA
- **WHEN** 获准管理员再次选择 OA 类型
- **THEN** 引导进入现有 OA 配置，并说明当前租户仅允许一条

#### Scenario: 编辑或覆盖 MCP
- **WHEN** 用户从获准卡片编辑 MCP 或创建租户覆盖
- **THEN** 打开同一 MCP 弹窗，显示实际操作范围，保存定位到原连接或其显式覆盖，不改变其他租户和平台原记录

### Requirement: 操作状态与配置生效一致

连接配置界面 SHALL 支持保存、取消、测试及字段级错误，保存与测试 SHALL 明确区分。测试 SHALL 呈现具体阶段、成功/失败/超时/协议部分成功和脱敏原因；编辑参数后旧测试 SHALL 标记已过期。页面 MUST NOT 将保存成功、启用、一次测试成功或历史工具数量解释为当前可执行授权；写入待确认、版本冲突 SHALL 不显示成功。删除、恢复继承和默认连接替换 SHALL 展示影响并请求明确确认。

MCP 保存 SHALL 沿用 master 的检查流程：对未停用的待保存项执行草稿探测，成功或明确需要授权的项可进入保存；探测失败 SHALL 保留输入并展示原因，提供“仍然保存”。“仍然保存” SHALL 只跳过本次未改变草稿的探测，不绕过字段、权限、凭据、归属、版本及事务校验。修改任意配置或秘密操作 SHALL 撤销该状态。草稿探测结果 SHALL 只描述本次输入；首次保存后的卡片仍依照已保存测试记录显示“未测试”。

#### Scenario: 邮箱部分测试成功
- **WHEN** IMAP 验证成功而 SMTP 认证失败
- **THEN** 分别显示两项结果及整体部分成功，不把发件能力标为正常

#### Scenario: 保存出现并发冲突
- **WHEN** 表单基于旧版本保存被拒绝
- **THEN** 保留本次未提交输入，提供重新读取和人工合并路径，不自动覆盖新版本

#### Scenario: 探测失败后仍然保存
- **WHEN** MCP 草稿因网络不可用或部署未开放测试而探测失败，用户随后选择“仍然保存”
- **THEN** 对相同草稿执行完整保存校验，合法时保存配置，不产生测试成功记录或开放调用；未通过权限或配置校验时仍拒绝保存

#### Scenario: 失败后修改配置
- **WHEN** 用户在“仍然保存”状态下修改地址、JSON、启停状态或凭据操作
- **THEN** 恢复正常保存检查，先前结果不能被用于新草稿

#### Scenario: 批量探测结果混合
- **WHEN** 多条 MCP 中部分成功、部分失败或需要授权
- **THEN** 按名称显示各项结果及工具摘要，失败项使本轮保存进入失败提示；只有用户选择“仍然保存”或重新检查满足条件后才开始逐项保存未完成的配置

### Requirement: 草稿与异步结果隔离

关闭配置弹窗或抽屉、切换连接或类型、应用内导航及租户切换 SHALL 接入统一未保存保护。取消切换 SHALL 保持原页面、路由、作用域和输入；确认离开 SHALL 清除秘密输入，包括 JSON 中本次输入的秘密。失效身份 SHALL 强制清理草稿；过期请求返回 MUST NOT 写入新身份、新租户或新表单。秘密 MUST NOT 写入 URL、浏览器持久存储或分析事件。重复打开 MCP 编辑器 SHALL 只处理一次用户操作，不因重复监听重发同一项；关闭后焦点 SHALL 返回原触发入口。

#### Scenario: 测试过程中切换租户
- **WHEN** 用户确认放弃草稿并切换租户后旧测试返回
- **THEN** 旧结果被丢弃，新页面不出现原租户地址、凭据状态或测试内容

#### Scenario: JSON 草稿取消离开
- **WHEN** 用户编辑含凭据的 JSON 后尝试离开并取消
- **THEN** 保持当前模式、输入、作用域和路由；随后确认离开时清理表单及 JSON 中的秘密

#### Scenario: 重复打开与迟到响应
- **WHEN** 用户关闭 MCP 弹窗、打开另一连接，原弹窗请求随后返回
- **THEN** 新弹窗不被旧结果覆盖，保存按钮不因重复绑定发送多次写入

### Requirement: MCP 配置表单不提供逐工具声明

MCP 新增/编辑表单及 JSON 模式 SHALL 只暴露连接级配置字段，MUST NOT 提供任何「哪些远端工具可调用」的逐工具声明输入。提交到连接存储的 `config` SHALL 只包含 `mcp-connection-integration` 接受的非秘密键；master 格式的秘密值 SHALL 经适配进入凭据管理，不能混入普通配置。任一会被服务端拒绝的字段 SHALL 在提交前被表单或 JSON 校验拦下并提示，服务端 SHALL 再次校验。查看模式 SHALL 只呈现已保存的连接级非秘密配置及秘密存在性。

#### Scenario: 表单不含逐工具声明
- **WHEN** 操作者打开 MCP 新增或编辑表单
- **THEN** 表单不含逐工具声明输入，远端工具名不作为可编辑配置项出现

#### Scenario: 提交的配置只含连接级键
- **WHEN** 操作者保存 MCP 连接
- **THEN** 普通配置只含传输、地址、命令、参数、认证元数据、变量或请求头名称、工具名前缀、超时及 OAuth scope 等被类型规范接受的连接级键，不含秘密值或逐工具名单

#### Scenario: 窄屏与多语言
- **WHEN** 在窄屏或非默认语言下打开 MCP 配置
- **THEN** 既有字段与提示可用、文案完整，表单/JSON、高级设置、错误和底部操作均可到达

## ADDED Requirements

### Requirement: MCP 配置体验与 master 编辑器一致

MCP 编辑器 SHALL 使用固定 master 基线的居中弹窗布局、表单/JSON 页签、传输联动、高级设置、暂时停用及测试/取消/保存操作。表单 SHALL 提供名称、传输方式、命令、逐行参数、逐行 `KEY=value` 环境变量、URL、逐行 `KEY=value` 请求头、工具名前缀、超时秒数和 OAuth scope。默认新建传输 SHALL 与该基线一致为 stdio；部署不支持测试或执行时 SHALL 显示实际原因，不能以界面默认值改变部署能力。当前能力中心及 Desktop 的系统接入入口 SHALL 使用同一 Web 配置体验。

#### Scenario: 选择远程传输
- **WHEN** 用户将 stdio 改为 SSE 或 Streamable HTTP
- **THEN** 按 master 行为显示 URL、请求头及适用高级字段，隐藏命令参数字段；返回 stdio 后显示其对应字段

#### Scenario: 能力中心进入系统接入
- **WHEN** 用户通过能力中心或 Desktop 既有入口进入系统接入并新增 MCP
- **THEN** 使用相同的 Web 居中弹窗，无第二套具有不同配置能力的 MCP 新增表单

### Requirement: MCP 表单与 JSON 双向转换且支持批量新增

JSON 模式 SHALL 接受 `{"mcpServers": {"name": config}}`、名称到配置的映射、配置数组和带名称的单条配置，兼容 `serverUrl` 地址别名及 master 的传输别名。单条配置 SHALL 能在表单与 JSON 间转换而保持支持字段及凭据操作语义；JSON 多条配置 SHALL 留在 JSON 模式并说明不能转换为单条表单。新增 SHALL 支持同一作用域的批量输入和逐项保存；编辑及创建租户覆盖 SHALL 只接受一条，编辑名称按 master 保持锁定。无效 JSON、空批次、重复名称、未知字段及不适用字段 SHALL 明确报错且不修改输入，不静默丢弃配置。页面 SHALL 明确说明批量配置按项保存，逐项展示成功、失败和未提交状态。首次保存失败或结果未知 SHALL 停止后续提交，已成功项 SHALL 保留并从待提交内容移出；未完成项 SHALL 留在弹窗供处理。全部项确认成功后才关闭弹窗，部分成功时 SHALL 刷新已确认的目录变化并保持结果可见。

#### Scenario: 粘贴标准配置
- **WHEN** 用户粘贴包含两个不同服务的 `mcpServers` 对象并保存
- **THEN** 展示两条配置的检查结果，在同一范围依次创建并显示各项结果，全部成功后目录显示两张连接卡片

#### Scenario: 单条往返转换
- **WHEN** 用户配置环境变量或请求头、前缀、超时及停用状态，在表单与 JSON 间往返
- **THEN** 本次输入和支持字段保持，未修改的已保存凭据仍保持原保留语义

#### Scenario: 编辑时提交多个服务
- **WHEN** 用户在编辑已有连接时提交多条 JSON 配置或尝试改变被锁定名称
- **THEN** 显示明确错误，原连接及其他连接不被修改

#### Scenario: JSON 包含不支持字段
- **WHEN** 输入包含未支持的扩展字段或逐工具声明
- **THEN** 指明对应服务及字段，转换和保存均不静默忽略该字段

### Requirement: MCP 批量输入逐项反馈且重试不重复

批量输入 SHALL 复用单条连接的事务、幂等和权限语义，不要求整批回滚。已成功项 MUST NOT 因后续项失败而自动删除或再次提交；失败项与未提交项 SHALL 可继续处理。结果未知的项 SHALL 使用原幂等键和原负载核对或重试，在确认结果前不得改负载重新创建；明确失败项修改输入后 SHALL 使用新键。关闭弹窗 SHALL 清除秘密，不能为了继续导入将秘密存入浏览器持久存储。当前入口的批量输入 SHALL 在写入前检查批内重名及获准目录中的同名，不通过覆盖同名记录完成新增。

#### Scenario: 第二项保存失败
- **WHEN** 第一项保存成功、第二项被服务端拒绝，第三项尚未提交
- **THEN** 第一项保留并显示成功，第二项显示失败，第三项显示未提交；修正第二项后只继续处理后两项

#### Scenario: 创建响应丢失
- **WHEN** 某项服务端已提交但客户端没有收到响应
- **THEN** 该项显示结果未知，后续项暂停；以原键和原负载重试返回同一连接，不重复创建

#### Scenario: 部分成功后的重试
- **WHEN** 第一项成功、第二项失败，页面已按成功项刷新目录，用户修正第二项后再次保存
- **THEN** 弹窗保持打开且可继续提交，本次只提交第二项和未提交项，成功项既不被重发也不被删除

#### Scenario: 同一身份下的目录刷新
- **WHEN** 用户正在弹窗内编辑发送保存请求，同时列表因同一身份的刷新重新读取
- **THEN** 刷新不作废本次保存或探测结果，身份变化才强制清理草稿

#### Scenario: 批内同名
- **WHEN** 配置数组包含两个相同名称的新增项
- **THEN** 提交前提示重名并保留输入，不把两项合并或覆盖已有记录

### Requirement: MCP 编辑模式不回显已保存秘密

编辑已有 MCP 时，表单和 JSON SHALL 只呈现已保存秘密的名称及配置状态，不回传明文。编辑器 SHALL 沿用现有凭据的整组保留、替换和显式清除语义，请求头和环境变量各为一组。未输入、JSON 省略该字段或空对象、删除脱敏展示及模式切换 MUST NOT 被推断为清除；输入非空内容 SHALL 明确提示整体替换该组，需要删除单个键时 SHALL 提供删减后的完整组或取消替换。用户本次输入的秘密 SHALL 可在当前弹窗内随模式切换保留，关闭时清除。创建租户覆盖 SHALL 提示使用自己的凭据，不能把平台凭据的存在性视为覆盖已经配置。

#### Scenario: 只修改超时
- **WHEN** 用户修改已有 MCP 的超时并切换到 JSON 后保存，未修改任何秘密
- **THEN** 原秘密及其版本保留，不提交掩码作为新秘密，配置更新成功

#### Scenario: 替换整组请求头
- **WHEN** 已有多个请求头，用户输入一组新的完整键值并选择保存
- **THEN** 页面明确提示整组替换，按本次完整输入保存该组，旧值不混入新组；未修改的环境变量组保持不变

#### Scenario: 显式清除请求头组
- **WHEN** 用户明确选择清除已配置请求头组
- **THEN** 同时清除该组有效键名和值，不把空白输入当作清除，也不在清除后重新使用旧单请求头

#### Scenario: 创建带认证的租户覆盖
- **WHEN** 平台模板带凭据且租户管理员创建覆盖
- **THEN** 弹窗要求该覆盖自己的凭据或明确未配置状态，平台明文与秘密引用均不复制到租户
