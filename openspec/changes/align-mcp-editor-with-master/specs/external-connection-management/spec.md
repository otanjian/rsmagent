## ADDED Requirements

### Requirement: MCP 创建时支持初始停用状态

MCP 创建 SHALL 将用户指定的初始启停状态与配置、秘密及原有初始分配状态按现有单条事务提交；停用项 MUST NOT 先以启用状态出现再发起停用。省略初始状态 SHALL 保持现有默认行为。创建 SHALL 继续遵循既有幂等与授权规范，不自动授予智能体使用权限；配置管理、连接测试和实际执行资格保持区分。

#### Scenario: 新增暂时停用的服务
- **WHEN** 单条表单或批量输入中的某项设置 `disabled=true`
- **THEN** 该项初次可见即为停用，不参与自动保存前探测，不存在先创建启用再停用的窗口

### Requirement: MCP 测试支持平台范围及编辑草稿

平台 MCP 的草稿和已保存测试 SHALL 按独立平台权限判断，零租户平台管理员不需要租户成员身份。租户测试 SHALL 继续按当前租户授权。草稿测试 SHALL 不持久化连接、秘密或健康记录，测试和执行开关及目标策略保持原有语义。

已有连接的编辑草稿 SHALL 引用稳定 ID 和预期连接版本，服务端在授权后使用本次修改的配置，并按整组保留/替换/清除解析本次有效秘密。保留的秘密 MUST NOT 返回浏览器或要求用户重新输入；配置及秘密的失效判断 SHALL 复用既有版本机制。创建租户覆盖 MUST NOT 保留或借用平台秘密，身份、授权或相关版本变化后的结果不能成为当前结论。

#### Scenario: 零租户平台管理员测试
- **WHEN** 合法平台管理员未加入任何租户，测试新的平台草稿或已保存平台 MCP
- **THEN** 按平台权限和现有测试条件处理，不以缺少租户成员身份拒绝，不伪造租户

#### Scenario: 编辑只改超时但保留认证
- **WHEN** 用户修改已有连接超时并测试，未重新输入已保存请求头
- **THEN** 服务端验证当前版本后使用新的超时与原请求头测试，不能只探测数据库中的旧配置，浏览器不接触原秘密

#### Scenario: 草稿引用旧版本
- **WHEN** 原连接或秘密在编辑测试期间变化
- **THEN** 按既有版本机制提示冲突或结果失效，不覆盖已保存连接的当前健康状态

#### Scenario: 租户覆盖不借用平台秘密
- **WHEN** 租户创建平台模板的覆盖，但没有提供所需租户凭据
- **THEN** 按实际缺少凭据返回结果，不解析平台秘密来补齐

#### Scenario: 测试开关未开放
- **WHEN** 部署未开放 MCP 测试或 stdio 尚未满足现有隔离条件
- **THEN** 在启动进程或发出请求前拒绝并说明原因；合法配置仍按保存权限处理，不因新弹窗开放执行
