## MODIFIED Requirements

### Requirement: 页面与页签具有稳定地址

系统 SHALL 为可用页面提供稳定路径地址；对话使用 `/`，Agent 配置使用 `/agents`，模型配置使用 `/settings`，定时任务使用 `/scheduler`，管理首页保留 `/admin`，其余页面使用明确登记的规范路径。工作台与管理区归属 SHALL 由页面登记决定，不以路径前缀推断访问权限。需要保持选择的页签 SHALL 使用已登记的路径段，默认页签省略；刷新与复制地址打开 SHALL 恢复经认证和授权确认的页面与合法页签。URL MUST NOT 包含凭据、绝对文件路径、草稿正文或持久化权限声明。

旧 `/chat`、`/chat#view-<id>` 及规范曾声明的 `/chat#/workbench/<page>`、`/chat#/admin/<page>` 与其登记的 `tab` 参数 SHALL 在同一权限及离页规则下解析为规范路径；无目标的旧 `/chat` SHALL 进入获准首页。兼容解析 SHALL 保留合法目标，规范化只替换当前历史项，不形成重定向循环或把片段内容作为任意外部跳转地址。

#### Scenario: 复制模型服务地址并刷新
- **WHEN** 获准用户打开模型服务的能力页签并复制地址，在有效认证下重新打开或刷新
- **THEN** 恢复模型服务及该页签，不回到默认对话，不将模型密钥或表单输入写入地址

#### Scenario: 未认证用户直接访问深链接
- **WHEN** 用户打开合法页面地址但尚未登录
- **THEN** 先完成现有认证及必要租户选择，再按当前授权恢复目标；登录不能使原本不可访问页面获得权限

#### Scenario: 页面路径与业务区域前缀不同
- **WHEN** 获准用户直接打开 `/agents` 或 `/settings`
- **THEN** 页面进入登记的管理区并显示对应菜单，不因地址未以 `/admin` 开头而跳回工作台

#### Scenario: 旧链接兼容规范化
- **WHEN** 用户打开有效旧 hash 链接或旧 `/chat` 书签
- **THEN** 登录和授权后恢复对应功能及合法页签，并替换为规范路径；一次后退不在新旧地址之间循环

### Requirement: 旧内部标识与展示回退保持兼容

系统 SHALL 为原有可用页面内部标识提供兼容导航映射，原 `config` 入口 SHALL 进入模型服务的默认页，已知配置子操作 SHALL 定向到对应职责页面。关闭新导航呈现后，规范路径和已有 hash 地址 SHALL 仍被解析或规范化到同功能兼容页，不出现不可恢复空白。回退呈现 MUST NOT 恢复无反馈占位、隐藏焦点或扩大访问能力。

#### Scenario: 旧代码进入智能体创建流程
- **WHEN** 对话选择器仍通过原智能体配置标识发起创建
- **THEN** 统一检查可用性及离页条件后进入智能体管理的原创建操作，不跳到智能体使用目录

#### Scenario: 导航呈现开关关闭
- **WHEN** 用户关闭新导航呈现后打开规范路径或旧 hash
- **THEN** 仍进入相同获准功能，地址解析不依赖该展示开关，也不重新开放被撤权页面

## ADDED Requirements

### Requirement: 页面路径与实际服务入口一致

系统 SHALL 从实际运行的控制台服务响应每个登记的页面路径及合法页签路径，并保持 API、媒体、静态资源和健康检查的既有语义。页面外壳的可访问性 MUST NOT 代替数据和动作授权；未知路径不得由无边界页面兜底吞掉。深层路径刷新 SHALL 正确加载其必要资源，且 `GET /config` MUST 保持原 API 响应而非配置页 HTML。

#### Scenario: 深层页签直接请求
- **WHEN** 获准用户直接请求或刷新 `/settings/models`、`/scheduler/records`
- **THEN** 服务返回可装载的外壳并恢复对应页签，脚本和样式不会相对于深层目录请求而失败

#### Scenario: 页面不能覆盖 API
- **WHEN** 客户端请求已有配置 API、文件路径或未知页面
- **THEN** API 和文件按原协议处理，未知页面返回明确不可恢复目标说明或 404，不伪装成对话首页成功

#### Scenario: 刷新后的权限已失效
- **WHEN** 用户刷新曾获准的页面但权限或租户资格已失效
- **THEN** 按既有可用性规则显示拒绝或恢复入口，不因书签或外壳已加载而启动受限数据访问

#### Scenario: SAP 工作台在身份失效时清理
- **WHEN** 深路径页面已打开 SAP 工作台且当前账号或租户失效
- **THEN** 立即关闭旧 iframe、丢弃旧配置草稿和异步响应，不询问离页确认，不以新身份发送旧绑定控制请求；重新登录后仍可恢复合法深路径
