## Why

私有与共享普通智能体都需要安全地修改已发布配置，同时防止聊天工具、脚本和后台任务改写核心逻辑。首期只建立草稿、有限预览、不可变发布与核心写保护的完整流程，复用现有权限、执行隔离和个人目录，避免扩大为通用安全治理或模板管理平台。

## What Changes

- **BREAKING**：普通智能体统一采用草稿与不可变发布版本；首次未发布只能由获权维护者预览，正式聊天、渠道、默认候选及普通后台调用要求有效发布版本。私有发布仍仅本人可用。
- 已发布对象编辑时创建或继续一个草稿，保存不影响线上；明确发布才生成新版本。在途运行固定旧版本，同一会话下一轮重新装配新版本；回滚保留草稿并重新校验当前权限。
- 简化授权：草稿、工具绑定配置和预览复用现有维护资格；共享对象只新增 `agent.publish` 功能权限及对象 `publish` 动作，发布与回滚共用。私有 owner 发布、回滚复用本人维护资格；member 默认权限不扩充，不新增测试人员专属角色。
- 预览绑定固定草稿快照、独立会话和测试输出；首期必需范围为文本对话与测试文件处理；已有实际验证证据的只读连接按需接入，不作为整体上线前置。生产发送、业务写入、正式调度和生产记忆写入不开放，不建设任意工具的通用副作用分析器。
- 发布固定核心规则、技能脚本、场景/SOP、模型及工具/知识绑定；个人资料、引导完成状态、动态记忆、会话、业务文件和凭据正文不进入发布包；称呼等资料经受限本人数据服务更新，核心初始化在首次发布前完成。文件、Bash、连接、后台修改与管理 API 均须防止核心改写，不能强制保护的执行路径不启用。
- 不增加一级菜单，复用详情的「配置草稿」「版本与发布」「运行权限」；运行权限配置属于同一草稿并随发布生效，受现有资源授权上限限制。
- **BREAKING**：范围转换先停用，处理冲突引用并等待在途任务结束；私有转共享仅由 owner 本人确认并提交，管理员代发起延期。转换后保持停用，私有转共享形成共享草稿并重新发布；共享转私有在定义不变、依赖合格时保留有效版本，无需重复发布，按原启用资格显式恢复。个人数据和旧私有历史不公开。
- 首期风险处置复用停用、现有任务取消和回滚，不新增独立版本撤销状态或按版本批量取消机制；实时撤权检查和核心写保护保持。
- 审计元数据与完整发布包分别保留：审计记录不因包清理删除，完整包按策略清理；活动、在途、当前草稿基线及明确保留的包受保护。
- 存量等价配置可由获授权迁移服务批量建立技术基线，无需逐个 owner 确认；实际内容、范围或授权变化另行确认。按对象/批次预检与切换，不因失败对象中断全部服务；声明最低兼容构建并阻止不支持发布机制的降级。

## Capabilities

### New Capabilities

- `agent-release-management`: 统一草稿、有限预览、发布/回滚、版本固定、隐私与等价迁移。
- `agent-runtime-protection`: 复用现有执行边界，阻止已启用运行路径和后台服务改写核心定义及控制数据。
- `agent-release-console`: 现有详情三页签，明确草稿、线上版本和私有发布范围的交互。

### Modified Capabilities

- `agent-runtime-capability-enforcement`: 固定版本清单、显式空工具集合和逐次授权收紧。
- `execution-isolation`: 定义只读、业务可写与控制数据隔离的实际执行门槛。
- `shared-agent-personal-workspace`: 私有/共享核心定义改从固定版本读取，个人资料与引导状态按动态归属装配，保留 cwd、文件地址与状态归口。
- `agent-workbench`: 普通目录仅投影可用发布版本，私有仍仅 owner 可见。
- `agent-chat-launch`: 正式入口的发布门槛、独立管理预览和默认解析。
- `tenant-channel-configuration`: 渠道绑定及入站只使用有效发布版本，保留个人渠道 owner 限制。
- `user-private-agent-management`: 私有生命周期、历史隐私及双向转换的不同处理。
- `business-permission-catalog`: 仅新增共享发布权限，保护现有持久化权限集合。
- `role-resource-authorization`: 明确共享发布与私有维护资格，管理豁免不跳过核心保护。

## Impact

- 保留 change 标识 `add-shared-agent-release-governance`，适用私有与共享普通 Agent；外部 coding 仍遵循原独立契约，不能承接无法落实保护的受治理委派。
- 合并保留已存在的共享发布切片及其默认关闭开关；该切片不是本方案的完整实现。较早方案、任务完成记录和规格存于 [历史方案说明](evidence/legacy-shared-release/README.md)，后续以当前 proposal/design/specs/tasks 为目标适配并验收。
- 复用 `agent/admin.py` 的修订校验、`auth/` 的 owner/资源授权、`common/runtime_identity.py` 的运行上下文、`agent/protocol/agent_stream.py` 的调用检查及 `agent/execution/sandbox.py` 的 OS 隔离；接入既有 Registry、初始化、文件、渠道与任务服务。
- 数据只新增“当前草稿及活动指针”和“不可变版本”两个领域概念。身份库仍拥有归属与授权；发布服务拥有定义修订和版本。Registry/`team.json` 不成为受治理运行的第二份可写真相源；预览复用现有会话/运行记录。
- 以现行 `openspec/specs/` 为权威；`unify-private-agent-personal-workspace` 已归档，直接保留其已纳入现行规格的个人目录、文件 owner 和历史附件语义，不增加等待该 change 的合并门槛。
- 按实际启用路径复用并验收审计、凭据、审批、配额、外部身份、连接分配与执行隔离切片；Linux/macOS 分别验收和启用，不以另一平台未完成阻塞已通过的平台。
- 通用出口代理、全工具副作用分类、仅预览测试者角色、可写外部集成测试、独立版本撤销、管理员代发起共享、系统模板字段锁定及升级合并均延期，不列入首期实施任务。现有系统供应来源与删除限制继续生效。
- 本次仅优化规划文档；交互 HTML 保留为原始模拟参考，真实实现仍须通过任务与验收。
