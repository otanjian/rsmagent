# 较早共享发布切片与当前方案的合并说明

本目录保存 Gitea `rdai` 提交 `7f303f25db8fb8df873926c8987995a59c7ffd72` 中的 proposal、design、tasks 和五份规格原文，作为历史设计与实现追溯材料，不参与当前 change 的有效规格集合。

远端已包含 `auth/agent_release.py`、存储迁移、服务与 HTTP 动作、能力快照接入及测试。本次合并完整保留这些运行代码和默认关闭的 `shared_agent_release_governance` 开关，不因文档合并启用或改写该能力。

当前方案以 change 根目录的 proposal.md、design.md、tasks.md 及 specs/ 为准。当前任务按新范围独立验收，旧任务的勾选状态不自动继承；[原实施证据](../implementation-2026-10-10.md)仍可用于了解旧切片的测试范围和未完成事项。

| 边界 | 较早共享发布切片 | 当前统一治理目标 |
|---|---|---|
| 对象范围 | 租户共享普通智能体，私有行为保持原样 | 私有与共享普通智能体统一发布生命周期 |
| 发布资格 | 管理资格及既有单动作审批 | 共享 `agent.publish`/对象 publish；私有 owner + `agent.edit`，不新增双人审批 |
| 回滚与停用 | 历史快照复制为新版本；独立 suspended 发布状态 | 合法历史版本激活并保留草稿；复用既有停用与任务取消 |
| 定义保护 | 配置及能力快照切片 | 不可变定义包、固定运行版本、各启用路径的核心写保护 |
| 关闭治理开关 | 保留历史并恢复旧运行行为 | 已治理对象失败关闭，不退回旧可写定义 |
| 验收依据 | 旧 tasks 编号和当时的单元/路由证据 | 当前任务的真实运行、隔离、隐私、迁移及兼容验收 |

原 active specs 中仅属于旧方案的 `shared-agent-release-governance`、`action-approval`、`tenant-resource-isolation` 已移入本目录；两份同名规格也保存了旧原文。这样既保留实现来源，也避免同一 change 同时要求“私有无需发布”与“私有必须发布”等相互冲突的行为。
