## MODIFIED Requirements

### Requirement: 权限模式在租户语境下收紧

现有会话权限模式（read-only / workspace-write / full-access）在 database 多租户下 SHALL 按租户隔离根收紧解释：`workspace-write` 只允许在该租户工作根与 Agent 状态目录内写入，`full-access` MUST NOT 突破租户隔离边界或访问其他租户/全局敏感凭据。

对受治理普通正式运行和预览，以上模式 SHALL 进一步受发布策略与用途约束：定义包及其可替换父目录为只读，业务写入只限本次有效工作根与隔离临时区；状态由可信服务按接口维护，MUST NOT 因原有 Agent 状态目录或租户工作根授权而向任意代码暴露整个可写根。`full-access`、管理员身份和审批通过都不能扩大该边界。文件工具与真实前后台进程 SHALL 执行一致根策略，平台无法提供该保护时不得启动受保护任意代码。

#### Scenario: full-access 不突破租户边界
- **WHEN** 某租户会话以 `full-access` 运行
- **THEN** 仍受租户隔离根约束，不能读取其他租户目录或全局明文凭据

#### Scenario: 管理员以全访问模式修改核心
- **WHEN** 租户管理员的共享聊天使用 full-access 并尝试改规则、替换发布目录或写发布控制数据
- **THEN** 操作被拒绝，不能借该权限模式、父目录重命名或后续派生进程获得写入能力

#### Scenario: 合法业务执行继续可用
- **WHEN** 获权用户以允许的技能读取本次文件、访问获权业务网络并生成报告
- **THEN** 文件工具与沙箱进程都能读写其业务范围并返回产物，定义和控制根摘要不变，不能用关闭全部 Shell 或网络代替隔离验收
