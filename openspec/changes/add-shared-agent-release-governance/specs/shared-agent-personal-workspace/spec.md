## MODIFIED Requirements

### Requirement: 目录提示与会话执行一致且保持配置来源

共享普通 Agent 及私有普通 Agent 的默认目录提示、正常打开的文件面板位置，以及当前会话原生文件/Shell 工具的业务 cwd SHALL 指向同一有效工作位置。本轮路径提示 SHALL 与实际 cwd 一致；浏览共享资料或文件面板有提示地回落到其他获权位置 MUST NOT 自动改变会话执行目录。

工作位置切换 SHALL 仅作用于当前会话，MUST NOT 改 Agent Profile 或进程级 cwd，不得污染其他用户会话。受邀普通 Agent 和子任务 SHALL 沿用已有宿主/父任务目录继承关系。受治理普通 Agent 的设定、技能、作为规则的知识/SOP 和工具/MCP 绑定 SHALL 来自本次固定的发布或授权预览快照；动态知识正文和连接凭据保持其受控来源并按当前授权读取。姓名/称呼等个人资料及引导状态保持既有本人数据域，通过受限服务按当前可信身份读写，不进入发布包或成为脚本可任意写入的核心路径；个人资料按 user-personal-context 既有规则装配。私有与共享受治理普通 Agent 均从固定版本装配核心定义，所有对象的会话存储和个人记忆 SHALL 保持既有唯一来源，个人业务目录中的同名文件不能自动替换这些配置。新增定义根 MUST NOT 迁移或复制现有用户文件，也不能把状态目录整体变为脚本可写范围。

#### Scenario: 读取共享模板并生成本人文件
- **WHEN** A 使用获权共享模板和技能生成相对路径文档
- **THEN** 资源从本轮有效配置和获权数据来源读取，文档写入 A 的有效工作目录，目录提示一致，共享配置不复制进个人目录

#### Scenario: 并发会话互不改目录
- **WHEN** A、B 同时使用 X，A 为后续会话操作选择项目或刷新面板
- **THEN** B 的 cwd 不变，刷新不重定向正在执行的任务，已授权的目录应用仍按既有会话时机生效

#### Scenario: 客座 Agent 与子任务处理现有文件
- **WHEN** A 在 X 的会话中让受邀普通 Agent 或子任务处理本轮文件
- **THEN** 继续使用宿主/父任务的有效目录，自身能力配置和权限保持原规则，受治理任务额外继承父任务发布保护与能力上限，不通过客座或子任务扩大权限

#### Scenario: 本人业务目录中存在同名配置文件
- **WHEN** A 的私有 Agent 本人目录内含 `RULE.md` 或 `skills/` 等同名内容
- **THEN** 这些内容保持业务文件身份，不替代本轮固定版本的配置与技能来源

#### Scenario: 共享定义与既有文件目录分离
- **WHEN** 共享 Agent 接入发布治理，已有用户文件和历史附件，且旧工作区规则随后改变
- **THEN** 业务 cwd 和历史附件定位保持，正式规则从固定发布包加载，不从旧工作区或个人同名文件热更新
