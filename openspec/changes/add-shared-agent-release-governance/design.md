## Context

范围和动机见 proposal.md。当前 `agent/admin.py` 已有修订与并发提交机制，`auth/service.py` 已区分私有 owner 和共享资源资格，运行时已有授权、审批、配额及 Linux/macOS 沙箱。需要补齐的是：管理草稿不影响线上、运行固定定义，以及现有可写根不能覆盖核心与控制数据。

合并基线已包含较早的共享发布切片（`auth/agent_release.py`、`agent_releases` 与 `agent_bindings` 发布列、`shared_agent_release_governance` 开关及相关服务/路由测试）。该切片的范围、审批、回滚和开关语义与本文不同；代码保持原样，后续按本文适配并复验，不将旧任务完成状态直接套用到当前任务。旧方案与差异说明保留在 [历史方案说明](evidence/legacy-shared-release/README.md)，旧测试证据不能替代本文的完整验收。

当前 `CORE_FILES` 把规则、用户信息和 MEMORY.md 放在同一列表，不能整体复制成发布包；现有沙箱会授权部分工作区父目录且保留网络，也不能直接视为核心不可改。系统供应对象当前有来源与删除限制，没有通用模板字段锁定/升级合并机制。现有首次引导要求聊天修改 AGENT.md/USER.md 并删除 BOOTSTRAP.md，提示构建器也有更新人设/称呼的写文件引导；受治理对象须同时调整这些入口，避免只读包下重复引导或写入失败。

个人目录统一 change 已归档到 `archive/2026-10-10-unify-private-agent-personal-workspace/`，现行 specs 是实现依据。本 change 不移动既有用户子树、记忆、会话或历史附件，也不修改工作区中其他任务的代码。

## Goals / Non-Goals

**Goals:**

- 私有/共享复用同一套草稿、发布、回滚和保护服务，归属与运行授权继续按现有规则判断。
- 在所有已启用执行路径上防止核心与控制数据被改写，同时保留获权业务文件、脚本及网络处理。
- 并发修改、故障恢复、历史隐私及存量切换有确定结果，未发布草稿不进入正式入口。

**Non-Goals:**

| 延期内容 | 首期替代及理由 |
|---|---|
| 通用出口代理、全工具副作用分类 | 使用现有身份、凭据、连接授权及沙箱，只验收本次启用路径的核心写边界 |
| 任意远程服务行为漂移检测 | 校验可观测 schema/声明版本/摘要，实际权限依赖可信连接和目标端授权 |
| 仅预览测试人员及独立策略编辑权限 | 预览/绑定配置复用维护资格，发布与回滚共用一个权限 |
| 生产可写或任意网络脚本预览 | 使用明确的有限预览能力集合，测试账号集成另行规划 |
| 模板字段锁定、自动升级合并平台 | 保留已有来源/删除规则，快照实际有效定义 |
| 独立预览管理系统、多个草稿分支 | 一份当前草稿，预览沿用已有会话/run 记录与临时产物清理 |
| 独立版本撤销及按版本批量取消 | 使用停用、既有任务取消和回滚处理，当前权限仍逐次校验 |
| 管理员代 owner 发起共享、跨人员确认流程 | 首期私有转共享由 owner 本人确认并提交，转换在停用状态下进行 |
| 新的个人资料或初始化平台 | 复用现有个人域/数据服务和配置表单，只补受限资料更新及引导状态 |

不承诺提示词保密或模型回答绝不被输入影响。宿主 root、获授权管理服务和部署控制属于受信边界；关键业务权限始终由模型之外的现有规则执行。不新增一级发布中心或双人审批。

## Decisions

### 1. 两个持久化概念与一个修订协议

在现有实例存储中增加或扩展两类记录，不预设四套独立表：

- **当前编辑状态**：tenant/agent、一个草稿及 base_release_id、active_release_id、revision、治理兼容版本。归属/启用仍引用原权威字段，不复制另一份可写状态。
- **不可变版本**：release_id、来源草稿修订、定义/清单摘要、包地址、发布者、时间与说明，以及发布时 scope、私有原 owner。包的可用/已清理状态、明确保留标记与不可变正文分开维护；首期不增加独立 revoked 状态。

身份库拥有租户、owner 和授权；上述控制记录由管理服务维护，并与归属转换使用同一事务边界。文件包只负责不可变内容。Registry/`team.json` 可保留管理兼容投影，但受治理运行只由 release loader 装配，禁止回退到旧可写来源。

保存、发布、回滚和转换均校验同一对象的 expected_revision；任何成功变更递增 revision，发布检查因此自然失效。发布还绑定 expected_active_release_id 和内容摘要，使用幂等键防止重试重复发布。同键异内容返回冲突。采用一个修订协议会让少量互不冲突的操作也需重试，但比独立 draft/head/visibility 代际简单。

编辑已发布对象时，无草稿则从当前版本创建；有草稿则继续，重复打开不覆盖修改。发布成功在同一事务将草稿对齐新基线，竞态保存返回冲突；回滚保留草稿并提示基线变化。不开设长期 preview 表：固定快照引用、修订和 purpose 写入现有会话/run 记录，临时文件按有界生命周期清理，在途引用不得提前删除。

### 2. 最小授权矩阵

| 操作 | 私有普通对象 | 共享普通对象 |
|---|---|---|
| 草稿读取/编辑、合法绑定配置 | 当前 owner + 既有维护功能资格 `agent.edit` | 既有 `agent.edit` + 对象 edit 或合法租户管理资格 |
| 预览 | 上述维护资格 + chat/model/tool 等实际运行依赖 | 上述维护资格 + chat/model/tool 等实际运行依赖 |
| 发布/回滚 | 当前 owner + `agent.edit`，无需新增逐对象 grant | 新增 `agent.publish` + 对象 publish 或合法租户管理资格 |
| 启停 | 沿用既有 owner 启停规则 | 沿用既有 enable 规则 |
| 正式使用 | owner + 原运行资格 + 有效 release | 原功能/对象运行资格 + 有效 release |

预览不要求正式 agent.use，也不依赖已发布状态。首期不向非编辑者单独授予预览权。工具/连接配置只是草稿字段，编辑者不能配置超出当前可授权范围的能力，运行时授权继续取交集；发布者可审阅固定差异和清单，publish 不附赠编辑权。

只新增一个功能权限和一个对象动作，回滚复用 publish。member 默认集合保持原样。新部署 tenant_admin 显式默认集合加入 agent.publish；升级只向仍采用上一版完整默认集合的 tenant_admin 追加此项，对已收紧、空集合或自定义角色保持原值，并报告需显式授权的角色。不动态展开目录，不运行时恢复被撤销的权限。owner 无 edit 或有效权限为空时，不能发布/预览；私有 owner 资格不延伸到共享或其他人的对象。

所有私有内容接口先检查当前 owner，再检查维护资格；平台 all 和租户管理权不授予私人正文读取权。系统供应助理保持既有来源标识、删除规则及合法供应入口，不新增字段锁定和模板升级合并。受控供应可通过同一快照服务建立准备就绪的首版本，普通用户新建仍是未发布草稿。

### 3. 发布边界按内容分类，不按 CORE_FILES 整体复制

| 内容 | 归属与版本处理 |
|---|---|
| AGENT.md、RULE.md 中的有效定义，persona、场景、技能及脚本、实际作为规则的 SOP、子 Agent 模板 | 纳入固定定义；核心初始化在首次发布前完成，正式运行不自动改核心 |
| 模型选择、工具清单、连接稳定引用、知识集合绑定 | 固定选择和上限；当前授权、连接分配、审批、配额继续实时收紧 |
| USER.md 中的姓名、称呼等个人资料 | 属于当前租户/用户的数据，不进入 release；复用现有个人域与本人数据服务受限读写，不因更新资料产生新版本 |
| 引导完成状态、MEMORY.md、memory/、会话、调度状态、索引、用户业务文件 | 动态数据，保持原专用服务/owner，不进入发布包，不因发布或回滚复原 |
| 旧 BOOTSTRAP.md | 仅作管理初始化的兼容输入，不打包或作为正式运行指令；加载 release 不删除包内文件 |
| 知识正文 | 动态检索数据；如果被用作执行规则，相关规则内容必须固定 |
| 密钥、令牌、浏览器登录态 | 保留现有凭据服务，包内仅允许稳定引用，不复制凭据正文 |

核心初始化复用现有配置表单，先完成 AGENT.md/persona 等必要定义，再首次发布；系统供应默认助理可使用已完成核心初始化的合法默认定义。个人资料可以稍后补齐，缺失称呼不阻断有效版本运行。引导完成与否存入现有状态服务，不能靠在发布包中修改或删除 BOOTSTRAP.md 表示完成；正式聊天不再执行旧的写核心/删引导脚本指令。

本人资料更新只接受已登记的姓名、称呼等数据字段，主体来自可信租户/用户上下文；不接受任意文件路径、其他 owner、核心规则或权限字段，不向脚本开放 USER.md 原始路径写权。个人资料按 user-personal-context 的现行规则装配，缺失不造空档案，群组/共享会话不注入个人段；内容作为数据，不能改变授权、工具上限或核心定义。预览使用测试资料和测试引导状态，不写生产个人资料。旧 USER.md 仅在归属可验证时作为受限兼容数据来源；归属不明时进入迁移报告，不推定为当前访问者所有，不复制进 release 或随转换公开。

定义包使用受保护的新根；state_root 与 work_root 沿用当前定位。运行仅通用写入本次获权业务目录/临时区，动态状态由原专用服务更新，不向任意脚本开放整个 Agent 根或个人记忆根。业务目录同名 RULE.md/skills 不成为核心来源。

管理草稿、release 文件及可替换祖先目录、控制数据库/WAL 和管理凭据必须对运行只读或不可见。哈希可信基准存在受保护管理存储中，不能让 worker 同时修改包和校验值。包缺失/损坏时拒绝运行。

### 4. 有限预览先做可证明的能力

仅认证的 Web 管理入口及其 Desktop 适配可创建 purpose=preview。服务端校验维护资格、固定草稿修订、建立独立会话/run 和本人测试输出；普通聊天、钉钉/企微消息不能声明预览用途或任意版本。

首期必需范围明确为文本对话和测试文件读取/生成。已有实际验证证据的只读连接可按需接入，缺少此类连接不阻止基础预览、发布或整体上线；本期不承担通用连接只读认证/分类项目。每个可选连接须有目标端实际只读身份及验证证据，不能仅依据 MCP tools.read、readOnlyHint、工具名称或模型声明放行；未验证连接一律显示“预览暂不支持”。

生产发送、业务写入、正式调度、生产个人资料/引导状态和长期记忆写入不开放。测试文件生成若调用 Shell，必须无生产凭据、关闭外网、只挂载测试输入/输出与必要只读运行资源；无法满足时不在预览开放 Shell。正式运行的合法业务网络不受这个预览限制。不提供解除预览限制的请求参数，预览通过不代表未覆盖的生产连接已经通过验证。

### 5. 复用执行边界，补齐核心写保护

从 `common/runtime_identity.py` 传递可信 purpose、版本/快照标识、原始主体和父任务能力上限。`agent_stream.py` 的工具枚举及实际 dispatch 都校验固定清单；发布清单 `[]` 为无工具，必要字段缺失为无效，旧 allowlist 缺省继承仅用于未迁移对象。当前资源、凭据分配、审批和配额接缝继续使用，不新增一套通用授权引擎。

在现有非豁免检查和实际修改服务补充核心保护：文件/上传/解压/移动/删除不能越根或替换祖先；管理 API 必须需要独立认证的管理请求，不能使用聊天主体身份直接升级为管理能力；旧 core-file/技能/场景更新入口进入草稿服务或明确拒绝。文件工具、Bash、派生进程及后台写服务使用一致根边界，阻断链接与竞态替换。

扩展现有 Linux/macOS launcher，只挂载允许的业务根与只读定义，清理环境/FD，隔离管理凭据、数据库和控制 socket；任意代码不得在具备管理能力的服务进程中直接执行。各平台以真实业务和越界测试分别验收，隔离失败不回退普通 subprocess，不静默改派执行位置。

网络/连接复用既有业务凭据与目标端授权。核验启用的 HTTP/MCP/数据库/浏览器是否能借运行凭据、管理登录态或可信内网调用改写核心/权限；移除管理身份或限定该路径后才允许启用。若现有机制无法约束某路径，则该路径保持不可用并记录阻断原因，不能宣称已全面保护。首期不新增通用出口代理，也不能用禁用所有 Shell/网络替代正常业务正向验收。

远程连接只能检测 schema、声明版本、目标身份或可取得的摘要变化；变化时重新校验，超出固定清单则拒绝。不声称能检测“同名同 schema 但内部逻辑变了”。核心安全依赖不授予这些业务身份管理控制能力；外部业务风险仍由原权限与审批承担。

后台自动进化不得直接改草稿或发布定义，只能输出建议，获权维护者自行纳入草稿；复用现有建议/产物机制，不建设候选合并平台。修正现有提示模板里“自动更新 AGENT/RULE/skill”、原始 USER.md 写入和“删除 BOOTSTRAP.md”的引导，核心改动只在管理草稿完成，个人资料走受限数据服务；动态记忆仍走原 owner 服务，不改变本期无关的群记忆产品行为。

### 6. 原子发布与运行切换

提交时重验维护/发布资格、预期修订、当前归属、依赖与部署门槛；构建临时包、校验摘要、原子固化后，在同一控制事务登记版本、可靠审计事件并切换活动指针。审计写入或事务失败不改变线上；固化后遗留孤包按清单清理，不能被运行引用。

顶层运行启动时固定有效 release，同一会话下一轮重新装配系统配置和工具缓存。历史只作对话数据。发布不热切在途任务；派生任务继承父目的/版本关系/权限上限，跨 Agent 委派还要验证真实主体对目标的访问权并固定目标版本。独立 scheduler 触发时选择当时有效 release 并重验授权；机器主体不冒充 owner。不能承载保护的外部 coding 或其他执行器不得接收受治理委派。

回滚共用发布权限，重验版本包仍可用、完整性、历史隐私、当前依赖及部署兼容性，保留草稿与现有授权。停用阻止正式运行的新启动、排队启动与后续工具调用；已启动的进程不因停用被宣称自动终止，按既有任务取消入口显式处置并报告实际结果。首期风险处置为停用、按需取消任务、回滚到可用版本、显式恢复启用，不新增独立版本撤销接口/状态或按版本批量取消机制；不承诺撤回已完成副作用。权限/连接撤销后的逐次拒绝不变。

审计记录与完整发布包分别管理：审计和最小版本元数据按现有审计规则保留 release_id、摘要、操作者、时间、来源范围/owner 和结果，不含个人正文；完整包按数量/期限策略清理，活动、在途运行、当前草稿基线和明确保留标记所引用的包除外。一次普通审计引用不自动构成包的永久保留标记。明确保留标记仅由原有发布资格者经管理入口设置/解除并留痕，不新增权限或归档平台。

清理与激活/新增引用使用同一控制存储中的短事务校验，不能在变为活动或被运行引用后删除包。清理后保留“内容已清理”的历史条目和审计，正文/差异/下载/回滚返回明确不可用原因，不从草稿或旧 workspace 重建。保留例外可能超过普通数量上限，需如实报告，不为满足数量上限删除受保护包。

### 7. 范围扩大与收窄分别处理

首期两个方向都要求先按既有启停入口停用对象，阻止新正式运行和排队启动，处理与目标范围冲突的默认/渠道引用，并等待已启动任务（含预览）结束；需要取消时由获权人员使用原任务取消操作。未结束、仍有排队任务或引用冲突则拒绝转换。预览启动、重新启用/引用修改与转换提交复用对象级短事务/锁，重验状态、统一修订与活跃引用：预览先登记则转换拒绝，转换先提交则旧修订/旧资格的预览请求拒绝。停用不额外禁止维护者正常预览，也不新增持久的“转换中”状态或常驻跨入口任务协调平台。转换提交重验停用状态、归属、修订和引用，失败保留转换前的停用状态，不自动恢复、取消或改绑。

私有转共享仅由当前 owner 本人在同一个经认证管理请求中确认目标修订和待公开定义后提交；管理员仅在自己是该 owner 时可操作，首期不接受非 owner 代发起、代确认或异步确认凭证。个人资料、引导状态、记忆、文件、会话和凭据不随转换公开。成功后原子清除 owner 与活动指针，建立确认过的共享草稿并保持停用；由获权共享发布者完成首次发布，再按既有启用资格显式启用。原 owner 不再有隐式维护权，使用按共享授权；原私有历史不进入共享差异视图或直接激活。

共享转私有仍由租户管理员指定有效 owner。定义不变、当前完整版本和保留草稿依赖均可由目标 owner 使用时，原子修改归属并保留活动版本/草稿，仍保持停用；目标 owner 可按原启用规则恢复，无需重复发布。从未发布对象仍为未发布。依赖失效、包无效或需要改定义时拒绝转换，先按原流程修复，不做部分转换或隐式删字段。

历史访问取“当前对象资格 ∩ 版本原始隐私约束”。私有版本还要求原 owner 匹配当前合法 owner；共享对象不会暴露其旧私有历史，新 owner 不继承别人的私有版本。原共享版本在收窄后只由当前 owner 访问，启用后可继续使用。范围转换使用统一 revision/CAS 与归属事务，无需额外可见范围代际体系；两个方向保持个人资料归属、文件 owner、目录与附件映射，不迁移、不转让。

### 8. 管理交互与错误

现有详情保留三个页签。运行权限页编辑的绑定属于草稿，与规则一起审阅、发布；不建立独立“策略编辑”工作流。共享编辑者可以保存/预览，有发布资格者才可发布/回滚；私有 owner 使用同一组件，发布标为“发布并使用／仅自己可用”。

同时展示可见范围、线上版本、草稿修订和未发布修改。保存提示线上仍为 v1，预览标示测试环境及未覆盖能力，发布成功才提示 v2 生效。首次未发布无正式对话入口；发布超时通过原幂等标识查询/重试，冲突保留本地修改。回滚提示草稿保留和基线变化；已清理历史只展示获权元数据，禁止下载/差异/回滚并说明原因。本人资料更新不进入发布向导；转换展示先停用、处理引用和等待任务的条件，成功后明确仍为停用。

后端提供最小线上投影、draft_revision、active_release_id、revision、has_unpublished_changes、allowed_actions；前端字段不能代替鉴权。建议错误沿用现有格式并区分 agent_unpublished、stale_revision、release_check_stale、release_integrity_failed、preview_capability_unsupported、runtime_policy_denied、release_package_unavailable、release_runtime_unavailable。跨租户信息隐藏仍遵循原接口契约。

## Risks / Trade-offs

- [有限预览覆盖不了全部正式业务] → 清晰列出未支持能力；首期不把测试成功当作生产发送/写入已验证。
- [现有写入口或网络身份存在旁路] → 按启用路径盘点并做真实拒绝测试；未闭合路径不启用，合法业务需同时通过。
- [单一修订带来额外冲突] → 保留用户编辑并要求重新比对，换取更简单的一致提交协议。
- [个人资料更新或首次引导被核心保护阻断] → 个人资料/引导状态走动态本人服务，核心初始化在首次发布前完成，正式加载不写包；专门验证 USER/BOOTSTRAP 与转换边界。
- [有界保留被审计引用变成永久保留] → 审计元数据和完整包分开；仅活动/在途/草稿基线/明确保留阻止包清理。
- [转换停用被误解为自动取消任务] → 界面显示实际任务状态，等待或使用原取消入口，转换后不自动启用。
- [私有历史因相同 agent_id 泄露] → 每个版本保存原始范围/owner，列表、差异、下载和激活都执行历史 ACL。
- [旧二进制忽略治理标记] → 部署与启动兼容门槛阻止不受支持构建启动；不依赖旧代码理解新增字段。
- [模拟原型被当成产品] → HTML 原样保留，README 标注差异；实际 API/OS/UI 证据单独验收。

## Migration Plan

1. **盘点与兼容准备**：按现行 specs 核验个人目录、权限、审计/凭据/审批/配额及对应 OS 切片；记录最低兼容构建和 schema。先部署同时支持迁移前后对象的兼容构建，治理能力默认关闭。
2. **控制与执行接入**：实现上述两个数据概念、授权和快照服务；受保护管理/预览只对通过鉴权与隔离验收的范围开放。Linux/macOS 分别设置支持矩阵，不要求同时上线。
3. **等价基线批处理**：获授权迁移服务在明确对象范围、备份与一致源快照下，将原有效配置转为首个 release；内容、scope 和业务授权等价时无需逐个 owner 再确认，运维仅接触脱敏结果。个人资料需保持可验证的原归属，初始化完成状态按旧状态映射且不复制旧自修改引导进 release；缺少核心初始化的对象需先完成草稿配置。无法等价装配私人资料、内容过滤导致行为变化、依赖缺失、范围或权利改变不属于等价，留在迁移前兼容路径并报告待处理，不静默发布。必要时仅暂停该批入站/调度/后台写入以取得一致快照。
4. **原子切换与恢复**：以对象/批次原子切换治理标记、活动版本和加载来源，迁移幂等；失败只阻止该对象/批次，成功对象继续服务。未迁移对象暂用原兼容路径且不宣称已获新保护；已迁移对象不能退回可写定义。保留原默认/渠道引用和用户数据地址，不自动改绑。普通新建草稿不借迁移自动发布；合法供应服务建立默认助理首版本走明确供应授权。
5. **启用与防降级**：能力开关只控制已验收路径开放，不清除持久治理标记；关闭或故障时已治理对象拒绝执行。部署系统阻止低于声明兼容版本的构建启动，恢复选用兼容构建与一致备份；业务版本回滚只能选当前兼容且合法的历史包。首期交付验收要求声明目标范围全部迁移或按授权明确停用，不能把兼容过渡无限期当作保护完成。

验收覆盖修订竞争/故障恢复、私有/共享权限、个人资料与首次引导、文本/测试文件预览及限制、核心写拒绝与合法业务、渠道、调度/委派、停用后由 owner 自助共享/管理员收窄、审计与包分别保留、等价批迁移、旧构建降级阻止及既有附件定位。可选只读连接仅验收实际启用项，不作为整体上线门槛。仅在临时租户/测试实例使用真实执行链路，模拟 Demo 不计为实现证据。预览 TTL、包保留数量和完整性缓存上限在实施时按现有配置风格设为有界值，不改变本设计的访问与引用保护规则。
