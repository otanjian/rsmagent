## Goals / Non-Goals

**Goals:**

- 已有获权主体、功能开关和合法技能链路保持有效，同时使越权访问在实际运行中失败。
- 本轮以单机、单进程 SQLite 部署为基线，按三个批次交付可独立审阅的必要修复。
- 真实安全、功能与恢复结果可追溯到同一候选版本。

**Non-Goals:**

- 不新增编排平台、执行微服务、跨主机任务总线、Redis 或 PostgreSQL；不重写 Agent、scheduler、Desktop 协议。
- 不建设热备、增量备份和自动容灾；第一版采用维护窗口停机快照。
- 不实现 Windows 新执行后端，不开展 Windows 桌面测试，不删除或关闭已有 Windows 功能。
- 不扩大原本未启用的消费者；不借本次变更重构其他进行中的 UI、记忆或登录 change。

## Decisions

### D1. 用功能基线约束修复，而非减少可用能力

阶段 1 固定实际已启用能力、账号角色、工具/技能授权、用途凭据、网络依赖和代表性技能清单。至少覆盖普通成员、租户管理员、平台管理员；正向执行使用各自已有授权，不用平台 all 替代成员。

每项安全修复都有配对的正向测试。当前已授权的 Python/文档处理、文件产物、业务系统请求、后台运行、增量输出和取消都需验证。不得调整角色、开关或全局联网状态以消除失败。隔离缺失时单次动作仍按安全规则拒绝，但候选因此未通过；继续修复执行环境，不将拒绝全体任务视为 P0 解决。

备选“只允许管理员 Bash”“关闭隔离开关”“只新增路径字符串规则”均不采用：前两项违背功能约束，最后一项无法覆盖解释器内部构造路径。

### D2. 保持工具接口，在启动处实施 OS 隔离

服务端首个候选目标按 Linux 单机/容器设计。用户于实施中明确当前没有 Linux 测试环境，要求先完成所有本地可做的修复：允许实现 Linux 启动适配及命令构造回归，真实宿主 OS、内核、容器权限和运行用户验收仍为发布前置。本机 macOS 的检查不能证明 Linux 部署可用。

Linux 选择 **bubblewrap 启动层**作为本期单一服务端方案，不引入独立执行服务、嵌套 Docker daemon 或把宿主 Docker socket 交给 Agent。bubblewrap 只是隔离机制，实际安全性取决于挂载、进程与权限策略；其用户命名空间前置需在最终容器/宿主组合中实测。[官方说明](https://github.com/containers/bubblewrap#sandbox-security)

执行上下文继续由现有身份/对象作用域解析，启动层只接收已验证的读取根、写入根、cwd、运行时路径、私有临时根、任务标识和经处理的环境。保持单次检查后立即启动，入队后仍重验权限，不能接受模型提供的任意挂载列表。

- 从最小文件系统视图开始，只读提供解释器、工具、所需运行库和技能；按原权限提供项目、本人及共享业务数据。
- 不能直接挂载整个宿主 home、数据根或含运行数据的源码根。共享目录包含私有子树时，需要排除其未授权部分，不能因父目录可读就暴露其他成员文件。
- 每个任务拥有独立临时目录，保留必要系统临时行为，禁止把整个宿主 `/tmp` 当成共享合法根。
- 使用独立进程视图，清理无关继承 FD，不暴露宿主管理 socket、控制面进程环境及设备；派生进程与原任务保持同一约束。
- 合法联网按现有业务要求保留，复用原外部连接与凭据授权，不直接套用 Desktop 的全禁网策略，也不声称文件沙箱自动提供目的地址级网络授权。部署侧已有 egress 规则保持；管理服务必须继续鉴权，不能通过共享网络获得免鉴权管理能力。
- 保留现有前后台任务登记和进程树回收。原 `bash_id` 继续由现有后台注册表管理，补齐其 owner/任务边界；增加启动接缝不再创建另一套任务数据库。

定向续修（风险复评第3项）：现有后台注册表的20项保留目标只淘汰结束记录，不能限制运行数。新增单进程容量 `COW_BASH_MAX_RUNNING`（默认20，非法或非正值回到默认）；锁内预留启动名额，进程创建期间不持登记锁，避免影响输出和取消。启动中名额与未完成回收的原任务合计，线程/进程创建失败回收并释放；正常结束无须轮询即可释放。保留前台、后台和权限契约，不新增排队服务或身份配额。

macOS 桌面已有本机项目启动器继续使用现有契约。若 macOS 本地后端也承载本次受影响的服务端 Bash 路径，复用既有 Seatbelt 构造规则增加对应调用点适配，并单独保留该路径原有联网能力；不能将它转成远端执行或未经验证直接运行。只抽取实际共同的环境/启动参数，避免为两个系统设计通用插件框架。

最终 Linux 环境必须通过真实启动探测。默认 seccomp/命名空间条件不支持时，给出需要的最小部署配置并实测；不得以 privileged、整根挂载或全局 `seccomp:unconfined` 代替边界验收。如果目标环境与本决定不兼容，应记录具体阻碍并修订部署适配，不能静默改为无隔离执行或关闭功能交付。

实施实测补充（2026-10-02）：当前 macOS Seatbelt 能限制文件/Unix socket，但 `KERN_PROCARGS2` 仍可读取同 uid 合成目标的环境；显式 sysctl deny 也未解决。不能以 ps 不可执行代替此检查。原生就绪探测现包含真实合成进程环境读，与文件正反例分别记录，当前 macOS 候选保持未就绪。没有关闭已有功能、改角色或转移执行位置；本期不为绕过该内核条件引入特权常驻服务/虚拟机。完整 macOS 进程隔离验收保持未满足，并与已有 Desktop 本机项目文件沙箱证据区分。

### D3. 任务凭据按用途注入，并完成技能兼容映射

保留 `auth` 与外部连接服务作为凭据权威源。原生模型和受控 MCP 连接的凭据仍由其受控调用点使用，不因为脚本运行就放入脚本环境。

前台、后台和失败重试共同调用一个环境构造函数：必要系统变量（解释器路径、语言、证书及经核实的代理设置）＋当前任务授权业务凭据＋当前任务路径。部署主密钥、Cookie、原生会话、宿主管理凭据不在可传递集合内；临时 HOME/缓存路径指向任务允许区域，保留技能需要的运行时行为。

对依赖全局 `.env` 的实际技能列出“变量名—业务用途—凭据归属—授权来源”映射，沿用现有凭据机制保存与解析，保留脚本变量名。只迁移明确归属条目；有歧义的业务凭据必须在切换前完成核对，不能删除变量后把技能失败记为安全通过。凭据在每次启动前重新解析，不创建跨请求明文缓存。输出/错误/进度沿用并补齐脱敏，保留真实退出码和诊断。

续修补充（2026-10-03）：前后台共用流式字节脱敏，只暂存可能组成凭据的末尾前缀，优先匹配完整长凭据，在写入缓存/截取进度尾部之前替换。普通短进度不等待固定长度缓冲；已支持的输出编码回退继续适用。后台命令元数据同样脱敏，失败重试日志只记录参数个数，不回显参数内容。

### D4. 两个身份缺陷做局部修复

`LoginRateLimiter` 保留进程内双维度结构：在锁内回收过期且为空的桶，容量将满时必须清理；可低频清理避免每次遍历 10,000 个键。同步清理相关审计去重标记，保留活跃阻断，重试时间按有效窗口计算。不增加 Redis。

`http_policy` 取消非预期异常继续调用 handler 的分支，统一 503。旧 `http_policy_gate_fail_closed=false` 不再改变安全结论，配置迁移说明可提示其已无放行语义。确定性 400/401/403、来源检查和路由分类不变；故障恢复后的合法请求自然重验通过。

### D5. 单一镜像入口与最小运维配置

以 `docker/Dockerfile.latest` 为唯一维护的正式构建定义，Compose 显式引用；根入口改为明确使用同一规则的方式或清晰引导，不再直接继承上游应用镜像。增加 `.dockerignore` 和明确的运行文件复制范围，配置在运行时生成/挂载。仓库技能、模型适配、渠道依赖、静态资源和必要离线资源不能被误删。

构建摘要读取临时副本的实际字节及软链接目标，避免复制后源文件改变造成记录错配；合成排除标记随后写入，覆盖标记位置的软链接前先解除链接。构建通过 `--iidfile` 获取不可变 image ID，扫描通过后才将该 ID 交给后续检查。独立镜像检查也只解析一次输入标签，所有层、历史、启动和记录均使用解析出的 ID。非 root 验收同时检查配置的用户部分和容器实际 UID；启动失败仍清理已创建容器与匿名卷。这些流程有离线回归，真实 Docker 运行仍待环境。

定向续修（风险复评第5项）：镜像检查增加 `--deployment-env`，仅在检查和容器清理成功后原子写出非秘密部署配置。Compose 使用其中的本地 image ID，移除重新构建入口并设置 `pull_policy: never`；文档清除可能覆盖该ID的 shell 变量。跨主机需传输同一镜像并在目标 daemon 重新检查，不混用 image ID 与 registry manifest digest；配置不是完整业务验收证明。`--all` 的本地检查失败时不发布新的配置。CI required checks 生效和真实镜像运行继续待环境，不以本地配置解析代替。

从目标 Linux/Python 组合生成一份生产依赖锁定清单，固定直接与传递依赖，并固定基础镜像摘要；不把当前 macOS venv 的 freeze 当作 Linux 锁。选择可维护的基础镜像，保留安全更新仓库；在变更依赖时重新验证代表性技能。一次镜像扫描记录真实结果，不凭版本外观推定 CVE。

Compose 内部监听所有容器接口，宿主按反向代理部署限制端口；提供 HTTPS、可信代理覆盖转发头及 Cookie/来源检查例子。持久化所有实际数据根，保留非 root 运行；补 `restart`、healthcheck 与适当资源上限，具体数值由目标容量测试填写。

运行日志采用标准轮转处理器，起始配置为单文件 20 MiB、5 个历史文件，可部署调整；身份审计表不随日志轮转删改。新增 `/api/ready`（经唯一 route registry 登记）检查身份库基本读取、必要目录、缓存的启动隔离探测结果；只返回状态及脱敏分类，不返回目录/SQL/凭据。目录探测如需临时标记，只允许自身诊断临时文件并回收，不写业务表、不初始化/迁移数据库。保留 `/api/health` 的桌面存活语义；容器 healthcheck 报错用于发现未就绪，进程退出后的重启交给已有运行管理器，不把 unhealthy 误写成 Docker 自动重启保证。

### D6. 增加显式停机整实例备份模式

复用 `cow backup` / `cow restore` 的 CLI 与归档工具，增加 `--instance` 模式；原工作区模式和历史格式不改变。整实例使用带版本的 manifest，恢复按格式分派。职责仍位于同一备份模块或一个窄化辅助模块，不新增备份服务。

通过配置、身份库登记和 Agent Registry 枚举全部根，包含配置的数据根之外的 `identity_db_path`、`tenant_shared_base`、私有 Agent/用户根及业务数据库。嵌套根去重。只读查询登记信息，备份过程不得调用会自动迁移/初始化数据库的服务构造器。

第一版要求维护窗口：操作者停止应用、scheduler、渠道写线程和后台执行，复用现有 PID/生命周期检查确认退出；仅 HTTP 探针失败不能证明停机。必要时增加与启动流程共用的最小互斥保护，避免备份期间重新启动写进程。停机后身份库通过只读连接和 SQLite backup API 生成包含已提交 WAL 页的独立快照，其他业务数据库随完整目录文件集保存，不做运行中逐文件拷贝的“热备”。发布归档前重验停机状态，不能在替换旧备份后才检查。

续修补充：备份按运行环境中的声明配置覆盖值枚举根，并归档生效配置；Docker 模式从目标容器读取环境和工作目录，主密钥仍单独提供。渠道默认游标、微信多实例凭据按完整文件名关系保存。外置单文件按父目录分组但只收录明确文件列表，避免为保留相邻文件关系而归档整个 HOME；尚未生成的渠道文件仅保存恢复路径，不虚构内容。

实施核对补充（2026-10-02）：现有 `.cow.pid` 只登记主进程，Bash 后台任务使用独立进程 session，登记表位于父进程内存。因此，主进程退出或 PID 文件不存在不能证明后台写入已经停止；仅给父进程增加文件锁也不能补齐这项保证。新增整实例模式强制使用启动互斥，并要求专用 Linux cgroup 空组、不同系统启动周期，或宿主 Docker daemon 对精确已停止容器的前后复核；缺失证据拒绝生成包，绝不把旧工作区归档加上“整实例成功”标签。Docker 运行态路径按已检查的持久化挂载映射到宿主，未挂载根拒绝。合成离线备份/恢复已本地验证，目标运行管理器的停止与恢复保证仍需目标环境实测，不为解决前置新增常驻备份服务。

备份写入临时文件，校验后原子发布；目录 0700、文件 0600，生产存放于受控加密介质/存储，复用部署现有加密手段。需要恢复的运行凭据文件纳入受控归档，主密钥单独托管；清单和日志不含明文秘密。不得把主密钥与备份一起放进源码、镜像或普通下载目录。

恢复到空根或暂存目录，操作者明确确认逻辑根映射，校验路径、完整性、格式与数据库兼容性后再切换配置。整实例模式不复用当前“边复制边合并”语义覆盖活跃实例。保持 users/tenant/owner ID 与引用一致，只迁移部署路径。演练期间抑制对真实外部系统的副作用，使用合成连接或隔离接收端验证调度/凭据；这只是演练措施，不作为生产关闭功能的配置。

### D7. 一份发布检查入口与准确的平台证据

增加 `scripts/check-production.sh`，调用现有测试、route coverage、module seams、Node 行为测试、renderer `tsc --noEmit` 和构建；独立步骤保留退出码与实际结果。先本机可执行，再接实际交付仓库/分支的 runner 与 required checks，不以 GitHub 上游 workflow 证明 Gitea/main 已受保护。

修复 `ChannelsPage.tsx` 的图标类型兼容；测试夹具中的 macOS 路径先 canonicalize；外部目录权限测试用明确无读取权限的角色。保留错误断言原本的安全属性，不把全部 403 改成 200 或删除测试。

真实验收包括：Linux 最终镜像上的隔离正反例、完整恢复、Web 浏览器与 macOS 实际客户端登录/重登/文件执行/取消；真实远程服务的断线重连、重启及撤权时序。按原有已启用技能清单选择有代表性的实际脚本、联网与后台任务，测试可使用合成数据和受控测试凭据。

Windows 记为 `deferred: environment_unavailable`，不进入本轮必需检查列表、不宣称通过，不因共享代码修改删除 Windows 分支。缺 Linux/远程环境时对应必需项保持未完成，不能以 macOS 回环或单元 mock 代替。

容量只做目标并发下一轮有代表性的基线观测，记录延迟、排队和内存。发现持续增长后增加局部队列上限/过载反馈；本轮不预先改造成分布式架构。

## Risks / Trade-offs

- [目标内核/容器不支持隔离启动] → 第一阶段实测用户命名空间、运行用户和 seccomp；正式镜像中重测，不使用特权和无隔离回退。
- [技能依赖网络、系统库、缓存或既有凭据] → 建立实际能力清单，按用途提供必要只读运行根和变量，完成普通成员正向执行后切换。
- [租户共享根中混有私人子树] → 消费现有 owner 范围构造执行视图，用同租户不同成员负向测试验证，不仅测试跨租户。
- [运行态停止不完整影响备份一致性] → 停机检查包含后台任务和重启互斥；不声称进程在线快照可用；必须恢复演练。
- [与现有未提交改动或进行中 change 重叠] → 只修改本轮必要接缝，保留其他工作区变更；验收注明实际代码树，不替其他 change 签署通过。
- [开发机无法覆盖生产环境] → 明确区分本地、Linux 容器、远程与安装包证据；Windows 按用户要求暂缓，其他必需环境缺失不冒充成功。

## Migration Plan

1. **固定基线**：登记当前已启用功能、身份/授权切片和技能依赖；合成复现漏洞。按用户最新要求先完成可本地实施的启动适配；目标 Linux 实测条件具备且真实隔离机制通过后，才允许候选切换，不以本地/mock 结果替代。
2. **第一批——安全与缺陷**：完成 OS 启动边界、任务凭据、镜像排除、限流回收及鉴权异常修复；原功能与安全双向测试通过后才能标记本批完成。保留功能开关，不以关闭开关完成迁移。
3. **第二批——部署与恢复**：固定本项目镜像和依赖，完成停机整实例备份/恢复、轮转日志、就绪与代理配置。真实恢复演练通过后才具备交付恢复保证。
4. **第三批——发布验收**：统一检查与实际仓库准入、Linux/远程/Web/macOS 验收、容量基线；Windows 明确暂缓。候选提交和产物摘要固定后出具发布记录。
5. **切换与回滚**：维护窗口备份完整数据和配置，迁移必要凭据映射后部署已验收镜像；验证原用户功能再结束窗口。异常时恢复兼容的已验收产物/快照；不自动回滚到已知越权的执行路径，不把恢复工作转换为关闭用户能力。若没有安全兼容回滚产物，记录为发布前未满足条件。

本轮原则上不新增业务 schema；确需辅助元数据时优先复用现有凭据用途与配置结构。任何必要格式变更须带版本和旧工作区归档回归。
