## Purpose

为现有智能体增加使用共享 OpenCode 服务的编码类型，使用户能够沿用智能体分配权限进入代码项目；明确类型配置、旧数据兼容及普通执行路径边界，避免将外部编码服务扩展为新的通用运行平台。

## ADDED Requirements

### Requirement: 智能体类型与项目配置

系统 SHALL 支持 `normal`、`coding` 两种智能体类型，缺少类型的旧档案 MUST 按 normal 处理且不重写原数据。coding 创建 SHALL 要求名称及远端默认项目目录，类型保存后不可变。项目目录 SHALL 与平台状态工作区分开，允许已有非空代码目录。复制 SHALL 只复制档案和项目配置，不复制会话、凭据或代码文件。

#### Scenario: 旧智能体无需迁移即可使用
- **WHEN** 加载未保存类型字段的智能体
- **THEN** 其普通聊天及原配置继续生效，不增加外部服务依赖

#### Scenario: 创建与复制编码智能体
- **WHEN** 用户创建或复制 coding 智能体并指定远端已有代码目录
- **THEN** 保存合法配置，目录不因非空被拒绝，也不在平台服务器上创建或改写该目录；复制不带入原会话

#### Scenario: 修改已有类型
- **WHEN** 更新请求试图将已保存的 normal 改为 coding 或反向修改
- **THEN** 请求明确拒绝，原配置与历史保持不变

### Requirement: 单一共享服务按开关启用

系统 SHALL 使用一个管理员配置的共享 OpenCode 服务，缺省关闭。创建表单 SHALL 展示该服务而不要求用户输入服务密码、会话 ID 或独立服务地址。服务密码 MUST 只用于服务端连接。关闭能力 SHALL 保留档案、关联和缓存，并标记不可用，不回退普通执行器。

#### Scenario: 服务关闭或未配置
- **WHEN** 用户选择已有 coding 智能体或尝试新建编码会话
- **THEN** 显示稳定的不可用原因，不创建远端会话、不调用普通模型，已有缓存不被清空

#### Scenario: 查询智能体配置
- **WHEN** 普通用户读取智能体列表、详情或嵌入地址
- **THEN** 不返回服务密码，不在 URL 或页面消息中携带长期认证凭据

### Requirement: 复用入口授权并防止错误运行

coding 的平台入口及会话管理 SHALL 复用当前身份、智能体分配与历史权限；每次请求重新检查，不能只隐藏卡片。首版 coding SHALL 仅支持显式 Web 对话，MUST NOT 被设为通用默认或进入普通执行器、群聊、委派、渠道与定时任务。模型由 OpenCode 管理，普通智能体的模型授权及隔离规则保持不变。

#### Scenario: 只有查看权限
- **WHEN** 用户可查看 coding 卡片但没有使用授权，并直接请求新建或打开
- **THEN** 服务端拒绝，且不向 OpenCode 发出会话创建请求

#### Scenario: 撤销分配后继续使用平台入口
- **WHEN** 已打开的用户失去目标智能体使用权限
- **THEN** 下一次平台请求拒绝，页面停止刷新并关闭该嵌入视图，不切换到其他智能体

#### Scenario: coding 被提交到普通运行路径
- **WHEN** 调用者绕过选择器提交 coding 为普通执行、团队成员、委派或渠道目标
- **THEN** 返回明确的仅支持 Web 编码入口原因，不初始化普通模型或启动其定时任务

#### Scenario: 设置通用默认
- **WHEN** 请求将 coding 智能体设为全局、租户或用户通用默认
- **THEN** 请求拒绝，现有普通默认及个人助理配置保持不变
