## Why

2026-10-10 排查复现了登录框约 19.1 秒和 9.9 秒才出现、缓存命中约 0.48 秒的差异。已确认控制台资源未压缩、账号检查在大脚本执行后才发出、检查缺少超时；应先通过传输压缩、提前一次只读检查和现有错误恢复降低等待，再用同环境对照判断收益。

## What Changes

- 为公开页面外壳及静态 JS/CSS 启用 gzip，保持现有缓存、版本、来源校验和流式响应行为。
- 在页面头部、重型脚本执行前发起一次有界的 `/auth/check` 请求；由现有账号初始化消费该结果，避免同次启动重复请求。业务脚本仍按原顺序加载，登录表单和认证状态仍由现有实现负责。
- 为首次检查和手动重试统一补充 5 秒请求期限及明确超时提示，沿用当前请求去重、身份代次和重试入口。
- 对比冷暖缓存的资源字节和登录框可操作时间，并回归有效会话、错误恢复和桌面重登录。间歇性公网停顿保留未定位结论，不据此修改数据库。

## Capabilities

### New Capabilities

- `web-console-login-startup`: 首次账号检查与资源加载重叠、一次性消费及失效规则，不要求独立登录应用或动态业务装载。

### Modified Capabilities

- `sidebar-account-menu`: 在既有加载和失败恢复语义上补充账号检查期限、超时提示和迟到响应隔离。
- `production-deployment`: 增加公开外壳/静态资源的压缩协商和缓存正确性要求。

## Impact

- **代码**：主要修改 `channel/web/chat.html`、实际生效的 `static/js/console.js` 账号检查/启动段和账号翻译，增加一个只负责检查请求的小型 fork 脚本。沿用模板逐文件版本标记、原登录模板、样式和全部业务脚本顺序。
- **部署**：更新 `docker/nginx.conf.example` 及现有运维说明，形成仅作用于目标站点公开响应的压缩补丁。HTTP/2 不列为本 change 的要求；若实测仍有明显连接排队，再独立评估。
- **唯一归属**：账号状态继续由现有 `console.js` 管理，身份库及 `AuthSession` 仍是服务端唯一身份来源。早期脚本仅保存本页一次检查的临时结果，不写 UI、不持久化身份、不发起登录写请求。
- **兼容与依赖**：沿用 `user-auth`、`sidebar-account-menu`、`console-route-lifecycle` 和前端实际装载规范。使用既有账号、桌面和资源测试确认受影响行为，不将其他 change 整体完成作为前置。
- **边界**：不抽取认证核心、不建立动态资源加载器、不新建登录样式体系、不新增 feature flag 或数据库迁移。脚本加载期间仍需等待现有 UI 就绪，本次不承诺业务脚本缺失时登录表单也能工作。
- **证据**：[排查基线](evidence/baseline.md)保留实测与未确定部分；[简化审查记录](evidence/review.md)解释删减原因。当前仅修改方案，尚未实施。
