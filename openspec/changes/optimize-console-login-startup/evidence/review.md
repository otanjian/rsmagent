# 简化审查记录

2026-10-10，按用户“检查是否简单问题复杂化，如有直接修改”的要求修订本 change。此次只调整方案文件，未实施产品或部署变更。

| 问题 | 修改及理由 |
| --- | --- |
| 为提前一个 GET 抽取完整认证核心，改接大量身份消费者 | 保留现有状态机，仅增加有界请求和首次一次性消费；当前代码已有请求去重、身份代次及重试机制 |
| 动态装载全部业务脚本，新增资源清单、DOM 就绪适配、独立登录 CSS 和第二套加载错误流程 | 全部移出本次范围；先压缩现有资源并重叠账号请求，避免改变所有页面的初始化生命周期 |
| 新增开关及新旧两套装配，要求两个版本后再清理 | 删除开关及双路径，直接用版本和代理备份回退 |
| 强制 HTTP/2 及缺失模块处置 | 从规范和任务删除；协议升级不是已证明必须的修复，当前只保留 gzip |
| 依据三次非受控页面采样制定 P95 2/1 秒、200 KiB、300 ms 及 10% 回归硬线 | 改为相同环境冷暖缓存各至少 5 次前后对照，报告中位数和范围；验证请求真正前移、体积下降、故障可恢复及实际等待改善 |
| 28 项任务和跨 change 的整体装配梳理 | 收敛为 11 项必要任务，复用现有账号、桌面和资源回归 |

保留 5 秒账号检查期限，因为“无限等待”是已确认问题，并保留超时后的迟到响应隔离。提前请求不变成第二套认证系统，也不代表主脚本下载阶段完全消失；完整登录拆分只有在本轮优化后的证据仍证明有必要时再评估。公网间歇延迟仍未定位，不由方案简化推导为已解决。
