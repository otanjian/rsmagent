## Purpose

允许已认证成员在 Web 查看本人业务会话的实时上下文用量并主动压缩历史，同时保持租户、会话 owner 和智能体的访问边界，避免并发生成时丢失新消息，并明确区分无实时上下文、功能未开放和请求失败。

## ADDED Requirements

### Requirement: 本人会话的上下文用量查询

系统 SHALL 提供上下文用量读取，先验证有效身份、当前租户、会话归属及对应 Agent；管理员身份 MUST NOT 替代个人会话所有权。查询 SHALL 只观察已有运行时实例，不创建 Agent、加载工具或发起模型推理。返回 SHALL 保留现有客户端使用的 available、used、limit、window、messages 和 breakdown 字段。

#### Scenario: 查询本人非默认智能体会话
- **WHEN** 获权成员查询本人非默认 Agent 的已有会话
- **THEN** 返回该会话的上下文用量，不读取默认 Agent 或其他会话的状态

#### Scenario: 合法会话没有实时实例
- **WHEN** 本人会话存在但进程内没有该会话的实时上下文
- **THEN** 返回成功且 available=false，不创建实例、不进行推理

#### Scenario: 伪造会话与智能体组合
- **WHEN** 用户以本租户 Agent 标识请求其他用户或其他租户的会话
- **THEN** 请求被拒绝，不返回用量、模型或会话存在性细节

### Requirement: 手动压缩保持授权和并发一致性

系统 SHALL 提供本人会话的手动压缩写操作并应用现有写请求来源保护。生成正在进行时 SHALL 返回可诊断冲突；压缩期间会话内容发生变化时 MUST 放弃旧快照提交，保留新消息，且不把未提交摘要写入长期记忆。重复并发压缩 SHALL 至多有一个有效提交。无可压缩内容 SHALL 返回成功的无操作结果，不伪造压缩成功。

#### Scenario: 正常压缩
- **WHEN** 本人会话存在可压缩历史且无并发生成
- **THEN** 压缩成功，返回 compacted_turns、before、after 和刷新后的 usage，保留最近会话内容

#### Scenario: 压缩期间新消息到达
- **WHEN** 摘要计算期间会话被追加或修改
- **THEN** 返回冲突，原消息及新消息完整保留，不提交旧摘要，不写入该摘要的长期记忆

#### Scenario: 非法来源或非 owner 操作
- **WHEN** 压缩请求来自非法 Origin 或操作者不是会话 owner
- **THEN** 在模型调用和历史修改之前拒绝请求

### Requirement: Web 上下文入口反映真实服务结果

Web SHALL 在功能开放且当前会话可操作时显示用量和压缩入口，关闭时不发轮询或压缩请求。客户端 SHALL 区分空上下文、冲突、拒绝和服务错误；切换身份、租户、Agent 或会话后 MUST 丢弃旧请求结果。

#### Scenario: 切换会话后旧响应返回
- **WHEN** 旧会话用量请求尚未结束时切换到另一会话
- **THEN** 旧响应不覆盖新会话的用量，不改变新会话按钮状态

#### Scenario: 功能关闭
- **WHEN** 服务端未声明或关闭上下文控制能力
- **THEN** 页面呈现未开放状态且不发相应请求，其他聊天功能保持原有行为
