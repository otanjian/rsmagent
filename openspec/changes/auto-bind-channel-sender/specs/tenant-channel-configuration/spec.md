## MODIFIED Requirements

### Requirement: 入站消息只在渠道实例所属租户内执行

经某渠道实例进入的消息 SHALL 只在该实例所属租户内解析与执行，租户归属 MUST 以该实例自身的登记归属为准，MUST NOT 由其绑定 Agent 的绑定推断。当发送者不是该租户有效成员、未完成外部身份绑定，或其账号停用、受限（含强制改密）时，系统 MUST 拒绝该消息且 MUST NOT 调用模型或产生工具副作用。渠道实例所绑定的 Agent MUST NOT 被用作跨租户执行的依据，入站路径 MUST NOT 回退到全局默认 Agent 或任何其他租户的资源。

**从未建立过发送者身份**的实例收到**私聊**时，系统 SHALL 把该发送者三元组绑定到该实例的**创建者**（`created_by`）名下，作为该实例的发送者身份。该绑定 MUST 落在该实例所属租户内：被绑定的成员 MUST 是该租户的有效成员，租户归属仍取实例自身登记，MUST NOT 因该例外改由 Agent 绑定或发送者归属推断。该例外 MUST 同时满足：私聊、实例从未绑定过发送者身份、三元组未属其他账号、创建者为该租户有效成员、实例启用且未被治理停用、凭据未撤、类型入站可证明发送者。任一不满足时 MUST NOT 写入绑定，并按本要求既有规则拒绝。认领后 SHALL 继续执行成员、权限与 Agent 判定；该实例 MUST NOT 再被任何发送者认领。

该例外 MUST NOT 为共享实例新增个人私聊路由或私有目标：绑定的成员在该实例上仍以其租户可用的 Agent 被服务。

#### Scenario: 其他租户成员向该渠道发消息

- **WHEN** 已绑定账号的用户并非该渠道实例所属租户的有效成员，却向该实例发送消息
- **THEN** 消息被拒绝并返回固定提示，不执行对话

#### Scenario: 未绑定的发送者
- **WHEN** 发送者尚未完成外部身份绑定，且该实例已经建立过发送者身份（或消息来自群聊，或该三元组已属他人，或创建者不可用）
- **THEN** 消息被拒绝且不调用模型

#### Scenario: 从未绑定的共享实例收到首条私聊
- **WHEN** 共享实例从未建立发送者身份，其创建者是所属租户的有效成员且实例可用于运行，收到一条私聊消息
- **THEN** 该发送者三元组被绑定到创建者名下并在该实例所属租户内执行，写入可审计的自动绑定事件

#### Scenario: 认领后的第二条消息来自另一个账号
- **WHEN** 共享实例已被首条私聊认领，另一个未绑定账号向该实例发送私聊
- **THEN** 该消息按未绑定处理并返回固定提示，不得改变已经建立的发送者身份

#### Scenario: 实例绑定与实例归属不一致
- **WHEN** 某实例所绑定 Agent 的租户与该实例自身登记的租户不一致
- **THEN** 入站解析以实例自身归属为准，且 MUST NOT 因该 Agent 的绑定而放行到另一租户
