## Context

动机见 `proposal.md`。排查确认运行页面装载 `assets/js/console.js`；实施已完成，代码与页面验证结果见 `evidence/verification.md`。

现有实现已经具备所需机制：`_refreshHistoryList()` 可刷新侧栏并按完整历史页可见性刷新或标记待更新；侧栏有请求序号；SSE 已捕获原 `ownerSession`／`ownerAgent`，并用 `streamBuffers` 支持切回重放。缺口主要是调用遗漏，而非缺少新的同步架构。

数据库模式的 `/message` 会在请求授权阶段创建业务会话并提交，用户消息也在模型运行前预存；因此正常发送成功后可直接读取列表。`/cancel` 和 `/steer` 不按新会话创建处理，实施沿用现有成功分支，不将控制命令当作持久化确认。未发送消息只生成前端 ID，没有可供服务端历史查询的记录。

## Goals / Non-Goals

**Goals:**

- 已保存会话及时出现在授权预览或通过完整历史可达，不等待最终回答和标题；完成及标题保存后反映最新信息。
- 后台普通会话按原 owner 处理标题与历史，切回重放不丢失或重复生成首次标题。
- 新增刷新不破坏身份隔离、侧栏重命名输入及既有搜索／归档规则。

**Non-Goals:**

- 不增加未保存会话行、草稿管理、额外预览名额、同步进度或新的重试界面。
- 不引入协调模块、事件总线、全局队列、单飞／尾部补读、周期性历史轮询或后端事件协议。
- 不迁移存储，不修改桌面认证、独立 Desktop 列表或编码会话同步，不开展全站前端拆分。

## Decisions

### 1. 直接补齐现有刷新入口

正常发送确认及已存在的同步／推送回复成功路径调用 `_refreshHistoryList()`。SSE `done` 在当前会话显示保护之前调用同一入口；自动标题保存成功再次调用，侧栏展开时调用 `loadSidebarRecentSessions()`。这些低频事件足够，无需按 chunk 刷新、定时轮询或先新建调度层。

完整历史继续使用原搜索词、编辑／拖动保护和 `_historyDirty`。已正常刷新的归档、恢复、置顶、删除和 coding hooks 保持原实现，不顺带重新组织所有消费者。仅修改实际装载入口，不把修改未装载的拆分文件当作交付。

替代方案是抽象新协调模块并新增适配器；当前已有双界面刷新函数，此抽象增加装配、状态和测试成本，缺少收益。

### 2. 复用请求缓冲保存一次性标题信息

首次发送时在 `titleInfo` 中一并记录原会话与 owner，保存在现有 `streamBuffers[requestId]` 中，恢复流时读取同一信息；不能在发送响应迟到后重新取当前活动智能体作为标题归属。收到 `done` 后，在消息显示保护之前取出并清空，再用原会话和 owner 调用标题生成；重放沿用同一已消费字段。不新增完成任务注册表、独立缓存寿命或请求状态机。

生成标题显式传递原 `agent_id`，不能依赖用户已切换后的活动智能体；原缓冲清理仍按现有 `stream_end`／错误生命周期进行。完成处理不绘制后台消息、不切会话；coding 不进入普通 SSE 标题路径。

仅移动当前闭包中的标题调用还不够：`_reattachStream()` 会关闭原流并以空 `titleInfo` 建立新流。复用现有缓冲字段能解决这个已确认的缺口，无需另建系统。

### 3. 只增加刷新带来的必要保护

- 侧栏继续以 `_sidebarRecentSeq` 丢弃旧请求；列表读取、发送成功回调及标题任务捕获并校验已有 `_authEpoch` 和租户，旧上下文不能驱动新身份的读写。不重构身份生命周期。
- 侧栏存在 `.sidebar-recent-rename-input` 时延后重绘，包括读取途中才开始编辑的情况；最多一个待刷新标记，在保存／取消完成后重读。完整历史的现有编辑与拖动门禁不改写。
- 请求失败沿用现有错误反馈，通过已有完整历史刷新或重新展开重试；自动标题失败仍有已保存初始标题。此次不升级失败缓存策略或新建错误恢复界面。

保留必要保护的原因是，完成时增加刷新会更频繁触达已有列表和账号切换。默认预览仍完全来自服务端读取，不客户端补行，因此归档记录不会被插回，预览数量和置顶排序也无需改动。

## Risks / Trade-offs

- [发送确认早于兼容路径实际保存] → 复用完成事件补刷；核对当前有效模式，不新增空会话写入或持久化协议。数据库模式的会话 claim 已在成功返回前提交。
- [切回流丢失标题信息或重放重复处理] → 同请求复用已有缓冲的可消费字段，测试切回前后完成与重复事件。
- [刷新移除正在编辑的侧栏节点] → 请求前及渲染前检查编辑态，保存／取消后仅补一次最新读取。
- [多个生命周期事件发出少量相邻请求] → 接受发送、完成和标题保存各一次读取，沿用最新请求生效规则；当前无请求负载证据支持额外合并层。
- [其他工作同时修改 `console.js`] → 核对当前 diff，局部编辑并保留既有改动，不整函数覆盖。

## Migration Plan

1. 对有效脚本的上述局部入口实施修复，完成聚焦的时序回归和语法检查。
2. 在真实 Web 页面验证保存前后、前后台完成、切回重放、展开刷新及编辑保护；同时确认已保存数量、搜索和归档维持现有行为。既有布局开关仅做受影响侧栏入口抽查，不建立完整三语／主题／多端组合矩阵。
3. 发布沿用现有静态资源版本机制。无需数据库迁移或回填，旧记录和未发送对话行为不变；回退本次代码 diff 即可，业务数据不回滚。
