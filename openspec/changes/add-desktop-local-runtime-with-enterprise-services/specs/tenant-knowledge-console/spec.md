## ADDED Requirements

### Requirement: 个人自有知识通过同一权威版本跨端维护

本人私有 Agent 的实际自有知识库 SHALL 支持 Web 与企业本机桌面的版本化新建、编辑、重命名、移动、删除及显式导入，成功提交后保存于服务器原合法数据根并进入统一变更记录。稳定文档标识 SHALL 在重命名和移动中保留，跨数据根转移继续按原授权处理，不借此扩大 owner 范围。写入 SHALL 复用 can_write_knowledge 与真实数据根判定，非 owner 管理员不得读写私有知识；私有 Agent 引用共享库仍按共享写权限处理。同步不得修改 index.md/log.md 等受保护内容，不自动导入本地项目目录或索引。

#### Scenario: 桌面创建本人知识后在 Web 编辑
- **WHEN** owner 在有写权的个人自有库创建文档并同步，再从 Web 知识库编辑
- **THEN** Web 可读取同一文档并写入新版本，桌面拉取后更新；其他成员及非 owner 管理员不能取得该私有内容

#### Scenario: 私有 Agent 实际引用共享库
- **WHEN** 普通成员试图把个人同步操作提交到其私有 Agent 引用的租户共享根
- **THEN** 按真实共享库写规则拒绝不合格操作，不因本人拥有 Agent 或启用同步而放行

#### Scenario: 缺少可写个人知识库
- **WHEN** 当前账号没有合法可写的个人自有知识库却选择导入资料
- **THEN** 显示可用目标或所需条件，不能自动改共享模式、授予管理权限或把资料存入他人目录

### Requirement: 知识同步和索引状态分别表达

知识正文及显式导入原始资料 SHALL 完整提交后才标为已同步，版本冲突保留草稿，重传不产生重复文档。服务器索引 SHALL 对应已提交文档版本，并在删除或失效后阻止旧结果被引用；索引未就绪或失败 SHALL 与保存/同步状态区分并可重试，不将派生索引当作个人资料上传。Web 原有导入限制、路径保护、读取及维护合同 SHALL 保持。

#### Scenario: 资料已同步但索引失败
- **WHEN** 上传资料保存成功，而服务器索引构建失败
- **THEN** Web 与桌面可辨认正文已保存和索引不可用，重试索引不重复上传或新建文档

#### Scenario: 多端冲突及删除传播
- **WHEN** Web 已修改或删除文档，离线桌面提交旧版本编辑
- **THEN** 返回冲突或已删除状态并保留草稿，不覆盖新版或复活旧文档，旧索引不能继续作为有效来源
