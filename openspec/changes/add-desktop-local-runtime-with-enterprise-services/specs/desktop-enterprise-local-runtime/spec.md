## Purpose

定义桌面连接企业服务器时仍由本机执行完整 Agent 循环的运行模式，明确企业服务、本地会话、项目文件及后台任务的归属，并使身份失效、恢复和旧版本迁移具有可验收的行为。

## ADDED Requirements

### Requirement: 企业连接本机运行是独立且显式选择的模式

系统 SHALL 提供 `enterprise-local` 模式，允许用户在桌面使用企业身份和资源并启动本机 Agent 运行时。既有 `local`、`remote`、Web 和 Channel 的执行位置、认证要求与已支持功能 SHALL 保持；升级 MUST NOT 自动切换模式或恢复已退役的共享密码、免登录和旧令牌路径。未具备企业服务协议或必要能力时 SHALL 展示具体原因，不能假装连接成功。

#### Scenario: 选择新模式
- **WHEN** 用户明确选择企业连接本机运行，且企业身份、租户和基础能力满足条件
- **THEN** 桌面显示已连接的企业与本机运行位置，可创建本机会话

#### Scenario: 旧安装升级
- **WHEN** 使用 local 或 remote 的用户升级客户端
- **THEN** 原模式及数据来源不变，进入新模式需要明确选择

#### Scenario: 旧服务器不支持
- **WHEN** 新客户端连接不提供该协议的服务器
- **THEN** 显示升级或模式不兼容原因，不转入免鉴权运行或将请求发往另一个服务器

### Requirement: 一个本机会话只有一个本地 Agent 循环

企业连接本机运行的任务规划、上下文装配、模型与工具调用循环 SHALL 在桌面运行时进行；服务器 SHALL 只执行被请求的企业服务动作，不为同一会话启动第二个规划循环。本地子 Agent SHALL 继承该用户、租户、企业来源和运行资格，不能使用目标 Agent 作者或服务进程身份。模型推理位置 SHALL 单独显示，不将本机编排表示为本地模型推理。

#### Scenario: 多轮工具任务
- **WHEN** 用户提交需要多次模型和本机文件工具调用的任务
- **THEN** 规划循环和文件工具在桌面发生，服务器处理企业服务、执行关联和会话增量存储，不启动第二个规划循环

#### Scenario: 子 Agent 与模型位置
- **WHEN** 本机 Agent 派生子 Agent 并使用企业远程模型
- **THEN** 子 Agent 保持同一调用者范围，界面说明本机运行及远程模型推理两个事实

### Requirement: 企业权威与本机数据明确分离

服务器 SHALL 继续唯一管理企业身份/权限、企业 Agent 定义、共享知识/Skill，并保存会话、个人知识、个人 Skill 及允许跨端个人状态的已确认版本。新企业本机会话 SHALL 默认增量同步，桌面按企业来源/实例、租户与用户保存缓存、草稿和待同步操作；设备仅记录来源与执行位置，不复制云端业务身份。本地缓存不得成为权限或公共配置真值。原始项目文件和完整产物 SHALL 留在本机授权范围，除非用户明确纳入知识资料或附件；系统 MUST NOT 自动复制身份库或镜像整个企业知识库/本机项目。

#### Scenario: 同一用户连接不同企业
- **WHEN** 同一电脑以相同用户名连接两个企业实例
- **THEN** 历史、缓存、项目授权和配置投影独立，不因用户名或资源同名而互相复用

#### Scenario: 本地结果与共享资源
- **WHEN** 本机完成 Excel 分析并生成报告
- **THEN** 原文件与完整报告保存在本机授权范围，服务器保存获准服务参数、会话消息、有界计算结果及文件来源引用，完整文件需明确选择才上传

### Requirement: 历史迁移和后台任务不复制执行责任

系统 SHALL 保留存量服务器历史及本地历史的原归属与标识。获权服务器历史和已同步桌面历史 SHALL 可在同一业务会话中续作，但必须确认原执行者终止、同步检查点完整，并重验资格及附件可用性；不得自动接管活动或未知运行。只有用户明确复制为新会话才创建新 ID 与来源关联。旧纯本地历史/资源 SHALL 经显式选择才导入企业。启动本机企业运行时 MUST NOT 复制启动服务器 IM 渠道、共享定时任务或委派队列；服务器既有任务保持原执行责任。

#### Scenario: 从服务器历史续作
- **WHEN** 用户获准读取服务器历史并明确选择本机续作
- **THEN** 在原运行结束且同步确认后沿用同一会话，并重验当前权限；活动/未知运行明确阻止切换，服务器附件未获准传输前不被当成本机文件

#### Scenario: 旧纯本地历史加入企业
- **WHEN** 用户初次选择新模式但未明确选择旧历史导入
- **THEN** 新模式数据默认同步，旧本地会话仍保留原归属且不自动上传

#### Scenario: 桌面登录不重复定时执行
- **WHEN** 企业存在定时任务且用户启动桌面本机运行模式
- **THEN** 不在桌面复制调度该任务，服务器仅按原规则执行一次

### Requirement: 企业失联与恢复不能授予离线权限

首期企业能力 SHALL 在线重验。断网时新企业步骤 SHALL 暂停或明确失败；已合法开始的本地单步可以结束并保存待确认结果，个人编辑可以保存本地草稿/outbox，但后续步骤 MUST NOT 依赖旧授权继续。恢复网络、进程或历史后 SHALL 重验身份、Agent 和资源资格，再按持久步骤与同步状态恢复，不能自动重放结果不明的副作用。退出、明确撤销和切换遵守 desktop-tenant-context 的失效规则。

#### Scenario: 计算期间断网
- **WHEN** 已开始的本地计算期间企业连接中断
- **THEN** 可以保存该单步结果，下一次企业资源或模型调用被阻断，不宣称整项任务已完成

#### Scenario: 恢复时已经撤权
- **WHEN** 重连或恢复旧会话时成员或 Agent 使用资格已被撤销
- **THEN** 后续运行被拒绝，已完成产物保留且不被当成继续执行的授权

### Requirement: 启用与回滚按实际能力保留数据

新模式及其知识、技能、固定计算、脚本和同步子能力 SHALL 缺省关闭并按协议、服务端与设备实际能力分别报告。新模式正式开放 SHALL 具备统一存储/同步及对应平台的真实验收；回滚或关闭新模式 SHALL 停止新运行、保留服务器历史及本地草稿/outbox/产物并处理未确认步骤，不能改写存量角色、删除恢复记录或自动转成服务器执行。新模式和同步开关 MUST NOT 关闭原有 Web 功能。

#### Scenario: 仅固定计算已验收
- **WHEN** 某平台固定计算通过而任意脚本未通过
- **THEN** 仅声明已验收能力，脚本不可用有明确原因，不影响其他已支持模式

#### Scenario: 回滚后保留本地成果
- **WHEN** 操作者关闭新模式或使用兼容旧模式
- **THEN** 新任务停止，本地历史/产物/journal 保留，未知模式的旧版本不会误读或重写其状态
