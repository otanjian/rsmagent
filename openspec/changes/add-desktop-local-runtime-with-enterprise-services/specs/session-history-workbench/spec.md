## ADDED Requirements

### Requirement: 历史展示同一服务器确认的跨端会话

Web 和企业本机桌面 SHALL 在当前授权范围使用同一业务会话 ID、消息、智能体、项目和设置。桌面已确认的消息及标题/置顶/归档/删除变化 SHALL 在既有历史入口可见；Web 的正常写入也 SHALL 可被桌面增量取得。既有分组、标题搜索、分页、归档恢复和不制造持久空记录的合同保持，不为每台设备创建重复会话，也不展示其他身份的缓存。部分同步的回复 SHALL 标明部分内容，不能冒充完整终态。

#### Scenario: 从 Web 打开桌面历史
- **WHEN** 桌面已同步某会话，用户在 Web 历史页搜索并打开该记录
- **THEN** 沿用原会话和 Agent/项目归属呈现已确认内容，标题搜索和管理操作仍按原规则工作

#### Scenario: Web 归档后桌面更新
- **WHEN** 用户通过原 Web 历史入口归档会话，随后桌面增量同步
- **THEN** 桌面更新相同会话的归档状态，消息/置顶/项目保留，不新建记录、不停止仅因归档仍在进行的回复

### Requirement: 跨端续聊遵守运行占用和附件可用性

打开历史 SHALL 不自动切换执行位置或启动任务。Web 新建对话 SHALL 继续默认服务器执行；同一会话已有活动执行者时另一端 SHALL 显示占用并允许获权阅读，不启动第二个循环。切换执行者 SHALL 遵守已确认检查点、终止确认与当前资源授权要求；桌面专属文件 SHALL 显示设备来源及不可达状态，不能仅凭历史记录获得文件访问或静默上传。原有 Web 功能 SHALL 不依赖桌面在线，新能力关闭时仍可用。

#### Scenario: 阅读进行中的桌面会话
- **WHEN** 用户在 Web 打开桌面仍在执行的已同步会话并尝试发送
- **THEN** 可读已确认消息并收到运行占用说明，不中断原任务或启动服务器的重复运行

#### Scenario: 空闲历史需要本机文件
- **WHEN** 已结束且同步完成的桌面会话在 Web 续聊需要原设备上的附件
- **THEN** 明确说明文件仅在原设备，用户可选择获权上传、替代输入或回原设备继续，不使用伪造服务器路径

#### Scenario: 桌面离线时新建 Web 对话
- **WHEN** 用户没有在线桌面且从 Web 新建正常对话
- **THEN** 沿用服务器运行及原权限、历史管理合同，不要求连接桌面或开启同步入口
