## Purpose

定义企业本机运行模式下会话、个人知识、个人 Skill 及非秘密个人状态的统一存储和多端同步。服务器保存唯一已确认版本，桌面保存缓存、草稿和待同步操作，使 Web 与多台桌面能够可靠续用同一资源，同时保持租户、owner、删除、授权与本机文件边界。

## ADDED Requirements

### Requirement: 企业本机数据默认同步到服务器权威记录

`enterprise-local` SHALL 默认将实际提交的会话消息、必要工具调用及有界结果、会话管理状态、个人知识正文与显式导入资料、个人 Skill 完整定义/资源包、允许跨端的非秘密个人配置同步到当前企业服务器。服务器 SHALL 是已确认版本的唯一权威，桌面缓存和未提交草稿不得冒充云端已保存。不同设备 SHALL 使用相同业务对象标识和原有 Agent/项目归属，设备标记不得创建重复云端会话；仅打开新对话或输入未发送草稿不得制造持久空记录。

#### Scenario: 桌面数据在 Web 和另一桌面可见
- **WHEN** 用户在企业本机模式提交消息、修改个人知识及个人 Skill，且服务器已确认同步
- **THEN** 同一企业、租户和本人在 Web 与另一桌面可读取相同标识及版本的记录，计算仍在原选定位置运行

#### Scenario: 尚未确认和未发送草稿
- **WHEN** 用户只打开新对话，或已保存本地编辑但网络阻止提交
- **THEN** 前者不新增持久历史，后者保留草稿并显示待同步，不宣称另一端已可见

### Requirement: 同步逐对象验证身份和私有归属

每次提交、拉取、快照、上传和下载 SHALL 从有效会话解析企业来源、租户与本人身份，并复用对应业务功能、真实资源范围、owner 和当前状态校验。目录、数量和分页 SHALL 先过滤权限；个人资料同步不得自动发布为共享资源、授予共享 grant 或允许非 owner 管理员读取。客户端自报 owner、设备、对象标识或游标 MUST NOT 扩大作用域。账号/租户切换 SHALL 隔离旧队列、缓存和迟到响应，未确认内容保留原身份归属。

#### Scenario: 管理员或其他成员读取个人数据
- **WHEN** 非 owner 管理员或其他成员通过同步列表、对象 ID 或游标请求个人会话、知识或 Skill
- **THEN** 私有数据、计数和内容不被返回，平台身份不绕过真实 owner 范围

#### Scenario: 补传期间切换身份
- **WHEN** 账号 A 尚有待同步编辑时切换为 B，随后 A 的请求才返回
- **THEN** 旧响应不修改 B 的视图或队列，A 的未确认内容不以 B 身份提交；重新登录 A 并重验资格后才能恢复

### Requirement: 增量提交和恢复不会丢失或重复数据

同步 SHALL 支持持久待提交操作、稳定操作标识、服务端确认、增量游标和有界分页。相同操作与相同内容重试 SHALL 返回同一结果，不重复创建消息、资源或费用；同一操作标识携带不同内容 SHALL 拒绝。客户端确认进度 SHALL 以已持久保存的页面为准，首次快照与后续增量之间不得漏掉并发变化。断网、休眠、客户端或服务端崩溃后 SHALL 能重验身份并恢复；同步恢复 MUST NOT 重新发送聊天执行请求、调用模型或重做工具副作用。

#### Scenario: 服务端成功但确认丢失
- **WHEN** 服务端已经保存一条消息或资源更新，而桌面未收到确认并在重启后重传
- **THEN** 仅保留一次业务变更并返回原确认，模型和工具不再次执行

#### Scenario: 首次快照与重复分页
- **WHEN** 初次同步分页期间 Web 更新资源，或同一增量页被重复传输并遇到客户端崩溃
- **THEN** 恢复后包含快照及其后全部合法变化，不漏记录、不重复显示或跳过尚未持久应用的页面

### Requirement: 双向变化包含既有业务写入口

Web、桌面、Channel 和后台通过支持的同类业务入口成功写入后，SHALL 进入同一可恢复的版本及变更记录，包括消息、自动标题、历史操作、个人知识和 Skill 维护。系统 MUST NOT 只记录同步接口自身的写入。数据库与文件资源均 SHALL 在完整持久提交后确认，崩溃时不得暴露半个文件版本或成功但永远无法被其他端发现的更新。Web 业务写入 SHALL 不等待桌面在线或同步传输进程。

#### Scenario: Web 修改后桌面拉取
- **WHEN** 用户通过既有 Web 接口重命名/归档会话、编辑个人知识或以 expected_mtime 写回 Skill 正文
- **THEN** 桌面可通过增量取得该更新，旧 API 的字段、权限和冲突响应仍兼容

#### Scenario: 文件发布时服务崩溃
- **WHEN** 服务端在写入个人知识文件或 Skill 包过程中崩溃
- **THEN** 恢复后可见完整旧版或完整已提交新版，未完成版本不被确认或对外分发，变更记录与可见内容一致

### Requirement: 会话增量保留顺序并限制执行者

消息及流式内容 SHALL 使用稳定标识和有序修订，重复片段不重复显示，未完成回复明确标记部分内容。会话历史 SHALL 保留工具调用与结果关联及运行位置，不能因同步而新增第二个 Agent 循环。同一业务会话同一时刻 SHALL 只有一个获权执行者；Web、桌面及其他运行入口均须检查该占用。切换执行位置 SHALL 在原运行终止确认、已同步到完整检查点且重新校验当前资格后进行，未确认副作用和失联占用不得自动抢占。旧执行代际不得追加到新运行。

#### Scenario: Web 与桌面同时发送
- **WHEN** 桌面正执行某会话，Web 或另一桌面尝试在该会话启动新的回复
- **THEN** 后者明确收到运行占用状态，仍能读取获权的已同步内容，不启动并行执行链

#### Scenario: 空闲会话换端续聊
- **WHEN** 原运行结束且全部消息和工具结果已确认，用户在另一端续聊
- **THEN** 重验资格和附件后沿用同一会话与历史，由新的执行者继续，旧端迟到事件不覆盖新运行

#### Scenario: 流中断或设备失联
- **WHEN** 回复只同步了一部分，或本机执行者失联且副作用无法确认
- **THEN** 历史标记部分内容和待核对运行，保留已确认片段；不伪造完整回复、不自动重跑或接管

### Requirement: 多端编辑冲突保留双方内容

会话可编辑管理字段、个人知识、个人 Skill 及个人配置的变更 SHALL 携带服务端基准版本并进行条件提交；版本不符 SHALL 返回冲突和当前可读版本，保留本地草稿供用户处理。系统 MUST NOT 按客户端时间、设备优先级或静默最后写入覆盖。Skill 资源包 SHALL 作为完整版本处理，不将多个设备的指令与脚本随意拼接；旧 Web 接口已有并发合同保持。

#### Scenario: 两端改同一知识文档
- **WHEN** 桌面离线编辑期间 Web 已保存同一文档的新版本
- **THEN** 桌面重连后显示冲突并保留两份内容，用户确认解决前不覆盖服务器版本

#### Scenario: 两端改同一 Skill 的不同文件
- **WHEN** Web 修改 Skill 正文而桌面基于旧版本修改脚本
- **THEN** 提交返回整包版本冲突，运行目录继续提供原已确认完整版本，直到冲突解决并提交完整新包

### Requirement: 删除传播且过期设备不能复活对象

删除 SHALL 产生可同步的版本化删除状态，并保持会话取消/清理、知识受保护文件与 Skill 授权规则；归档不得作为删除处理。已删除对象的旧更新 SHALL 被拒绝，不因设备离线而恢复原 ID。删除及去重记录的保留期限 SHALL 明确；游标或操作基准过期时 SHALL 要求完整对账并拒绝自动重放旧操作，同时保留未提交草稿。用户若保留冲突内容，SHALL 显式创建新的获权对象，不冒充恢复原对象。

#### Scenario: Web 删除而桌面仍有旧编辑
- **WHEN** Web 删除个人文档、Skill 或会话后，离线桌面携旧版本重连
- **THEN** 旧缓存收敛为已删除状态，旧编辑转为待处理草稿，不在云端复活该对象

#### Scenario: 长期离线超过保留窗口
- **WHEN** 桌面游标和旧操作超过服务端删除/去重保留窗口
- **THEN** 必须快照对账并显式处理过期操作，不能把服务端已清理的对象当作全新上传自动创建

#### Scenario: 归档仍可恢复
- **WHEN** 一端归档或取消归档会话
- **THEN** 另一端更新相同归档字段，消息、置顶和项目归属按既有合同保留，不产生删除标记

### Requirement: 文件同步有明确用途并完整校验

原始项目目录、本机索引、临时文件、大型计算产物和完整调试日志 MUST NOT 被默认镜像到服务器。明确纳入个人知识、个人 Skill 的必要资源及用户选择的附件 SHALL 按用途、owner、文件数/大小/存储限额传输，并在完整性与路径校验通过后提交；未完成上传不得替换旧版。本机绝对路径、目录 grant、身份凭据和公共秘密不得进入同步载荷；附件引用 SHALL 区分已上传与仅在某设备存在。可见消息正文不得因单次同步上限被静默截断，应分块或明确报告待处理。

#### Scenario: 分析大型 Excel 后同步会话
- **WHEN** 桌面完成大型本地 Excel 处理并同步结果消息
- **THEN** 服务器取得消息、有界计算结果和本机文件的可辨认引用，原 Excel 与完整报告未因同步自动上传

#### Scenario: 明确导入个人知识或上传附件
- **WHEN** 用户选择本地文件纳入本人知识库或作为跨端附件
- **THEN** 仅选定文件在授权、限额和完整性校验后成为云端已确认资料，其父目录及其他项目文件不随之上传

#### Scenario: 包损坏或存储额度不足
- **WHEN** 个人 Skill 包摘要不符、包含越界文件或上传超过存储限额
- **THEN** 拒绝提交并显示原因，旧完整版本继续有效，本地草稿保留且不标为已同步

### Requirement: 同步状态可见且故障不授予离线权限

桌面 SHALL 显示待同步、同步中、已同步、冲突、无权限/需登录、额度或其他失败及可用的恢复操作，运行状态与同步状态分别表达。临时故障 SHALL 有界退避重试，磁盘不足或队列满不得丢弃未确认内容或虚报成功。断网可以保存原身份的编辑草稿与已发生结果，但 MUST NOT 据此执行新的企业模型、资源或工具步骤；撤权后不得用同步重试恢复资格。

#### Scenario: 计算完成但同步失败
- **WHEN** 本地计算已成功，结果上传因网络中断而未确认
- **THEN** 显示计算完成及待同步两个状态，重连按原操作补传，不重新计算或宣称已备份

#### Scenario: 本地磁盘满或登录过期
- **WHEN** 待同步队列无法持久保存，或身份在重试时失效
- **THEN** 明确报告未保存/需登录并保留已有草稿，停止不合格提交，不删除队列或使用其他账号补传

### Requirement: Web 独立可用并兼容原有客户端

新增同步能力 SHALL 保持 Web 既有地址、API 必填字段、权限边界、存量业务标识、历史管理及默认服务器执行。Web SHALL 不依赖桌面在线、桌面安装或同步传输 worker；关闭新模式/同步入口不得关闭原 Web 功能。Web 自身业务成功提交后即为服务器已保存，桌面恢复后通过增量或快照追上。新增来源、版本等字段 SHALL 向后兼容；同一会话运行占用、实际文件不可达和真实冲突应明确反馈。

#### Scenario: 桌面关闭且同步功能暂停
- **WHEN** 所有桌面退出或新同步入口被关闭，用户使用现有 Web
- **THEN** 登录、服务器聊天、历史管理、获权知识/Skill 维护仍正常；同步重新开放后能够取得期间的合法变化

#### Scenario: 旧 Web 客户端请求
- **WHEN** 旧客户端按原字段访问历史、知识和 Skill 内容接口
- **THEN** 不被要求提供新同步字段，原数据和并发错误合同保持，写入仍进入统一版本记录

### Requirement: 同步迁移和回滚保留未确认内容

既有服务器数据 SHALL 保留标识、归属和业务内容并以兼容方式补同步元数据。旧纯本地历史/资源 SHALL 仅在用户明确选择目标企业与范围后幂等导入，不自动扫描或上传整个本地数据目录。新模式正式开放 SHALL 以统一存储/同步实测通过为前置；回滚 SHALL 保留服务器已确认数据、本地草稿/outbox 和恢复记录，并保持 Web 可用。迁移和补传 MUST NOT 重放历史运行或复制身份库。

#### Scenario: 旧本地安装加入企业
- **WHEN** 用户首次连接企业并启用新模式，尚未选择历史导入
- **THEN** 获取本人服务器记录并默认同步新模式中新产生的数据，旧纯本地历史和目录不自动上传

#### Scenario: 回滚时有待同步编辑
- **WHEN** 关闭新模式或回滚客户端时仍有未确认内容
- **THEN** 显示待处理内容并保留可恢复分区，服务器历史和 Web 继续可用，不把清空队列当作回滚成功
