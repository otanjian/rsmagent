## ADDED Requirements

### Requirement: 本人私有 Skill 定义在现有页面统一维护

系统 SHALL 在正式工具与技能页面支持本人私有 Skill 定义的新建、读取、更新和删除，包含正文、引用、脚本和模板，不能只保存使用参数。创建 SHALL 要求有效租户成员及 skill.edit，并由服务器强制绑定当前 tenant/owner；后续读取要求 skill.read 与对应资源 read，更新/删除要求 skill.edit 与对应资源 edit，私有归属在统一对象授权层判定。同步到服务器 SHALL 不授予公共管理资格或自动共享，非 owner 管理员不得读写该私有定义；公共安装、正文、启停仍按原管理及资源授权处理。个人资源 SHALL 使用精确 resource_id，不通过同名定义回退。

#### Scenario: 成员创建本人 Skill 并跨端使用
- **WHEN** 具备 skill.edit 的成员创建个人 Skill 完整定义并提交成功
- **THEN** 服务器登记本人私有资源，Web 与本人另一桌面可在现有页面按权限读取；实际使用仍需 skill.use、启用、Agent 选用及执行条件

#### Scenario: 同名公共技能与私有归属
- **WHEN** 成员更新/删除个人 Skill，且公共库存在同名技能，或非 owner 管理员提交该私有 resource_id
- **THEN** 本人操作只影响指定私有资源，公共定义不变；非 owner 管理员被拒绝，不能借管理身份覆盖个人文件

#### Scenario: 缺功能权限或伪造 owner
- **WHEN** 调用者缺少 skill.edit，或试图新建归其他用户/租户的个人定义
- **THEN** 创建请求被拒绝，不产生技能文件、共享授权或其他人的资源

### Requirement: 个人 Skill 同步提交完整版本并兼容旧正文接口

个人 Skill 的定义与包内资源 SHALL 形成可校验的完整版本，编辑草稿、服务器已确认版本和只读运行缓存 SHALL 分开。多端版本冲突、未传完、大小超限、非法路径或秘密内容 SHALL 阻止发布并保留原完整版本；未确认草稿不得冒充可运行企业版本。既有 content/expected_mtime 正文写回 SHALL 保持原权限及冲突响应，成功后形成同一资源的新版本与增量变化，未修改资源仍归该完整包。删除 SHALL 传播失效，旧缓存不得恢复运行资格；正常更新不得混用运行锁定版本。

#### Scenario: 桌面更新含模板和脚本的 Skill
- **WHEN** 本人编辑 Skill 正文、模板和脚本后同步成功
- **THEN** Web 与另一桌面读取同一完整新版本，已运行任务保留其获权固定版本，不将新正文配旧脚本

#### Scenario: 旧 Web 正文写回遇到并发
- **WHEN** Web 按原 expected_mtime 提交，而桌面已更新该资源
- **THEN** 返回原 conflict 语义；若无冲突则保存原始正文并产生新包版本及同步记录，不改变公共启停或个人参数

#### Scenario: 删除和未完成包
- **WHEN** 本人删除已同步 Skill，或下一版本资源上传中断
- **THEN** 删除通过统一状态使后续获权检查拒绝旧包；中断更新不发布半个版本、不丢失草稿或覆盖原完整包
