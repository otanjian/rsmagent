## 4. 服务端归属解析与授权

- [x] 4.1 新增按会话标识解析归属的服务端端点/解析器：由 `sessionID` 得到平台用户与工作台绑定。→ `WorkbenchStore.binding_for_session()`：按 `remote_session_id` 反查，已关闭的行不返回，**命中多行时拒绝而非猜测**（猜任一行都会让一个 owner 的调用打到另一个 owner 的浏览器）
- [x] 4.2 复用既有校验链：主体授权、浏览器连接、控制代次、动作账本、配额；未归属或未授权返回未绑定拒绝。→ 把 `WorkbenchRuntime.bridge()` 中「归属已确认之后」的执行链抽成 `dispatch()`，桥接端点经**存活的绑定实例**调用它，因此 `authorize()`（用开启时捕获的平台令牌重查主体）、`admit_action`、`consume_quota`、`audit` 全部原样生效；`session_not_bound`(403) / `session_not_running`(409) 为未归属拒绝
- [x] 4.3 明确拒绝采信模型参数、请求体或提示词声明的用户、SAP 账号、浏览器与会话标识。→ 导航端点请求体只接受 `session_id`/`transaction`/`call_id`，业务数据端点只接受 `session_id`/`connection`/`tool`/`arguments`/`call_id`，多余字段（`user_id`、`binding_id` 等）直接 `invalid_request`；调用方凭编码服务自身 HTTP Basic 凭据认证，且必须是不带转发头的本机直连调用
- [x] 4.4 左侧画面导航通道：只接受导航请求并回报送达结果，不代表登录或业务结果可被读取。→ `POST /api/scenes/sap-workbench/bridge` → `WorkbenchRuntime.navigate()`，复用 `IframeNavigation`，回报 `sap_page_verified: false` / `business_result_verified: false`
- [x] 4.5 审计：工具执行记录会话、绑定、动作与结果，不记录凭据。→ 复用 `dispatch` 的 `action.dispatch` / `action.succeeded` 审计（`target` 为绑定 id，参数仅记 action/kind/generation/action_id）
- [x] 4.6 业务数据通道：同一条归属解析与授权链上再开一条 `POST .../bridge/data`，只接受业务参数，凭据与 `connection_id` 留在服务端。→ `SapWorkbenchDataBridgeHandler` → `WorkbenchRuntime.data_call()` → `ConfiguredMcp.call_business()`，参数由 `mcp_business.business_arguments()` 在写入 worker **之前**校验（`run_query` 限单条只读 SELECT；`read_table` 限表名/字段/行数；`call_rfc` 限函数名与参数体积；身份键一律拒绝；ADT 系统变更工具不在工具面内）。失败状态按语义区分：业务写动作可能已生效，`sap_data_call` 不在 `READ_ACTIONS`，失败记为 `unknown` 而非 `failed`；纯参数形状错误在账本之前就被拒（不扣配额、不写 `action.dispatch`）
