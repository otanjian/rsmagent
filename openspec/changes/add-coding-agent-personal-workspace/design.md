## Context

当前 `coding_project_dir` 是 OpenCode 主机的项目路径，平台把它用于远端会话和 iframe。顶部面板仍有本机路径假设，iframe 附件也可能只在消息中。因此只改按钮不能满足输入、处理和输出落在个人目录的需求。

本次取消前版 change 的三种 Agent 发布模式、五级门槛、历史继续与复制工具，以及强制远端全功能文件管理。此前设计及审查文档作为背景，实施契约以本 change 的 specs 为准。

| 现有接入点 | 必要改动 |
| --- | --- |
| `agent/coding/sessions.py`、`opencode.py` | 复用服务连接和会话创建幂等，解析 U 并传给创建/恢复 |
| 身份库、会话 schema/store | 一张个人绑定表，会话链接增加可空 workspace_id |
| fork 下 `coding.py`、`coding_browser.py`、`workspace.py` | 复用授权和文件协议，补远端来源、目录与附件核验 |
| `workspace.js`、`coding.js`、`fork/project-source.js` | 文件树、上传、预览下载和 @ 使用同一来源 |
| 配套 RSMCode 服务及 Web | 目录准备、最小文件操作、附件落盘，必要时补 P 的配置发现 |
| `Scene/sap_workbench/backend/` | 区分项目安装根 P 与实际会话目录 U，保持场景控制授权 |

## Goals / Non-Goals

**Goals:** 文件按钮打开按账号命名的个人目录；新会话的输入文件、默认运行目录与输出文件一致；保留既有工具、权限和历史可用性。

**Non-Goals:** 新执行沙箱、用户独立引擎、项目复制、全量文件索引/版本库、旧会话迁移、通用远端文件编辑与回收站扩建。纯文本回复和未保存代码块不强制生成文件。

## Decisions

### 1 一个个人目录上下文

```text
P = 远端核验的 coding_project_dir
U = P/user/<身份库规范 username>

配置和项目工具读取 P
新个人会话 Location、文件面板、附件、默认业务输出使用 U
```

`agent/coding/workspace.py` 集中解析已授权身份、Agent 及可选会话，避免各入口独立拼路径。同一服务、租户、项目和用户共用 U，不增加 Agent 子目录；不同项目分开。已有个人会话使用绑定快照，新会话采用当前配置。

目录用账号名命名，授权用不可变 user_id。账号名在首次绑定取规范拼写，昵称或登录大小写不改目录，不安全的路径段拒绝；未来账号改名不自动搬目录。同一实际 U 不允许被其他用户或租户认领，不扩大为禁止一切既有共享 P。

### 2 最小持久状态与幂等准备

身份库增加 `coding_user_workspaces`：`id`、`service_id`、`tenant_id`、`user_id`、`username_at_creation`、`base_project_dir`、`effective_directory` 和创建时间。唯一键为 `(service_id, tenant_id, base_project_dir, user_id)` 与 `(service_id, effective_directory)`；按远端规范路径核对别名和目录重叠。

会话链接仅增加可空 `workspace_id`。有值表示个人会话，空值沿用旧行为；不重复增加可推导的 workspace_mode、布局版本或继续来源字段。原 `project_dir` 仍是实际 Location：个人会话为 U，旧会话为 P。owner 仍由既有 `sessions` 提供。

顺序为鉴权 → 远端核验 P → 预留唯一绑定 → 远端 prepare → 创建/打开个人会话。prepare 复用现有服务认证，只创建 user/账号子树，uploads/outputs/work 在使用时创建。

为区分重试与冒领已有目录，远端保留最小的受保护目录归属记录（规范 U 与绑定 ID），置于服务状态区而非用户可写的 U。同一路径的首次认领与目录准备串行化；先检查未知存量目录，再记录归属并 mkdir，重试只接受相同绑定。中断后重新 prepare；未知已有目录或归属冲突报错。该记录只解决首次准备归属，不扩建多阶段日志、补偿队列或第二套文件索引。

目录操作在实际主机校验路径和链接边界，使用安全文件操作避免链接替换。创建失败保留可重试绑定，不创建公共根替代会话。历史列表查询不触发目录创建。

### 3 复用面板，只适配本次必要操作

在既有 `/api/workspace/*` handler 根据已授权上下文增加 `coding_remote` 分派，沿用 DTO。必需能力为准备、元信息、列举、搜索/解析引用、读取/流式预览下载及上传；不为 server/desktop 另做通用框架重构。

`meta` 返回来源、workspace_id、账号根标签和真实 capabilities。远端编辑、重命名、删除和回收站若没有兼容实现，前端不显示，后端也拒绝；已有可复用实现可接入，补齐这些能力不是本次完成条件。普通和桌面来源原有能力不受影响。

逐次核验用户、租户、Agent 与会话/工作区归属；客户端只提交对象标识和相对路径。预览下载继续由平台鉴权代理，不向浏览器下发服务凭据，不能将远端 abs_path 交给本机 `/api/file` 或 fallback。上传 XHR、预览 URL 和 @ 选择器也进入来源适配，scope epoch 处理切换后的迟到响应。文件变化在上传完成、任务完成或面板重新激活时刷新，不建设新事件同步服务。

### 4 附件与输出直接落盘

```text
U/
  uploads/<session-id>/<attachment-id>/<filename>
  outputs/<session-id>/<已有消息或执行ID>/...
  work/<session-id>/...
```

面板上传尊重选定的 U 内子目录；无会话且未选子目录时用 uploads/manual。对话附件用稳定附件标识避免重复保存。iframe 选择、拖拽、粘贴图片、场景注入和平台代理接受的直接消息请求均先落盘再提交，从持久文件构造模型媒体内容。失败保留草稿，服务器拒绝伪造路径和跨工作区引用。消息提交沿用已有消息标识与重试语义，不扩建通用“恰好一次”消息系统。

默认执行目录为 U，按会话及调用传递输入/输出位置，不改共享进程全局 cwd 或环境。复用已有消息/执行标识区分同名输出；没有此标识的独立导出使用唯一文件名，不引入新任务身份。已接入的下载、导出、MCP 文件返回使用 U 内目标或显式导入，不扫描宿主全盘搬文件。

引用为 `{source, workspace_id, relative_path}`，复用附件/结果元数据，交付前验证存在及归属。普通浏览下载读取路径当前内容，改名或删除后显示不存在；已有版本/ETag 语义继续使用，不要求为所有文件新增强制版本体系或不可变副本。系统自己的新附件和输出使用唯一位置，避免覆盖旧交付。

上传沿用单请求大小校验、流式落盘、原子发布、进度和逐项重试。仅清理自身可识别的不完整临时文件，完整但未发送的附件保留；优先复用既有清理机制，不新增调度服务。

### 5 保留项目能力和现行约束

先实测配置发现能否从 U 正确读取 P，不足时只补可信 P 来源。U 内用户配置不能扩大平台授予的范围或冒充可信安装。SAP 工具仍安装在 P，场景关联按 P 与 U 分别校验，原用户、权限 profile 和控制代次保持；仅适配已经支持的文件输出。

Git 项目准备前检查 P/user 是否有跟踪源码或用途冲突，冲突时报错。无冲突的个人树用本地 exclude 等排除公共普通提交，保留其他规则。本人列举与 @ 搜索在 U 内执行，不因父 Git 忽略隐藏附件；复用已有快照范围，不承诺忽略文件的 Git 撤销。

身份、CSRF、凭据、审计与适用资源配额消费现有接口，缺口只补对应切片；不能把配额失败当成功，也不预设新增远端预留/结算 RPC、独立账本或跨服务对账引擎。单次上传限额不代替已配置硬配额。

外部共享 OpenCode 沿用 `execution-isolation` 的明确例外：统一文件 API 范围和默认落点，不增加沙箱前置、关闭 Shell，亦不承诺任意脚本无法访问宿主其他路径。

### 6 一个开关，兼容旧会话

`opencode.personal_workspace.enabled` 默认 false。启用且远端服务/Web 能力验证通过后，所有新建 Code 会话使用 U；不增加每 Agent 三态模式。关闭仅停止新增个人绑定/个人会话，已有个人会话仍使用 U；完全停用继续使用现有 OpenCode 总开关。

旧会话保留原目录和使用方式，不改绑、不冻结、不复制历史。启用时，旧会话的文件按钮按原项目快照打开本人 U，清楚提示“本会话仍在原项目目录运行；新建对话使用个人目录”。沿用现有新建入口，不增加继续并迁移上下文/附件的流程。旧文件链接按既有授权处理。

完成范围是个人文件入口及启用后的新会话，不能称为全部存量交互已迁移。对直接修改 P 源码的用法，部署前说明新会话 cwd 变化；个人目录并非代码仓库副本。

## Risks / Trade-offs

- U 与 P 分离可能影响配置和 SAP：用真实服务先做小范围验证，只修实际缺口。
- 故障、并发准备和陌生存量目录：唯一绑定、最小归属记录及 prepare 重试处理，错误不 fallback。
- 多会话共用 U：系统输出使用会话/消息子目录，用户或外部脚本显式覆盖仍按既有语义。
- 单开关范围较粗：在测试环境验证后启用，减少配置组合；不把旧会话留在 P 隐藏为已全量切换。
- 远端编辑能力不完整：如实投影 capabilities，不牺牲必须的上传、处理、查看和下载链路。

## Migration Plan

1. **实现前核对**：确认仓库接缝、部署版本及身份/审计/配额消费接口；用临时 P/U 验证真实 Location 与项目工具。有阻断先解决再扩展产品接口，无需独立五阶段审批或报告系统。
2. **实现与集成**：增量建表、添加可空 workspace_id；完成准备、会话、来源及附件，开关保持关闭。上线前必须有真实远端上传→处理→下载，以及两账号并发、适用 SAP、普通/桌面回归证据，不能以 mock 或文档代替。
3. **启用与回退**：在经验证的部署范围显式开启，旧会话保持兼容并提示。关闭新建开关保留 U 和个人会话；只回退到能识别 workspace_id 的版本。不能让不兼容旧程序接管个人会话并改回 P。删除会话不删除个人文件，Git 排除不随开关自动撤销。
