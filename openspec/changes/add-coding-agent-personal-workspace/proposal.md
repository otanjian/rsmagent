## Why

Code 类智能体的顶部文件面板、iframe 附件和实际运行目录目前没有共同的个人文件落点。需要让文件按钮打开远端项目的 `user/<登录账号>/`，不存在时创建，并使新会话的附件、默认工作目录和交付文件使用同一位置。

## What Changes

- 增加最小个人目录绑定：项目根 P 来自智能体配置，个人根 `U=P/user/<username>`；账号名由身份库取得，所有权按不可变用户 ID 判断。首次使用在 OpenCode 主机准备目录。
- **BREAKING**：个人功能启用后，新 Code 会话的实际 Location 从 P 改为 U；项目配置和工具仍从 P 加载。既有会话保持原位置并明确提示，用户通过现有新建入口开始个人会话。
- 复用文件面板和 `/api/workspace/*` 协议，补充 `coding_remote` 来源，完成列举、搜索与 @ 引用、上传、预览、下载。远端未支持的编辑、重命名和回收站不展示或放行，不将补齐整套文件管理能力作为本次前置。
- 输入框选择、拖拽、粘贴及服务端消息附件先保存到 U 再提交；默认输出按会话和已有消息标识分组，文件引用直接指向 U 内真实文件。
- 保留项目工具和 SAP 现有权限，只适配项目根 P 与运行目录 U 的区别；个人文件不进入公共 Git 普通提交，但仍能被本人搜索。
- 用一个部署开关控制新建个人目录/会话，保留已有个人绑定。复用身份、审计、上传限制与适用配额规则，不新增发布模式状态机、历史迁移工具、通用文件版本库或跨服务结算系统。

## Capabilities

### New Capabilities

- `coding-agent-personal-workspace`: 账号目录绑定与准备、统一远端文件来源、附件和结果落盘、Git/搜索及新旧会话兼容边界。

### Modified Capabilities

- `opencode-coding-agents`: 区分配置项目根与个人运行目录，明确单一开关下的新会话行为。
- `opencode-session-sync`: 会话关联保存个人目录绑定，保持原创建幂等、历史快照和文件保留语义。
- `opencode-embedded-chat`: 导航及分叉校验个人目录，附件使用同一持久化来源。
- `platform-file-browsing`: Code 文件入口打开本人远端目录，复用基本文件操作并按真实能力显示按钮。
- `sap-workbench-project-toolkit`: 个人 Location 继续发现和使用项目根的现有工具。
- `sap-workbench-session-binding`: 区分项目根和个人目录，维持既有场景权限与文件落点。

## Impact

- 平台修改集中在 `agent/coding/`、身份库个人目录绑定、会话关联的 `workspace_id`、fork 下 coding/workspace handler 及文件来源适配；普通 Agent 与桌面来源保持原契约。
- 配套 RSMCode 需补服务内受认证的个人目录/文件操作，以及附件落盘和必要的配置来源适配。不能仅改平台按钮；发布须验证实际服务及 Web 构建。
- 数据归属保持单一：平台登记目录归属和会话关联；OpenCode 保存正文及工具记录；文件字节保存在远端 U。引用使用工作区与相对路径，不建设全量文件索引。
- 消费既有身份、凭据、CSRF、审计和资源配额的适用切片，缺口在对应责任域最小补齐；不等待其他 change 全量完成，不取消现行要求。外部共享 OpenCode 沿用既有执行边界，不增加沙箱前置或关闭已授权 Shell。
- 本次交付覆盖个人文件入口及启用后的新会话；旧会话不迁移、不冻结，不能宣称存量交互已经全部切换。批量迁移、自动携带历史上下文和远端完整文件编辑能力如有需要另行提出。
- 与 `fix-coding-session-history-management`、`optimize-console-login-startup` 可能有代码重叠，无功能前置关系，实施时保留各自改动。
