## MODIFIED Requirements

### Requirement: 页面导航通知可验证并关联真实会话

系统 SHALL 在 OpenCode 内部新建、分叉或导航后同步当前会话选择及合法关联，已有关联不得重复创建或重新归属。父页 SHALL 验证消息来源 origin、对应 iframe 及本次挂载标识；服务器 SHALL 查询真实远端会话验证目录与归属，不能把页面通知视为授权。内部子任务 SHALL 不自动成为独立历史记录。

个人模式的导航或分叉 SHALL 继承经验证的个人工作区绑定，远端实际目录和可信创建来源 SHALL 与该绑定及会话所有者相符；同一 Git 项目 ID MUST NOT 单独证明个人目录或会话归属。内部子任务的执行及文件交付 SHALL 使用父会话的个人范围。合法切换后文件面板和附件来源 SHALL 跟随当前个人绑定，迟到事件不得污染新范围。

#### Scenario: 在嵌入页分叉
- **WHEN** 用户分叉当前编码会话并进入新根会话
- **THEN** 平台登记新会话并选中它，原会话仍可恢复，重复通知不增加重复记录；个人模式下复用同一获权个人绑定

#### Scenario: 迟到或伪造通知
- **WHEN** 旧 iframe、错误 origin 或错误挂载标识发送会话通知
- **THEN** 平台忽略该通知，当前选择、权限和关联不变

#### Scenario: 未知或不匹配会话
- **WHEN** 通知引用不存在的会话、另一智能体已关联会话或不符合当前项目的会话
- **THEN** 后端拒绝认领，原会话不改归属，界面给出失败反馈

#### Scenario: 同项目不同个人目录
- **WHEN** 被通知的远端会话与当前会话 Git 项目 ID 相同但属于另一 U 或缺少可信创建归属
- **THEN** 拒绝认领，不因共享项目 ID 采用其他账号会话

## ADDED Requirements

### Requirement: 嵌入附件与个人文件来源一致

个人模式 iframe SHALL 按 coding-agent-personal-workspace 的附件准入规则处理选择、拖拽、粘贴和既有文件引用。父页与 iframe SHALL 使用同一受信个人绑定，客户端路径和页面消息不构成授权；文件选择、持久化和消息提交的失败 SHALL 可见且可恢复。配套 Web 不支持该流程时 MUST NOT 将个人模式标记为就绪。

#### Scenario: iframe 附件与顶部面板
- **WHEN** 用户在嵌入输入框选择文件并发送
- **THEN** 持久化成功后才提交消息，顶部文件面板可以找到同一原件，切换账号后的旧上传回包不会更新新输入框

#### Scenario: 附件持久化失败
- **WHEN** 远端附件写入失败或浏览器与服务能力版本不匹配
- **THEN** 保留草稿及明确失败，不用仅存于消息载荷的附件伪装个人目录上传完成
