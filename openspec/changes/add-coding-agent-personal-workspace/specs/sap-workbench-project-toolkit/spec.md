## MODIFIED Requirements

### Requirement: 项目目录内交付的 SAP 能力

系统 SHALL 把 SAP 工作台的操作能力交付为配置项目目录内的标准产物：由项目插件提供可执行工具，由 skill 提供业务知识、流程与风险纪律。安装 SHALL 幂等，重复安装 MUST NOT 产生重复项或重复注册，MUST NOT 静默覆盖用户已有改动。该交付 MUST NOT 要求用户安装场景专用 OpenCode 构建、手工维护工具注册或由工作台宿主注入工具。

Code 个人模式下，工具安装和可信配置来源 SHALL 保持在配置项目根 P，运行在本人 U 的获权会话 SHALL 能发现并按原权限使用同一套项目工具。MUST NOT 为每个个人目录复制独立工具安装或自动扩大 SAP 工具权限。配置继承不足时 SHALL 通过配套服务的配置来源适配解决并验证，不以把会话回落 P 掩盖失败。

#### Scenario: 首次写入项目产物
- **WHEN** 场景在工作台首次启用而项目目录尚无对应产物
- **THEN** 写入 skill 与插件，重复执行不产生第二份，且不改动项目其他配置

#### Scenario: 用户已改动项目产物
- **WHEN** 用户修改或删除项目内的 skill 或插件文件
- **THEN** 系统不就静默覆盖其改动，按幂等规则处理并如实报告差异

#### Scenario: 普通对话不受注入
- **WHEN** 用户在同一项目目录发起普通编码对话
- **THEN** 不出现由场景宿主注入的 SAP 工具；SAP 能力只来自标准插件与 MCP

#### Scenario: 个人目录加载项目工具
- **WHEN** 受授权的 SAP 会话在 P/user/账号 中运行
- **THEN** 原有项目技能和工具正常发现及调用，安装仍位于 P，其他个人会话不会因此获得该场景的权限档案
