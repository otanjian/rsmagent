## MODIFIED Requirements

### Requirement: 智能体类型与项目配置

系统 SHALL 支持 `normal`、`coding` 两种智能体类型，缺少类型字段的旧档案 MUST 按 normal 处理且不重写原数据。coding 创建 SHALL 要求名称及远端默认项目目录，类型保存后不可变。配置项目根 SHALL 与平台状态工作区分开，允许已有非空代码目录。复制 SHALL 只复制档案与项目配置，不复制会话、个人工作区归属、凭据或代码文件。

个人文件能力 SHALL 通过单一部署开关启用；启用且能力就绪后，coding 的新会话 SHALL 按 coding-agent-personal-workspace 从配置根 P 派生本人 U，项目根继续提供可信配置和资源。系统 MUST NOT 为此增加每 Agent 的试运行/完整切换状态；既有会话保持原绑定，使用个人目录不改变 Agent 类型。

#### Scenario: 旧智能体无需迁移即可使用
- **WHEN** 加载未保存类型字段的智能体
- **THEN** 其普通聊天及原配置继续生效，不增加外部服务依赖

#### Scenario: 创建与复制编码智能体
- **WHEN** 用户创建或复制 coding 智能体并指定远端已有代码目录
- **THEN** 保存合法配置，目录不因非空被拒绝，也不在平台服务器上创建或改写该目录；复制不带入原会话，个人目录只在远端经授权按当前用户准备

#### Scenario: 修改已有类型
- **WHEN** 更新请求试图将已保存的 normal 改为 coding 或反向修改
- **THEN** 请求明确拒绝，原配置与历史保持不变

#### Scenario: 个人模式的新建与存量兼容
- **WHEN** 个人功能启用且就绪后新建 Code 会话，或恢复启用前的旧会话
- **THEN** 新会话使用 U，旧会话保留原目录并提示差异，不因升级被自动改绑或冻结

#### Scenario: 不适用个人业务目录的代码项目
- **WHEN** 部署启用个人功能，涉及原本直接修改 P 下源码的智能体
- **THEN** 部署及使用说明明确新会话在 U 工作及其兼容影响，不能声称 P 的现有构建和编辑基准自动保持不变
