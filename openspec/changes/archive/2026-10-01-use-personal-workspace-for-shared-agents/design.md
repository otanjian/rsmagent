## Context

参见 [proposal.md](./proposal.md)。现有实现已经具备三项基础：

- `state_dir.agent_user_root()` 负责 `<agent>/user/<uid>` 布局、安全用户 ID 与容器校验，文件面板有本人目录物化入口。
- `Agent.apply_project_dir()` 能重定向会话工具 cwd，同时保持 `workspace_dir` 下的设定、技能和记忆来源；Bridge 已按会话创建运行实例并传递宿主 Agent。
- Web/Desktop 已消费 `default_workspace` 与 `current.path`。Web 文件面板已默认进入共享 Agent 的本人子目录。

缺口是默认值没有用于实际执行，而且 Web 的相对媒体/工件代码仍混用文件浏览根。文件服务可浏览的根、默认落点和工具 cwd 是不同职责；本次只统一业务工作位置，不必把全部文件 API 的服务根缩成个人目录。

## Goals / Non-Goals

**Goals:**

- 共享普通 Agent 的默认提示和相对业务操作指向本人目录，显式项目仍优先。
- 复用现有路径、物化、权限和 cwd 切换机制；新产物能正确预览、下载并在会话恢复后继续定位。
- 保留共享配置来源和当前用户/会话边界，准备失败时不误写公共根。

**Non-Goals:**

- 不新增 feature flag、协议协商、强制客户端升级或共享资料页面。
- 不改项目失效后的既有处理，不新增项目状态机、运行快照和调度系统。
- 不改 uploads/outputs/work 布局、同名产物策略，不迁移历史文件或建设历史映射系统。
- 不建设用户级脚本沙箱，不改外部 OpenCode、本机文件访问或无用户机器任务契约。

## Decisions

### D1 用一个小辅助函数统一默认值，复用既有会话目录覆盖

在现有目录/工作区模块中提供返回路径的小辅助函数，验证当前身份与目标 Agent 后，对共享普通 Agent 返回 `agent_user_root`。目录布局仍只在 `state_dir` 中定义。本人私有 Agent 及外部 coding 等不适用对象保留原行为。

Bridge 在已有 `get_project_dir(session_id, host_agent_id)` 没有返回有效项目时应用个人默认目录；否则使用项目。优先复用 `apply_project_dir` 作为**运行时 cwd 覆盖**，不把个人默认目录写成 projects.json 中的项目，不创建项目最近记录，也不修改 `workspace_dir`。若提示现有“项目”名称不适用于个人默认空间，只调整相应工作目录措辞。

目录投影使用同一辅助函数且不隐式创建目录；运行准备复用 `agent_user_root(..., ensure=True)`。个人准备失败不得被 `_apply_session_project` 的宽泛异常处理吞掉后继续执行，直接沿现有错误路径报告即可，不引入错误状态机。无用户的系统初始化不绑定个人路径；已认证用户会话发生身份错误仍按现有授权拒绝，不能当作系统初始化。

采用现有会话实例与 host_agent_id，不重设计缓存键或 ExecutionRun。客座 Agent 继续遵循宿主会话目录；子任务只需沿用父任务已经生效的 cwd。对已运行的实例，展示刷新不应触发新目录应用；检查并做必要的局部保护，不借此重写整体并发调度。

### D2 保留 API 和浏览范围，只修正默认位置

`_project_state` 及同类默认空间投影在共享 Agent 分支返回本人目录；前端继续用 `current.path || default_workspace`。保留「默认空间」名称，无需新增本地化名称或协议字段。

保留文件服务的既有租户/项目浏览根与 owner 过滤，不全局替换 `_get_workspace_root`：它还服务于显式公共资料浏览、已有相对 API 路径及权限边界。文件面板正常打开仍落在本人目录；如果实现对非标准布局需要适配，仅将服务端已解析的本人位置转换为既有面板路径，不建立新的浏览作用域。已有有提示的浏览回落不改变会话 cwd。

`@` 搜索仍查询已有授权范围。选中文件时使用已经返回的 `abs_path` 等明确定位，服务端继续校验实际资源归属，不能因为模型 cwd 改变而把原引用当成相对于个人目录的新路径。无需新增受限搜索接口，也不移除用户原本有权引用的共享资料。

Web 和 Desktop 继续消费原字段；更新 Web 源模块时按仓库已有装配方式同步入口。与其他进行中 Desktop 工作只做接口兼容检查，不引入其部署和升级流程为前置。

### D3 新相对产物按实际执行目录解析，旧数据不迁移

必须检查 `_rewrite_relative_media`、实时工件生成及 `_artifacts_from_steps` 的边界。**新运行产生的**相对业务文件按该运行已经应用的 cwd 解析；通过现有工件/消息字段保存明确文件定位，历史重放优先使用这个已保存定位。消息发送或项目切换后，不重新查询当前项目来解释已产生文件。

文件面板和 `@` 引用采用文件服务返回的明确定位。对真正来自浏览 API 的旧相对路径，按该 API 原浏览基准解析并授权后再传入模型；不能将所有相对路径一律改为 cwd。

旧文件、旧消息及已保存绝对链接保持原有处理，不批量扫描或重写。旧消息如果缺乏原始目录信息，保留既有缺失处理，不承诺本次恢复全部历史相对文本，也不按新 cwd 猜测同名文件。只有新增定位字段确有必要时复用现有消息扩展，不能为此新增数据库或迁移服务。

### D4 保留必要回归，移除独立产品需求

默认目录准备、实际 pwd/相对文件、两用户并发、项目选择/清除、共享配置来源及链接可打开，是本次必验。已删除项目仍按 `project_store` 现有规则退回默认空间，此默认值对共享 Agent 变为本人目录；不对所有私有 Agent 改成“项目不可用即阻断”。已有项目归属和越界拒绝规则不放宽。

原稿审核后的范围修正：

| 原稿内容 | 审核结论 |
| --- | --- |
| 新开关、目录协议版本、客户端升级拦截 | 可用现有字段完成，删除 |
| 新共享资料入口与独立浏览协议 | 现有文件浏览和引用可复用，删除 |
| 历史引用扫描、映射和迁移系统 | 超出默认目录修正，改为旧数据不动、新产物保存明确定位 |
| work 按 run 分层、产物唯一命名 | 属于独立并发交付需求，删除 |
| 全局项目失效新策略、运行快照、后台上下文重构 | 与默认值切换无必然关系，删除；只检查共用接入点的兼容性 |

## Risks / Trade-offs

- 技能把相对路径当作共享资源位置 → 平台提示与内置调用明确资源路径，实跑代表性技能；不复制整套配置到个人目录，不链接整个共享根。
- 展示目录正确但下载定位仍用租户根 → 用真实生成文件测试 SSE、轮询及重新打开会话，检查明确文件定位。
- 个人目录准备失败仍沿用旧 cwd → 局部异常处理必须终止本次目录应用/执行，测试没有公共写入副作用。
- 同租户脚本仍可按原执行规则访问其他位置 → 如实说明这是工作位置调整，不能当成新增用户级执行隔离。

## Migration Plan

无需数据迁移、schema 迁移或新增 feature flag。完成核心路径测试后，用一个共享 Agent 和两个用户验证 UI 提示、真实 cwd、附件读取、项目选择/清除及下载；再执行已有私有 Agent、目录 owner、Desktop 和团队相关回归。前序本人目录物化与文件归属切片必须实际可用，不等待其他 change 整体归档。

部署按现有版本发布流程进行，新行为从下一次会话目录应用生效，不在运行中途切换。回滚通过代码版本恢复，按既有服务重启流程处理在途请求；保留已生成个人文件，不搬回公共根，既有 HTTP owner 校验保持有效。产品说明标明新相对路径基准和脚本隔离限制即可。
