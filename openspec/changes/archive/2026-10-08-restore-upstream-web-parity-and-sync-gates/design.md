## Context

动机和范围见 [proposal.md](proposal.md)，当前事实和复现边界见 [evidence/baseline.md](evidence/baseline.md)。本文件为拟实施设计，未声称运行代码、CI 或更新服务已按此方案改变。

当前生产入口是 `build_web_app()` → `route_registry.py` → `fork/handlers/**`，页面由 fork 的 `ChatHandler` 组装 `chat.html`。上游 `build_app()` 与 `api/**` 保留为独立装配，不能用于证明 rdai 生效。前端仍加载单体和若干已移植模块；直接同时加载上游全部脚本会产生全局状态、事件和函数重复。

两个既有约束需要显式处理：`console-route-lifecycle` 仍规定 hash 地址，本 change 通过 delta 改为 path；`adopt-upstream-web-frontend-split` 已归档但任务未全部实现，归档不是七项缺口的完成证据。Gitea 已有 `production-readiness.yml`，本轮应扩展现有入口，不另建一套互不一致的生产门禁。

## Goals / Non-Goals

**Goals:**
- 七项缺口有固定来源、唯一生效实现、实际入口正向/权限/故障验证及关闭证据。
- 地址、区域、页签、权限与浏览器历史一致；通知不因长任务、多页、重连或身份切换漏发/越界。
- 合并和普通补偿修复共用持续清单与必要检查，明确已验证、待交付和产品差异。

**Non-Goals:**
- 不重做通用路由框架，不切换前端框架/构建器，不完成旧单体的全量退役。
- 不改写 Git 历史、不再次合并已包含的源提交；本次规划不触发生产更新、远端发布或修改远端分支保护。
- 不扩展桌面本地运行时、渠道能力或数据授权，不把上次隔离复现当成部署端到端验收。

## Decisions

### D1. 以缺口为单位补偿接入，保留双方行为

实施从重新确认的 rdai 候选创建 `codex/restore-upstream-web-parity` 工作分支；源固定为已核查的 `48c0d79c`。若目标已前移，先核对七项是否已修复及相关调用变化，更新受测基线，不重放旧快照。按依赖批次提交修复，普通提交明确引用来源提交和 GAP ID。

复用上游可直接复用的算法及表现，fork 只承载 IAM、通知作用域、导航区域及发布源适配。每个切片记录调用方、辅助符号、状态、模板、样式、翻译、启动与清理钩子、API 和测试。上游模块与 fork 替代模块不得双加载同一功能；在需要抽取的范围内从单体移走旧实现，不能全局重名覆盖。暂时仍留在单体的已裁定补丁列入来源映射，后续结构迁移必须带走。

取舍：整站模块化成本大且并非这七项修复的前置；只增加脚本标签会引入重复全局状态，因此采用受影响模块的最小迁移并保持完整依赖。

### D2. 路径登记接入现有导航与授权

在既有 `route_registry.py` 的页面登记中增加规范路径、view ID、区域、页签/默认页签及兼容别名的描述；由同一份页面描述生成明确的 GET 页面路由和交给模板的非敏感导航元数据。前端既有 `VIEW_META` 保留标签与可用性关联，校验其 view ID 与页面描述一致；区域不再由 `_navAreaFromPath()` 的 `/admin` 前缀猜测。该描述不承载权限授予，数据 API 仍执行原授权。

| 规范路径 | view | 区域 | 兼容 |
| --- | --- | --- | --- |
| `/` | chat | workbench | `/chat` 和已有 chat hash |
| `/agents` | agents（配置） | admin | 旧 agents 配置标识，不与 agent-workbench 使用目录混淆 |
| `/settings[/models]` | config | admin | 旧 config 标识及合法 tab；`/config` API 不变 |
| `/scheduler[/records]` | tasks | workbench | 旧 tasks 标识和已保存页签 |
| `/knowledge[/graph]` | knowledge | workbench | docs 默认省略，sources 登记为新增合法页签 |
| `/admin` | admin-home | admin | 管理首页入口 |

其余现有可用页面逐项登记，包括场景、待办、历史、外部连接、组织与权限、审计和 token 页。既有调用继续通过 `navigateTo` 的薄适配进入同一提交过程，不另建并行导航状态；按钮回调在导航成功后执行。合并现有区域 `popstate` 和上游 router 的事件处理，保证一次事件只做一次离页判定、历史提交和加载。

页面外壳采用与现有 `/chat` 一致的显式策略：仅返回无租户数据外壳，认证就绪后才恢复目标并访问数据；不把所有未知路径公开兜底。`/chat` 保留兼容外壳，客户端解析 fragment 后 `replaceState` 到规范路径，无 fragment 则规范化为 `/`，避免服务端看不到 fragment 而误丢目标。兼容两类旧 hash；拒绝外部 URL、未登记 tab/参数作为内部目标。所有第一方及惰性资源、片段和预览地址按明确资源根构造，检查深层路径与尾斜杠。

沿用现有 classic/split 展示开关，两种模式共用路径契约；新路由不加永久关闭开关。覆盖直接访问、登录/选租户后恢复、取消离页后的 URL/焦点/草稿恢复、快速导航、撤权、SAP iframe 与桌面 Web 容器链接。完整路径默认启用前必须通过这些场景。

### D3. 回复与布局修复采用真实消费方验证

- **GAP-002**：复用上游 `isSchedulerRequest` 判断并放入实际加载的共享依赖；SSE error 分支在有效身份下完成错误展示和幂等清理。测试实际 `startSSE` 的 error/done/cancel/background/stale-identity 分支，不能仅 stub 掉缺失符号来通过。修复历史刷新夹具，使它加载现有 `_patchHistoryCache` 依赖；不把夹具错误列成生产缺陷。
- **GAP-004**：采用上游区分用户上滚与程序滚动的逻辑，验证 10px 上滚后新增片段不抢位、显式回到底部恢复跟随；用真实滚动容器验证程序事件时序。
- **GAP-005**：将已选页签与有文档状态统一收敛到一处面板投影，保留 fork 新增 sources 的独立状态。列表返回不直接 unhide docs；请求捕获 Agent/tenant/auth epoch，过期回答不更新当前库。空态、来源态、失败态分别测试。
- **GAP-006**：将上游 `.msg-content`、链接及行内代码的换行规则接入实际加载样式，限定作用范围，保留代码块/表格局部滚动。用实际模板/加载样式验证窄屏与主题，隔离 260px 样例只作快速回归，不替代整页验证。

### D4. 通知复用已授权运行记录，修正进度语义

复用 `chat/scheduler-notify.js`、`core/notify.js` 的行为，经 fork 适配接入已经存在的 `RunAccessService`/`RunScopeRepository`。不调用上游无作用域的全局会话运行记录接口。独立轮询只在认证、租户和能力就绪后启动，退出/切租户取消请求与 timer；与当前 Agent 选择解耦，但每次请求仍重验可见范围。通知内容只用授权投影，点击会话再走原会话授权。

当前 `since` 是 `started_at >=`，直接照搬“取最大开始时间”的上游通知游标会漏长任务，也可能截断超过 limit 的记录。因此在现有 `/api/scheduler/runs` 增加可选的终态通知查询模式，保留原列表参数语义；授权在分页之前，查询使用与终态落库顺序一致的稳定游标。`ended_at` 与 `run_id` 可用于排序，但不能直接把两者最大值当永久水位：翻页后新落库的记录可能时间相同而 run_id 更小，时钟也可能回拨。默认在原运行存储中提供事务内单调终态顺序字段及加法迁移，用它推进游标；只有现有字段已能证明同等保证时才可复用，不能新增一套独立运行记录存储。用相同时间且迟到的较小 run_id、多页、时钟回拨、运行中跨轮转完成和删除记录验证不遗漏，不用截断分页或客户端猜测通过。

初次登录取服务端水位作为开始，不重放全部历史；同身份短暂断线延续游标。客户端 cursor/dedupe 以服务端、user、tenant 分区，run_id 为事件标识；通知与 SSE 共用去重，沿用手动运行窗口归属。跨窗口竞争需验证原子认领，不能仅把 localStorage 的先读后写当作原子锁；复用现有通知协调逻辑并在支持的浏览器上验收。普通消息仍遵守当前偏好，IM 投递不重复提醒。浏览器权限拒绝时保持明确状态，不影响任务执行。

### D5. 一键更新绑定 fork 的实际交付源

上游 `cli/update_service.py` 硬编码 CowAgent GitHub releases，工作进程注释明确“无备份步骤”，因此本次不能直接暴露上游三个 handler。复用其安装类型识别、状态、候选检查及重启服务；由 fork 适配提供唯一受信发布来源：部署配置的 repository/remote、发布 ref 和固定目标 SHA。不得默认推断 `origin/master` 或 `gitea/main` 就是每个部署的交付来源，也不接受浏览器任意替换来源。

检查返回当前/目标 SHA、来源标识、安装类型和可启动原因，并绑定服务器侧检查结果；启动重验当前 checkout、ref 解析、平台资格和来源/CSRF，来源漂移要求重新检查。先为受支持的源码部署交付；Docker/安装包显示部署升级方式，源码更新接口明确拒绝。

进程链采用“检查 → 获取并准备固定候选 → 候选自检 → 受控替换/重启 → 健康检查 → 完成/恢复”。候选依赖在独立环境准备，不能在自检前破坏原运行环境；重用原状态文件并增加原子实例锁、幂等操作 ID、阶段和 worker 存活信息。检查/状态只返回脱敏摘要，不把凭据 URL 或完整 subprocess 输出直送浏览器。

只接受干净且满足发布关系的部署 checkout，不用 `reset --hard` 清除操作者改动。可能执行数据迁移时，复用现有 instance-backup/restore 切片取得一致恢复点；先完成隔离部署下的停服/备份/恢复验收。替换前失败保持原服务；替换后失败同时核对代码、依赖和数据库兼容，不能只退源码宣称成功。不自动把旧快照覆盖仍在写入的数据；无法安全恢复则记录失败并提供明确操作依据。

这里的确认是产品更新动作原有的用户确认，不是本次撰写提案需要额外审批。提案阶段不更新实际服务。更新启用条件是发布源、平台权限、锁、恢复和目标形态验收齐备，按部署能力投影；不以永久隐藏菜单结案。

### D6. 持续能力清单与五层检查

拟在 `docs/design/upstream-sync/capabilities.json` 维护唯一持续能力清单，首批录入 GAP-001～007，并核对旧延期表中已接入项；旧证据保持只读来源。字段包括：`id`、上游 SHA/路径/行为、实际页面/模块/路由/handler/启动点、依赖、身份边界、`disposition`、`verification`、候选/产物、证据、负责人/任务、适用形态及有依据的例外。实现裁定和验收状态分离，source hash 只是来源证据。

拟新增 `scripts/check-upstream-sync.py` 作为同步汇总入口，调用既有检查而不复制授权/路由逻辑，接受固定源和候选以及持续清单。可机器生成入口/模块/提交候选清单，再人工核对行为分类；工具不声称能从任意 diff 自动推断全部产品语义。

| 层次 | 检查对象 | 必须失败的注入例子 |
| --- | --- | --- |
| 来源与历史 | 固定源新增/变更模块、既有清单及历史 open 项 | 删除仍未修复的 GAP 项；新增上游模块未分类；只更新哈希 |
| 入口 | 上游行为入口 → 实际路由/handler/惰性页面 | 上游新增 `/scheduler`，fork registry 内部一致却漏该页 |
| 装配与依赖 | 实际 HTML/样式/脚本、声明依赖、惰性加载与事件生命周期 | 移走 `isSchedulerRequest` 提供方；重复全局声明；漏换行样式 |
| 必要执行 | 必需 pytest node ID/Node 测试/浏览器场景及实际结果 | skip/xfail/零收集/缺浏览器被 runner 返回成功 |
| 行为与交付 | 真实页面正向、权限/故障分支、候选/产物与分支检查 | 单测通过但刷新回首页；仅改 CI YAML 未验证阻断 |

必要用例清单记录测试标识及行为契约，依据 runner 机器输出核对收集和执行，不把固定总通过数当验收。允许有明确来源的第三方全局符号/合法未加载参考模块，但不得用宽泛白名单掩盖新增依赖。原先整组 skip 的资源/路由测试改测实际 rdai 装配；独立上游测试另组保留。浏览器必需依赖不存在时明确失败，不再静默 SKIP。历史刷新夹具缺依赖必须修正后保留原行为断言。

将此入口接入 `scripts/check-production.sh` 的适用范围和实际 GitHub/Gitea 检查；Gitea 已有 main/rdai push/PR 触发，需要核查 runner 与必需检查的实际可执行性，不能把 GitHub 改动当成 Gitea 已生效。通过临时失败候选验证缺模块和必要用例跳过能阻止交付。尚无远端权限/runner 时记录未验证，保留该交付任务，不能写成全完成。

### D7. 合并规范与版本管理同步修订

直接更新既有合并规范：补充逐功能接入包、七项必查场景、历史缺口状态、候选树/构建绑定和检查工具未完成时的人工要求。`.gitignore` 从忽略 `/doc/` 改为忽略 `/doc/*` 并只例外此规范，其他本地文档仍被忽略。规范中明确自动检查尚待本 change 实现，不给出不存在脚本已经可执行的印象。

## Risks / Trade-offs

- [路径与现行 hash 规范冲突] → 同批修改两个相关 requirement，保留旧地址适配，并用浏览器验证片段迁移、深路径资源与后退。
- [单体与模块共存期间依赖难静态穷举] → 限定唯一生效实现、来源与必要依赖检查，再用真实页面故障场景补足；不只做字符串搜索。
- [通知进度与任务开始时间混淆] → 明确终态排序/完整分页、原存储授权及迟完成测试，首轮和断线恢复采用不同水位策略。
- [更新错误来源或依赖回退不完整] → 来源及目标锁定、独立候选环境、实例锁和实际恢复演练；部署不支持时明确不可执行。
- [规范、清单或哈希自证通过] → 引用真实装配和同候选结果，使用故意破坏候选验证门禁；文档归档不改变实现状态。
- [与生产加固 change 重叠] → 复用已验收检查和备份切片，在实施开始时核对状态，按切片共享证据而不等待整份 change。

## Migration Plan

1. **基线与回归入口**：重新固定版本，建立持续缺口/必要用例清单，复现缺陷，修正夹具；没有基线和候选关联不进入交付。
2. **即时缺陷**：先交付 SSE/滚动/知识库/换行四项，各自从失败场景到通过，保持授权及既有工作台行为。
3. **路径路由**：登记全部页面并接通后端和实际资源，兼容旧地址；classic/split、登录恢复、SAP 与桌面容器通过后默认生效。
4. **跨会话提醒**：终态查询与客户端身份生命周期一起交付；运行记录读取前置已验收，真实双会话及多窗口场景通过后开放。
5. **Web 更新**：在隔离源码部署完成来源、平台资格、并发、失败和恢复验证后交付；不支持安装类型验证明确拒绝。
6. **汇总及交付**：五层检查、必要用例零跳过、实际流水线阻断验证；更新持续清单与规范，执行同候选 Web/桌面受影响回归后提交 PR。

每批为可审阅提交，部分批次通过只代表该批可交付，七项和门禁未全部验收不得关闭整份 change。功能修复本身不能因全量模块化延期而停止。

共享分支通过对应提交的 revert 回滚，保留缺口与证据。已发行的路径需要保留兼容入口或明确迁移，不能回滚后让既有书签全部 404。通知状态可重建且必须保持身份分区；若新增运行顺序字段则采用加法迁移并验证旧版本可读。更新路径的回滚以该次记录的代码/依赖/数据兼容性为准，不能把源码 revert 当作数据恢复。

## Open Questions

以下为实施/部署参数，不改变上述方案：实际交付仓库配置的发布 ref、平台审核人/缺口负责人、Gitea runner 可用标签与现有必需检查名称、隔离源码更新验收使用的进程管理器。实施时从实际环境确定并写入证据；不得猜测生产目标或因此把未验收项标为通过。
