## Context

需求动机见 `proposal.md`。下述为本 change 的设计约定，实施结果及验收缺口见 `evidence/implementation.md`。

已拉取并核对 `origin/master@48c0d79c36146950667f8d1884ab823deae62305`。master 已将 Web 控制台拆成模板与视图模块；其记忆页有两个标签、列表分页和通用文档编辑器，编辑经工作区接口完成。当前 RongAI 工作区为 `rdai`，实际页面仍加载 `console.js`，后端记忆路由由 fork handler 承载。因此“仓库存在 master 模块”不等于运行时已使用该模块。

当前代码证据：

- `memory_console._agent_root()` 经运行时工作区解析取得租户共享根；页面默认 Agent 目标可能读取空根，而实际个人文件位于租户的 `users/<user_id>/`。
- `console.js` 的通用 fetch 封装会追加当前 `agent_id`，与个人请求的 `scope=personal` 冲突；后端正确拒绝歧义目标。
- 个人兼容读响应固定 `read_only=true`，个人分类不接受 evolution/dream；正式写接口拒绝个人目标。既有个人服务实际已支持本人文件的保存、删除、清空与索引恢复。
- `MemoryManager.add_memory()` 当前写 chunks 和文件元数据，没有生成个人 Markdown 文件；工具能报告成功而管理页仍无条目。
- 摘要、Deep Dream、进化记录已有个人路径接缝，但仍有直接文件写入，需要与人工编辑、清空的最终提交协议统一。
- 前次针对性检查为 136 项通过、1 项失败；失败为 `test_shared_knowledge_is_indexed_without_crashing`。这是待复核的共享知识检索基线问题，不能据此宣称个人记忆已修复或认定它是空页根因。

## Goals / Non-Goals

**Goals:**

- 基于 master 的功能实现进行改造，交付实际加载的账号记忆页面；保留 master 的交互能力和后续增量可追踪性。
- 以一个可信 `(tenant_id, user_id)` 作为读取、保存、检索、自动任务及迁移的唯一个人归属；同租户跨 Agent 一致。
- 复用现有安全文件访问、操作版本、索引屏蔽与恢复协议，补齐真实运行链路和受控并发验证。

**Non-Goals:**

- 不整体切换产品为上游单用户认证模型，不合并与记忆无关的 master 功能，不重写整个控制台。
- 不提供浏览其他成员记忆的管理员入口，不把共享 Agent 的记忆搬入个人域。
- 不新增进化调度器、全局开关页面或“修改日志即撤销进化”的行为；既有进化执行、备份与撤销机制继续遵守其原权限。
- 不重算全部历史聊天，不调用模型凭空补造记忆，不将本次文档完成当成实现或迁移完成。

## Decisions

### D1. 从 master 的功能代码适配，按现有接缝接入 RongAI

master 是本次功能代码来源，不只是视觉参考。实施先读取固定提交下的来源文件，逐处对比现有 fork，并记录保留上游行为及账号适配的理由。工作区当前未提交的菜单更名不能因取 master 文件而丢失。

| master 来源 | 使用方式及必要适配 |
| --- | --- |
| `static/js/views/memory.js`、`templates/views/memory.html` | 沿用两个标签、表格、分页和文件类型；fork 版本移除 Agent 选择，增加本人信息与准确状态 |
| `static/js/views/doc-viewers.js`、`static/js/doc-editor.js` | 沿用渲染、编辑、快捷键、未保存提醒和冲突交互；个人文档 read/write 回调改用正式记忆接口，技能编辑不受影响 |
| `api/memory.py`、`agent/memory/service.py` | 沿用列表/内容响应形状、分类和排序语义；fork handler 解析可信身份并委托既有个人服务 |
| `agent/memory/summarizer.py`、`agent/evolution/record.py` | 保留自动摘要、梦境、进化记录生成流程，接入可信个人根和统一最终提交 |

按 `web-console-module-seams` / `web-console-frontend-modules` 现有约束，在 fork 命名空间承载账号定制，登记来源提交/指纹，保持上游模块不含 fork 专有授权。优先通过既有覆盖映射加载 fork 记忆模块。若实施时仍加载单体，执行范围仅为记忆的迁移：从 `console.js` 移除已迁移的记忆实现，保留它与导航、身份和通用请求封装的必要调用接缝，装载 master 派生的唯一记忆模块；不得双加载同名顶层声明或保留第二套记忆实现。单体其余部分继续存在的范围与后续归属须显式登记。

交付证据记录“master 来源 → fork 目标 → 实际 HTML/script URL → 实际路由 handler”，验证加载顺序、源码指纹、缓存版本和 Web/Desktop 所用表面。仅改未加载的 `views/memory.js` 或仅在单体打补丁均不算完成。

替代方案：只改 Agent 根路径不能满足账号归属；只修改旧单体不能满足用户要求的 master 代码基线；直接覆盖全部 master 文件会丢失已交付的租户授权。采用功能切片移植。

### D2. 页面固定个人域，旧 Agent 请求保留显式兼容

正式页面所有记忆请求显式使用 `scope=personal`，不携带 `agent_id`、用户标识或文件绝对路径；用户身份从已验证请求上下文解析。缺少身份拒绝访问，不能回落共享根。

复用现有 `/api/memory`、`/api/memory/content`、`/api/memory/save`、`/api/memory/delete`、`/api/memory/clear`，在统一目标适配层支持个人域。个人 `scope` 与 Agent 参数并存仍返回歧义错误，从前端修正参数注入；不能靠后端静默忽略错误参数掩盖缺陷。旧显式 Agent 调用维持原授权、真实目标和响应语义，不修成“任何 Agent 参数都返回本人”。旧 `/api/memory/personal*` 仅适配输入输出并委托同一服务。

在请求封装中明确区分个人记忆路由/作用域与需要 Agent 的请求，覆盖 GET 查询、POST JSON、Request 对象及 URL 形式。保留租户头、认证刷新等公共逻辑，其他 Agent 请求仍正常注入目标。

账号或租户切换、退出登录时清空列表、正文、编辑器及旧目标缓存，取消在途读取并校验请求所属身份代次，迟到响应不能重新显示旧账号内容。编辑请求使用打开文档时绑定的身份与版本，不能把旧账号草稿提交给新账号。普通同身份导航保留 master 的未保存提醒。

### D3. 文件为内容真值，个人服务统一四类条目

通过既有 `state_dir.user_root(identity)` 解析个人根，不新增配置目录或个人数据库。条目白名单扩展为：

```text
MEMORY.md
memory/<name>.md
memory/evolution/<name>.md
memory/dreams/<name>.md
```

`memory` 分类展示长期、每日和主动记忆；`evolution` 标签合并 evolution/dream 文件。响应保留 master 列表字段，同时返回稳定的相对条目 ID、版本和实际可用动作。类型为长期记忆而非“全局共享”；同名日期文件以完整相对 ID 区分。

扩展 `PersonalMemoryService` 的安全枚举与分类，列表、读写均通过既有防路径替换机制。master 的个人记录文本编辑能力一并保留；日志编辑不触发任务撤销、不改变关联备份权限。服务区分正式记忆和历史记录：正式记忆参与记忆检索/蒸馏，进化与梦境文本仅用于记录展示，不因开放编辑而自动扩大检索或模型输入范围。

保存和删除携带条目 revision；清空携带集合 revision。索引仍采用现有 Agent 索引和个人归属过滤，保存发布、删除清理覆盖同租户所有实际索引副本。新增 Agent 从正式文件重建同一账号记忆，不创建另一内容真值。

### D4. 清空范围显式化，兼容旧调用

新页面按钮为“清空我的记忆”，确认内容给出当前账号/租户及各类文件数量，明确覆盖 D3 四类文件。请求显式提交 `clear_scope=all_personal` 及四类集合的版本；清理正式记忆索引、相关已检索历史记录遗留索引并失效旧发布者。人设、聊天记录、Agent 共享记忆、技能和进化备份不在范围内。

旧接口没有此参数时保留原来的 memory 分类清空语义，不能因升级扩大旧客户端删除范围。个人记录仍可单条删除。未来使用旧进化备份恢复时也必须按当前身份与有效版本重新提交，不能通过旧任务或恢复重放绕过清空边界。

### D5. 所有个人发布者共用最终提交协议

`memory_add(scope=user)` 从可信运行时身份取得目标，经统一个人发布入口落盘再更新派生索引；修复放在个人写入分支，不改变 shared/session 的既有语义。默认生成稳定的个人条目 ID；重复相同内容幂等。显式指定已有路径时用当前版本做受控追加，遇并发变更重读后有限重试，不能无条件覆盖其他内容。返回条目 ID 和真实持久化/索引状态。

摘要、Deep Dream、进化记录及允许修改个人记忆的已有工具均接入同一发布协议。后台任务启动时捕获不可伪造的租户/账号身份以及输入内容版本、操作版本、清空 generation；在线程/异步任务内恢复身份，最终提交在受保护临界区重新验证。过期任务放弃或基于新内容重新生成，不提交旧结果。跨类别的主记忆与梦境日志写入用持久化操作记录协调，部分提交可恢复且不伪报完整成功。

沿用持久化发布意图、屏蔽/墓碑、重试与索引重建接缝；状态损坏拒绝发布，不当作空状态。索引不可用时正文若已提交，应报告“已保存，索引待恢复”，可在页面查看并重试，但不得声称所有 Agent 已可检索。现有协议只具备进程内锁时，必须落实单写进程门槛或补齐跨进程保护后才支持多写进程。

### D6. 复用功能开关与审计，不放宽个人权限

按现有 `member_personal_console` / `personal_memory_write` 能力投影控制页面和动作，服务端最终检查真实能力；关闭写入开关时阻止人工及工具/后台新增、修改，保留已授权的本人读取、删除、清空和必要的清理恢复。重新打开不得自动执行已过期任务。一般成员无需管理员身份即可管理本人记忆，管理员无额外的他人个人域权限。

沿用脱敏审计，只记录操作者、租户、动作、分类、结果和关联操作标识，不写入正文。功能开关撤回、迁移恢复、索引失败均有可诊断反馈。

## Risks / Trade-offs

- [master 模块存在但未装载] → 按 D1 核验实际 HTML、单一模块来源与端到端行为；交付来源映射，不能只跑辅助函数测试。
- [旧 root 或环境身份导致跨账号访问] → 仅用可信个人根，覆盖 API、工具、定时/异步任务、工作区别名；软链接和账号切换均纳入测试。
- [扩展日志类别使 clear 或索引意外扩大] → 显式分类/清空范围；旧调用保持原语义，历史日志默认不作为模型记忆输入。
- [多 Agent 同日追加、整理与编辑并发] → 在统一提交协议中校验 revision/操作版本/generation，失败不无条件覆盖；用受控交错测试证明。
- [索引只存片段无法恢复全文] → 优先原文件，仅能恢复片段时生成带来源和不完整标识的恢复条目，不宣称找回完整原文。
- [迁移重复或回滚覆盖用户新编辑] → 内容指纹、迁移账本和版本条件；只撤回版本未变的本次迁移写入。
- [前次已有共享知识回归失败] → 在实施起点重跑并分类；本 change 若触及对应索引链路需验证并处理，不能删测试或把失败算通过。

## Migration Plan

1. **基线门槛**：确认固定 master 来源、当前集成分支和真实路由/脚本；记录既有菜单更名与未提交改动。核验个人安全文件访问、身份、开关与审计切片证据。master 若继续变化，逐处评估并更新来源记录，不能悄然改基线。
2. **服务门槛**：先完成账号域四类文件访问、统一发布、版本/恢复及跨账号隔离测试，再允许页面写动作开放。沿用既有开关，在测试环境验证开/关，不修改生产开关默认值作为修复手段。
3. **页面门槛**：接入 master 派生页面及编辑器，证明实际请求不受 Agent 注入影响，并在 Web/Desktop 涉及的实际表面验证登录和切租户；未完成的依赖切片留明确证据缺口。
4. **迁移预览**：按租户解析可信用户与旧存储；现有个人文件原位保留。对旧个人文件和 index-only 行生成归属、来源、目标、指纹、完整性、冲突与隔离原因清单，默认只读，不输出正文。共享/session、已删除/清空版本、无可信归属的数据不进入导入。
5. **迁移执行与恢复**：限定清单范围，备份源文件及必要数据库快照，经统一服务写入；运行时仍校验身份/文件版本/清空 generation。先文件后派生索引，逐条记录状态；故障可续跑，重复执行不重复追加，不能抢写用户已有文件。所有有效 Agent 索引按正确归属重建或标记待恢复。
6. **验收与撤回**：完成完整读写检索和故障矩阵后提供实施证据。发现问题可关闭新写入并保留本人读取/删除/清空；不能恢复到错误共享根。迁移撤回只清理本批且版本未变的目标文件/索引，不恢复已清空版本、不影响新内容；旧源备份不参与正常读取和索引。

## Open Questions

无影响需求边界的未决项。迁移批次大小、备份保留周期和性能阈值在实施预览后记录为运行参数，不改变账号隔离、默认只读预览、版本条件及幂等要求。
