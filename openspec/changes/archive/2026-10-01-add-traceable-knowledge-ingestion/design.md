## Context

动机与范围见 [proposal.md](./proposal.md)。现有 KnowledgeService 已有文件管理和同步导入，MemoryManager 已能将知识 MD 与个人记忆纳入检索，SQLite chunk metadata 可承载来源扩展。缺口集中在原件保存、转换、有效文件筛选和引用传递。

上一版将这些缺口扩大为新的库级检索存储、多 worker 调度、运行中根迁移和整理稿依赖管理。本次收敛到现有文件／索引链路；以下均为待实现设计。

## Goals / Non-Goals

**Goals:** 原件完整保存；支持格式忠实转换；来源可核验；有进度与重试；旧知识、共享／独立归属和智能体搜索可用。

**Non-Goals:** 新建搜索存储、通用任务平台、并行转换、在线索引分代重建、运行中迁移任务、独立任务中心、人工整理稿依赖图。七种首期格式不缩减；其余文件可以保存但不承诺转换。

## Decisions

### D1. 简化边界与保留的必要保护

| 上一版设计 | 本次选择及理由 |
|---|---|
| 唯一库级 search.sqlite3、跨 Agent 索引迁移、分代重建协调器 | 复用现有每个 MemoryManager 的索引；查询前核对知识库修订，落后则同步，避免连带重写记忆与重建入口 |
| 租约续期、fencing、多 worker 竞争和多套发布世代 | 每库一次只运行一个任务，使用系统文件锁持有执行权；用资料修订与目标 task_id 拒绝过期结果 |
| 根定位注册表、binding_epoch、运行中迁移和暂存库清理调度 | 有未完成任务／清理就返回忙；只在空闲时切换，保留一个工作区内的切换恢复标记 |
| 独立任务抽屉、多来源整理稿和重新发布流程 | 列表状态 + 资料详情处理记录；转换 MD 只读，现有普通 MD 仍可编辑，整理稿管理另行设计 |
| 来源、版本、产物、任务、尝试、回执、维护等独立对象模型 | 一份 SQLite，meta、sources、versions、tasks 四类记录；产物清单与定位用任务内 JSON，幂等键放版本记录 |

原件不覆盖、当前授权、受管理目录保护、失效内容过滤和失败可恢复直接关系数据正确性，保留。简化不以删除这些保护换取表面上的任务减少。

### D2. 页面只增加完成闭环所需的入口

现有知识页面保留知识文档／图谱，增加原始资料页签和右上角「上传资料」按钮。「新建」仍创建普通分类／文档。上传面板显示当前目标库、分类、文件队列、限额与自动转换／仅保存；成功后定位本批资料。

原始资料列表显示名称、类型、状态、最新原件和当前生效版本；详情复用侧栏显示原件下载、转换 MD、历史版本、阶段／错误及重试、取消、停用和删除。进度嵌入列表和详情，不另建任务中心。各页签独立处理空／加载／失败；切换智能体后忽略旧请求，页面离开时停止轮询。

智能体菜单顶部固定搜索框，只筛选已授权 agentCatalog 的完整名称／ID，支持 trim、大小写归一、中文、无结果与清空；查询不自动切换。复用 initDropdown 的结构，搜索为 opt-in，不开发通用查询框架。覆盖键盘、中文输入法、三语、主题和窄屏。

### D3. 少量持久化记录与普通目录

在实际知识根保存来源数据，knowledge_id 随根移动，不另建根定位数据库：

~~~text
knowledge/
  .ingestion/catalog.sqlite3
  .ingestion/staging/<request-id>/
  originals/<source-id>/<version>/<blob>
  converted/<source-id>/<version>/<task-id>/
    content.md                 或多个 MD
    assets/
  <existing-category>/*.md
  index.md
  log.md
~~~

meta 保存 schema_version、knowledge_id 和文档集合 revision；sources 保存名称、分类、生命周期、latest_version、active_task_id 和目标 task_id；versions 保存不可变原件路径、哈希、请求键及提交状态；tasks 保存转换／清理类型、主体引用、目标版本、状态、错误和产物 manifest。manifest 内记录文档 ID、路径、正文行区间与原件位置。接口回执、MD 文件头和页面状态由这些记录投影，不单独存另一份关系事实。

保留 SQLite 是为了版本分配、幂等重试和状态切换的事务；不改成多个可并发写的 JSON 真值。文件名只作展示，内部使用安全 ID。启用前检查目录冲突；使用一次性选定并记录的无冲突内部目录名，不搬动已有人工文件。资料分类变更只更新 metadata。

### D4. 保存与删除使用短事务和可重试操作

沿用 10 MiB／文件、100 文件／批、200 MiB 内容总量的默认限额，后端投影实际配置。每文件一个请求键：校验维护权并预留现有存储额度，写 staging、核对字节／哈希，记录提交意图，原子落盘后提交版本和回执。相同请求重试复用结果，不同内容复用同键返回冲突；同库同内容提示复用，同名不同内容显式选择新资料或更新指定资料。

新版本不覆盖旧原件。失败项不显示保存成功；恢复只核对 versions 中未提交记录与对应 staging／目标文件，再完成或清理并结算额度。不新建通用事务补偿框架。审计和容量结算使用现有服务的幂等标识；原件及转换输出均计入容量。

停用／删除先事务修改生命周期、清除生效资格、增加 revision 并取消待执行转换；查询立即过滤。阶段 B 先实现同一 tasks 表和串行执行器的清理分支，阶段 C 再加入转换。清理移除原件／MD／附件，失败保留待重试状态和最小删除标识；根内文件尚未清理完时不显示删除完成，也不允许移动该根。派生索引缓存立即失效，在各缓存下次同步时清退；文件清理完成不宣称全部闲置缓存已物理清空，不必等待闲置 Agent 才能切换模式。分类删除走资料生命周期，旧路径接口不能递归删除受管理目录。

### D5. 每库串行转换，避免为并行能力建平台

应用内 runner 从可信租户／Agent 目录发现当前知识根，以 knowledge_id 去重；每库的系统文件锁保证同一时间只有一个执行者，锁位于根外的可信运行目录。获得锁后领取一项 queued 任务，持锁直到结束或超时。进程退出会释放锁；后继执行者把遗留 running 任务标为中断、允许用户重试，未开始的 queued 任务可继续。无需租约接管或过期 worker 仲裁。

公开状态收敛为已保存／排队／处理中／可检索／需处理／失败／已取消，处理记录保留 converting、indexing 等阶段。重试新建一次任务记录并更新目标 task_id；有界暂时重试可在一次任务内完成，不建独立 attempts 服务。执行前和发布前恢复真实主体、检查现行授权、配置、额度及资源执行条件，不持久化登录令牌。

转换器只读原件快照，在既有隔离临时目录写输出，不获知识根写权限。受控 Skill 提取 MD、附件和位置映射，后端验证非空、路径、完整性、容量并注入来源；上传正文／文件头不能改变权限。PDF 文本、DOCX 段落／表格、XLSX 工作表／公式与可得缓存值、CSV 行列、PPTX 页和 MD/TXT 均以真实样本验收。缺 OCR、加密、损坏或 partial 结果保留原件并明确失败／需处理，摘要不能替代正文。

### D6. 模式切换等待处理结束，不迁移运行中的任务

保留 set_knowledge_mode 的共享根本体守卫及 knowledge.own 暂存规则。在知识根之外使用简单的跨进程读写锁：所有知识文件操作取得共享的使用锁并在锁内解析根；转换任务从开始到结束持续持锁，相关文件／catalog 句柄在释放前关闭。排队任务虽未持锁，但有持久化状态。模式切换按稳定顺序取得受影响 Agent 和知识根的独占锁后再次检查队列；有 queued／running 转换、未完成提交或清理时返回 409 knowledge_busy，不改任何目录或模式。任务入队同样持使用锁，因此检查与入队不会穿插。

这是刻意选择的限制：长转换期间用户需等待、取消并等执行结束，或处理清理失败后再切换。超时必须实际终止解析子进程、释放文件资源才解除忙状态；UI 只提示和提供已有任务操作，不偷偷取消。停用／删除可以在 runner 持使用锁时更新 SQLite 生命周期，runner 发布前核对目标 task_id 和修订，不能复活删除内容。

空闲切换只需在工作区记录旧／目标模式、实际暂存目录和步骤的一个恢复标记；目录／链接按既有规则改动，成功后移除标记。异常或重启时在独占锁内按该标记完成或回退；标记未处理前知识入口返回暂时不可用，避免回落到错误共享库。恢复不扫描猜测目录，不创建第二套根注册服务。成功切换后清除 Agent 的 KnowledgeService 根缓存和知识索引同步标记；失败任务仅由当前有权用户重试，重新核验目标库，不自动跟随新路径。

### D7. 复用现有索引，新增内容只做增量适配

一个 eligible_documents 实现向目录、index.md、图谱、MemoryManager.sync 和工具读取提供：普通 MD + 当前 active_task_id 的转换 MD。原件、staging、控制目录和历史产物始终排除。直接按路径读知识也检查该集合；历史原件通过另行授权的来源接口查看。

转换产物使用含 task_id 的独立路径。runner 先用提交端现有 MemoryManager 的窄范围适配索引这一批候选 MD，显式确认所配置关键词／向量均完成；不调用会先删除旧文档的全量替换。同一缓存的同步、重建与候选发布使用一个索引写锁串行，避免候选写入至生效之间被清扫。候选片段带 knowledge_id/source/version/task_id，正常查询在 active 指针切换前过滤它们。成功后在来源事务内同时切换 active_task_id、标记任务完成并增加 revision；失败保留旧指针及旧片段，索引重试复用已验证 MD。这是单资料发布，不另建全库索引代。

共享库仍被不同 MemoryManager 缓存。每次知识搜索都比较当前解析的 knowledge_id/revision 与该缓存已同步值；不一致就用现有 sync 更新知识部分，成功并确认修订未再次变化后才记录同步值，不能只靠本进程 mark_dirty。普通 MD 通过应用入口增删改也增加 revision；宿主离线直接改盘继续按既有扫描机制处理。知识片段（含旧普通 MD）记录根身份，换库后过滤并清理旧根标签，个人记忆保持原范围。同步失败或持续变化时显式报告本次知识检索未就绪，只返回仍获准的非知识结果，不用旧知识缓存假装已同步。

资料的“可检索”表示提交端完成索引；另一个 Agent 首次查询可能需同步并受其实际索引配置影响，接口单独报告当前消费者状态，不承诺所有闲置缓存同时更新。查询返回前再次按当前生命周期／active 指针过滤，删除和停用不等待各缓存物理清理。

现有 /memory rebuild-index、独立命令仍重建各自原有索引范围，沿用原权限；只接入有效文档枚举、来源 metadata 和同步标记，不获得修改原件／来源关系的能力，也不新增库级维护调度。在现有索引 metadata 记录 provider／模型／维度／分块版本，查询前检查兼容性，无法确认或配置改变时显式关键词降级并提示按原入口重建；同维度不同模型不能混用。已有缓存配置不兼容时暂缓新的向量写入，提示先重建，不因一批新文档就把旧向量标为新模型。沿用既有重建失败提示及重试，不承诺整库无停顿重建；此限制不影响原件和引用的完整性。

### D8. 来源字段贯通，暂不管理人工衍生稿

MD 文件头导出 knowledge_id、source_id、version、task_id、原件哈希和受控来源链接；真实关系来自 catalog 中的 manifest。chunker 依据正文行区间携带 PDF 页、PPT 页、工作表／范围、CSV 行列、DOCX 章节或文本行号，没有可靠位置则文件级。

SearchResult、全文／向量结果、memory_search／memory_get 和聊天引用传递同一可选 provenance。来源接口按稳定 ID 和指定版本逐次授权；版本更新不改写旧链接，停用提示历史状态，删除显示不可用，无权用户不获正文或私有细节。原件活动内容不作同源可执行页面；无法安全预览时提供下载。不要为旧普通 MD 和个人记忆虚构来源。

转换 MD 只读，重新转换生成新产物。现有普通 MD 编辑功能不变；首期不新增“创建整理稿”按钮、自动多来源依赖追踪或整理稿失效／再发布机制，后续需要知识编辑治理时再设计。

### D9. 接口与阶段门槛

新增能力查询、sources 列表／上传／详情／版本／生命周期、资料内转换状态／重试／取消和 provenance 接口。基础 API 与 fork handler 共用服务及现行租户路由授权，异步接受不冒充同步完成。旧导入仍只处理普通 MD/TXT。

旧文档／分类／工作区写入口统一保护实际登记的 originals、converted、控制目录及祖先受影响子树，覆盖移动两端、覆盖、删除和符号链接别名；直接请求返回 409 managed_knowledge_path。只有受控来源操作可写，外部参数不得绕过；新开关关闭后保护继续生效。隔离脚本无这些目录的写权限，权限／路径检查与实际 I/O 使用同一根锁。

| 阶段 | 前置和验收 |
|---|---|
| A：兼容基础 | 目录预检、四类记录、所有扫描过滤、路径保护、模式忙状态／恢复和旧导入回归；两个新开关关闭 |
| B：原件保存 | A 通过；真实 IAM／private owner、限额／存储配额、审计、下载、上传故障恢复通过，启用 knowledge_source_upload_enabled |
| C：转换与追溯 | B 通过；真实 Skill 授权／隔离／计量、七种格式、串行恢复、索引增量发布、跨 Agent 同步、引用与 UI 通过，启用 knowledge_conversion_enabled |

两个开关默认关闭；总 knowledge 开关仍适用，智能体搜索不依赖新开关。验收复用现有依赖切片，不以占位或 mock 代替生产证据，也不借本 change 重建配额、审计、凭据和审批体系。

## Risks / Trade-offs

- **串行处理降低大批量吞吐、长任务阻止模式切换** → 首期接受，提供真实进度、取消及超时；有真实并发需求后再增加 worker 协议。
- **共享库另一 Agent 首次检索需要同步** → 每次校验 revision，失败明确不可用；换取不迁移现有检索架构。
- **文件与 SQLite 不能一次提交** → 少量提交状态、原子落盘、幂等恢复与现有额度结算，不引入通用补偿框架。
- **转换可能遗漏原件内容** → 真实样本和完整性检查，partial 不发布、原件可下载，不以生成摘要替代提取。
- **旧索引残留或旧路径接口绕过** → 统一有效集合、查询前过滤和集中写保护；功能回滚仍保留它们。
- **普通人工编辑稿无自动来源治理** → 不展示新整理稿入口或承诺依赖传播；本期追溯覆盖受管理转换正文与其引用。

## Migration Plan

1. A 阶段预检目录、登记 knowledge_id／schema；旧 MD 原位保留，不生成虚假原件。先给现有扫描和写入口接入保护，不移动索引数据库。
2. B 阶段开放保存；C 阶段先验证转换，再开放生产转换。首次访问旧知识缓存时按新根身份和有效集合同步，旧数据不可在同步前绕过过滤。
3. 备份知识文件、catalog 及存在的切换恢复标记；任务中断显示可重试，原件提交／清理记录按幂等步骤恢复。共享／独立切换仅在任务处理完毕后执行。
4. 回滚先关闭转换发布，再关闭上传，保留来源读取、写保护、扫描过滤和清理。退回不认识新目录的旧二进制时，停服将新增目录与 catalog 整体备份移出扫描范围并清退相关缓存；不能只关闭开关。
5. 文档说明串行／繁忙限制、每个消费者的同步状态及原有重建命令。归档前以实际实施证据核对任务，不将本次文档修订视为完成。

## Open Questions

解析依赖锁定版本、任务超时、轮询间隔和页大小可在实现时确定；目录归属、权限、串行执行、索引复用和模式繁忙策略已经确定，不再留给实现者临时选架构。
