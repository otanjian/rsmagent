- [x] 11.4 演练 A32 的在途/完成/unknown 回退，先停止新调用并核对在途效果，保留原文件、journal、历史与未知状态，不改投服务端。→ `tests/test_desktop_execution_broker.py::RollbackDrillTests`（**7 通过**，该文件 46 通过）先用**真实创建路径**造出三个命令（设备 claim → ack → prepare → start → heartbeat 全走真接口）：一个 `running`（带 journal 与 permit）、一个 `succeeded`、一个 `phase=outcome_unknown`。关掉开关后逐条核对：**新调用全封锁**（`prepare`/`start`/`heartbeat`/`status` 四条路径都以 `503 feature_unavailable` 拒绝，且在任何授权判断之前）；**一个都不删一个字都不改**（三张表在这些命令上的全部列关闭前后逐字段相等，含「被拒绝的调用不得顺手终止在途行」）；**在途效果与回执保留**（`journal_id`/`permit_id`/`started_at` 原样）；**重开后回答不变**（running 仍 running 且带「先看原文件与 journal、不要自动重跑」的 `reconcile`；succeeded 仍 succeeded 且**没有** `reconcile`；unknown 仍 `outcome_unknown` 且 `effects=unknown`）；**未知状态绝不被自动重跑**（连查两次 `status` 得到同样答复，行快照与 outbox 行数都不变——没有「补发一次」）；**降级客户端能解释**（meta 报 `disabled_by_deployment`，开关回来即恢复）；**不改投服务端**（开关关闭时既不委派，本进程又解析不到本机目录时 `run_local_cwd` 返回**拒绝**而不是某个服务器目录）。R8（委派不再看开关）/R9（解析不到就退回 `.`）两个变异正打在最后一行的两半上，都被抓。**边界**：原文件与设备侧 journal 在设备上、本进程碰不到，故主张严格限定为「服务器侧不删、不改、不补发，且不把工作改投服务器目录」；关闭开关时 broker 全部路径（含 `status`）一律 503 是**取舍**——让客户端立刻看到可解释原因，代价是关闭期间服务器侧也不回答，行本身没丢、重开即原样读回。证据 `evidence/release-gates.md` §四。
