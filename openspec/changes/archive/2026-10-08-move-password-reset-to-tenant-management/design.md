## Context

用户已明确：只在截图「当前租户管理员」卡片右侧增加账号启停和重置密码按钮。前版提出的全部用户目录、租户筛选、搜索分页与单账号读取均不再需要。

`_renderTenantCurrentAdmin` 已有卡片，`_loadTenantCurrentAdmin` 读取 `/api/platform/tenants/{id}/admins` 并展示第一项。该查询目前排除停用账号，且不返回账号版本；若只加按钮，停用后的账号会消失，无法在这里重新启用。

现有账号 PATCH 同时接收 `active` 和 `is_platform_admin`，遗漏后者会被 handler 当作 false。新按钮必须保留原平台资格。现有密码 POST 已实现重置规则，但前端结果被通用弹窗完成逻辑立即关闭，需要局部修正。

## Goals / Non-Goals

**Goals:** 在原卡片增加两项操作，停用后仍能找到同一账号恢复，保留平台权限及租户编辑草稿。

**Non-Goals:** 不新增账号目录、搜索分页、账号详情 API 或角色维护；不改管理员选择表单、不统一三个历史重置入口、不重构认证或弹窗框架。成员页既有版本问题不在本次范围。

## Decisions

### 1. 只补足现有卡片的数据

扩展现有管理员读取的白名单，增加 `account_active`、`account_version`、`is_platform_admin`；使用同一条账号记录的状态、版本及既有平台资格投影。账号标识继续使用 `user_id`。

管理员绑定查询仍要求成员关系有效且持有 `tenant_admin`，但不再用 `u.active=1` 排除停用账号，按原绑定时间排序。卡片仍只展示最早绑定者，并标明其账号状态；这使一次成功停用后刷新页面仍定位同一账号。该接口目前只有租户卡片这一处生产调用，直接更新读取契约及相关测试即可，不加兼容开关或新的 API。

`_count_valid_tenant_admins` 及写入服务的有效管理员检查不改，停用账号只在管理卡片中可见，不成为有效管理员。成员关系已停用或管理员角色已移除的账号不保留在卡片中。无管理员、新建未保存或读取失败时，不显示可操作按钮。下方账号选择器的未保存选择不是卡片按钮目标。

### 2. 两个按钮复用原账号写入

卡片右侧水平放置「停用账号/启用账号」「重置密码」，窄屏允许换行。仅平台管理员可用，操作对象显示登录名；确认说明账号启停/改密影响该账号的所有租户，复核操作者本次密码。

| 操作 | 复用请求 |
| --- | --- |
| 启用/停用账号 | `PATCH /api/platform/users/{user_id}`，提交目标 `active`、原 `is_platform_admin`、`expected_version=account_version` 和 `recent_password` |
| 重置密码 | `POST /api/platform/users/{user_id}/password`，提交账号版本及操作者密码 |

不提供平台管理员资格编辑控件；不能只提交 `active` 而漏传平台资格。版本冲突提示重新读取，不能自动换版本重试。最后有效管理员保护、启用账号须有有效租户归属、会话撤销、本人重置拒绝等均沿用原接口，不为了按钮可点击而放宽。尤其目标为最后一名有效管理员时，停用会被拒绝，界面提示先配置其他管理员。

操作独立于底部「保存」。成功后只重读卡片，更新状态及版本，不提交或重建租户表单。切换租户编辑对象后不应用旧响应；请求期间禁用重复操作。账号状态变更不改成员启停、租户启停或角色绑定。

### 3. 局部修复临时密码展示

复用原平台账号重置弹窗，将需要的账号对象和刷新回调参数化。使用已有 `afterSuccess` 展示可查看和主动复制的结果，避免刚写入密码就被通用提交关闭；不新增通用状态机。本人提示使用本人改密。

结果关闭、离页、切换编辑目标或身份时清空密码 DOM/引用，不写 storage 或日志。卡片刷新失败单独提示，不能覆盖已经成功返回的密码。服务端密码规则、审计与现有认证处理保持。

### 4. 隐藏菜单而保留维护页

删除侧栏 `platform` 行。现有控制台快捷入口由侧栏 DOM 生成，会同步移除；检查其他实际存在的派生入口即可。保留视图注册、页面内容、`/platform` 和平台 API，不撤掉与租户页共用的 `admin.tenants` 资格。

兼容维护页继续显示原标题和面包屑，不错误选中其他菜单；该例外仅针对这个隐藏入口，不扩大为导航改造。

## Risks / Trade-offs

- [停用后卡片消失] → 展示已绑定但账号停用的管理员，保留原排序；实际有效管理员判断不变。
- [启停时意外撤销平台资格] → 按同一账号版本提交原 `is_platform_admin`，增加针对性测试。
- [最后管理员不能停用] → 保留已有拒绝并说明原因，不改变管理员连续性规则。
- [按钮影响租户草稿或另一个账号] → 固定卡片 `user_id`，独立提交和局部刷新，核对编辑目标。

## Migration Plan

先验证管理员读取与账号状态字段，再接入按钮、结果展示和菜单隐藏，一次验收交付。只需本次相关后端/前端测试及原启停/重置回归，不重新建立身份验收工程。

无数据库迁移、新角色或新增 feature flag；验证既有 classic/split 两种呈现。使用测试账号验证停用、刷新后启用、重置和最后管理员拒绝。回退使用兼容代码版本，不回滚已提交账号状态/密码或恢复已撤销会话；保留 `/platform` 作为维护入口。
