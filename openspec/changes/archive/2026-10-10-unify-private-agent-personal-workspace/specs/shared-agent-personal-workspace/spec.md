## MODIFIED Requirements

### Requirement: 共享普通智能体默认使用本人业务目录

已认证用户使用共享普通 Agent 或本人私有普通 Agent，且没有现有项目解析返回的有效项目时，默认业务工作目录 SHALL 为 `<agent workspace>/user/<不可变用户ID>/`。有有效项目时 SHALL 继续优先使用该项目，清除项目后 SHALL 回到本人默认目录；外部 coding 和本机项目保持原有行为。个人默认目录 MUST NOT 被登记为用户选择的项目，也不进入项目最近记录。`work/` 仅为临时处理子目录，不替代本人目录成为默认 cwd。

目录归属 SHALL 由经验证的租户、用户和宿主 Agent 决定，私有 Agent 还须验证当前用户为真实 owner；客户端/模型自报 owner 或显示名 MUST NOT 改变落点。尚未创建业务 session 的已登录请求 SHALL 能展示相同默认目录。未知身份、无权 Agent 或他人会话继续按既有规则拒绝，不猜测 owner。

新建和存量普通 Agent SHALL 使用同一目录规则，不依赖布局版本或启用记录；旧业务文件按 `agent-work-file-layout-migration` 在维护窗口内整理。带可信用户上下文的后台任务 SHALL 使用相同目录解析；机器主体 MUST NOT 通过读取私有 Agent owner 冒用成员身份。

#### Scenario: 两用户共享同一智能体
- **WHEN** A、B 分别在共享 Agent X 的无项目会话中生成相对路径 `报告.txt`
- **THEN** A 的文件默认位于 X 的 user/A，B 的文件默认位于 user/B，互不覆盖对方文件

#### Scenario: 查看默认目录并选择清除项目
- **WHEN** A 在首条消息前查看默认目录，随后选择本人项目 P，再清除项目
- **THEN** 默认值始终为 X 的 user/A；选中项目时使用 P，清除后使用 user/A，个人默认目录不成为项目记录

#### Scenario: 伪造归属或使用私有 Agent
- **WHEN** A 伪造 B 的身份定位目录，或正常使用 A 本人的私有 Agent
- **THEN** 前者不能定位到 B 的个人目录；后者默认使用该私有 Agent 的 user/A，私有使用权限保持

#### Scenario: 私有 Agent 的可信用户后台任务
- **WHEN** A 的后台任务携带经验证且仍有效的租户、用户和目标 Agent 上下文运行
- **THEN** 无有效项目时使用该 Agent 的 user/A，身份失效则拒绝，不借服务进程或私有 owner 字段推断身份

#### Scenario: 外部 coding 和本机项目
- **WHEN** 用户进入外部 coding 或已授权本机项目执行
- **THEN** 保持该入口原有目录和实际执行位置，不构造服务器用户目录替代本机路径

### Requirement: 目录提示与会话执行一致且保持配置来源

共享普通 Agent 及私有普通 Agent 的默认目录提示、正常打开的文件面板位置，以及当前会话原生文件/Shell 工具的业务 cwd SHALL 指向同一有效工作位置。本轮路径提示 SHALL 与实际 cwd 一致；浏览共享资料或文件面板有提示地回落到其他获权位置 MUST NOT 自动改变会话执行目录。

工作位置切换 SHALL 仅作用于当前会话，MUST NOT 改 Agent Profile 或进程级 cwd，不得污染其他用户会话。受邀普通 Agent 和子任务 SHALL 沿用已有宿主/父任务目录继承关系。Agent 设定、技能、知识、MCP、会话存储及个人记忆 SHALL 保持既有来源，个人业务目录中的同名文件不能自动替换这些配置。

#### Scenario: 读取共享模板并生成本人文件
- **WHEN** A 使用获权共享模板和技能生成相对路径文档
- **THEN** 资源从原来源读取，文档写入 A 的有效工作目录，目录提示一致，共享配置不复制进个人目录

#### Scenario: 并发会话互不改目录
- **WHEN** A、B 同时使用 X，A 为后续会话操作选择项目或刷新面板
- **THEN** B 的 cwd 不变，刷新不重定向正在执行的任务，已授权的目录应用仍按既有会话时机生效

#### Scenario: 客座 Agent 与子任务处理现有文件
- **WHEN** A 在 X 的会话中让受邀普通 Agent 或子任务处理本轮文件
- **THEN** 继续使用宿主/父任务的有效目录，自身能力配置和权限保持原规则

#### Scenario: 本人业务目录中存在同名配置文件
- **WHEN** A 的私有 Agent 本人目录内含 `RULE.md` 或 `skills/` 等同名内容
- **THEN** 这些内容保持业务文件身份，不替代 Agent 原配置与技能来源

### Requirement: 新文件引用按实际工作位置定位且不重写旧数据

新回复和工件中的相对业务路径 SHALL 按本轮实际执行目录解析，并通过既有消息/工件记录保留明确定位。SSE、轮询、预览下载及新消息重放 SHALL 对应同一文件，之后切换项目或重开会话不能把已生成文件定位到新目录。文件面板及 `@` 的选择 SHALL 保留文件服务返回的明确定位，并继续校验实际归属；搜索范围不因个人 cwd 改变而扩大或收窄。

旧文件在未执行受控迁移时 SHALL 保持现有存储与授权处理；符合 `agent-work-file-layout-migration` 的迁移 SHALL 保留历史消息正文、业务标识和原文件内容，通过受保护的单跳路径映射兼容已保存的明确引用。缺少原始基准的旧相对文本 MUST NOT 被新 cwd 下的同名文件冒充；无法定位的历史文本按既有缺失处理。

默认目录 SHALL 只表示业务工作位置，不扩大任何权限。本能力 MUST 保留现有文件 owner 与执行授权规则，不新增脚本沙箱或关闭原已获权执行入口，也不得宣称目录统一已实现同租户任意脚本直接读盘的用户隔离。离线迁移期间按迁移契约停止相关服务，不新增在线准入机制。

#### Scenario: 新文件通过不同返回方式打开
- **WHEN** A 生成相对路径图片/文档，经 SSE 或轮询收到结果，之后切项目并重新打开该消息
- **THEN** 图片、预览和下载仍定位原生成文件，B 使用其私人链接仍按原 owner 规则被拒绝

#### Scenario: 引用共享文件及读取旧附件
- **WHEN** A 从文件面板或 `@` 选择获权共享文件，或打开旧的绝对附件链接
- **THEN** 使用原文件的明确定位与授权；已迁移附件经受控映射定位原内容，不将其重解释为个人 cwd 下同名文件

#### Scenario: 已获权脚本保持执行规则
- **WHEN** A 在共享或私有 Agent 下运行原已获权的 Shell 或技能脚本
- **THEN** 默认 cwd 使用本人目录，执行入口和边界仍按原规则；验收不把 cwd 变化当作新的用户级沙箱
