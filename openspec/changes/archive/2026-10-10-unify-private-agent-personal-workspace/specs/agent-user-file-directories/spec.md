## MODIFIED Requirements

### Requirement: 共享智能体按真实用户保存平台文件

租户共享 Agent 及私有普通 Agent 的平台上传和回传结果 SHALL 保存于其工作区的 `user/<不可变用户ID>/`，该用户来自已认证的当前租户身份。账号名称仅用于展示，客户端或模型自报 owner MUST NOT 决定落点；无可信用户、租户/Agent 冲突或会话属于他人时 MUST 拒绝平台文件写入及私人链接生成，不回落共用上传目录。用户目录 SHALL 与 Agent 配置分开，MUST NOT 修改进程级 cwd 或共享 Profile 来临时切换用户。私有 Agent 同时要求当前用户为真实 owner，统一布局不扩大任何读取、使用或维护权限。

上传、交付结果及临时文件 SHALL 分别使用本人目录下的 `uploads/outputs/work`，业务子目录保留原相对结构。该目录 MUST NOT 与共享根下跨 Agent 的 `users/<user_id>` 个人数据域混淆。存量私有对象按 `agent-work-file-layout-migration` 在维护窗口内整理旧业务文件；已保存于本人目录的上传保持原位置，不新增运行时布局状态。

#### Scenario: 两用户上传及回传同名结果
- **WHEN** A、B 在同一个租户共享 Agent 中上传同名文件，平台分别回传生成结果
- **THEN** 文件分别进入 user/A 和 user/B 的相应子目录，不覆盖他人文件，返回链接对应真实发起用户

#### Scenario: 改名或伪造用户
- **WHEN** A 修改账号显示名，或请求携带 B 的 owner 字段
- **THEN** 改名仍使用 A 的原用户目录，伪造 B 的落点被拒绝，不转移文件归属

#### Scenario: 无会话上传与后台身份缺失
- **WHEN** 已登录 A 尚无业务会话就上传，或后台结果没有可验证的原始用户
- **THEN** 前者归 A；后者不发布私人文件或共用下载链接，不能靠服务进程身份猜测 owner

#### Scenario: 私有 Agent 的上传与交付结果
- **WHEN** A 使用本人的私有普通 Agent 上传文件并接收交付结果
- **THEN** 文件分别保存在该 Agent 的 user/A/uploads 与 user/A/outputs，B 及非 owner 管理员不能因同租户或管理资格访问

### Requirement: 旧文件兼容不猜测用户归属

启用前 SHALL 检查预留 user 目录及旧上传/平台结果。存在名称冲突时停止该 Agent 的文件布局切换，不覆盖原目录。已知 owner 的旧文件 SHALL 依据可信会话/上传记录迁入本人目录并更新或映射原引用；未知/冲突归属保留在不可经普通文件接口读取的位置，不能分给当前访问者或全部用户。迁移 SHALL 保留内容及业务标识，支持从清单重复执行；旧私有 token/公开副本不得继续经平台链接开放。

私有普通 Agent 的统一布局迁移 SHALL 进一步覆盖根目录业务文件、业务子目录和回收站；分类、切换与恢复遵循 `agent-work-file-layout-migration`，不能根据当前 owner 猜测全部历史归属，也不能搬移配置、会话和记忆来凑成统一目录。

#### Scenario: 已知归属与迁移中断
- **WHEN** 旧文件可唯一关联 A，迁移中断后按原清单重跑
- **THEN** 内容验证后只生成一个目标，原会话可通过本人鉴权引用访问，B 不能用旧路径读取

#### Scenario: user 名称冲突或未知 owner
- **WHEN** 预留 user 路径已有不兼容内容，或旧上传无法证明归属
- **THEN** 冲突不自动覆盖，未知旧文件不经普通文件接口开放，源数据保持可恢复

#### Scenario: 私有根业务目录和既有用户上传并存
- **WHEN** A 的私有 Agent 同时有根目录业务报告与已经位于 user/A/uploads 的上传
- **THEN** 仅迁移已确认归属的旧业务内容并保留相对结构，现有用户上传原地保持，不递归搬移配置、会话或记忆
