## Why

私有智能体的默认执行目录与文件面板仍在 Agent 根，而已认证用户的上传已经进入 `user/<user_id>/uploads`。将普通私有智能体接入共享智能体已有的个人工作目录机制，使上传、执行和浏览位置一致，并减少两套目录分支。

## What Changes

- **BREAKING**：普通私有智能体无有效项目时，与共享普通智能体一样使用 `<agent workspace>/user/<不可变用户ID>/`；有效项目继续优先，默认目录不登记为项目，`work/` 仅作临时子目录。
- 复用目录 helper、会话 cwd、项目响应和用户目录准备接口，同步文件面板落点；Agent 配置根、知识技能、会话记忆及凭据位置不变。
- **BREAKING**：私有智能体的面板拖拽上传、删除及回收站恢复，采用共享智能体现有的本人目录范围。文本编辑与配置维护继续走原鉴权，不新增一套编辑权限或维护接口。
- 新建与存量对象运行同一规则，无布局版本、按 Agent 启用状态或新增 feature flag。升级在维护窗口完成，不混跑两套默认目录。
- 保留旧文件整理：扩展现有脚本，停止相关服务、调度、在途任务和其他写入者后，按可信归属与显式业务文件清单离线迁移；保留相对结构、摘要、冲突报告和备份，不搬整根、不猜测归属。
- 已移动文件的旧附件通过受保护的单跳路径映射兼容并重新鉴权；离线更新回收站恢复位置。映射不参与普通会话启动或新文件写入，不引入数据库、在线状态机、跨进程写租约或自动降级框架。
- 可见性转换沿用既有动作和权限；用户子树不转让、不自动公开，复制不带用户工作文件。外部 coding、本机项目及实际执行位置保持原契约。

## Capabilities

### New Capabilities

- `agent-work-file-layout-migration`: 维护窗口内的一次性文件迁移、有限旧引用兼容和基于备份的恢复，不是在线迁移服务。

### Modified Capabilities

- `shared-agent-personal-workspace`: 将本人默认业务目录扩展到普通私有智能体，保持项目优先、配置来源与历史定位规则。
- `agent-user-file-directories`: 将共享智能体已有的用户文件布局明确应用到私有智能体，衔接离线迁移。
- `platform-file-browsing`: 统一面板落点以及现有上传、删除和回收站的本人范围，保留原编辑与配置维护授权。
- `user-private-agent-management`: 明确新建/复制使用统一目录、转换不转让个人文件，不新增生命周期登记或转换门禁。
- `agent-workspace-scaffold`: 工作区说明反映配置根、user 工作文件与跨 Agent 的 users 个人数据域的区别。

## Impact

- 核心接入：`personal_default.py`、既有 `state_dir` helpers、Bridge/cwd、`fork/runtime.py`、`fork/handlers/workspace.py` 和 `static/js/workspace.js`；旧引用在现有解析链补一个共用 helper。
- 数据唯一归属：身份服务仍决定租户/owner，文件仍在 Agent 工作区；迁移只产生受保护清单、单跳路径表及备份，不新增数据库、身份字段或布局状态。
- 接口：沿用项目、文件和维护 API；改变目录值及面板上传/删除范围，不引入布局代际协议。
- 依赖：复用现有文件、执行授权、审计与配额机制，验收受影响路径，不重新交付整套治理能力。保持正在进行的 Web/桌面 change 的接缝，不依赖其整份完成。
- 发布取舍：接受一次维护窗口，避免为不停机迁移改造全部运行/写入入口。真实迁移只在明确目标范围内执行；产物完成不代表功能或生产迁移已经完成。
