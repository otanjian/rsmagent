## Context

2026-10-10 复核发现，原稿把目录统一扩大成了在线迁移系统。此次修正保留统一目录与存量迁移目标，精简长期运行机制。

| 原稿问题 | 代码依据与修正 |
| --- | --- |
| 独立数据库、布局版本与七态流程 | `agent_user_root` 已能服务两类 Agent；运行时采用同一规则，无需另一份启用状态 |
| 全链路跨进程写锁与调度准入改造 | 未要求零停机；改为停止写入后的离线迁移 |
| 将文本编辑一起收窄并重接配置维护页面 | `_write_scope` 用于上传/删除/恢复，`WorkspaceWriteHandler` 另用 `_editable_target` 支持获权编辑；仅统一前者 |
| 创建和转换必须登记布局与检查就绪 | 目录可从可信身份直接计算；生命周期复用原流程 |
| 映射代际、在线回滚与自动降级框架 | 限本次迁移的单跳表，回收站离线更新，恢复使用清单与备份 |

`personal_default_dir` 当前排除私有对象；Bridge 已有会话 cwd 覆盖；上传已进入本人目录；面板和 `_write_scope` 保留私有根分支。现有迁移脚本只覆盖 tmp/uploads/outputs，计划阶段还可能建目录，需要小范围扩展。以上为静态核查，尚未实现本 change。

## Goals / Non-Goals

**Goals:**

- 获权普通 Agent 使用同一默认业务目录，项目和配置来源不变。
- 对齐面板上传、删除和恢复的本人范围，保留原归属与配置维护能力。
- 在维护窗口内整理旧文件，兼容明确旧附件和回收站恢复位置。

**Non-Goals:**

- 不建设在线迁移、按 Agent 灰度布局、数据库账本、写租约或自动版本降级系统。
- 不重构文本编辑/配置维护权限，不新增文件操作，不调整 Shell 的授权范围。
- 不移动知识、技能、会话、记忆、凭据或本机项目，不新增跨端同步与执行隔离。

## Decisions

### D1. 扩展现有解析器，不增加运行状态

复用 `agent_user_root`，让 `personal_default_dir` 接受共享普通 Agent 和当前用户自己的私有普通 Agent。真实身份、租户、私有 owner 和类型校验在前；已知无权或路径不安全时拒绝，不能回落根。保留 `is_tenant_shared_agent` 原含义。

默认 cwd 为 `<workspace>/user/<uid>`，其下使用 uploads/outputs/work 和业务子目录。Profile、配置来源与共享根下的 users 数据不变。新建和存量同规则，无布局开关或登记；已有授权准备接口按需建目录，只读投影不建目录。

有效项目优先，清除后回本人目录；显式越权项目仍拒绝。受邀 Agent/子任务继承宿主目录，可信用户后台任务沿用原身份；无用户机器调用保持原契约，不能推断私有 owner。不改进程 cwd。

### D2. 面板与现有操作范围同步

调整现有默认空间/会话根解析、`wsOwnUserDirPath` 和面板落点，使私有对象进入本人目录；优先复用现有 `default_workspace`、服务根及获权目录信息，不增加布局状态/代际协议。项目和 Desktop 本机来源优先，原有权限回落最多一次且只改变面板范围。

`_write_scope` 对两种普通 Agent 返回本人目录，沿用上传、删除及回收站目标校验和冲突处理。`WorkspaceWriteHandler` 的 `_editable_target`、正式知识/技能/记忆维护和原生工具权限保持原规则。目录统一不要求取消既有配置编辑能力；只做调用链回归，不新建“业务编辑/配置编辑”接口体系。

### D3. 离线整理替代在线迁移平台

升级采用维护窗口：停止相关 Web/Channel/调度进程及外部写入者，等待在途工作结束并备份。仅停用 Agent 不阻断所有文件接口，不能作为停写依据。命令声明离线前提并检查已知占用，不能确认无写入时不执行；接受停机成本，不新增全链路锁。

扩展现有脚本，支持显式工作区与业务候选清单。预检只读，根据真实配置位置排除核心文件、能力实体和运行状态，依据可信会话/上传记录确认 owner。曾共享或混合内容不能只凭当前 owner 分配；未知分类/归属、user 冲突和目标冲突先处理，未解决不完成升级，不递归搬整根或自动隔离全部未知文件。

源到目标保留相对结构。普通 JSON 清单记录租户、Agent、源/目标、归属证据、摘要与结果，作为运维记录，不是运行时状态。执行前重验源，不覆盖不同内容；重跑以实际摘要确认已完成项。同工作区迁移限定同文件系统，挂载点/跨设备明确拒绝，由运维先处理，不增加跨设备搬移引擎。

备份和清单放现有受保护运维目录，避开可浏览工作区及脚本获权根。可信回收站条目的恢复目标在离线阶段更新并备份原元数据，不改变恢复协议。具体脚本/任务的硬编码旧路径列入预检，经原维护方式修复，不承诺分析任意程序。

### D4. 保留必要的旧附件兼容

搬文件后旧附件仍需定位。迁移命令生成按租户/Agent 隔离的“旧绝对路径 → 新绝对路径”单跳 JSON 表，保存在受保护应用数据位置；无迁移对象不需要表，普通新会话和目录解析不查询它。

在已有工件/文件解析链增加共用 helper，仅处理明确命中的旧引用，覆盖历史工件、旧预览下载和附件关联资源。重验源资源范围、目标 owner 与当前资格，维持私人响应；目标限定同一 Agent 的本人目录，不允许链式映射、客户端映射或跨 Agent 重定向。

旧路径再被占用、映射损坏或无法确定引用时，相关旧附件报冲突/缺失，不读取同名替代物。缺少原 cwd 的相对文本不猜测，原消息正文不批量替换。映射故障只影响相关旧附件，不阻断新会话。HTTP 兼容不代替脚本路径修复。

### D5. 生命周期维持现有规则

新建、复制和系统供应助理无需布局登记，首次准备时直接使用本人目录。检查现有复制白名单不带 user 树、业务文件和回收站，必要时补排除项。

可见性转换不移动工作区根与用户子树；双方默认 cwd 都按当前获权用户计算。新 owner 不获得他人文件，原用户失去 Agent 资格后不能只凭文件 owner 访问。旧业务文件在升级前处理，转换入口不再读取迁移状态、扫描整根或隐式搬文件。

## Risks / Trade-offs

| 风险/代价 | 处理 |
| --- | --- |
| 需要维护停机 | 明确停写、备份、迁移、抽验和重启顺序，不承诺零停机 |
| 归属/分类含混 | 明确清单与可信记录，先解决含混项，不按当前 owner 猜测 |
| 相对路径基准改变 | 验证 cwd、项目、技能资源，标明 BREAKING，修复具体脚本依赖 |
| 旧附件/回收站定位 | 单跳附件映射、离线更新恢复位置，保持原鉴权 |
| 配置维护回归 | 仅对齐现有上传/删除/恢复范围，文本编辑与维护权限不重构 |
| 恢复不能自动合并新旧数据 | 先保留当前数据，冲突人工处理，不以旧快照覆盖新文件 |

静态估算为 2～4 人日开发与回归；真实迁移耗时、停机与含混数据处理由预检决定。

## Migration Plan

1. **实现与验证：** 在临时数据上实现解析/面板和离线命令，核验受影响的文件、身份、项目与执行依赖切片；无需重新交付整套治理能力，不开启原未获权执行入口。
2. **升级预检：** 确定工作区与业务清单，解决归属、分类和路径冲突，修复具体硬编码依赖并核对备份空间。无旧数据的新部署直接采用新规则。
3. **维护窗口：** 停止相关写入服务及任务，备份工作区和受影响元数据，重验后执行同文件系统迁移，生成单跳表并更新回收站；失败保持停写，按清单重试或备份恢复。
4. **恢复服务：** 校验摘要、原配置、默认目录、典型旧附件和回收站，再部署/启动一致版本的前后端，不混跑两套 cwd；含未解决项不宣告完成。
5. **回退：** 停服务并先保存当前数据与映射。上线前失败可按清单反向移动或恢复备份；上线后已有新增/修改则先保留它们、人工解决冲突，不能覆盖旧快照。恢复一致的数据与代码后重启，不新增自动降级守护服务。活动附件依赖的映射继续保留。

## Open Questions

- 实际工作区数量、数据量与维护窗口由预检确定。
- 备份位置/保留期限沿用运维策略；活动路径映射不能随备份到期清理。
