## Goals / Non-Goals

**Goals:**

- 用户看到的 SAP 页面与 OpenCode 工具操作对象一致，可手动操作、暂停、接管后继续。
- 改动集中于新场景、其独立部署组件及必要注册，保留 `normal`/`coding` 及已有入口契约。
- 新场景所有资源和操作都有可校验的用户、租户、会话归属；断线/重试不能串会话或重复保存。
- 本轮提供已登记的不保存页面能力及独立实现验证，支持范围按对应版本的实际证据声明；后续完整目标为一条真实测试系统中的页面导航、单据输入、校验、受控保存及单据号核对流程。本轮不执行被暂缓的实际操作检查，也不开放提交。

**Non-Goals:**

- 不新增 `sap`/`web_operator` 类型，不修改普通智能体执行器、通用 browser 工具、调度或渠道。
- 不重写 OpenCode 模型循环、历史正文、全局 MCP/插件体系；不重构现有 SAP 数据分析场景。
- 不承诺 SAP 全部交易/主题/版本通用，不将 ADT/RFC 写入冒充可见页面操作。
- 首版不做原生 SAP GUI for Windows、桌面本地浏览器接管、浏览器扩展或 WebRTC 媒体平台。

## Decisions

### 0. 当前原生配置与 SAP智能助手交互

- 原生实例加载相同 HOME/XDG 与 OpenCode 配置查找入口，按配置选择默认模型/agent，保留项目 agent、MCP、技能、命令及原生权限交互。项目目录仍来自 coding 配置。已有项目四个 OpenSpec 技能及 `/opsx-*` 命令直接发现，CLI 沿 PATH 使用；不维护第二份技能。
- 只覆盖 `OPENCODE_DB`，恢复原工作台会话 ID 和消息。启动时只读原生全局数据库，将 provider 的 `credential` 记录继承到私有库，不复制会话或正文；已继承凭据随来源轮换/删除更新，私有实例主动修改的连接保留，不回写全局库。凭据和同步索引只在私有目录保存，权限为 0600，不进入日志、项目或浏览器。旧场景强制的 `sap` agent/provider 若原生配置中不存在，迁移到原生默认；原生用户已选模型/agent 不重置。私人监听器使用随机 Basic 服务凭据，由已验证所有者的场景网关注入，不提供浏览器直连凭据。
- 网关转发原生会话、模型/agent 切换、配置、权限确认、文件、终端和 WebSocket API，不再固定模型列表或把 native prompt 裁成纯文本。Native 子会话、分叉、项目导航不解除工作台；它们仍在该私有实例内，不取得旧场景浏览器自动控制租约。旧画面模式保持原限定路径。
- 当前 Web/CLI 构建存在元数据差异：只适配默认模型查询、metadata 与事件形状；默认模型读取原生合并配置，不代替模型目录。界面样式由场景返回 HTML 注入，不改 OpenCode 源码或构建。
- 标题为「SAP智能助手」。隐藏 OpenCode 内部顶部空白工具栏（含右侧复核切换按钮）及移动紧凑布局的「会话／更改」页签，不禁用其后端或其他工具。点击「全屏」让右侧区域占满浏览器内容视口，标题栏保留「还原／收起对话」；还原回并排布局。只改变布局，不重新挂载 iframe、建立会话或请求模型；SAP iframe 保留。宿主 Escape 依次还原、收起、退出，iframe 内按键由原应用处理。
- 并排布局的 6px 分隔线支持指针左右拖动、方向键 24px 微调和 Home/End 边界定位；两侧至少保留 320px。拖动期间暂时禁用 iframe 指针事件，结束/取消后恢复；全屏隐藏分隔线，还原保留之前宽度。窄屏使用上下布局并隐藏拖动手柄。调整不重建 iframe 或请求模型。
- 后台进程沿原环境重载，保留主密钥、配置及数据库。原生模式不是生产多用户执行沙箱，不能复用旧工具限制的生产验收结论；未完成阶段继续记录在任务中。验证见 [原生配置和全屏](evidence/native-config-fullscreen.md)。

### 1. 场景负责组织页面，OpenCode 负责对话执行

新增 `Scene/sap_workbench/`，建议包含 `scene.json`、`frontend/`、`backend/`、`browser_service/`、`opencode_adapter/`、`skills/`、`deploy/` 和使用说明；测试按现有测试目录惯例独立命名。场景使用已有 `data` 分类，展示「SAP 工作台」，与「SAP 数据分析」并列。

场景绑定已有的、当前租户可用的 `coding` 智能体配置，复用 OpenCode 会话服务的身份和项目检查。该配置只登记默认项目、服务与业务用途，不承载 SAP 登录态。新增配置不改变任何现有默认智能体，不自动复制用户的 `sapwork` 或业务数据。

不调用普通 `POST /api/scenes/activate`，不向普通会话写 greeting，不通过打开页面调用模型。SAP 业务指引在 OpenCode 的专用助手/技能配置中提供，经实际工具路径验证；创建页面本身只准备资源。

普通卡片、选择器和直达分发以 `{view: 'new-session'}` 调用场景挂载器，配置及可视能力就绪后直接执行现有新建接口；「配置」仍使用 settings，不创建会话。单独的普通 open 保留准备页，恢复入口继续显式区分。配置加载返回是否成功应用，迟到或失败结果不能创建；创建中/已绑定的重复普通入口忽略，不改当前 iframe、画面或控制状态。只在共享 adapter 的 SAP 分支增加该参数，其他场景不变。

取舍：新增类型会牵涉类型枚举、普通路径排除和历史路由，而此处已有 OpenCode 引擎；两个裸 iframe 则只有展示能力。选择场景加执行桥可隔离新增业务并复用已有引擎。

### 3. SAP 主界面与页内嵌入式 OpenCode 对话

SAP 页面在对话收起时占满工作区，右下角提供「AI 对话」按钮。展开后 SAP 与 OpenCode 左右并排，共同填满工作区，对话不覆盖 SAP。会话创建/恢复沿原接口完成，现有 iframe 在绑定就绪后挂载并默认隐藏；展开/收起只切换展示与 inert 状态，不重新提交 bootstrap、不更换目标、不调用模型或改变自动控制。工作台关闭、进入配置或结束会话仍按原路径暂停及卸载；host 重建时使用新授权重新挂载，保留当前展开状态。

对话区域在正常文档流中占据 32vw、限定 360–560px 的宽度，铺满工作区高度，无外边距、圆角或阴影；720px 及以下改为上下排列，各占一半可用高度。展开时隐藏右下角按钮，通过头部按钮收起；SAP 页面保持挂载并随分配空间调整布局。按钮声明 aria-controls/aria-expanded，收起后的面板不可聚焦，展开焦点进入收起按钮，收起返回按钮。工作台内 Escape 优先收起面板；iframe 内键盘继续由 OpenCode 自身处理，不跨域拦截。

本次页内布局仅改 `frontend/workbench.css` 和对应资源摘要，既有 `frontend/workbench.js` 挂载、收起和会话逻辑保留，不增加后端接口或 OpenCode 核心接缝。当前 Chrome 页面通过样式热更新验证左右布局、收起与 iframe 保留；本次不发送模型消息或操作 SAP 业务，真实工具检查继续暂缓。

工作台外层覆盖浏览器可用视口，使用固定定位、零外边距与零圆角。2026-10-04 全视口调整只涉及 CSS 和对应资源摘要；SAP 画面保持原比例及坐标映射，右下角浮动对话仍嵌在工作台内，不请求操作系统全屏。实际 Chrome 恢复原登录会话后的验证见 [全视口布局](evidence/fullscreen-workbench.md)。

后续按用户红框要求，绑定会话时隐藏工作台标题、状态栏、会话操作栏、SAP 区域标题和画面控制栏，移除主区域内边距与边框，让 SAP 画面容器覆盖整个视口；仅保留 SAP 画面及右下角嵌入式 AI 对话。通过既有 `data-live=true` CSS 条件限定会话视图，配置与未绑定准备页仍可使用；Escape 退出和控制权逻辑保留。此次仍只修改 CSS 和资源摘要，见 [纯画面布局](evidence/content-only-workbench.md)。

SAP 页面视口随工作区尺寸同步：ResizeObserver 和 WebSocket open 触发 120ms 合并上报，尺寸为有界整数（每轴 1..4096，超大窗口同比缩小），隐藏或未连接时不发送。场景网关将 resize 与人工输入分开，BoundScreen 重新授权并在布局变化时撤销旧自动操作租约，专属 Chrome 通过设备视口设置让 SAP 重新布局；后续画面元数据更新 canvas 和点击坐标。收起对话不改变主区域大小，关闭和重连清理旧 observer。该修复仍为画面流，不等同 SAP 原生 iframe，见 [尺寸同步证据](evidence/responsive-sap-viewport.md)。

首版选择独立执行节点上的有界浏览器运行单元：Chromium 的真实有头页面、独立显示会话、VNC/WebSocket 桥与 noVNC 前端；页面动作由 Playwright 或匹配版本的浏览器控制通道执行。版本在 G0 实测后固定，运行镜像/依赖单独放在场景部署目录，不加入主服务的默认启动必需项。

主工作区显示这个浏览器的实时交互画面，浮动面板的 OpenCode 页面工具绑定同一个 browser/target。SAP 原站作为该浏览器中的页面加载，平台不依赖跨域读取 SAP iframe。保留正常的 SAP、证书和登录校验，不通过移除安全响应头、关闭浏览器安全机制实现嵌入。

执行节点必须能访问登记的 SAP 与 SSO 地址；SAP 仅在企业内网时节点部署于内网。用户本地浏览器中的 SAP cookie 不会自动迁入，用户在左侧重新登录或完成已验证的 SSO。弹窗属于同一受控浏览器会话；不选择“第一个页面”或借用另一会话。

桌面端加载同一个 Web 场景。首版不触及 Electron 主进程或新增本地执行模式，桌面收益来自已有 Web 工作台的复用。

#### 3.1 G1 首片：浏览器执行节点与实时画面（2026-10-03 决策）

原设计（第 3 节）建议 noVNC/RFB + 独立显示会话。实施时核实本机不具备该前提：macOS 无 Xvfb，Docker 不可达，因此「独立显示单元 + VNC 桥」无法在本机落地。主 Web 服务使用 `web.py` 的 WSGI 服务器，**不能升级 WebSocket**；仓库已有的 `integrations/desktop/local_gateway.py` 正是为此在进程内另起 aiohttp 网关的先例。

因此把左栏画面的传输从 VNC 改为 **CDP screencast**，其余架构（独立浏览器、逐用户归属、网关承载持久 WebSocket、主服务不做图形编码）不变：

| 关注点 | 决策 | 依据 |
| --- | --- | --- |
| 浏览器进程 | 复用 `agent/tools/browser/chrome_launcher.ChromeLauncher`，系统 Chrome + 独立 `--user-data-dir` + 自选调试端口 | 已有实现，避免 Playwright 接管触发 macOS TCC 自动化授权卡顿；每节点独立 profile 隔离登录态 |
| 画面传输 | 直连该页面的 CDP WebSocket，`Page.startScreencast`（JPEG）+ `Page.screencastFrameAck` 流控；帧经浏览器网关的前端 WebSocket 下行 | 无需 X/VNC；aiohttp 客户端（`ClientSession.ws_connect`）与 Chrome 通信 |
| 人工输入 | 前端 canvas 坐标 → 视口坐标，`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` / `Input.insertText` 上行 | 与该会话同一 target，满足「可视页面与工具目标一致」 |
| WebSocket 承载 | 场景自有的进程内 aiohttp 网关，绑定 127.0.0.1 临时端口，仿 `LocalGateway` 在守护线程内跑独立事件循环 | WSGI 主服务不能承载 WS；网关自行做认证、来源校验与图形编码 |
| 画面接入令牌 | 场景 HTTP 端点签发短时令牌，绑定 `(tenant, user, 节点代次)`；前端以 `Sec-WebSocket-Protocol` 携带（浏览器 WS 不能设置自定义头，故不落 URL、不入日志） | 与桌面网关「令牌不进 query」同等约束 |
| 证书 | Chrome 保持证书校验；测试环境警告由用户在专属 Chrome 中亲自处理，不发送忽略证书的 CDP 指令 | 后台 MCP 的单一测试源 TLS 例外独立配置，不继承或改变浏览器信任 |
| 本片范围 | 单用户「画面 + 输入」闭环：创建节点、跳转登记 URL、双向流。容量上限/多用户租约仲裁/空闲回收留待后续 G1 任务 | 先证明真实 SAP 登录页可见且可人工操作，再叠加隔离策略 |

`capabilities()` 的 `browser_runtime_unavailable` 仅当该节点路径真正可用并通过真实画面验收后才可移除；本片实现不等于 G1 全部门槛（第 3、4、5 项仍为关闭）。

### 4. 场景配置、接口和数据归属

场景私有配置至少包含 `enabled`（缺省 false）、`automation_enabled`（缺省 false）、`commit_enabled`（缺省 false）、coding 智能体引用、登记 SAP 系统引用、浏览器执行节点引用与容量/空闲回收参数。前端仅接收当前授权范围内的投影与稳定不可用原因，不接收服务密钥或任意上游地址。配置通过现有部署/管理授权入口提供，避免扩建通用配置中心。

#### 4.1 场景连接配置入口和字段

在 SAP 工作台内提供「连接配置」入口，获权配置管理员可维护场景私有连接参数、选择已有资源并测试连接；普通使用者只查看必要连接摘要与就绪状态。此入口使用场景自己的前后端，不扩建通用智能体配置页。地址由配置管理员登记并经服务端校验，普通运行请求不能覆盖登记值。

| 配置分组 | 字段/来源 | 含义与规则 |
| --- | --- | --- |
| SAP 系统 | `sap.system_id`、`sap.web_gui_url` | 系统标识与真实 Web GUI 登录/入口地址，由执行节点访问；不含账号密码、认证码或会话令牌 |
| SAP 页面参数 | `sap.client`、`sap.language`、`sap.allowed_origins` | 可选 client/语言及登记的 SAP/SSO 来源；与入口 URL 中同名参数必须一致，冲突明确报错 |
| SAP 登录 | `sap.login_mode` | 当前 Web GUI 单独登录；统一登录保留为后续能力，本阶段 MCP 不从浏览器提取凭据 |
| OpenCode 绑定 | `coding_agent_id` | 选择当前主体获准的既有 coding 配置，沿用其服务与项目检查，不新增智能体类型 |
| OpenCode 服务 | 既有 `opencode.service_id`、`api_url`、`web_url` | 平台服务端 API 地址和用户浏览器可访问的嵌入 Web 地址是两项；场景展示获准摘要，复用现有部署配置，不存第二套冲突值 |
| OpenCode 项目 | 所选配置的 `coding_project_dir` | OpenCode 服务器上的已有绝对目录，例如 `/srv/opencode/projects/sap-workbench`；指项目根目录，不是单个文件、用户电脑路径或聊天 URL。场景显示解析值，修改通过已有 coding 配置入口完成 |
| MCP 连接 | `backend/deployment.py` 固定两个端点，配置只改 `enabled` | `sap-abap` → `http://127.0.0.1:8100/mcp`；`sap-pyrfc` → `http://127.0.0.1:8200/mcp`；服务端与消费者均拒绝替换端点 |
| MCP 业务身份 | `credential_source = scene_config`、`mcp.username` 与只写密码 | 按最新要求，管理员先维护一个场景账号供两个固定网关使用；密码加密，目标系统和 Client 沿用 SAP 配置 |
| MCP 传输认证 | 固定 `none` | 本机两个 HTTP 网关不需额外认证；SAP 业务认证在 `sap_connect` 中由受信消费者注入配置账号密码 |
| 浏览器执行 | `browser_service_ref`、容量/空闲租约参数 | 与 SAP 地址分开配置，引用能够到达 SAP 的执行节点；沿用有界资源策略 |

2026-10-03 用户调整本阶段策略：MCP 链接写死，仅这套测试 SAP 跳过证书校验，MCP 账号密码先维护在配置中。该要求替代早期本阶段强制 Web GUI 同源密码的约束。两网关使用同一个配置账号；当前不会根据浏览器 cookie/SSO 推断密码，也不宣称 Web GUI 已使用相同身份。统一登录另行接入。

管理员提交 `mcp_password` 只写字段；普通 config_json 只含账号。服务端复用 `auth.crypto` 的 AES-256-GCM 与部署主密钥，将密文存到场景 `cj-sap_workbench-credentials`，绑定租户、SAP 系统、来源地址、Client 和账号。留空保留，显式清除删除；更换绑定且无新密码则撤销旧密文。配置及密文同事务提交，审计失败回滚。回读只有布尔状态。运行消费者按预期配置版本解密，并核对 MCP 返回的登记账号、Client、目标与自身连接引用。当前网关 whoami 来自 registry，只能标为 `gateway_metadata`，不能作为 SAP 服务端 SID 或实际登录身份已验证的证明；固定 ADT 身份探测也只证明该配置账号，不证明浏览器或既有 connection_id。本机桥接已接通，实际身份与完整双用户生命周期验收仍见 tasks.md 的未完成项。

TLS 例外只匹配 HTTPS 主机 `sap.goodsap.cn` 的 44300 端口，设置两个连接器各自的 `insecure` / `tls_verify` 参数。其他目标严格验证，不改全局 HTTP 或 Chrome 信任设置。模型没有 TLS 参数或密码输入口。

项目目录的默认值仍由 coding 配置唯一拥有。新场景额外在 OpenCode 所在环境验证目录存在、可访问及项目匹配，不用平台主机的同名路径替代检查，也不自动创建、覆盖或同步项目文件。嵌入 URL 继续由已验证服务、项目和会话生成，不要求手填固定会话链接。

MCP 配置由场景保存启用意图及 `scene_config` 凭据来源规则，经 G0 验证的适配器按目标构建需要的格式接入专用项目/会话。源码中的远程 MCP schema 提供 URL、headers 与 OAuth 字段，本地配置提供 command/environment；它们不是通用 `username/password` 配置字段，也不证明实际 V2 工具注册已可运行。已有 `sap-connect` 连接器的 `sap_connect(user, password, client, ...)` 参数由受信桥在服务端补齐，不让模型调用原始含密码接口；返回的 connection_id 也须由桥绑定实际主体，不能由模型挑选另一连接。秘密不能写进项目 `opencode.json`、`.env`、提示词或让文件/终端工具可读的共享环境，也不能出现在 OpenCode 工具调用正文。实际版本无法满足凭据隔离和受信会话传递时记录适配缺口，保持对应 MCP/自动操作关闭，不改全局 MCP 配置凑通。

#### 4.2 保存、检测和变更语义

场景连接配置保存到场景自己的 `cj-sap_workbench-configs`，按真实租户及获准配置范围访问，存储版本、连接、账号和凭据来源规则而不存明文密码；密码密文单独属于场景凭据表，复用既有加密实现，不修改身份库结构。静态 `scene.json` 只声明能力，不承载环境地址或账号。配置读写、会话登录、凭据关联和测试接口均在场景命名空间登记，更新采用版本校验，记录脱敏审计。既有 coding 项目和 OpenCode 全局配置只引用，不复制为另一份可编辑来源。

「测试连接」分项检查 SAP/SSO 从浏览器节点可达、OpenCode API/嵌入构建匹配、远端项目目录有效、MCP 认证/初始化/工具发现及无副作用测试调用；用户浏览器的 iframe 就绪另行核验。报告失败在哪一层，认证成功不等于页面控制工具可用。测试不调用模型、不保存 SAP 单据、不改变现有工作台绑定，临时检测资源有界清理。

当前本机部署的节点、canonical host 和 MCP 消费端与主后端在同一主机执行，因此目录/执行文件检查明确标为 `environment: local`；不能把这些结果当成另一台 OpenCode API 主机或远程浏览器的目录检查。登记节点为 `sap-browser-worker`，兼容早期 `local` 别名，未知值拒绝分配且旧配置保留修复入口。离线命令只检查执行文件、源码/依赖目录、Web 入口资源和项目，不启动服务、请求网络或创建项目。联网检测两个 HTTP 请求各 10 秒、MCP 初始化 50 秒、worker 清理 12+2 秒，总预算在 90 秒内；完整 host 启动另设 70 秒。MCP 使用同任务 deadline 兼容实际 Python 3.10，不将 AnyIO 连接栈交给新任务退出；外层网关超时取消请求，登记的分配及清理保留原有 shield 恢复语义。证据见 `evidence/environment-readiness.md`。

保存配置不自动启用功能。新建会话记录配置版本、SAP 系统/入口、OpenCode 服务/项目和 MCP 连接引用快照；普通默认值调整只影响新会话，不静默移动已有会话的目标。场景 MCP 账号、目标或密码变化应使旧配置代次的 MCP 连接失效；受信消费者重新解析当前版本并核对连接登记信息后才能执行，不使用旧连接或缓存秘密，不将登记信息提升为实际 SAP 身份证明。Web GUI 本阶段单独登录，页面会话失效仍须暂停页面操作。显式要求已有会话采用新目标时先暂停和核验未保存/unknown 状态，再按重新绑定流程处理，不自动转移 SAP 登录态。

#### 4.3 接口和数据归属

场景 API 使用独立命名空间，例如 `/api/scenes/sap-workbench/`：读取 capabilities；幂等创建/恢复场景会话；查询状态；暂停/接管/恢复/关闭；申请短时画面接入；工具动作经受信服务端桥进入。HTTP 方法逐项登记到现有路由/授权表，写操作沿用来源/CSRF 校验。浏览器网关处理持久 WebSocket，主服务不承担图形编码。

| 数据 | 唯一拥有者 |
| --- | --- |
| 用户、租户、角色、凭据引用与正式审计 | 现有身份/凭据/审计系统 |
| 平台 coding 会话、远端关联和历史摘要 | 既有 coding 会话存储与同步服务 |
| 消息正文、模型调用、工具调用正文 | OpenCode；平台不复制为普通 messages |
| SAP 单据、锁和业务提交事实 | SAP；UI 成功提示/单据查询仅为核验依据 |
| 场景连接配置与版本、关联、控制代次和动作结果索引 | 场景专属持久化扩展；coding 默认项目、OpenCode 服务配置及秘密仍由原责任域拥有 |
| 登录 cookie、浏览器进程与短时画面连接 | 浏览器运行单元；不写入对话或普通配置 |

场景表按现有规范命名为 `cj-sap_workbench-configs`、`cj-sap_workbench-session_links`、`cj-sap_workbench-actions`，位于已授权业务存储下，经场景自己的幂等迁移创建，SQL 标识符正确引用。身份库不复制，公共会话表不重设计。

具体存储位置为平台数据根 `scenes/sap_workbench.sqlite3`，在 Agent 的共享/项目文件目录之外，所有配置行按真实租户访问。会话与动作的运行存取已接通，原生对话正文保存在各绑定独立 OpenCode 数据库；场景表只保存关联、控制与动作状态，不复制正文。完整生产验收与提交能力仍由 tasks.md 的相应阶段控制。

关联至少记录已验证的 tenant/user/agent、平台 coding 会话、OpenCode 服务实例与远端 session、SAP 系统、执行节点、browser/target 标识、binding generation、控制者与生命周期状态。动作记录包含 scoped request ID、tool call ID、参数摘要、页面版本、审批引用、结果与脱敏证据索引，不保存口令或第二份完整聊天。

当前独立登录方式记录平台主体、配置/绑定代次与 MCP 连接归属，不填造浏览器和 MCP 已核验一致的 SAP 身份。后续统一登录模式才接入可信 Web GUI 身份采集，记录经验证的 SAP SID/Client/用户、登录代次及受限会话凭据关联，完成改密、退出、切号与连接失效联动；现有纯合同和 ADT 配置账号探测不等于这套运行态已接通。平台用户与 SAP 用户是两个身份维度，不能因平台主体或 OpenCode 项目相同而借用另一绑定的连接；当前管理员维护的配置账号可供各获权绑定分别建立独立 MCP 连接，不宣称各自浏览器使用同一账号。

### 5. 幂等创建与恢复

创建顺序：解析权限及配置 → 预留场景关联 → 通过已有 coding 服务创建/采用远端会话 → 分配浏览器 → 持久化双方关联 → 生成受限画面连接 → 挂载两侧。重试键绑定实际 tenant/user/agent 与调用请求；客户端同名请求不能跨用户复用。部分成功记为可重试状态，重试先核对已存在资源，不能整链重新创建。

本机实现使用已有 coding ID 派生方法与外置 canonical host 的会话 API。持久分配阶段为 `reserved/host_starting/conversation_ready/browser_starting/ready`，独立于人工/自动控制权；对话就绪后发放受限画面令牌，浏览器在画面连接时按需分配。读取原会话仅在明确 404 时使用原 ID 创建，其他失败不解释为不存在；采用前核对 ID、agent 与项目。浏览器失败保留对话与固定错误码，握手中断解除连接占用，后续重连只补齐缺失侧。详情见 `evidence/allocation-recovery.md`。

生命周期与控制权分开：生命周期 `creating/ready/reconnecting/unavailable/closing/closed`；控制权 `manual/agent/paused`，提交不明的动作额外为 `unknown`。刷新复用现存实例；实例丢失时保留 OpenCode 历史，明确要求重新登录，binding generation 更新，不恢复旧动作队列。

离开场景或断开控制端会暂停后续自动页面动作并使旧控制租约失效，不把普通 coding 的“离页继续执行”行为改掉，也不宣称撤销已发生的 SAP 提交。再次进入必须核对当前状态并显式恢复操作。

OpenCode 分叉/切换通知只触发服务器核验：验证 origin、iframe、挂载通道和远端真实会话及项目/归属。新根会话默认未绑定浏览器；禁止自动继承当前 SAP 控制权。可显式创建新的场景会话，或在旧控制租约被撤销后受控重新绑定；只允许一个有效控制者。重复或迟到通知无副作用。

### 6. OpenCode 工具适配与版本门槛

G0 验证实际部署的前后端构建和 API，而不是以 `sdk/v2` 命名猜测执行路径。测试创建/读取/恢复会话、iframe ready/session 协议、模型工具可见性、一次无副作用工具调用及取消传播。

优先通过该版本已支持的工具扩展加载场景目录的适配包。V2 可评估标准工具注册入口及调用上下文，旧路径可评估插件/MCP；这是同一窄适配目标的兼容实现选择，不包含修复整个 MCP 框架。如果只能修改 OpenCode 核心才能接入，记录未满足依赖并按范围约定另立配套 change；后续场景 UI 可保持禁用态继续开发，但不能将模拟工具标作 G0 通过。

工具最小集合：读取页面、打开允许交易、填写字段/表格、选择/点击/按键、读取 SAP 消息与提交结果。具体工具名和版本协议在 G0 固定。受信执行上下文中的 OpenCode sessionID 与服务实例映射场景关联；模型只提供业务动作参数，不能选择 tenant/user/browser ID 或注入远端地址。桥凭据限制用途、有效期和会话范围，每次执行重验归属及权限。

对话中的“当前页面”必须来自最近页面快照；页面正文、帮助文本和工具输出当作数据处理，不能借其中指令更换控制目标或调用无关工具。DOM/可访问性信息优先，截图用于补充；首版限定已验收的交易和控件，无法识别时暂停并报告。

### 7. 授权与现有规则的衔接

每次创建、状态查询、画面连接、人工输入通道、工具执行和恢复均重验实际身份与绑定。机器桥使用受限服务身份并携带经验证的业务授权引用，不伪造普通 Membership。会话 ID 是定位信息，不是权限凭据。

本轮复用既有平台/coding 授权和获权管理员登记的 SAP URL/来源、固定执行节点及运行态绑定，不新增生产 SAP 权限体系。规范要求的是登记目标和受信授权，独立 SAP 资源目录不是限定的唯一实现方式；后续生产资源策略的设计与接线仍须按现行责任域完成，不能称为只差现场测试，也不能把特定目录形态追加为本轮前置。

尤其要验证 OpenCode 上游访问边界：若所有用户持有同一广域 Basic 权限，可直接打开或向他人 session 发消息，仅平台 iframe 校验无法保障 SAP 归属。SAP 场景必须经已验证的逐会话访问网关或相应部署隔离，工具执行绑定的会话不能被另一用户写入；直达上游的广域旁路须在该部署受控。若环境无法满足，此场景不启用，既有普通 coding 的外部共享约定保持不变；本 change 不静默改造它。

既有 `action-approval` 仅用于已登记为高风险的 Agent 动作，审批资格、有效期和职责分离沿用原规范；OpenCode 工具确认或用户在聊天中说“保存”不能替代该审批。普通页面读取、导航与已授权非提交输入不额外加逐点击审批。人工接管后的用户直接 SAP 操作遵循用户自己的 SAP 权限，工具自动化不得伪装为人工输入绕过动作检查。

凭据、审计与配额均复用现行责任域；本场景只实现消费者接入与证据。浏览器租约/并发、工具消耗及 OpenCode 模型消耗的计量路径须验证，不能只限制浏览器数量就宣称全部配额生效。未接通某类硬门槛时保持该类消耗关闭。

本机模型/工具消费、脱敏审计和派发前复验已有接线；独立工具/模型资源授权及完整生产计量验收留待后续，不因优先跑通而删除现有检查。确定未派发的请求按原 reference 同桶退还，跨桶及已派发的未知用量保守保留。跨时间桶精确退款是当前结算限制，现行 `resource-quota` 未将这种实现方式列为本 change 的额外前置；不以保守保留冒充精确结算已完成。

### 8. 控制并发与业务结果

同一浏览器的 Agent 动作串行，每条动作携带 binding generation、控制租约与预期页面状态。人工接管、登录过期、刷新重建或权限撤销使旧租约立即失效；队列里的旧点击不得落在新页面。当前已派发的动作等待结果或标记 unknown，再允许下一段自动执行。

执行按“观察 → 定位 → 操作 → 等待 SAP 响应 → 核对”循环。不能只设置 DOM value 而忽略 SAP 输入事件、回车校验与后台响应。菜单树、F4 帮助、表格分页/滚动、模态框、中文输入、日期/数量格式、快捷键和未保存提示均进入目标交易验收。

所有自动保存/过账入口（包括按钮、快捷键、Enter 的默认动作）遵循同一业务动作分类与授权。首版不向模型开放可任意绕过分类的 evaluate、原始浏览器调试端口或无约束指针接口。

保存前生成当前单据摘要与参数指纹；成功必须以 SAP 返回的明确消息/单据号及必要只读核验判定。网络断开、超时或工具进程崩溃后的副作用动作保持 unknown，先核对是否已完成；未查清不能自动重试，更不能承诺通用“恰好一次提交”。用户目标为“填写供核对”时停在保存之前。

### 9. 分阶段门槛

| 阶段 | 进入下一阶段的证据 |
| --- | --- |
| G0 接口与边界验证 | 文件级改动清单；实际 OpenCode 会话/嵌入/工具路径兼容；受信会话上下文；SAP/SSO 可达；逐会话上游访问路径，无需改核心或已有批准的配套依赖 |
| G1 双栏与隔离会话 | 真实远程浏览器可见且可人工操作；两个用户/租户不能交叉读写；创建重试、重连、容量、凭据与画面授权通过；不得提前宣称自动操作完成 |
| G2 可视自动操作 | OpenCode 经真实工具操作同一页面，目标交易的导航/输入/校验、暂停/接管/过期动作处理通过；审计、工具权限及相关配额切片具备证据 |
| G3 受控业务提交 | 既有高风险审批消费者接通；测试系统中真实保存并核验单据号；超时不重放、撤权及审批失效通过 |
| G4 发布与回退 | Web 与现有桌面 Web 入口通过；普通聊天、原 coding、原场景兼容；开关关闭/重新开启、迁移/恢复、差异边界检查通过 |

测试替身用于契约/故障注入，不能代替 G0 的真实工具加载或 G1–G3 的实际浏览器/SAP 验收。缺少真实系统、权限或配套依赖时保留相应任务未完成并记录缺口，允许已完成的独立部分继续工作。

## Risks / Trade-offs

- [OpenCode 构建/API/工具版本不一致] → G0 固定版本与契约证据；适配外置，缺口不扩散为核心重构。
- [两个页面看似并排但操作了不同会话] → browser/target 与远端 session 双向关联，验收同时记录可见变化和工具回读。
- [共享 OpenCode 接入不能保证 SAP 会话归属] → 先验逐会话上游访问与执行绑定，部署不满足就不启用新场景；不把隐藏导航当隔离。
- [远程浏览器成本和延迟] → 独立组件、按需创建、并发硬上限、空闲回收；真实并发记录 CPU/内存和交互延迟，容量值据实设定。
- [SAP 控件、主题、SSO 或证书不兼容] → 先选一个明确版本和交易，建立控件样例与支持矩阵；未知状态暂停，不盲点。
- [保存结果不确定或中断后重复执行] → 动作结果持久化、未知状态核验与非自动重放；浏览器重连不能恢复动作租约。
- [用户要求最少改动与现有入口耦合] → 按文件评审接缝、独立场景模块、禁用态回归；范围外必要变化先单列，不静默扩大。

## Migration Plan

1. 保存源码与部署基线，确认现有未提交工作，执行 G0；本 change 产物不改变生产配置。
2. 以 feature flags 全关闭部署场景代码与独立组件，运行场景幂等迁移；不重写普通/coding 记录，不迁移历史 SAP 登录态。
3. 按已验证范围配置测试租户的已有 coding 引用和登记 SAP 目标；后续恢复实际验收时再核对各级真实证据及依赖切片。当前实际操作检查暂缓，业务提交保持关闭；完整提交不因开关或一般继续请求自动开放。
4. 平台重启后通过已授权的持久关联恢复原 OpenCode 历史，验证浏览器实例是否仍在；实例消失则重新登录，动作保持停止。备份覆盖新增场景表及必要的脱敏证据，不将活动 cookie 直接导出为明文。
5. 回退先停发新自动动作并撤销画面/控制租约；核对正在进行的提交，unknown 保留待查。关闭场景开关后标记不可用并回收运行资源，保留 coding 历史、关联和审计，不删除 SAP 单据或 OpenCode 项目。
6. 回退代码或重新启用均不重放旧动作，新增表可保留供恢复；已有普通聊天、原 coding 和其他场景无需迁移或重配。
