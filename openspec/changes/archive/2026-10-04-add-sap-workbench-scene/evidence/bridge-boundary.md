# 桥请求、排队复验与派发前失败

2026-10-03。本轮仅使用临时平台身份/配置/存储、loopback HTTP 测试服务及页面/模型替身。没有新增真实 Chrome、OpenCode、SAP、MCP 或模型操作；生产权限和完整配额扩展仍按此前安排延后。

场景 `backend/runtime.py` 的 call/cancel 桥先验证 JSON 对象、动作与调用 ID，非法 JSON、null/list、异常 action/call_id 在暂停、配额消费和工具派发前返回 400。来源会话仍由原绑定校验，不从请求自行选取用户或浏览器。

解析请求可能等待上传，因此在解析完成后重新核验当前身份及配置代次。页面 controller 获得串行锁后及实际输入前也调用 runtime 的复验回调；排队期间的配置变化或注销不能借用旧授权执行输入。配置凭据消费者仍采用既有版本失效及回收逻辑。

动作预留后，配额拒绝、配额服务异常或派发审计异常发生在创建工具任务之前，会把该动作记为 `failed`，不遗留 `running`。确已消费但不能证明计量操作未生效的收费记录保守保留；不根据传输错误自动退费或重播。

`model_relay.py` 在解析后、配额消费前，以及预留和审计后、provider 请求派发前复验。确定尚未派发的审计/授权失败按原 reference 调用既有 `refund_quota`；由于共享接口只能退当前时间桶，只有同秒才执行退款，跨秒不减记其他请求。provider 请求开始后的未知用量仍保留预留，实际用量回执沿用原有核对规则。这不是新增生产计量接口，也不声明跨时间桶退款已实现。

表格滚动桥也纳入封闭 action 白名单。成功时保留服务端 `action_effect` 投影和效果/风险审计；取消或未确认回读记为 `unknown`，不会重播。

## 隔离结果

`test_sap_workbench_bridge_boundary.py`、`test_sap_workbench_model_relay.py`、`test_sap_workbench_runtime.py`、`test_sap_workbench_lifecycle.py` 共 **121 项通过，7.80 秒**。其中新增桥专项 43 项，覆盖真实 loopback malformed 请求、解析期间失效、真实临时身份在页面锁排队时的配置/注销失效，以及滚动分发/取消/审计。模型新增 6 项验证解析后零消费/零请求、确定未派发的同桶退款及跨桶守护。

上述测试为专项且与最终全套重叠，不相加。它们补齐现有桥接行为，不替代任务 3.2 的完整生产资源策略、3.11 的统一 SAP 登录或 5.5 的生产计量验收。
