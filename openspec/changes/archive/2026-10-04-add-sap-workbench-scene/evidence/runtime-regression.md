## 本轮修复

- Chrome 实际复现配置页“请求失败”：响应正文是成功的配置投影，但 HTTP 状态为 404。过滤其他租户 coding 配置时，web.py 的 HTTPError 修改了响应上下文；即使异常被捕获，错误状态仍残留。现在可选配置读取恢复原上下文，真实 Chrome 已看到正常配置表单；没有放宽 coding 归属检查。
  修复后的 Web 后端已重启，Chrome 刷新后再次从场景卡片打开配置通过，见 [实际配置页](config-http-status-fixed.png)。当前默认租户尚无配置，截图中的空表单不代表原租户配置丢失。
- 异步网关撤权检查复用 Web 授权时，补齐并恢复临时 web.py 上下文，把拒绝转换为明确的 401/403，避免未初始化 headers 引发 500。连接检测同样归一化登录失效。
- 启动任务拥有运行时登记，HTTP 调用者取消不再丢失正在启动的 host；重试复用同一分配和远端会话 ID。启动失败会清理部分资源。
- 关闭可取消未完成的启动；功能停用后，所有者仍能结束已有会话。并发关闭等待同一清理任务，调用者断开不打断清理；恢复需等旧资源释放，正在回收的 host 仍计入容量。
- 工具取消保留 unknown 状态且暂停控制，不重复派发。界面遇到登录过期、撤权、停用或配置变化时停止重连，卸载两栏并给出明确提示；旧画面的迟到状态和解码结果不会影响新会话。
