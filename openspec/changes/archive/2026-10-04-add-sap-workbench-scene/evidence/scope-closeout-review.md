## 4.1 的组件提供与运行验收边界

`deployment/browser.Dockerfile`、`browser-compose.yaml`、`browser-versions.json`、`entrypoint.py` 和 `healthcheck.py` 提供完整 headed Chrome → Xvfb → x11vnc → websockify/noVNC 链路、精确版本与下载锁、独立口令/profile、非 root 沙箱、loopback 发布和有界回收。主服务不自动启动该单元，也不以它在线作为默认启动前提。原 45 项专项覆盖配置/协议、临时进程和文件边界，支持原组件提供合同；不是容器画面或 SAP 运行证据。

旧表将实际构建、远端工作台绑定和完整运行验收合并为 4.1 的必需条件，本轮纠正这一归因。固定镜像 HEAD EOF 的真实失败记录仍见 [部署重试](linux-display-retry.md)；`runtime_verified` 与 `workbench_binding_verified` 保持 `false`。当前 `BROWSER_SERVICE_REFS` 仅登记本机 worker/local，远程显示不开放。4.3/4.4/4.7、完整 G1 和桌面现场条件继续保留。

## 3.2 与 5.5 的源码和验收边界

`backend/http.py` 和 `channel/web/route_registry.py` 已有所有当前场景公开方法；私有 `/bridge/call`、`/bridge/cancel` 和模型中继由 `WorkbenchRuntime.boundary` 逐次验证私有凭据及平台绑定。客户端不能在会话请求中提交任意工作目录、模型地址或另一浏览器 target，配置 coding 必须通过既有授权，执行节点限 `sap-browser-worker` 和兼容的 `local`。这些不是未接通的入口。

配置中的 SAP URL 及允许来源由授权管理员登记，普通运行请求只能消费保存配置，不允许重选目标。它与 coding 授权和固定执行节点共同满足 3.2 的原合同；无需为本项增建独立 SAP 资源目录。配置和方法登记、身份/来源检查及目标注入拒绝经真实临时平台 API 专项核对。用户要求先跑通、暂不考虑生产权限，不扩大公共 IAM 改造，也不删除现有平台授权。

`backend/model_relay.py` 实际调用现行 `consume_quota`，提前失败同时间桶按原 reference 退还，已派发未知用量保留；模型流失效会停止继续回传。工具桥也在操作前消费配额并记审计。当前缺口不是“没有计量路径”。非提交工具采用平台 chat/coding 访问语义，独立工具/模型资源策略及完整生产消费尚未验收；提交消费者单独使用现行 `tool.execute` 与正式审批。跨桶精确退款并非现行规范必需的新增合同，保守保留用量的限制如实记录；完整 5.5 不据此次 3.2 复核同步勾选。

## 入口与能力误报复核

- `scene.json`/catalog、共享场景 renderer、配置控件、四个公开 route、场景资产路径与原生 host 接线齐全；没有发现卡片再次退回普通 activate 或无法挂载的静态缺口。该结论来自当前源码和入口契约，未请求已运行 Web 的页面。
- `configuration.capabilities()` 的 visual/automation 表示已实现且配置允许的本机路径，分配时再验证组件/目录/资产；不表示 SAP 已登录或现场控件已全部验收。commit 明确为 false。
- `identity.py` 目前是可选合同/独立固定 ADT 探测；当前 runtime/probe 没有调用它来冒充 Web GUI 身份或强行共享登录。`VerifiedLoginBinding.status()` 仍将 MCP 身份标为未核验，registry whoami 不升级为服务端 SID 证明。
- Linux noVNC 单元未接入 `BROWSER_SERVICE_REFS` 作为远程节点，部署文件及构建尝试不被当前本机配置检查误报为在线远程浏览器。
- `commit_prepare/execute/reconcile` 未注册完整适配器即提前拒绝；`commit_status` 可以读取场景台账。审批测试成功不开放真实保存，不改变普通 Agent 或 rsmcode 核心。
