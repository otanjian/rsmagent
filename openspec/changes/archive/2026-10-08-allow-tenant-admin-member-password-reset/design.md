## Context

动机与范围见 [proposal.md](proposal.md)。账号密码属于全局 `users`，成员资料与角色属于租户，因此成员可见性不能直接等同于全局改密权限。原成员页隐藏租户管理员的重置入口，且以成员 `version` 调用要求账号版本的平台接口。

本文件是 2026-10-08 实现后的补录。主规范已同步本次行为，delta 使用现有 requirement 的完整 `MODIFIED` 块；补录产物齐全不代表已部署或已通过真实浏览器验收。

## Goals / Non-Goals

**Goals:**

- 以服务端对象范围约束授予租户管理员有限重置能力，不依赖前端按钮鉴权。
- 复用现有密码哈希、受限登录、会话撤销和事务审计，保持账号与成员版本分离。
- 在锁外密码复核之后，仍能拒绝资格或对象范围已变化的写入。

**Non-Goals:**

- 不增加角色权限页可勾选的写权限点，也不将租户管理员提升为平台管理员。
- 不修改新建账号或永久密码强度，不将平台重置的随机密码改为固定值。
- 不承担相邻 change 的平台管理员卡片、账号启停、导航或菜单变更，不执行真实成员密码重置。

## Decisions

### 1. 用租户专用接口表达有限授权

`TenantMemberPasswordHandler` 通过路由注册表接入 `POST /api/tenant/members/{id}/password`。请求携带当前租户、操作者本次密码及目标账号 `expected_version`，会话 ID 从验证后的请求凭据解析，不接受客户端指定操作者身份。Cookie 写入沿用来源检查。

服务按当前租户解析成员 ID；其他租户的成员 ID 返回 404。目标须为有效账号及有效成员、无任何其他租户成员关系、无平台或租户管理员绑定，并非操作者本人。已停用的其他租户关系仍算共享，避免恢复关系后暴露共享账号。放宽原平台接口会扩大授权范围，故保留原接口的平台身份限制。

### 2. 固定值只用于本次租户临时密码

`TENANT_RESET_TEMPORARY_PASSWORD` 固定为用户指定的 `123456`，仅该入口以专用最小长度参数生成带随机盐的哈希。现有 24 小时到期、强制改密、受限登录和旧会话撤销继续生效。永久密码仍要求正常强度；“一次性”指成功结果仅展示本次、完成改密后失效，不表示临时密码只能尝试登录一次，也不表示每次重置值不同。

平台重置和租户重置共同使用 `_reset_account_password_in_tx` 写入密码哈希、到期、强制改密、账号版本、撤销会话与审计；平台入口继续生成随机密码。

### 3. 同事务重验操作者与目标

密码复核和新哈希计算在写锁外执行。`BEGIN IMMEDIATE` 后同连接重验操作者账号状态、非受限会话、有效期、撤销状态、账号版本及密码哈希，重验当前租户启用和有效管理员角色，再检查目标对象范围及账号版本。

版本冲突返回 409；错误本次密码或失效会话返回 401；越权返回 403；锁或审计故障返回 503 并回滚。不能仅靠锁外校验，因为成员可以在密码计算期间被共享、提升为管理员，操作者也可能被撤权。

### 4. 列表投影与写接口采用同一目标规则

成员列表保留成员 `version`，增加账号 `user_version` 和基于操作者的 `can_reset_password`。租户按钮依据服务端能力投影显示，点击后仍由写接口重新鉴权。平台管理员在成员页沿用平台接口，提交账号版本。

前端成功后先打开独立结果弹窗，再刷新列表；结果弹窗没有重复提交按钮，关闭清空密码和表单。响应使用 `no-store`，不将临时密码写入浏览器存储、URL 或日志。

### 5. 相邻改动的共享边界

`move-password-reset-to-tenant-management` 使用相同文件和通用弹窗完成回调，负责平台卡片。合并时保留其回调结果传递及平台入口，分别验证成员页和平台卡片，不能将其未完成的测试算作本次失败或通过。主规范中的共享 requirement 需保留双方完整内容。

## Risks / Trade-offs

- 固定临时密码可被猜测 → 按用户选择限定在独占普通成员，要求操作者本次密码、24 小时到期、强制改密、撤销旧会话和审计；这些约束不使固定值具备随机密码的保密性。
- 共享关系包含已停用记录，部分业务上已离开的成员仍不能由租户重置 → 由平台管理员处理，避免通过停用关系绕过全局账号边界。
- 共享文件有并行改动 → 按实际代码和测试归属补录；上线前重跑相关前端及路由集成检查。
- 工作区已有翻译快照差异 → 单列基线差异，不用本次功能测试通过替代全量检查结论，见 [验证记录](evidence/verification.md)。

## Migration Plan

1. 无数据库迁移、数据回填或新增 feature flag；现有账号、成员、角色和会话标识保持不变。部署前通过租户重置服务、HTTP、路由与成员页测试。
2. 在共享工作区集成稳定后，按既有启动方式重载目标 Web 服务，保留原配置、数据目录和密钥。前后端需同步加载，避免新版按钮投影与旧接口不匹配。
3. 使用明确的测试成员做真实浏览器验收：租户管理员可见符合条件的入口、提交本次密码、看到结果，目标账号受限登录后改密，旧会话失效；记录脱敏证据后方可标记运行验收完成。本次补文档不执行上述操作。
4. 回退仅撤销本 change 的代码和页面改动，保留其他 change。已重置账号的旧会话不恢复，已写入的临时凭据继续受现有到期和改密规则约束；需要恢复访问时使用平台管理员流程，不回写旧密码或删库。
