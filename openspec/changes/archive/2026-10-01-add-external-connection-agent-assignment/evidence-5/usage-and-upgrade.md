# 使用与升级说明（任务 5.4）

本文件是 `add-external-connection-agent-assignment` 的面向上线/运维说明：只描述本次新增的行为、权限口径、升级与回滚方式，以及备份恢复的兼容边界。既有连接、凭据、审计、测试状态与派发授权的表述不在本文重复。

## 1. 用户可见行为

| 位置 | 变化 |
| --- | --- |
| 连接卡片 | 租户 MCP/ERP/OA 及本租户获准使用的平台 MCP 增加「分配智能体」入口与一句摘要 |
| 卡片摘要（未配置存量） | 显示「未配置 · 沿用原权限」：运行行为不变，入口仍可打开 |
| 卡片摘要（已配置） | 显示「已配置 · N 个智能体可用」；`N` 是**当前操作者可见**的分配数量，不披露隐藏对象 |
| 分配弹窗 | 默认加载已分配列表；输入名称或 ID 按需搜索候选并标注「已添加」；行内移除；统一保存 |
| 保存 | 只提交增删差量（最多 100 项）与读取时的版本号，不做全量替换；成功后卡片摘要按服务端重新读取的数量局部更新，筛选与滚动不重置 |

- 平台目录卡片没有业务租户，不提供入口也不显示摘要；个人邮箱保持原行为与入口。
- 只读调用方（无连接管理资格）能看到获准范围内的已分配列表，所有增删与保存控件不可用并说明原因。

## 2. 权限规则

| 动作 | 要求 |
| --- | --- |
| 读卡片摘要、已分配列表、候选搜索 | 连接可读 + 智能体可见（结果先按身份过滤，再搜索、排序、分页） |
| 添加、移除、保存 | 连接管理资格（`external.connections.manage`）+ 目标智能体的当前管理资格 |
| 保存校验 | 事务内重验全部目标与版本；任一目标非法整笔拒绝，不做部分写入 |

- 不可见对象不进入列表、数量或错误详情；可见但不可管理的对象行内动作禁用并给出原因。
- 身份一律从认证上下文解析，请求参数不能指定 Agent；模型不能换 Agent。
- 停用智能体沿用既有管理资格，配置分配不会启用它。

## 3. 首次保存的影响（按连接生效）

状态与运行行为（与 `design.md` D3 一致）：

| 该连接状态 | 页面 | 运行 |
| --- | --- | --- |
| 未配置存量（`configured=0`） | 「沿用原权限」，可配置 | 沿用原授权 |
| 已配置且有分配 | 显示当前可见数量 | 仅已分配且原授权允许的智能体可用 |
| 已配置且实际分配为空 | 显示 0 | 无智能体可用，**不能**回退为原权限 |

- 弹窗对未配置连接提示：「当前沿用原权限；保存后仅已分配智能体可使用，可能影响其他正在使用本连接的智能体。」
- 首次保存即使增删都为空也允许，语义是「明确配置为空」；关系、`configured=1` 与分配 revision 同事务提交。
- 新建受管连接、平台模板首次授予某租户时初始化为「已配置、空分配」。
- 普通接口不能把连接改回未配置；`configured=false` 只出现在迁移初始化出来的存量行上。
- 请按连接逐个评估后再保存：收窄的是该连接本身，取消不改变任何行为。

## 4. 升级与回滚

- **无数据迁移窗口**：既有连接与既有平台消费关系在常规 schema 迁移中初始化为未配置，行为与升级前一致；不推测任何 Agent 分配，不做全租户切换或映射导入。
- **无新增 feature flag**：入口按既有连接读取/管理权限出现，随代码发布即时生效，没有需要开启的开关。也不存在「关闭入口」的开关，因此不存在「关掉入口却仍保留限制」的矛盾状态。
- **回滚**：回退到上一版提交即可（`cow stop` → `git reset --hard <previous-commit>` → `cow start`），分配入口随之消失。
- **回退到不支持分配的版本前，先停用受影响连接**：旧版本不读取分配关系，已保存的限制不会报错，而是被静默忽略成「沿用原权限」。要让收窄仍然生效，只能先停用这些连接；重新升级后启用即可恢复分配检查。
- 本次不改变个人邮箱、内置工具、本地知识与未迁移旧 MCP 配置路径。

## 5. 备份与恢复的兼容边界

- 两张新表（`external_connection_agent_assignment_sets`、`external_connection_agent_assignments`）已纳入既有备份/恢复机制，按租户归属；备份清单记录 `assignment_tables`。
- 重复执行 schema 迁移是幂等的；恢复后 `configured` 与分配关系保持。
- **缺少分配的旧备份不能被静默恢复**：当备份未声明分配表、而线上存在已配置（`configured=1`）连接时，恢复在写入前即被拒绝，返回 `code=backup_incompatible_assignment_state`（409）；dry run 同样拒绝，避免运维事后才发现。
- 处置方式二选一：重新做一份当前备份，或先取消这些连接的分配限制（普通接口不能改回未配置，如需彻底解除需按连接删除/重建流程处理），再恢复旧备份。
- 线上没有任何已配置连接时，旧备份照常恢复（结果与现状一致），`restore-files` 命令会给出相应提示。

## 6. 本次不涉及

- 不开放 MCP `tools.call` 等仍关闭的执行切片：分配成功不等于第三方业务执行已验收。
- 不新增智能体详情反查页、跨租户策略切换、映射导入工具、游标分页或独立幂等重放设施。
- 不复制凭据：分配只是关系，凭据、版本、测试结论、工具白黑名单不受分配变更影响。
