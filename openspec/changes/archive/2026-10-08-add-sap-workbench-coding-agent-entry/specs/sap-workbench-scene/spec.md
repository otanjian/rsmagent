## MODIFIED Requirements

### Requirement: 配置投影与明确就绪状态

系统 SHALL 在服务端绑定获准的 coding 配置（含其 OpenCode 服务与项目目录）、SAP 系统和浏览器执行节点，使用当前身份提供受限配置投影。系统 MUST NOT 允许普通运行请求任意指定上游地址、工作目录、他人的浏览器或服务凭据；连接参数只能通过获授权配置入口登记。缺少配置、未授权、登录过期、服务未就绪或版本不兼容 SHALL 显示可辨识原因，不渲染无限空白或冒充可操作状态。

页内对话所用的 OpenCode 服务 SHALL 取自场景配置的 coding 智能体，工作台 MUST NOT 另行登记服务地址或自建引擎。打开工作台前 SHALL 确认该服务就绪，未就绪时按可辨识原因报告且不发起长时间等待。

本机阶段 SHALL 复用既有身份/coding 授权、获权管理员登记的 SAP URL/允许来源和固定执行节点；独立 SAP 资源目录不是此登记契约限定的唯一实现方式。后续生产资源策略及消费者仍须按现行责任域实现，不作为本轮扩建公共 IAM 的前置。

#### Scenario: 浏览器服务未配置

- **WHEN** 有权用户打开场景而执行节点未配置
- **THEN** 显示明确的未配置状态，不分配半可用浏览器，不切换到普通智能体

#### Scenario: 引用的 OpenCode 服务未就绪

- **WHEN** 场景配置的编码智能体缺少可用服务地址，或该服务当前不可达
- **THEN** 显示可辨识的未就绪原因与可重试状态，不启动替代引擎、不创建普通智能体会话

#### Scenario: 伪造连接参数

- **WHEN** 用户提交未登记的 SAP 地址、服务地址或其他用户的浏览器参数
- **THEN** 后端拒绝，前端和错误中不返回可复用凭据

### Requirement: OpenCode 原生配置与 OpenSpec 技能复用

当前本机 SAP iframe 模式 SHALL 使用 OpenCode 原生全局/项目配置及监听器，保留全部配置模型、智能体、工具、MCP、技能、命令和原生权限交互，MUST NOT 注入场景单一模型、SAP-only 智能体或额外工具屏蔽。工作台对话 SHALL 由平台编码会话入口承载并使用 OpenCode 原生对话数据库，MUST NOT 为工作台会话另建引擎进程、专属监听端口或专属对话数据库。四项 OpenSpec 技能及已有 `/opsx-*` 命令 SHALL 从配置项目的原生入口发现，不复制或覆盖项目文件；场景自身交付的 SAP skill 与插件 SHALL 走该项目目录的标准发现路径，与用户已有技能并存而不互相覆盖。场景桥的审批、提交开关和配额 MUST NOT 被描述为原生工具执行的约束或已完成的生产验收。

#### Scenario: 全局与项目配置合并

- **WHEN** 用户打开配置了多个模型、项目智能体、MCP 和技能的工作台
- **THEN** 原生目录显示配置和 OpenCode 提供的可用项，默认模型按原生配置选择，不把目录裁成一个模型或两个只读工具

#### Scenario: 场景产物与用户技能并存

- **WHEN** 项目目录已有用户技能，场景再交付 SAP skill 与插件
- **THEN** 两类产物按标准发现路径同时可用，场景产物不覆盖同名用户文件，用户删除后不自动重建而不告知

#### Scenario: 已有工作台迁移

- **WHEN** 原历史记录引用已不存在的场景强制 sap agent/provider
- **THEN** 保留会话 ID 与正文，仅替换为原生默认；原生配置中有效的用户选择不被重置

#### Scenario: OpenSpec 原生加载

- **WHEN** 项目已配置四个 OpenSpec 技能、命令且 CLI 在 PATH 中
- **THEN** SAP 专用实例能够发现并通过原生 skill 加载技能，命令沿原生工具路径执行，不需要另写 SAP 技能副本
