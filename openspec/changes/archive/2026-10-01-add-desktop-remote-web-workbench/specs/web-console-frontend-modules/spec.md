## MODIFIED Requirements

### Requirement: 被延后的上游前端增量不留未交代的活跃消费方

每一条被延后的上游前端增量（含其依赖的未路由接口）SHALL 在 `evidence/deferred-upstream-frontend.md` 逐条登记，并在交付前给出「已随本 change 生效」或「显式转交下一轮同步」的结论。若某未交付能力存在**活跃消费方**（独立前端或客户端已调用该能力依赖的接口），该消费方 SHALL 被登记并说明受影响界面与失败形态，且 SHALL 在本 change 内二选一收口：交付其后端路由与授权判定，或降级/隐藏该入口。MUST NOT 以「该能力属拆分后前端」为由留空。

桌面端 SHALL 按运行模式登记消费方：本地 React 模式（`desktop/src/renderer/**`）仍是独立前端，按上游版本合并且可能调用尚未路由的接口；远程模式装载服务器实际发布的 Web 工作台，另登记原生适配和文件连接器所消费的接口。两种模式均适用本条要求，不得以另一模式已有实现替代自身接口、权限和错误行为的验收，也不得为远程模式复制整套 Web 业务页面。

#### Scenario: 未路由接口存在活跃消费方

- **WHEN** 某被延后能力依赖的接口从未注册，而某独立前端已调用它
- **THEN** 登记该消费方与受影响界面、失败形态（空态/报错），并在本 change 内完成「补路由与授权」或「降级入口」之一，附两侧验证证据

#### Scenario: 以「属拆分后前端」为由留空被拒绝

- **WHEN** 一次处置把存在活跃消费方的未路由接口仅标注为「该能力属拆分后前端」而不给出消费方与收口结论
- **THEN** 该处置被判定为不通过，需补出消费方清单与逐条收口结果

#### Scenario: 远程模式新增原生能力接口
- **WHEN** Web 工作台增加桌面适配动作而旧客户端尚未支持
- **THEN** 登记该消费方并提供明确能力降级，普通浏览器与本地 React 模式保持原有功能；未知接口不默认为可用
