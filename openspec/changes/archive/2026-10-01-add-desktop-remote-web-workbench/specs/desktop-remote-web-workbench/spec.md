## Purpose

规定服务器集中部署时桌面端承载同一 Web 工作台的行为，覆盖服务器选择、页面与权限一致性、原生能力接入和兼容回退，使业务功能无需在两套前端重复实现且不扩大本机权限。

## ADDED Requirements

### Requirement: 显式选择远程服务器并保留本地模式

桌面端 SHALL 提供本地模式与远程模式，既有安装升级后保持原模式。远程服务器 SHALL 由用户或受控安装配置选择精确 HTTPS origin，不接受 URL 中的用户信息、查询、片段或非根路径；本地 HTTP 例外仅限本进程登记的后端。远程模式 SHALL 不启动完整本地业务后端，不自动迁移本地账号、会话或文件。TLS 失败、能力不兼容和服务器不可达 SHALL 分别提示，MUST NOT 自动忽略证书或降级认证。

#### Scenario: 首次连接远程服务器
- **WHEN** 用户保存合法 HTTPS 地址并连接支持当前协议的服务器
- **THEN** 客户端完成连接检查后进入原生登录，不启动本地业务后端，不要求用户配置模型密钥

#### Scenario: 升级既有安装及错误地址
- **WHEN** 既有本地安装升级，或用户提交 HTTP 公网地址、带路径前缀的地址、证书无效地址
- **THEN** 原本地模式及数据保持不变；不支持的远程地址明确拒绝，不在错误站点自动登录

### Requirement: 同一 Web 功能与授权范围在桌面容器可用

远程桌面 SHALL 加载配置服务器发布的同一 Web 工作台，复用业务页面、路由、菜单、品牌、语言及页面动作投影。其验收范围 SHALL 包含聊天与多智能体、历史、智能体使用/管理、场景工作台、知识文档/图谱/原始资料、待办、技能、记忆、模型、渠道、系统接入、定时任务、账户、组织权限、租户平台、品牌、日志、审计和 Token 用量。功能的实际开放 SHALL 以服务器当前能力与调用者授权为准；不存在或关闭的消费者 MUST NOT 被桌面端补成假成功。普通浏览器行为 SHALL 保持兼容。

#### Scenario: 获权成员使用专业场景
- **WHEN** 同一成员分别用浏览器和远程桌面进入已开放场景，提交相同合法输入
- **THEN** 两端提供同一业务表单、状态与结果，桌面端不要求额外 React 场景实现

#### Scenario: 管理功能与未开放能力
- **WHEN** 普通成员访问未授权管理页，或管理员进入依赖尚未开放的知识转换/外部执行功能
- **THEN** 两端均按同一服务端拒绝或不可用契约呈现，不因桌面容器而提升权限或隐藏真实故障

### Requirement: Web 内容与本地特权明确隔离

远程内容 SHALL 运行在与可信本地设置界面分离的受限浏览环境，不能访问原生凭据、完整文件系统接口、任意进程执行或通用认证代理。原生调用 SHALL 校验登记的内容实例、主 frame、精确 origin、协议版本与当前上下文；同源文件预览、用户生成 HTML、子 frame、弹窗和导航后的旧页面 MUST NOT 因同源而获得原生能力。非白名单导航 SHALL 阻断或经明确用户动作在系统浏览器打开；外链不得携带产品凭据。

#### Scenario: 恶意预览调用本地接口
- **WHEN** 用户打开含脚本的 HTML 附件，脚本尝试列本地目录、调用 Shell 或使用父页面的原生桥
- **THEN** 预览环境不具有这些能力，调用被拒绝，不泄漏目录路径或凭据

#### Scenario: 同源跳转与身份变更
- **WHEN** 主页面离开登记的工作台文档，或切换账号/服务器后旧 frame 发送 IPC
- **THEN** 原生能力立即失效，即使旧页面 origin 相同也不能继续调用

### Requirement: 原生适配保持 Web 与桌面行为完整

系统 SHALL 提供可检测版本和能力的环境适配入口，覆盖另存为、下载、外链、通知、窗口快捷操作和必要媒体权限。无桥的普通浏览器 SHALL 使用既有 Web 行为。远程桌面 SHALL 支持文件/文件夹上传、拖拽、图片/音频/PDF/HTML 预览及所需路由返回/刷新；取消选择和下载失败 MUST NOT 显示成功。功能缺失 SHALL 按单项说明，不导致整个工作台白屏。

#### Scenario: 上传预览与取消下载
- **WHEN** 用户在桌面上传文件夹、查看图片/PDF，随后取消结果另存为
- **THEN** 上传和预览保持正确用户归属，取消不会创建目标文件，也不会显示已保存

#### Scenario: 浏览器无原生桥
- **WHEN** 同一发布页面在普通浏览器打开
- **THEN** 页面正常加载，使用 Web 下载/上传，明确不展示未具备的持续本地目录访问能力

### Requirement: 远程功能承载按角色和真实发行包验收

桌面远程功能 SHALL 通过普通成员、租户管理员、零租户平台管理员、强制改密账号以及两个租户两个成员的实际客户端验收。仅通过路由存在、截图、模拟 IPC 或单元测试 MUST NOT 被标记为已完成承载。未开放业务的正确拒绝 SHALL 可验收，但 MUST NOT 被记录为其执行能力已通过。

#### Scenario: 打包客户端覆盖不足
- **WHEN** 只有浏览器测试通过而未执行真实 Windows/macOS 打包客户端验收
- **THEN** 对应平台发布门槛保持未通过，不宣称该平台功能完整
