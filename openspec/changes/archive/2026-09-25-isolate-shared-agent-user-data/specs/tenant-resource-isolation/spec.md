## MODIFIED Requirements

### Requirement: 个人与共享资源有明确边界

系统 SHALL 在租户和 Agent 校验之后继续检查实际资源所有者与当前动作授权。本人会话、执行记录、个人记忆与私有 Agent 资产 SHALL 仅由对应 owner 访问；tenant_admin 与平台管理员的业务读取资格 MUST NOT 绕过该边界，其治理投影不包含成员私有正文。历史 Agent 资产 SHALL 默认归初始管理员私有，只有明确登记共享的 Agent 资产才可由具备读取权限的本租户成员访问；其中 user/<user_id> 子目录仍按用户归属校验。列表、文本搜索和总数 SHALL 先过滤后分页，组织部门或岗位 MUST NOT 自动扩大范围。

共享回退 SHALL 继续校验实际资产来源的私有/共享归属，不能只凭消费 Agent 的共享属性开放另一 Agent 的私有资产；来源归属缺失 MUST 拒绝读取。

归属校验 SHALL 同样覆盖**文件服务数据面**，与列表、文本搜索和记忆读取使用同一规则：以绝对路径、相对路径（含租户共享根之下的目录嵌套）或服务端签发 URL 请求文件时，系统 SHALL 解析该被寻址资源**所属 Agent** 并校验其私有/共享归属（仅属主本人放行；管理员资格不形成私有读取旁路），MUST NOT 仅凭调用者对租户的成员资格、或仅凭「路径位于调用者租户共享根内」放行同租户其他成员的私有 Agent 资产；目录列举与搜索 SHALL 同样过滤。请求自报的 Agent 标识 MUST NOT 作为授权来源。对 Agent 工作区的 user/<user_id>，平台文件页面及 HTTP 文件接口 SHALL 在共享或平台管理员放行之前追加本人判断；该子目录归属不随 Agent 私有/共享转换而转移，但仍须满足原有 Agent 访问资格。此新增约束不声明租户共享智能体内部脚本直接读盘的用户隔离，也不改变既有跨租户、私有 Agent 和系统敏感路径规则。归属 MUST 取最具体的命中根；归属无法唯一确定时 MUST 失败关闭并按不可见拒绝。

#### Scenario: 同租户读取他人历史
- **WHEN** 普通成员使用同租户另一个人的会话或记忆标识请求内容
- **THEN** 系统拒绝访问，不因该成员有基础读取权限或属于相同部门而放行

#### Scenario: 历史资产不默认公开
- **WHEN** 旧工作空间登记到默认租户后新增一个普通成员
- **THEN** 该成员不能读取初始管理员私有的历史 Agent 资产，只有显式共享且满足权限的内容可见

#### Scenario: 汇总与搜索一致过滤
- **WHEN** 成员查询历史、知识或个人记忆的列表、总数及文本搜索
- **THEN** 结果和总数仅包含其获准范围，搜索不得绕过归属或隐式触发尚未开放的模型调用

#### Scenario: 共享 Agent 引用了私有共享根
- **WHEN** 普通成员从租户共享 Agent 请求的内容实际来自默认 Agent 的私有资产
- **THEN** 系统按实际来源拒绝读取，不因消费 Agent 的共享标识或同租户目录嵌套公开私有内容

#### Scenario: 管理员经共享根访问成员私有文件

- **WHEN** 非 owner 管理员经共享根、平台父目录或另一共享 Agent 定位到成员私有资产
- **THEN** 按实际资产 owner 拒绝读取，不因管理资格、目录包含关系或客户端 agent 参数放行

#### Scenario: 同租户成员以绝对路径读取他人私有 Agent 文件

- **WHEN** 普通成员（非该 Agent 属主）以绝对路径请求同租户内他人私有 Agent workspace 中的文件，无论请求声明的 Agent 参数是否为共享 Agent
- **THEN** 系统按不可见拒绝（403 或 404），不返回文件内容或路径存在性

#### Scenario: 目录嵌套不公开私有 Agent 内容

- **WHEN** 普通成员（非该 Agent 属主）以相对路径请求、或列举一个位于本租户共享根之下的他人私有 Agent workspace
- **THEN** 系统拒绝读取并在列举中省略该 Agent，不因「嵌套在共享根内」公开其内容或路径存在性

#### Scenario: 私有 Agent 仅属主可读正文

- **WHEN** 私有 Agent 的属主本人，或同租户的 `tenant_admin`，以绝对路径请求该私有 Agent workspace 中的文件
- **THEN** 属主本人返回内容、归属校验不阻止合法读取；`tenant_admin` 不因管理资格取得正文，仅经治理接口获得归属与用量元数据

#### Scenario: 归属无法唯一确定时失败关闭

- **WHEN** 被请求路径同时落在同租户两个不同 Agent 的 workspace 之下，或无法解析出唯一归属
- **THEN** 系统按不可见拒绝，不任选其一的 Agent 归属放行

#### Scenario: 共享 Agent 仍有用户私人文件子目录
- **WHEN** A、B 都获准访问同一个租户共享 Agent，B 通过平台文件接口请求 user/A
- **THEN** 请求被拒绝，共享属性与同租户关系不能代替 owner 校验

#### Scenario: 可见性转换保留用户子目录归属
- **WHEN** 包含 user/A 的 Agent 在私有和租户共享间转换
- **THEN** user/A 的 owner 判断继续有效，B 不因变为 Agent owner 或 Agent 共享而取得 A 的目录；所有读取仍检查原有 Agent 权限

### Requirement: 迁移优先登记既有数据

首次登记到 database 身份体系时，系统 SHALL 提供只读预检、一致备份和受信引导，将既有工作空间明确登记给默认租户及初始管理员，只补必要归属元数据，保持目录、业务 ID 和索引内容。归属或目录有歧义 SHALL 阻止切换，不自动共享、全量复制或忽略异常。迁移重复执行 SHALL 依据版本和唯一约束保持幂等。


已登记租户后续启用共享 Agent 用户文件目录时，SHALL 允许按可信 owner 将已知上传/回传文件迁入 user/<user_id> 并修正历史引用，保留内容和业务 ID；未知文件受保护保留，不将首次登记的原路径兼容解释为旧私人 URL 可以继续公开。此限定迁移不涉及运行环境、个人记忆库或 OpenCode 历史改造。

#### Scenario: 单实例原地迁移
- **WHEN** 预检无异常且运维完成一致备份和默认租户/管理员指定
- **THEN** 原有 Agent、会话及内容路径保持不变，身份和个人归属明确，旧凭据失效且未适配消费者关闭

#### Scenario: 迁移中断或归属异常
- **WHEN** 迁移遇到未知归属、非法根，或在提交前中断
- **THEN** 系统不启用 database，保留源数据与备份；修复后重试不重复建立租户、成员或归属

#### Scenario: 已登记共享 Agent 调整用户文件落点
- **WHEN** 已登记租户把可唯一确定归属的旧上传/结果迁入 user/A
- **THEN** 内容及业务标识保持，A 按原入口权限和本人校验读取，未知归属不猜测分配且不公开
