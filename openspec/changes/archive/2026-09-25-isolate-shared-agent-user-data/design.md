## Context

本设计按用户最终确认的边界替代此前完整隔离方案：只保证租户共享智能体中，经 RongAI 平台文件页面和文件 HTTP 接口看不到其他账号的用户目录。Python、Shell、技能脚本和 coding 保持现有开放方式；不保证同一租户共享智能体内部脚本直接读盘时的用户隔离。既有跨租户、私有 Agent 和系统敏感路径权限继续执行。本次只有设计文档，没有运行实现或验收证据。

| 现有代码 | 本次改动 |
| --- | --- |
| common/state_dir.py | 增加 Agent 用户文件目录帮助函数，不重定义现有个人记忆 user_root 或配置 state_root |
| auth/object_scope.py | 复用可信身份与数据范围，增加文件子目录 owner 判断 |
| Web fork/runtime.py | 上传目前进入 Agent/tmp；改为本人子目录，平台回传结果也使用该落点 |
| fork/handlers/files.py、workspace.py | 现有判断主要依赖 Agent owner；补充 user 子树规则并先于共享/平台根放行 |
| route_registry.py / 预览 | user 私人下载、token 预览及子资源都需当前本人身份 |
| send / cloud_client.copy_send_file | 私人文件不自动复制到 websites/cow-send 生成公开 URL |

## Goals / Non-Goals

**Goals:**

- 通过目录布局和一处共用归属判断解决平台文件可见性，保留当前 Agent 面板及既有接口。
- 上传及平台回传结果按真实用户组织；用户不可经链接、搜索父目录或平台管理员入口读取其他账号文件。
- 明确页面/API 校验与脚本执行边界的不同，验证原有四类执行能力不被本次改造关闭。

**Non-Goals:**

- 不建设 OS 沙箱、用户容器、执行代理、OpenCode 独立实例或原生终端/文件服务隔离。
- 不检测租户共享智能体中的脚本自行读取、复制、打印或外传其他用户内容；平台文件服务检查实际访问的目录，不做内容溯源。
- 不重构模型上下文、缓存、记忆、渠道或调度体系，不适配 Desktop。
- 不新增文件数据库、逐文件 ACL、权限点、版本、分享或文件产品；不改变既有执行授权与开关。

## Decisions

### D1：在共享 Agent 下增加稳定用户目录

```text
<租户共享 Agent workspace>/
  AGENT.md / skills / knowledge / ...   # 原有权限继续生效
  user/
    <user_id>/
      uploads/
      outputs/
      work/
```

使用不可变用户 ID，展示账号名称；租户通过 Agent 的实际绑定及当前有效成员校验，user_id 来自 RequestContext/RuntimeIdentity。目录不存在时按需创建；预留 user 路径有旧内容或根为链接时先预检，不自动覆盖。该结构和已有 shared_root/users 下的个人记忆不是同一个存储域，不迁移记忆库。

新增目录解析帮助函数，不修改全局 state_root、进程 cwd 或共享 Agent Profile。Web 文件生成的默认输出/本次工作路径通过请求级参数传递；平台收到已生成文件时，由可信回传用户归档到 outputs，已位于本人目录的文件直接引用。未携带可信用户的结果不生成私人链接，不能默认使用管理员或最后活跃用户。此限制只阻止无归属的平台文件发布，不关闭任务或执行器。

原有 coding 项目、脚本自选目录和本机直接读盘方式不重写；因此只承诺平台管理的上传及回传文件归档，不宣称所有程序写盘都被强制限制。若源路径实际命中他人 user 子目录，平台收集/send 同样拒绝；程序预先复制出的内容不属于本次检测范围。

### D2：原有动作权限加一条 owner 判断

共用文件路径策略从真实 Agent workspace 识别受保护的 user 根。流程是：解析当前身份及租户 → 原有 Agent/动作权限 → 实际命中用户目录的 owner 判断 → 安全读取/写入。共享根、平台根放行之前必须完成用户子树判断。owner 一致是必要条件，不代替原有权限。

不新增 file.read/write 或资源 grant，不给普通用户增加配置管理权。现有写接口继续检查其动作与 CSRF/来源，附加目标 owner 校验。文件删除、移动、打包等只接入实际已有入口，不借本任务新建这些功能。API 禁止改名 user/owner 根或跨 owner 移动，以免通过目录操作转移归属。

同租户管理员和平台管理员没有其他用户子目录的文件读取特权。Agent 可见性切换后 user 子树规则仍然生效，但不新增“Agent 失权后仍可读历史文件”的例外；共享 Agent 转为 B 私有，不会使 user/A 变为 B 的文件。

### D3：入口共用过滤，原始路径和实际路径都检查

覆盖 /api/workspace 的 tree/search/resolve/meta/read/write、/api/file、/uploads、/preview，以及平台文件浏览和实际已有递归打包/复制入口。直接访问他人目录按不可见拒绝；列举 user 时只返回本人目录，递归搜索与计数在进入目录前剪枝，不先收集他人结果再过滤。

校验原始定位与真实打开目标，处理绝对路径、父级、重复编码及软硬链接别名；不能先 realpath 抹去 user 前缀再按共享根放行。保护目录不得是链接，文件服务拒绝可形成别名的链接路径或非普通文件；必要时用受限目录句柄/no-follow 安全打开，防止检查后替换。此规则应用于平台文件 API，不限制脚本在自身运行环境创建链接。

保留已有接口和附件结构，只给新上传/结果 URL 加入真实 owner 定位信息；所有参数仅用于定位/冲突检测，授权始终来自当前登录身份。本人浏览器原生下载不能发送租户头时，继续从可信目标 Agent/文件位置派生租户，校验有效成员、原入口权限和 owner。旧 URL 只在已确认归属和兼容映射后可用。

### D4：现有面板与鉴权预览保持简单

沿用 refine-workspace-panel-agent-root 的当前 Agent 落点和现有获权公共目录展示；user 下仅显示本人目录。缺少本人文件时展示空态，不产生其他账号条目。用户/租户/Agent 切换后清除旧列表、预览和挂起请求，不展示旧身份的迟到结果。

私人 /uploads、下载、预览和每个关联子资源都在消费时鉴权，不把目录 token 当作本人凭据。没有可靠身份的预览改为登录父页面取数或提供本人鉴权下载；不新增复杂预览框架，也不因本任务全面取消原已安全可用的预览。私人响应 private/no-store，旧私人 token、反向代理静态路径不能绕过。

send 和 Web 回传识别本人目录及可信回传用户，不触发 copy_send_file 的自动公开复制。既有明确公共素材继续使用原规则。平台不会追踪任意脚本自行写到公共目录的副本，这是已确认的范围边界。

### D5：限定历史处理与启用检查

通过一次性、可重跑的清单处理已有上传/回传文件，不建设文件元数据库或迁移状态机。仅用可信会话、上传或运行记录确认 owner；确认后搬入本人目录、核对内容并改写/映射历史引用。未知或冲突文件保留在平台文件服务明确拒绝的旧数据区，不复制给所有用户，也不按文件名认领。

部署前核验现有文件身份、动作权限、写来源、适用配额与审计链路可用。文件能力若需临时关闭，复用现有 capability matrix/禁用机制，不增加 tenant/user 校验开关。平台文件接口验收通过即可部署本能力；不以新增执行隔离为条件，不改变 Python/Shell/技能/coding 的已有开放状态。

与 Agent visibility change 只做用户子树优先判断的集成回归，不新增整套 Agent 生命周期/转换迁移门禁。与工作区面板 change 沿用其目录落点，仅增加过滤；OpenCode 共享服务方案不改造。

## Risks / Trade-offs

- [用户误以为脚本也被隔离] → 产品与交付说明写明：仅平台文件页面/API；不保证租户共享智能体内部脚本直接读盘时的用户隔离。既有跨租户、私有 Agent、敏感路径规则不放宽。
- [目录位于原共享 Agent 根下] → 所有平台文件入口先检查 user 子树，覆盖平台父目录、递归操作、旧 token 和静态映射；不能仅隐藏前端。
- [旧文件无法确认 owner] → 保留数据并关闭普通文件访问，明确待处理清单，不无声丢失或猜测公开。
- [账号改名或目录重名] → 使用稳定 user_id；预检预留 user 路径，API 禁止改名 owner 根。
- [平台归档与程序并发改写文件] → 回传复制到唯一结果名称并完整写入后生成链接；已有文件编辑保持原冲突语义，不承诺资产版本或内容溯源。

## Migration Plan

1. 盘点共享 Agent 的 user 名称冲突、旧上传/结果和文件入口，备份内容与已有引用。
2. 在维护窗口暂停涉及迁移文件的写入，先部署用户子树守卫及旧私人路径拒绝规则；不新增关闭执行能力的配置。
3. 按清单迁移已知 owner 文件、核对内容并修正引用；未知内容受保护保留，重复运行沿用目标与进度，不重复复制。
4. 通过真实 HTTP 与浏览器验证 A/B/C、管理员、路径别名、父目录、旧链接、静态映射；验证原已开放 Python/Shell/技能/coding 继续可用后发布。
5. 失败时暂停受影响文件接口、保留内容和清单并修复重跑；不恢复能忽略 user 子树规则的旧文件处理器。执行服务沿用既有规则，不因文件接口回退而新增全局停用。

## Open Questions
