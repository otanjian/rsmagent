## MODIFIED Requirements

### Requirement: 关于和退出保持完整能力

关于入口 SHALL 展示当前品牌与版本并可打开原更新记录；品牌变化同步，版本未知时明确表达，不另设专用页面。退出 SHALL 结束当前登录会话、回登录页，保留单次提交及失败提示/重试；复用已有离开检查并检查本次密码输入，无未保存内容不额外确认，不删除聊天数据。

Desktop 容器的账号菜单 SHALL 在当前 Web 退出确认后，调用经能力协商的宿主退出动作，按 `desktop-tenant-context` 回到原生登录入口；MUST NOT 并发执行两种退出，或以 reload 后的普通 Web 密码登录替代桌面重登。普通浏览器 SHALL 保留现有 Cookie 账号流程。

#### Scenario: 查看版本并退出
- **WHEN** 用户查看关于、打开更新记录并点击退出
- **THEN** 品牌/版本与现有来源一致、链接可达；退出成功结束当前会话，失败提供重试而不假报成功，其他独立会话不因普通退出撤销

#### Scenario: 桌面菜单接回原生流程
- **WHEN** 用户从支持宿主退出能力的 Desktop 工作台点击退出
- **THEN** 先确认 Web 会话退出，再由宿主接续原生退出及登录界面；不刷新出普通网页密码表单，不影响聊天数据或其他独立会话

#### Scenario: 浏览器与旧宿主的区别
- **WHEN** 页面运行于普通浏览器，或已识别为 Desktop 但宿主未声明退出能力
- **THEN** 普通浏览器继续原账号流程；缺少能力的 Desktop 明确提示升级，不调用不存在的方法，不降级为普通 Web 重登并宣称桌面已恢复
