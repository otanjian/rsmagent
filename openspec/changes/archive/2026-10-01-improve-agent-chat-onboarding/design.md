## Context

实施与验收仅覆盖 Web 普通单智能体。Desktop 客户端和 OpenCode 类智能体（`agent_type=coding`）不参与本 change，不新增其编辑、展示、发送、兼容或回归要求。

现有 `paintWelcomeAgentIntro()` 已实现 `greeting → description → 默认介绍`；`bindWelcomeSuggestions()` 已能填入问题；`sendMessage()` 已处理消息、附件、流式回复和失败。问题主要在内容配置、布局和点击后缺少发送这一步，不需要建立新的聊天流程。

当前接入点是 `agent/registry.py`、`agent/admin.py`、`channel/web/fork/handlers/agents.py`、`channel/web/chat.html`、`channel/web/static/js/console.js` 与 `appearance.css`。实施时核对实际装载位置，遵守既有 fork 模块归属，不顺带推进全局前端拆分。

## Goals / Non-Goals

**Goals:** 用现有档案、表单和聊天能力完成自我介绍、使用说明、建议问题直发及首屏优化。

**Non-Goals:** 新建发送框架、欢迎配置子系统、独立状态机、批量预设工具、工具栏重排、实时预览或聊天中的说明面板。

## Decisions

### 1. 仅新增两个可选字段

```json
{
  "greeting": "我帮你把客户的想法整理成清晰需求，形成可讨论的方案。",
  "usage_hint": "描述需求或提供会议纪要 → 补齐关键信息 → 确认需求与方案",
  "suggested_questions": [
    "只有一个初步想法，能带我梳理需求吗？",
    "分析客户需求，需要先准备哪些资料？",
    "怎样判断需求适合智能体还是场景应用？",
    "能给我一份客户需求访谈提纲吗？"
  ]
}
```

直接沿用岗位字段的解析、持久化和 revision 模式，不引入 `welcome` 嵌套对象及其替换协议。使用说明是一段最多 200 字的文本，问题是一至四条、每条最多 200 字的文本；空说明/空列表使用默认引导。省略字段保留当前值；空字符串/空列表显式清空。复制与现有保存路径保留字段，但不新增导入导出能力。

不另建核心能力标签或三步数组字段；“能做什么”写在 greeting，“怎么使用”写在 usage_hint。输入框继续使用通用提示。六组文案在 `onboarding-copy.md` 中提供，缺失时使用中性默认值，不根据名称或系统提示词自动推导。

### 2. Web 管理只增加普通输入控件

现有概况页继续编辑 greeting，增加使用说明文本框和四个按显示顺序排列的问题输入框。复用现有保存、取消、错误和版本冲突处理；不做拖拽排序、预览组件或独立配置页面。

本扩展只服务 Web 普通智能体的概况表单与欢迎页。字段缺省和省略保存只是现有管理 API 的数据语义，不派生跨客户端适配任务。

### 3. 空编辑器时复用现有发送，避免拆分发送管道

建议问题只在以下条件下可点击：普通单智能体欢迎页仍存在、目标可用、输入框无非空白文本、无待发送/上传附件、当前会话没有提交或回复中的任务。

点击时再次检查上述条件及卡片所属智能体仍为当前对象，立即锁住问题入口，把可见问题写入原 textarea、触发原输入事件，然后调用现有 `sendMessage()`。这些步骤同步完成，不等待网络后再恢复输入快照。欢迎区随原首问流程移除；若前置拒绝未进入发送，则恢复入口状态并保留可见问题供用户处理。

已有草稿或附件时，入口禁用并显示“输入框已有内容，请先发送或清空后使用建议问题”；清空后恢复。此处是本次简化明确调整的交互，避免引入“问题独立发送但另存一份草稿”的双输入通道。

建议问题限定为普通自然语言，不支持斜杠命令、`@` 路由或填写占位符。保存校验及点击时的轻量防护避免意外触发现有快捷命令；不为建议问题增加另一套消息解析路径。

消息受理、服务端授权、网络重试、错误和流式接续均沿用原发送逻辑；点击处理器不另行 POST、重试或轮询。防重只保证同一欢迎入口不会反复调用发送函数，不承诺本次解决全平台网络层恰好一次投递。若接入验证发现原流程缺陷，记录后单独处理，不预先建设专用恢复状态机。

### 4. 只调整普通智能体空态

内容顺序为：头像与名称 → 简短介绍 → 使用说明 → 建议问题 → 原输入框。Web 宽屏问题双列，窄屏单列；缩小标题和上方留白，输入默认两三行。长问候语自然换行并允许页面滚动，不增加折叠面板或严格像素居中算法。

普通智能体不再应用旧“介绍和大输入框组必须纵向居中”的规则。工具栏、模型/工作空间菜单及其原展开逻辑保留；只修复新布局引起的遮挡或溢出。复用原 textarea，不创建第二个编辑器。

已有头像、品牌、主题、语言及目标切换机制继续使用。新字段随既有智能体使用目录一起返回，页面切换时重新取当前对象；不新增欢迎接口、缓存或加载状态机。加载失败沿用原目录处理，不显示前一个对象的内容。

首问后进入原消息页，历史恢复不重复介绍。接入既有普通单智能体入口，不扩展场景应用或多智能体流程。

### 5. 文案直接配置，验证集中完成

六组文案作为普通配置示例保留。实施时确认具体智能体，用现有页面/API 补齐空缺说明及问题，保留自定义值；找不到目标就记录缺失，不新建对象。不编写预设版本管理、dry-run、安装或回滚工具。

实现顺序为字段及表单 → 欢迎展示 → 点击发送 → 定向回归和浏览器验证。进入展示联调前先确认字段回读及省略保存通过；进入最终验收前确认真实首问通过。证据集中记录一次，不为每个小步骤增加审批或多轮验收。

## Risks / Trade-offs

- **输入草稿时建议问题不能使用** → 显示禁用原因，发送或清空后恢复；换取原发送流程完整复用和零草稿覆盖。
- **已有 Web 档案没有新字段** → 使用默认引导；管理 API 省略字段即保留原值，无数据库迁移。
- **问题触发现有命令或对象切换** → 只接受普通文本问题，校验明显命令/路由标记，不改发送解析器。
- **长介绍挤占首屏** → 六组示例采用短文案，旧长文本完整保留、自然滚动，不为所有极端内容承诺首屏容纳。
- **现有规范要求六入口及纵向居中** → 只修订普通单智能体适用条款，其他模式原有场景继续保留。

## Migration Plan

无数据库迁移、无新增 feature flag。两个字段可选，代码随正常版本发布；六组内容通过原编辑能力录入。验证 Web 普通智能体旧字段缺省、管理 API 省略保存及当前授权即可。

保留现有配置备份方式。回退时可撤回本次 UI 与字段增量，已运行会话不受影响；如旧服务会在保存时丢弃未知字段，先备份这两个新增字段。无需为此建设恢复平台。

## Review Outcome

本轮审查移除原方案中的跨客户端扩展、工具栏“更多”重排、会话内说明面板、结构化能力/步骤配置、独立载荷发送和恢复状态机、批量预设工具及重复阶段门槛。必要的目标正确性、纯文本渲染、旧配置兼容、权限复用、防连点和基本浏览器验收继续保留。
