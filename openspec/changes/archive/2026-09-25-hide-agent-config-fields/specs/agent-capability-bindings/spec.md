## MODIFIED Requirements

### Requirement: 能力页签管理 UI
智能体管理 SHALL 提供「能力」页签（可与既有「技能」页签合并或升级），由该界面管理技能与工具两类绑定：技能 SHALL 支持「使用全部」与子集勾选；工具管理 SHALL 支持从已注册工具目录勾选白名单，并支持配置黑名单。知识绑定 SHALL 从当前身份可见的知识条目中选择。

SOP 绑定 Phase 1 MUST NOT 在控制台提供直接编辑控件：界面 MUST NOT 渲染 SOP 标识的标题区块、已绑列表、输入框或添加/删除按钮。

`sops` 仍 SHALL 作为可持久化字段存在，并继续可经智能体管理 API 读写、继续参与 `revision` 乐观并发、继续进入运行时员工上下文。本要求只约束控制台界面不提供编辑入口，MUST NOT 被解释为该字段被删除或既有值被清空。

#### Scenario: 从目录勾选工具
- **WHEN** 用户在能力页打开工具选择器
- **THEN** 展示当前平台已注册工具列表，勾选结果写入该智能体工具白名单

#### Scenario: 添加 SOP 标识
- **WHEN** 需要为某智能体绑定一个 SOP 标识
- **THEN** 控制台能力页不提供输入框与添加按钮（管理员改经智能体管理 API 写入），写入后该标识随配置保存，既有标识不被清空

#### Scenario: 能力页不提供 SOP 编辑入口
- **WHEN** 用户打开任一智能体的能力页签
- **THEN** 界面不渲染 SOP 标识区块（标题、提示、已绑列表、输入框与添加按钮），同页的技能勾选与工具白/黑名单仍照常渲染并可保存

#### Scenario: 已绑 SOP 的智能体保存后不回退
- **WHEN** 某智能体已有非空 `sops`，用户在能力页改动技能或工具绑定
- **THEN** 保存后读取该智能体仍返回原有 SOP 标识，既有值不被清空，且不影响其他智能体的绑定

#### Scenario: 无权知识不可绑定
- **WHEN** 当前主体无权读取某知识条目
- **THEN** 选择器不提供该项；即使客户端伪造 ID，保存或运行时也不得扩大可读范围
