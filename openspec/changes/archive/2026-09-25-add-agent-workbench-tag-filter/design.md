## Context

见 proposal.md。真实入口为 chat.html 的 view-agent-workbench，console.js 的 fetch/apply/renderAgentWorkbench 使用独立只读投影，完整列表也供 chatAgentCatalog 使用。租户投影缺少既有规范要求的 position/category/tags；legacy 投影已包含。管理页目前只按英文逗号拆分标签。

## Goals / Non-Goals

**Goals:** 在现有名单与标签配置上完成筛选，保留请求乱序保护、权限边界、聊天启动和主题样式。

**Non-Goals:** 新增岗位字段、映射帮助站场景、服务端全文检索、修改运行时能力、数据库迁移。

## Decisions

1. tags 仍以 AgentProfile 为唯一来源；只补齐租户投影白名单，不读取管理接口来补数据。这样保留原对象范围，旧客户端仅增加可忽略展示字段。
2. 纯前端派生搜索结果与标签计数，完整 agentWorkbench/chatAgentCatalog 不变。关键词匹配用 trim/lowercase/includes；标签精确匹配，Map/Set 避免特殊名称与重复项问题。标签按完整名单首次出现排序，刷新不因数量变化跳位。
3. 单选标签与搜索取交集。全部为 null，未打标签为空字符串，其余为实际标签，避免与用户自定义“全部”等名称碰撞。计数只受关键词约束，零计数标签仍可见。选中标签临时排在“全部”后，确保折叠到一行时仍可见，其他标签顺序不变。
4. 状态仅保存在页面内存：同页导航/刷新保留；身份失效清除，租户/账号上下文变化重置，并把账号 epoch 纳入已有过期响应检查。刷新删除已选标签时回到全部。
5. 控件使用独立 DOM，不随卡片重建；中文 composition 期间延迟筛选到完成。标签按钮只携带数字索引，名称作为转义文本展示。超过一行按真实布局折叠，先为第一行右侧的展开/收起按钮预留宽度再隐藏溢出标签；已选标签保持可见；展开区限高滚动，保证窄屏卡片空间。
6. 标签保存只调整管理表单序列化为中英文逗号拆分 + trim/filter/Set，无需变更持久化格式。已有数组不拆分其中的合法逗号文本以避免隐式迁移。

## Risks / Trade-offs

- 标签很多 → 一行折叠、展开区限高滚动；计数仍覆盖完整可见名单。
- 补齐元数据后卡片高度增加 → 检查网格与窄屏，标签允许长词换行。
- 共享 console.js 有未提交改动 → 仅增量编辑与定向回归，不覆盖其他 change。
- 当前服务可能未启用后端热重载 → 核对实际进程，以独立本地验收或安全重启验证真实接口，不将旧进程响应当作新实现。

## Migration Plan

先完成白名单及标签保存规范化并通过回归，再接入筛选与界面，最后浏览器检查搜索、组合筛选、空态和三种布局。无需数据迁移或新增 feature flag；新界面随本次静态资源发布生效，tags 缺失仍可搜索且视为未打标签。回滚只撤回本 change 的增量代码，已保存 tags 数组兼容旧版本。验收结果记录 evidence.md。
